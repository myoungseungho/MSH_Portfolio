Part 1. 컴파일러가 하는 일

컴파일러가 정확히 뭘 해?

인간이 읽는 코드를 CPU가 실행할 수 있는 기계어로 번역해!

근데 한 번에 번역하는 게 아니라, 여러 단계를 거쳐.

🔄 컴파일 파이프라인 ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ 1️⃣ 전처리 │ → │ 2️⃣ 어휘 │ → │ 3️⃣ 구문 │ → │ 4️⃣ 의미 │ → │ 5️⃣ 코드 │ │ │ │ 분석 │ │ 분석 │ │ 분석 │ │ 생성 │ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ #include 토큰화 문법 트리 타입 체크 기계어 #define 생성 변수 확인 출력

Part 2. 전처리 (Preprocessing)

#include가 뭔데?

간단해! 해당 파일 내용을 그 자리에 복붙하는 거야.

📋 전처리기가 하는 일

1. #include → 파일 내용 복사-붙여넣기

2. #define → 텍스트 치환

3. #ifdef → 조건부 코드 선택

4. 주석 → 제거

// main.cpp (전처리 전) #include "player.h" #define MAX_HP 100 int main() { Player p; p.hp = MAX_HP; }
⬇️ 전처리 후 (실제로 컴파일되는 코드) // player.h 내용이 여기에 복붙됨 class Player { public: int hp; void Attack(); }; int main() { Player p; p.hp = 100; // MAX_HP가 100으로 치환됨 }
잠깐, 그럼 windows.h를 include하면?

windows.h 안에는 또 다른 #include가 수십 개 있어.

그게 다 펼쳐지면... 수만 줄이 됨!

📊 windows.h 포함 시 코드량 변화 #include <windows.h> ↓ 전처리 후 약 50,000줄의 코드가 됨! 😱 ┌─────────────────────────────────────────┐ │ 원본 main.cpp: 10줄 │ │ 전처리 후: 50,010줄 │ │ 추가된 양: 5,000배! │ └─────────────────────────────────────────┘

⚠️ 여기서 PCH의 필요성이 나온다!

100개 .cpp 파일이 모두 windows.h를 include하면?

5만 줄 × 100번 = 500만 줄을 파싱해야 함!

→ 이걸 해결하는 게 다음에 배울 Precompiled Header

Part 3. 어휘 분석 (Lexical Analysis)

어휘 분석은 뭐야?

코드를 토큰(Token)으로 쪼개는 거야.

문장을 단어로 나누는 것과 비슷해!

📝 코드를 토큰으로 분리 원본 코드: int playerHP = 100; 토큰화 결과: ┌─────────────────────────────────────────┐ │ [int] → 키워드 │ │ [playerHP] → 식별자(변수명) │ │ [=] → 연산자 │ │ [100] → 숫자 리터럴 │ │ [;] → 구분자 │ └─────────────────────────────────────────┘

Part 4. 구문 분석 (Syntax Analysis)

구문 분석은?

토큰들을 문법 트리(AST)로 조립해!

코드의 구조를 이해하는 단계야.

🌳 AST (Abstract Syntax Tree) 코드: int hp = health + bonus; [선언문] / | \ [int] [hp] [대입식] | [덧셈] / \ [health] [bonus]
문법 오류는 여기서 잡히겠네?

맞아! 세미콜론 빠뜨림, 괄호 안 닫음 같은 에러!

// 구문 오류 예시 int x = 10 // ❌ 세미콜론 없음 if (x > 5 { // ❌ 괄호 안 닫음
💥 에러 메시지: error C2143: syntax error: missing ';' before '}' ↑ 구문 분석 단계에서 발생!

Part 5. 의미 분석 (Semantic Analysis)

문법은 맞는데 에러 나는 경우도 있잖아?

그게 바로 의미 분석 단계에서 잡히는 거야!

🔍 의미 분석이 체크하는 것

1. 타입 체크 - int에 string 넣으려고 하면?

2. 변수 존재 - 선언 안 한 변수 쓰면?

3. 함수 시그니처 - 인자 개수/타입 맞나?

// 의미 오류 예시 (문법은 맞음) int hp = "백"; // ❌ 타입 불일치 int x = undeclaredVar; // ❌ 선언 안 된 변수 Attack(1, 2, 3); // ❌ 인자 개수 틀림
💥 에러 메시지: error C2440: 'initializing': cannot convert from 'const char*' to 'int' error C2065: 'undeclaredVar': undeclared identifier ↑ 의미 분석 단계에서 발생!

Part 6. 코드 생성 (Code Generation)

드디어 기계어 만드는 거야?

맞아! AST를 어셈블리 → 기계어로 변환해.

📦 코드 생성 과정 C++ 코드: int add(int a, int b) { return a + b; } ↓ 어셈블리로 add: mov eax, ecx ; a를 eax에 add eax, edx ; b를 더함 ret ; 결과 반환 ↓ 기계어로 0x8B 0xC1 0x03 0xC2 0xC3
최적화는 언제 해?

코드 생성 과정에서! Release 빌드가 느린 이유야.

더 빠른 기계어를 만들려고 여러 최적화를 적용하거든.

Part 7. 어디서 시간이 오래 걸려?

컴파일에서 가장 오래 걸리는 단계는?

대부분 전처리 + 구문 분석이야!

특히 헤더 파일 처리가 병목!

⏱️ 컴파일 시간 분포 (일반적인 경우) ┌────────────────────────────────────────────────────────┐ │ 전처리 (35%) ████████████████ │ │ 구문분석 (30%) █████████████ │ │ 의미분석 (15%) ██████ │ │ 코드생성 (20%) ████████ │ └────────────────────────────────────────────────────────┘ 💡 전처리가 오래 걸리는 이유: - #include로 수만 줄 복사 - 같은 헤더를 여러 파일에서 반복 처리 → 해결책: PCH (Precompiled Header)!

📝 핵심 정리

  • 전처리: #include 복붙, #define 치환 → 가장 비용 큼!
  • 어휘분석: 코드를 토큰으로 분리
  • 구문분석: 토큰을 문법 트리(AST)로 조립
  • 의미분석: 타입 체크, 변수 존재 확인
  • 코드생성: 기계어 출력 + 최적화
  • 병목: 헤더 파일 반복 처리 → PCH로 해결!
