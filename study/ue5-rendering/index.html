• 프레임이 30fps도 안 나와

• 프로파일러 보니까 특정 패스가 4ms나 먹어

고급 그래픽 = 최적화가 필수

문제의 원인을 찾고, 해결책을 찾아가는 과정을 함께 해봅시다.

CASE 1

Nanite 그래스가 너무 느려

프로파일러를 봤더니 Nanite Visibility Buffer 패스가 4ms나 걸려. 뭐가 문제야?

보통은 1~2ms인데 4ms면 2배 이상이야.

어디서 발생하는지 확인해보자.

해당 지점을 확인해봤어. 뭐가 문제일까?

주변에 풀 인스턴스가 약 50만 개 배치되어 있고, 모두 Nanite 메시로 설정됨.

그리고 Visible Cluster 수가 10만 개 이상이야.

정상적인 장소: Visible Cluster 2~3만 개
문제 지점: Visible Cluster 10만 개 이상

그래스의 특징이 문제

왜 그래스가 특히 문제야?

그래스 메시는 Nanite에 불리한 특징이 많아:

1. 토폴로지에 빈 공간이 많음
   → 컬링이 어려워짐
   → 클러스터 오버드로우 증가

2. WPO(World Position Offset) + Masked 머티리얼 사용
   → 픽셀 위치가 재질 평가 이후에 달라짐
   → 불필요한 재질 평가 수행
   → 추가 계산 발생

3. 크기가 작고 버텍스 수가 적음
   → Nanite LOD 트리가 얕음
   → 루트 클러스터로 5~10m에서 이미 렌더링
   → 원경 대응 LOD 부족
🌿 비유: 나무 vs 풀

나무: 크고 덩치가 커서 멀리서도 잘 보임 → LOD 단계가 많음
풀: 작고 얇아서 가까이서도 디테일 필요 없음 → LOD 단계 부족

Nanite는 "큰 오브젝트"를 최적화하는 데 유리한데, 풀은 정반대 특성을 가짐.

시도 1: Nanite 임포스터

LOD가 부족하다면 임포스터를 써보면 어때?

좋은 생각이야! Nanite 임포스터를 루트 클러스터의 상위 LOD로 활용해보자.

방법:
1. 임포스터 렌더링 조건 변경
   - 기존: 특정 픽셀 사이즈 이하일 때
   - 변경: 루트 클러스터 + LOD 임계값 넘어설 때

2. 엔진 커스텀으로 구현
결과는?

성능: 약간 개선되었지만 미미함

비주얼: 거뭇거뭇하게 렌더링되어 거슬림

→ 폐기

시도 2: 병합된 메시

개별 풀을 하나로 합치면 어때?

병합된 메시는 더 많은 버텍스를 보유하니까 더 깊은 LOD 트리를 생성할 수 있어!

테스트:
- 단일 풀 10만 개
- 10개 묶음 풀 1만 개

비교 결과:
→ 어느 정도 효과 있지만 기대만큼은 아님
→ 작업 비용 대비 효율이 낮음

→ 실제 게임 적용 안 함

최종 해결: Opacity Cutout

그래서 어떻게 해결했어?

아트팀에서 Opacity Cutout 기능을 활용했어.

풀 머티리얼의 Masked 속성을 제거한 거지.

✅ 결과:
기존: 4.37ms 개선: 2.38ms 약 45% 성능 향상!

WPO와 Masked 머티리얼이 사라지면서 추가 계산이 제거됨.

💡 교훈:

"프로그래밍으로 해결하려고만 하지 말고, 에셋을 잘 다듬는 것도 중요하다."

Nanite의 설계 의도와 맞지 않는 에셋은 오히려 독이 될 수 있음.
CASE 2

포그가 벽을 뚫고 나와

Volumetric Fog를 쓰는데 벽을 뚫고 스며드는 것처럼 보여. 왜 그래?

이미 기존 개발자가 잘 대응했는데, 추가 비용이 발생하고 있어.

이 비용을 줄여보자.

Volumetric Fog가 뭐야?

Volumetric Fog는 어떻게 동작해?

현실 세계에서 빛이 소립자에 의해 산란되는 현상을 모델링한 거야.

수식:
LE (Radiance) = 카메라로 입사하는 빛
Scattering = 구간에 대한 적분

컴퓨터로 계산:
→ 리만섬 (Riemann Sum)
→ 3D 그리드로 나눈 "Froxel" 자료 구조 사용
Froxel이 뭐야?

Froxel = Frustum Voxel

3D 텍스처로 구현된, 뷰 공간을 이산화한 공간 셀이야.

동작 과정:
1. 각 셀마다 광원들로부터 빛 입사
2. 카메라 방향으로 산란된 값 계산 & 저장
3. 같은 지축 방향으로 누적합 (리만섬)
간접광은 어떻게 처리해?

Lumen Translucency Volume을 사용해.

각 셀의 중심에서 모든 방향으로 트레이싱한 레디언스를 저장한 Froxel이야.

문제 발견: 빗샘 현상

그래서 왜 벽을 뚫고 나와?

빗샘(Bleeding) 현상이야.

발생 과정:
1. Volumetric Fog 셀이 벽 근처에 위치
2. 간접광을 Lumen Volume에서 샘플링
3. 텍스처 샘플링 시 Bilinear Filtering 발생
4. 벽 외부의 간접광 정보가 섞임!

결과:
→ 실내인데 실외 빛이 섞여 들어옴
🖼️ 비유: 사진 편집

검은색 배경에 흰색 원을 그렸어.
근데 이미지를 축소하면? 원 경계가 회색으로 변해.
→ 검은색과 흰색이 섞였기 때문!

Volumetric Fog도 마찬가지. 벽 안쪽과 바깥쪽 값이 섞여버림.

기존 해결책

기존에는 어떻게 해결했어?

하늘 방향 차폐도(Occlusion) 계산

방법:
1. GI Scattering 계산 시
2. 천장 방향으로 차폐도 계산
3. 실내라고 판단되면 간접광 영향 감소

문제:
→ 차폐도 구하기 위한 트레이싱 수행
→ 추가 비용 발생!

개선: 루맨 볼륨 활용

트레이싱 없이 차폐도를 구할 수 있을까?

Lumen Translucency Volume을 활용!

아이디어:
1. Lumen Volume은 이미 모든 방향으로 트레이싱한 정보
   → 하늘 방향도 포함됨!

2. 트레이싱 거리 정보가 포함되어 있음
   → 이걸로 차폐도 계산 가능!

3. 사용하지 않는 필드에 차폐도 저장
   → 추가 샘플링 필요 없음

결과:
→ 제로 코스트에 가까운 해결책!
✅ 결과:
  • 비주얼: 원하는 효과 달성 (포그 빗샘 제거)
  • 성능: 기존 트레이싱 비용 제거
  • 비용: 거의 제로 코스트
💡 교훈:

"문제 원인 분석이 정말 중요하다."

원인을 파악하는 과정에서 이미 존재하지만 숨어 있던 가능성을 발견할 수 있음.
CASE 3

반투명 반사가 너무 비싸

반투명 재질의 반사 퀄리티가 너무 낮아. 어떻게 해?

Front Layer Reflection 기능을 활성화하면 돼.

반사 퀄리티가 확 올라가!

근데 문제가 있어?

성능이 3배 이상 증가

기존: 0.3ms
활성화 후: 1.3ms

반투명 재질이 화면에 크게 보이는 경우에는 더 심해져.

왜 이렇게 비싸?

Front Layer Reflection이 뭐길래 이렇게 비싸?

기본적으로 반투명 리플렉션은 러프하게 계산해.

실시간 렌더링 방식이 비싸기 때문이야.

Front Layer Reflection:
→ 가장 앞에 있는 반투명 재질들에 대해서만
→ Lumen Reflection과 동일한 품질로 처리

추가되는 패스:
1. G-Buffer 패스 (댑스, 노멀 등 렌더링)
2. Lumen Reflection 패스 (레이트레이싱)

→ 특히 레이트레이싱이 비쌈!

최적화 아이디어

어떻게 최적화할 수 있을까?

두 가지 접근 방식을 생각해봤어:

접근 1: 기본 반투명 반사의 퀄리티 높이기
→ 효과 장담 어려움
→ 배보다 배꼽이 더 커질 수 있음
→ 포기

접근 2: Front Layer Reflection 퀄리티 낮추기
→ 해상도를 낮춰보면 어떨까?

구현: 해상도 다운스케일

어떻게 구현했어?

입력 해상도를 낮춰서 렌더링

방법:
1. G-Buffer 렌더링 입력 해상도 조작
2. 낮은 해상도로 G-Buffer + Lumen Reflection 렌더링
3. 라이팅 시 업샘플링하여 사용

코드 예시:
// 반투명 렌더링 전에
ScaleFactor = 0.5;  // 1/2 해상도
ViewRect.Scale(ScaleFactor);

// G-Buffer 렌더링
RenderGBuffer(ViewRect);  // 낮은 해상도로 렌더링

// Lumen Reflection
RenderLumenReflection(ViewRect);  // 낮은 해상도

// 라이팅 시 업샘플링
UpscaleAndLight();

문제 발생

문제 1: 경계부 댑스 판정

캐릭터 가장자리에 계단 형태 아티팩트 발생

원인: - 댑스 다운스케일로 해상도 차이 발생 - 경계부 판정 오차 증가 해결: → 댑스 판정을 아예 생략 → 모든 반투명에 반사 적용 → 겹친 부분에서 반사 강해지는 부작용 있지만 → 인게임에서 크게 티 안 남

문제 2: 플리커링 (자글자글)

캐릭터 주변, 유리창 가장자리에 노이즈 발생

원인: - Lumen Reflection 내부의 Temporal Accumulator 오차 증가 - 낮은 해상도 → 더 많은 노이즈 - 업샘플링 시 노이즈 픽셀이 확대됨 해결: → Median Filter 적용 → 다운스케일된 텍스처 대상이라 가벼움 → Pepper & Salt 노이즈 제거에 효과적

최종 결과

✅ 성능 비교:
원본 (Full Resolution): 1.3ms 1/2 해상도: 큰 차이 없음 1/4 해상도: 약 0.6~0.7ms (약 45% 개선) 비주얼: → 1/4 해상도에서도 꽤 괜찮은 퀄리티

선택: 1/4 해상도로 적용

💡 교훈:

"아이디어 구상과 구현보다, 추후 발생하는 문제 해결이 더 까다로웠다."

끊임없는 원인 파악과 수정이 필요했지만, 그 과정에서 얻은 노하우와 지식이 상당했음.

📌 핵심 정리: UE5 렌더링 최적화

  • Nanite 그래스 - 에셋 특성이 Nanite와 맞지 않으면 독이 됨. Masked 제거로 45% 개선
  • Volumetric Fog - 문제 원인 분석으로 숨어있던 해결책 발견. 제로 코스트 최적화
  • Front Layer Reflection - 해상도 다운스케일 + 문제 해결로 45% 개선


공통점: 모든 사례에서 "왜?"를 계속 물으며 원인을 파고들었고, 그 과정에서 해결책을 찾았다.

💡 배운 점

1. 도구의 특성을 이해하라

Nanite는 "큰 오브젝트"에 최적화되어 있음. 풀처럼 작고 얇은 오브젝트는 오히려 독이 될 수 있다.


2. 문제의 원인을 파고들어라

표면적 현상만 보지 말고, 깊이 분석하면 숨어있던 해결책을 발견할 수 있다.


3. 프로그래밍만이 답은 아니다

때로는 에셋을 잘 다듬는 것이 더 효과적일 수 있다.


4. 완벽하지 않아도 괜찮다

약간의 부작용이 있더라도 인게임에서 티 나지 않으면 충분히 좋은 해결책이다.


5. 과정에서 배우는 것이 많다

시행착오를 겪으며 얻은 노하우와 지식이 가장 큰 자산이다.
