사후 디버깅

Postmortem Debugging — 크래시 후 분석 전략

Part 1. 사후 디버깅이란?

크래시가 이미 발생했는데 어떻게 분석해?

사후 디버깅은 크래시 발생 후 남은 정보로 원인을 분석하는 것.

덤프 파일, 로그, 이벤트 뷰어 등을 활용한다.

Part 2. 준비해야 할 것들

크래시 분석에 뭐가 필요해?

1. 덤프 파일 (.dmp)

2. PDB 파일 (크래시 난 exe와 같은 빌드)

3. 소스 코드 (같은 버전)

4. 가능하면 로그 파일

// 크래시 시 자동 덤프 생성 코드 #include LONG WINAPI MyExceptionFilter(EXCEPTION_POINTERS* pExInfo) { // 타임스탬프로 파일명 생성 SYSTEMTIME st; GetLocalTime(&st); wchar_t szFile[256]; swprintf_s(szFile, L"crash_%04d%02d%02d_%02d%02d%02d.dmp", st.wYear, st.wMonth, st.wDay, st.wHour, st.wMinute, st.wSecond); HANDLE hFile = CreateFileW(szFile, GENERIC_WRITE, 0, NULL, CREATE_ALWAYS, FILE_ATTRIBUTE_NORMAL, NULL); if (hFile != INVALID_HANDLE_VALUE) { MINIDUMP_EXCEPTION_INFORMATION mei; mei.ThreadId = GetCurrentThreadId(); mei.ExceptionPointers = pExInfo; mei.ClientPointers = FALSE; // MiniDumpWithFullMemory로 전체 힙 포함 (큰 파일) MiniDumpWriteDump(GetCurrentProcess(), GetCurrentProcessId(), hFile, MiniDumpWithFullMemory, &mei, NULL, NULL); CloseHandle(hFile); } return EXCEPTION_EXECUTE_HANDLER; } // main() 시작 시 SetUnhandledExceptionFilter(MyExceptionFilter);

Part 3. 덤프 분석 체크리스트

덤프 열면 뭘 봐야 해?

VS에서 덤프 열고 "Debug with Native Only" 클릭 후:

// 분석 체크리스트 1. 예외 코드 확인 - 0xC0000005: Access Violation (가장 흔함) - 0xC00000FD: Stack Overflow - 0xC0000094: Integer Divide by Zero 2. Call Stack 확인 - 크래시 난 함수 - 호출 경로 - 각 프레임의 파라미터 3. 지역 변수/파라미터 확인 - nullptr인 포인터가 있나? - 이상한 값이 있나? 4. 스레드 목록 확인 - 다른 스레드는 뭘 하고 있었나? - 데드락 징후가 있나? 5. 메모리 패턴 확인 - 0xCCCCCCCC: 미초기화 스택 - 0xDDDDDDDD: 해제된 힙 - 0xFEEEFEEE: 해제된 힙 (Windows)

Part 4. PDB 버전 관리

어떤 PDB가 맞는 건지 모르겠어

빌드할 때마다 PDB 아카이브를 해두자.

버전 번호나 빌드 번호로 관리.

// PDB 관리 전략 // 1. 빌드 스크립트에서 자동 복사 xcopy /Y "Release\*.pdb" "\\fileserver\symbols\v1.2.345\" // 2. 심볼 서버 구축 (대규모) symstore add /r /f "Release\*.pdb" /s "\\fileserver\symbols" /t "MyGame" // 3. VS 심볼 경로 설정 // Debug → Options → Symbols // \\fileserver\symbols 추가 // exe에 버전 정보 넣기 #define VERSION_STRING "1.2.345" // 크래시 리포트에 버전 포함

핵심 정리

  • 덤프 + PDB + 소스 세 가지 필수
  • 크래시 시 자동 덤프 생성 코드 추가
  • Call Stack → 변수 → 메모리 패턴 순으로 분석
  • PDB 버전 관리로 나중에 분석 가능하게
