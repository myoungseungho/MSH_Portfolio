프로시저 앞에 이 한 줄이면 네트워크 20% 절약

SET NOCOUNT ON - 왜 쓰는지, 안 쓰면 뭐가 문제인지

Part 1. 이상한 현상

프로시저 코드 보다가 맨 위에 이런 게 있던데, 이게 뭐야?

SET NOCOUNT ON

거의 모든 프로시저에 들어가 있지? 일단 뜻부터 보자.

CREATE PROCEDURE gp_SaveQuest @pc_uid bigint, @questData binary(1064) AS BEGIN SET NOCOUNT ON; -- 이게 뭘까? UPDATE TQuest SET QuestInfo = @questData WHERE charunique = @pc_uid END
NOCOUNT면... COUNT를 안 한다? 뭘 안 세는 거야?

정확해. "영향받은 행 개수"를 안 센다는 뜻이야.

잠깐, 먼저 "원래 뭘 세는지"부터 보자.

Part 2. DB는 원래 뭘 세고 있어?

UPDATE 하면 DB가 뭘 세?

직접 SSMS에서 쿼리 날려보면 알 수 있어.

UPDATE TCharacter SET level = level + 1 WHERE job = 1

이걸 실행하면 하단 메시지 창에 이게 뜸:

(128개 행이 영향을 받음)
아, "128개 행이 영향을 받음" 이거?

맞아. "N rows affected" 메시지야.

INSERT, UPDATE, DELETE 할 때마다 나옴.

그거 그냥 SSMS 화면에 보여주는 거 아니야?

아니, 진짜 데이터로 전송돼.

클라이언트(게임 서버)한테 "128개 바꿨어~"라고 보내는 거야.

[게임 서버] [DB 서버] | | |--- UPDATE 요청 ------------> | | | (128행 UPDATE) |<-- "128 rows affected" ------ | ← 이 메시지가 진짜 전송됨 |<-- 완료 응답 --------------- | | |
어? 그럼 프로시저에서 UPDATE 3번 하면?

메시지도 3번 전송됨.

CREATE PROCEDURE gp_SaveCharacter ... AS BEGIN UPDATE TCharacter SET ... -- "(1개 행이 영향을 받음)" 전송 UPDATE TInventory SET ... -- "(50개 행이 영향을 받음)" 전송 UPDATE TSkill SET ... -- "(30개 행이 영향을 받음)" 전송 END

이 프로시저 한 번 호출하면 "N rows affected" 메시지가 3번 전송됨.

Part 3. 그래서 뭐가 문제야?

"128개 바꿨어"라고 알려주는 게 뭐가 나빠?

두 가지 문제가 있어.

문제 1: 네트워크 트래픽 낭비

항목 내용
"1개 행이 영향을 받음" 메시지 크기 약 30~50 바이트
프로시저당 UPDATE/INSERT 횟수 3~10회
1초에 프로시저 호출 횟수 (동접 1000명) 수백 ~ 수천 회

계산해보면:

50바이트 × 5회 × 1000호출/초 = 250KB/초 = 낭비

문제 2: 클라이언트 처리 오류

처리 오류? 그건 또 뭐야?

OLE DB 같은 DB 라이브러리가 이 메시지를 "결과셋"으로 착각할 수 있어.

// C++ 게임 서버 코드 bool result = pProc->Execute(¶m, &rowset); // 기대: rowset에 SELECT 결과가 들어옴 // 현실: "3 rows affected" 메시지가 먼저 와서 혼란

특히 여러 개의 SELECT를 반환하는 프로시저에서

"N rows affected" 메시지가 끼어들면 결과 파싱이 꼬일 수 있음.

Part 4. 해결책: SET NOCOUNT ON

그래서 SET NOCOUNT ON이 뭘 하는 거야?

"N rows affected" 메시지를 보내지 마!라고 DB에게 지시하는 거야.

[SET NOCOUNT OFF - 기본값] 게임 서버 DB 서버 |--- UPDATE 요청 ------------>| |<-- "128 rows affected" -----| ← 전송됨 |<-- 완료 --------------------| [SET NOCOUNT ON] 게임 서버 DB 서버 |--- UPDATE 요청 ------------>| | | (메시지 생략) |<-- 완료 --------------------| ← 바로 완료만 전송
그럼 @@ROWCOUNT는 어떻게 돼? 그것도 안 되는 거야?

@@ROWCOUNT는 정상 작동해!

SET NOCOUNT ON은 클라이언트로 보내는 메시지만 막는 거야.

프로시저 내부에서 @@ROWCOUNT로 행 수를 확인하는 건 여전히 가능.

SET NOCOUNT ON; UPDATE TCharacter SET level = 10 WHERE charunique = @uid -- 클라이언트에 메시지 안 보내지만, 내부에서는 확인 가능 IF @@ROWCOUNT = 0 BEGIN PRINT '업데이트할 캐릭터가 없음' RETURN -1 END

Part 5. 실제 프로젝트 사례

우리 프로젝트는 어떻게 되어 있어?

분석해보니까...

프로시저 SET NOCOUNT ON 상태
gp_LoadCharacter O 최적화됨
gp_save_pc O 최적화됨
gp_SaveQuest O 최적화됨
gp_make_pc X 레거시 (개선 필요)
gp_Add_Title X 레거시 (개선 필요)

최신 프로시저에는 다 들어가 있는데,

레거시 프로시저 일부에 빠져있음.

실제 코드 - gp_make_pc (개선 전)

CREATE PROCEDURE gp_make_pc @account_uid int, @char_name nvarchar(20), ... AS BEGIN -- SET NOCOUNT ON 없음! INSERT INTO TCharacter ... -- "(1개 행)" 전송 INSERT INTO TInventory ... -- "(50개 행)" 전송 INSERT INTO TSkill ... -- "(20개 행)" 전송 INSERT INTO TQuest ... -- "(1개 행)" 전송 ... -- 총 10개 이상 메시지! END

개선 후

CREATE PROCEDURE gp_make_pc @account_uid int, @char_name nvarchar(20), ... AS BEGIN SET NOCOUNT ON; -- 한 줄 추가! INSERT INTO TCharacter ... INSERT INTO TInventory ... INSERT INTO TSkill ... INSERT INTO TQuest ... -- 불필요한 메시지 0개 END

Part 6. 실제 성능 효과

진짜 효과가 있긴 해?

Microsoft 공식 문서에서도 권장하는 최적화야.

네트워크 트래픽 감소 효과

SET NOCOUNT OFF
+15~20%
불필요한 트래픽
SET NOCOUNT ON
0%
필수 데이터만
체감이 잘 안 되는데...

동접 1000명, 프로시저 호출 1000회/초 기준으로:

항목 OFF ON
메시지 전송 5000회/초 0회
추가 트래픽 250KB/초 0
1시간 누적 900MB 0

한 줄 추가로 시간당 900MB 트래픽 절약.

핵심 정리

  • SET NOCOUNT ON = "N rows affected" 메시지 전송 안 함
  • @@ROWCOUNT는 프로시저 내부에서 여전히 사용 가능
  • 네트워크 트래픽 15~20% 절약 효과
  • 결과셋 파싱 오류 방지 (OLE DB 등에서 중요)
  • 적용 방법: 프로시저 시작 부분에 SET NOCOUNT ON; 추가
  • 우리 프로젝트: 최신 프로시저는 적용됨, 레거시 일부 미적용

실무 체크리스트

새 프로시저 작성 시:

• AS BEGIN 바로 다음에 SET NOCOUNT ON; 추가

• 팀 코딩 컨벤션으로 정해두면 좋음

CREATE PROCEDURE gp_NewProcedure @param1 int AS BEGIN SET NOCOUNT ON; -- 반드시 첫 줄에! -- 이하 로직... END

레거시 프로시저 점검:

• SET NOCOUNT ON 없는 프로시저 찾기

• 한 줄 추가만 하면 되니까 리스크 낮음

-- SET NOCOUNT ON 없는 프로시저 찾기 SELECT name FROM sys.procedures WHERE OBJECT_DEFINITION(object_id) NOT LIKE '%SET NOCOUNT ON%'
