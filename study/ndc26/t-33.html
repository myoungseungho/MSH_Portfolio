AI가 좋아졌는데, 왜 데이터부터 손볼까

게임 운영팀의 지연에게 “오늘 매출이 왜 달라졌지?”라는 질문이 왔다고 해 보자. 모델은 문장을 잘 만들 수 있다. 하지만 지연의 게임에서 매출이 어느 결제를 뜻하는지, 오늘과 비교할 어제가 무엇인지 모르면 답을 믿기 어렵다.

넥슨이 발표에서 붙든 것은 바로 이 재료다. 모델은 빠르게 바뀌고, 외부 서비스가 대신할 수도 있다. 반면 게임을 플레이하며 쌓인 기록과 그 기록이 만들어진 사정은 회사 안에 있다.

🎤 발표에서는 파트너 조사상 기업의 57%가 자사 데이터가 아직 AI 레디 상태가 아니라고 답했다고 소개한다. 넥슨은 큰 변화를 만든 것이 모델 교체보다 데이터 파이프라인과 온톨로지 정비였다고 말한다.
🔤 AI 레디 데이터 — AI가 꺼내 볼 수 있고, 뜻을 헷갈리지 않으며, 다른 정보와의 관계까지 따라갈 수 있게 준비된 데이터다. 파일을 많이 모아 둔 상태만 뜻하지 않는다.
[지연의 질문: “오늘 매출이 왜 달라졌지?”] ↓ [매출의 뜻·기간·관련 사건을 함께 찾을 수 있는 데이터] ↓ [AI가 근거를 붙여 분석]
🧩 모델이 좋아질수록 “무슨 데이터를 근거로 삼았는가”가 더 눈에 띈다. 같은 질문에도 회사마다 다른 답이 나오는 이유는 모델 이름보다 각 회사의 맥락 데이터에 있을 수 있다.

모노레이크 1.0: 흩어진 장부를 같은 책상에 올리기

게임 플레이 중에는 게임 데이터가 쌓인다. 업무를 하면서는 또 다른 데이터가 쌓인다. 예전에는 담당 조직마다 장부와 열쇠가 따로 있었다. 운영 CS 담당자가 고객 문의를 확인하려면 개발팀이나 데이터 조직에 추출을 요청하고, 받은 뒤에야 답할 수 있었다.

🔤 데이터 사일로 — 곡물 창고가 칸막이로 나뉜 모습처럼, 데이터가 조직·시스템마다 갇혀 서로 보기 어려운 상태다. 데이터가 없어서가 아니라 필요한 사람이 제때 못 쓰는 문제가 된다.

모노레이크는 넥슨의 게임 데이터를 한곳에 모아, 같은 기준으로 안전하게 쓰도록 만든 전사 데이터 플랫폼이다. 발표에서는 Snowflake 기반의 데이터 레이크라고 설명한다. 여기서 중요한 장면은 저장 장소 하나보다, 여러 사람이 같은 장소를 쓴다는 점이다.

Before [CS] → 추출 요청 → [개발/데이터 조직] → 파일 전달 → [CS가 답변] After [CS] → 권한 있는 데이터 도구 → 필요한 기록 확인 → [고객에게 답변]
🎤 발표은 모노레이크 1.0의 목표를 “누구나 쉽게 데이터를 활용”하는 것으로 설명한다. 데이터베이스 통합, 표준화된 파이프라인과 통합 거버넌스, 비용 25% 절감·17배 이상 성능 향상 입증이 사일로 해소의 세 요소였다고 말한다. CS 조직에서는 고객 응답 속도가 빨라졌다는 사례도 소개했다.
🧩 한 저장소로 옮기는 일만으로는 CS의 답변이 빨라지지 않는다. 권한, 찾는 방법, 데이터의 공통 기준이 함께 갖춰져야 “기다리던 사람”이 직접 확인하는 장면으로 바뀐다.

통합은 복사가 아니라, 흐르는 길을 만드는 일

게임 데이터와 플랫폼 데이터 사이에는 사일로가 있었다. 넥슨은 표준화 게임 로그도 만들었지만, 로그만으로는 실시간성이 떨어지고 로그인 과정에서 빈틈도 있었다고 이야기한다. 라이브 데이터를 바로 건드리는 일도 쉽지 않았다.

🔤 데이터 파이프라인 — 수도관처럼, 데이터가 생긴 곳에서 필요한 저장소와 도구까지 흘러가는 길이다. 중간에서 형식을 맞추고, 누락이나 이상을 확인하는 일도 이 길에 들어간다.
[게임 플레이·플랫폼 업무] ↓ 서로 다른 형식과 저장 위치 [표준화·이동·확인하는 파이프라인] ↓ [모노레이크] → [게임 데이터 + 플랫폼 데이터 결합 활용]

여기서 “하나의 뷰”는 모든 사람이 똑같은 파일을 본다는 뜻에 가깝다. 같은 매출이라는 말을 써도 서로 다른 표를 가져오지 않게, 비교할 출발점을 맞추는 것이다.

발표의 CS 사례를 따라 만든 학습용 흐름이다. 실제 처리 시간은 대본에 제시되지 않았다.

🧩 실시간성이 필요한 데이터와 안전하게 운영 중인 라이브 시스템 사이에는 긴장이 있다. 발표가 ‘통합’뿐 아니라 파이프라인을 말한 이유는, 데이터를 옮기는 길 자체도 제품의 일부이기 때문으로 읽을 수 있다.

누구나 쓰게 하면, 아무렇게나 쓰게 되는가

비엔지니어가 데이터를 직접 쓰기 시작하면 좋은 일만 생기지는 않는다. 지연이 넓은 기간의 데이터를 반복해서 찾거나, 출처를 모르는 표를 기준으로 판단할 수도 있다. 그래서 “열어 준다”와 “방치한다”는 다른 말이다.

🔤 거버넌스 — 데이터에 이름표와 사용 규칙을 붙이고, 누가 어느 범위까지 볼지 정하며, 이상한 사용을 알아차리는 운영 약속이다. 도서관에서 책의 출처·분류·대출 규칙을 함께 관리하는 모습에 가깝다.

🎤 발표에서는 출처와 경로를 담은 메타데이터, 권한 통제, 미리 만든 쿼리와 쿼리 빌더, 과도한 쿼리를 감지하는 알림을 설명한다. 데이터를 모으기 시작할 때 표준화와 거버넌스를 병행하고, 이후 모니터링·운영 방법론을 갖추는 것이 중요하다고 말한다.

🧩 거버넌스는 데이터를 못 쓰게 하는 울타리만은 아니다. 자주 쓰는 안전한 길을 미리 만들면, 비전문가도 더 빨리 움직이고 엔지니어는 예외와 품질 문제에 집중할 수 있다.

모노레이크 2.0: AI에게 ‘매출’의 뜻을 가르치기

사람은 “DAU가 떨어졌다”는 말을 들으면 팀에서 쓰는 계산법과 어제의 상황을 떠올린다. AI는 그 배경을 저절로 알지 못한다. 같은 단어가 팀마다 다른 계산을 가리키면, 말이 매끄러운 답을 받아도 판단은 흔들린다.

🔤 DAU — Daily Active Users의 줄임말이다. 하루 동안 활동한 이용자 수를 말한다. 다만 ‘활동’을 어떤 행동으로 셀지는 회사의 정의가 필요하다.
🔤 온톨로지 — 여기서는 데이터 용어의 뜻을 정하고, 서로 어떤 관계인지와 판단할 때 볼 맥락을 연결해 둔 지식의 지도다. ‘매출’이라는 표지판만 세우는 것이 아니라, 계산에 쓰는 데이터와 함께 볼 지표도 이어 둔다.
[“오늘 DAU가 낮다”] ↓ [DAU의 계산 규칙] + [데이터 품질] + [연결된 사건·지표] ↓ [AI가 질문의 단어를 업무 맥락에서 해석]
🎤 발표은 AI 레디 데이터의 조건으로 ① AI가 쉽게 접근할 환경, ② 의미 표준화와 데이터 신뢰성, ③ 데이터 간 연결 관계와 맥락 해석을 제시한다. 넥슨은 용어의 의미를 정의하고 관계·판단 기준을 입히는 과정을 온톨로지라고 부른다.
🧩 ‘매출’이라는 열 이름을 한 번 통일하는 것보다 어려운 일은, 계산 규칙이 바뀔 때 관련된 지표와 설명도 함께 고치는 일이다. 온톨로지는 그 변경 지점을 드러내는 지도 역할을 할 수 있다.

온톨로지 팩토리: 베테랑의 머릿속 판단을 꺼내는 반복 작업

운영 베테랑 수현은 특정 보스에서 유저가 막히는 패턴을 본다. 수현에게는 익숙한 판단이다. 하지만 “어떤 기록을 보고, 어떤 경우를 제외하고, 무엇과 비교했는지”를 규칙으로 적으라고 하면 이야기가 길어진다. 이런 말로 다 쓰지 않은 경험을 암묵지라고 한다.

🔤 암묵지 — 일을 오래 해 온 사람이 감각적으로 아는 판단 기준이다. 자전거를 타는 법을 몸으로 알지만, 처음 타는 사람에게 모든 균형 조절을 문장으로 옮기기 어려운 것과 비슷하다.

발표에서 온톨로지 팩토리는 현업과 기술팀이 이 판단을 함께 꺼내고, AI에 넣어 보고, 현업이 다시 결과를 확인하는 태스크포스형 작업이다. 한 번 입력하고 끝나는 사전 제작이 아니다.

[수현의 업무 판단] ↓ 꺼내어 구조화 [AI가 읽을 맥락 데이터] ↓ 질문·결과 확인 [수현의 “맞음/틀림” 피드백] ↓ [보정된 맥락] ─────────────────┘

🎤 발표에서는 현업의 암묵지를 잘 끌어내 구조화하는 일이 AI 품질을 좌우한다고 말한다. 현업 노하우 수집 → AI 적용 → 결과 확인 → 맞고 틀림 피드백 → 재학습·보정의 루프를 설명한다.
🧩 현업에게 ‘데이터를 내 달라’고만 요청하면 본업과 경쟁한다. 자기 판단이 다음 결과에서 어떻게 반영됐는지 다시 확인하게 하는 루프가 있어야, 지식이 일방적으로 빠져나가는 느낌을 줄일 수 있다.

AI 서치와 능동형 에이전트: 질문에 답하고, 먼저 알려 주기

지연이 “오늘 비가 오는데 매출에 영향이 있어?”라고 묻는다. 발표의 AI 서치는 자연어 질문으로 리포트와 분석 결과를 만들도록 내부에서 사용하는 서비스다. 여기서 앞서 만든 온톨로지는 AI가 질문 속 단어를 회사의 데이터 의미와 연결하게 돕는다.

🔤 자연어 — 사람이 평소 말하듯 쓰는 문장이다. SQL처럼 정해진 명령 문법을 외우지 않고 질문하는 방식을 말한다.

한 걸음 더 가면, 사람이 화면을 열기 전에 AI가 먼저 신호를 보낼 수 있다. 발표에서는 사람이 “CPU가 90% 이상이면 알려 줘”라고 한 줄의 숫자 규칙을 정하는 대신, 학습한 맥락으로 이상 징후를 미리 탐지해 알려 주는 브리핑 서비스를 설명한다.

질문형 [지연] → “오늘 매출은?” → [AI 서치] → [리포트·분석] 능동형 [데이터 흐름] → [학습한 맥락과 비교] → [이상 징후] → [지연에게 브리핑]
🎤 AI 서치는 내부에서 열어 사용 중이며, 발표에서는 메이플스토리 모바일에 처음 적용한 뒤 전체 넥슨 게임으로 확대하는 상황이라고 말한다. 능동형 에이전트는 정의한 맥락을 바탕으로 이상 데이터를 탐지해 알리는 방향으로 내부 서비스에 적용 중이라고 소개했다.
🧩 미리 알림은 단순 임계치보다 더 많은 맥락을 쓰려는 시도다. 그만큼 “왜 알렸는지”를 사람이 확인할 수 있게 근거와 피드백 경로를 남기는 일이 중요해진다.

처음 시작하는 개발자/취준생이 가져갈 5가지

이 발표는 거대한 플랫폼 이름을 외우는 이야기가 아니다. 게임의 기록이 실제 판단과 서비스로 이어지려면, 저장·의미·사람의 검증이 함께 돌아야 한다는 이야기다.

  1. 데이터를 모으기 전에 쓸 장면을 그려라. CS 담당자가 고객 문의를 직접 확인하는 장면처럼, 사용자가 바뀌는 순간을 먼저 잡는다.
  2. 표준화와 거버넌스는 나중의 청소가 아니다. 데이터를 모으는 첫날부터 출처·권한·사용량을 같이 설계한다.
  3. AI에는 값뿐 아니라 뜻과 관계가 필요하다. 지표의 계산법과 비교할 맥락이 없으면 그럴듯한 답도 업무 판단이 되기 어렵다.
  4. 현업의 암묵지를 검증 루프로 바꿔라. 베테랑의 판단을 한 번 받아 적는 대신, 결과를 다시 보여 주고 보정한다.
  5. 작게 시작해 효능을 보인다. 발표의 조언처럼 비즈니스에 도움 되는 한두 데이터를 골라 고도화하고, 그 경험을 확장한다.
