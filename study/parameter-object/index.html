파라미터 객체 도입

리팩토링 #8 기본 기법 Introduce Parameter Object

파라미터가 너무 많은 함수는 어떻게 해?

파라미터가 3개를 넘어가면 함수 시그니처가 복잡해지고, 호출하는 곳에서 실수하기 쉽습니다. 파라미터 객체(Parameter Object)를 도입하면 해결됩니다.

❌ 파라미터가 너무 많은 함수 
// 호출할 때마다 순서 헷갈림
void CreateCharacter(
    int accountId,
    const char* name,
    int classType,
    int gender,
    int hairStyle,
    int hairColor,
    int faceType,
    int skinColor,
    int startingMap,
    int startingX,
    int startingY
);

// 호출하는 곳 - 무슨 파라미터인지 알 수 없음
CreateCharacter(1001, "전사", 1, 0, 3, 2, 1, 0, 100, 500, 300);

⚠️ Long Parameter List 코드 스멜

파라미터가 4개 이상이면 "Long Parameter List" 코드 스멜입니다. 순서 실수, 가독성 저하, 확장 어려움의 원인이 됩니다.

파라미터 객체로 어떻게 바꿔?

관련 있는 파라미터들을 하나의 구조체/클래스로 묶습니다:

❌ Before 11개 파라미터 
void CreateCharacter(
    int accountId,
    const char* name,
    int classType,
    int gender,
    int hairStyle,
    int hairColor,
    int faceType,
    int skinColor,
    int startingMap,
    int startingX,
    int startingY
);

// 호출
CreateCharacter(
    1001, "전사", 1, 0,
    3, 2, 1, 0,
    100, 500, 300
);
✅ After 파라미터 객체 
struct CharacterAppearance {
    int hairStyle;
    int hairColor;
    int faceType;
    int skinColor;
};

struct SpawnPosition {
    int mapId;
    int x;
    int y;
};

struct CharacterCreateParams {
    int accountId;
    std::string name;
    int classType;
    int gender;
    CharacterAppearance appearance;
    SpawnPosition spawn;
};

void CreateCharacter(
    const CharacterCreateParams& params
);
✅ 호출하는 곳 
CharacterCreateParams params;
params.accountId = 1001;
params.name = "전사";
params.classType = CLASS_WARRIOR;
params.gender = GENDER_MALE;
params.appearance.hairStyle = 3;
params.appearance.hairColor = 2;
params.appearance.faceType = 1;
params.appearance.skinColor = 0;
params.spawn.mapId = 100;
params.spawn.x = 500;
params.spawn.y = 300;

CreateCharacter(params);  // 명확!

💡 부가 효과

  • 구조체에 검증 로직을 추가할 수 있음
  • 관련 데이터가 함께 이동함
  • 새 필드 추가 시 함수 시그니처 변경 불필요

리팩토링 절차는?

  1. 1

    관련 파라미터 식별

    항상 함께 전달되는 파라미터 그룹을 찾습니다. (예: x, y, z 좌표)

  2. 2

    파라미터 객체 클래스 생성

    그룹을 담을 구조체나 클래스를 만듭니다. C++에서는 보통 struct가 적합합니다.

  3. 3

    함수 시그니처 변경

    개별 파라미터 대신 객체를 받도록 수정합니다.

  4. 4

    호출부 수정

    모든 호출 위치에서 객체를 생성하여 전달하도록 수정합니다.

  5. 5

    동작 이동 (선택)

    파라미터와 관련된 로직이 있다면 객체 내부로 이동시킵니다.

객체에 동작도 넣을 수 있어?

네, 파라미터 객체가 단순 데이터 홀더에서 풍부한 객체로 진화할 수 있습니다:

데이터 → 동작 추가 
struct CharacterStats {
    int level;
    int hp;
    int maxHp;
    int mp;
    int maxMp;

    // 검증 로직 추가
    bool IsValid() const {
        return level > 0 && level <= MAX_LEVEL
            && hp >= 0 && hp <= maxHp
            && mp >= 0 && mp <= maxMp;
    }

    // 계산 로직 추가
    float GetHpPercent() const {
        return maxHp > 0 ? (float)hp / maxHp * 100.0f : 0.0f;
    }

    // 변환 로직 추가
    bool IsDead() const {
        return hp <= 0;
    }
};

// 사용
if (!saveData.stats.IsValid()) {
    LogError("Invalid character stats");
    return false;
}

✅ 동작 추가의 장점

  • 검증 로직이 데이터와 함께 있음
  • 중복 검증 코드 제거
  • 데이터 무결성 보장

언제 파라미터 객체를 쓰면 안 돼?

⚠️ 과도한 객체화 주의

  • 파라미터가 2-3개일 때는 굳이 객체화 불필요
  • 함께 다니지 않는 파라미터를 억지로 묶지 말 것
  • 성능이 극도로 중요한 핫패스에서는 구조체 복사 비용 고려
❌ 과도한 객체화 
// 이건 그냥 두 개 파라미터가 나음
struct AddParams {
    int a;
    int b;
};
int Add(const AddParams& p);  // 과하다

// 이게 낫다
int Add(int a, int b);

핵심 요약

📌 파라미터 객체 핵심

  • 파라미터 4개 이상이면 객체화 고려
  • 함께 다니는 파라미터를 그룹으로 묶기
  • 객체에 검증/계산 로직 추가 가능
  • 새 필드 추가 시 시그니처 변경 불필요
  • 2-3개 파라미터는 그냥 두기
