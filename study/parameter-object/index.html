파라미터 객체 도입

Introduce Parameter Object - 긴 파라미터 리스트를 객체로 묶기

Part 1. 파라미터가 너무 많아!

함수에 파라미터가 10개 넘는데 어떡해?

파라미터가 3개를 넘으면 Long Parameter List 코드 스멜이야.

순서 헷갈리고, 실수하기 쉽고, 새 파라미터 추가할 때 지옥이지.

// 호출할 때마다 순서 헷갈림 void CreateCharacter( int accountId, const char* name, int classType, int gender, int hairStyle, int hairColor, int faceType, int skinColor, int startingMap, int startingX, int startingY ); // 호출하는 곳 - 무슨 파라미터인지 알 수 없음 😱 CreateCharacter(1001, "전사", 1, 0, 3, 2, 1, 0, 100, 500, 300);
1이 뭐고 0이 뭔지 어떻게 알아?

알 수 없어. 매번 함수 정의를 봐야 해. 그게 문제야.

Part 2. 파라미터 객체로 해결

어떻게 바꾸면 돼?

관련 있는 파라미터들을 구조체로 묶어!

// ✅ 관련 데이터를 구조체로 그룹화 struct CharacterAppearance { int hairStyle; int hairColor; int faceType; int skinColor; }; struct SpawnPosition { int mapId; int x; int y; }; struct CharacterCreateParams { int accountId; std::string name; int classType; int gender; CharacterAppearance appearance; SpawnPosition spawn; }; // 함수 시그니처가 깔끔해짐! void CreateCharacter(const CharacterCreateParams& params);
// 호출하는 곳 - 의미가 명확! CharacterCreateParams params; params.accountId = 1001; params.name = "전사"; params.classType = CLASS_WARRIOR; params.gender = GENDER_MALE; params.appearance.hairStyle = 3; params.appearance.hairColor = 2; params.spawn.mapId = 100; params.spawn.x = 500; params.spawn.y = 300; CreateCharacter(params); // 깔끔!

Part 3. 우리 프로젝트에서 적용할 곳

조선협객전에서 이런 코드 있어?

DB 프로시저 호출 쪽에 엄청 많아.

// Procedure_SavePC.h에서 발견된 패턴 void SaveCharacter( DWORD dwAccUnique, DWORD dwCharUnique, int nLevel, __int64 i64Exp, int nHP, int nMP, int nStr, int nDex, int nInt, int nCon, int nMapId, int nPosX, int nPosY // ... 더 많은 파라미터들 );
// ✅ 리팩토링 후 struct CharacterIdentity { DWORD accountId; DWORD characterId; }; struct CharacterStats { int level; __int64 exp; int hp, mp; int str, dex, intelligence, con; }; struct CharacterPosition { int mapId; int x, y; }; struct CharacterSaveData { CharacterIdentity identity; CharacterStats stats; CharacterPosition position; }; void SaveCharacter(const CharacterSaveData& data);
부가 효과

• 구조체에 검증 로직을 추가할 수 있음
• 관련 데이터가 함께 이동함
• 새 필드 추가 시 함수 시그니처 변경 불필요

Part 4. 객체에 동작도 넣을 수 있어

그냥 데이터만 담는 거야?

검증이나 계산 로직도 넣을 수 있어!

struct CharacterStats { int level; int hp, maxHp; int mp, maxMp; // 검증 로직 추가 bool IsValid() const { return level > 0 && level <= MAX_LEVEL && hp >= 0 && hp <= maxHp && mp >= 0 && mp <= maxMp; } // 계산 로직 추가 float GetHpPercent() const { return maxHp > 0 ? (float)hp / maxHp * 100.0f : 0.0f; } // 상태 체크 로직 bool IsDead() const { return hp <= 0; } }; // 사용 예 if (!saveData.stats.IsValid()) { LogError("Invalid character stats"); return false; }

Part 5. 언제는 안 해도 돼?

파라미터 2개도 객체로 묶어?

아니, 과하게 하지 마.

과도한 객체화 주의

• 파라미터가 2-3개일 때는 굳이 객체화 불필요
• 함께 다니지 않는 파라미터를 억지로 묶지 말 것
• 성능 극도로 중요한 핫패스에서는 복사 비용 고려
// ❌ 과도한 객체화 struct AddParams { int a; int b; }; int Add(const AddParams& p); // 과하다! // ✅ 이게 낫다 int Add(int a, int b);

핵심 정리: 파라미터 객체

  • 파라미터 4개 이상이면 객체화 고려
  • 함께 다니는 파라미터를 그룹으로 묶기
  • 객체에 검증/계산 로직 추가 가능
  • 새 필드 추가 시 시그니처 변경 불필요
  • 2-3개 파라미터는 그냥 두기
