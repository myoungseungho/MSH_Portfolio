Part 1. 프로젝트 DH가 뭐야?

프로젝트 DH는 어떤 게임이야?

말 타고 용 사냥하는 액션 RPG야.

6km x 6km 광대한 맵에서 활, 화기, 직접 전투로 용을 잡는 게임이야.

핵심 특징

- 6km x 6km 오픈월드
- 언리얼 엔진 4 사용
- 멀티플레이어 지원
- "실버 바인 모션 엔진" 자체 개발 (절차적 애니메이션)

Part 2. "용처럼 날게 해주세요"가 뭔데?

디렉터가 뭘 원했어?

정리하면 이래:

1. 공중 길찾기 기능 필요

2. 6km x 6km 맵에서 동작

3. 기획자 의도대로 가이드 가능

4. "용처럼 날게 해주세요"

용처럼 난다는 게 뭔 소리야? 용을 본 적이 있어?

바로 그게 문제야! 용을 직접 본 일이 없으니까 레퍼런스를 찾아봤어.

드라마, 영화, 게임에 나오는 용을 분석했지.

용의 비행 특징 분석 결과: 기본 모션: 이륙, 착륙, 수직 상승/하강, 활강, 선회, 급정지 특수 모션: 수직 강하, 정지 비행, 절벽 따라 활강, 스파이럴 핵심 발견: - 방향 전환 시 일정한 선회 반경 유지 - 속도를 무시한 급선회는 없음 - 용도 물리 법칙의 지배를 받음!
그럼 시스템 요구사항이 뭐야?

5가지로 정리했어:

요구사항 이유
3차원 패스 파인딩 공중이니까 당연히
부드러운 경로 뚝뚝 끊기면 용답지 않아
즉각적 애니메이션 반응 상황에 맞는 모션 필요
기획자 의도 반영 원하는 대로 비행 유도
작은 데이터 6km 맵이니까 용량 터지면 안돼

Part 4. 하늘길 시스템이 뭐야?

어떤 아이디어로 만들었어?

"실크로드" 개념이야!

용을 위한 안전한 길을 미리 깔아놓고, 그 위에서 자유롭게 비행하게 하는 거지.

고속도로 비유

고속도로가 있으면 차가 IC에서 진입 → 도로 따라 이동 → IC에서 퇴출하잖아?

Waypoint = IC (인터체인지)
Sky Road = 고속도로 본선
Probe = 내비게이션이 안내하는 경로
하늘길 시스템 구조: [Waypoint A] -------- Sky Road (Spline) -------- [Waypoint B] | | | 안전 영역 안전 반경 안전 영역 (구 형태) (부피를 가진 길) (구 형태) | v 실제 이동 경로 생성 | v [Probe] --> [Dragon]
각 구성요소가 뭐 하는 거야?

Waypoint: IC 역할. 안전 반경 구체, 연결된 길 목록 관리

Sky Road: 스플라인으로 만든 도로. 부피(안전 반경)를 가진 길

Probe: 용을 이끄는 선행 객체. 전체 경로 정보 보유

장점

안전이 보장된 길 위에서만 계산하니까
→ 실행 비용 낮음
→ 자연스러운 비행 정보 획득 가능

Part 5. 스플라인이 뭔데?

스플라인 커브가 뭐야? 왜 써?

점 몇 개로 부드러운 곡선을 만드는 수학적 방법이야.

복셀은 직선으로만 연결되지만, 스플라인은 곡선이 되니까 용 움직임에 딱이야.

Bezier랑 Hermite가 뭐가 달라?

Cubic Bezier: 4개 점으로 곡선 만듦. 연쇄 보간 방식.

Cubic Hermite: 2개 점 + 기울기(탄젠트)로 곡선 만듦.

둘 다 서로 변환 가능해!

연속성(Continuity)이 뭐야?

커브가 얼마나 부드러운지 나타내는 거야.

연속성 의미 효과
C0 위치만 연속 점이 이어져 있음
C1 1차 미분 연속 (속도) 일정한 속도로 이동
C2 2차 미분 연속 (가속도) 기울기 변화량까지 부드러움
C1 연속이 안 되면?

A-B 구간은 느리게 가다가 B-C 구간에서 갑자기 빨라짐!
→ 용이 뚝뚝 끊기듯 움직임 → 부자연스러움
언리얼 스플라인 컴포넌트 그냥 쓰면 안 돼?

문제가 있어. Arrive/Leave 탄젠트 길이가 다를 수 있어서 C1 연속이 안 될 수 있어.

그래서 FInterpCurve 템플릿으로 직접 만들었어.

Part 6. 길찾기는 어떻게 해?

패스 파인딩 전체 흐름이 어떻게 돼?

5단계로 진행돼:

패스 파인딩 절차: [1] 출발/도착 → 하늘길로 임시 링크 연결 | v [2] A* 그래프 탐색 (최단경로) | v [3] 들어오는 길 / 나가는 길 경로 생성 | v [4] 전체 경로 스무딩 | v [5] 최종 스플라인 완성!
임시 링크가 뭐야?

출발/도착 지점이 하늘길 밖에 있을 수 있잖아.

용 관점에서 하늘 보고 → 보이는 모든 하늘길에 임시 링크 연결 → A* 탐색

들어오는 길/나가는 길은 어떻게 부드럽게 만들어?

직선으로 연결하면 부자연스럽잖아.

후보 공간 탐색 알고리즘을 개발했어:

후보 공간 탐색 알고리즘: [출발점 탄젠트] ------+------ [도착점 탄젠트] | +------+------+ | 후보 공간 | +------+------+ | +----+----+----+----+ | P1 | P2 | P3 | P4 | <-- 후보 지점들 +----+----+----+----+ | v 선호도 계산 → 유효성 검증 → 스플라인 생성
경로 스무딩은 왜 해?

Waypoint에서 꺾이는 지점을 부드럽게 만들어야 해.

안전 반경 내에서 벗어나기 직전 두 지점을 찾아서 부드럽게 연결!

스무딩 핵심

안전 반경 데이터가 있으니까 검사 비용이 크지 않아!
꺾이는 부분만 부드럽게 → 자연스러운 비행

Part 7. 프로브가 뭐야? 왜 필요해?

그냥 스플라인 따라가면 안 돼?

처음엔 그렇게 생각했어. 시간 t 위치로 용 위치만 갱신하면 될 줄.

근데 문제가 생겼어:

단순 스플라인 따라가기의 문제: 1. 단조로운 움직임 - 모션이 변화 없이 일정 2. Re-parameterization 정밀도 - 정밀도 낮으면 속력 일정 X 3. 경로 이탈 제어 불가 - 충돌/피격 시 대응 못함
그래서 프로브가 뭔데?

예인선(Tugboat) 모델이야!

작은 배가 큰 배를 이끄는 것처럼, 프로브가 용을 이끄는 거야.

예인선 비유

항구에서 큰 배가 혼자 움직이기 어려우면, 작은 예인선이 앞에서 끌어주잖아?

프로브 = 예인선 (스플라인 위를 정직하게 이동)
용 = 큰 배 (프로브를 향해 따라감)

프로브가 용의 속도 제어, 완충 장치 역할!
프로브-용 관계: Spline Path: =====[Probe]===================> | | 따라감 (적정 거리 유지) v [Dragon] | v 위치/회전/모션 갱신

Part 8. 비행 유형은 어떻게 정해?

용이 언제 날개짓하고 언제 활강하는지 어떻게 알아?

선형 속도와 회전 속도의 변화로 결정해.

경로의 Z(높이) 성분에서 극점(Extrema)을 분석하는 거야.

극점 분석: 1차 도함수 극점: 기울기가 +에서 -로, 또는 -에서 +로 바뀌는 지점 2차 도함수 극점: 기울기 변화량이 바뀌는 지점 (변곡점) 예시 - 하강 후 상승: A-B 구간: 속도가 점진적으로 줄어듦 B 지점: 더 이상 속도가 줄어들 수 없음 B-C 구간: 상승을 위해 날개짓 시작!
극점은 어떻게 계산해?

Cubic Hermite 커브는 3차 다항식이야.

1차 미분은 2차 다항식이니까 근의 공식으로 바로 풀어!

// 3차 다항식 P(t) = at^3 + bt^2 + ct + d // 1차 미분: P'(t) = 3at^2 + 2bt + c (근의 공식!) // 2차 미분: P''(t) = 6at + 2b (1차 방정식!) // 코드 1-2줄로 구현 가능! float t1 = (-2*b + sqrt(4*b*b - 12*a*c)) / (6*a); float t2 = (-2*b - sqrt(4*b*b - 12*a*c)) / (6*a);
뱅크 앵글(Bank Angle)은 뭐야?

비행기가 곡선 돌 때 옆으로 기울이잖아? 그게 뱅크턴이야.

빠른 선회하려면 양력이 회전 중심을 향하게 몸을 틀어야 해.

뱅크 앵글 공식
  • 속력 일정 시, 선회 반경 작아짐 = 선회율 상승
  • 선회 반경은 수평 곡률에 비례
  • 수평 곡률 상승 = 뱅크 앵글 상승
  • X, Y 성분만으로 곡률 계산 (Z 불필요)
결과

휘어진 경로에서 용의 몸체가 회전 방향으로 기울어짐!
→ 자연스러운 롤(Roll) 회전 구현

Part 9. 프로브와 용은 어떻게 움직여?

프로브 제어는 어떻게 해?

프로브는 단순해:

프로브 제어 (단순): 1. 용과 적정 거리 유지하며 스플라인 위 이동 2. 일정한 속력 유지 3. 용과 가까우면 → 속력 높임 4. 용과 멀면 → 속력 낮춤
용 움직임 제어는?

용은 복잡해:

용 움직임 제어 (복잡): 1. 프로브 현재 구간 유형 확인 2. 현재 위치 기울기로 가속력 계산 3. 가속력 → 속력 계산 4. 프로브 방향으로 속력만큼 이동 5. 프로브 방향 정렬을 위한 회전 속력 계산 6. 롤 회전 요소 누적 7. 최종 회전 속력 → 델타 로테이션 계산
모션 연동

패스 유형이 바뀌는 시점에 용 객체에 통지
→ 실버 바인 모션 엔진이 해당 모션 재생!
타겟이 움직이면 어떻게 해?

Pruning & Grafting (가지치기 & 접붙이기)!

경로 재탐색 (Re-pathfinding): 기존: ====[Dragon]=====[Cut Point]=====>[Old Target] | 잘라냄 (Pruning) | v 새로운 경로 생성 (Grafting) | v 새 경로: ====[Dragon]=====[Cut Point]---->[New Target] 위치와 탄젠트 유지한 채 새 경로 접붙이기!

Part 10. 언리얼 엔진에 어떻게 붙였어?

기존 언리얼 내비게이션 흐름이 어떻게 돼?

원래 흐름은 이래:

기존 언리얼 내비게이션: [AI Controller] → MoveTo() ↓ [Navigation System] → FindPath() ↓ [NavMesh Data] (Recast) ↓ [Path Following Component] → FollowPathSegment() ↓ [AI Agent 이동]
하늘길 시스템은 어떻게 끼워넣었어?

확장과 교체를 적절히 섞었어:

기존 변경 방식
AI Controller DH AI Controller 확장 (FlyTo 추가)
Navigation System Flight Path System 자체 개발
NavMesh Data 하늘길 데이터 자체 개발
Path Following Component DH Path Following Component 교체
지상/공중 분리
  • 지상 이동: 기존 Path Following Component 그대로
  • 공중 이동: 프로브의 Update/Follow 로직으로 대체
에디터 툴은?

언리얼 에디터 내에서 바로 사용 가능!

스플라인으로 쉽게 편집, 안전 반경 자동 계산까지.

Part 11. 앞으로 뭘 더 해야 해?

성능은 괜찮아?

아직 자세한 프로파일링은 안 했지만, 게임 플레이에 영향 없는 수준이야.

근데 최적화할 부분은 있어:

최적화 대상

1. 스플라인 객체 생성/파괴 - 빈번해서 메모리 부담
2. 레이트레이스/캡슐 오버랩 테스트 - 충돌 처리 다수
아직 안 된 기능은?

할 거 많아:

미구현 사항 기대 효과
날개짓 맞는 요 움직임 더 자연스러운 움직임
물리 법칙 기반 움직임 현재는 "그럴싸하게" 처리 중
스플라인 오프셋팅 가장자리로도 이동 가능
비동기 패스 파인딩 AI 시스템과 유기적 연동
복셀 하이브리드 복셀 + 하늘길 조합
개발하면서 뭘 느꼈어?

"연구와 실전은 많이 다르다"

설계 시 고려 못한 코너 케이스가 엄청 많았어.

AI 내비게이션은 역사가 깊지만 아직 실버불릿이 없어.

"욕심과 현실 사이에서 균형 잡기가 어렵다"

핵심 정리: 용의 공중 내비게이션

  • 문제 - 기존 NavMesh는 지상 전용, 복셀은 부드러운 곡선 X
  • 해결 - 스플라인 기반 "하늘길" 시스템 자체 개발
  • 구성 - Waypoint (IC) + Sky Road (도로) + Probe (내비)
  • 패스 파인딩 - 임시 링크 → A* → 스무딩 → 스플라인
  • 패스 팔로잉 - 프로브(예인선)가 용을 이끔
  • 비행 유형 - 극점 분석으로 날개짓/활강 구분
  • 뱅크 앵글 - 수평 곡률로 롤 회전 계산
  • 디자이너 의도 - 하늘길 배치로 비행 패턴 유도 가능
