이 변수 누가 바꿨어요?

데이터 중단점 (Data Breakpoint) — 값이 바뀌는 순간을 잡아라

Part 1. 문제 상황

변수 값이 이상한데, 누가 바꿨는지 모르겠어

이런 상황이다:

- m_nHP가 갑자기 음수가 됐다

- pItem이 어느 순간 nullptr이 됐다

- 배열의 특정 원소가 이상한 값으로 바뀌어 있다

어디서 바뀌는지 찾으려면 모든 코드에 중단점을 걸어야 할까?

그럼 어떻게 해?

데이터 중단점(Data Breakpoint)을 쓴다.

"이 메모리 주소의 값이 바뀌면 멈춰라"

→ 값을 바꾸는 코드에서 자동으로 멈춤

Part 2. 데이터 중단점 설정하기

1 먼저 일반 중단점에서 멈추기

감시할 변수가 유효한 상태에서 멈춰야 한다.

예: 객체가 생성된 직후, 값이 정상일 때

2 Watch 창에서 주소 확인

Watch 창에 &변수명을 입력해서 주소를 확인한다.

예: &pPlayer->m_nHP → 0x00007FF6A1B23400

3 데이터 중단점 설정

Debug → New Breakpoint → Data Breakpoint

또는 Watch 창에서 변수 우클릭 → "Break When Value Changes"

// 예: pPlayer의 m_nHP가 바뀌는 순간을 잡고 싶다 // 1. 아무 중단점에서 멈춘 상태에서 // 2. Watch 창에 입력: &pPlayer->m_nHP // 결과: 0x00007FF6A1B23408 // 3. Debug → New Breakpoint → Data Breakpoint // 주소: 0x00007FF6A1B23408 // 크기: 4 (int는 4바이트) // 4. F5로 실행 → m_nHP가 바뀌는 순간 자동으로 멈춤!

Part 3. 데이터 중단점의 제한사항

왜 4개까지만 걸 수 있어?

데이터 중단점은 CPU의 하드웨어 디버그 레지스터를 사용한다.

x86/x64 CPU에는 DR0~DR3, 딱 4개의 레지스터만 있다.

→ 동시에 4개까지만 감시 가능

제한사항 설명 해결책
최대 4개 하드웨어 레지스터 한계 필요 없는 것 삭제 후 추가
주소 고정 객체가 이동하면 추적 불가 객체 생성 직후 설정
로컬 변수 주의 함수 종료 시 스택 해제 전역/힙 변수에 사용 권장

Part 4. 실전 예시

예시 1: 플레이어 HP가 갑자기 음수가 된다
// 문제: 어디선가 m_nHP가 음수로 바뀜 // 1. 플레이어 생성 직후 중단점에서 멈춤 CPlayer* pPlayer = new CPlayer(); // ← 여기서 멈추고 // 2. Watch 창: &pPlayer->m_nHP → 0x12345678 // 3. Data Breakpoint 설정: 0x12345678, 4바이트 // 4. F5 실행 → 잠시 후 멈춤! // → 콜스택 확인: CMonster::Attack() → Damage 계산 버그 발견
예시 2: 포인터가 갑자기 nullptr이 된다
// 문제: m_pWeapon이 갑자기 nullptr // 1. 무기 장착 후 중단점에서 멈춤 pPlayer->EquipWeapon(pWeapon); // ← 여기서 멈추고 // 2. Watch 창: &pPlayer->m_pWeapon → 0x12345680 // 3. Data Breakpoint 설정: 0x12345680, 8바이트 (포인터는 8바이트) // 4. F5 실행 → 멈춤! // → 콜스택 확인: CPlayer::UnequipAll() 에서 nullptr로 설정됨
예시 3: 배열 특정 원소가 덮어써진다
// 문제: m_aInventory[50]이 이상한 값으로 바뀜 // 1. Watch 창: &m_aInventory[50] → 0x12345800 // 2. Data Breakpoint 설정: 0x12345800, sizeof(CItem) // 3. F5 실행 → 멈춤! // → 범인: 버퍼 오버런으로 다른 배열이 침범함

Part 5. 데이터 중단점 vs 조건부 중단점

상황 데이터 중단점 조건부 중단점
"누가 바꿨는지" 찾기 적합 (자동 감지) 부적합 (코드마다 걸어야 함)
"특정 값일 때" 멈추기 가능 (변경 감지 후 조건 추가) 적합 (조건식 직접 지정)
성능 빠름 (하드웨어 지원) 느림 (매번 조건 평가)
개수 제한 4개 무제한

실무 팁

1. 객체 생성 직후 설정하기 - 객체가 이동하면 주소가 바뀌므로

2. 4개 제한 활용하기 - 한 번에 의심 변수 4개 감시 → 범인 좁히기

3. 크기 정확히 지정 - int=4, pointer=8, double=8, bool=1

4. 멈추면 콜스택 먼저 - "어디서 바꿨는지"가 바로 보임

핵심 정리

  • 데이터 중단점 = 메모리 값이 바뀌면 자동으로 멈춤
  • 설정 방법: Watch 창에서 &변수 → 주소 확인 → Data Breakpoint
  • 제한: 최대 4개 (하드웨어 레지스터 한계)
  • 용도: "누가 이 값을 바꿨는지" 찾을 때 최고
  • 주의: 객체 이동 시 주소 변경됨, 로컬 변수는 스택 해제 주의
