Guard Clauses

보호 구문 - 예외 상황을 먼저 처리

Part 1. 보호 구문이 뭐야?

if-else가 너무 깊어져서 읽기 힘들어.

예외 상황을 먼저 처리하고 빠져나가.

비정상 케이스를 함수 초반에 걸러내면 들여쓰기가 줄어.

어떻게 다른데?

중첩 if-else: "사용자 있으면, 활성 상태면, 권한 있으면... 처리"

Guard Clause: "사용자 없으면 리턴. 비활성이면 리턴. → 이제 처리"

경비실 검문 비유

건물 입구에서:
- 신분증 없음? → 돌려보냄
- 예약 없음? → 돌려보냄

검문 통과한 사람만 안으로.
코드도 함수 입구에서 걸러내면 본체가 깔끔해져.

Part 2. return 여러 개 괜찮아?

함수에 return 하나만 있어야 한다던데?

오래된 미신이야!

"단일 출구 원칙"의 진실

옛날 언어의 한계 때문이었어:
- 리소스 정리가 return 전에 있어야 했음
- goto 남용 막으려는 의도

현대 언어는 자동 메모리 관리, try-finally, RAII 있어서
조기 리턴의 장점이 더 커.
장점이 뭔데?

비정상 케이스 빨리 처리, 중첩 줄어서 가독성 향상,

정상 경로가 명확해져.

Part 3. 언제 써?

어떤 경우에 Guard Clause 써?

이런 상황들:

Guard Clause 적용 케이스

1. null/빈 값 체크 - 파라미터 null이면 바로 리턴
2. 권한 검증 - 관리자 아니면 에러 리턴
3. 상태 검증 - 이미 처리됐으면 스킵
4. 입력값 범위 - 음수면 0 리턴

공통점: "이 조건 아니면 할 일 없다" → 바로 리턴!

Part 4. 변환 절차와 주의점

어떻게 바꿔?

단계별로:

Guard Clause 변환 절차

1단계: 가장 바깥 조건 확인
2단계: 조건 뒤집어서 조기 리턴 - if (!condition) return;
3단계: else 제거 - 이제 필요 없음
4단계: 다음 중첩에 반복
5단계: 테스트
주의사항

1. 리턴값 - 조기 리턴 시 적절한 값(null, 0, false) 리턴
2. 부작용 - 리턴 전에 로그나 정리할 게 있는지 확인
3. 과도한 Guard - 10개 넘으면 함수가 너무 많은 일 하는 신호
예외 던지기랑 리턴 중 뭘 써?

프로그래밍 오류(null이면 안 되는데 null): 예외

정상적 예외 상황(데이터 없음): 리턴

핵심 정리: Guard Clauses

  • 방법: 예외 상황 먼저 처리하고 조기 리턴
  • 효과: 중첩 if-else를 평면적 구조로
  • 장점: 정상 흐름에 집중 가능
  • 미신: "단일 출구 원칙"은 현대에서 불필요
  • 주의: Guard 너무 많으면 함수 분리 고려
