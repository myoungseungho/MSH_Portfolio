2. GitOps가 뭐야?

IaC랑 뭐가 달라?

Git을 Single Source of Truth로!

GitOps 원칙: 1. 선언적 (Declarative) - "서버 3대 실행해" (O) - "서버 1대 추가해" (X) 2. Git = 진실의 원천 - Git에 있는 설정 = 실제 인프라 - 수동 변경 금지 3. 자동 동기화 - Git 변경 -> 자동으로 인프라 반영 - 드리프트 자동 감지/수정 4. 풀 기반 (Pull-based) - 에이전트가 Git을 감시 - 변경 감지하면 Pull해서 적용
기존 CI/CD랑 뭐가 달라?
구분 전통적 CI/CD GitOps
배포 방식 Push (CI가 밀어넣음) Pull (에이전트가 당김)
인증 CI에 클러스터 접근 권한 에이전트만 접근
상태 관리 CI 서버에 의존 Git이 진실의 원천
드리프트 수동 확인 자동 감지/수정

3. ArgoCD로 GitOps 하기

ArgoCD가 뭐야?
ArgoCD 동작 방식: [Git Repository] | | (감시) v [ArgoCD] | | (동기화) v [Kubernetes Cluster] Git에 Deployment YAML 수정 | v ArgoCD가 변경 감지 | v 자동으로 kubectl apply | v 클러스터에 반영!
설정 예시 보여줘
# argocd-application.yaml apiVersion: argoproj.io/v1alpha1 kind: Application metadata: name: game-server namespace: argocd spec: project: default source: repoURL: https://github.com/company/game-server-k8s.git targetRevision: HEAD path: k8s/production destination: server: https://kubernetes.default.svc namespace: game syncPolicy: automated: prune: true # 삭제된 리소스 정리 selfHeal: true # 드리프트 자동 복구 syncOptions: - CreateNamespace=true
Git 저장소 구조는?
# GitOps 저장소 구조 game-server-k8s/ ├── base/ # 공통 설정 │ ├── deployment.yaml │ ├── service.yaml │ └── kustomization.yaml ├── overlays/ │ ├── development/ # 개발 환경 │ │ ├── kustomization.yaml │ │ └── patch-replicas.yaml │ ├── staging/ # 스테이징 │ │ ├── kustomization.yaml │ │ └── patch-replicas.yaml │ └── production/ # 프로덕션 │ ├── kustomization.yaml │ ├── patch-replicas.yaml │ └── patch-resources.yaml └── README.md
# base/deployment.yaml apiVersion: apps/v1 kind: Deployment metadata: name: game-server spec: replicas: 1 # base는 1개 selector: matchLabels: app: game-server template: spec: containers: - name: game-server image: game-server:latest resources: requests: memory: "256Mi" cpu: "200m"
# overlays/production/patch-replicas.yaml apiVersion: apps/v1 kind: Deployment metadata: name: game-server spec: replicas: 10 # 프로덕션은 10개!

4. 게임 서버 설정은?

게임 밸런스 설정도 GitOps?

Yes! 기획 데이터도 Git으로:

# game-config/monster-stats.yaml monsters: - id: 1001 name: "슬라임" hp: 100 attack: 10 defense: 5 exp_reward: 15 - id: 1002 name: "고블린" hp: 250 attack: 25 defense: 12 exp_reward: 45 - id: 2001 name: "드래곤 (보스)" hp: 50000 attack: 500 defense: 200 exp_reward: 10000
기획팀도 Git 써야 해?
기획팀 워크플로우: 1. 기획팀: Excel로 밸런스 작업 2. 변환 도구: Excel -> YAML 자동 변환 3. Git PR: "몬스터 밸런스 조정 v1.2" 4. 코드 리뷰: 개발팀 검토 5. 머지: main 브랜치에 반영 6. ArgoCD: 자동으로 ConfigMap 업데이트 7. 게임 서버: 설정 리로드 (무중단) 장점: - 변경 이력 추적 (누가 언제 뭘 바꿨는지) - 롤백 가능 ("어제 패치가 OP였어요" -> 되돌리기) - 리뷰 프로세스 (실수 방지)
핫 리로드는 어떻게?
// 게임 서버 설정 핫 리로드 class ConfigManager { public: void WatchConfigMap() { // Kubernetes ConfigMap 변경 감지 while (m_running) { auto newConfig = LoadConfigMap("game-config"); if (newConfig != m_currentConfig) { LOG_INFO("Config changed, reloading..."); // 무중단 적용 ApplyConfig(newConfig); m_currentConfig = newConfig; LOG_INFO("Config reloaded successfully!"); } Sleep(5000); // 5초마다 체크 } } private: void ApplyConfig(const Config& config) { // 락 걸고 적용 std::lock_guard lock(m_configMutex); // 몬스터 스탯 업데이트 for (const auto& monster : config.monsters) { m_monsterStats[monster.id] = monster; } // 아이템 정보 업데이트 for (const auto& item : config.items) { m_itemStats[item.id] = item; } } };

Terraform도 자동 적용?
# .github/workflows/terraform.yml name: Terraform GitOps on: push: branches: [main] paths: ['terraform/**'] pull_request: paths: ['terraform/**'] jobs: plan: runs-on: ubuntu-latest steps: - uses: actions/checkout@v3 - name: Terraform Init run: terraform init working-directory: terraform - name: Terraform Plan run: terraform plan -out=plan.tfplan working-directory: terraform - name: Save Plan uses: actions/upload-artifact@v3 with: name: terraform-plan path: terraform/plan.tfplan apply: needs: plan if: github.ref == 'refs/heads/main' runs-on: ubuntu-latest environment: name: production steps: - uses: actions/checkout@v3 - name: Download Plan uses: actions/download-artifact@v3 with: name: terraform-plan path: terraform - name: Terraform Apply run: terraform apply -auto-approve plan.tfplan working-directory: terraform

핵심 정리: GitOps

  • IaC - 인프라 설정을 코드 파일로 관리
  • GitOps - Git이 진실의 원천, 자동 동기화
  • ArgoCD - 쿠버네티스 GitOps 도구 (Pull 방식)
  • 게임 설정 - 밸런스 데이터도 Git으로 버전 관리
  • Terraform - AWS/GCP 인프라도 코드로
  • 핵심 - 변경 추적 + 리뷰 + 롤백 가능!
