Soft vs Hard Reference

로딩 시점을 제어하는 참조 전략

Part 1. 개념 - 참조 방식의 차이

Hard Reference가 뭐야?

직접 참조입니다. 참조하는 에셋이 무조건 함께 로드됩니다.

// Unity - Hard Reference 예시 public class Enemy : MonoBehaviour { // Inspector에 직접 할당 = Hard Reference [SerializeField] private Material enemyMaterial; // Hard [SerializeField] private AudioClip deathSound; // Hard [SerializeField] private GameObject explosionPrefab; // Hard // 이 Enemy 프리팹이 로드되면 // enemyMaterial, deathSound, explosionPrefab도 동시에 로드됨! }
┌─────────────────────────────────────────────────────────────────┐
│                    Hard Reference 동작                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  빌드 시:                                                       │
│  ┌────────────────────────────────────────────────────────┐    │
│  │  Enemy.prefab                                          │    │
│  │  ├─ enemyMaterial ────→ [Material 포함]                │    │
│  │  ├─ deathSound ───────→ [AudioClip 포함]               │    │
│  │  └─ explosionPrefab ──→ [Prefab + 하위 에셋 전부 포함] │    │
│  └────────────────────────────────────────────────────────┘    │
│                                                                 │
│  로드 시:                                                       │
│  Instantiate(enemyPrefab);  ← 한 번 호출에                     │
│                                                                 │
│  메모리:                                                        │
│  ├─ Enemy.prefab .............. 0.1 MB                         │
│  ├─ enemyMaterial ............. 2 MB                           │
│  ├─ deathSound ................ 1 MB                           │
│  └─ explosionPrefab ........... 5 MB (파티클, 텍스처 포함)     │
│  ────────────────────────────────────                          │
│  합계: 8.1 MB (모두 즉시 로드)                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
Soft Reference는 뭐야?

간접 참조입니다. 경로나 ID만 저장하고 실제 에셋은 필요할 때 로드합니다.

// Unity Addressables - Soft Reference 예시 using UnityEngine.AddressableAssets; public class Enemy : MonoBehaviour { // AssetReference = Soft Reference (GUID만 저장) [SerializeField] private AssetReference explosionRef; private GameObject _explosionPrefab; public async void OnDeath() { // 죽을 때만 폭발 이펙트 로드 if (_explosionPrefab == null) { _explosionPrefab = await explosionRef .LoadAssetAsync<GameObject>().Task; } Instantiate(_explosionPrefab, transform.position, Quaternion.identity); } }
┌─────────────────────────────────────────────────────────────────┐
│                    Soft Reference 동작                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  빌드 시:                                                       │
│  ┌────────────────────────────────────────────────────────┐    │
│  │  Enemy.prefab                                          │    │
│  │  └─ explosionRef ─────→ [GUID만 저장: "abc123..."]    │    │
│  └────────────────────────────────────────────────────────┘    │
│                                                                 │
│  ┌────────────────────────────────────────────────────────┐    │
│  │  별도 번들: effects_bundle                             │    │
│  │  └─ ExplosionPrefab + 텍스처 + 파티클                  │    │
│  └────────────────────────────────────────────────────────┘    │
│                                                                 │
│  로드 시:                                                       │
│  Instantiate(enemyPrefab);  ← Enemy만 로드                     │
│                                                                 │
│  메모리 (초기):                                                 │
│  └─ Enemy.prefab .............. 0.1 MB                         │
│                                                                 │
│  OnDeath() 호출 시:                                             │
│  └─ ExplosionPrefab ........... 5 MB (이때 로드)               │
│                                                                 │
│  💡 적이 죽지 않으면 5MB 절약!                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
한마디로 뭐가 다른 거야?

로딩 시점이 다릅니다. Hard는 즉시, Soft는 지연 로드입니다.

┌─────────────────────────────────────────────────────────────────┐
│                Hard vs Soft Reference 비교                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  구분          │ Hard Reference      │ Soft Reference           │
│  ──────────────┼─────────────────────┼────────────────────────  │
│  저장 내용     │ 에셋 직접 포함       │ 경로/GUID만 저장         │
│  로드 시점     │ 부모와 함께 즉시     │ 명시적 로드 호출 시      │
│  빌드 포함     │ 같은 번들에 포함     │ 별도 번들 가능           │
│  메모리        │ 항상 점유            │ 필요시만 점유            │
│  로드 속도     │ 빠름 (이미 로드됨)   │ 첫 호출 시 딜레이        │
│  코드 복잡도   │ 단순                 │ 비동기 처리 필요         │
│  ──────────────┼─────────────────────┼────────────────────────  │
│  적합한 상황   │ - 항상 필요한 에셋   │ - 가끔 필요한 에셋       │
│                │ - 즉시 사용 필수     │ - 조건부 사용            │
│                │ - 핵심 게임플레이    │ - 선택적 콘텐츠          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

Part 2. Unity에서의 구현

Unity에서 Hard Reference는 어떤 거야?

SerializeField로 Inspector에 직접 할당하면 Hard Reference입니다.

// 모든 직접 참조 = Hard Reference public class PlayerController : MonoBehaviour { // Hard References (Inspector 할당) [SerializeField] private Sprite idleSprite; [SerializeField] private Sprite runSprite; [SerializeField] private AudioClip jumpSound; [SerializeField] private ParticleSystem dustEffect; // 코드에서 Resources.Load도 Hard Reference처럼 동작 private Material specialMaterial; void Start() { // Resources 폴더 에셋은 빌드에 무조건 포함 specialMaterial = Resources.Load<Material>("Materials/Special"); } } // ScriptableObject 안의 참조도 Hard [CreateAssetMenu] public class ItemDatabase : ScriptableObject { // 모든 아이템 아이콘이 이 SO와 함께 로드됨 public List<ItemData> items; // 각 아이템에 Sprite 있으면 전부 Hard }
Unity에서 Soft Reference는?

Addressables의 AssetReference가 대표적인 Soft Reference입니다.

using UnityEngine; using UnityEngine.AddressableAssets; using UnityEngine.ResourceManagement.AsyncOperations; public class SoftReferenceExample : MonoBehaviour { // Soft References (Addressables) [SerializeField] private AssetReference bossModelRef; [SerializeField] private AssetReferenceGameObject specialEffectRef; [SerializeField] private AssetReferenceSprite rareIconRef; private AsyncOperationHandle<GameObject> _bossHandle; private GameObject _bossInstance; // 보스전 시작 시에만 보스 모델 로드 public async void StartBossBattle() { if (!bossModelRef.RuntimeKeyIsValid()) { Debug.LogError("Boss model reference is not set!"); return; } // 이때 비로소 보스 에셋 로드 _bossHandle = bossModelRef.LoadAssetAsync<GameObject>(); await _bossHandle.Task; if (_bossHandle.Status == AsyncOperationStatus.Succeeded) { _bossInstance = Instantiate(_bossHandle.Result); } } // 보스전 종료 시 해제 public void EndBossBattle() { if (_bossInstance != null) { Destroy(_bossInstance); } // Addressables 핸들 해제 (메모리 반환) if (_bossHandle.IsValid()) { Addressables.Release(_bossHandle); } } private void OnDestroy() { // 컴포넌트 파괴 시 정리 EndBossBattle(); } }
AssetReference 종류가 여러 개야?

네, 타입 안전성을 위한 제네릭 버전들이 있습니다.

using UnityEngine.AddressableAssets; public class TypedAssetReferences : MonoBehaviour { // 범용 (어떤 타입이든) [SerializeField] private AssetReference anyAsset; // 타입 지정 (Inspector에서 해당 타입만 선택 가능) [SerializeField] private AssetReferenceGameObject prefabRef; [SerializeField] private AssetReferenceSprite spriteRef; [SerializeField] private AssetReferenceTexture2D textureRef; [SerializeField] private AssetReferenceT<AudioClip> audioRef; [SerializeField] private AssetReferenceT<ScriptableObject> dataRef; // 라벨 기반 참조 (여러 에셋 그룹) [SerializeField] private AssetLabelReference enemyLabel; public async void LoadByLabel() { // "enemies" 라벨이 붙은 모든 에셋 로드 var handle = Addressables.LoadAssetsAsync<GameObject>( enemyLabel, (enemy) => { Debug.Log($"Loaded: {enemy.name}"); } ); await handle.Task; } }
💡 타입별 AssetReference 장점
1. Inspector에서 잘못된 타입 선택 방지
2. 코드에서 캐스팅 불필요
3. 컴파일 타임 타입 체크

Part 3. Unreal Engine에서의 구현

Unreal에서는 어떻게 구분해?

Unreal은 TSoftObjectPtr / TSoftClassPtr로 명시적으로 구분합니다.

// Unreal Engine C++ // Hard Reference - 항상 로드됨 UPROPERTY(EditDefaultsOnly, Category = "Assets") UStaticMesh* HardMeshRef; UPROPERTY(EditDefaultsOnly, Category = "Assets") TSubclassOf<AActor> HardClassRef; // Soft Reference - 필요 시 로드 UPROPERTY(EditDefaultsOnly, Category = "Assets") TSoftObjectPtr<UStaticMesh> SoftMeshRef; UPROPERTY(EditDefaultsOnly, Category = "Assets") TSoftClassPtr<AActor> SoftClassRef; // Soft Reference 사용 void AMyActor::LoadSoftAsset() { // 동기 로드 UStaticMesh* Mesh = SoftMeshRef.LoadSynchronous(); // 비동기 로드 FStreamableManager& StreamableManager = UGameGlobals::Get().StreamableManager; StreamableManager.RequestAsyncLoad( SoftMeshRef.ToSoftObjectPath(), FStreamableDelegate::CreateUObject( this, &AMyActor::OnMeshLoaded ) ); } void AMyActor::OnMeshLoaded() { if (SoftMeshRef.IsValid()) { UStaticMesh* LoadedMesh = SoftMeshRef.Get(); // 사용... } }
Unreal의 FSoftObjectPath는?

문자열 경로만 저장하는 가장 가벼운 참조 방식입니다.

// FSoftObjectPath - 경로 문자열만 저장 UPROPERTY(EditDefaultsOnly) FSoftObjectPath AssetPath; // 사용 예 void AMyActor::LoadFromPath() { if (AssetPath.IsValid()) { // 동기 로드 UObject* Loaded = AssetPath.TryLoad(); // 또는 StreamableManager로 비동기 FStreamableManager& SM = ...; SM.RequestAsyncLoad(AssetPath, ...); } } // FSoftObjectPath vs TSoftObjectPtr 비교 // // FSoftObjectPath: // - 순수 경로 문자열 // - 타입 정보 없음 // - 가장 가벼움 // - 직렬화/네트워크 전송에 적합 // // TSoftObjectPtr<T>: // - 타입 안전 // - 캐싱된 포인터 포함 // - .Get()으로 빠른 접근 (로드된 경우) // - 일반적인 게임플레이 코드에 적합
┌─────────────────────────────────────────────────────────────────┐
│                Unreal 참조 타입 스펙트럼                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Hard ◀────────────────────────────────────────────────▶ Soft  │
│                                                                 │
│  UObject*         TObjectPtr<T>       TSoftObjectPtr    FSoft  │
│  (Raw Ptr)        (Smart Ptr)         (Lazy Load)       Object │
│                                                          Path  │
│  │                │                   │                 │      │
│  │                │                   │                 │      │
│  ▼                ▼                   ▼                 ▼      │
│  즉시 로드        즉시 로드           지연 로드         경로만  │
│  참조 추적 X      참조 추적 O         참조 추적 O       저장   │
│  GC 위험          GC 안전             GC 안전           최소   │
│                                                         오버헤드│
│                                                                 │
│  💡 권장:                                                       │
│  - 일반 에셋: TSoftObjectPtr                                   │
│  - 클래스/BP: TSoftClassPtr                                    │
│  - 직렬화/저장: FSoftObjectPath                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

Part 4. 실전 적용 패턴

언제 Hard Reference를 써야 해?

항상 필요하고 즉시 사용해야 하는 에셋에 적합합니다.

// ✅ Hard Reference가 적합한 경우 public class PlayerCharacter : MonoBehaviour { // 플레이어 기본 에셋 - 항상 필요 [SerializeField] private Animator animator; // 즉시 필요 [SerializeField] private AudioClip footstepSound; // 자주 사용 [SerializeField] private Material baseMaterial; // 기본 외형 } public class UIManager : MonoBehaviour { // UI 기본 에셋 - 항상 표시 [SerializeField] private Sprite healthBarFill; // 항상 보임 [SerializeField] private Font mainFont; // 필수 폰트 } public class GameSettings : ScriptableObject { // 설정 데이터 - 게임 시작 시 필요 [SerializeField] private AudioMixer mainMixer; [SerializeField] private InputActionAsset inputActions; }
Hard Reference 체크리스트
✓ 게임 시작과 동시에 필요한가?
✓ 매 프레임 또는 자주 접근하는가?
✓ 로딩 딜레이가 용납되지 않는가?
✓ 메모리에 항상 있어도 괜찮은 크기인가?
언제 Soft Reference를 써야 해?

조건부로 필요하거나 대용량 에셋에 적합합니다.

// ✅ Soft Reference가 적합한 경우 public class Enemy : MonoBehaviour { // 죽을 때만 필요 (대부분의 적은 안 죽음) [SerializeField] private AssetReferenceGameObject deathEffectRef; // 희귀 행동 (5%의 적만 사용) [SerializeField] private AssetReferenceGameObject specialAttackRef; } public class BossManager : MonoBehaviour { // 보스전 시작 시에만 필요 (대용량) [SerializeField] private AssetReferenceGameObject bossModelRef; [SerializeField] private AssetReference bossCutsceneRef; } public class AchievementUI : MonoBehaviour { // 달성 시에만 필요 (대부분 미달성) [SerializeField] private List<AssetReferenceSprite> achievementIcons; } public class LocalizationManager : MonoBehaviour { // 선택된 언어만 필요 [SerializeField] private AssetReferenceT<TextAsset> koreanRef; [SerializeField] private AssetReferenceT<TextAsset> englishRef; [SerializeField] private AssetReferenceT<TextAsset> japaneseRef; }
Soft Reference 체크리스트
✓ 10% 미만의 확률로만 사용되는가?
✓ 특정 조건/이벤트에서만 필요한가?
✓ 용량이 커서 상시 로드가 부담되는가?
✓ 비동기 로딩 딜레이를 감출 수 있는가?
하이브리드 패턴은?

핵심은 Hard, 부가요소는 Soft로 분리합니다.

public class HybridCharacter : MonoBehaviour { // ═══ Hard References (항상 필요) ═══ [Header("Core Assets - Always Loaded")] [SerializeField] private RuntimeAnimatorController animator; [SerializeField] private Material baseMaterial; [SerializeField] private AudioClip[] basicSounds; // 이동, 점프 등 // ═══ Soft References (선택적 로드) ═══ [Header("Optional Assets - Loaded On Demand")] [SerializeField] private AssetReferenceGameObject ultimateEffectRef; [SerializeField] private AssetReference victoryAnimationRef; [SerializeField] private AssetReferenceT<AudioClip> rareVoiceLineRef; // ═══ 스킨 시스템 (Soft로 분리) ═══ [Header("Skin System")] [SerializeField] private List<SkinData> availableSkins; [System.Serializable] public class SkinData { public string skinId; public AssetReferenceT<Material> materialRef; // Soft public AssetReferenceGameObject meshOverrideRef; // Soft } private Dictionary<string, AsyncOperationHandle> _loadedSkins = new(); // 스킨 로드 (필요할 때만) public async Task LoadSkin(string skinId) { var skinData = availableSkins.Find(s => s.skinId == skinId); if (skinData == null) return; // 이미 로드되어 있으면 스킵 if (_loadedSkins.ContainsKey(skinId)) return; var handle = skinData.materialRef.LoadAssetAsync<Material>(); await handle.Task; if (handle.Status == AsyncOperationStatus.Succeeded) { _loadedSkins[skinId] = handle; ApplyMaterial(handle.Result); } } }

Part 5. 빌드와 번들 영향

Hard Reference가 빌드에 미치는 영향은?

Hard Reference된 에셋은 무조건 같은 번들에 포함됩니다.

│  ├─ [Hard] EnemyMaterial                                       │
│  │   └─ [Hard] EnemyTexture.png (4MB)                          │
│  ├─ [Hard] EnemyMesh                                           │

│                                                                 │

│  │  ├─ Enemy.prefab                        │                    │
│  │  ├─ EnemyMaterial                       │                    │
│  │  ├─ EnemyTexture.png .......... 4MB    │ ← 전부 포함!       │

Part 6. 주의사항과 안티패턴

Hard Reference의 함정은?

의존성 체인으로 예상치 못한 대량 로드가 발생할 수 있습니다.

// ❌ 안티패턴: 거대한 의존성 체인 [CreateAssetMenu] public class ItemDatabase : ScriptableObject { // 모든 아이템 데이터 (1000개) public List<ItemData> allItems; } [System.Serializable] public class ItemData { public string name; public Sprite icon; // Hard - 1000개 아이콘! public GameObject dropPrefab; // Hard - 1000개 프리팹! public AudioClip useSound; // Hard - 1000개 사운드! } // 결과: ItemDatabase 하나 로드하면 // 1000개의 아이콘 + 프리팹 + 사운드가 전부 로드됨 // → 수백 MB 메모리 사용 // ✅ 해결책: Soft Reference로 변경 [System.Serializable] public class ItemDataOptimized { public string name; public AssetReferenceSprite iconRef; // Soft public AssetReferenceGameObject dropRef; // Soft public AssetReferenceT<AudioClip> soundRef; // Soft } // 결과: ItemDatabase 로드해도 메타데이터만 // 실제 에셋은 인벤토리 UI에 표시할 때 개별 로드
Soft Reference의 함정은?

로딩 딜레이와 핸들 관리 실수가 문제입니다.

// ❌ 안티패턴 1: 동기적 사용 시도 public void OnButtonClick() { // 클릭 즉시 이펙트 필요한데... var handle = effectRef.LoadAssetAsync<GameObject>(); // 로딩 중... 1-2초 딜레이 발생! // 유저: "버튼 안 먹히네?" } // ✅ 해결책: 미리 로드 또는 로딩 표시 private GameObject _cachedEffect; private async void Start() { // 씬 시작 시 미리 로드 var handle = effectRef.LoadAssetAsync<GameObject>(); _cachedEffect = await handle.Task; } // ❌ 안티패턴 2: 핸들 해제 안 함 public async void SpawnEnemy() { var handle = enemyRef.LoadAssetAsync<GameObject>(); var prefab = await handle.Task; Instantiate(prefab); // handle 해제 안 함 → 메모리 누수! } // ✅ 해결책: 핸들 관리 private List<AsyncOperationHandle> _handles = new(); public async void SpawnEnemySafe() { var handle = enemyRef.LoadAssetAsync<GameObject>(); _handles.Add(handle); // 추적 var prefab = await handle.Task; Instantiate(prefab); } private void OnDestroy() { foreach (var handle in _handles) { if (handle.IsValid()) Addressables.Release(handle); } }
참조 분석은 어떻게 해?

Unity의 Addressables Analyze 또는 에디터 도구로 확인합니다.

using UnityEditor; using UnityEngine; using System.Linq; public class ReferenceAnalyzer { [MenuItem("Tools/Analyze Hard References")] public static void AnalyzeSelected() { var selected = Selection.activeObject; if (selected == null) return; string path = AssetDatabase.GetAssetPath(selected); string[] dependencies = AssetDatabase.GetDependencies(path, true); Debug.Log($"=== {selected.name} Hard Dependencies ==="); Debug.Log($"Total: {dependencies.Length} assets"); // 타입별 분류 var byType = dependencies .GroupBy(d => AssetDatabase.GetMainAssetTypeAtPath(d)?.Name ?? "Unknown") .OrderByDescending(g => g.Count()); foreach (var group in byType) { Debug.Log($" {group.Key}: {group.Count()}"); } // 대용량 에셋 경고 foreach (var dep in dependencies) { var fileInfo = new System.IO.FileInfo(dep); if (fileInfo.Exists && fileInfo.Length > 1024 * 1024) // 1MB 이상 { Debug.LogWarning($" ⚠️ Large: {dep} ({fileInfo.Length / 1024}KB)"); } } } }

Part 7. 마이그레이션 전략

기존 Hard Reference를 Soft로 바꾸려면?

점진적 마이그레이션이 안전합니다. 한 번에 바꾸지 마세요.

// 단계별 마이그레이션 전략 // Step 1: 분석 - 어떤 참조가 문제인지 파악 // - Addressables Analyze 실행 // - 중복 에셋 확인 // - 대용량 Hard Reference 목록화 // Step 2: 래퍼 클래스 생성 public class MigratableAssetRef<T> where T : Object { [SerializeField] private T hardRef; // 기존 Hard [SerializeField] private AssetReferenceT<T> softRef; // 새 Soft [SerializeField] private bool useSoft = false; // 전환 플래그 private T _cachedAsset; public async Task<T> GetAssetAsync() { if (!useSoft) { // 기존 Hard 모드 return hardRef; } // 새 Soft 모드 if (_cachedAsset != null) return _cachedAsset; var handle = softRef.LoadAssetAsync<T>(); _cachedAsset = await handle.Task; return _cachedAsset; } } // Step 3: 점진적 전환 // - 테스트 환경에서 useSoft = true로 변경 // - 문제없으면 프로덕션 적용 // - 안정화 후 hardRef 필드 제거

핵심 정리

  • Hard Reference: 직접 참조, 즉시 로드, 같은 번들 포함
  • Soft Reference: 간접 참조, 지연 로드, 별도 번들 가능
  • Unity: SerializeField(Hard) vs AssetReference(Soft)
  • Unreal: Raw Ptr(Hard) vs TSoftObjectPtr(Soft)
  • 핵심 에셋은 Hard, 선택적/대용량은 Soft
  • 의존성 체인 주의: Hard Reference가 연쇄적으로 번들 크기 증가
  • Soft 핸들 관리: 로드한 핸들은 반드시 해제
