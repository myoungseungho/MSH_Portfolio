Extract Method - 함수 분리

가장 자주 쓰는 리팩토링 기법

Part 1. Extract Method가 뭐야?

Extract Method? 영어인데?

"메서드를 뽑아낸다" = 함수를 분리한다

긴 코드에서 일부분을 별도 함수로 만드는 거야.

레고 비유

하나의 거대한 레고 블록 vs 작은 블록 여러 개

거대한 블록: 다른 곳에 재사용 불가, 일부만 교체 불가
작은 블록: 조합 가능, 일부만 교체 가능, 이해하기 쉬움

Extract Method는 큰 블록을 작은 블록으로 쪼개는 것.
왜 이게 "가장 자주 쓰는" 기법이야?

거의 모든 코드 스멜의 해결책이기 때문.

❌ Before

Long Method → 길어서 읽기 힘듦

Duplicated Code → 복붙됨

Comments → 주석으로 설명해야 함

✅ After (Extract Method)

짧은 함수 → 한눈에 들어옴

재사용 → 한 곳에서 호출

함수 이름 → 주석 대신 설명

Part 2. 실제 예시 - Before

실제 코드로 보여줘.

우리 프로젝트의 ServerMsgProcess.cpp에서 가져왔어.

// Before: SSM_SERVER_CONNECTED 처리 (약 100줄) case SSM_SERVER_CONNECTED: { // 1단계: 패킷 파싱 MP_Server_Connected* pPacketStruct = (MP_Server_Connected*)pPacket; int iServer = pPacketStruct->m_nServer; // 2단계: 로깅 printf(" %s ", g_Server.m_ServerManage.m_SocInfo[iClient].szTitle); printf("(%3d) Recv SSM_SERVER_CONNECTED (ServerID:%d, IP:%s)\n", iClient, iServer, g_ClientArray[iClient].m_szPeerName); SendNotice_C(1, "[GAMEDB_SERVER] connected %s", g_Server.m_ServerManage.m_SocInfo[iClient].szTitle); g_DebugManager.LogFile_Printf(LOG_FILE_EXCEPTION, __FILE__, __LINE__, "(%3d) Recv SSM_SERVER_CONNECTED (ServerID:%d, IP:%s)\n", iClient, iServer, g_ClientArray[iClient].m_szPeerName); // 3단계: 유효성 검사 if (iServer <= 0 || iServer > BRAVO_MAX_MULTI_SERVER) { DebugPrintf(DEBUG_PACKET, "\tnot allowed server. 뭐가 문제야?

이 코드를 보고 한눈에 "뭐 하는 코드인지" 알 수 있어?

5가지 일이 섞여 있어서 읽기 힘들어.

Part 3. 어디서 어떻게 자를까?

어디를 잘라야 해?

"의미 단위"로 자르면 돼.

주석이 있다면? 그게 힌트야!

Step 1: 주석 찾기

주석은 "이 코드가 뭐 하는지" 설명해. → 그게 바로 함수 이름!

// 주석이 있는 곳 = 함수로 분리할 곳 // 1단계: 패킷 파싱 → ParsePacket() // 2단계: 로깅 → LogServerConnection() // 3단계: 유효성 검사 → ValidateServer() // 4단계: 게임 서버 초기화 → InitializeGameServer() // 5단계: 유니온 서버 처리 → HandleUnionServer()

Step 2: 추상화 수준 맞추기

한 함수 안에서 추상화 수준이 같아야 읽기 편해.

// BAD: 추상화 수준이 들쭉날쭉 void HandleConnection() { ProcessHighLevelLogic(); // 높은 수준 printf("debug: %d", value); // 낮은 수준 (갑자기?) DoAnotherHighLevelThing(); // 높은 수준 } // GOOD: 추상화 수준이 일정 void HandleConnection() { ProcessHighLevelLogic(); LogDebugInfo(value); // 같은 수준으로 감쌈 DoAnotherHighLevelThing(); }

Part 4. 실제 예시 - After

분리하면 어떻게 돼?

각 역할을 별도 함수로 빼면:

// After: 깔끔하게 분리 // 메인 핸들러 - 이제 한눈에 들어옴! case SSM_SERVER_CONNECTED: { int iServer = ParseServerPacket(pPacket); LogServerConnection(iClient, iServer); if (!ValidateServer(iClient, iServer)) { break; } InitializeGameServer(iClient); HandleUnionServer(iClient); } break; // 이제 "무엇을" 하는지 바로 보임!
// 분리된 함수들 int ParseServerPacket(BYTE* pPacket) { MP_Server_Connected* pPacketStruct = (MP_Server_Connected*)pPacket; return pPacketStruct->m_nServer; } void LogServerConnection(int iClient, int iServer) { printf(" %s ", g_Server.m_ServerManage.m_SocInfo[iClient].szTitle); printf("(%3d) Recv SSM_SERVER_CONNECTED (ServerID:%d, IP:%s)\n", iClient, iServer, g_ClientArray[iClient].m_szPeerName); SendNotice_C(1, "[GAMEDB_SERVER] connected %s", g_Server.m_ServerManage.m_SocInfo[iClient].szTitle); g_DebugManager.LogFile_Printf(LOG_FILE_EXCEPTION, __FILE__, __LINE__, "(%3d) Recv SSM_SERVER_CONNECTED\n", iClient, iServer); } bool ValidateServer(int iClient, int iServer) { if (iServer <= 0 || iServer > BRAVO_MAX_MULTI_SERVER) { DebugPrintf(DEBUG_PACKET, "\tnot allowed server.\n"); g_ClientArray[iClient].Close(0); return false; } return true; } void InitializeGameServer(int iClient) { if (CGameManager::GetInstance()->CheckGameServer(iClient)) { CGameManager::GetInstance()->GetGroupServerItemUnique(iClient); CDBManager::RankLoadLastList(iClient, 100); } } void HandleUnionServer(int iClient) { if (iClient == g_ServerArray.Bravo_UnionServer) { // 유니온 서버 전용 처리 } }
효과

✅ 메인 핸들러가 5줄로 줄어듦
✅ 각 함수가 "한 가지 일"만 함
✅ 함수 이름으로 동작이 설명됨
✅ 테스트하기 쉬워짐 (ValidateServer만 따로 테스트 가능)

Part 5. 주의사항

무조건 쪼개면 좋아?

아니. 너무 잘게 쪼개면 오히려 읽기 힘들어.

// BAD: 너무 과하게 쪼갬 void Process() { int a = GetValueA(); // return 1; int b = GetValueB(); // return 2; int sum = AddValues(a, b); // return a + b; PrintResult(sum); // printf("%d", sum); } // 1줄짜리 함수가 4개? 오히려 복잡해!
Extract Method 하면 안 되는 경우

1. 1-2줄짜리 코드 - 함수 호출 오버헤드만 늘어남
2. 재사용 안 되는 코드 - 한 번만 쓰면 그냥 두기
3. 맥락이 중요한 코드 - 분리하면 이해가 더 어려워짐
그럼 언제 Extract Method 해?

이런 경우에:

Extract Method 해야 하는 신호

✅ 주석으로 "이 부분은 ~하는 코드"라고 설명해야 할 때
✅ 같은 코드가 2곳 이상에서 반복될 때
✅ 함수가 20줄을 넘어갈 때
✅ 조건문 안의 코드가 복잡할 때
✅ 테스트하고 싶은 로직이 큰 함수 안에 묻혀있을 때

Part 6. IDE가 대신 해준다

수동으로 다 해야 해?

아니! Visual Studio가 자동으로 해줘.

Visual Studio에서 Extract Method

1. 분리할 코드 블록 선택
2. 우클릭 → Quick Actions and Refactorings
3. 또는 Ctrl + . → Extract Method
4. 함수 이름 입력 → Enter

// 1. 이 부분을 드래그해서 선택 if (iServer <= 0 || iServer > BRAVO_MAX_MULTI_SERVER) { DebugPrintf(DEBUG_PACKET, "\tnot allowed server.\n"); g_ClientArray[iClient].Close(0); return; } // 2. Ctrl + . 누르고 "Extract Method" 선택 // 3. 함수 이름 "ValidateServer" 입력 // 4. 자동으로 이렇게 됨! if (!ValidateServer(iClient, iServer)) { return; } bool ValidateServer(int iClient, int iServer) { // 자동으로 파라미터도 추출! }
IDE 단축키

Visual Studio: Ctrl + . → Extract Method
VS Code: Ctrl + Shift + R → Extract to function
JetBrains: Ctrl + Alt + M

핵심 정리: Extract Method

  • 정의: 코드 일부를 별도 함수로 분리
  • 분리 기준: 의미 단위, 주석이 있는 곳
  • 효과: 가독성, 재사용성, 테스트 용이성
  • 주의: 너무 작게 쪼개면 역효과
  • 도구: IDE가 자동으로 해줌 (Ctrl + .)
  • 원칙: 한 함수는 한 가지 일만!
