조건문을 다형성으로

Replace Conditional with Polymorphism - 반복되는 switch를 클래스로

Part 1. switch문이 계속 커져!

switch문에 case가 30개가 넘는데?

타입별로 다른 동작을 하는 switch가 여러 곳에 반복되면 문제야.

새 타입 추가할 때마다 모든 switch를 찾아 수정해야 해.

// 몬스터 타입별 처리가 여러 곳에 흩어져 있음 int GetMonsterDamage(CMonster* pMon) { switch (pMon->GetType()) { case MONSTER_NORMAL: return pMon->GetAtk() * 1; case MONSTER_ELITE: return pMon->GetAtk() * 2; case MONSTER_BOSS: return pMon->GetAtk() * 5; } } int GetMonsterExp(CMonster* pMon) { switch (pMon->GetType()) { // 또 같은 switch! case MONSTER_NORMAL: return 100; case MONSTER_ELITE: return 500; case MONSTER_BOSS: return 5000; } } const char* GetMonsterName(CMonster* pMon) { switch (pMon->GetType()) { // 또또! case MONSTER_NORMAL: return "일반 몬스터"; case MONSTER_ELITE: return "정예 몬스터"; case MONSTER_BOSS: return "보스"; } }
새 몬스터 타입 추가하면?

3곳 전부 수정해야 해. 10곳이면 10곳 다.

그리고 하나라도 놓치면 버그야.

Part 2. 다형성으로 어떻게 바꿔?

다형성이 뭔데?

각 타입을 별도 클래스로 만들고,

switch 분기를 가상 함수로 대체하는 거야.

        ┌─────────────────┐
        │   CMonster      │ ◀── 기반 클래스
        │  + GetDamage()  │     (순수 가상 함수)
        │  + GetExp()     │
        │  + GetName()    │
        └────────┬────────┘
                 │
        ┌────────┼────────┐
        │        │        │
        ▼        ▼        ▼
    ┌────────┐┌────────┐┌────────┐
    │ Normal ││ Elite  ││  Boss  │
    │Monster ││Monster ││Monster │
    └────────┘└────────┘└────────┘
// ✅ 다형성으로 리팩토링 // 기반 클래스 class CMonster { public: virtual ~CMonster() {} virtual int GetDamage() const = 0; // 순수 가상 함수 virtual int GetExp() const = 0; virtual const char* GetName() const = 0; protected: int m_nAtk; }; // 일반 몬스터 class CNormalMonster : public CMonster { public: int GetDamage() const override { return m_nAtk * 1; } int GetExp() const override { return 100; } const char* GetName() const override { return "일반 몬스터"; } }; // 정예 몬스터 class CEliteMonster : public CMonster { public: int GetDamage() const override { return m_nAtk * 2; } int GetExp() const override { return 500; } const char* GetName() const override { return "정예 몬스터"; } }; // 보스 몬스터 class CBossMonster : public CMonster { public: int GetDamage() const override { return m_nAtk * 5; } int GetExp() const override { return 5000; } const char* GetName() const override { return "보스"; } };
사용하는 쪽은?

switch 없이 깔끔하게 호출해.

// switch 없이 깔끔하게 호출 void ProcessDamage(CMonster* pMon, CGamePC* pPC) { int damage = pMon->GetDamage(); // 타입에 맞는 함수가 자동 호출! pPC->TakeDamage(damage); } void GiveReward(CMonster* pMon, CGamePC* pPC) { int exp = pMon->GetExp(); // switch 불필요! pPC->AddExp(exp); }

Part 3. 새 타입 추가할 때

레이드 보스를 추가하고 싶어

새 클래스 파일 1개만 추가하면 돼!

기존 코드는 수정 안 해도 됨.

// 새 파일: RaidBossMonster.h - 이것만 추가! class CRaidBossMonster : public CMonster { public: int GetDamage() const override { return m_nAtk * 10; } int GetExp() const override { return 50000; } const char* GetName() const override { return "레이드 보스"; } // 레이드 보스만의 특수 기능도 추가 가능 void EnrageMode() { m_nAtk *= 2; } }; // MonsterFactory.cpp에 1줄 추가 case MONSTER_RAID_BOSS: return new CRaidBossMonster();
Before vs After 비교

Before (switch 방식):
새 몬스터 추가 → GetDamage, GetExp, GetName 등 10곳 수정

After (다형성):
새 클래스 1개 추가 + Factory에 1줄. 끝!
개방-폐쇄 원칙 (OCP)

"확장에는 열려있고, 수정에는 닫혀있다"

새 타입을 추가할 때 기존 코드를 수정하지 않아도 됨!

Part 4. 우리 프로젝트에 적용할 곳

게임 서버에서 어디에 적용해?

이런 패턴들이 있어:

switch 패턴 다형성 클래스
몬스터 타입별 처리 CMonster → CNormal, CElite, CBoss
스킬 타입별 효과 CSkill → CAttackSkill, CBuffSkill
아이템 타입별 사용 CItem → CWeapon, CArmor, CPotion
퀘스트 타입별 완료 CQuest → CKillQuest, CCollectQuest

Part 5. 언제는 안 해도 돼?

모든 switch를 다형성으로 바꿔야 해?

아니, 과하게 하지 마.

과도한 적용 주의

• switch가 1곳뿐이면 굳이 클래스 계층 불필요
• 분기가 2-3개뿐이고 확장 가능성 낮으면 switch가 나음
• 단순 값 반환만 하는 경우 맵/테이블이 더 적합
• 레거시 코드에서 대규모 변경이 필요하면 위험
// 단순 값 매핑은 테이블이 더 간단 std::map<int, int> MonsterExpTable = { {MONSTER_NORMAL, 100}, {MONSTER_ELITE, 500}, {MONSTER_BOSS, 5000} }; int GetExp(int type) { return MonsterExpTable[type]; }

핵심 정리: 조건문 → 다형성

  • 같은 switch가 여러 곳에 반복되면 다형성 고려
  • 각 타입을 별도 클래스로 분리
  • switch 분기를 가상 함수 오버라이드로 대체
  • 새 타입 추가 = 새 클래스 추가 (기존 코드 수정 X)
  • switch 1곳, 분기 2-3개면 그냥 switch 사용
