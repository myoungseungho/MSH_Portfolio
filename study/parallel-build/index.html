Part 1. 8코어인데 1코어만 쓴다고?

빌드할 때 CPU 사용량 보니까 12%밖에 안 쓰던데?

8코어 CPU인데 1코어만 쓰고 있다는 거야!

기본 설정은 순차 컴파일이거든.

❌ 기본 설정 (순차 컴파일) 시간 ─────────────────────────────────────→ Core 1: [main.cpp]─[game.cpp]─[player.cpp]─[monster.cpp]─... Core 2: 💤 (놀고 있음) Core 3: 💤 (놀고 있음) Core 4: 💤 (놀고 있음) Core 5: 💤 (놀고 있음) Core 6: 💤 (놀고 있음) Core 7: 💤 (놀고 있음) Core 8: 💤 (놀고 있음) CPU 사용률: 12.5% (1/8) 빌드 시간: 2분
왜 기본이 순차야? 병렬이 당연히 빠를 텐데.

역사적인 이유야. 옛날에는 싱글코어가 대부분이었거든.

그리고 병렬화하면 메모리 사용량이 늘어나는 부작용도 있어.

Part 2. /MP - 병렬 컴파일

어떻게 병렬로 바꿔?

/MP 옵션을 켜면 돼!

Multi-Processor Compilation의 약자야.

🔧 /MP 설정 방법

프로젝트 속성 → C/C++ → General

Multi-processor Compilation: Yes (/MP)

✅ /MP 적용 후 (병렬 컴파일) 시간 ──────────────────→ Core 1: [main.cpp ]─[skill.cpp ] Core 2: [game.cpp ]─[quest.cpp ] Core 3: [player.cpp]─[npc.cpp ] Core 4: [monster.cpp]─[item.cpp ] Core 5: [map.cpp ]─[shop.cpp ] Core 6: [party.cpp ]─[chat.cpp ] Core 7: [guild.cpp ]─[mail.cpp ] Core 8: [event.cpp ]─[log.cpp ] CPU 사용률: 100%! 빌드 시간: 15초! (2분 → 15초)
와 8배 빨라진 거야?

이론적으로는 그래! 실제로는 4~6배 정도.

파일 크기가 다르고, 디스크 I/O 병목도 있거든.

Part 3. /MP 숫자의 의미

/MP8 이런 식으로 숫자를 붙이던데?

동시에 컴파일할 최대 프로세스 수야!

옵션 의미 권장 상황
/MP 자동 (CPU 코어 수만큼) 대부분의 경우
/MP4 최대 4개 동시 메모리가 부족할 때
/MP16 최대 16개 동시 고성능 서버
그냥 /MP 쓰면 알아서 해주는구나!

맞아! CPU 코어 수에 맞춰서 자동 결정해.

8코어면 8개, 16코어면 16개 동시 컴파일.

Part 4. 링킹도 병렬화할 수 있어?

컴파일은 빨라졌는데, 링킹도 1코어만 쓰는 것 같아.

맞아! 링킹은 기본적으로 순차 처리야.

근데 /CGTHREADS 옵션으로 병렬화 가능!

🔧 /CGTHREADS 설정 방법

프로젝트 속성 → Linker → Command Line

Additional Options: /CGTHREADS:8

📊 /CGTHREADS의 역할 링킹 과정 중 "코드 생성(Code Generation)" 단계를 병렬화! ❌ 기본: [심볼 해결]─[코드생성 ████████████████████]─[출력] ↑ 여기가 오래 걸림 (1코어) ✅ /CGTHREADS:8: [심볼 해결]─[코드생성 ████]─[출력] [코드생성 ████] [코드생성 ████] [코드생성 ████] ← 8코어 동시!
링킹 시간도 줄어드는구나!

큰 프로젝트에서 효과가 커. 특히 Release 빌드!

최적화 코드 생성에 시간이 많이 들거든.

Part 5. 병렬 빌드 주의사항

무조건 병렬화하면 좋은 거 아냐?

대부분 좋지만, 몇 가지 주의점이 있어!

주의사항 설명 해결책
메모리 사용량 증가 코어당 컴파일러 인스턴스 /MP4로 제한
PCH와 함께 사용 시 .pch 파일 동시 접근 이슈 VS 2019+ 자동 해결
빌드 출력 뒤섞임 여러 파일 로그가 섞임 정상 동작, 무시해도 됨
💾 메모리 사용량 비교 /MP 없음: 컴파일러 1개 × 500MB = 500MB /MP (8코어): 컴파일러 8개 × 500MB = 4GB! 메모리 8GB 미만이면 /MP4 정도로 제한 권장

Part 7. 프로젝트 단위 병렬 빌드

솔루션에 프로젝트가 여러 개면?

MSBuild의 /m 옵션으로 프로젝트도 병렬 빌드!

📦 솔루션 수준 병렬화 chosun_server.sln ├── server_Game ─┐ ├── server_Login ─┼─→ 의존성 없으면 동시 빌드! ├── server_Gate ─┘ ├── server_GameDB ─┐ ├── server_AccountDB ─┼─→ 이것들도 동시에! └── server_CashDB ─┘ MSBuild 명령: msbuild chosun_server.sln /m /p:Configuration=Debug /m = 최대 병렬 (코어 수만큼) /m:4 = 최대 4개 프로젝트 동시
그럼 /MP랑 /m을 같이 쓰면?

이중 병렬화!

프로젝트도 동시에, 각 프로젝트 안에서도 파일 동시 컴파일!

📝 핵심 정리

  • /MP: 파일 단위 병렬 컴파일 (CPU 100% 활용)
  • /CGTHREADS:N: 링킹 중 코드 생성 병렬화
  • /m: 솔루션 내 프로젝트 병렬 빌드
  • 세 가지 조합하면 빌드 시간 50%+ 단축
  • 메모리 부족하면 /MP4 등으로 제한
  • VS 2019 이상에서 PCH와 잘 호환
