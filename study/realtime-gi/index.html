그늘진 곳도 왜 완전히 까맣지 않을까?

실시간 Global Illumination의 원리

Part 1. 일상에서 발견하는 GI

방에서 커튼을 닫으면 완전히 깜깜해져?

아니지. 커튼을 닫아도 방 안은 어둡지만 완전히 까맣진 않아.

왜일까? 빛이 여기저기서 튕겨오기 때문이야.

현실에서의 빛: 창문 ─────→ 벽1 ─────→ 벽2 ─────→ 천장 │ │ │ │ │ 반사 반사 반사 │ │ │ │ └──────────┴──────────┴──────────┘ ↓ 방 전체가 은은하게 밝아짐 (직접 햇빛 안 닿는 곳도!) 빛은 계속 튕기면서 에너지가 조금씩 줄어들어. 하지만 여러 번 튕긴 빛이 쌓여서 그늘도 밝아지는 거야.
그걸 게임에서 구현 안 하면 어떻게 돼?

직접 빛만 계산하면 그늘진 곳이 완전히 새까맣게 보여.

현실과 완전히 다른, 부자연스러운 그래픽이 되는 거지.

[GI 없음 - 직접광만] [GI 있음 - 간접광 포함] * 태양 * 태양 \ \ \ \ ┌────\────┐ ┌────\────┐ │밝음│검정│ │밝음│ 어둠│ │████│ │ │████│░░░░│ │████│ │ ← 완전 검정 │████│░░░░│ ← 은은하게 밝음 └─────────┘ └─────────┘ 게임에서 건물 뒤편이 완전히 검게 보이면 이상하잖아? 실제로는 하늘빛, 바닥 반사빛이 있으니까.

Part 2. 빛의 반사는 "무한 반복"

그럼 빛이 몇 번이나 튕겨?

이론적으로는 무한 번이야. 매번 에너지가 줄어들 뿐이지.

🎱 비유: 당구공

당구공을 치면 벽에 부딪혀서 여러 번 튕기잖아?
처음엔 빠르지만 점점 느려지다가 결국 멈춰.

빛도 마찬가지야. 벽에 부딪힐 때마다 일부가 흡수되고,
남은 빛만 튕겨나가. 그래서 점점 약해지다가 거의 0이 돼.
빛의 반사 과정 (Bounce): 1번째 반사 (Primary Bounce) 태양 ──→ 바닥 (100% → 60% 반사) 2번째 반사 (Secondary Bounce) 바닥 ──→ 벽 (60% → 36% 반사) 3번째 반사 (Tertiary Bounce) 벽 ──→ 천장 (36% → 22% 반사) 4번째, 5번째... 점점 약해져서 무시 가능 보통 게임에서는 2~3번 반사까지만 계산해.
무한히 반복하면 게임이 엄청 느려지지 않아?

맞아, 그래서 문제야. 빛이 튕기는 걸 전부 계산하면 1프레임에 몇 시간 걸려.

영화는 괜찮아. 어차피 미리 렌더링하니까. 하지만 게임은 실시간이잖아.

그래서 여러 가지 "꼼수"가 필요해. 정확하진 않지만 빠른 방법들.

Part 3. 가장 간단한 방법 - "미리 구워놓자"

그럼 미리 계산해두면 안 돼?

정확히 그 방법이 Baked Lightmap이야!

🍞 비유: 빵 굽기

매번 손님이 올 때마다 빵 반죽부터 하면 너무 오래 걸리잖아?
그래서 미리 빵을 구워놔. 손님이 오면 바로 꺼내주면 끝.

게임도 마찬가지야. 빛 계산을 미리 "굽고(Bake)" 텍스처로 저장해.
Baked Lightmap 방식: [개발 단계 - 오프라인] 빛 시뮬레이션 (수 시간) │ ▼ ┌─────────────┐ │ Lightmap │ ← 빛 정보가 담긴 텍스처 │ Texture │ └─────────────┘ [게임 실행 시 - 런타임] 3D 모델 + Lightmap = 완성된 조명 │ ▼ 그냥 텍스처 읽기만 하면 끝! (매우 빠름) 장점: 아주 빠르고, 품질도 최고급 단점: 빛이 바뀌면? 다시 구워야 해...
그럼 낮/밤 바뀌는 건 어떻게 해?

그게 문제지. Bake 방식은 동적인 빛에 대응 못 해.

오픈월드 게임에서 시간이 흐르면? Lightmap 무용지물.

그래서 나온 게 실시간 GI야.

Part 4. 실시간 GI - "요약본을 저장하자"

실시간으로 빛 반사를 계산할 수 있어?

완벽하게는 못 하지만, "요약해서" 저장하면 가능해.

📝 비유: 수업 노트

수업 전체를 녹화하면 용량이 엄청 크잖아?
대신 핵심만 요약한 노트를 만들면 가볍고 빠르게 복습 가능해.

GI도 마찬가지야. 공간의 빛 정보를 "요약"해서 저장해.

대표적인 방법이 Light Probe야.

Light Probe가 뭔데?

공간에 "빛 측정기"를 띄엄띄엄 배치하는 거야.

Light Probe 배치: * * * * ← Probe들 (공 모양으로 상상) ┌───────┐ │ │ * │ 방 │ * * │ │ └───────┘ * * * * 각 Probe는 그 위치에서 보이는 빛을 360도 기록해. "여기는 위에서 파란 빛, 아래서 갈색 빛이 오네~" 캐릭터가 움직이면? → 가까운 Probe 4개의 값을 섞어서 사용!

Probe 안에는 SH (Spherical Harmonics)라는 형태로 저장해.

복잡한 빛 분포를 단 9~16개 숫자로 요약하는 수학 기법이야.

근데 Probe도 미리 계산해야 하는 거 아냐?

옛날에는 그랬어. 근데 이제는 실시간으로 Probe를 업데이트해!

NVIDIA의 DDGI(Dynamic Diffuse GI)가 대표적이야.

DDGI 작동 방식: [매 프레임] 1. 각 Probe에서 레이(광선) 발사 * Probe /|\ / | \ → 64~256개 방향으로 빛 쏴봐 ↙ ↓ ↘ 어디서 무슨 색이 튕겨오는지 확인 2. 결과를 Probe에 저장 3. 캐릭터 렌더링할 때 Probe 값 참조 장점: 빛이 바뀌면 Probe도 같이 업데이트! 단점: 레이트레이싱 필요 → 비싼 GPU 필요

Part 5. Lumen - 언리얼 5의 GI

언리얼 5의 Lumen은 뭐가 달라?

Lumen은 여러 기법을 섞은 하이브리드야.

Lumen의 전략: ┌─────────────────────────────────────────┐ │ 상황에 따라 다른 방법 사용 │ ├─────────────────────────────────────────┤ │ │ │ [가까운 것] - Screen Space 트레이싱 │ │ 화면에 보이는 것끼리 반사 계산 │ │ 빠르지만 화면 밖은 모름 │ │ │ │ [중간 거리] - Software 레이마칭 │ │ RTX 없이도 SDF로 빛 추적 │ │ 대부분의 환경 반사 담당 │ │ │ │ [먼 것] - 프로브 기반 │ │ 미리 계산한 프로브 값 사용 │ │ 하늘 반사 등 대략적인 GI │ │ │ │ [RTX 있으면] - 하드웨어 레이트레이싱 │ │ 가장 정확하지만 비쌈 │ │ │ └─────────────────────────────────────────┘ 핵심: 상황에 맞게 "싼 방법"과 "비싼 방법" 혼합!
RTX 없이도 되는 거야?

응, 소프트웨어로도 돼! 그게 Lumen의 장점이야.

비결은 SDF (Signed Distance Field)야.

SDF 레이마칭: 물체의 "거리 정보"를 미리 계산해둬: "이 점에서 가장 가까운 표면까지 3m" 레이를 쏠 때: ┌────────────────────────────────────┐ │ │ │ 출발 ●──(3m)──●──(1m)──●──●표면 │ │ │ │ "3m 안전하니까 3m 점프!" │ │ "1m 안전하니까 1m 점프!" │ │ "거의 0m... 표면 도착!" │ │ │ └────────────────────────────────────┘ 픽셀 하나하나 계산 안 해도 되니까 빠름! RTX 가속 없이도 레이트레이싱 "비슷하게" 가능.

Part 6. Color Bleeding - GI의 꽃

GI 하면 뭐가 제일 달라 보여?

Color Bleeding이 제일 눈에 띄어.

빨간 벽 옆에 있으면 얼굴이 붉게 물드는 현상!

Color Bleeding: ┌──────────────────────────────────────┐ │ │ │ ████ │ │ ████ 빨간 벽 │ │ ████ │ │ \ │ │ \ 빛이 반사될 때 │ │ \ 벽의 색깔도 같이 튕김! │ │ \ │ │ ↘ │ │ 😊 ← 얼굴이 붉게 물듦 │ │ │ └──────────────────────────────────────┘ GI 없으면: 얼굴은 그냥 회색 그림자 GI 있으면: 얼굴에 은은한 빨간 빛이 비침 이 차이가 사실적인 느낌을 만들어!

영화 포스터에서 조명 쓸 때도 이 효과를 일부러 만들어.

Part 7. 성능과 품질의 트레이드오프

그래서 요즘 게임은 다 GI 쓰는 거야?

대부분 쓰지만, 품질과 성능은 반비례해.

GI 방식별 비교: ┌─────────────────────────────────────────────┐ │ 방식 │ 속도 │ 품질 │ 동적 대응 │ ├─────────────────────────────────────────────┤ │ Baked Lightmap │ ★★★★★ │ ★★★★★ │ ✗ │ │ Light Probes │ ★★★★ │ ★★★ │ △ (제한적) │ │ SSGI │ ★★★★ │ ★★ │ ○ │ │ Lumen │ ★★★ │ ★★★★ │ ○ │ │ DDGI │ ★★ │ ★★★★ │ ○ │ │ Path Tracing │ ★ │ ★★★★★ │ ○ │ └─────────────────────────────────────────────┘ Path Tracing이 가장 정확하지만, 아직 게임에서 60fps로 돌리긴 어려워.
앞으로는 어떻게 될까?

GPU가 좋아지면서 점점 실시간 Path Tracing에 가까워지고 있어.

언젠가는 영화 수준의 GI가 게임에서도 실시간으로 돌아갈 거야!

📌 핵심 정리

  • Global Illumination - 빛이 여러 번 튕겨 그늘도 밝아지는 현상
  • Baked Lightmap - 미리 구워두는 방식 (빠르지만 동적 대응 불가)
  • Light Probe - 공간에 빛 측정기를 배치해 요약 저장
  • DDGI - 프로브를 실시간 레이트레이싱으로 업데이트
  • Lumen - 여러 기법을 상황에 맞게 혼합 (UE5)
  • Color Bleeding - 색깔 있는 표면이 주변에 색을 물들임
