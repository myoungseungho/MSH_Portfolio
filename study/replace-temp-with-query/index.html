Replace Temp with Query

임시 변수를 질의 함수로 바꾸기

Part 1. 임시 변수를 왜 바꿔?

변수에 담아두는 게 더 편한데?

편하긴 해. 근데 재사용이 안 돼.

그 변수는 그 함수 안에서만 유효하잖아.

그럼 어떻게 해?

계산 결과를 담는 임시 변수 대신, 그 계산을 수행하는 메서드를 만들어.

basePrice 변수 대신 GetBasePrice() 메서드.

계산기 vs 메모 비유

메모에 "123 + 456 = 579" 적어두고 계속 보기 vs
필요할 때마다 계산기로 123 + 456 치기

메모는 그 자리에서만 유효해. 계산기(질의)는 어디서든 같은 답을 줘.

Part 2. 성능 문제는?

매번 계산하면 느리지 않아?

자주 나오는 걱정인데:

성능 걱정 해결

1. 대부분 체감 안 됨 - 단순 계산 몇 번 더 하는 건 무시할 수준
2. 측정 후 판단 - "느릴 것 같다"가 아니라 프로파일링
3. 필요하면 캐싱 - 메서드 내부에서 캐싱하면 호출자는 몰라도 됨
진짜 조심할 때

루프 안에서 매번 호출되는 무거운 계산일 때만 조심해.
10만 번 도는 루프 안에서 DB 조회를 매번? 그건 문제.
단순 수식 계산? 걱정 안 해도 돼.

Part 3. 언제 써?

언제 질의로 바꾸고, 언제 변수 그대로 둬?

이렇게 판단해:

질의로 바꾸면 좋은 경우

- 같은 계산이 여러 메서드에서 필요할 때
- 계산 로직에 이름을 붙여 의도를 드러내고 싶을 때
- 메서드 추출하려는데 임시 변수가 방해될 때
- 변수가 한 번만 할당되고 변하지 않을 때
변수 유지가 나은 경우는?

루프 안에서 여러 번 사용되는 무거운 계산.

디버깅 시 중간값 확인이 필요할 때.

핵심 정리: Replace Temp with Query

  • 방법: 임시 변수 대신 계산하는 메서드 생성
  • 장점: 재사용성, 의도 표현
  • 성능: 대부분 문제없음, 측정 후 판단
  • 대상: 한 번 할당되는 변수
  • 활용: Extract Method 전 선행 작업
