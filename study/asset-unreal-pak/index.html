Unreal Pak 파일 구조

.pak 파일 안에는 뭐가 들어있을까?

Part 1. Pak 파일이란?

Pak 파일이 뭐야?

.pak = 언리얼의 에셋 아카이브 포맷

여러 파일을 하나로 묶어서 효율적으로 배포

Pak 파일 = ZIP과 비슷한 개념: 빌드 전 (개별 파일): Content/ ├── Characters/ │ ├── Warrior.uasset │ └── Archer.uasset ├── Maps/ │ └── Level1.umap └── Textures/ ├── Ground.uasset └── Sky.uasset 빌드 후 (Pak으로 묶음): MyGame-WindowsNoEditor.pak (500MB) ├── ../Content/Characters/Warrior.uasset ├── ../Content/Characters/Archer.uasset ├── ../Content/Maps/Level1.umap ├── ../Content/Textures/Ground.uasset └── ../Content/Textures/Sky.uasset 장점: - 하나의 파일로 배포 간편 - 압축 가능 (용량 절감) - 암호화 가능 (해킹 방지) - 순차 읽기 최적화 (HDD 성능)

Part 2. Pak 파일 내부 구조

Pak 파일 안은 어떻게 생겼어?

데이터 + 인덱스 + 푸터 구조

Pak 파일 바이너리 구조: ┌──────────────────────────────────────────────────┐ │ │ │ 파일 데이터 영역 │ │ ┌────────────────────────────────────────┐ │ │ │ File 1 Data (압축/암호화 가능) │ │ │ ├────────────────────────────────────────┤ │ │ │ File 2 Data │ │ │ ├────────────────────────────────────────┤ │ │ │ File 3 Data │ │ │ ├────────────────────────────────────────┤ │ │ │ ... │ │ │ └────────────────────────────────────────┘ │ │ │ ├──────────────────────────────────────────────────┤ │ │ │ 인덱스 (파일 목록) │ │ ┌────────────────────────────────────────┐ │ │ │ MountPoint: "../../../" │ │ │ │ FileCount: 1000 │ │ │ │ File 1: Name, Offset, Size, Hash │ │ │ │ File 2: Name, Offset, Size, Hash │ │ │ │ ... │ │ │ └────────────────────────────────────────┘ │ │ │ ├──────────────────────────────────────────────────┤ │ 푸터 (Footer) │ │ ┌────────────────────────────────────────┐ │ │ │ Magic: 0x5A6F12E1 │ │ │ │ Version: 11 │ │ │ │ IndexOffset: 0x1F3A0000 │ │ │ │ IndexSize: 524288 │ │ │ │ IndexHash: SHA1 │ │ │ └────────────────────────────────────────┘ │ └──────────────────────────────────────────────────┘ 읽기 순서: 1. 파일 끝에서 푸터 읽기 2. 푸터의 IndexOffset으로 인덱스 찾기 3. 인덱스에서 원하는 파일의 Offset 확인 4. 해당 Offset에서 데이터 읽기

Part 3. 마운트 포인트

마운트 포인트가 뭐야?

Mount Point = Pak 내 파일들의 가상 루트 경로

마운트 포인트 동작: Pak 파일 (MountPoint: "../../../") ├── Content/Characters/Warrior.uasset └── Content/Maps/Level1.umap 게임 실행 시 마운트: MyGame/ ├── Content/ ← 실제 폴더 │ └── (비어있음) └── Saved/ ↓ Pak 마운트 후 MyGame/ ├── Content/ ← Pak에서 가상 매핑 │ ├── Characters/ │ │ └── Warrior.uasset ← Pak에서 읽음! │ └── Maps/ │ └── Level1.umap ← Pak에서 읽음! └── Saved/ 코드에서는 경로만 사용: FString Path = "/Game/Characters/Warrior"; → Pak에서 자동으로 찾아줌!

Part 4. 청킹 (Chunking)

DLC는 어떻게 별도로 배포해?

청킹: 콘텐츠를 여러 Pak으로 분리

청킹 설정: Project Settings > Packaging > Asset Manager Chunk 0: 기본 게임 (항상 포함) ├── 코어 시스템 ├── 플레이어 캐릭터 └── 메인 메뉴 Chunk 1: DLC 1 ├── 새 맵 ├── 새 캐릭터 └── 새 퀘스트 Chunk 2: DLC 2 └── ... 빌드 결과: WindowsNoEditor/ ├── MyGame-WindowsNoEditor.pak (Chunk 0) ├── pakchunk1-WindowsNoEditor.pak (Chunk 1 = DLC1) └── pakchunk2-WindowsNoEditor.pak (Chunk 2 = DLC2) 장점: - 기본 게임: 필수 다운로드 - DLC: 구매 시에만 다운로드 - 패치: 변경된 청크만 업데이트
// PrimaryAssetLabel로 청크 지정 // 에디터에서 에셋에 라벨 할당: // Asset → Asset Actions → Assign to Chunk // DefaultGame.ini 설정 [/Script/UnrealEd.ProjectPackagingSettings] bGenerateChunks=True // C++에서 런타임 마운트 bool MountDLC(FString PakPath) { FPakPlatformFile* PakPlatform = (FPakPlatformFile*)(FPlatformFileManager::Get() .FindPlatformFile(TEXT("PakFile"))); if (PakPlatform) { return PakPlatform->Mount(*PakPath, 0, nullptr); } return false; }

Part 5. 암호화와 서명

해커가 Pak을 열어보면 어떡해?

AES 암호화로 콘텐츠 보호 가능

암호화 옵션: Project Settings > Packaging > Pak File Settings ┌────────────────────────────────────────────────┐ │ ☑ Encrypt Pak Index │ │ → 파일 목록 암호화 (파일명 숨김) │ │ │ │ ☑ Encrypt Ini Files │ │ → 설정 파일 암호화 │ │ │ │ ☑ Encrypt UAsset Files │ │ → 에셋 파일 암호화 │ │ │ │ ☐ Sign Pak Files │ │ → 무결성 검증용 서명 (변조 감지) │ └────────────────────────────────────────────────┘ 암호화 키 설정: Project Settings > Crypto > Encryption Key → 256-bit AES 키 설정 (Base64) 주의! - 암호화해도 메모리 덤프로 추출 가능 - 완벽한 보안은 불가능, 난이도만 높임 - 키는 .ini 파일에 저장되므로 별도 보호 필요

Part 6. UnrealPak 커맨드라인

수동으로 Pak 만들고 싶으면?

UnrealPak.exe로 직접 생성/추출 가능

// Pak 파일 생성 UnrealPak.exe MyContent.pak -Create=FileList.txt // FileList.txt 형식: "D:\Content\Characters\*.*" "../../../Content/Characters/" "D:\Content\Maps\*.*" "../../../Content/Maps/" // Pak 파일 내용 목록 보기 UnrealPak.exe MyContent.pak -List // Pak 파일 추출 UnrealPak.exe MyContent.pak -Extract D:\Extracted\ // 압축 옵션 (Oodle 사용) UnrealPak.exe MyContent.pak -Create=FileList.txt -compress // 암호화 옵션 UnrealPak.exe MyContent.pak -Create=FileList.txt -encrypt -encryptindex // IoStore 포맷 (UE5+) UnrealPak.exe MyContent.pak -Create=FileList.txt -IoStore

Part 7. IoStore (UE5 신기능)

UE5에서 바뀐 게 있어?

UE5의 IoStore: 더 빠른 I/O 최적화 포맷

Pak vs IoStore: 기존 Pak: ┌──────────────────────────────────────────┐ │ MyGame.pak │ │ └── 순차적 파일 배치 │ │ → HDD에 최적화 │ │ → 랜덤 접근 시 느림 │ └──────────────────────────────────────────┘ IoStore (UE5): ┌──────────────────────────────────────────┐ │ MyGame.utoc (Table of Contents) │ │ └── 에셋 메타데이터, 압축 정보 │ │ │ │ MyGame.ucas (Content Archive Storage) │ │ └── 실제 에셋 데이터 │ │ → 64KB 블록 단위 압축 │ │ → 병렬 압축 해제 │ │ → SSD/NVMe에 최적화 │ └──────────────────────────────────────────┘ IoStore 장점: - 비동기 I/O 친화적 - DirectStorage 연계 가능 - 블록 단위 압축/해제 - 더 빠른 로딩 속도

핵심 정리

  • .pak: 언리얼의 에셋 아카이브 포맷
  • 구조: 데이터 + 인덱스 + 푸터
  • 마운트 포인트: 가상 루트 경로 매핑
  • 청킹: DLC/패치를 위한 콘텐츠 분리
  • 암호화: AES 256-bit로 콘텐츠 보호
  • IoStore: UE5의 SSD 최적화 포맷
