← AI 활용

NPC가 진짜로 살아있으려면, AI가 뭘 해야 하는 건데?

기억하는 NPC, 학습하는 보스, 감정, 생태계, 소문 — 각각의 원리

Part 0. 전제 — "살아있다"의 5단계

NPC가 "살아있다"는 게 정확히 뭘 의미해?

살아있는 존재의 특성을 분해해보면 5개 레이어로 나뉘어.

각 레이어마다 필요한 AI 기술이 다르고, 이 문서는 그걸 하나씩 풀어가는 거야.

[살아있는 NPC의 5개 레이어] Level 1. 기억 (Memory) → "이 유저가 나한테 뭘 했는지 안다" → 기술: 이벤트 로그 + 벡터 검색 Level 2. 적응 (Adaptation) → "같은 수법은 두 번 안 통한다" → 기술: 패턴 인식 + 카운터 전략 Level 3. 감정 (Emotion) → "무섭거나 화나거나 좋아한다" → 기술: 감정 상태 모델 Level 4. 생태 (Ecology) → "다른 생물과 먹이사슬로 연결된다" → 기술: 에이전트 시뮬레이션 Level 5. 사회 (Society) → "정보를 주고받고, 여론이 형성된다" → 기술: 정보 전파 알고리즘 밑으로 갈수록 복잡하지만, 각각의 원리 자체는 놀라울 정도로 단순하다.

Part 1. 기억하는 NPC — "너 지난번에 나 털었잖아"

NPC가 과거를 기억한다는 게, 기술적으로 어떻게 되는 거야?

비유부터 하나 해볼게.

[비유: 동네 가게 사장님] 기억 없는 NPC = 대형마트 캐셔 → 매번 "어서오세요" (누가 와도 똑같음) → 어제 10번 와도 오늘 처음 보는 사람 취급 기억 있는 NPC = 동네 가게 사장님 → "아, 어제 라면 사간 학생! 또 왔네?" → "요즘 맨날 오네, 단골이야 단골" → "지난달에 외상 아직 안 갚았잖아..." 사장님의 비밀: 머릿속에 "이 사람 = 라면 자주 삼, 외상 있음, 단골" 이라는 태그가 붙어있음.
그 "태그"를 기술적으로 어떻게 구현해?

이벤트 로그 + 요약 점수로 구현해. 생각보다 단순해.

[원리: 이벤트 로그 → 관계 점수 → 행동 변화] 1단계: 이벤트 기록 ┌──────────┬──────────┬─────────────┐ │ 시간 │ 유저ID │ 행동 │ ├──────────┼──────────┼─────────────┤ │ 1일 전 │ 영희 │ 물건 구매 │ │ 1일 전 │ 철수 │ NPC 공격 │ │ 3시간 전 │ 영희 │ 퀘스트 완료 │ │ 1시간 전 │ 철수 │ NPC 공격 │ │ 30분 전 │ 철수 │ NPC 공격 │ └──────────┴──────────┴─────────────┘ → 그냥 기록만 쌓는다. 이건 DB나 배열이면 됨. 2단계: 관계 점수 계산 영희: 구매(+2) + 퀘스트(+5) = 호감도 +7 → "단골" 철수: 공격(-3) × 3회 = 호감도 -9 → "원수" 이 계산은 단순 덧뺄셈이다. AI가 필요 없다. 3단계: 행동 변화 (여기서 AI가 등장) 호감도 > +5 → "반갑네! 오늘은 할인해줄게" + 가격 10% 할인 호감도 -3~+5 → "어서오세요" (기본) 호감도 < -3 → "또 왔어?" + 가격 20% 인상 호감도 < -8 → NPC가 도망가거나 경비병 호출
잠깐, 이건 그냥 if-else 아니야? 여기서 AI가 뭘 해?

맞아. 여기까지는 AI가 없어도 돼. AI가 진짜 빛나는 건 "대사 생성"이야.

[AI가 없을 때 vs 있을 때] AI 없음 (기존 방식): if (호감도 > 5) → "반갑습니다, 모험가님!" if (호감도 < -3) → "당신과는 거래하고 싶지 않군." → 대사가 고정. 10번 와도 같은 말. 기억은 있지만 "표현"이 없음. AI 있음 (LLM 연동): 프롬프트: "너는 대장장이 NPC다. 이 유저의 기록을 보고 대사를 생성해라." "유저 기록: 3일 연속 방문, 검 3개 구매, 호감도 +12" NPC 대사: "오! 3일 연속이잖아. 이쯤 되면 단골 중의 단골이지. 검은 이제 질리지 않아? 오늘은 창도 한번 봐봐." → 같은 호감도 +12여도, "기록"에 따라 대사가 달라짐. → "기억하는 것처럼 느껴지는" 건 이 표현 때문.
그러면 전체 구조는?
[기억하는 NPC — 전체 아키텍처] 유저 행동 ↓ ┌─────────────┐ │ 이벤트 로그 │ ← DB에 쌓기만 함 (단순) │ (기록 저장) │ └──────┬──────┘ ↓ ┌─────────────┐ │ 관계 점수 │ ← 덧뺄셈 (단순) │ (호감/적대) │ └──────┬──────┘ ↓ ┌─────────────┐ │ 행동 결정 │ ← if-else 또는 FSM (단순) │ (할인/거부) │ └──────┬──────┘ ↓ ┌─────────────┐ │ 대사 생성 │ ← LLM (여기가 AI) │ (자연어) │ └─────────────┘ 핵심: AI가 "기억"을 하는 게 아니다. DB가 기억하고, AI는 "기억을 표현"하는 것이다. 이걸 분리해서 이해해야 한다: 기억 = 데이터 (DB의 역할) 표현 = 자연어 생성 (AI의 역할)

Part 1 핵심

기억 자체는 DB 문제이고, 기억의 표현이 AI 문제다.

이벤트 로그(DB) + 관계 점수(수학) + 대사 생성(LLM) = 기억하는 NPC

각각은 단순한데, 조합하면 "살아있는 것처럼" 느껴진다.

Part 2. 학습하는 보스 — "같은 수법은 두 번 안 통한다"

보스가 플레이어 패턴을 학습한다는 게, 어떤 원리야?

비유를 하나 들어볼게.

[비유: 가위바위보 고수] 초보: 가위바위보를 랜덤으로 냄 → 승률 33% 고수: 상대가 뭘 냈는지 기록함 "이 사람 바위를 60%나 냄" → 다음에 보자기를 냄 → 승률 60% 이게 "학습하는 보스"의 전부야. 상대방의 행동 빈도를 세고, 가장 많이 하는 행동에 카운터를 치는 것.
이걸 보스전에 어떻게 적용해?
[원리: 행동 빈도 추적 → 카운터 선택] 1단계: 플레이어 행동 빈도 기록 ┌────────────────┬───────┬────────┐ │ 행동 │ 횟수 │ 비율 │ ├────────────────┼───────┼────────┤ │ 왼쪽 회피 │ 47 │ 62% │ │ 오른쪽 회피 │ 18 │ 24% │ │ 뒤로 회피 │ 8 │ 11% │ │ 가드 │ 3 │ 4% │ └────────────────┴───────┴────────┘ → 그냥 카운터를 세는 것. 배열에 +1 하면 됨. 2단계: 카운터 전략 매핑 (미리 정의) ┌────────────────┬─────────────────────────┐ │ 유저가 자주 │ 보스의 카운터 │ ├────────────────┼─────────────────────────┤ │ 왼쪽 회피 │ 왼쪽을 막는 광역기 │ │ 오른쪽 회피 │ 오른쪽으로 돌진 │ │ 뒤로 회피 │ 전방 돌진 후 후방 공격 │ │ 가드 │ 가드 브레이크 공격 │ └────────────────┴─────────────────────────┘ → 이 테이블도 개발자가 미리 만들어 놓는 것. 3단계: 보스의 다음 행동 선택 유저의 최다 행동 = 왼쪽 회피 (62%) → 보스: 40% 확률로 "왼쪽 봉쇄 광역기" 사용 → 나머지 60%는 기존 패턴 유지 왜 100%가 아니라 40%? → 100%면 유저가 "보스가 항상 왼쪽 막네" 하고 바로 적응 → 40%면 "어? 오늘따라 왼쪽이 위험한데?" 수준의 긴장감
이것도 AI 없이 되는 거 아니야?

맞아. 여기까지는 빈도수 세기 + if-else야.

하지만 여기서 강화학습(RL)을 붙이면 레벨이 완전히 달라져.

[빈도수 카운터 vs 강화학습 — 차이] 빈도수 카운터 (단순): "유저가 왼쪽 많이 감" → "왼쪽 막기" (고정 매핑) 한계: 유저가 "왼쪽 많이 가다가 갑자기 오른쪽"으로 바꾸면? → 카운터가 비율이 바뀔 때까지 몇 턴 걸림 → 그 사이에 유저가 이김 강화학습 (RL): State: [유저의 최근 5회 행동, HP 비율, 거리, 쿨타임] Action: [기본공격, 광역기, 돌진, 가드브레이크, 후퇴] Reward: 유저에게 데미지 +1.0, 보스가 데미지 받음 -0.5 학습 결과: → "유저가 왼쪽 3번 연속 → 다음도 왼쪽일 확률 높지만, 4번째는 일부러 바꿀 수 있다 → 기본공격으로 대기" → "유저 HP가 30% 이하면 공격적으로 나가야 끝낼 수 있다" → "유저가 포션 쓸 때 돌진하면 캔슬시킬 수 있다" 이런 판단은 if-else로 대본에 쓸 수 없다. "상대의 패턴 + 상황"을 종합해서 실시간 판단하는 것. 이게 RL이 필요한 이유.
근데 보스가 너무 강해지면 재미없지 않아?

여기가 핵심이야. "이기는 AI"는 쉽다. "재밌게 싸워주는 AI"가 어렵다.

[진짜 어려운 것: "적당히 강한" 보스] 나쁜 보상 설계: 보스가 이기면 +10 → 결과: 모든 공격을 완벽하게 피하고 최적 타이밍에 때림 → 유저: "이거 어떻게 이겨. 안 해." 좋은 보상 설계: 유저가 간신히 졌을 때 +2.0 ← 핵심! 유저가 간신히 이겼을 때 +1.0 유저를 압도적으로 이겼을 때 -1.0 ← 너무 강하면 벌점 보스가 압도적으로 졌을 때 -2.0 ← 너무 약해도 벌점 → 보스가 학습하는 것: "유저를 죽이되, 아슬아슬하게 죽여야 한다" "유저가 너무 쉽게 이겨도 안 되고, 절망하게 해도 안 된다" 이게 "적응형 난이도"의 핵심이야. "이기는 게 목적"이 아니라 "재밌는 싸움이 목적".

Part 2 핵심

단순 카운터는 빈도수 세기 + 매핑 테이블로 가능 (AI 불필요)

실시간 적응은 RL이 필요 (상황 조합이 대본에 쓸 수 없을 만큼 많으니까)

그리고 가장 어려운 건 "적당히 강한" 보상 설계다.

Part 3. 감정 있는 NPC — "이 NPC, 나한테 화났어?"

NPC에 감정을 넣는다는 게 어떤 원리야? 진짜 감정을 느끼는 건 아니잖아.

당연히 진짜 감정은 아니야. "감정처럼 보이는 숫자"를 관리하는 거야.

비유를 하나 들어볼게.

[비유: 감정 온도계] 사람의 감정을 관찰하면: 화남: 0~100 사이 어딘가 (30이면 살짝 짜증, 90이면 분노) 공포: 0~100 사이 어딘가 기쁨: 0~100 사이 어딘가 슬픔: 0~100 사이 어딘가 NPC의 감정도 이렇게 만들면 된다: anger: 42 fear: 15 joy: 60 sadness: 5 이건 그냥 변수 4개야. 비밀은 "이 숫자가 언제, 얼마나 변하느냐"에 있어.
그 숫자가 어떻게 변해?
[원리: 이벤트 → 감정 변화 → 행동 변화] 1단계: 이벤트 감지 "플레이어가 내 앞에서 다른 NPC를 죽였다" 2단계: 감정 변화 규칙 (미리 정의) ┌─────────────────────┬───────┬───────┬───────┬───────┐ │ 이벤트 │ 분노 │ 공포 │ 기쁨 │ 슬픔 │ ├─────────────────────┼───────┼───────┼───────┼───────┤ │ 플레이어가 선물 줌 │ -5 │ -5 │ +20 │ -5 │ │ 플레이어가 공격 │ +30 │ +10 │ -20 │ +5 │ │ 동료 NPC가 죽음 │ +10 │ +40 │ -30 │ +20 │ │ 퀘스트 완료 │ -5 │ -5 │ +15 │ -5 │ │ 플레이어가 무시 │ +10 │ 0 │ -5 │ +15 │ └─────────────────────┴───────┴───────┴───────┴───────┘ → 이 테이블은 게임 디자이너가 만든다. 3단계: 자연 감쇠 (시간이 지나면 감정이 누그러짐) 매 분마다: 모든 감정 × 0.95 (5%씩 줄어듦) → 분노 100이어도 1시간 후엔 5로 내려감 → "시간이 약이다"를 수학으로 표현한 것 4단계: 행동 변화 (감정 임계값) 분노 > 70 → 공격적 행동 (경비병이면 선공) 공포 > 60 → 도망 (유저가 다가오면 뒷걸음) 기쁨 > 50 → 할인, 보너스 퀘스트 제공 슬픔 > 70 → 대화 거부 ("지금은 말하고 싶지 않아...")
이것도 그냥 숫자 계산이잖아. 여기서 AI는 뭘 해?

두 가지 레벨이 있어.

[Level 1: AI 없이도 되는 감정 시스템] 이벤트 테이블 + 감쇠 + 임계값 → 이건 순수 수학. 충분히 "감정 있는 것처럼" 보인다. 대부분의 게임은 이걸로 충분해. 스카이림의 NPC 호감도, GTA의 경찰 수배 레벨 — 다 이 방식이야. [Level 2: AI를 쓰면 달라지는 것] 1. 감정 표현의 다양성 (LLM): 분노 42 + 공포 15 → "...뭘 봐. 볼일 있으면 빨리 말해." (짜증 + 약간 경계) 분노 42 + 공포 60 → "가, 가까이 오지 마...! 경비병 부를 거야!" (짜증 + 두려움) → 같은 분노 42여도 다른 감정과 조합되면 대사가 달라짐. → 이 조합 수가 너무 많아서 대본으로 쓸 수 없음 → LLM이 생성. 2. 감정 전이 패턴 학습 (ML): 데이터: "유저가 NPC를 3번 공격 → 도망 → 경비병한테 신고" 학습: "공격 3회 이상이면 바로 경비병한테 가는 게 NPC 생존에 유리" → NPC가 "경험"으로 행동 패턴을 개선 3. 감정 전파 (다른 NPC에게): NPC A가 공포 상태 → 근처 NPC B, C도 공포 약간 상승 → "무서움이 전염되는" 효과 → 마을 전체가 유저를 경계하기 시작

Part 3 핵심

감정 = 숫자 4개 (분노, 공포, 기쁨, 슬픔). 이건 그냥 변수다.

이벤트가 숫자를 바꾸고, 숫자가 행동을 바꾸고, 시간이 숫자를 줄인다.

AI가 빛나는 건 "숫자 조합을 자연어로 표현"하는 단계다.

Part 4. 몬스터 생태계 — "늑대가 줄면 토끼가 폭증한다"

몬스터끼리 먹이사슬이 존재하는 세계를 어떻게 만들어?

이건 생각보다 오래된 수학이야. 1920년대에 만들어진 공식이 있거든.

[비유: 섬에 늑대와 토끼만 산다] 처음: 토끼 100마리, 늑대 10마리 매달 일어나는 일: 토끼: 번식 (토끼 수 × 번식률) - 잡아먹힘 (토끼 × 늑대 × 포식률) 늑대: 번식 (늑대 × 토끼 × 포식성공률) - 굶어죽음 (늑대 수 × 사망률) 1월: 토끼 100, 늑대 10 → 토끼 번식 잘 됨 2월: 토끼 140, 늑대 12 → 늑대도 먹이 많아서 번식 3월: 토끼 150, 늑대 18 → 늑대 급증, 토끼 사냥 증가 4월: 토끼 110, 늑대 22 → 토끼 줄기 시작 5월: 토끼 60, 늑대 20 → 늑대 굶기 시작 6월: 토끼 40, 늑대 14 → 늑대 사망 증가 7월: 토끼 50, 늑대 8 → 토끼 다시 번식 시작 8월: 토끼 80, 늑대 7 → 사이클 반복... 이게 "로트카-볼테라 방정식" — 100년 전 수학이야. 게임에선 이걸 약간 단순화해서 쓴다.
이걸 게임에 넣으면 어떻게 돼?
[게임 적용: 3종 먹이사슬] 풀 (무한 재생) ↑ 먹음 토끼 (초식) ↑ 먹음 늑대 (포식) ↑ 사냥 플레이어 매 시간 서버가 계산: 토끼 증가 = 풀이 있는 구역 × 번식률 토끼 감소 = 늑대 수 × 포식률 늑대 증가 = 토끼를 잡은 수 × 번식률 늑대 감소 = 자연사망 + 플레이어 사냥 플레이어 개입 효과: "이 구역의 늑대를 다 잡았다" → 토끼 폭증 → 풀이 다 먹혀서 황무지 됨 → 토끼도 결국 굶어서 감소 → "아무것도 없는 죽은 땅"이 됨 → 시간이 지나면 풀이 다시 자라고 → 생태계 복구 플레이어의 행동이 세계에 "결과"를 남기는 것.
이건 AI가 필요한 거야?

기본 먹이사슬은 수학 공식만으로 가능해. 하지만 여기에 AI를 붙이면:

[수학만 vs AI 추가] 수학만 (로트카-볼테라): 인구 변화 = 공식대로 계산 한계: 몬스터가 멍청함. "토끼가 없어도 같은 곳에서 서성임" AI 추가 (에이전트 시뮬레이션): 각 몬스터가 독립적인 "에이전트"로 판단: 늑대 에이전트: State: [배고픔, 주변 토끼 수, 주변 늑대 수, 체력] Action: [사냥, 이동, 휴식, 영역 표시] Reward: 먹이 +1.0, 굶주림 -0.5 학습 결과: "이 구역에 토끼가 없으면 북쪽으로 이동" "다른 늑대가 너무 많으면 새 영역을 찾음" "체력이 낮으면 사냥 대신 휴식" → 수학 공식 + RL = 진짜 살아있는 것처럼 행동하는 생태계 → 몬스터가 이동하고, 영역을 나누고, 먹이를 찾아 떠돌아다님 → 플레이어가 "저 늑대 무리는 왜 북쪽으로 갔지?" 하게 됨

Part 4 핵심

인구 변동은 100년 된 수학 공식으로 가능 (AI 불필요)

개체의 행동 (이동, 영역, 먹이 탐색)은 RL 에이전트가 자연스러움

조합하면: 수학이 "얼마나 많은지"를 결정, AI가 "어떻게 행동하는지"를 결정

Part 5. NPC 소문 전파 — "동쪽에서 악마가 왔대"

NPC끼리 소문이 퍼진다는 게 어떤 원리야?

이건 분산 시스템에서 쓰는 "가십 프로토콜"과 완전히 같은 원리야.

서버끼리 상태를 전파하는 알고리즘을 NPC한테 적용하는 거야.

[비유: 동네 아줌마 네트워크] 사건 발생: "3번 집 앞에서 싸움이 났다" 1분 후: 목격자 아줌마 1명이 옆집 아줌마에게 전달 5분 후: 옆집 아줌마가 건너 아줌마에게 전달 10분 후: 골목 전체가 알고 있음 30분 후: 옆 골목까지 퍼짐 1시간 후: 동네 전체가 알고 있음 특징: → 중앙 방송국이 없다 (아무도 전체에 공지하지 않음) → 각자가 아는 사람에게 전달할 뿐 → 시간이 지나면 자연스럽게 전체에 퍼짐 → 멀리 갈수록 내용이 약간 변함 ("싸움" → "큰 사건" → "살인?!") 이게 가십 프로토콜이야.
이걸 NPC에 어떻게 적용해?
[원리: 소문 전파 시스템] 1단계: 이벤트 발생 유저가 A마을 광장에서 NPC 3명을 죽임 → 이벤트 생성: {type: "학살", location: "A마을", severity: 9} 2단계: 목격자 생성 반경 50m NPC들이 "목격" → 각 NPC의 기억에 저장: {소문, 신뢰도: 1.0, 시간} 3단계: 전파 (매 틱마다) 각 NPC가 근처 NPC에게 확률적으로 전달: NPC_B → NPC_C에게: "A마을에서 학살이 있었대" 전파 확률 = severity × 관계친밀도 × (1 - 이미_아는지) 전파될 때마다: 신뢰도 × 0.8 (전해질수록 신뢰도 감소) 내용 변형 확률 5% ("학살" → "전쟁?", "몬스터 습격?") 4단계: 거리에 따른 감쇠 A마을: severity 9, 신뢰도 1.0 → "악마가 나타났다! 도망쳐!" B마을: severity 7, 신뢰도 0.6 → "동쪽에서 무슨 일이 있었대" C마을: severity 4, 신뢰도 0.3 → "뭔가 소문이 돌던데..." D마을: 아직 안 퍼짐 (시간 필요) 5단계: 소문에 의한 행동 변화 severity > 7 + 신뢰도 > 0.8 → 경비 강화, NPC 실내 대피 severity > 5 + 신뢰도 > 0.5 → 경비 주의, NPC 경계 severity > 3 → NPC 대화에 소문 등장 severity < 3 → 무시
이것도 AI 없이 되는 건가?

기본 전파는 AI 없이 가능해. 확률 계산 + 그래프 탐색이면 돼.

하지만 AI를 붙이면 두 가지가 달라져:

[AI가 추가하는 것] 1. 소문의 자연어 변형 (LLM): 원본: "A마을에서 유저가 NPC 3명을 죽임" A마을 NPC: "미쳤어! 눈앞에서 사람이 죽었어!" B마을 NPC: "A마을에서 큰일 났대. 누가 사람을 죽였다던데..." C마을 NPC: "동쪽에서 무슨 소동이 있었다던데, 자세한 건 모르겠어." D마을 NPC: "요즘 세상이 험해졌다나 봐." → 같은 사건인데, 거리에 따라 자연스럽게 다른 표현. → 이걸 대본으로 쓰려면 조합이 너무 많음 → LLM이 생성. 2. NPC 네트워크 구조 학습 (ML): 어떤 NPC가 "허브"인지 (많은 NPC와 연결된 수다쟁이) 어떤 NPC가 "고립"인지 (혼자 산속에 사는 은둔자) → 허브 NPC를 통하면 소문이 빠르게 퍼지고 → 고립 NPC한테는 소문이 안 가거나 매우 늦게 감 → 이 네트워크 구조를 ML로 분석하면 "이 소문이 전체에 퍼지는 데 얼마나 걸릴지" 예측 가능

Part 5 핵심

소문 전파 = 가십 프로토콜 (분산 시스템 기술을 NPC에 적용)

거리에 따라 감쇠하고, 시간에 따라 퍼지고, 변형된다

AI는 "소문을 자연어로 표현"하고, "전파 네트워크를 분석"하는 데 쓰인다

Part 6. 공통 원리 — 모든 "살아있는 AI"의 구조

5개를 다 봤는데, 뭔가 공통점이 보여. 정리해줘.

전부 같은 3단계 구조야.

[모든 "살아있는 NPC"의 공통 구조] ┌───────────────────────────────────────────────────────┐ │ 1층. 데이터 수집 (DB/배열) │ │ → 이벤트 기록, 행동 빈도, 감정 값, 인구 수, 소문 │ │ → AI 필요 없음. 그냥 저장. │ └───────────────────┬───────────────────────────────────┘ ↓ ┌───────────────────────────────────────────────────────┐ │ 2층. 상태 계산 (수학/규칙) │ │ → 호감도 계산, 카운터 확률, 감정 감쇠, 인구 변동 │ │ → AI 필요 없음. 덧뺄셈, 공식, if-else. │ └───────────────────┬───────────────────────────────────┘ ↓ ┌───────────────────────────────────────────────────────┐ │ 3층. 표현/판단 (AI) │ │ → 자연어 대사 생성 (LLM) │ │ → 실시간 상황 판단 (RL) │ │ → 패턴 예측 (ML) │ │ → 여기서만 AI가 필요. │ └───────────────────────────────────────────────────────┘
그러면 5개를 이 구조로 정리하면?
기능 1층: 데이터 2층: 수학 3층: AI
기억하는 NPC 이벤트 로그 호감도 점수 LLM 대사 생성
학습하는 보스 행동 빈도 카운터 매핑 RL 실시간 판단
감정 있는 NPC 이벤트 기록 감정값 증감 LLM 감정 표현
몬스터 생태계 인구 카운터 로트카-볼테라 RL 개체 행동
NPC 소문 전파 소문 저장소 가십 프로토콜 LLM 소문 변형
결국 핵심이 뭐야?

"살아있는 NPC"의 80%는 AI가 아니다.

DB + 수학이 80%를 해결하고, AI는 마지막 20%인 "표현"과 "판단"만 담당한다.

이 구조를 모르면 "전부 AI로 해야 해"라고 생각하게 되는데, 그건 오버엔지니어링이야.

과하게 쓰면 역효과

NPC가 "너무 똑똑하면" 유저가 불쾌해한다 (언캐니 밸리).

NPC가 "너무 기억을 잘 하면" 감시당하는 느낌이 든다.

생태계가 "너무 사실적이면" 게임이 아니라 시뮬레이터가 된다.

"살아있는 것처럼 느껴지되, 게임으로서 재밌는" 균형점을 찾는 게 핵심이다.

핵심 정리

  • 살아있는 NPC = 데이터(DB) + 수학(공식) + AI(표현) — 3층 구조. AI는 맨 위층에만 필요
  • 기억하는 NPC — 이벤트 로그(DB) + 호감도(덧뺄셈) + 대사 생성(LLM)
  • 학습하는 보스 — 행동 빈도(카운터) + 카운터 전략(테이블) + 실시간 판단(RL)
  • 감정 있는 NPC — 감정값 4개(변수) + 이벤트 규칙(테이블) + 감정 표현(LLM)
  • 몬스터 생태계 — 인구(카운터) + 로트카-볼테라(수학) + 개체 행동(RL)
  • NPC 소문 전파 — 소문(데이터) + 가십 프로토콜(알고리즘) + 자연어 변형(LLM)
  • AI 없이도 80%는 가능 — AI는 "표현"과 "판단"에만 쓰인다. 나머지는 DB + 수학
  • 가장 어려운 건 균형 — 너무 똑똑하면 불쾌, 너무 멍청하면 죽은 세계. "적당히 살아있는" 게 핵심
