Q76. 서버 권위란 실제로 뭘 검증하는 건가? 어디까지 의심해야 하나?

1차 답변

0. 저는 먼저 "권위 = 검증"이라는 오해부터 걷어냅니다

이 질문에 많은 사람이 "클라가 보낸 값을 서버가 검사하는 것"이라고 답하는데, 저는 그게 서버 권위의 핵심을 놓친 답이라고 봅니다. 서버 권위는 값을 검사하는 게 아니라, 중요한 값을 애초에 클라가 만들지 못하게 하는 것입니다.

정의부터 명확히 하면 — 서버 권위란 "게임 세계의 진실은 서버 메모리에 있고, 클라가 보내는 건 '결과'가 아니라 '의도'다"라는 원칙입니다. 클라는 "나 데미지 9999 넣었어"라고 결과를 통보하는 게 아니라, "나 스킬1을 이 대상에게 썼어"라고 의도만 보냅니다. 데미지가 얼마인지는 서버가 계산해요. 그래서 "어디까지 의심하나"는 곧 "어떤 값을 클라가 만들게 두고, 어떤 값은 서버만 만드는가"의 선긋기 문제입니다.

1. 흔한 안 — 클라가 보낸 값을 범위 체크한다

흔한(하지만 틀린) 안: "클라가 보낸 데미지 값이 9999처럼 말도 안 되면 거르면 되죠. 값이 정상 범위인지 검증하는 게 서버 권위 아닌가요?"

이건 권위가 아니라 클라가 만든 결과를 받아놓고 뒤늦게 sanity check하는 것입니다. 근본이 틀렸어요. 왜냐하면 데미지 9999는 걸러도, "가능한 최대치 근처"의 그럴듯한 거짓말은 매번 통과하거든요. 범위 안의 거짓말은 범위 체크로 못 잡습니다.

그래서 올바른 설계는 "클라가 보낸 데미지를 검증"이 아니라 "클라가 데미지를 애초에 안 보내는 것"입니다. 클라는 "스킬 썼다"는 의도만 보내고, 데미지·명중·크리티컬은 전부 서버가 자기 메모리의 스탯으로 계산합니다. 검증은 최후의 방어선이고, 진짜 방어는 권한을 안 주는 설계예요.

2. 그럼 무엇을 서버가 소유해야 하나 — 세 층위

모든 걸 다 서버가 하면 좋겠지만 그건 비용이 폭발하니(뒤에서 다룹니다), 저는 세 층위로 나눕니다.

(A) 절대 클라를 믿지 않는 것 — 서버가 결과를 만든다. 데미지·판정 결과, 재화, 아이템 획득, 확률(뽑기·드랍), 쿨타임 소진 여부, 사거리·시야 판정. 클라는 결과를 아예 안 보내고 서버가 계산합니다.

(B) 클라가 주장하되 서버가 타당성을 검증하는 것. 대표가 이동입니다. 위치는 클라가 보내되(반응성 때문에), "직전 위치에서 이 시간에 이 거리 이동이 물리적으로 가능한가"를 서버가 검증합니다. 입력은 클라가, 물리 타당성은 서버가.

(C) 믿어도 되는(믿을 수밖에 없거나, 믿어도 손해 없는) 것. 순수 연출(카메라·이펙트·로컬 UI), 그리고 어차피 그 사람만 손해 보는 것. 여기까지 의심하면 서버가 죽습니다.

3. "어디까지 의심하나" = 틀렸을 때 잃는 것의 크기

의심의 깊이를 정하는 제 기준은 하나입니다 — "이게 틀렸을 때 무엇을 잃나." 재화·거래·아이템이 조작되면 경제 전체가 붕괴하니 편집증적으로 의심하고 전량 로깅합니다. 전투 판정이 조작되면 공정성이 무너지니 서버가 계산합니다. 이동은 좀 어긋나도 남 위치가 잠깐 튀는 정도라 사후 검증으로 충분합니다. 순수 연출은 잃을 게 없으니 안 봅니다. 손실이 큰 순서로 의심 예산을 배분하는 거예요.

🧭 이 문제의 원칙"서버 권위는 값을 검사하는 게 아니라, 값을 만들 권한을 애초에 안 주는 것이다." 검증은 최후의 방어선일 뿐이다. 그리고 다 의심할 순 없으니 '틀렸을 때 잃는 것'의 크기로 의심의 깊이를 산다 — 경제가 걸리면 편집증적으로, 그 사람만 손해면 관대하게.

면접관 꼬리질문
면접관🔥 "그럼 이동도 서버가 매 프레임 계산해야 진짜 권위 아니에요? 클라 예측을 허용하면 스피드핵에 뚫리잖아요."

여기서 저는 반응성·비용·보안의 삼각관계를 정직하게 펼칩니다. 이동을 서버가 매 좌표 원천 계산하면 두 가지가 터집니다. 하나는 비용 — 수천 명 × 초당 수십 틱을 서버가 다 시뮬레이션하면 CPU가 감당 못 합니다. 다른 하나는 반응성 — 클라가 한 걸음 옮길 때마다 서버 왕복을 기다리면 이동이 뚝뚝 끊겨 게임이 안 됩니다.

그래서 저는 "권위 = 매 틱 재현"이라는 정의 자체를 바로잡습니다. 권위란 클라의 주장을 서버가 승인·거부·정정할 최종 권한이지, 서버가 모든 걸 처음부터 다시 그리는 게 아니에요. 이동에서는 클라가 위치를 주장하면 서버가 "직전 위치에서 경과 시간 동안 이 거리 이동이 가능한가"(속도 상한·충돌·텔레포트 감지)를 검증하고, 위반이면 서버 기준 위치로 스냅백합니다.

즉 스피드핵은 이 "타당성 검증"에서 잡지, "매 좌표 계산"으로 잡는 게 아닙니다. 오히려 매 좌표 계산은 비용만 폭발시키고 보안 이득은 검증과 비슷해요. 다만 랙으로 인한 정상 유저의 위치 점프와 스피드핵을 어떻게 구분하느냐는 또 다른 층의 문제인데, 그건 다음 질문에서 제대로 다루겠습니다.

면접관🔥 "확률(뽑기)까지 서버가 하는 건 알겠는데, 클라가 이미 결과를 화면에 보여준 뒤에 서버가 다르면 유저가 뭐라 하지 않아요?"

이건 연출과 판정의 순서 문제입니다. 그리고 여기서 흔한 치명적 실수가 나와요 — 클라가 뽑기 애니메이션의 결과를 로컬에서 정하고 서버에 통보하는 구조. 이러면 클라 조작으로 원하는 걸 뽑는 조작 천국이 됩니다. 실제로 이렇게 뚫린 게임이 많고요.

올바른 순서는 서버가 결과를 먼저 확정 → 클라에 내려줌 → 클라는 그 결과로 연출입니다. 유저가 보는 "두근거리는 회전 연출"은 연출이지 판정이 아니에요. 결과는 이미 서버에서 정해졌고, 클라는 그걸 극적으로 보여줄 뿐입니다. 그래서 "클라가 먼저 보여준 뒤 서버가 뒤집는" 상황 자체가 생기지 않습니다 — 애초에 서버가 먼저 정하고 클라가 받아서 연출하니까요.

정리하면 "연출은 클라, 결과는 서버, 순서는 서버 먼저." 이 순서만 지키면 유저 경험(두근거림)도 살리고 조작도 막습니다. 반대로 순서를 뒤집으면 둘 중 하나(경험 또는 보안)를 반드시 잃어요. 순서 하나가 보안을 가르는 겁니다.

면접관🔥 "다 서버 권위로 검증하면 서버 CPU가 감당이 안 될 텐데, 어디서 선을 그어요?"

정직하게 말하면 모든 걸 실시간으로 완전 검증하는 서버는 없습니다. 그건 이상이고, 현실은 "의심 예산"을 배분하는 것이에요. 제 기준은 세 가지 곱입니다 — 이게 틀렸을 때 무엇을 잃나 × 얼마나 자주 일어나나 × 검증 비용이 얼마나 드나.

재화는 틀리면 경제가 붕괴하니 손실이 무한대에 가깝습니다 → 비용을 얼마든 써서 완전 검증 + 로깅. 이동은 틀려도 남 위치가 잠깐 어긋나는 정도고 발생 빈도는 높으니 → 매번 완전 검증 대신 물리 타당성만 싸게 사후 검증. 순수 연출은 잃을 게 없으니 → 아예 안 봄. 손실이 큰 쪽에 예산을 몰아주는 겁니다.

그리고 "전수 실시간 검증"이 비싼 건 "사후 이상탐지"로 미룹니다. 예를 들어 매 거래를 실시간으로 다 검증하기 어려운 부분은 로그를 쌓아 나중에 패턴으로 잡습니다 — 오토·현금거래(RMT) 탐지가 이런 식이죠. 실시간 방어선을 뚫려도 사후에 회수·제재할 수 있게요. 완벽한 실시간 무신뢰라는 환상을 버리고, 손실 크기로 예산을 배분하고 못 막는 건 사후에 잡는 것 — 이게 실전의 서버 권위입니다. 이 "어디까지 검증하나"는 별도 질문에서 더 깊이 파고들 만한 주제이기도 하고요.
