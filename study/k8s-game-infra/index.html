쿠버네티스로 게임 서버 인프라 운영하기

Devsisters NDC 발표 | 쿠키런 킹덤, 서버 팜, GitOps

왜 게임 회사에서 쿠버네티스를 쓰는가?
핵심 답변

효율적인 퍼블리싱과 컨테이너 오케스트레이션이 핵심 이유입니다.

  • 서버 팜 찍어내기: 동일한 환경을 Dev/QA/Staging/Prod에 빠르게 복제
  • 리소스 효율화: 하나의 클러스터에서 여러 게임을 운영 (멀티 테넌시)
  • 자동화된 배포: GitOps를 통한 선언적 인프라 관리
  • 빠른 스케일링: 신규 게임 런칭 시 인프라 구축 시간 단축

게임 회사는 신규 게임 런칭이 잦고, 각 게임마다 비슷한 인프라가 필요합니다. 쿠버네티스를 사용하면 "서버 팜을 찍어내듯" 환경을 복제할 수 있어 운영 효율이 극대화됩니다.

데브시스터즈의 7년간 쿠버네티스 여정은?
타임라인
2014년 - 쿠버네티스 연구 시작 (당시 버전 0.x)
2015~2017년 - 내부 도구 및 CI/CD 파이프라인 구축
2018~2019년 - 개발/QA 환경 쿠버네티스 전환
2020년 - 프로덕션 환경 쿠버네티스 도입 준비
2021년 - 쿠키런: 킹덤 글로벌 런칭 성공

7년이라는 긴 시간 동안 점진적으로 도입했다는 점이 핵심입니다. 처음부터 프로덕션에 적용하지 않고, 개발 환경부터 천천히 경험을 쌓아갔습니다.

서버 팜 찍어내기 구조란?
핵심 개념

동일한 인프라 구성을 여러 환경에 빠르게 복제하는 방식입니다.

  • Dev: 개발자 로컬 테스트 환경
  • QA: QA팀 테스트 환경
  • Staging: 프로덕션과 동일한 사전 검증 환경
  • Prod: 실제 서비스 환경

쿠버네티스의 선언적 설정(YAML)을 사용하면 환경 간 차이를 최소화하고, 새 게임 출시 시 기존 템플릿을 복제하여 빠르게 인프라를 구축할 수 있습니다.

이를 통해 "환경마다 동작이 다른" 문제를 해결하고, 프로덕션 배포의 신뢰성을 높입니다.

GitOps 배포는 어떻게 구성하는가?
배포 파이프라인

Git을 Single Source of Truth로 사용하는 배포 방식입니다.

ArgoCD
쿠버네티스 네이티브 GitOps 도구. Git 저장소의 상태를 클러스터에 자동 동기화
Spinnaker
멀티 클라우드 지원 CD 플랫폼. 복잡한 배포 전략 (카나리, 블루/그린) 지원
Terraform
인프라 프로비저닝 도구. 클러스터 자체를 코드로 관리

GitOps 워크플로우: 개발자가 Git에 변경사항 Push -> ArgoCD가 변경 감지 -> 자동으로 클러스터에 배포 -> 롤백도 Git revert로 간단히 처리

멀티 테넌시란 무엇인가?
운영 효율화

하나의 쿠버네티스 클러스터에서 여러 게임을 운영하는 방식입니다.

  • 네임스페이스 분리: 각 게임을 별도 네임스페이스로 격리
  • 리소스 쿼터: 게임별 CPU/메모리 할당량 제한
  • 네트워크 정책: 게임 간 네트워크 격리
  • RBAC: 팀별 접근 권한 관리

장점: 클러스터 운영 비용 절감, 공통 인프라 (모니터링, 로깅) 공유, 운영 노하우 축적

주의점: 한 게임의 장애가 다른 게임에 영향을 주지 않도록 철저한 격리가 필요합니다.

이러한 CNCF 생태계 도구들을 조합하여 안정적인 게임 서버 운영 환경을 구축합니다.

쿠버네티스 도입 시 조언은?
실전 조언
핵심 메시지: 소프트하게 도입하라

"처음부터 프로덕션에 적용하지 마세요. 개발 환경부터 천천히 시작하세요."

  • 1단계: 로컬 개발 환경 (minikube, kind)에서 학습
  • 2단계: 내부 도구/CI 서버를 쿠버네티스로 이전
  • 3단계: 개발/QA 환경 쿠버네티스화
  • 4단계: 비핵심 서비스부터 프로덕션 적용
  • 5단계: 핵심 게임 서버 프로덕션 적용

중요: 팀의 쿠버네티스 숙련도를 높이는 것이 먼저입니다. 기술보다 운영 경험이 더 중요합니다.
