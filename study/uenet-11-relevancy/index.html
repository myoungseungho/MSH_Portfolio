Relevancy — 누구에게 보낼지 (= 우리 AOI)

안 보이는 액터는 아예 안 보낸다. UE의 관련성 = 조선협객전의 관심 영역

30초 요약

Relevancy = 한 클라에게 '관련 있는' 액터만 복제. 가장 흔한 기준은 거리(Net Cull Distance).

시야 밖 액터는 컬링(안 보냄) + ActorChannel 닫음. 플레이어가 움직이면 관련 집합이 갱신.

이게 우리 BroadCast의 AOI(관심 영역)와 정확히 같은 개념.

Part 1. 왜 다 안 보내?

서버에 있는 모든 액터를 모든 클라한테 보내면 안 돼?

맵에 액터 1만 개, 접속 1천 명이면? 다 보내면 1만 × 1천 = 천만 건. 대역폭·CPU 폭발이야.

근데 내가 서울에 있는데 부산 몬스터 정보가 필요해? 안 보이는데. 그래서 '관련 있는 것만' 보내 — 이게 Relevancy.

관련 있다는 기준은?

기본은 거리야. 액터의 NetCullDistanceSquared 안(시야)에 있으면 관련 있음. 그 밖이면 컬링.

거리 말고도 규칙이 있어 — 항상 관련(bAlwaysRelevant, 예: 매치 상태), 소유자에게만(bOnlyRelevantToOwner, 예: 내 인벤토리) 등.

Part 2. 시야 안만 복제된다

플레이어 주변만 복제되는 걸 봐.

노란 '나'가 움직이면 시야(점선 원) 안 액터만 초록(복제 중, 선 연결)이 되고, 밖은 회색(컬링)이 돼.

탭으로 시야 크기를 바꿔봐 — 시야가 크면 복제 수가 늘고(부하↑), 작으면 줄어(끊겨 보일 위험).

0복제 중(관련 있음)
0컬링됨(안 보냄)

Part 3. 우리 AOI와 같은 것

개념조선협객전 (우리)언리얼
관심 영역AOI (BroadCast 대상 추리기)Relevancy
거리 기준시야/그리드 셀NetCullDistanceSquared
특수 규칙전체 공지(전서버 방송)bAlwaysRelevant / bOnlyRelevantToOwner
경계 넘을 때구독 갱신ActorChannel 열고/닫음
그럼 우리 AOI 글이랑 겹쳐?

맞아, 같은 문제·같은 해법이야. 우리가 'BroadCast를 누구한테까지'로 고민하던 게, UE에선 'Relevancy로 어떤 액터를 복제'로 나타나는 거지.

다음 챕터(ReplicationGraph)는 이 관련성 계산을 대규모에서 빠르게 하는 방법이야.

UE 속성Relevancy 설정

액터의 NetCullDistanceSquared로 거리 컬링 임계, bAlwaysRelevant로 항상 보내기, bOnlyRelevantToOwner로 소유자에게만. IsNetRelevantFor 오버라이드로 커스텀 판정도 가능.

// 클래스 생성자에서 NetCullDistanceSquared = 900000000.f; // 30000² (30m) bAlwaysRelevant = false; bOnlyRelevantToOwner = false; // 커스텀 판정 bool AMyActor::IsNetRelevantFor(const AActor* Viewer, ...) const { // 팀원이면 거리 무시하고 보임 등 if (IsSameTeam(Viewer)) return true; return Super::IsNetRelevantFor(Viewer, ...); }
우리 서버

BroadCast 함수가 직접 'AOI 그리드 셀 + 이웃 셀'만 추려서 SM_ 송신.

언리얼

액터마다 속성 설정. 엔진이 매 틱 자동 추리기.

Part 4. 트레이드오프

시야를 무조건 좁히면 좋은 거 아냐?

아니. 너무 좁으면 멀리 있는 적이 '갑툭튀'해(컬링됐다 갑자기 복제 시작). 저격수 시야 밖 적이 안 보이는 문제도 생겨.

그래서 '거리'만으로 안 되고, 중요 액터는 항상 관련(bAlwaysRelevant)으로 빼거나 거리를 타입별로 다르게 줘. 부하 vs 체감의 균형이야.

💭 잠깐, 이런 생각 들지 않아?
NetCullDistanceSquared가 모든 액터에 똑같이 적용돼?
아니, 액터마다 따로. 캐릭터는 100m, 작은 아이템은 30m, 거대 보스나 매치 알림 액터는 200m... 식으로 액터 종류에 맞게. 클래스 기본값 + 인스턴스별 오버라이드도 됨. 그래서 같은 맵에 있어도 액터 타입에 따라 시야가 달라 — 작은 풀잎은 가까이서만 보이고, 큰 빌딩은 멀리서도 보임.

핵심 정리

  • Relevancy = 관련 있는 액터만 복제. 기본 기준 = 거리(NetCullDistanceSquared)
  • 시야 밖 = 컬링(안 보냄) + ActorChannel 닫음. 이동하면 관련 집합 갱신
  • = 우리 AOI. BroadCast 대상 추리기와 같은 문제·해법
  • 특수 규칙: bAlwaysRelevant(항상), bOnlyRelevantToOwner(소유자만)
  • 너무 좁으면 '갑툭튀' — 부하 vs 체감 균형, 중요 액터는 예외 처리

이런 것도 궁금하지 않아?

읽다 보면 떠오르는 꼬리질문 — 눌러서 펼쳐봐

Q. 컬링됐던 적이 시야에 들어오면 트래픽이 튀는 거 아냐?

맞아 — 그 액터의 "현재 상태 전체"를 처음부터 받아야 해(초기 복제). 한순간 트래픽 스파이크가 생기지.

[시야 진입 순간] 적 시야 밖: 채널 닫혀 있음, 상태 0 전송 ↓ 시야 진입 채널 열림 → 초기 복제 - 위치, 회전, 체력, 장비, 버프 ... 전부 한 번에 - 트래픽 5~50KB 스파이크

완화책:

  • 히스테리시스: 시야 경계 안쪽에서 미리 일부 받아둠. 진입 순간엔 변경분만 추가.
  • 우선순위 분산: 모든 액터를 동시에 보내지 않고, 중요도 순으로 N틱에 걸쳐 채움.
  • 핵심부터: 위치·체력 같은 필수 먼저, 버프·치장 같은 보조는 나중에.
Q. 안 보여도 발소리는 들려야 하는데?

그래서 관련성은 단순 "시각" 하나가 아니야. 여러 축이 있어:

  • 시각 관련성: 보이는 액터.
  • 청각 관련성: 안 보여도 들리는 거리.
  • 전술 관련성: 미니맵에 표시될 거리 등.
[다축 관련성] 내 위치 (X) ├─ 시각 반경 (50m) — 액터 위치·메시·애니 ├─ 청각 반경 (100m) — 발자국·사운드 이벤트 └─ 전술 반경 (200m) — 미니맵 점 정보

축마다 보내는 정보가 다르고 비용도 달라. "안 보이지만 소리 들림"은 청각 관련성 안에 들면 사운드 이벤트만 전송 — 위치·메시는 안 보냄.

Q. 벽 뒤 적도 거리가 가까우면 복제돼서 월핵으로 보이는 거 아냐?

맞아, 그게 거리 기반 컬링의 약점이야. 핵 제작자가 클라 메모리를 읽으면 패킷에 실린 적 위치를 그대로 볼 수 있어 — 벽 너머라도.

경쟁 FPS의 대응:

  • 가시성 컬링: 서버가 "이 적이 진짜 보이나"(레이캐스트·시야각 체크)까지 판단해 안 보이면 패킷 자체에 안 실음.
  • 지연 전송: 안 보이는 적은 보내되 위치를 일부러 좀 흐릿하게(과거 위치 등).
[가시성 컬링 비용] 매 틱 × 매 적 × 매 관전자 → 레이캐스트 100명 매치면: 100×100 = 10000 레이캐스트/틱 비싸지만 핵 방지를 위해 감수
발로란트·CS2가 이걸 강하게 적용해. UE 기본은 거리만 봐서, 경쟁 게임은 별도 구현이 필요해.
Q. bAlwaysRelevant를 남발하면 결국 다 보내는 거랑 같잖아?

맞아. 한두 액터에 쓰면 안전망이지만, 남발하면 관련성의 의미가 사라져 — 부하가 폭발.

적절한 사용:

  • GameState: 매치 점수·시간 같은 글로벌 상태. 모두 알아야 함.
  • PlayerState: 다른 플레이어의 이름·점수.
  • 특수 이벤트 오브젝트: 매치 결과 표시기 등.
규칙: bAlwaysRelevant는 "수가 매우 적고, 진짜로 모두가 알아야 하는" 메타 객체에만. 일반 액터엔 절대 X. 게임에서 보통 10개 미만이 정상.
