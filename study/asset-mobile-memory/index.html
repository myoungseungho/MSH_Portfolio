Mobile Memory Management

모바일 게임의 메모리 제약과 생존 전략

Part 1: 모바일 메모리 제약

Q1: 모바일에서 메모리 관리가 왜 "지옥"이라고 하나요?

PC보다 10배 적은 메모리로, OS가 언제든 앱을 죽일 수 있기 때문입니다.

[플랫폼별 메모리 비교]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
플랫폼              총 RAM      앱 사용 가능    GPU 전용
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
게이밍 PC          32GB        ~28GB          8~24GB (VRAM)
PS5                16GB        ~12GB          공유
Xbox Series X      16GB        ~13GB          공유
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
iPhone 15 Pro      8GB         ~3GB           공유 (UMA)
Galaxy S24         12GB        ~4GB           공유 (UMA)
저가 Android       3GB         ~1GB           공유 (UMA)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

핵심 차이:
1. 총량 부족: PC 32GB vs 모바일 3~8GB
2. 통합 메모리: GPU VRAM이 따로 없음 → RAM에서 공유
3. OS 제어: 앱이 많이 쓰면 OS가 강제 종료

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[모바일 메모리 압박 시나리오]

총 RAM: 4GB
├─ OS 커널:      0.8GB
├─ 시스템 앱:    0.5GB
├─ 백그라운드:   0.7GB (카톡, 음악 등)
├─ 게임 앱:      ?
└─ 여유:         0.2GB (안전 마진)

게임 사용 가능: ~1.8GB (실질적으로)

→ PC 게임의 1/15 수준
→ 4K 텍스처 한 장 = 64MB = 사용 가능 메모리의 3.5%
Q2: "앱 킬"이 뭔가요? 왜 갑자기 게임이 종료되죠?

OS가 메모리 확보를 위해 앱을 강제 종료하는 것입니다.

[메모리 압박 → 앱 킬 과정]

1. 메모리 사용량 증가
   ┌────────────────────────────────────┐
   │████████████████████████░░░░░░░░░░░│ 75%
   └────────────────────────────────────┘
   → 정상 동작

2. 경고 단계 (Memory Warning)
   ┌────────────────────────────────────┐
   │██████████████████████████████░░░░░│ 90%
   └────────────────────────────────────┘
   → iOS: didReceiveMemoryWarning 호출
   → Android: onTrimMemory(RUNNING_LOW) 호출
   → 앱은 캐시 정리 기회

3. 임계 단계
   ┌────────────────────────────────────┐
   │█████████████████████████████████░░│ 95%
   └────────────────────────────────────┘
   → 백그라운드 앱부터 종료

4. 킬 단계 (OOM Killer)
   ┌────────────────────────────────────┐
   │██████████████████████████████████│ 98%+
   └────────────────────────────────────┘
   → 포그라운드 앱도 강제 종료
   → 게임 크래시처럼 보임 (실제론 OS가 죽임)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[앱 킬의 결과]

사용자 경험:
"게임 하다가 갑자기 홈 화면으로 튕겼어요"
"크래시 리포트도 없고 그냥 종료됨"

개발자 관점:
- 크래시 로그 없음 (OS가 SIGKILL 보냄)
- 사용자 데이터 저장 기회 없음
- 디버깅 어려움
중요: OOM(Out Of Memory)으로 죽으면 크래시 로그가 남지 않습니다. 메모리 문제인지 확인하려면 Instruments(iOS) 또는 Memory Profiler(Android)를 사용해야 합니다.

Part 2: iOS vs Android

Q3: iOS와 Android의 메모리 관리 차이점은?

iOS는 더 엄격하고, Android는 파편화가 심합니다.

[iOS 메모리 관리]

Q4: 메모리 경고를 어떻게 처리해야 하나요?

캐시 정리와 품질 저하로 메모리를 확보해야 합니다.

// iOS - AppDelegate
- (void)applicationDidReceiveMemoryWarning:(UIApplication *)application {
    [self handleMemoryWarning:MemoryWarningLevel::Warning];
}

// iOS - 뷰 컨트롤러
- (void)didReceiveMemoryWarning {
    [super didReceiveMemoryWarning];
    [self handleMemoryWarning:MemoryWarningLevel::Warning];
}

// Android - Activity
@Override
public void onTrimMemory(int level) {
    super.onTrimMemory(level);

    switch (level) {
        case TRIM_MEMORY_RUNNING_MODERATE:
            handleMemoryWarning(MemoryWarningLevel::Low);
            break;
        case TRIM_MEMORY_RUNNING_LOW:
            handleMemoryWarning(MemoryWarningLevel::Warning);
            break;
        case TRIM_MEMORY_RUNNING_CRITICAL:
            handleMemoryWarning(MemoryWarningLevel::Critical);
            break;
    }
}

// 공통 메모리 경고 처리 (C++)
class MemoryManager {
public:
    enum class WarningLevel {
        Low,        // 캐시 정리 시작
        Warning,    // 적극적 정리
        Critical    // 비상 조치
    };

    void HandleMemoryWarning(WarningLevel level) {
        switch (level) {
            case WarningLevel::Low:
                // 1단계: 사용 안 하는 캐시 정리
                m_TextureCache.TrimUnused(0.5f);  // 50% 정리
                m_AudioCache.TrimUnused(0.3f);
                break;

            case WarningLevel::Warning:
                // 2단계: 적극적 정리
                m_TextureCache.TrimUnused(0.8f);
                m_AudioCache.TrimUnused(0.7f);
                m_MeshCache.TrimUnused(0.5f);

                // MIP 레벨 강제 하향
                m_TextureManager.ForceLowerMips(2);

                // 파티클 풀 축소
                m_ParticlePool.Shrink(0.5f);
                break;

            case WarningLevel::Critical:
                // 3단계: 비상 조치
                m_TextureCache.ClearAll();
                m_AudioCache.ClearAll();
                m_MeshCache.ClearAll();

                // 현재 씬 외 모든 에셋 언로드
                UnloadNonEssentialAssets();

                // GC 강제 실행
                ForceGarbageCollection();

                // 품질 설정 최저로
                SetQualityLevel(QualityLevel::Lowest);
                break;
        }

        LogMemoryState("After handling warning");
    }
};

Part 3: 메모리 압박 대응

Q5: 메모리 사용량을 런타임에 어떻게 모니터링하나요?

플랫폼별 API로 물리 메모리 사용량을 추적합니다.

// 플랫폼별 메모리 쿼리

// iOS
#include <mach/mach.h>
size_t GetUsedMemoryiOS() {
    struct mach_task_basic_info info;
    mach_msg_type_number_t size = MACH_TASK_BASIC_INFO_COUNT;
    kern_return_t kerr = task_info(mach_task_self(),
                                    MACH_TASK_BASIC_INFO,
                                    (task_info_t)&info,
                                    &size);
    if (kerr == KERN_SUCCESS) {
        return info.resident_size;  // 물리 메모리 사용량
    }
    return 0;
}

// Android (JNI 통해 호출)
// Java 코드:
public long getUsedMemory() {
    Runtime runtime = Runtime.getRuntime();
    return runtime.totalMemory() - runtime.freeMemory();
}

// Native 메모리 (mallinfo)
#include <malloc.h>
size_t GetNativeMemoryAndroid() {
    struct mallinfo mi = mallinfo();
    return mi.uordblks;  // 할당된 바이트
}

실시간 메모리 모니터:

class MemoryMonitor {
public:
    void Update() {
        size_t currentUsage = GetPlatformMemoryUsage();
        size_t availableMemory = GetAvailableMemory();

        // 메모리 사용률 계산
        float usageRatio = (float)currentUsage / m_MemoryBudget;

        // 예측: 현재 추세로 언제 한계 도달?
        float delta = currentUsage - m_PreviousUsage;
        m_MemoryTrend = m_MemoryTrend * 0.9f + delta * 0.1f;  // 평활화

        if (m_MemoryTrend > 0) {
            float timeToLimit = (m_MemoryBudget - currentUsage) / m_MemoryTrend;
            if (timeToLimit < 60.0f) {  // 60초 내 한계 도달 예상
                TriggerPreemptiveCleanup();
            }
        }

        // 경고 임계값 체크
        if (usageRatio > 0.9f) {
            OnMemoryPressure(PressureLevel::Critical);
        } else if (usageRatio > 0.8f) {
            OnMemoryPressure(PressureLevel::High);
        } else if (usageRatio > 0.7f) {
            OnMemoryPressure(PressureLevel::Medium);
        }

        // 통계 기록
        m_PreviousUsage = currentUsage;
        m_MaxUsage = std::max(m_MaxUsage, currentUsage);
    }

private:
    size_t m_MemoryBudget;      // 목표 예산 (e.g., 1.5GB)
    size_t m_PreviousUsage = 0;
    size_t m_MaxUsage = 0;
    float m_MemoryTrend = 0;    // 증가/감소 추세
};

Part 4: 텍스처 최적화

Q7: 모바일에서 텍스처가 왜 메모리를 많이 쓰나요?

텍스처는 게임 메모리의 40~60%를 차지하며, 통합 메모리라 RAM을 직접 사용합니다.

[텍스처 메모리 계산]

기본 공식:
메모리 = 가로 × 세로 × 픽셀당 바이트 × MIP 배수

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
해상도      RGBA32(4B)    RGBA16(2B)    ASTC 4x4(1B)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
256×256     256KB         128KB         64KB
512×512     1MB           512KB         256KB
1024×1024   4MB           2MB           1MB
2048×2048   16MB          8MB           4MB
4096×4096   64MB          32MB          16MB
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MIP 맵 포함 시 × 1.33 (각 레벨이 1/4 크기)

예: 2K 텍스처 50장 (RGBA32)
= 16MB × 1.33 × 50 = 1,064MB (1GB!)

같은 텍스처를 ASTC 4x4로:
= 4MB × 1.33 × 50 = 266MB (75% 절약)

모바일용 텍스처 압축 포맷:

[모바일 압축 포맷 비교]

ASTC (Adaptive Scalable Texture Compression)
├─ iOS: A8 이상 (iPhone 6+)
├─ Android: OpenGL ES 3.2+ (대부분 지원)
├─ 블록 크기 선택 가능 (4×4 ~ 12×12)
├─ 품질/크기 트레이드오프 유연함
└─ ★ 권장: 크로스 플랫폼 최선의 선택

ETC2 (Ericsson Texture Compression 2)
├─ Android 기본 (OpenGL ES 3.0+)
├─ 고정 4×4 블록
├─ ASTC보다 품질 낮음
├─ 구형 Android 호환성 좋음
└─ iOS에서도 지원

PVRTC (PowerVR Texture Compression)
├─ iOS 전용 (구형)
├─ 2×2, 4×4 블록
├─ iOS 8 이하 호환 필요 시
└─ ASTC가 지원되면 ASTC 사용 권장

            androidSettings.format = TextureImporterFormat.ASTC_4x4;
            iosSettings.format = TextureImporterFormat.ASTC_4x4;

        else if (assetPath.Contains("Environment")) {

            androidSettings.format = TextureImporterFormat.ASTC_6x6;
            iosSettings.format = TextureImporterFormat.ASTC_6x6;

Q9: 메모리 풀링이 모바일에서 왜 중요한가요?

잦은 할당/해제가 GC 스파이크와 메모리 파편화를 유발하기 때문입니다.

[풀링 없이 매 프레임 할당]

프레임 1: 총알 생성 → new Bullet()
프레임 2: 총알 파괴 → delete (GC 대기열)
프레임 3: 총알 생성 → new Bullet()
...
프레임 60: GC 실행! → 50ms 스파이크 (프레임 드롭)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[풀링 사용]

초기화: 총알 100개 미리 생성 (풀)
        [○○○○○○○○○○○○○○○...○○○○] 100개 대기

프레임 1: 풀에서 가져옴 → [●○○○○...] 1개 활성
프레임 2: 풀로 반환   → [○○○○○...] 0개 활성
프레임 3: 풀에서 가져옴 → [●○○○○...] 1개 활성

→ 할당/해제 없음 → GC 스파이크 없음
→ 메모리 위치 고정 → 파편화 없음

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[메모리 파편화 문제]

할당 후:
[████░░░░████░░████░░░░████░░░░████]
  A       B     C       D       E

Q10: 오브젝트 풀을 어떻게 구현하나요?

미리 할당된 객체 배열과 사용 가능 인덱스 스택으로 구현합니다.

template<typename T>
class ObjectPool {
public:
    ObjectPool(size_t initialSize) : m_PoolSize(initialSize) {
        // 메모리 한 번에 할당 (연속된 메모리)
        m_Objects = static_cast<T*>(malloc(sizeof(T) * initialSize));

        // 사용 가능 인덱스 스택 초기화
        m_FreeIndices.reserve(initialSize);
        for (size_t i = 0; i < initialSize; i++) {
            m_FreeIndices.push_back(i);
        }
    }

    ~ObjectPool() {
        // 활성 객체 소멸
        for (size_t i = 0; i < m_PoolSize; i++) {
            if (IsActive(i)) {
                m_Objects[i].~T();
            }
        }
        free(m_Objects);
    }

    T* Acquire() {
        if (m_FreeIndices.empty()) {
            // 풀 확장 또는 에러
            ExpandPool();
        }

        size_t index = m_FreeIndices.back();
        m_FreeIndices.pop_back();

        // placement new로 생성자 호출
        T* obj = new (&m_Objects[index]) T();
        m_ActiveFlags[index] = true;

        return obj;
    }

    void Release(T* obj) {
        // 풀 내 인덱스 계산
        size_t index = obj - m_Objects;

        if (index < m_PoolSize && m_ActiveFlags[index]) {
            // 소멸자 호출
            obj->~T();
            m_ActiveFlags[index] = false;
            m_FreeIndices.push_back(index);
        }
    }

    // 통계
    size_t GetActiveCount() const {
        return m_PoolSize - m_FreeIndices.size();
    }

    size_t GetPoolSize() const {
        return m_PoolSize;
    }

private:
    void ExpandPool() {
        size_t newSize = m_PoolSize * 2;
        T* newObjects = static_cast<T*>(realloc(m_Objects, sizeof(T) * newSize));

        if (newObjects) {
            m_Objects = newObjects;

            // 새 인덱스 추가
            for (size_t i = m_PoolSize; i < newSize; i++) {
                m_FreeIndices.push_back(i);
                m_ActiveFlags.push_back(false);
            }

            m_PoolSize = newSize;
        }
    }

    T* m_Objects;
    std::vector<size_t> m_FreeIndices;
    std::vector<bool> m_ActiveFlags;
    size_t m_PoolSize;
};

// 사용 예
ObjectPool<Bullet> bulletPool(100);

void Fire() {
    Bullet* bullet = bulletPool.Acquire();
    bullet->Initialize(position, velocity);
}

void OnBulletHit(Bullet* bullet) {
    bulletPool.Release(bullet);
}

Q12: 메모리 누수를 어떻게 찾나요?

반복 씬 로드 테스트와 힙 스냅샷 비교로 찾습니다.

// 메모리 누수 탐지용 래퍼
class MemoryLeakDetector {
public:
    static void BeginTrack() {
        s_BaselineMemory = GetCurrentMemoryUsage();
        s_TrackingEnabled = true;
        s_Allocations.clear();
    }

    static void EndTrack() {
        s_TrackingEnabled = false;
        size_t currentMemory = GetCurrentMemoryUsage();
        size_t leaked = currentMemory - s_BaselineMemory;

        if (leaked > LEAK_THRESHOLD) {
            LogError("Potential memory leak: {} bytes", leaked);
            DumpAllocations();
        }
    }

    // 커스텀 할당자에서 호출
    static void OnAlloc(void* ptr, size_t size, const char* file, int line) {
        if (s_TrackingEnabled) {
            s_Allocations[ptr] = {size, file, line};
        }
    }

    static void OnFree(void* ptr) {
        if (s_TrackingEnabled) {
            s_Allocations.erase(ptr);
        }
    }

    static void DumpAllocations() {
        LogWarning("=== Unfreed Allocations ===");
        for (const auto& [ptr, info] : s_Allocations) {
            LogWarning("  {} bytes at {}:{}", info.size, info.file, info.line);
        }
    }

private:
    struct AllocInfo {
        size_t size;
        const char* file;
        int line;
    };

    static inline bool s_TrackingEnabled = false;
    static inline size_t s_BaselineMemory = 0;
    static inline std::unordered_map<void*, AllocInfo> s_Allocations;
    static constexpr size_t LEAK_THRESHOLD = 1024 * 1024;  // 1MB
};

// 테스트 방법: 씬 반복 로드
void LeakTest() {
    for (int i = 0; i < 10; i++) {
        MemoryLeakDetector::BeginTrack();

        LoadScene("BattleScene");
        PlayForSeconds(30);
        UnloadScene("BattleScene");

        MemoryLeakDetector::EndTrack();

        ForceGarbageCollection();
    }
}
누수 탐지 팁: 같은 씬을 10번 반복 로드/언로드하면서 메모리가 계속 증가하면 누수입니다.

Q14: 저사양 기기에서 동적으로 품질을 낮추려면?

기기 감지 + 런타임 메모리 체크로 자동 조절합니다.

class DynamicQualityManager {
public:
    enum class QualityTier {
        Ultra,   // 고사양 (8GB+ RAM)
        High,    // 중상급 (6GB RAM)
        Medium,  // 중급 (4GB RAM)
        Low,     // 저사양 (3GB RAM)
        Minimal  // 최저 (2GB RAM)
    };

    void Initialize() {
        // 기기 스펙 확인
        size_t totalRAM = GetDeviceTotalRAM();
        int gpuTier = GetGPUTier();

        // 초기 품질 설정
        if (totalRAM >= 8 * GB && gpuTier >= 3) {
            m_CurrentTier = QualityTier::Ultra;
        } else if (totalRAM >= 6 * GB) {
            m_CurrentTier = QualityTier::High;
        } else if (totalRAM >= 4 * GB) {
            m_CurrentTier = QualityTier::Medium;
        } else if (totalRAM >= 3 * GB) {
            m_CurrentTier = QualityTier::Low;
        } else {
            m_CurrentTier = QualityTier::Minimal;
        }

        ApplyQualitySettings(m_CurrentTier);
    }

    void ApplyQualitySettings(QualityTier tier) {
        switch (tier) {
            case QualityTier::Ultra:
                SetTextureQuality(2048, TextureCompression::ASTC_4x4);
                SetShadowQuality(ShadowQuality::High, 2048);
                SetParticleLimit(500);
                SetDrawDistance(300);
                break;

            case QualityTier::High:
                SetTextureQuality(1024, TextureCompression::ASTC_5x5);
                SetShadowQuality(ShadowQuality::Medium, 1024);
                SetParticleLimit(300);
                SetDrawDistance(200);
                break;

            case QualityTier::Medium:
                SetTextureQuality(1024, TextureCompression::ASTC_6x6);
                SetShadowQuality(ShadowQuality::Low, 512);
                SetParticleLimit(200);
                SetDrawDistance(150);
                break;

            case QualityTier::Low:
                SetTextureQuality(512, TextureCompression::ASTC_8x6);
                SetShadowQuality(ShadowQuality::Off, 0);
                SetParticleLimit(100);
                SetDrawDistance(100);
                break;

            case QualityTier::Minimal:
                SetTextureQuality(256, TextureCompression::ETC2);
                SetShadowQuality(ShadowQuality::Off, 0);
                SetParticleLimit(50);
                SetDrawDistance(80);
                DisablePostProcessing();
                break;
        }
    }

    // 런타임 자동 조절
    void OnMemoryPressure(PressureLevel level) {
        if (level >= PressureLevel::High) {
            // 품질 한 단계 낮춤
            int tierValue = static_cast<int>(m_CurrentTier);
            if (tierValue < static_cast<int>(QualityTier::Minimal)) {
                m_CurrentTier = static_cast<QualityTier>(tierValue + 1);
                ApplyQualitySettings(m_CurrentTier);
                LogInfo("Quality reduced to tier {} due to memory pressure",
                        tierValue + 1);
            }
        }
    }

private:
    QualityTier m_CurrentTier;
    static constexpr size_t GB = 1024 * 1024 * 1024;
};
주의: 품질을 낮추면 메모리는 줄지만, 이미 로드된 에셋을 언로드해야 실제 메모리가 해제됩니다. 품질 변경 후 씬 재로드가 필요할 수 있습니다.
