카트리지에서 SSD까지 - 50년간의 저장 매체 발전과 로딩 시간의 전쟁

Part 1. 카트리지 시대 - 로딩이 없던 황금기 (1970s~1990s)

옛날 게임은 정말 로딩이 없었어?

맞아! 카트리지(Cartridge)는 ROM(Read-Only Memory)이라서 CPU가 직접 접근할 수 있었어.

데이터를 RAM으로 복사할 필요 없이 즉시 실행 가능했지!

카트리지의 "뱅크 스위칭"이 뭐야?

CPU의 주소 공간(예: 32KB)보다 카트리지 용량이 클 때, 뱅크(Bank)를 교체해가며 접근하는 기법이야.

이것도 일종의 "로딩"이지만, 마이크로초 단위라서 플레이어는 인지 못해.

// NES 뱅크 스위칭 예시 (MMC3 마퍼) // CPU 주소 공간: $8000~$FFFF (32KB) // 카트리지 ROM: 최대 512KB void SwitchBank(uint8_t bankNumber) { // 마퍼 레지스터에 쓰기만 하면 즉시 전환! // 소요 시간: 마이크로초 단위 *(volatile uint8_t*)0x8000 = bankNumber; } // 스테이지 1 로드 SwitchBank(0); // 뱅크 0으로 전환 (즉시!) // 이제 $8000~$BFFF는 뱅크 0의 데이터 // 스테이지 2 로드 SwitchBank(1); // 뱅크 1로 전환 (즉시!) // 이제 $8000~$BFFF는 뱅크 1의 데이터 // 플레이어는 이 전환을 전혀 인지하지 못함

Part 2. 플로피 디스크 시대 - 로딩의 시작 (1980s)

플로피 디스크는 어땠어?

플로피 디스크는 자기 매체라서 기계적 동작이 필요했어.

헤드가 움직이고, 디스크가 회전해야 해서 느렸지.

Part 3. CD-ROM 시대 - 로딩 화면의 전성기 (1990s)

CD-ROM이 나오면서 뭐가 바뀌었어?

CD-ROM은 650MB라는 엄청난 용량을 제공했어!

하지만 읽기 속도는 150 KB/s (1x)로 느렸지.

용량은 커지고, 속도는 느려서 로딩 화면이 길어졌어.

주요 CD 기반 콘솔/플랫폼:
- PlayStation 1 (1994): 2x CD-ROM

PS1 시대 로딩이 왜 그렇게 길었어?

PS1은 2x CD-ROM (300 KB/s)에 RAM이 2MB밖에 없었어.

화면 전환마다 새 데이터를 CD에서 읽어야 했지.

// PS1 시대 로딩 패턴 // RAM: 2MB, CD 속도: 300 KB/s void LoadStage(int stageNumber) { // 이전 데이터 해제 ClearRAM(); // CD에서 새 데이터 로딩 // 텍스처 + 모델 + 사운드 = 약 1.5MB // 1.5MB ÷ 300KB/s = 5초 ShowLoadingScreen(); LoadTextures(stageNumber); // 800KB, 2.7초 LoadModels(stageNumber); // 400KB, 1.3초 LoadSounds(stageNumber); // 300KB, 1초 HideLoadingScreen(); // 총 약 5초 로딩 } // PS1 파이널 판타지 7 사례: // - 디스크 3장 (총 1.86GB) // - 배틀 진입 로딩: 3~5초 // - 에어리어 이동: 2~4초 // - 당시로서는 "짧은" 로딩!

Part 4. DVD 시대 - 대용량의 시대 (2000s)

DVD로 뭐가 바뀌었어?

DVD는 4.7~8.5GB로 CD의 7~13배 용량!

읽기 속도도 1.35~10.8 MB/s로 빨라졌어.

하지만 게임 용량도 급격히 커져서 로딩 문제는 여전했지.

게임 용량 증가:
- PS1 시대: 평균 500MB~1.5GB
- PS2 시대: 평균 2~8GB
- 용량 5배 ↑, 속도 4배 ↑ → 로딩은 여전히 김

PS2 시대 로딩 시간 예시:
- GTA 산 안드레아스: 초기 로딩 40~60초
- 파이널 판타지 X: 배틀 로딩 3~5초
- 갓 오브 워: 스테이지 로딩 10~15초
PS2 vs Xbox 로딩 속도 차이가 있었어?

Xbox는 내장 HDD가 있어서 게임 데이터를 HDD에 캐싱할 수 있었어.

그래서 같은 게임도 Xbox 버전이 로딩이 빨랐지!

왜 설치가 필요하게 됐어?

게임 용량은 수십 GB로 커졌는데, Blu-ray 속도는 9~27 MB/s로 한계가 있었어.

HDD로 복사해야 쾌적한 플레이가 가능했지.

// PS3/Xbox 360 시대 로딩 전략 enum class InstallMode { NO_INSTALL, // 디스크에서 직접 (느림) MANDATORY, // 필수 설치 (MGS4) OPTIONAL, // 선택 설치 (권장) BACKGROUND, // 플레이 중 백그라운드 설치 }; struct LoadTimeComparison { // GTA V (Xbox 360) 예시 float discOnly = 90.0f; // 디스크만: 90초 float discPlusHDD = 45.0f; // 설치 후: 45초 float hddOnly = 35.0f; // 완전 설치: 35초 }; // 게임 용량 폭발 // GTA V: 16GB (Xbox 360 DVD 2장) // Halo 4: 8GB (DVD 2장) // → DVD 용량 한계로 디스크 여러 장 필요

Part 6. SATA SSD 시대 - 체감 속도 혁명 (2015~2020)

SSD가 게임에 어떤 변화를 가져왔어?

SSD는 탐색 시간(Seek Time)이 거의 0이야!

HDD가 헤드를 움직이는 동안 SSD는 바로 데이터를 읽어.

SSD vs HDD 핵심 차이:

┌─────────────────────────────────────────────────────────────────────┐
│  HDD의 탐색 시간 문제                                               │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  파일 A 읽기 → 헤드 이동(10ms) → 읽기 → 헤드 이동(10ms) → 파일 B  │
│                                                                     │
│  작은 파일 1000개 읽기:                                             │
│  1000 × 10ms = 10초 (탐색만으로!)                                  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────┐
│  SSD의 즉시 접근                                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  파일 A 읽기(0.1ms) → 파일 B 읽기(0.1ms) → 파일 C 읽기(0.1ms)      │
│                                                                     │
│  작은 파일 1000개 읽기:                                             │
│  1000 × 0.1ms = 0.1초!                                             │
│                                                                     │

→ SSD의 진짜 장점은 "랜덤 읽기"와 "탐색 시간"!

Part 7. NVMe SSD 시대 - 초고속의 시대 (2020~현재)

NVMe는 SATA SSD보다 뭐가 달라?

NVMe는 PCIe 직결로 SATA의 인터페이스 한계를 극복했어!

SATA: 최대 600 MB/s vs NVMe: 3,500~7,000+ MB/s

NVMe vs SATA 아키텍처:

SATA SSD:
┌─────────────────────────────────────────────────────────────────────┐
│  [SSD] ─── SATA 인터페이스 ─── SATA 컨트롤러 ─── CPU/메모리        │
│             최대 600 MB/s (병목!)                                   │
└─────────────────────────────────────────────────────────────────────┘

NVMe SSD:
┌─────────────────────────────────────────────────────────────────────┐
│  [SSD] ───────── PCIe 직접 연결 ──────────────── CPU/메모리        │
│         PCIe 3.0 x4: 3,500 MB/s                                     │
│         PCIe 4.0 x4: 7,000 MB/s                                     │
│         PCIe 5.0 x4: 14,000 MB/s                                    │
└─────────────────────────────────────────────────────────────────────┘

속도 비교:
┌────────────────────────────────────────────────────────────────────┐
│                                                                    │
│  HDD           █████ (150 MB/s)                                   │
│  SATA SSD      ██████████████████ (550 MB/s)                      │
│  NVMe PCIe 3.0 ██████████████████████████████████████████████████ │
│                ██████████████████████ (3,500 MB/s)                │
│  NVMe PCIe 4.0 ██████████████████████████████████████████████████ │
│                ████████████████████████████████████████████████   │
│                ██ (7,000 MB/s)                                    │
│  PS5 SSD       ██████████████████████████████████████████████████ │
│                ██████████████ (5,500 MB/s + 압축)                │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
NVMe로 로딩이 얼마나 빨라졌어?

SATA SSD 대비 20~50% 더 빨라졌어. 하지만 기대만큼은 아니야.

이유: 순차 읽기 속도만 빨라지고, CPU 처리가 병목이 되기 시작!

NVMe의 한계 - 새로운 병목:

SATA SSD 시대:
[디스크] ──(병목)──▶ [CPU] ──▶ [GPU]
  느림                 빠름      빠름

NVMe SSD 시대:
[디스크] ──▶ [CPU] ──(병목)──▶ [GPU]
  빠름        느림 (압축해제,     빠름
                    포맷변환)

실제 측정 (CPU 처리 시간 포함):
┌────────────────────────────────────────────────────────────────────┐
│  10GB 게임 데이터 로딩                                             │
├────────────────────────────────────────────────────────────────────┤
│  SATA SSD:                                                         │
│  - 디스크 읽기: 18초                                               │
│  - CPU 처리: 5초                                                   │
│  - 총: 23초                                                        │
│                                                                    │
│  NVMe SSD:                                                         │
│  - 디스크 읽기: 3초                                                │
│  - CPU 처리: 5초 (변함없음!)                                       │
│  - 총: 8초                                                         │
│                                                                    │
│  이론상 6배 빠른데 실제로는 2.9배 (CPU가 병목)                     │
└────────────────────────────────────────────────────────────────────┘

→ 이 문제를 해결하기 위해 DirectStorage, PS5 I/O 등장!

Part 8. 콘솔 혁신 - PS5와 Xbox Series (2020~)

PS5의 로딩이 왜 그렇게 빠른 거야?

PS5는 전용 설계로 모든 병목을 제거했어!

SSD + 압축 해제 칩 + I/O 코프로세서 = 완벽한 통합

Part 9. DirectStorage - PC의 반격 (2022~)

PC에서도 PS5처럼 빨라질 수 있어?

DirectStorage가 그 해답이야!

GPU가 직접 NVMe에서 읽고, GPU에서 압축 해제해.

DirectStorage 아키텍처:

기존 Win32 방식:
┌─────────────────────────────────────────────────────────────────────┐
│  [NVMe] ─▶ [RAM] ─▶ [CPU 압축해제] ─▶ [RAM] ─▶ [PCIe] ─▶ [VRAM]  │
│            복사      느림              복사      복사              │
│            │         │                │         │                  │
│            └─────────┴────────────────┴─────────┘                  │
│                       많은 CPU 사이클                               │
└─────────────────────────────────────────────────────────────────────┘

DirectStorage 방식:
┌─────────────────────────────────────────────────────────────────────┐
│  [NVMe] ────────────────────────────────▶ [VRAM]                   │
│                                             │                       │
│                                     GPU에서 압축 해제              │
│                                     (GDeflate)                      │
│                                                                     │
│  CPU 개입 최소화!                                                   │
└─────────────────────────────────────────────────────────────────────┘

DirectStorage 요구 사항:
- Windows 11 (또는 Windows 10 일부 지원)
- NVMe SSD
- DirectX 12 GPU
- 게임이 DirectStorage API 사용

지원 게임 (2024 기준):
- Forspoken (최초 지원작)
- Ratchet & Clank: Rift Apart (PC 이식)
- Starfield
- 다수의 AAA 타이틀 지원 예정
DirectStorage로 얼마나 빨라져?

이론적으로 기존 대비 40% 로딩 시간까지 단축 가능!

하지만 실제 게임에서는 아직 최적화 진행 중이야.

// DirectStorage GPU 압축 해제 성능 // RTX 4090 벤치마크 (GDeflate) // - CPU Zstd: 3.5 GB/s 해제 // - GPU GDeflate: 24+ GB/s 해제 // 로딩 시간 비교 (4GB 압축 데이터 → 8GB 해제) struct LoadingBenchmark { // 기존 방식 (Win32 + CPU Zstd) float diskRead = 4.0f / 7.0f; // 0.57초 float cpuDecompress = 8.0f / 3.5f; // 2.29초 float cpuToGpu = 8.0f / 15.0f; // 0.53초 float oldTotal = 3.39f; // 총 3.39초 // DirectStorage (GPU GDeflate) float diskToGpu = 4.0f / 7.0f; // 0.57초 float gpuDecompress = 8.0f / 24.0f; // 0.33초 float newTotal = 0.9f; // 총 0.9초 // 성능 향상: 3.39초 → 0.9초 (3.8배!) };

Part 10. 미래 전망 - 로딩이 사라지는 날

로딩이 완전히 사라질 수 있을까?

기술적으로는 거의 0초에 근접하고 있어!

하지만 게임 용량도 계속 커지고 있어서... 싸움은 계속될 거야.

→ 로딩은 점점 짧아지고 있다
앞으로 어떻게 될까?

다음 기술들이 로딩을 더 줄여줄 거야:

미래 기술 전망:

1. PCIe 5.0 / 6.0 SSD
   - PCIe 5.0: 14 GB/s (현재 최고의 2배)
   - PCIe 6.0: 28 GB/s (개발 중)

2. CXL (Compute Express Link)
   - 메모리 확장 기술
   - SSD를 확장 메모리처럼 사용

3. 지능형 프리페칭
   - AI가 플레이어 행동 예측
   - 필요한 에셋 미리 로딩

4. 클라우드 스트리밍
   - 로컬 로딩 개념 자체가 사라짐
   - 데이터센터에서 렌더링 후 영상만 전송

5. 메모리 계층 통합
   - RAM/VRAM/SSD 구분 없어짐
   - 통합 메모리 공간으로 관리

핵심 정리

  • 카트리지 (1970s~90s): ROM 직접 접근, 로딩 0초
  • 플로피 (1980s): 125KB/s, "Please wait..." 탄생
  • CD-ROM (1990s): 150KB~7.8MB/s, 긴 로딩의 시작
  • DVD (2000s): 1.35~10.8MB/s, 설치 개념 등장
  • HDD (2005~): 100~200MB/s, 설치 필수화
  • SATA SSD (2015~): 550MB/s, 탐색 시간 0.1ms
  • NVMe SSD (2020~): 3,500~7,000MB/s, CPU가 병목
  • PS5/XSX (2020~): 전용 하드웨어로 거의 즉시 로딩
  • DirectStorage (2022~): GPU 직접 처리로 PC도 빨라짐
  • 용량 vs 속도 경쟁은 계속, 로딩 시간은 점점 짧아짐
