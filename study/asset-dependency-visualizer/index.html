의존성 시각화 도구

AssetGraph, Reference Viewer, 커스텀 시각화 구현

Part 1. 개념: 의존성 시각화란?

의존성 시각화가 왜 필요해?

에셋 의존성은 코드처럼 눈에 보이지 않습니다. Material이 어떤 Texture를 참조하는지, Prefab이 어떤 Script를 포함하는지 일일이 열어봐야 합니다.

프로젝트가 커지면 이런 문제가 생깁니다:

문제 1: "이 텍스처 삭제해도 돼?"
         → 어디서 쓰이는지 모름 → 무서워서 남겨둠 → 불필요한 용량 증가

문제 2: "왜 이 씬이 500MB나 되지?"
         → 어떤 에셋이 포함되는지 파악 불가 → 최적화 불가능

문제 3: "번들 A가 왜 번들 B, C, D를 같이 로드하지?"
         → 숨겨진 의존성 → 메모리 폭증

문제 4: "이 에셋 수정하면 어디까지 영향 받아?"
         → 역참조 파악 불가 → 사이드 이펙트 위험

시각화 도구가 이 모든 문제를 해결합니다.

어떤 형태로 시각화하는 게 좋아?

의존성 데이터의 특성에 따라 다른 시각화가 적합합니다:

시각화 형태별 적합한 용도:

1. 그래프 (Node-Link)
   ┌───┐     ┌───┐
   │ A │────→│ B │     ✓ 참조 관계 직관적
   └───┘     └───┘     ✓ 순환 참조 탐지
     │         │       ✗ 노드 많으면 복잡
     ▼         ▼
   ┌───┐     ┌───┐
   │ C │────→│ D │
   └───┘     └───┘

2. 트리맵 (Treemap)
   ┌────────────────────────────┐
   │ Textures (80MB)           │     ✓ 크기 비교 직관적
   │ ┌──────────┬─────┬───┐   │     ✓ 계층 구조 표현
   │ │ Env(50MB)│Char │UI │   │     ✗ 참조 관계 표현 어려움
   │ │          │(20) │(10)│   │
   │ └──────────┴─────┴───┘   │
   └────────────────────────────┘

3. 선버스트 (Sunburst)
         ╱─────╲
       ╱ Meshes ╲              ✓ 계층 깊이 표현
     ╱───────────╲             ✓ 비율 직관적
   ╱   Textures    ╲           ✗ 참조 관계 표현 불가
   ╲    Audio     ╱
     ╲───────────╱
       ╲ Scripts╱
         ╲─────╱

4. 매트릭스 (Adjacency Matrix)
        A  B  C  D
      ┌──┬──┬──┬──┐
    A │  │ ● │ ● │  │     ✓ 대규모 데이터 처리
    B │  │  │  │ ● │     ✓ 패턴 발견 용이
    C │  │  │  │ ● │     ✗ 직관성 떨어짐
    D │  │  │  │  │
      └──┴──┴──┴──┘

Unity에서 역참조(이 에셋을 누가 쓰나)는 어떻게 찾아?

Unity는 역참조를 기본 제공하지 않습니다. 직접 구현해야 합니다:

using UnityEngine; using UnityEditor; using System.Collections.Generic; using System.Linq; public class ReverseReferencesFinder : EditorWindow { private Object targetAsset; private List<string> referencingAssets = new List<string>(); private Vector2 scrollPos; private bool isSearching; // 역참조 인덱스 (한 번 빌드 후 재사용) private static Dictionary<string, HashSet<string>> reverseIndex; [MenuItem("Tools/Find Asset References")] static void ShowWindow() { GetWindow<ReverseReferencesFinder>("Reference Finder"); } void OnGUI() { EditorGUILayout.LabelField("Find References To Asset", EditorStyles.boldLabel); targetAsset = EditorGUILayout.ObjectField( "Target Asset", targetAsset, typeof(Object), false); EditorGUILayout.BeginHorizontal(); if (GUILayout.Button("Build Index") && !isSearching) { BuildReverseIndex(); } if (GUILayout.Button("Find References") && targetAsset != null) { FindReferences(); } EditorGUILayout.EndHorizontal(); if (reverseIndex != null) { EditorGUILayout.HelpBox( $"Index ready: {reverseIndex.Count} assets indexed", MessageType.Info); } EditorGUILayout.Space(); EditorGUILayout.LabelField($"Found {referencingAssets.Count} references:"); scrollPos = EditorGUILayout.BeginScrollView(scrollPos); foreach (var assetPath in referencingAssets) { EditorGUILayout.BeginHorizontal(); var asset = AssetDatabase.LoadAssetAtPath<Object>(assetPath); EditorGUILayout.ObjectField(asset, typeof(Object), false); if (GUILayout.Button("Select", GUILayout.Width(60))) { Selection.activeObject = asset; EditorGUIUtility.PingObject(asset); } EditorGUILayout.EndHorizontal(); } EditorGUILayout.EndScrollView(); } void BuildReverseIndex() { isSearching = true; reverseIndex = new Dictionary<string, HashSet<string>>(); var allAssets = AssetDatabase.GetAllAssetPaths() .Where(p => p.StartsWith("Assets/")) .ToArray(); for (int i = 0; i < allAssets.Length; i++) { var assetPath = allAssets[i]; if (EditorUtility.DisplayCancelableProgressBar( "Building Index", $"Processing {assetPath}", (float)i / allAssets.Length)) { break; } // 이 에셋이 참조하는 것들 var dependencies = AssetDatabase.GetDependencies(assetPath, false); foreach (var dep in dependencies) { if (dep == assetPath) continue; if (!reverseIndex.ContainsKey(dep)) { reverseIndex[dep] = new HashSet<string>(); } // dep를 참조하는 assetPath 기록 reverseIndex[dep].Add(assetPath); } } EditorUtility.ClearProgressBar(); isSearching = false; } void FindReferences() { referencingAssets.Clear(); var targetPath = AssetDatabase.GetAssetPath(targetAsset); if (reverseIndex != null && reverseIndex.ContainsKey(targetPath)) { // 인덱스가 있으면 즉시 조회 (O(1)) referencingAssets = reverseIndex[targetPath].ToList(); } else { // 인덱스 없으면 전체 스캔 (느림) FindReferencesWithoutIndex(targetPath); } referencingAssets.Sort(); } void FindReferencesWithoutIndex(string targetPath) { var allAssets = AssetDatabase.GetAllAssetPaths() .Where(p => p.StartsWith("Assets/")); foreach (var assetPath in allAssets) { var deps = AssetDatabase.GetDependencies(assetPath, false); if (deps.Contains(targetPath)) { referencingAssets.Add(assetPath); } } } }

Reference Viewer의 주요 옵션:

Reference Viewer 옵션 설명:

Search Depth (검색 깊이)
  ├─ 1: 직접 참조만
  ├─ 2: 2단계까지 (참조의 참조)
  └─ 3+: 더 깊은 관계 (복잡해질 수 있음)

Search Breadth Limit (검색 너비)
  └─ 각 노드에서 표시할 최대 참조 수

Show/Hide 옵션:
  ├─ Referencers: 역참조 (이걸 쓰는 것들)
  ├─ Dependencies: 의존성 (이게 쓰는 것들)
  ├─ Soft References: 약한 참조 (TSoftObjectPtr)
  ├─ Hard References: 강한 참조 (직접 참조)
  ├─ Management References: 에디터 전용 참조
  └─ Searchable Names: 문자열 기반 참조

색상 코드:
  ├─ 파란색 선: Hard Reference
  ├─ 초록색 선: Soft Reference
  └─ 빨간색 선: Circular Reference (순환)

Part 4. 커스텀 시각화 도구 구현

// Unity 실시간 의존성 모니터링 public class RealTimeDependencyMonitor : AssetPostprocessor { public static event Action<DependencyChange> OnDependencyChanged; // 에셋 임포트 완료 시 static void OnPostprocessAllAssets( string[] imported, string[] deleted, string[] moved, string[] movedFrom) { var changes = new List<DependencyChange>(); // 새로 임포트된 에셋 foreach (var path in imported) { var deps = AssetDatabase.GetDependencies(path, false); changes.Add(new DependencyChange { type = ChangeType.Added, assetPath = path, newDependencies = deps.ToList() }); } // 삭제된 에셋 foreach (var path in deleted) { changes.Add(new DependencyChange { type = ChangeType.Removed, assetPath = path }); } // 이동된 에셋 for (int i = 0; i < moved.Length; i++) { changes.Add(new DependencyChange { type = ChangeType.Moved, assetPath = moved[i], oldPath = movedFrom[i] }); } foreach (var change in changes) { OnDependencyChanged?.Invoke(change); } } } public class DependencyChange { public ChangeType type; public string assetPath; public string oldPath; public List<string> oldDependencies; public List<string> newDependencies; } public enum ChangeType { Added, Removed, Modified, Moved } // 시각화 도구에서 구독 public class DependencyGraphWindow : EditorWindow { void OnEnable() { RealTimeDependencyMonitor.OnDependencyChanged += HandleChange; } void OnDisable() { RealTimeDependencyMonitor.OnDependencyChanged -= HandleChange; } void HandleChange(DependencyChange change) { switch (change.type) { case ChangeType.Added: AddNodeToGraph(change.assetPath, change.newDependencies); HighlightNode(change.assetPath, Color.green); break; case ChangeType.Removed: RemoveNodeFromGraph(change.assetPath); break; case ChangeType.Modified: UpdateNodeDependencies(change.assetPath, change.oldDependencies, change.newDependencies); HighlightNode(change.assetPath, Color.yellow); break; } Repaint(); } }

의존성 시각화 도구 구축 시 권장 사항은?

✅ 권장 사항

  • 인덱스 캐싱: 역참조 인덱스는 한 번 빌드 후 변경분만 업데이트
  • 증분 분석: 변경된 에셋만 재분석 (파일 해시 비교)
  • 비동기 처리: 대규모 분석은 백그라운드에서
  • LOD 렌더링: 줌 레벨에 따라 표시 정보 조절
  • 검색 기능: 대규모 그래프에서 특정 에셋 빠르게 찾기

⚠️ 주의 사항

  • 문자열 참조 감지 불가: Resources.Load("path") 같은 동적 로드
  • 리플렉션 참조 감지 불가: Type.GetType() 등
  • 빌드 타임 참조: 에디터 전용 참조가 런타임에는 없을 수 있음
  • 플랫폼 차이: iOS/Android 간 의존성이 다를 수 있음

핵심 정리

  • 정방향/역방향 탐색 - "이게 뭘 쓰나" + "이걸 누가 쓰나"
  • Unity 내장 - Select Dependencies, Addressables Analyze
  • Unreal 내장 - Reference Viewer, Size Map, Asset Audit
  • 커스텀 시각화 - D3.js/vis.js + JSON 내보내기
  • 대규모 최적화 - 클러스터링, LOD, 가상화, WebGL
  • 인터랙션 - 검색, 필터, 경로 하이라이트, 영향 범위
  • CI 통합 - 빌드 전 검증, PR 코멘트, 변경 diff
  • 실전 활용 - 삭제 안전성, 중복 제거, 허브 노드 분리
