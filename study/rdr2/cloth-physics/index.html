실시간 천 시뮬레이션 (Cloth Physics)

Part 1: 천 시뮬레이션의 어려움

Q: 왜 천 시뮬레이션이 어려워요?

천은 수천 개의 점이 실시간으로 상호작용하기 때문입니다.

천 시뮬레이션이 복잡한 이유

  1. 점 개수가 많음
    • Arthur의 코트: 약 1,500개 정점
    • 각 정점마다 물리 계산 필요
  2. 제약(Constraint)이 많음
    • 점끼리 거리 유지 (늘어나면 안 됨)
    • 굽힘 저항 (너무 접히면 안 됨)
    • 충돌 처리 (몸 뚫고 지나가면 안 됨)
  3. 실시간 성능
    • 60fps 유지 필요
    • 하나의 프레임당 16.6ms만 사용 가능
천 메쉬 구조 (간소화) 고정점 (어깨) ●───●───●───● │╲ │╲ │╲ │ │ ╲ │ ╲ │ ╲ │ ●───●───●───● │╲ │╲ │╲ │ │ ╲ │ ╲ │ ╲ │ ●───●───●───● │ │ │ │ ● ● ● ● ← 자유롭게 움직임 정점(●): 각각 위치, 속도, 가속도 보유 선(─): Spring Constraint (거리 유지) 대각선(╲): Shear Constraint (비틀림 방지)

Part 2: Mass-Spring 모델

Q: 가장 기본적인 천 시뮬레이션은 어떻게 해요?

Mass-Spring 모델을 사용합니다.

기본 원리

천을 질량을 가진 점(Mass)과 용수철(Spring)로 연결된 네트워크로 표현합니다.

  • 질량점: 중력의 영향을 받음
  • 용수철: 늘어나면 원래 길이로 복원하려는 힘
// Mass-Spring 시뮬레이션 (의사코드) struct ClothParticle: Vector3 position Vector3 velocity Vector3 acceleration float mass bool isFixed // 고정점 (어깨 등) struct SpringConstraint: ClothParticle* p1 ClothParticle* p2 float restLength // 원래 길이 float stiffness // 강성 (0~1) function SimulateSpring(spring, deltaTime): // 현재 거리 계산 delta = spring.p2.position - spring.p1.position currentLength = delta.Length() // 늘어난 정도 stretch = currentLength - spring.restLength // 복원력 (Hooke's Law: F = -kx) force = delta.Normalized() * stretch * spring.stiffness // 양쪽 점에 힘 적용 if not spring.p1.isFixed: spring.p1.acceleration += force / spring.p1.mass if not spring.p2.isFixed: spring.p2.acceleration -= force / spring.p2.mass // 매 프레임 업데이트 function UpdateCloth(deltaTime): // 1. 외력 적용 (중력, 바람) for particle in clothParticles: if not particle.isFixed: particle.acceleration = Vector3(0, -9.8, 0) // 중력 // 2. 용수철 힘 계산 for spring in springs: SimulateSpring(spring, deltaTime) // 3. 위치 업데이트 (Verlet Integration) for particle in clothParticles: if not particle.isFixed: particle.velocity += particle.acceleration * deltaTime particle.position += particle.velocity * deltaTime
용수철 복원력 [정상 상태] ●─────● (restLength = 1.0) [늘어남] ●──────────● (currentLength = 1.5) stretch = 1.5 - 1.0 = 0.5 force = 0.5 * stiffness ●←───────→● (양쪽으로 당김) [압축] ●───● (currentLength = 0.7) stretch = 0.7 - 1.0 = -0.3 force = -0.3 * stiffness ●→ ←● (서로 밀어냄)

Part 3: Position Based Dynamics (PBD)

Q: Mass-Spring은 뭐가 문제예요?

수치 안정성 문제가 있습니다.

Mass-Spring의 문제점

  • 강한 힘이 가해지면 폭발적으로 늘어남
  • stiffness를 높이면 떨림(jitter) 발생
  • 안정화를 위해 매우 작은 timestep 필요 → 느림

PBD의 해결책

힘(Force) 대신 위치(Position)를 직접 수정합니다.

구분 Mass-Spring PBD
방식 힘 계산 → 가속도 → 속도 → 위치 제약 위반 → 위치 직접 보정
안정성 낮음 (폭발 가능) 높음 (항상 안정)
성능 작은 timestep 필요 큰 timestep 가능
// Position Based Dynamics (PBD) function SolveDistanceConstraint(p1, p2, restLength): // 현재 거리 delta = p2.position - p1.position currentLength = delta.Length() // 위반 정도 error = currentLength - restLength if error == 0: return // 제약 충족 // 위치 직접 보정 correction = delta.Normalized() * error * 0.5 if not p1.isFixed: p1.position += correction // 절반씩 당김 if not p2.isFixed: p2.position -= correction // PBD 메인 루프 function UpdateClothPBD(deltaTime): // 1. 예측 위치 계산 (중력, 바람) for particle in clothParticles: particle.velocity += gravity * deltaTime particle.predictedPosition = particle.position + particle.velocity * deltaTime // 2. 제약 충족 반복 (Solver Iterations) for iteration in 0 to 5: // 보통 5~10회 반복 for constraint in constraints: SolveDistanceConstraint(constraint.p1, constraint.p2, constraint.restLength) // 3. 속도 업데이트 for particle in clothParticles: particle.velocity = (particle.position - particle.prevPosition) / deltaTime particle.prevPosition = particle.position
PBD vs Mass-Spring 비교 [Mass-Spring - 폭발 가능] 프레임 0: ●────● 프레임 1: ●─────────● (과도하게 늘어남) 프레임 2: ●──────────────────● (폭발!) [PBD - 항상 안정] 프레임 0: ●────● 프레임 1: ●──────● (약간 늘어남) ●─────● (즉시 보정) 프레임 2: ●────● (원상 복귀) PBD는 매 프레임 "거리가 restLength가 되도록" 위치를 강제로 조정하므로 절대 폭발하지 않음

Part 4: 바람과 상호작용

Q: 바람은 어떻게 시뮬레이션해요?

바람을 벡터 필드로 표현하고, 천의 표면적에 따라 힘을 가합니다.

바람 시뮬레이션 과정

  1. Wind Zone 정의: 지역별 바람 방향/세기
  2. 노이즈 추가: Perlin Noise로 돌풍 표현
  3. 표면적 계산: 삼각형이 바람을 얼마나 받는지
  4. Drag 적용: 공기 저항
// 바람 시스템 struct WindZone: Vector3 baseDirection // 기본 바람 방향 float baseStrength // 기본 세기 float turbulence // 난류 정도 float frequency // 변화 속도 function CalculateWind(position, time): // Perlin Noise로 돌풍 생성 noiseValue = PerlinNoise( position.x * 0.1 + time, position.z * 0.1, time * windZone.frequency ) // 바람 방향 변화 windDir = windZone.baseDirection windDir += RandomVector() * noiseValue * windZone.turbulence // 바람 세기 windStrength = windZone.baseStrength * (1.0 + noiseValue * 0.5) return windDir.Normalized() * windStrength // 천에 바람 적용 function ApplyWind(cloth, deltaTime): for triangle in cloth.triangles: // 삼각형 법선 (바람을 받는 방향) normal = CalculateNormal(triangle) // 삼각형 중심 center = (triangle.p1 + triangle.p2 + triangle.p3) / 3.0 // 해당 위치의 바람 wind = CalculateWind(center, currentTime) // 바람이 삼각형에 수직으로 부딪치는 정도 windDot = Dot(normal, wind.Normalized()) if windDot > 0: // 앞면에만 적용 // 표면적 계산 area = triangle.Area() // 바람 힘 = 세기 × 표면적 × 수직도 force = wind * area * windDot // 세 정점에 분배 triangle.p1.acceleration += force / (3.0 * triangle.p1.mass) triangle.p2.acceleration += force / (3.0 * triangle.p2.mass) triangle.p3.acceleration += force / (3.0 * triangle.p3.mass)
바람 상호작용 [바람이 정면으로 부딪힘] Wind →→→ ↓ [코트] /│\ / │ \ ●──●──● windDot = 1.0 (최대 영향) force = 최대 [바람이 측면에서 스침] Wind ↓↓↓ | [코트] /│\ windDot = 0.2 (약한 영향) force = 최소 [바람이 뒤에서 불어옴] ←←← Wind [코트] \│/ windDot < 0 (무시) force = 0

Part 5: 충돌 처리 (Self-Collision & Body Collision)

Q: 옷이 왜 몸을 뚫고 지나가지 않아요?

두 가지 충돌 검사를 합니다.

1. Body Collision (몸과 충돌)

Arthur의 몸을 Capsule Collider로 근사화합니다.

2. Self-Collision (옷끼리 충돌)

코트 앞자락과 뒷자락이 겹치지 않도록 합니다.

// Body Collision (Capsule) struct CapsuleCollider: Vector3 pointA // 윗점 (어깨) Vector3 pointB // 아랫점 (허리) float radius // 반지름 function ResolveBodyCollision(particle, capsule): // 점과 캡슐 축 사이의 최단 거리 closestPoint = ClosestPointOnLineSegment( particle.position, capsule.pointA, capsule.pointB ) delta = particle.position - closestPoint distance = delta.Length() // 충돌 체크 if distance < capsule.radius: penetration = capsule.radius - distance // 밖으로 밀어냄 particle.position += delta.Normalized() * penetration // Self-Collision (Spatial Hashing) function ResolveSelfCollision(cloth): // 공간 해싱으로 가까운 점들만 체크 spatialGrid = BuildSpatialGrid(cloth.particles, cellSize: 0.1) for cell in spatialGrid: particles = cell.GetParticles() for i in 0 to particles.Count: for j in i+1 to particles.Count: p1 = particles[i] p2 = particles[j] // 같은 삼각형 정점은 스킵 if AreNeighbors(p1, p2): continue delta = p2.position - p1.position distance = delta.Length() // 최소 거리 (옷 두께) minDistance = 0.01 // 1cm if distance < minDistance: penetration = minDistance - distance correction = delta.Normalized() * penetration * 0.5 p1.position -= correction p2.position += correction
충돌 처리 시각화 [Body Collision - Capsule] ● ← pointA (어깨) | | ○ ← 천 정점 (침투) | ● ← pointB (허리) 1. 가장 가까운 점 찾기: closestPoint 2. 거리 체크: distance < radius? 3. 밖으로 밀어냄: position += normal * penetration [Self-Collision - Spatial Grid] ┌───┬───┬───┐ │ │ ● │ │ Spatial Grid (0.1m 셀) ├───┼─●─┼───┤ │ │●● │ │ ← 같은 셀 안에서만 체크 ├───┼───┼───┤ │ │ │ │ 같은 셀 안의 점끼리만 충돌 검사 → O(n²) 대신 O(n) 복잡도

Part 6: 성능 최적화 (LOD & GPU)

Q: 모든 캐릭터의 옷을 시뮬레이션하면 느려지지 않아요?

LOD와 GPU 가속으로 최적화합니다.

LOD (Level of Detail) 전략

거리 정점 개수 업데이트 주기 충돌 검사
0~5m 1,500 매 프레임 Body + Self
5~20m 500 2프레임마다 Body만
20~50m 100 5프레임마다 없음
50m+ 0 (꺼짐) 애니메이션만 없음

GPU Compute Shader 가속

천 시뮬레이션을 GPU에서 병렬 처리합니다.

// GPU Compute Shader (HLSL 의사코드) // 스레드 그룹: 64개 스레드가 병렬 실행 [numthreads(64, 1, 1)] void ClothSimulationCS(uint3 threadID : SV_DispatchThreadID) { uint particleIndex = threadID.x; if (particleIndex >= particleCount) return; // 읽기 전용 버퍼 ClothParticle particle = particlesIn[particleIndex]; if (!particle.isFixed) { // 1. 중력 적용 particle.velocity += float3(0, -9.8, 0) * deltaTime; // 2. 바람 적용 float3 wind = SampleWindTexture(particle.position); particle.velocity += wind * deltaTime; // 3. 위치 업데이트 particle.position += particle.velocity * deltaTime; // 4. Body Collision float3 capsuleClosest = ClosestPointOnCapsule(particle.position); float dist = distance(particle.position, capsuleClosest); if (dist < capsuleRadius) { float3 normal = normalize(particle.position - capsuleClosest); particle.position = capsuleClosest + normal * capsuleRadius; } } // 쓰기 버퍼에 저장 particlesOut[particleIndex] = particle; } // CPU에서 GPU 호출 function UpdateClothGPU(cloth): // 데이터를 GPU 버퍼로 복사 CopyToGPU(cloth.particles, particlesInBuffer) // Compute Shader 실행 Dispatch(ClothSimulationCS, cloth.particleCount / 64, 1, 1) // 제약 충족 (여러 번 반복) for i in 0 to 5: Dispatch(ConstraintSolverCS, constraintCount / 64, 1, 1) // 결과를 CPU로 복사 CopyFromGPU(particlesOutBuffer, cloth.particles)

실제 게임 예시

Q: 게임에서 어디서 확인할 수 있어요?

1. 트래퍼 코트 (Trapper Coat)

  • 긴 코트로 가장 많은 정점 (약 2,000개)
  • 말을 타면 코트가 말 몸체와 충돌 처리됨
  • 바람 부는 산 정상에서 크게 펄럭임

2. 판초 (Poncho)

  • 넓은 표면적으로 바람 영향 크게 받음
  • 뛰어다닐 때 팔 움직임에 따라 흔들림
  • 비 올 때 물방울이 천 위에서 흘러내림

3. NPC 긴 드레스

  • Valentine 거리 걸어다니는 여성 NPC
  • 드레스 밑단이 바닥과 충돌 (끌리지 않음)
  • 계단 오를 때 Self-Collision으로 겹치지 않음

💡 핵심 정리

  • Mass-Spring: 기본 모델이지만 수치 불안정 문제
  • PBD (Position Based Dynamics): 위치 직접 보정으로 안정적
  • Wind System: Perlin Noise + 표면적 기반 힘 계산
  • Collision: Body (Capsule) + Self (Spatial Grid)
  • LOD: 거리별 정점 개수 조정 (1,500 → 0)
  • GPU Acceleration: Compute Shader로 병렬 처리

기술적 의의:

단순히 "옷이 펄럭인다"가 아니라, 물리적으로 정확한 천 시뮬레이션으로 플레이어가 환경(바람, 비)과 상호작용하는 느낌을 극대화했습니다. 수천 개 정점을 실시간으로 시뮬레이션하면서도 60fps를 유지하는 것이 핵심입니다.
