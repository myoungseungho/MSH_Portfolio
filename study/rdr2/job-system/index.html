RDR2는 스레드를 몇 개 쓸까?

RAGE 엔진의 Job System 아키텍처

Part 1: 왜 스레드 개수가 궁금해지나?

Q: RDR2는 도대체 어떻게 이렇게 많은 걸 동시에 처리하나요?
Red Dead Redemption 2의 시뮬레이션 규모는 정말 엄청납니다:
  • 1500+ NPC - 각자 일과, 대화, AI 상태 업데이트
  • 200종 동물 - 생태계 시뮬레이션, 먹이사슬
  • 75km² 맵 - 지형 LOD, 스트리밍, 물리 시뮬레이션
  • 동적 날씨 - 구름, 비, 눈, 안개
  • Euphoria 물리 - 래그돌, 천 시뮬레이션
이 모든 걸 단일 스레드로는 절대 불가능합니다.
성능 병목의 핵심:
게임은 초당 30~60프레임을 유지해야 합니다. 60 FPS라면 한 프레임당 16ms밖에 없습니다. 모든 작업을 순차 처리하면 0.1초도 안 걸리는 작업이 없습니다. 병렬 처리는 선택이 아닌 필수입니다.

Part 2: Thread Pool vs Job System (핵심!)

Q: "스레드풀이랑 잡시스템이 같은 거야?"
아니요, 관계가 있지만 다릅니다.

쉬운 비유:
Thread Pool = 택배 기사들 (대기 중인 배달원)
Job System = 물류 센터 (누가 어떤 순서로 배달할지 결정)
Thread Pool Job System
역할 스레드 재사용 작업 스케줄링
관심사 "스레드 관리" "작업 분배"
의존성 없음 있음 (A→B→C)
우선순위 없음 (FIFO) 있음 (중요한 작업 우선)
핵심 차이점:
Thread Pool은 Job System의 구현 수단 중 하나일 뿐입니다. Job System은 "무엇을, 언제, 어떤 순서로 실행할지"를 결정하고, Thread Pool은 "누가 실행할지"를 관리합니다.

Part 3: RDR2의 스레드 구조 (추정)

Q: 그래서 RDR2는 스레드를 몇 개 쓰나요?
정확한 수치는 공개되지 않았지만, RAGE 엔진 분석과 유사 게임들을 참고하면:
  • 고정 스레드: 8~12개 (역할별 전용 스레드)
  • Worker Thread Pool: 논리 코어 수만큼 (6~16개)
  • 총 스레드 개수: PC에서 관측 시 60~100개 생성됨 (실제 활성은 20~30개)
[고정 스레드] ~8-12개 ├─ Main Thread (게임 로직, 싱글스레드 보장) ├─ Render Thread (GPU 명령 큐 생성) ├─ Audio Thread (사운드 믹싱, 스트리밍) ├─ Physics Thread (Euphoria 래그돌) ├─ Animation Thread (Motion Matching, IK) ├─ AI Thread (NPC 행동 트리, 길찾기) ├─ Streaming Thread (맵, 텍스처 로딩) └─ Network Thread (RDO 멀티플레이) [Worker Thread Pool] ~논리코어 수 ├─ Job: 지형 LOD 계산 ├─ Job: Frustum Culling ├─ Job: 파티클 시뮬레이션 ├─ Job: Cloth 시뮬레이션 ├─ Job: 동물 AI 업데이트 ├─ Job: 날씨 계산 └─ ... (수백 개 Job이 큐에 대기)
왜 이렇게 많이?
  • 고정 스레드: 특정 작업 전담 (지연시간 최소화)
  • Worker Pool: 병렬화 가능한 작업 분산
  • 유휴 스레드: 대기 중이거나 동기화 대기

Part 4: 플랫폼별 스레드 사용

플랫폼 CPU 코어 활성 스레드 비고
PS4 8코어 (6개 가용) ~12-16개 OS가 2코어 예약
Xbox One 8코어 (7개 가용) ~12-16개 OS가 1코어 예약
PC (6코어) 6코어 12스레드 ~20-24개 Worker Pool 증가
PC (8코어+) 8코어 16스레드 ~30-40개 최대 병렬화
실제 관측: Windows Task Manager에서 RDR2를 보면 60~100개 스레드가 생성되지만, 실제로 활성 상태(CPU 사용 중)인 스레드는 20~30개 정도입니다. 나머지는 대기 상태거나 동기화 중입니다.

Part 5: Job System의 의존성 관리

Q: Thread Pool로 그냥 작업 던지면 되는 거 아닌가요?
안 됩니다! 작업 간 의존성이 있기 때문입니다. 
// 단순 Thread Pool (의존성 없음)
threadPool.Submit([]{ DoWork(); });

// Job System (의존성 관리)
JobHandle jobA = Schedule(LoadTexture);
JobHandle jobB = Schedule(LoadMesh);
JobHandle jobC = Schedule(CreateObject, DependsOn(jobA, jobB));
//                        ↑ A, B 끝나야 C 실행

// A, B는 병렬 실행 가능
// C는 A, B 완료 후에만 실행
RDR2 실제 예시:
  • NPC AI 순서: NPC 위치 계산 → 애니메이션 선택 → IK 적용 → 렌더링
  • 지형 렌더링: 스트리밍 → LOD 계산 → 컬링 → 렌더 명령 생성
  • 파티클 효과: 시뮬레이션 → 정렬 → 배치 생성 → GPU 제출
각 단계는 이전 단계가 완료되어야 시작할 수 있습니다. 
// RDR2 스타일 Job 의존성 (의사코드)
void UpdateNPC(NPC* npc) {
    JobHandle aiJob = JobSystem::Schedule([=] {
        npc->UpdateBehaviorTree();
        npc->UpdatePathfinding();
    });

    JobHandle animJob = JobSystem::Schedule([=] {
        npc->SelectAnimation();
    }, DependsOn(aiJob));  // AI 완료 후

    JobHandle ikJob = JobSystem::Schedule([=] {
        npc->ApplyIK();
    }, DependsOn(animJob));  // 애니메이션 완료 후

    JobHandle renderJob = JobSystem::Schedule([=] {
        npc->SubmitRenderCommands();
    }, DependsOn(ikJob));  // IK 완료 후
}

// 1500명 NPC는 병렬로 처리되지만,
// 각 NPC 내부의 단계는 순서가 보장됨

Part 6: 왜 6코어 이상에서 성능이 급상승할까?

Q: RDR2는 왜 4코어보다 8코어에서 훨씬 빠른가요?
Job System의 Worker Pool이 코어 수에 비례해서 병렬 작업을 처리하기 때문입니다.
4코어 시스템: Frame 시작 ├─ Worker 1: NPC AI (10ms) ├─ Worker 2: 지형 LOD (10ms) ├─ Worker 3: 파티클 (10ms) └─ Worker 4: 물리 (10ms) ↓ 다음 작업 대기 (큐에 50개 Job 남음) 총 프레임 시간: 40ms (25 FPS) 8코어 시스템: Frame 시작 ├─ Worker 1~8: 8개 작업 동시 실행 (10ms) ↓ ├─ Worker 1~8: 다음 8개 작업 (10ms) 총 프레임 시간: 20ms (50 FPS)
병목점:
Worker 수가 적으면 Job 큐에 작업이 쌓입니다. 8코어는 단순히 "2배 빠른" 게 아니라, 병목이 제거되어 전체 파이프라인이 원활하게 돌아가는 효과입니다.

Part 7: 다른 엔진의 Job System

엔진 Job System 이름 특징
Unity C# Job System Burst Compiler로 컴파일, 안전성 검증
Unreal Task Graph 그래프 기반 의존성, 자동 병렬화
Frostbite Fiber Job System 경량 스레드(Fiber) 사용, 컨텍스트 스위칭 최소화

공통점: 모두 Thread Pool + 의존성 관리 + 우선순위 스케줄링을 포함합니다. 차이는 구현 방식과 최적화 수준입니다.

Part 8: Job System의 핵심 - Work Stealing

Q: 어떤 Worker가 일을 덜 하면 어떻게 하나요?
Work Stealing 알고리즘을 사용합니다. 바쁜 Worker의 작업을 유휴 Worker가 "훔쳐가는" 방식입니다.
Worker 1 큐: [Job A] [Job B] [Job C] [Job D] ← 바쁨 Worker 2 큐: [Job E] ← 한가함 Worker 3 큐: [] ← 완전 유휴 Work Stealing 발동: Worker 3이 Worker 1의 큐 뒤쪽에서 Job D를 훔침 Worker 1 큐: [Job A] [Job B] [Job C] Worker 3 큐: [Job D] 결과: 작업 부하 균등화 
// Work Stealing 의사코드
class Worker {
    Deque localQueue;  // 양방향 큐

    void Run() {
        while (running) {
            Job job = localQueue.PopFront();  // 자기 작업 먼저

            if (job == null) {
                // 할 일이 없으면 다른 Worker 훔치기
                job = StealFromOtherWorker();
            }

            if (job != null) {
                job.Execute();
            }
        }
    }

    Job StealFromOtherWorker() {
        for (Worker other : allWorkers) {
            if (other != this) {
                Job stolen = other.localQueue.PopBack();  // 뒤에서 훔침
                if (stolen != null) return stolen;
            }
        }
        return null;
    }
}

핵심 요약

  1. Job System ≠ Thread Pool: Job System = Thread Pool + 의존성 + 스케줄링
  2. RDR2 스레드 구성: 고정 스레드 8-12개 + Worker Pool (코어 수)
  3. 의존성 관리: A→B→C 순서 보장하면서 병렬 처리
  4. Work Stealing: 유휴 Worker가 바쁜 Worker 작업 훔쳐 부하 균등화
  5. 스레드 개수보다 중요한 것: Job 분배와 의존성 해결 품질

결론: RDR2는 단순히 "스레드 많이 쓰기"가 아니라, Job System으로 작업을 작은 단위로 쪼개고 의존성을 관리하여 병렬화합니다. 6코어 이상에서 성능이 급상승하는 이유는 Worker Pool이 병목을 제거하기 때문입니다.
