NPC가 진짜 하루를 사는 것 같아요

1500+ NPC 일과 시스템 (Daily Routine AI)

Q: 다른 오픈월드 게임과 뭐가 다른가요?
대부분의 오픈월드 게임에서 NPC는 "고정된 위치에 서있는 자판기"입니다. 상점 주인은 24시간 가게에 서있고, 같은 대사만 반복합니다. 하지만 RDR2의 NPC는 자기만의 삶을 삽니다. 아침에 일어나고, 일하고, 밥 먹고, 술집 가고, 잠듭니다.

Part 1: 기존 오픈월드 NPC의 문제

Q: 기존 방식이 왜 문제인가요?
전형적인 오픈월드 NPC (Skyrim, GTA 5 이전):
  • 상점 주인은 항상 가게에 있음 (밤에도, 주말에도)
  • 대화 옵션 3개 반복 ("어서오세요", "뭘 찾으세요?", "안녕히가세요")
  • 플레이어가 시야에서 사라지면 "꺼짐" (Despawn)
  • 다음에 다시 와도 기억 못함
이런 NPC는 "배경 장식"일 뿐, 살아있는 사람이 아닙니다.
기존 방식 vs RDR2 [기존 오픈월드] Valentine 대장장이 ↓ ┌──────────────┐ │ 08:00 - 22:00│ → "일하는 중" 상태 │ 가게에 서있음│ 대사 3개 반복 └──────────────┘ ↓ 22:00 이후? → Despawn (사라짐) 플레이어 기억? → 없음 [RDR2] Valentine 대장간 주인 (이름: Hermann) ↓ 06:00 ────> 침대에서 일어남 (집 2층) 06:30 ────> 세면, 아침식사 07:00 ────> 가게로 걸어감 (2분 거리) 07:30-12:00 > 일 (말굽 수리, 망치질 애니메이션) 12:00 ────> 점심 (뒤편 식탁) 13:00-18:00 > 일 재개 18:30 ────> 술집으로 이동 19:00-21:00 > 맥주 2잔, 다른 NPC와 대화 21:30 ────> 집으로 귀가 22:00 ────> 취침 + 플레이어가 3일 전 말 수리 맡김 → 기억하고 언급

Part 2: 24시간 스케줄 시스템

Q: 각 NPC마다 스케줄을 어떻게 만드나요?
RDR2의 각 NPC는 Schedule Table을 가집니다. 시간대별로 "어디서, 무엇을" 해야 하는지 정의된 테이블입니다. 
// 의사코드: NPC 스케줄 데이터 구조
class NPCSchedule {
    string npcName;
    List dailySchedule;

    struct ScheduleEntry {
        TimeRange time;           // 06:00 - 07:00
        Location location;        // Valentine_Blacksmith_Interior
        Activity activity;        // "Working_Hammer"
        Animation[] animations;   // [Hammer_Swing, Wipe_Sweat, Check_Horseshoe]
        Behavior behavior;        // Behavior Tree 참조
        float priority;           // 우선순위 (긴급 상황 시 중단 가능 여부)
    };
}

// 실제 예: Valentine 대장장이
NPCSchedule hermann = new NPCSchedule {
    npcName = "Hermann_Blacksmith",
    dailySchedule = {
        // 아침
        { time: (06:00, 06:30), location: "Hermann_House_Bedroom",
          activity: "Sleeping", animations: ["Sleep_WakeUp", "Stretch"],
          behavior: BT_WakeUp, priority: 1.0 },

        { time: (06:30, 07:00), location: "Hermann_House_Kitchen",
          activity: "Eating", animations: ["Eat_Bread", "Drink_Coffee"],
          behavior: BT_Breakfast, priority: 0.8 },

        // 출근
        { time: (07:00, 07:30), location: "Path_House_To_Shop",
          activity: "Walking", animations: ["Walk_Casual"],
          behavior: BT_Commute, priority: 0.5 },

        // 근무 시간
        { time: (07:30, 12:00), location: "Blacksmith_Workbench",
          activity: "Working", animations: ["Hammer_Swing", "Heat_Metal", "Quench"],
          behavior: BT_Blacksmith_Work, priority: 0.3 },

        // 점심
        { time: (12:00, 13:00), location: "Blacksmith_BackRoom",
          activity: "Eating", animations: ["Eat_Stew", "Drink_Water"],
          behavior: BT_Lunch, priority: 0.7 },

        // 오후 근무
        { time: (13:00, 18:00), location: "Blacksmith_Workbench",
          activity: "Working", animations: ["Hammer_Swing", "Repair_Horseshoe"],
          behavior: BT_Blacksmith_Work, priority: 0.3 },

        // 저녁 (술집)
        { time: (18:30, 21:00), location: "Saloon_Interior",
          activity: "Socializing", animations: ["Drink_Beer", "Talk", "Laugh"],
          behavior: BT_Socialize, priority: 0.4 },

        // 귀가
        { time: (21:00, 21:30), location: "Path_Shop_To_House",
          activity: "Walking", animations: ["Walk_Tired"],
          behavior: BT_Commute, priority: 0.6 },

        // 취침
        { time: (21:30, 06:00), location: "Hermann_House_Bedroom",
          activity: "Sleeping", animations: ["Sleep_Snore"],
          behavior: BT_Sleep, priority: 1.0 }
    }
};

Part 3: 행동 트리 (Behavior Tree)

Q: 단순히 애니메이션만 재생하나요?
아니요. 각 활동은 Behavior Tree로 구현됩니다. 상황에 따라 유연하게 반응합니다. 예: 대장간 일하는 중 플레이어가 말을 끌고 오면 → 일 중단 → 플레이어에게 다가감
Behavior Tree 예시: "대장간 일하기" [ROOT] │ ┌───────┴───────┐ │ Selector │ (우선순위 순서대로 시도) └───────┬───────┘ │ ┌──────────┼──────────┬──────────┐ │ │ │ │ ▼ ▼ ▼ ▼ [고객 응대] [긴급] [일반 작업] [휴식] Priority 1 Priority 2 Priority 3 Priority 4 │ ├─ Condition: 고객이 5m 이내? │ └─ YES → Sequence │ ├─ 망치 내려놓기 │ ├─ 고객에게 다가가기 │ ├─ 인사 ("어서오시오") │ └─ 대화 트리 시작 │ └─ NO → 다음 노드 시도 [일반 작업] │ └─ Sequence ├─ 재료 확인 (말굽 있는지) ├─ 화로에 가열 (5초) ├─ 모루로 이동 ├─ 망치질 (랜덤 3~7회) ├─ 물에 담그기 └─ 완성품 선반에 놓기 
// 의사코드: Behavior Tree 실행
class BehaviorTree_Blacksmith_Work {
    NPC owner;
    GameObject currentWorkpiece;

    BehaviorNode root = new SelectorNode([
        new CustomerService(),     // Priority 1
        new EmergencyResponse(),   // Priority 2
        new RegularWork(),         // Priority 3
        new IdleRest()             // Priority 4
    ]);

    void Update() {
        root.Tick(owner);
    }
}

// 노드 1: 고객 응대
class CustomerService : SequenceNode {
    bool CheckCondition(NPC owner) {
        // 5m 이내에 플레이어나 말이 있는지
        return FindNearbyPlayer(owner.position, 5.0f) != null;
    }

    void Execute(NPC owner) {
        Player player = FindNearbyPlayer(owner.position, 5.0f);

        // 1. 도구 내려놓기
        owner.PlayAnimation("Put_Down_Hammer");
        owner.currentTool = null;

        // 2. 플레이어에게 다가가기
        owner.WalkTo(player.position, 2.0f);

        // 3. 인사
        if (owner.HasMetBefore(player)) {
            owner.Speak("또 오셨군요! 말이 또 문제라도?");
        } else {
            owner.Speak("어서 오시오. 뭘 도와드릴까요?");
        }

        // 4. 대화 시스템으로 전환
        owner.EnterDialogueMode(player);
    }
}

// 노드 3: 일반 작업
class RegularWork : SequenceNode {
    void Execute(NPC owner) {
        // 1. 작업물 선택 (70% 말굽, 20% 도구, 10% 무기)
        string workType = RandomWeighted(["Horseshoe", "Tool", "Weapon"], [0.7, 0.2, 0.1]);

        // 2. 재료 가져오기
        owner.WalkTo("Blacksmith_MaterialShelf");
        GameObject material = owner.PickUp(workType + "_Raw");

        // 3. 화로에 가열
        owner.WalkTo("Blacksmith_Furnace");
        owner.PlayAnimation("Heat_Metal", duration: 5.0f);

        // 4. 모루로 이동
        owner.WalkTo("Blacksmith_Anvil");

        // 5. 망치질 (랜덤 횟수)
        int hammerCount = Random.Range(3, 7);
        for (int i = 0; i < hammerCount; i++) {
            owner.PlayAnimation("Hammer_Swing");
            PlaySound("Metal_Clang");
            Wait(0.8f);

            // 가끔 땀 닦기
            if (Random.value < 0.2f) {
                owner.PlayAnimation("Wipe_Sweat");
            }
        }

        // 6. 담금질
        owner.WalkTo("Blacksmith_WaterBucket");
        owner.PlayAnimation("Quench_Metal");
        PlaySound("Steam_Hiss");

        // 7. 완성품 보관
        owner.WalkTo("Blacksmith_FinishedShelf");
        owner.PlaceItem(material.transformed);

        // 8. 만족스러운 표정 (가끔)
        if (Random.value < 0.3f) {
            owner.PlayAnimation("Nod_Satisfied");
        }
    }
}

Part 4: 기억 시스템 (Memory System)

Q: NPC가 플레이어를 어떻게 기억하나요?
각 NPC는 Memory Database를 가집니다. 플레이어의 행동, 대화, 범죄 등을 기록하고, 다음 만남에 반영합니다.
기억되는 것들:
  • 만남 기록: 언제, 어디서 만났는지
  • 거래 내역: 뭘 샀는지, 말을 맡겼는지
  • 대화 내용: 무슨 얘기 나눴는지
  • 플레이어 행동: 친절했는지, 위협했는지, 총 쐈는지
  • 평판: 호감도 (-100 ~ +100)
// 의사코드: NPC 기억 시스템
class NPCMemory {
    struct MemoryEntry {
        DateTime timestamp;
        MemoryType type;
        object data;
        float emotionalImpact;  // -10 (매우 부정) ~ +10 (매우 긍정)
    };

    List memories;
    float overallReputation = 0.0f;  // 종합 평판

    void RecordInteraction(Player player, InteractionType type, object data) {
        MemoryEntry memory = new MemoryEntry {
            timestamp = GameWorld.CurrentTime,
            type = type,
            data = data,
            emotionalImpact = CalculateImpact(type, data)
        };

        memories.Add(memory);

        // 평판 업데이트
        overallReputation += memory.emotionalImpact;
        overallReputation = Clamp(overallReputation, -100, 100);

        // 오래된 기억은 희미해짐 (30일 이상 → 50% 감소)
        DecayOldMemories();
    }

    string GetGreeting(Player player) {
        // 최근 기억 우선 검색
        MemoryEntry recent = GetMostRecentMemory(player, days: 7);

        if (recent == null) {
            return "어서 오시오."; // 첫 만남
        }

        // 평판에 따라 인사 변경
        if (overallReputation > 50) {
            return "아, 친구! 또 뵙게 되어 반갑소!";
        }
        else if (overallReputation > 10) {
            return "다시 오셨군요. 환영합니다.";
        }
        else if (overallReputation > -10) {
            return "어서 오시오."; // 중립
        }
        else if (overallReputation > -50) {
            return "또 왔군요..."; // 약간 불편
        }
        else {
            return "당신을 여기서 보고 싶지 않소."; // 매우 부정적
        }
    }

    bool RemembersPastEvent(MemoryType type, int daysAgo) {
        MemoryEntry memory = memories.Find(m =>
            m.type == type &&
            (GameWorld.CurrentTime - m.timestamp).Days <= daysAgo
        );

        return memory != null;
    }
}

// 실제 사용 예
void OnPlayerApproach(Player player) {
    if (memory.RemembersPastEvent(MemoryType.HorseRepair, daysAgo: 3)) {
        Speak("말은 잘 달리고 있소? 지난번에 굽을 고쳐드렸는데.");
    }

    if (memory.RemembersPastEvent(MemoryType.Threatened, daysAgo: 7)) {
        Speak("저번에 총 겨누던 건 잊지 않았소...");
        CallSheriff(); // 보안관 호출
    }

    if (memory.overallReputation > 70) {
        Speak("당신은 좋은 사람이오. 특별히 10% 할인해드리지.");
    }
}

Part 5: 최적화 전략

Q: 1500명의 NPC를 동시에 시뮬레이션하면 느려지지 않나요?
매우 느려집니다. 그래서 RDR2는 시뮬레이션 범위와 LOD (Level of Detail)를 사용합니다.
NPC 시뮬레이션 LOD 플레이어로부터 거리: 0-50m (High Detail) │ ├─ Full Behavior Tree (매 프레임) ├─ 기억 시스템 활성 ├─ 동적 대화 생성 └─ 세밀한 애니메이션 ↓ 50-150m (Medium Detail) │ ├─ 단순 Behavior Tree (1초당 1회) ├─ 기억 시스템 비활성 ├─ 고정 애니메이션 루프 └─ 대화 불가 ↓ 150-500m (Low Detail) │ ├─ 스케줄만 실행 (10초당 1회) ├─ "텔레포트" 이동 (걷기 생략) ├─ 애니메이션 1개만 └─ 상호작용 불가 ↓ 500m+ (Simulation Only) │ ├─ 위치만 업데이트 (1분당 1회) ├─ 렌더링 안 함 └─ 플레이어가 가까이 오면 "스폰" ↓ 다른 도시/지역 (Paused) │ └─ 시뮬레이션 중단 플레이어가 도시 진입 시 "이어서 재생" 
// 의사코드: NPC LOD 시스템
class NPCManager {
    List allNPCs;
    Vector3 playerPosition;

    void Update(float deltaTime) {
        playerPosition = Player.Instance.position;

        for (NPC npc : allNPCs) {
            float distance = Distance(npc.position, playerPosition);

            // LOD 0: 매우 가까움 (0-50m)
            if (distance < 50.0f) {
                UpdateHighDetail(npc, deltaTime);
            }

            // LOD 1: 중간 (50-150m)
            else if (distance < 150.0f) {
                if (frameCount % 60 == 0) {  // 1초당 1회
                    UpdateMediumDetail(npc, deltaTime * 60);
                }
            }

            // LOD 2: 먼 거리 (150-500m)
            else if (distance < 500.0f) {
                if (frameCount % 600 == 0) {  // 10초당 1회
                    UpdateLowDetail(npc, deltaTime * 600);
                }
            }

            // LOD 3: 매우 멀거나 다른 지역
            else {
                if (frameCount % 3600 == 0) {  // 1분당 1회
                    UpdateSimulationOnly(npc);
                }
            }
        }
    }

    void UpdateHighDetail(NPC npc, float deltaTime) {
        // 1. Behavior Tree 전체 실행
        npc.behaviorTree.Tick(deltaTime);

        // 2. 기억 시스템 활성
        npc.memory.Update(deltaTime);

        // 3. 동적 대화 준비
        if (npc.CanSeePlayer()) {
            npc.PrepareDynamicDialogue();
        }

        // 4. 물리, 애니메이션, IK
        npc.UpdatePhysics(deltaTime);
        npc.UpdateAnimation(deltaTime);
        npc.UpdateIK(deltaTime);  // 발이 지형에 맞게
    }

    void UpdateMediumDetail(NPC npc, float deltaTime) {
        // 1. 단순 BT만 (고객 응대 등 생략)
        npc.ExecuteScheduledActivity();

        // 2. 애니메이션 루프
        npc.PlayLoopAnimation();

        // 3. 물리는 간소화
        npc.SimpleMove(deltaTime);
    }

    void UpdateLowDetail(NPC npc, float deltaTime) {
        // 1. 스케줄에 따라 위치만 업데이트
        ScheduleEntry current = npc.GetCurrentSchedule();

        // 걷기 생략 → 즉시 텔레포트
        if (npc.location != current.location) {
            npc.position = current.location.GetRandomPosition();
            npc.location = current.location;
        }

        // 2. 애니메이션 1개만
        npc.SetStaticAnimation(current.activity);
    }

    void UpdateSimulationOnly(NPC npc) {
        // 렌더링 안 함, 위치만 시뮬레이션
        ScheduleEntry current = npc.GetCurrentSchedule();
        npc.logicalLocation = current.location;

        // 플레이어가 가까이 오면 실제 스폰
        if (Distance(npc.logicalLocation, playerPosition) < 500.0f) {
            SpawnNPC(npc);
        }
    }
}

Part 6: 실제 사례 - Valentine 대장장이의 하루

Q: 실제 게임에서 어떻게 보이나요?
Valentine의 대장장이 Hermann을 예로 들면:
Hermann의 하루 (플레이어 관점):
  • 07:00: 플레이어가 Valentine 도착 → 가게로 걸어가는 Hermann 목격 (출근 중)
  • 09:00: 가게 방문 → 망치질하며 일하는 중 → 플레이어 보고 반갑게 인사
  • 12:30: 가게 방문 → "점심시간이오, 잠시 후에 와주시오" → 뒤편에서 식사 중
  • 14:00: 말 수리 맡김 → "1시간 후에 오시오" → 기억에 기록
  • 15:00: 돌아옴 → "아, 딱 맞춰 오셨군요! 말굽 새로 달았소" → 거래 완료
  • 19:00: 술집에서 재회 → "어이, 친구! 한잔 하시오" → 맥주 권유
  • 3일 후 09:00: 다시 방문 → "말은 잘 달리고 있소? 혹시 또 문제라도?" → 과거 기억

핵심 요약

  1. 24시간 스케줄: 각 NPC는 시간대별 활동 테이블 보유
  2. Behavior Tree: 상황에 따라 유연하게 반응 (고객 응대, 긴급 상황 등)
  3. 기억 시스템: 플레이어 행동 기록 → 평판 → 동적 대화 생성
  4. LOD 최적화: 거리별로 시뮬레이션 상세도 조절 (High/Medium/Low/Simulation-only)
  5. 몰입감: NPC가 "배경"이 아닌 "살아있는 사람"처럼 느껴짐

게임 내 체험: Valentine에서 며칠 동안 체류하면서 같은 NPC를 관찰하면, 그들이 실제로 삶을 살고 있다는 느낌을 받습니다. 아침마다 같은 시간에 가게를 여는 대장장이, 저녁마다 술집에 오는 단골손님, 일요일마다 교회 가는 주민들...

기술적 의의: 1500명 이상의 NPC가 각자의 일과를 가지면서도 60fps를 유지하는 것은 LOD 시스템의 승리입니다. 플레이어는 "살아있는 세계"를 경험하지만, 실제로는 가까운 50명만 풀로 시뮬레이션됩니다.
