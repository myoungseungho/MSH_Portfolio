말 볼알이 왜 줄어들어요?

온도에 따른 동물 신체 변화 시스템

Q: 진짜요? 게임에서 그런 디테일까지 구현했나요?
네, 정말입니다. Red Dead Redemption 2에서 말의 고환은 주변 온도에 따라 실제로 크기가 변합니다. 추운 지역(예: Grizzlies 산맥)에서는 수축하고, 따뜻한 지역(예: Lemoyne 늪지대)에서는 이완됩니다. 이것은 Rockstar의 극단적인 디테일에 대한 집착을 보여주는 대표적인 사례입니다.

Part 1: 왜 이런 디테일을?

Q: 이게 게임플레이에 무슨 영향을 주나요?
직접적인 게임플레이 영향은 전혀 없습니다. 플레이어 대부분은 이런 디테일을 눈치채지도 못합니다. 하지만 Rockstar의 철학은 "플레이어가 의식하지 못하더라도, 세계는 살아있어야 한다"입니다.
Rockstar의 디자인 철학:
  • 몰입감은 눈에 보이지 않는 디테일의 합
  • 세계관 일관성 = 모든 요소가 현실적 규칙을 따름
  • 플레이어는 의식하지 못해도 무의식적으로 느낌

Part 2: 온도 시스템 기초

환경 요소 → 온도 계산 → 신체 반응 ┌─────────────┐ │ 시간대 │ 낮 12시: +10°C │ (Hour) │ 밤 2시: -5°C └──────┬──────┘ │ ▼ ┌─────────────┐ │ 지역 │ Grizzlies: -15°C │ (Region) │ New Hanover: 0°C │ │ Lemoyne: +20°C └──────┬──────┘ │ ▼ ┌─────────────┐ │ 날씨 │ 맑음: 0°C │ (Weather) │ 비: -5°C │ │ 눈: -10°C └──────┬──────┘ │ ▼ ┌─────────────┐ │ 최종 온도 │ = Base + TimeModifier + WeatherModifier └──────┬──────┘ │ ▼ ┌─────────────┐ │ 신체 반응 │ < 0°C: 수축 (0.7x) │ │ 0-20°C: 보통 (1.0x) │ │ > 20°C: 이완 (1.3x) └─────────────┘
Q: 온도는 어떻게 계산하나요?
온도는 시간대, 지역, 날씨 세 가지 요소의 합입니다. 각 지역마다 기본 온도가 설정되어 있고, 시간과 날씨가 이를 수정합니다. 
// 의사코드: 온도 계산
class TemperatureSystem {
    float CalculateTemperature(Region region, TimeOfDay time, Weather weather) {
        // 1. 지역 기본 온도
        float baseTemp = region.baseTemperature;

        // 2. 시간대 보정 (낮 +10, 밤 -10)
        float timeModifier = sin((time.hour - 6) * PI / 12) * 20.0f;

        // 3. 날씨 보정
        float weatherModifier = 0.0f;
        if (weather == Weather.Rain) weatherModifier = -5.0f;
        if (weather == Weather.Snow) weatherModifier = -15.0f;
        if (weather == Weather.Fog) weatherModifier = -3.0f;

        // 4. 고도 보정 (100m당 -0.6°C)
        float altitudeModifier = -region.altitude * 0.006f;

        return baseTemp + timeModifier + weatherModifier + altitudeModifier;
    }
}

// 실제 사용 예
Region grizzlies = { baseTemperature: -15.0f, altitude: 2000.0f };
TimeOfDay midnight = { hour: 0 };
Weather snow = Weather.Snow;

float temp = CalculateTemperature(grizzlies, midnight, snow);
// 결과: -15 + (-10) + (-15) + (-12) = -52°C

Part 3: 신체 반응 시스템 (Morph Target)

Q: 크기가 변하는 건 어떻게 구현하나요?
3D 모델의 Morph Target (또는 Blend Shape) 기술을 사용합니다. 기본 메쉬와 변형된 메쉬 두 개를 준비하고, 온도에 따라 두 형태 사이를 보간합니다.
Morph Target 시스템 기본 메쉬 (1.0x) 축소 메쉬 (0.7x) ●●● ●● ● ● ● ● ● ● ● ● ● ● ●●● ●● ↓ 온도에 따라 보간 ↓ BlendWeight = (Temperature - MinTemp) / (MaxTemp - MinTemp) FinalVertex = Lerp(ShrunkVertex, BaseVertex, BlendWeight) 실제 예: 온도 -10°C → BlendWeight = 0.0 → 완전 수축 온도 5°C → BlendWeight = 0.5 → 중간 온도 20°C → BlendWeight = 1.0 → 완전 이완 
// 의사코드: Morph Target 적용
class HorseTestes {
    Mesh baseMesh;           // 정상 크기 메쉬
    Mesh contractedMesh;     // 수축 메쉬
    float minTemp = -10.0f;  // 완전 수축 온도
    float maxTemp = 20.0f;   // 완전 이완 온도

    void UpdateMorphTarget(float currentTemp) {
        // 1. 온도를 0~1 범위로 정규화
        float normalizedTemp = Clamp((currentTemp - minTemp) / (maxTemp - minTemp), 0, 1);

        // 2. 부드러운 전환을 위한 Smoothstep
        float blendWeight = Smoothstep(0, 1, normalizedTemp);

        // 3. 각 정점 보간
        for (int i = 0; i < vertexCount; i++) {
            Vector3 contractedPos = contractedMesh.vertices[i];
            Vector3 basePos = baseMesh.vertices[i];

            // Lerp: Linear Interpolation
            finalMesh.vertices[i] = Lerp(contractedPos, basePos, blendWeight);
        }

        // 4. 노멀 벡터도 재계산
        finalMesh.RecalculateNormals();
    }
}

// Smoothstep 함수 (부드러운 곡선)
float Smoothstep(float edge0, float edge1, float x) {
    float t = Clamp((x - edge0) / (edge1 - edge0), 0, 1);
    return t * t * (3.0f - 2.0f * t);
}

Part 4: 말 외의 동물들

Q: 다른 동물들도 온도에 반응하나요?
네! 말뿐만 아니라 다양한 동물들이 온도 시스템과 연동됩니다:
  • 곰: 겨울철 털 밀도 증가 (셰이더 파라미터 조정)
  • 새: 추울 때 깃털 부풀림 (파티클 스케일 증가)
  • 개: 더울 때 헐떡임 애니메이션 재생 빈도 증가
  • 사슴: 겨울철 뿔 색상 변화
온도 반응 카테고리:
  1. 기하학적 변형: Morph Target (고환, 귀)
  2. 재질 변경: 셰이더 파라미터 (털 밀도, 색상)
  3. 행동 변경: 애니메이션 블렌딩 (떨림, 헐떡임)
  4. 파티클 효과: 입김, 땀
// 의사코드: 동물별 온도 반응
class AnimalTemperatureResponse {
    void ApplyTemperatureEffects(Animal animal, float temperature) {
        if (animal.type == AnimalType.Horse) {
            // 말: 고환 크기 조정
            animal.testes.UpdateMorphTarget(temperature);

            // 추가: 입김 파티클
            if (temperature < 5.0f) {
                animal.breathParticles.SetActive(true);
                animal.breathParticles.rate = (5.0f - temperature) * 2.0f;
            }
        }

        else if (animal.type == AnimalType.Bear) {
            // 곰: 털 밀도 조정 (셰이더)
            float furDensity = Lerp(0.8f, 1.5f, (10.0f - temperature) / 20.0f);
            animal.furShader.SetFloat("_Density", furDensity);
            animal.furShader.SetFloat("_Length", furDensity * 1.2f);
        }

        else if (animal.type == AnimalType.Bird) {
            // 새: 깃털 부풀림
            if (temperature < 10.0f) {
                float puffScale = 1.0f + (10.0f - temperature) * 0.05f;
                animal.featherParticles.SetScale(puffScale);
            }
        }

        else if (animal.type == AnimalType.Dog) {
            // 개: 헐떡임 빈도
            if (temperature > 25.0f) {
                float pantingSpeed = 1.0f + (temperature - 25.0f) * 0.1f;
                animal.PlayAnimation("Panting", pantingSpeed);
            }
        }
    }
}

Part 5: 최적화 전략

Q: 모든 동물을 매 프레임 체크하면 느려지지 않나요?
당연히 느려집니다. 그래서 LOD (Level of Detail)와 업데이트 빈도 조절을 사용합니다.
LOD 기반 업데이트 전략 거리 업데이트 빈도 적용 효과 ─────────────────────────────────────────── 0-10m 매 프레임 전체 (Morph + 셰이더 + 파티클) (60 FPS) │ ▼ 10-30m 2프레임당 1회 Morph + 셰이더만 (30 FPS) (파티클 생략) │ ▼ 30-100m 10프레임당 1회 셰이더만 (6 FPS) (Morph 생략) │ ▼ 100m+ 업데이트 안 함 기본 상태 유지 
// 의사코드: LOD 기반 업데이트
class AnimalTemperatureManager {
    List animals;
    float updateTimer = 0.0f;

    void Update(float deltaTime) {
        updateTimer += deltaTime;

        Vector3 cameraPos = Camera.main.position;

        for (Animal animal : animals) {
            float distance = Distance(animal.position, cameraPos);

            // LOD 0: 매우 가까움 (0-10m)
            if (distance < 10.0f) {
                UpdateFullDetail(animal);
            }

            // LOD 1: 중간 거리 (10-30m)
            else if (distance < 30.0f && updateTimer > 0.033f) { // 30 FPS
                UpdateMediumDetail(animal);
            }

            // LOD 2: 먼 거리 (30-100m)
            else if (distance < 100.0f && updateTimer > 0.166f) { // 6 FPS
                UpdateLowDetail(animal);
            }

            // LOD 3: 매우 멀거나 화면 밖
            // → 업데이트 안 함
        }

        // 타이머 리셋 (1초마다)
        if (updateTimer > 1.0f) updateTimer = 0.0f;
    }

    void UpdateFullDetail(Animal animal) {
        float temp = GetTemperature(animal.position);
        animal.UpdateMorphTargets(temp);      // Morph Target
        animal.UpdateShaderParams(temp);      // 셰이더
        animal.UpdateParticles(temp);         // 파티클
    }

    void UpdateMediumDetail(Animal animal) {
        float temp = GetTemperature(animal.position);
        animal.UpdateMorphTargets(temp);
        animal.UpdateShaderParams(temp);
        // 파티클 생략
    }

    void UpdateLowDetail(Animal animal) {
        float temp = GetTemperature(animal.position);
        animal.UpdateShaderParams(temp);
        // Morph Target, 파티클 생략
    }
}

Part 6: 왜 이게 중요한가?

Q: 이런 디테일이 정말 게임을 더 좋게 만드나요?
플레이어는 말의 고환 크기 변화를 의식적으로 인지하지 못합니다. 하지만 이런 수백 가지의 "눈에 보이지 않는 디테일"이 합쳐져서 RDR2의 압도적인 몰입감을 만듭니다.
몰입감의 공식:
  • 의식적 디테일: 플레이어가 "와, 이것 봐!" 하는 요소 (20%)
  • 무의식적 디테일: 플레이어가 모르지만 느끼는 요소 (80%)
말의 고환, NPC의 눈동자 추적, 풀잎의 바람 반응 등은 모두 후자입니다. 각각은 작지만, 합쳐지면 "이 세계는 진짜다"라는 느낌을 만듭니다.

핵심 요약

  1. 온도 시스템: 지역 + 시간 + 날씨 → 실시간 온도 계산
  2. 신체 반응: Morph Target으로 기하학적 변형 (고환, 귀 등)
  3. 다층적 효과: 기하 변형 + 셰이더 + 애니메이션 + 파티클
  4. LOD 최적화: 거리별로 업데이트 빈도와 디테일 조절
  5. 디자인 철학: 플레이어가 모르더라도, 세계는 일관된 규칙으로 작동

결론: 말의 고환은 그 자체로는 사소하지만, Rockstar의 "세계관 일관성"에 대한 집착을 보여주는 상징입니다. 이런 디테일이 수백 개 쌓여서 게임 역사상 가장 살아있는 오픈월드를 만들었습니다.
