변경된 것만 UPDATE, 불필요한 쓰기 막기

Dirty Checking 패턴 - 똑같은 값 UPDATE하지 마세요

Part 1. 똑같은 값 UPDATE하면 어때?

캐릭터 저장할 때 모든 컬럼을 다 UPDATE하면 안 돼?

기술적으로는 가능해. 근데 낭비야.

-- 단순 무식한 방법 UPDATE TCharacter SET level = @level, -- 변경됨 exp = @exp, -- 변경됨 gold = @gold, -- 변경 안 됨 (같은 값) hp = @hp, -- 변경 안 됨 mp = @mp, -- 변경 안 됨 mapIndex = @mapIndex, -- 변경 안 됨 posX = @posX, -- 변경 안 됨 posY = @posY -- 변경 안 됨 WHERE charunique = @uid
2개만 바뀌었는데 8개를 다 UPDATE 하네?

맞아. 근데 DB는 "같은 값이어도 쓰기 작업을 수행해".

수행되는 작업 같은 값이어도?
데이터 페이지 수정 수행됨
트랜잭션 로그 기록 수행됨
인덱스 업데이트 수행됨 (해당 컬럼에 인덱스 있으면)
잠금 획득 수행됨

같은 값 UPDATE = 아무것도 안 하면서 비용만 발생

Part 2. Dirty Checking이 뭐야?

그래서 Dirty Checking이 뭔데?

"변경된(Dirty) 데이터만 찾아서(Checking) 저장하는 것"

ORM(JPA 등)에서 자주 쓰는 용어야.

[Dirty Checking 개념] 원본 데이터: level=10, exp=500, gold=1000, hp=100 현재 데이터: level=11, exp=0, gold=1000, hp=100 ↑ ↑ 변경됨 변경됨 Dirty(변경된) 컬럼: level, exp Clean(그대로인) 컬럼: gold, hp → level과 exp만 UPDATE!
SQL에서는 어떻게 구현해?

WHERE 절에 변경 여부 조건을 추가하는 방식이야.

Part 3. SQL에서 Dirty Checking 구현

어떻게 "변경됐는지" 확인해?

두 가지 방법이 있어:

방법 1: WHERE 절에 OR 조건

UPDATE TCharacter SET level = @level, exp = @exp, gold = @gold, mapIndex = @mapIndex WHERE charunique = @uid AND ( level <> @level OR exp <> @exp OR gold <> @gold OR mapIndex <> @mapIndex )

이렇게 하면 하나라도 다른 게 있을 때만 UPDATE 실행.

모든 값이 같으면 @@ROWCOUNT = 0.

방법 2: savetime만 갱신 (우리 프로젝트 패턴)

UPDATE TCharacter SET level = @level, exp = @exp, ... savetime = @savetime WHERE charunique = @uid AND ( level <> @level OR exp <> @exp OR ... ) -- 변경 사항이 없으면 savetime만 갱신 IF @@ROWCOUNT = 0 BEGIN UPDATE TCharacter SET savetime = @savetime WHERE charunique = @uid END

Part 4. 우리 프로젝트 실제 코드

실제로 어떻게 쓰고 있어?

gp_save_pc에서 이 패턴을 사용해.

실제 코드 - gp_save_pc (Dirty Checking)

UPDATE TCharacter SET channelID = @channelID, mapIndex = @mapIndex, posX = @posX, posY = @posY, level = @level, ... savetime = @save_servertime WHERE charunique = @vCharUnique AND ( channelID <> @channelID OR mapIndex <> @mapIndex OR posX <> @posX OR posY <> @posY OR level <> @level OR ... ) -- 데이터 변경 없으면 savetime만 갱신 IF @@ROWCOUNT = 0 BEGIN UPDATE TCharacter SET savetime = @save_servertime WHERE charunique = @vCharUnique END

이 패턴의 장점:

• 변경 없으면 대부분의 컬럼 UPDATE 안 함

• savetime은 항상 갱신 (마지막 저장 시간 추적용)

• 트랜잭션 로그 최소화

Part 5. 얼마나 효과가 있어?

진짜 차이가 나?

게임 서버에서는 주기적 자동 저장이 있잖아.

[자동 저장 시나리오: 60초마다 저장] 유저가 1분 동안 한 것: - 레벨업: 1회 - 이동: 수십 회 (최종 위치만 중요) - 전투: 수백 회 (HP/MP 변동) 60초 후 저장 시점: - 실제 변경된 컬럼: 5~10개 - 전체 컬럼: 50개 이상 Dirty Checking 없이: 50개 컬럼 전부 UPDATE Dirty Checking 있으면: 5~10개만 UPDATE

예상 성능 개선 (동접 1000명 기준)

전체 UPDATE
100%
Dirty Checking
~30%

효과가 큰 상황:

• 자동 저장 주기가 짧을 때 (30초, 60초)

• AFK(자리비움) 유저가 많을 때

• 컬럼 수가 많은 테이블

Part 6. 주의사항

Dirty Checking 쓸 때 조심할 거 있어?

몇 가지 있어:

주의사항 설명
NULL 처리 NULL <> 값은 항상 FALSE. ISNULL() 사용 필요
OR 조건 성능 OR가 많으면 인덱스 활용 어려움
@@ROWCOUNT 체크 0이면 변경 없음 vs 레코드 없음 구분 필요
-- NULL 처리 예시 WHERE charunique = @uid AND ( ISNULL(guild, 0) <> ISNULL(@guild, 0) OR ISNULL(party, 0) <> ISNULL(@party, 0) )

핵심 정리

  • Dirty Checking = 변경된 데이터만 찾아서 저장
  • 같은 값 UPDATE도 비용 발생 (로그, 잠금, 인덱스)
  • 구현: WHERE 절에 OR 조건으로 변경 여부 체크
  • 우리 프로젝트: gp_save_pc에서 이 패턴 사용 중
  • 효과: 자동 저장 시 UPDATE 부하 대폭 감소
  • 주의: NULL 처리, OR 조건 성능
