GPU에 텍스처 올릴 때 CPU는 왜 놀고 있을까? — DMA부터 DirectStorage까지

디스크 → RAM → GPU VRAM, 그 바이트는 누가 옮기나 — DMA·PCIe·스테이징, 그리고 CPU를 아예 건너뛰는 DirectStorage

30초 요약

텍스처의 최종 목적지는 GPU의 VRAM. 문제는 '디스크 → VRAM'까지 그 바이트를 누가 어떻게 옮기냐.

실제 바이트 이동은 CPU가 아니라 DMA 엔진(하드웨어)이 함. CPU는 '옮겨줘' 명령만 내리고 빠져 — 그래서 '텍스처 올릴 때 CPU가 논다'.

일반 경로는 그래도 CPU RAM을 경유하고 CPU가 압축 해제까지 해서 7GB/s SSD가 2~3GB/s로 병목.

DirectStorage/RTXIO/PS5 SSD = CPU를 아예 우회. SSD→GPU 직행 + GPU가 압축 해제 → SSD 대역폭을 그대로 뽑음.

Part 1. 텍스처는 결국 어디로 가야 하나

텍스처를 '메모리에 올린다'는데, 정확히 어느 메모리야?

GPU가 그림을 그리려면 텍스처가 GPU 전용 메모리(VRAM)에 있어야 해. CPU가 쓰는 시스템 RAM이 아니라, 그래픽카드에 붙은 별도 메모리야.

그런데 파일(텍스처)은 디스크에 있지. 그래서 디스크 → (RAM) → VRAM으로 옮겨야 해. 이 여정에서 '누가 옮기고, CPU는 뭘 하냐'가 이 글의 핵심이야.

왜 굳이 CPU RAM을 거쳐? 디스크에서 VRAM으로 바로 주면 안 돼?

전통적으로는 그럴 방법이 없었어. 디스크를 읽는 건 OS(CPU 쪽)의 일이고, 읽은 걸 CPU RAM에 일단 담은 뒤 GPU로 넘겼거든. 게다가 텍스처는 보통 압축돼 있어서 중간에 풀어야 하는데, 그걸 CPU가 했어.

그래서 경로가 '디스크 → OS → CPU RAM(압축 해제) → VRAM'이 된 거야. '바로 주면 안 돼?'가 바로 DirectStorage의 발상인데, 그건 뒤에서(Part 5). 먼저 'RAM→VRAM 그 복사는 누가 하냐'부터.

Part 2. 그 바이트, 누가 옮겨? — DMA

RAM에서 VRAM으로 데이터를 옮길 때, CPU가 한 바이트씩 복사해?

'그럴 것 같지'? 아니야. 만약 CPU가 직접 옮기면, 100MB 옮기는 내내 CPU가 그 단순 복사에 묶여 게임 로직·물리·AI를 못 돌려. 프레임 뚝뚝 끊기겠지.

그래서 실제 이동은 DMA(Direct Memory Access) 엔진이라는 전용 하드웨어가 해. 우리가 랜카드에서 본 그 DMA랑 똑같아 — 랜카드가 CPU 안 거치고 커널 메모리에 직접 썼잖아? GPU 업로드도 같은 원리야.

그럼 CPU는 아무것도 안 해?

시작과 끝만 관여해. "이 주소에서 저 주소로 100MB 옮겨"라고 DMA에게 명령(디스크립터)만 딱 던지고 빠져. 그다음 실제 복사는 DMA 엔진이 백그라운드로 하고, 다 되면 인터럽트로 "끝났어" 알려줘.

그래서 '텍스처 올릴 때 CPU가 논다'는 거야 — 명령 던진 뒤엔 자유라 그 시간에 게임 로직을 돌릴 수 있어. 아래에서 CPU 직접 복사 vs DMA를 비교해봐 ↓

🚚 그 바이트, 누가 옮겨? — CPU 직접 vs DMA

'100MB 텍스처 전송'을 눌러봐. CPU가 직접 복사하면 옮기는 내내 CPU가 묶여(게임 로직 정지). DMA는 CPU가 '옮겨줘' 명령만 내리고 빠져 — 전용 엔진이 옮기는 동안 CPU는 딴 일 해.

전송 주체

우리가 랜카드에서 본 DMA랑 똑같아 — 실제 바이트 이동은 CPU가 아니라 DMA 엔진(하드웨어)이 해. CPU는 시작·완료만 관여하고 빠져.

Part 3. RAM과 VRAM 사이 고속도로 — PCIe & 스테이징

DMA가 옮긴다 쳐도, RAM이랑 VRAM은 물리적으로 다른 칩이잖아. 뭘 타고 건너가?

PCIe(PCI Express)라는 고속 버스를 타. CPU/RAM 쪽과 그래픽카드를 잇는 고속도로야. DMA 엔진이 이 PCIe를 통해 RAM↔VRAM 사이로 데이터를 실어 날라.

대역폭도 이게 좌우해 — PCIe 4.0 x16이 약 32GB/s 정도. 이 고속도로가 좁으면 VRAM이 아무리 빨라도 업로드가 막혀.

그럼 GPU가 아무 RAM 주소나 DMA로 당길 수 있어?

아니, 여기 함정이 있어. DMA가 안전하게 당기려면 그 메모리가 고정(pinned)돼 있어야 해 — 우리가 제로카피에서 본 그 '핀 고정'이야! 안 그러면 옮기는 도중 OS가 페이지를 옮겨버려 사고 나거든.

그래서 스테이징(업로드) 버퍼를 둬: CPU가 접근 가능한 고정된 중간 버퍼에 데이터를 채우면, GPU가 거기서 DMA로 VRAM에 당겨가. '디스크 → 스테이징 RAM(고정) → PCIe/DMA → VRAM' 이 경로야.

Part 4. 근데 아직 CPU가 일한다 — 병목의 정체

DMA가 옮겨주면 다 해결 아냐? 왜 로딩이 여전히 느려?

바이트 이동(DMA)은 공짜여도, CPU가 여전히 해야 하는 일이 남아 있어서야. NVMe SSD가 7GB/s를 낼 수 있는데 실제론 2~3GB/s만 나오는 이유:

• OS 파일 시스템 오버헤드: 작은 파일 수천 개를 열고 닫으면 수천 번의 시스템 콜(우리가 배운 그 커널 문턱 넘기).

• CPU 압축 해제: 텍스처는 압축돼 있고, 그걸 CPU가 풀면 CPU가 2~3GB/s에서 병목.

• 포맷 변환 + RAM→VRAM 추가 복사.

일반 I/O 파이프라인의 병목 NVMe SSD (7GB/s 가능) │ ▼ [OS 파일시스템] ← 파일 수천 개 = 수천 번 syscall │ ~3GB/s로 제한 ▼ [CPU RAM] ← 압축 해제(CPU 2~3GB/s 병목) + 포맷 변환 │ ★여기서 CPU가 진짜 병목 ▼ [PCIe/DMA → VRAM] ← RAM→VRAM 복사(추가 시간) 결과: 7GB/s SSD인데 실제 2~3GB/s 😩

Part 5. CPU를 아예 건너뛴다 — DirectStorage / RTXIO

그럼 CPU가 하던 일(파일시스템·압축 해제)을 없애면?

그게 DirectStorage(PC) / RTXIO(NVIDIA) / PS5의 SSD I/O의 발상이야. CPU를 우회해:

• 여러 파일을 한 번에 배치로 요청 → 수천 번 syscall이 몇 번으로.

• SSD에서 읽은 압축 데이터를 GPU로 직행시키고, 압축 해제를 GPU가 함(GDeflate 등). CPU의 압축 해제 병목이 사라져.

• 결과: SSD의 7GB/s를 거의 그대로 VRAM까지.

DirectStorage: CPU 우회, GPU 직접 처리 NVMe SSD (7GB/s) │ 압축된 데이터를 배치로 ▼ [PCIe/DMA] ── CPU RAM·CPU 압축해제 건너뜀 ──▶ [GPU VRAM] │ [GPU가 압축 해제(GDeflate)] CPU는 "이 파일들 GPU로 줘" 명령만. 나머진 DMA+GPU. 결과: 실효 ~7GB/s (SSD 대역폭 그대로)
🛣️ 업로드 경로 — 일반 vs DirectStorage

텍스처가 SSD에서 GPU VRAM까지 가는 길이야. 일반 경로는 CPU RAM을 경유하며 CPU가 압축 해제까지 하고, DirectStorage는 SSD→GPU로 직행하고 GPU가 압축을 풀어. ▶로 흘려보내 비교해봐.

NVMe SSD는 7GB/s가 가능한데, 일반 경로는 CPU 압축 해제·파일시스템 오버헤드에 막혀 실제 2~3GB/s만 나와. DirectStorage는 CPU를 우회해 그 천장을 뚫어.

Part 6. 스트리밍·제로카피와 무슨 관계?

이게 '월드 스트리밍'이랑 '제로카피'랑 어떻게 엮여?

세 개를 축으로 나누면 딱 정리돼:

• 스트리밍 = 무엇을/언제 올리나 (근처만 로드, 멀면 언로드 — 메모리 예산). 버퍼 풀·AOI의 사촌.

• DMA/DirectStorage = 올릴 때 어떻게 옮기나 (CPU 우회, 저·제로 카피).

• 제로카피 = 경계마다 새로 복사 안 하기.

DirectStorage는 '스트리밍의 로드 경로'를 저카피로 구현한 것이야. 즉 스트리밍이 "근처 텍스처 올려!"라고 무엇을 정하면, DirectStorage/DMA가 그걸 CPU 안 거치고 옮기는 거지. 축이 다르니 '스트리밍=제로카피'가 아니라 '스트리밍이 그 로드를 저카피로 할 수 있다'가 맞아.

핵심 정리

  • 텍스처의 목적지는 GPU VRAM. 디스크→(RAM)→VRAM으로 옮겨야 한다.
  • 실제 바이트 이동은 CPU가 아니라 DMA 엔진(하드웨어) — CPU는 명령만 던지고 빠져(그래서 '논다').
  • RAM↔VRAM은 PCIe 고속도로를 타고, DMA 대상 메모리는 핀 고정(제로카피에서 본 그것)이 필요.
  • 그래도 CPU가 파일시스템·압축 해제를 하면 7GB/s SSD가 2~3GB/s로 병목.
  • DirectStorage/RTXIO/PS5 SSD = CPU 우회 + GPU 압축 해제 → SSD 대역폭을 그대로 뽑음.
  • 축 정리: 스트리밍(무엇/언제) ≠ 제로카피(어떻게). DirectStorage는 스트리밍 로드를 저카피로 구현한 것.
