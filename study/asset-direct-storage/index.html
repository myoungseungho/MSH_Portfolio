DirectStorage / RTXIO

GPU 직접 로딩으로 로딩 시간 혁신

Part 1. 기존 I/O의 병목

SSD가 빠른데 왜 로딩이 느려?

NVMe SSD는 7GB/s를 낼 수 있지만, 기존 I/O 경로가 병목입니다:

기존 I/O 파이프라인의 문제: ┌────────────────────────────────────────────────────────────┐ │ │ │ NVMe SSD (7GB/s 가능) │ │ │ │ │ ▼ │ │ ┌────────────────────────────────────────────────┐ │ │ │ OS 파일 시스템 (NTFS) │ │ │ │ - 파일 열기/닫기 오버헤드 │ │ │ │ - 작은 파일 수천 개 = 수천 번 시스템 콜 │ │ │ └────────────────────────────────────────────────┘ │ │ │ ~3GB/s로 제한 │ │ ▼ │ │ ┌────────────────────────────────────────────────┐ │ │ │ CPU 메인 메모리 (RAM) │ │ │ │ - 압축 해제 (CPU 부하, 최대 2-3GB/s) │ │ │ │ - 포맷 변환 │ │ │ └────────────────────────────────────────────────┘ │ │ │ CPU가 병목 │ │ ▼ │ │ ┌────────────────────────────────────────────────┐ │ │ │ PCIe 버스 → GPU VRAM │ │ │ │ - RAM→VRAM 복사 (추가 시간) │ │ │ └────────────────────────────────────────────────┘ │ │ │ │ 결과: 7GB/s SSD인데 실제 2-3GB/s 밖에 안 나옴 │ │ │ └────────────────────────────────────────────────────────────┘

Part 2. DirectStorage의 혁신

DirectStorage는 어떻게 해결해?

GPU가 SSD에서 직접 읽고 압축 해제합니다:

DirectStorage 파이프라인: ┌────────────────────────────────────────────────────────────┐ │ │ │ 핵심: CPU 우회, GPU 직접 처리 │ │ │ │ 기존: │ │ SSD → CPU → RAM → CPU(압축해제) → RAM → GPU │ │ ↑ ↑ ↑ │ │ 병목 병목 병목 │ │ │ │ DirectStorage: │ │ ┌─────────────────────────────────────────────────┐ │ │ │ │ │ │ │ SSD ──────────────────────────────────▶ GPU │ │ │ │ NVMe 직접 접근 GPU 압축 해제 │ │ │ │ │ │ │ └─────────────────────────────────────────────────┘ │ │ │ │ CPU는 "명령"만 내리고, 실제 데이터 이동은 GPU+DMA │ │ │ │ 속도 비교: │ │ ┌──────────────────┬────────────────┬────────────┐ │ │ │ 구분 │ 기존 │ DirectStorage │ │ │ ├──────────────────┼────────────────┼────────────┤ │ │ │ 처리량 │ ~3GB/s │ ~7GB/s+ │ │ │ │ CPU 사용률 │ 높음 (100%) │ 낮음 (5%) │ │ │ │ 압축해제 속도 │ 2GB/s (CPU) │ 24GB/s (GPU)│ │ │ └──────────────────┴────────────────┴────────────┘ │ │ │ └────────────────────────────────────────────────────────────┘
GPU가 압축 푸는 게 왜 빨라?

GPU는 수천 개 코어로 병렬 처리합니다:

CPU vs GPU 압축 해제: ┌────────────────────────────────────────────────────────────┐ │ │ │ CPU (8코어 가정): │ │ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ │ │ │1│ │2│ │3│ │4│ │5│ │6│ │7│ │8│ 8개 블록 동시 처리 │ │ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ │ │ │ │ → 100MB 압축 해제 = 약 50ms │ │ │ │ GPU (10,000+ 코어): │ │ ┌─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─... │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ └─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─... │ │ 10,000+ 블록 동시 처리 │ │ │ │ → 100MB 압축 해제 = 약 4ms │ │ │ │ GDeflate: GPU 최적화 압축 포맷 (DirectStorage 1.2+) │ │ - 기존 zlib/gzip과 호환 │ │ - GPU에서 24GB/s 이상 디코딩 가능 │ │ │ └────────────────────────────────────────────────────────────┘

Part 3. DirectStorage API 구조

코드에서 어떻게 사용해?

DirectStorage는 비동기 요청 큐 기반입니다:

// DirectStorage 기본 사용 패턴 // 1. 초기화 IDStorageFactory* factory; DStorageGetFactory(IID_PPV_ARGS(&factory)); IDStorageQueue* queue; DSTORAGE_QUEUE_DESC queueDesc = {}; queueDesc.Capacity = DSTORAGE_MAX_QUEUE_CAPACITY; queueDesc.Priority = DSTORAGE_PRIORITY_NORMAL; queueDesc.SourceType = DSTORAGE_REQUEST_SOURCE_FILE; queueDesc.Device = d3d12Device; // GPU 디바이스 factory->CreateQueue(&queueDesc, IID_PPV_ARGS(&queue)); // 2. 파일 열기 IDStorageFile* file; factory->OpenFile(L"textures.pak", IID_PPV_ARGS(&file)); // 3. 읽기 요청 생성 DSTORAGE_REQUEST request = {}; request.Options.SourceType = DSTORAGE_REQUEST_SOURCE_FILE; request.Options.DestinationType = DSTORAGE_REQUEST_DESTINATION_TEXTURE_REGION; request.Source.File.Source = file; request.Source.File.Offset = textureOffset; request.Source.File.Size = compressedSize; // GPU 텍스처로 직접 전송! request.Destination.Texture.Resource = gpuTexture; request.Destination.Texture.SubresourceIndex = 0; request.Destination.Texture.Region = { 0, 0, 0, width, height, 1 }; // GPU 압축 해제 설정 request.Options.CompressionFormat = DSTORAGE_COMPRESSION_FORMAT_GDEFLATE; request.UncompressedSize = uncompressedSize; // 4. 큐에 요청 추가 queue->EnqueueRequest(&request); // 5. 제출 (비동기 실행) queue->Submit(); // 6. 완료 대기 (선택적) IDStorageStatusArray* status; factory->CreateStatusArray(1, &status); queue->EnqueueStatus(status, 0); queue->Submit(); status->GetHResult(0); // 완료 확인

Part 4. 배칭과 최적화

요청을 어떻게 효율적으로 처리해?

배칭이 핵심입니다. 수백 개 요청을 한 번에 제출합니다:

DirectStorage 배칭 전략: ┌────────────────────────────────────────────────────────────┐ │ │ │ 나쁜 패턴 (매 요청마다 Submit): │ │ ┌────────────────────────────────────────────────┐ │ │ │ Enqueue → Submit → Wait │ │ │ │ Enqueue → Submit → Wait │ │ │ │ Enqueue → Submit → Wait │ 느림 │ │ │ ... │ │ │ └────────────────────────────────────────────────┘ │ │ │ │ 좋은 패턴 (배칭): │ │ ┌────────────────────────────────────────────────┐ │ │ │ Enqueue(텍스처1) │ │ │ │ Enqueue(텍스처2) │ │ │ │ Enqueue(텍스처3) │ │ │ │ ... │ │ │ │ Enqueue(텍스처100) │ │ │ │ Submit() ← 한 번에 제출! │ 빠름 │ │ │ (다른 작업 수행...) │ │ │ │ Wait() ← 나중에 완료 확인 │ │ │ └────────────────────────────────────────────────┘ │ │ │ │ 권장: 프레임당 1-2회 Submit, 수백 개 요청 배칭 │ │ │ └────────────────────────────────────────────────────────────┘
// 게임 루프에서의 DirectStorage 배칭 패턴 class StreamingManager { std::vector pendingRequests; void RequestTexture(const TextureInfo& info) { DSTORAGE_REQUEST request = {}; // ... 요청 설정 pendingRequests.push_back(request); } void FlushRequests() { if (pendingRequests.empty()) return; // 모든 요청을 한 번에 큐에 추가 for (auto& req : pendingRequests) { queue->EnqueueRequest(&req); } // 한 번에 제출 queue->EnqueueStatus(statusArray, frameIndex); queue->Submit(); pendingRequests.clear(); } void OnFrameEnd() { // 프레임 끝에 배치된 요청 제출 FlushRequests(); } };

Part 7. 설계 고려사항

DirectStorage 사용 시 주의점은?
DirectStorage 설계 체크리스트: ┌────────────────────────────────────────────────────────────┐ │ │ │ ✅ DO (권장) │ │ ──────────────────────────────────────────────────────── │ │ • 대용량 에셋을 PAK/번들로 통합 (파일 수 줄이기) │ │ • GDeflate 압축 사용 (GPU 디코딩 최적) │ │ • 요청 배칭 (수백 개씩 한 번에 Submit) │ │ • 읽기 크기 정렬 (4KB/64KB 배수) │ │ • 비동기 패턴 사용 (Submit 후 다른 작업) │ │ │ │ ❌ DON'T (피해야 할 것) │ │ ──────────────────────────────────────────────────────── │ │ • 작은 파일 수천 개 (오버헤드 증가) │ │ • 매 요청마다 Wait (동기 패턴) │ │ • HDD에서 DirectStorage 사용 (효과 없음) │ │ • CPU 압축 포맷 (zlib 등) 사용 │ │ │ │ Fallback 필수 │ │ ──────────────────────────────────────────────────────── │ │ • DirectStorage 미지원 시스템 대비 │ │ • HDD 사용자를 위한 기존 I/O 경로 유지 │ │ • 런타임 감지: IsDirectStorageSupported() │ │ │ └────────────────────────────────────────────────────────────┘
// 런타임 DirectStorage 지원 확인 및 Fallback class AdaptiveAssetLoader { enum class LoaderType { DirectStorage, Legacy }; LoaderType activeLoader; void Initialize() { // DirectStorage 지원 확인 DSTORAGE_CONFIGURATION config = {}; DStorageGetFactory(IID_PPV_ARGS(&factory)); bool dsSupported = factory != nullptr && IsNVMeSSD() && // SSD 타입 확인 IsGPUCapable(); // GPU 기능 확인 activeLoader = dsSupported ? LoaderType::DirectStorage : LoaderType::Legacy; if (activeLoader == LoaderType::Legacy) { Log("DirectStorage unavailable, using legacy I/O"); } } void LoadAsset(const char* path, void* dest) { if (activeLoader == LoaderType::DirectStorage) { LoadWithDirectStorage(path, dest); } else { LoadWithLegacyIO(path, dest); // 기존 방식 fallback } } };

핵심 정리

  • DirectStorage는 GPU가 SSD에서 직접 읽고 압축 해제
  • 기존 3GB/s → 7GB/s+ 달성, CPU 부하 제거
  • GDeflate: GPU 최적화 압축 포맷 (24GB/s 디코딩)
  • 배칭이 핵심 - 수백 개 요청을 한 번에 Submit
  • PS5 I/O 컴플렉스, Xbox Velocity Architecture도 동일 개념
  • Unreal/Unity에서 설정으로 활성화 가능
  • Fallback 필수 - HDD/구형 시스템 대비
