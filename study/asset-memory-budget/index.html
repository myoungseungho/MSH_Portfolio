메모리 버짓 시스템

카테고리별 메모리 한도를 설정하고 관리하는 체계

Part 1. 개념: 메모리 버짓이란?

메모리 버짓 시스템이 뭐야?

각 에셋 카테고리에 메모리 사용 한도를 할당하고 모니터링하는 관리 체계입니다.

가계부처럼 총 가용 메모리를 "예산"으로 보고, 텍스처/메시/오디오/UI 등 각 항목에 얼마씩 쓸지 미리 정해두는 것입니다. 예산을 초과하면 경고 또는 자동 축소가 발동됩니다.

왜 "버짓"이라고 불러?
┌─────────────────────────────────────────────────────────────────┐
│                   메모리 버짓 비유: 가계부                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  [월 생활비 100만원 = 총 가용 메모리 1GB]                        │
│                                                                 │
│    식비: 30만원         = 텍스처: 300MB                          │
│    교통비: 10만원       = 메시: 100MB                            │
│    주거비: 30만원       = 오디오: 150MB                          │
│    여가비: 15만원       = UI: 100MB                              │
│    비상금: 15만원       = 시스템 예비: 150MB                      │
│    ─────────────────────────────────────                        │
│    합계: 100만원        = 합계: 800MB (여유 200MB)               │
│                                                                 │
│  [규칙]                                                         │
│    • 각 항목은 할당량 내에서 사용                                │
│    • 한 항목이 초과하면 다른 항목에서 빌려오거나                  │
│    • 품질을 낮추거나 (밉맵 레벨 조정)                            │
│    • 필요 없는 것을 버림 (LRU 언로드)                            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

"Budget"은 재정 용어로 "예산"을 의미합니다. 한정된 자원(메모리)을 계획적으로 배분한다는 개념에서 유래했습니다.

버짓 없이 그냥 쓰면 안 돼?

메모리 부족 크래시의 주요 원인이 됩니다:

  • iOS: 앱이 일정 메모리 초과 시 시스템이 강제 종료 (Memory Jetsam)
  • Android: Low Memory Killer가 백그라운드 앱부터 정리, 최악엔 포그라운드도 종료
  • 콘솔: 고정 메모리 환경에서 OOM = 즉시 크래시

버짓 시스템은 예방적 관리를 가능하게 합니다. 크래시 직전이 아니라, 80% 사용 시점에 미리 대응할 수 있습니다.

Part 2. 왜 필요해?

버짓 시스템의 실질적 이점은?

🎯 예측 가능한 성능

  • QA 단계에서 "이 씬은 메모리를 얼마나 쓸까?"를 사전에 파악
  • 특정 기기에서 동작 여부를 빌드 전에 예측
  • 콘텐츠 제작자에게 명확한 가이드라인 제공

🔍 병목 조기 발견

  • "텍스처 버짓 초과" → 텍스처 최적화 필요성 즉시 파악
  • CI/CD에서 버짓 체크 자동화 → 문제 커밋 조기 탐지
  • 팀 간 책임 명확화 (아트팀: 텍스처, 사운드팀: 오디오)

⚡ 적응적 품질 조절

  • 저사양 기기: 버짓 작게 → 자동으로 저품질 에셋 로드
  • 고사양 기기: 버짓 크게 → 고품질 에셋 활용
  • 런타임에 동적으로 품질 스케일링
버짓 없을 때의 실패 사례는?

사례 1: 모바일 게임 런칭 실패

개발 기기(플래그십)에서는 잘 돌았는데, 실제 유저 기기(2~3년 전 모델)에서 대규모 크래시.

  • 원인: 텍스처 메모리만 1.5GB 사용 (저사양 기기 전체 RAM 2GB)
  • 결과: 앱스토어 평점 급락, 긴급 패치 배포

사례 2: 이벤트 콘텐츠 메모리 폭발

신규 이벤트 맵 추가 후 기존 맵들과 함께 로드 시 크래시.

  • 원인: 각 맵 제작자가 "내 맵은 괜찮다"고 생각, 전체 합산 미확인
  • 결과: 이벤트 첫날 긴급 점검, 매출 손실

버짓 시스템이 있었다면:

  • 빌드 시점에 "총 버짓 초과" 경고 발생
  • CI에서 PR 머지 블락
  • 출시 전 문제 해결 가능

※ 모바일에서 총 메모리의 50~60%를 앱 버짓으로 잡는 것이 안전
시스템 예비(Headroom)는 왜 필요해?

100% 꽉 채우면 위험합니다:

  • GC 스파이크: 가비지 컬렉션 시 일시적 메모리 증가
  • 비동기 로딩 버퍼: 로드 중인 에셋이 잠시 중복 존재
  • OS 할당 오버헤드: 실제 할당량이 요청량보다 큼
  • 드라이버/시스템 메모리: GPU 드라이버 내부 버퍼 등

일반적으로 총 버짓의 10~15%를 예비로 남겨둡니다.

public class MemoryBudgetManager : MonoBehaviour { public static MemoryBudgetManager Instance { get; private set; } // 카테고리별 버짓 정의 public enum AssetCategory { Texture, Mesh, Audio, Animation, UI, Effect, Script, System } [Serializable] public class CategoryBudget { public AssetCategory Category; public long BudgetBytes; // 할당된 버짓 public long CurrentUsageBytes; // 현재 사용량 public float WarningThreshold = 0.8f; // 80%에서 경고 public float UsageRatio => (float)CurrentUsageBytes / BudgetBytes; public bool IsOverBudget => CurrentUsageBytes > BudgetBytes; public bool IsWarning => UsageRatio >= WarningThreshold; } [SerializeField] private List<CategoryBudget> _budgets = new(); private Dictionary<AssetCategory, CategoryBudget> _budgetMap; public event Action<AssetCategory> OnBudgetWarning; public event Action<AssetCategory> OnBudgetExceeded; void Awake() { Instance = this; _budgetMap = _budgets.ToDictionary(b => b.Category); LoadBudgetProfile(); } // 디바이스 티어에 맞는 버짓 프로파일 로드 private void LoadBudgetProfile() { var tier = DetectDeviceTier(); var profile = Resources.Load<BudgetProfile>($"BudgetProfiles/{tier}"); if (profile != null) { ApplyProfile(profile); } } private DeviceTier DetectDeviceTier() { long totalMemory = SystemInfo.systemMemorySize; // MB 단위 if (totalMemory <= 2048) return DeviceTier.Low; if (totalMemory <= 4096) return DeviceTier.Mid; if (totalMemory <= 6144) return DeviceTier.High; return DeviceTier.Ultra; } }

public partial class MemoryBudgetManager { // 에셋 로드 시 호출 public void RegisterAsset(AssetCategory category, Object asset, long sizeBytes) { if (!_budgetMap.TryGetValue(category, out var budget)) { Debug.LogWarning($"Unknown category: {category}"); return; } budget.CurrentUsageBytes += sizeBytes; // 트래킹을 위해 에셋 정보 저장 _trackedAssets[asset.GetInstanceID()] = new TrackedAssetInfo { Category = category, SizeBytes = sizeBytes, LoadTime = Time.realtimeSinceStartup }; // 버짓 체크 CheckBudgetStatus(category, budget); } // 에셋 언로드 시 호출 public void UnregisterAsset(Object asset) { int instanceId = asset.GetInstanceID(); if (_trackedAssets.TryGetValue(instanceId, out var info)) { if (_budgetMap.TryGetValue(info.Category, out var budget)) { budget.CurrentUsageBytes -= info.SizeBytes; } _trackedAssets.Remove(instanceId); } } private void CheckBudgetStatus(AssetCategory category, CategoryBudget budget) { if (budget.IsOverBudget) { Debug.LogError($"[MemoryBudget] {category} EXCEEDED: {FormatBytes(budget.CurrentUsageBytes)} / {FormatBytes(budget.BudgetBytes)}"); OnBudgetExceeded?.Invoke(category); } else if (budget.IsWarning) { Debug.LogWarning($"[MemoryBudget] {category} WARNING: {budget.UsageRatio:P0}"); OnBudgetWarning?.Invoke(category); } } // 현재 상태 조회 public BudgetStatus GetStatus(AssetCategory category) { var budget = _budgetMap[category]; return new BudgetStatus { Category = category, BudgetBytes = budget.BudgetBytes, UsedBytes = budget.CurrentUsageBytes, AvailableBytes = budget.BudgetBytes - budget.CurrentUsageBytes, UsageRatio = budget.UsageRatio }; } // 전체 상태 리포트 public IEnumerable<BudgetStatus> GetAllStatus() { return _budgetMap.Values.Select(b => GetStatus(b.Category)); } }

public static class AssetSizeCalculator { public static long GetTextureSize(Texture tex) { if (tex == null) return 0; #if UNITY_EDITOR // 에디터에서는 정확한 값 return UnityEngine.Profiling.Profiler.GetRuntimeMemorySizeLong(tex); #else // 런타임에서는 추정 int width = tex.width; int height = tex.height; int bpp = GetBitsPerPixel(tex); int mipmapCount = tex is Texture2D t2d ? t2d.mipmapCount : 1; long baseSize = (width * height * bpp) / 8; // 밉맵 추가 용량 (약 1.33배) if (mipmapCount > 1) { baseSize = (long)(baseSize * 1.33f); } return baseSize; #endif } private static int GetBitsPerPixel(Texture tex) { if (tex is Texture2D t2d) { return t2d.format switch { TextureFormat.RGBA32 => 32, TextureFormat.RGB24 => 24, TextureFormat.ASTC_4x4 => 8, TextureFormat.ASTC_6x6 => 4, TextureFormat.ETC2_RGBA8 => 8, TextureFormat.DXT1 => 4, TextureFormat.DXT5 => 8, _ => 32 // 기본값 }; } return 32; } public static long GetMeshSize(Mesh mesh) { if (mesh == null) return 0; #if UNITY_EDITOR return Profiler.GetRuntimeMemorySizeLong(mesh); #else // 추정: 버텍스 * (위치 12B + 노말 12B + UV 8B + 탄젠트 16B) // + 인덱스 * 4B (32bit) 또는 2B (16bit) long vertexSize = mesh.vertexCount * 48; // 대략적인 버텍스 데이터 long indexSize = mesh.triangles.Length * 4; return vertexSize + indexSize; #endif } public static long GetAudioSize(AudioClip clip) { if (clip == null) return 0; #if UNITY_EDITOR return Profiler.GetRuntimeMemorySizeLong(clip); #else // 샘플 수 * 채널 수 * 바이트/샘플 return (long)clip.samples * clip.channels * 2; // 16bit PCM 가정 #endif } }

Part 5. 자동 품질 조절

버짓 초과하면 자동으로 대응할 수 있어?

적응적 품질 스케일링(Adaptive Quality Scaling)을 구현합니다:

public class AdaptiveQualityManager { private MemoryBudgetManager _budgetManager; private Dictionary<AssetCategory, QualityLevel> _currentQuality = new(); public enum QualityLevel { Ultra, High, Medium, Low, VeryLow } public void Initialize(MemoryBudgetManager budgetManager) { _budgetManager = budgetManager; _budgetManager.OnBudgetWarning += OnWarning; _budgetManager.OnBudgetExceeded += OnExceeded; // 초기 품질 설정 foreach (AssetCategory cat in Enum.GetValues(typeof(AssetCategory))) { _currentQuality[cat] = QualityLevel.High; } } private void OnWarning(AssetCategory category) { // 80% 도달 시 품질 한 단계 낮춤 ReduceQuality(category, 1); } private void OnExceeded(AssetCategory category) { // 100% 초과 시 적극적 대응 ReduceQuality(category, 2); ForceUnloadLRU(category); } private void ReduceQuality(AssetCategory category, int steps) { var current = _currentQuality[category]; var newLevel = (QualityLevel)Math.Min( (int)current + steps, (int)QualityLevel.VeryLow ); if (newLevel != current) { _currentQuality[category] = newLevel; ApplyQualityChange(category, newLevel); Debug.Log($"[AdaptiveQuality] {category}: {current} → {newLevel}"); } } private void ApplyQualityChange(AssetCategory category, QualityLevel level) { switch (category) { case AssetCategory.Texture: ApplyTextureQuality(level); break; case AssetCategory.Mesh: ApplyMeshQuality(level); break; case AssetCategory.Audio: ApplyAudioQuality(level); break; } } private void ApplyTextureQuality(QualityLevel level) { // 전역 밉맵 바이어스 조정 int mipBias = level switch { QualityLevel.Ultra => 0, QualityLevel.High => 0, QualityLevel.Medium => 1, QualityLevel.Low => 2, QualityLevel.VeryLow => 3, _ => 0 }; QualitySettings.globalTextureMipmapLimit = mipBias; } private void ApplyMeshQuality(QualityLevel level) { // LOD 바이어스 조정 float lodBias = level switch { QualityLevel.Ultra => 2.0f, QualityLevel.High => 1.5f, QualityLevel.Medium => 1.0f, QualityLevel.Low => 0.7f, QualityLevel.VeryLow => 0.5f, _ => 1.0f }; QualitySettings.lodBias = lodBias; } private void ApplyAudioQuality(QualityLevel level) { // 동시 음원 수 제한 int maxVoices = level switch { QualityLevel.Ultra => 64, QualityLevel.High => 48, QualityLevel.Medium => 32, QualityLevel.Low => 24, QualityLevel.VeryLow => 16, _ => 32 }; var config = AudioSettings.GetConfiguration(); config.numRealVoices = maxVoices; AudioSettings.Reset(config); } }
LRU 강제 언로드는?
public partial class AdaptiveQualityManager { private void ForceUnloadLRU(AssetCategory category) { var status = _budgetManager.GetStatus(category); long overBudget = status.UsedBytes - status.BudgetBytes; if (overBudget <= 0) return; // 해당 카테고리의 트래킹된 에셋을 LRU 순서로 정렬 var assetsToUnload = _budgetManager.GetTrackedAssets(category) .OrderBy(a => a.LastAccessTime) // 가장 오래 사용 안 한 것부터 .ToList(); long freedBytes = 0; foreach (var assetInfo in assetsToUnload) { // 현재 사용 중인 에셋은 건너뜀 if (assetInfo.IsCurrentlyUsed) continue; // 언로드 Addressables.Release(assetInfo.Handle); freedBytes += assetInfo.SizeBytes; Debug.Log($"[AdaptiveQuality] Unloaded: {assetInfo.Name} ({FormatBytes(assetInfo.SizeBytes)})"); // 충분히 해제했으면 중단 if (freedBytes >= overBudget * 1.2f) // 20% 여유 확보 { break; } } // 가비지 컬렉션 Resources.UnloadUnusedAssets(); Debug.Log($"[AdaptiveQuality] Freed {FormatBytes(freedBytes)} from {category}"); } }

Part 6. 모니터링과 디버깅

런타임에 버짓 상태를 어떻게 볼 수 있어?

디버그 오버레이 UI를 구현합니다:

public class BudgetDebugOverlay : MonoBehaviour { [SerializeField] private MemoryBudgetManager _budgetManager; [SerializeField] private bool _showOverlay = false; private GUIStyle _normalStyle; private GUIStyle _warningStyle; private GUIStyle _criticalStyle; void OnGUI() { if (!_showOverlay) return; InitStyles(); GUILayout.BeginArea(new Rect(10, 10, 300, 400)); GUILayout.Box("Memory Budget Monitor"); foreach (var status in _budgetManager.GetAllStatus()) { DrawCategoryBar(status); } // 총합 var total = _budgetManager.GetTotalStatus(); GUILayout.Space(10); GUILayout.Label($"TOTAL: {FormatBytes(total.UsedBytes)} / {FormatBytes(total.BudgetBytes)}"); DrawProgressBar(total.UsageRatio); GUILayout.EndArea(); } private void DrawCategoryBar(BudgetStatus status) { var style = status.UsageRatio > 1.0f ? _criticalStyle : status.UsageRatio > 0.8f ? _warningStyle : _normalStyle; GUILayout.BeginHorizontal(); GUILayout.Label(status.Category.ToString(), GUILayout.Width(80)); GUILayout.Label($"{status.UsageRatio:P0}", style, GUILayout.Width(50)); GUILayout.Label($"{FormatBytes(status.UsedBytes)}/{FormatBytes(status.BudgetBytes)}"); GUILayout.EndHorizontal(); DrawProgressBar(status.UsageRatio); } private void DrawProgressBar(float ratio) { var rect = GUILayoutUtility.GetRect(280, 16); GUI.Box(rect, ""); var fillRect = rect; fillRect.width = rect.width * Mathf.Clamp01(ratio); Color color = ratio > 1.0f ? Color.red : ratio > 0.8f ? Color.yellow : Color.green; GUI.color = color; GUI.DrawTexture(fillRect, Texture2D.whiteTexture); GUI.color = Color.white; } }

Part 7. 실전 체크리스트

버짓 시스템 구축 체크리스트는?

⚠️ 프로젝트 초기 설정

  • [ ] 타겟 디바이스 최소/권장 사양 정의
  • [ ] 디바이스 티어 분류 기준 확립 (RAM 기준 등)
  • [ ] 티어별 총 버짓 결정 (앱 가용 메모리의 50~60%)
  • [ ] 카테고리별 버짓 배분 (텍스처 35%, 메시 15% 등)
  • [ ] 시스템 예비 공간 확보 (10~15%)

📋 구현 체크리스트

  • [ ] 버짓 매니저: 싱글톤, 카테고리별 트래킹
  • [ ] 에셋 크기 계산: 텍스처/메시/오디오별 로직
  • [ ] 자동 등록: Addressables 콜백 연동
  • [ ] 경고/초과 이벤트: 80%, 100% 임계값
  • [ ] 적응적 품질 조절: 밉맵/LOD/음원 자동 조정
  • [ ] LRU 언로드: 초과 시 자동 해제
  • [ ] 디버그 오버레이: 런타임 모니터링 UI
  • [ ] 빌드 시점 검증: CI 연동 자동 체크

핵심 정리

  • 메모리 버짓 = 카테고리별 메모리 한도를 미리 할당하고 관리하는 시스템
  • 디바이스 티어별 프로파일로 저사양/고사양 대응
  • 시스템 예비(Headroom) 10~15% 확보 필수
  • 적응적 품질 조절: 버짓 초과 시 밉맵/LOD 자동 조정
  • LRU 강제 언로드로 크래시 방지
  • CI 연동으로 빌드 시점에 버짓 검증
  • 런타임 오버레이로 실시간 모니터링
