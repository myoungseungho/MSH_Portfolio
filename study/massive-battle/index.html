1000명이 한 곳에서 싸우면 서버는 왜 터질까?

대규모 공성전 서버 최적화 - 은탄환은 없다

왜 터지는가 - 수학으로 보기

평소에 3000명 잘 처리하는 서버가 공성전에서 왜 터져?

핵심은 "흩어져 있느냐, 몰려 있느냐"야.

평소 상황을 먼저 보자.

평소엔 뭐가 다른데?

3000명이 월드 전체에 흩어져 있어.

각 유저의 AOI (Area of Interest) 안에는 평균 30명 정도만 들어와.

AOI가 뭐야?

정의: AOI (Area of Interest) = 관심 영역. 내 캐릭터 주변 일정 반경 안에 있는 것만 동기화하는 범위.

왜 필요: 월드 전체 유저 정보를 다 보내면 서버가 죽으니까, 내 근처만 보내는 거야.

안 쓰면: 유저 수가 조금만 늘어도 패킷이 기하급수적으로 늘어서 서버가 터져.

평소엔 이래:

평소 상황: - 월드에 3000명 - AOI 안에 평균 30명 - 한 유저당 보내는 패킷 = 30개/틱 - 서버 전체 = 3000 x 30 = 90,000 패킷/틱 → 서버가 충분히 감당할 수 있는 양
공성전이면 뭐가 달라지는데?

1000명이 한 점에 모여.

AOI 반경 50m 안에 1000명이 전부 들어오는 거야.

그러면 한 유저가 봐야 할 다른 유저 수가 30명에서 999명으로 폭증해.

공성전 상황: - 성 앞에 1000명 밀집 - AOI 안에 999명 (= 나 빼고 전부) - 한 유저당 보내는 패킷 = 999개/틱 - 밀집 지역만 = 1000 x 999 = 999,000 패킷/틱 → 약 100만 패킷/틱. 평소의 11배!

이걸 수학으로 보면:

N명이 서로를 전부 볼 때 패킷 수: 패킷 수 = N x (N - 1) N = 30 → 30 x 29 = 870 (평소, 감당 가능) N = 100 → 100 x 99 = 9,900 (좀 버벅) N = 500 → 500 x 499 = 249,500 (심각) N = 1000 → 1000 x 999 = 999,000 (서버 사망) 핵심: N이 2배 되면, 패킷은 4배가 돼. 이걸 N제곱(N²) 문제라고 불러.
비유: 교실 속 자기소개

학생 5명이 서로 자기소개하면? 5 x 4 = 20번이면 끝나.
학생 100명이면? 100 x 99 = 9,900번. 수업 시간이 끝나도 못 끝내.
사람 수가 조금만 늘어도, "모두가 모두에게" 말해야 할 횟수는 제곱으로 폭발해.
서버도 마찬가지야. 밀집하면 "모두가 모두를" 동기화해야 하니까 터지는 거야.

결론: 공성전이 터지는 이유 = N² 패킷 폭발. 사람이 모이면 패킷이 제곱으로 늘어나기 때문이야.

그러면 어떻게 해결할까? 4가지 선택지를 하나씩 보자.

선택지 A - AOI 반경 동적 축소

제일 간단한 방법은 없어?

있어. AOI 반경을 줄이는 거야.

사람이 많이 모이면, 서버가 자동으로 "볼 수 있는 범위"를 좁혀버려.

평상시: AOI 반경 50m → 주변 30명 정도 보임 공성전: AOI 반경 20m → 주변 ~160명으로 줄어듦 혼전: AOI 반경 10m → 주변 ~40명까지 줄어듦 서버가 밀집도를 감지해서 자동으로 반경을 조절
왜 반경만 줄이면 효과가 있어?

반경이 절반(50m → 25m)이 되면, 면적은 1/4로 줄어.

면적이 1/4이면 그 안에 들어오는 유저 수도 대략 1/4.

유저 수가 1/4이면 패킷 수는 대략 1/16으로 줄어. (N²이니까)

강점: 가장 구현이 단순해. 파라미터 하나(반경 값)만 바꾸면 돼.

약점: 유저 경험이 나빠져. 적이 갑자기 눈앞에 튀어나와. 멀리서 달려오는 걸 못 보니까 전략적 플레이가 방해돼.

적합: 빠른 해결이 필요할 때. 대부분의 상용 MMO가 이걸 기본으로 깔고 감.

선택지 B - 패킷 우선순위 + 샘플링

AOI를 줄이면 적이 갑자기 나타나잖아. 범위는 유지하면서 패킷을 줄이는 방법은 없어?

있어. "누구 정보를 얼마나 자주 보낼지"를 차등 두는 거야.

지금까지는 AOI 안의 모든 유저에게 똑같은 빈도로 패킷을 보냈잖아. 근데 생각해봐 - 나를 때리고 있는 적이랑, 저 멀리 서 있는 아군이 같은 빈도로 업데이트될 필요가 있어?

틱(Tick)이 뭐야? 60Hz, 30Hz는 뭔데?

정의: 틱(Tick) = 서버가 게임 상태를 한 번 갱신하는 주기. Hz는 "초당 몇 번"이라는 뜻.

왜 필요: 서버는 끊임없이 "지금 상태"를 계산해서 클라이언트에 보내야 하는데, 그 주기가 틱이야.

안 쓰면: 기준 주기가 없으면 서버가 제멋대로 보내서 캐릭터가 순간이동하거나 끊겨 보여.

우선순위를 이렇게 나눠:

Priority 1: 내 캐릭터 → 60Hz (초당 60번, 최우선) Priority 2: 나를 때리는 적 → 60Hz (전투 반응 필수) Priority 3: AOI 내 파티원 → 30Hz (절반이어도 충분) Priority 4: AOI 내 적 → 15Hz (아직 안 싸우는 적) Priority 5: AOI 내 기타 (NPC 등) → 5Hz + 스냅샷
스냅샷이 뭐야?

정의: 스냅샷(Snapshot) = 특정 시점의 전체 상태를 한 번에 찍어서 보내는 것. 실시간 스트리밍 대신 "사진 한 장" 보내는 거.

왜 필요: Priority 5 같은 낮은 순위 대상은 실시간으로 계속 보낼 필요 없이, 가끔 한 번 전체 상태를 싹 보내주면 돼.

안 쓰면: 낮은 순위에도 실시간 스트리밍하면 패킷 절감 효과가 사라져.

이러면 얼마나 줄어?

대충 계산해보자:

AOI 안에 999명이 있다고 가정: 균등 전송 (기존): 999명 x 60Hz = 59,940 패킷/초 (유저 1명당) 우선순위 전송: P1: 1명 x 60Hz = 60 P2: 5명 x 60Hz = 300 P3: 20명 x 30Hz = 600 P4: 200명 x 15Hz = 3,000 P5: 773명 x 5Hz = 3,865 합계 = 약 7,825 패킷/초 → 59,940 → 7,825 = 약 87% 감소!

강점: 유저 체감 품질이 높아. 나랑 싸우는 상대는 끊김 없이 보이고, 먼 군중은 약간 덜 부드럽지만 눈에 안 띄어.

약점: 구현이 복잡해. "이 유저가 나를 때리고 있는가?", "파티원인가?" 같은 우선순위 판별 로직을 매 틱마다 돌려야 해.

적합: AAA급 게임. 품질과 성능 모두 잡고 싶을 때.

선택지 C - 전장 인스턴스 분리 + 결과 합산

패킷을 줄이는 게 아니라, 아예 사람을 나눠버리면 안 돼?

가능해. 전장을 여러 인스턴스(Instance)로 쪼개는 거야.

인스턴스가 뭐야?

정의: 인스턴스(Instance) = 같은 맵의 독립된 복사본. 물리적으로 같은 장소지만, 서버에서는 별도의 방으로 돌아가.

왜 필요: 한 공간에 너무 많은 유저가 몰리면, 여러 개의 복사본으로 나눠서 각각 처리하면 부하가 분산돼.

안 쓰면: 1000명이 한 서버 인스턴스에 몰려서 N² 폭발을 그대로 맞아.

1000명 공성전 → 4개 인스턴스로 분리: 인스턴스 1: 성문 공략 (250명) 인스턴스 2: 성벽 좌측 (250명) 인스턴스 3: 성벽 우측 (250명) 인스턴스 4: 성 내부 방어 (250명) 각 인스턴스 결과 → "공성 진행도"에 합산 반영 성문 HP, 성벽 내구도 같은 공유 상태를 중앙 서버가 관리
250명이면 어느 정도야?

N² 관점에서 보면:

1000명 한 곳: 1000 x 999 = 999,000 패킷/틱 250명 4곳: 250 x 249 = 62,250 패킷/틱 (x4 = 249,000) → 같은 1000명인데 패킷 총량이 75% 감소! (999,000 → 249,000)

강점: 서버 부하를 완벽하게 분산할 수 있어. 인스턴스 수를 늘리면 이론상 무한 확장 가능.

약점: "1000명이 한 전장에서 싸운다"는 느낌이 사라져. 유저 입장에서는 250명짜리 전투 4판을 따로 치르는 거라 몰입이 깨지고 불만이 나와.

적합: 성능 한계를 인정하고, 게임 디자인으로 자연스럽게 분리할 수 있을 때. 예를 들어 "성문 팀, 성벽 팀, 내부 팀" 같은 역할 분담이 기획에 녹아 있으면 위화감이 줄어.

선택지 D - 하이브리드 (상용 게임의 현실)

실제 게임은 위에 것 중에 뭘 써?

전부 다 써. 하나만 쓰는 게임은 없어.

리니지, 아키에이지 같은 대규모 공성전 게임들은 여러 기법을 동시에 적용해.

어떤 식으로 겹쳐?

실제 상용 게임의 공성전 최적화 레이어를 보면:

Layer 1: AOI 반경 약간 축소 (50m → 30m) Layer 2: 패킷 우선순위 적용 (전투 대상 우선) Layer 3: 비전투 NPC/이펙트 간소화 (상점 NPC 숨기기, 이펙트 생략) Layer 4: 틱레이트(Tick Rate) 낮춤 (60Hz → 20Hz) Layer 5: 물리/충돌 판정 단순화 (복잡한 물리 계산 생략)
틱레이트를 낮추면 유저가 못 느껴?

공성전은 수십~수백 명이 뒤엉키는 난전이야. 1:1 결투가 아니라서 20Hz로 낮춰도 체감 차이가 적어.

사실 대부분의 유저는 "렉이 좀 있네" 정도로 느끼지, 틱레이트가 낮아진 건 모르거든.

각 레이어가 20~30%씩 줄인다고 효과가 크다고?

곱셈이거든. 더하기가 아니라.

각 레이어가 패킷/연산을 30%씩 줄인다고 가정: 원본: 100% Layer 1 적용 후: 100% x 0.7 = 70% Layer 2 적용 후: 70% x 0.7 = 49% Layer 3 적용 후: 49% x 0.7 = 34% Layer 4 적용 후: 34% x 0.7 = 24% Layer 5 적용 후: 24% x 0.7 = 17% → 5개 레이어로 원본의 17%까지 줄일 수 있어! 하나만으로는 부족해도, 겹치면 큰 효과.

그리고 가장 중요한 포인트:

"기술로만 풀려고 하면 한계가 온다. 기획과 같이 풀어야 한다."

예를 들어:

- 공성전 시작 전 대기 시간을 둬서 사람이 한꺼번에 몰리는 걸 방지

- 성문/성벽/내부를 단계적으로 개방해서 자연스럽게 분산

- 광역기 범위를 제한해서 한 번에 처리할 타겟 수를 줄이기

- 부활 지점을 뒤쪽에 배치해서 전선이 분산되게 유도

비유: 교통 체증 해결

도로 하나만 넓힌다고 교통 체증이 풀리지 않아.
신호 체계 바꾸고, 우회도로 만들고, 출퇴근 시간 분산하고, 대중교통 늘리고...
여러 방법을 동시에 써야 효과가 나오지.

서버 최적화도 마찬가지야. "이거 하나면 해결!" 같은 은탄환(Silver Bullet)은 없어.

4가지 선택지 한눈에 비교

A. AOI 축소 B. 패킷 우선순위 C. 인스턴스 분리 D. 하이브리드

유저 경험 나쁨 (적 순간출현) 좋음 (자연스러움) 나쁨 (분리감) 가장 좋음

현실에서는 A를 기본으로 깔고, B와 D를 섞는 게 가장 일반적이야.

C는 게임 기획이 뒷받침될 때만 쓸 수 있어.

용어 사전

용어 뜻
AOI (Area of Interest) 관심 영역. 내 캐릭터 주변에서 동기화할 범위.
N² 문제 N명이 서로를 전부 동기화하면 패킷이 N x (N-1)로 폭발하는 현상.
틱 / 틱레이트 (Tick / Tick Rate) 서버가 게임 상태를 갱신하는 주기. Hz 단위 (60Hz = 초당 60번).
인스턴스 (Instance) 같은 맵의 독립된 복사본. 유저를 분리해서 부하를 나눔.
스냅샷 (Snapshot) 특정 시점의 전체 상태를 한 번에 보내는 것. 실시간 스트리밍의 반대.
은탄환 (Silver Bullet) "이것 하나면 모든 문제 해결" 같은 만능 해결책. 현실에는 없다는 의미로 자주 쓰임.

핵심 정리: 대규모 공성전 서버 최적화

  • N² 패킷 폭발 - 유저가 한 곳에 모이면 패킷이 제곱으로 늘어나서 서버가 터지는 근본 원인
  • AOI 축소 - 가장 쉽지만 유저 경험을 희생 (적 순간출현, 전략 방해)
  • 패킷 우선순위 - 전투 대상은 고빈도, 나머지는 저빈도로 보내서 품질 유지하며 감소
  • 인스턴스 분리 - 확실한 부하 분산이지만 "1000명 한판" 몰입이 깨짐
  • 현실 = 하이브리드 - 여러 기법을 겹쳐서 적용하고, 기획 단에서도 분산을 유도
