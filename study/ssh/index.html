SSH: 안전한 원격 접속

초보자를 위한 개념 정리 2025.01
SSH 원격 접속 공개키 서버 관리 GitHub

개요

서버를 관리하려면 원격으로 접속해야 합니다. ssh user@server.com 이런 명령어를 쳐본 적 있나요?

SSH가 뭔지, 왜 필요한지, 비밀번호 대신 "키"로 접속하는 건 뭔지, 질문과 답변 형식으로 차근차근 알아봅시다.

1. 원격 접속이 필요한 상황

상황

회사 서버실에 있는 컴퓨터를 관리해야 합니다. 그런데 서버실은 다른 건물에 있고, 매번 거기까지 가기 귀찮아요. 집에서 그 컴퓨터를 원격으로 조작하고 싶다면?

답

인터넷으로 연결해서 명령을 보내고 결과를 받는 프로그램이 필요하죠!

그래서 옛날에는 Telnet이라는 프로그램을 썼어요. 원격 컴퓨터에 접속해서 명령어를 치면 결과가 돌아오는 거죠.

내 컴퓨터 서버 (다른 건물) │ │ │ "파일 목록 보여줘" ──────────────> │ │ │ │ <────────────── "file1, file2..." │ │ │

2. Telnet의 치명적인 문제

질문

Telnet으로 보내는 명령어와 결과가 인터넷을 통해 왔다 갔다 합니다. 여기서 어떤 위험이 있을까요?

답

누가 중간에서 가로채볼 수 있죠!

Telnet의 치명적 문제

Telnet은 암호화가 없어요. 모든 게 평문(Plain Text)으로 전송됩니다!

당신 ────── 인터넷 ────── 서버 │ 해커가 여기서 보면: "login: admin" "password: mySecret123" ← 비밀번호 그대로 보임! "rm -rf /important/*" ← 명령어도 보임!

서버 비밀번호까지 그대로 노출되는 거예요. 이건 심각한 보안 문제입니다.

3. SSH의 등장 - Secure Shell

해결책은 간단합니다. 암호화하면 돼요!

SSH = Secure Shell

Secure = 안전한

Shell = 쉘 (명령어 입력 환경)

Shell이 뭐예요?

컴퓨터한테 명령어를 치면 결과를 보여주는 그 검은 화면 있잖아요.

  • 윈도우: cmd, PowerShell
  • 리눅스/맥: bash, zsh

이런 걸 Shell(쉘)이라고 불러요. 사용자와 운영체제 사이의 "껍데기" 역할을 하거든요.

┌─────────────────────────────┐ │ 사용자 (당신) │ └──────────────┬──────────────┘ │ 명령어 입력 ▼ ┌─────────────────────────────┐ │ Shell (cmd, bash) │ ← 이게 Shell! └──────────────┬──────────────┘ │ 운영체제에 전달 ▼ ┌─────────────────────────────┐ │ 운영체제 (Windows, Linux) │ └─────────────────────────────┘

SSH란?

"암호화된 안전한 연결로 원격 컴퓨터의 Shell을 사용하는 것"

중간에 누가 가로채도 암호화되어 있어서 내용을 알 수 없어요!

4. 인증 방식 1: 비밀번호

SSH로 서버에 접속하려면 "나 진짜 주인이야"를 증명해야 해요.

질문

가장 쉬운 방법은 뭘까요?

ssh admin@server.com
Password: ________    ← 여기에 뭘 치면 될까요?

답

비밀번호 치면 되는 거죠!

맞아요, 가장 직관적인 방법이에요. 하지만...

비밀번호 방식의 단점

문제 설명
외워야 함 서버가 10개면 10개 다 외워야 해요
무차별 대입 공격 해커가 비밀번호를 무작위로 계속 시도하면?
노출 위험 누가 어깨 너머로 보면 털려요
공유 문제 팀원에게 비밀번호 알려주면 보안 약화

그래서 더 안전한 방법이 필요했어요.

5. 공개키와 개인키 이해하기

비밀번호 없이 인증하려면 공개키/개인키 개념을 알아야 해요.

특수한 자물쇠와 열쇠

특수한 자물쇠-열쇠 세트를 상상해보세요:

┌─────────────────────────────────────────────┐ │ 공개키 (자물쇠) 개인키 (열쇠) │ │ 🔒 🔑 │ │ │ │ - 누구에게나 공개 OK - 나만 소유 │ │ - 복사해서 줘도 됨 - 절대 공개 금지 │ └─────────────────────────────────────────────┘

암호화에 사용할 때

상황: 누군가 나에게 비밀 메시지를 보내고 싶다 1. 내 공개키(자물쇠)를 상대에게 줌 2. 상대가 메시지를 공개키로 "잠금" 3. 나만 개인키(열쇠)로 "열 수 있음" → 공개키로 잠그면 → 개인키로만 열 수 있다!

근데 반대로도 돼요!

핵심 포인트

개인키로 잠그면 → 공개키로만 열 수 있다

이게 "서명(Signature)"의 원리예요!

내가 개인키로 뭔가를 잠갔어요 ↓ 공개키는 누구나 가지고 있으니까 누구나 열 수 있어요 ↓ 근데 "열린다"는 건 뭘 증명하죠? ↓ "이거 잠근 사람이 개인키 가진 사람이구나!"

현실 비유: 서명(싸인)

현실 암호화
나만의 고유한 싸인 개인키
은행이 알고 있는 내 싸인 공개키
서류에 싸인함 개인키로 서명
은행이 "진짜 본인이네" 확인 공개키로 검증

6. 인증 방식 2: 공개키/개인키

이제 SSH 인증에 적용해봅시다!

1키 쌍 생성

내 컴퓨터에서 공개키/개인키 쌍을 만듦

2공개키 등록

공개키를 서버에 미리 등록해둠 ("이게 내 싸인이야")

3접속 시도

나중에 접속할 때, 서버가 "싸인 해봐"라고 요청

4서명

내 컴퓨터가 개인키로 싸인해서 보냄

5검증 완료

서버가 공개키로 검증 → "OK 진짜 주인이네!"

핵심

비밀번호 없이, 개인키를 가졌다는 것 자체가 증명이 되는 거예요!

7. 공개키를 서버에 등록하는 방법

질문

근데 공개키를 어떻게 "미리 등록"하죠?

처음 한 번은 다른 방법으로 서버에 접근해야 해요.

방법 설명
비밀번호로 먼저 접속 처음에 비밀번호로 접속해서 공개키 등록, 다음부터 키로 접속
관리자가 등록 "야, 내 공개키 이거야. 등록해줘"
클라우드 설정 AWS, Azure 등에서 서버 만들 때 웹에서 공개키 입력

실제로 해보면

1단계: 키 쌍 만들기 (내 컴퓨터에서)

ssh-keygen -t rsa

그러면 두 개 파일이 생겨요:

~/.ssh/id_rsa        ← 개인키 (절대 공개 금지!)
~/.ssh/id_rsa.pub    ← 공개키 (이걸 서버에 등록)

2단계: 공개키를 서버에 복사

ssh-copy-id user@server.com

(이때 한 번은 비밀번호 입력 필요)

3단계: 이제부터 비밀번호 없이 접속!

ssh user@server.com

끝!

8. GitHub에서 SSH 사용하기

질문

GitHub에서 SSH로 clone할 때도 같은 원리일까요?

git clone git@github.com:myname/myrepo.git

답

GitHub에도 공개키 등록해두면 되는 거죠!

GitHub SSH 인증 흐름

1. 내 컴퓨터에서 키 쌍 생성 (ssh-keygen) 2. GitHub 설정 → SSH Keys → 공개키 등록 (github.com/settings/keys) 3. git clone git@github.com:myname/repo.git 할 때 GitHub: "너 누구야? 싸인해봐" 내 컴퓨터: (개인키로 싸인해서 보냄) GitHub: "이 싸인이... 등록된 공개키로 검증되네. OK!"

그래서!

비밀번호 안 쳐도 git push, git pull이 되는 거예요!

9. SSL vs SSH 비교

이름이 비슷해서 헷갈리지만, 완전히 다른 목적의 프로토콜이에요.

구분 SSL/TLS SSH
목적 웹 통신 암호화 원격 서버 접속
포트 443 (HTTPS) 22
인증 인증서 (CA 발급) 비밀번호 or 키 페어
사용 예 HTTPS 웹사이트, API 서버 관리, Git
누가 쓰나 웹사이트 방문자 (자동) 개발자/관리자 (직접)

공통점

둘 다 공개키/개인키 암호화 원리를 사용해요!

SSL은 "통신 암호화"에, SSH는 "인증"에 주로 활용하는 차이가 있어요.

10. 실무에서 자주 쓰는 표현

표현 의미
"SSH로 접속한다" 원격 서버에 안전하게 연결
"SSH 키 생성한다" ssh-keygen으로 키 쌍 만들기
"공개키 등록한다" 서버나 GitHub에 공개키 추가
"SSH 터널링" SSH 연결을 통해 다른 포트 연결 (포트 포워딩)
"22번 포트 열어줘" 방화벽에서 SSH 접속 허용

프로토콜 vs 구현체 (OpenSSH)

"OpenSSH 설치해"라는 말을 들어본 적 있나요?

"축구 규칙" vs "축구공, 축구화" │ │ 규칙 자체 실제 도구 (프로토콜) (구현체)
개념 설명
SSH "이런 방식으로 원격 접속해라"라는 규칙 (프로토콜)
OpenSSH 그 규칙을 실제로 수행하는 프로그램 (구현체)

"OpenSSH 설치해" =

SSH 접속 기능을 쓸 수 있는 프로그램을 설치해!

Open = 오픈소스. 누구나 무료로 쓸 수 있고, 코드가 공개되어 있어요.

리눅스, 맥에는 기본 설치되어 있고, 윈도우 10 이상도 기본 탑재!

관련 도구들

도구 설명
OpenSSH SSH 프로토콜의 오픈소스 구현체 (가장 많이 사용)
PuTTY 윈도우용 SSH 클라이언트 (GUI)
SCP SSH로 파일 복사 (Secure Copy)
SFTP SSH로 파일 전송 (Secure FTP)
