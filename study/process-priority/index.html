게임 중 Alt+Tab 하면 왜 프레임이 떨어질까?

프로세스 우선순위와 CPU 스케줄링

Part 1. 경험에서 시작하기

LOL 하다가 카톡 확인하려고 Alt+Tab 했어. 다시 돌아왔더니 렉걸려. 왜?

아, 이거 다들 겪어봤지?

게임은 분명 계속 돌아가는데, 백그라운드로 가면 갑자기 버벅거림.

이유가 뭘까?

컴퓨터가 카톡한테 CPU를 더 줘서?

거의 맞아! 좀 더 정확히 말하면:

Windows가 "지금 사용자가 보고 있는 앱"에 더 많은 자원을 줘.

백그라운드 앱은 "잠깐 쉬어"라고 하는 거야.

Part 2. 왜 그런 설계를 했을까?

왜 백그라운드 앱한테 똑같이 안 줘?

생각해봐. 네 컴퓨터에 지금 뭐가 돌아가고 있어?

작업 관리자 열어보면: ┌────────────────────────────────────────────────────┐ │ 이름 │ CPU │ 메모리 │ 상태 │ ├────────────────────────────────────────────────────┤ │ Chrome (12개 탭) │ 3% │ 2GB │ 백그라운드│ │ Discord │ 1% │ 300MB │ 백그라운드│ │ Spotify │ 0% │ 200MB │ 백그라운드│ │ Windows Defender │ 2% │ 150MB │ 백그라운드│ │ OneDrive │ 0% │ 100MB │ 백그라운드│ │ Steam │ 1% │ 250MB │ 백그라운드│ │ ... (30개 더) │ │ │ │ ├────────────────────────────────────────────────────┤ │ 게임.exe │ 40% │ 4GB │ 포그라운드│ └────────────────────────────────────────────────────┘ 백그라운드 앱이 수십 개! 다 똑같이 CPU 주면? → 게임 프레임 반토막
아, 그래서 "지금 보는 것"에 집중하는구나?

맞아! 이게 포그라운드 부스트 (Foreground Boost)야.

Windows의 핵심 설계 철학이지.

🍽️ 비유: 뷔페 레스토랑

뷔페에서 음식을 담고 있어.
10명이 줄 서있어. 다들 같은 양만큼 담을 수 있어.

근데 지금 접시를 들고 있는 사람은?
→ 좀 더 여유있게 담을 수 있어!
→ 뒤에 기다리는 사람들은 잠깐 참아야 해.

포그라운드 = 지금 접시 들고 있는 사람
백그라운드 = 줄 서서 기다리는 사람

Part 3. 구체적으로 뭐가 달라지는데?

포그라운드랑 백그라운드 차이가 뭐야?

세 가지가 달라져:

포그라운드 vs 백그라운드: 1️⃣ CPU 시간 할당량 (Time Slice) ─────────────────────────────────────────────────── 포그라운드: 긴 시간 할당 (약 60ms) 백그라운드: 짧은 시간 할당 (약 20ms) → 포그라운드 앱이 3배 더 오래 CPU 사용 가능! 2️⃣ 우선순위 부스트 ─────────────────────────────────────────────────── 포그라운드: 우선순위 +2 자동 부스트 백그라운드: 부스트 없음 → 다른 앱보다 먼저 실행될 확률 증가! 3️⃣ 타이머 정밀도 ─────────────────────────────────────────────────── 포그라운드: 1ms 타이머 사용 가능 백그라운드: 15.6ms 타이머로 강제 전환 → 게임 루프의 정밀도가 떨어짐! 60 FPS = 16.6ms마다 프레임 타이머가 15.6ms면? 프레임 타이밍 엉망!
타이머 정밀도가 15.6ms? 그게 왜 문제야?

게임 루프를 생각해봐:

게임 루프 타이밍: 포그라운드 (1ms 타이머): ┌─────────────────────────────────────────────────┐ │ Frame 1 Frame 2 Frame 3 Frame 4│ │ [16.6ms] [16.6ms] [16.6ms] [16.6ms]│ │ ████████ ████████ ████████ ████████│ └─────────────────────────────────────────────────┘ 정확한 60 FPS! ✅ 백그라운드 (15.6ms 타이머): ┌─────────────────────────────────────────────────┐ │ Frame 1 Frame 2 Frame 3 │ │ [15.6ms] [31.2ms!] [15.6ms] │ │ ███████ ██████████████ ███████ │ └─────────────────────────────────────────────────┘ 프레임 시간이 들쭉날쭉! 끊김 발생! ❌ Sleep(16)을 호출해도: - 1ms 타이머: 실제로 16~17ms 후 깨어남 ✅ - 15.6ms 타이머: 15.6ms 또는 31.2ms 후 깨어남 ❌

Part 4. 우선순위 시스템 이해하기

우선순위가 정확히 뭐야? 숫자로 되어있어?

응! Windows에서 모든 프로세스/스레드는 우선순위 숫자를 가져.

숫자가 높을수록 CPU를 먼저 받아.

Windows 우선순위 클래스: ┌─────────────────┬────────┬────────────────────────┐ │ 클래스 │ 기본값 │ 용도 │ ├─────────────────┼────────┼────────────────────────┤ │ REALTIME │ 24 │ 절대 사용 금지! │ │ HIGH │ 13 │ 게임, 미디어 │ │ ABOVE_NORMAL │ 10 │ 중요한 작업 │ │ NORMAL │ 8 │ 대부분의 앱 (기본값) │ │ BELOW_NORMAL │ 6 │ 백그라운드 다운로드 │ │ IDLE │ 4 │ 화면 보호기, 인덱싱 │ └─────────────────┴────────┴────────────────────────┘ 숫자가 높을수록 CPU를 먼저 받음! 우선순위 13인 게임 vs 우선순위 8인 Chrome: → 게임이 먼저 CPU 시간 받음!
REALTIME은 왜 사용 금지야?

REALTIME은 Windows 커널보다 높은 우선순위야!

REALTIME 우선순위의 위험: ┌─────────────────────────────────────────────────┐ │ 우선순위 24: 내 게임 (REALTIME) │ ├─────────────────────────────────────────────────┤ │ 우선순위 16~23: Windows 커널 스레드들! │ │ - 마우스/키보드 입력 처리 │ │ - 디스크 I/O │ │ - 네트워크 처리 │ └─────────────────────────────────────────────────┘ 내 게임이 REALTIME으로 무한 루프 빠지면? → 마우스가 안 움직임! → 키보드가 안 먹힘! → Ctrl+Alt+Del도 안 됨! → 컴퓨터 강제 종료만 가능! 결론: 게임에서는 HIGH가 최선!

Part 5. 게임 개발자는 어떻게 대응해?

그럼 게임 개발할 때 어떻게 해야 해?

몇 가지 방법이 있어:

방법 1: 프로세스 우선순위 높이기 ─────────────────────────────────────────────────── 게임 시작할 때: SetPriorityClass(GetCurrentProcess(), HIGH_PRIORITY_CLASS); 효과: - 다른 일반 앱보다 CPU를 먼저 받음 - 단, 시스템 프로세스보다는 낮음 방법 2: 타이머 정밀도 유지 ─────────────────────────────────────────────────── 게임 시작할 때: timeBeginPeriod(1); // 1ms 타이머 요청 게임 종료할 때: timeEndPeriod(1); // 반드시 해제! 효과: - 백그라운드에서도 1ms 타이머 유지 - 단, 배터리 소모 증가 (노트북 주의) 방법 3: 백그라운드 감지 + 대응 ─────────────────────────────────────────────────── 포그라운드일 때: 60 FPS 렌더링 백그라운드일 때: 30 FPS로 제한 (또는 일시정지) 장점: - CPU 사용량 감소 - 발열 감소 - 다른 앱에 양보
백그라운드에서 FPS 제한하는 게 좋은 거야?

상황에 따라 달라!

게임 유형별 백그라운드 전략: 싱글플레이어 게임 (스카이림 등) ─────────────────────────────────────────────────── → 일시정지! - 어차피 보고 있지 않음 - CPU/GPU 0%로 - 복귀 시 바로 재개 멀티플레이어 게임 (LOL, 오버워치 등) ─────────────────────────────────────────────────── → 저FPS로 계속 실행 - 서버 연결 유지 필수 - 게임 상태 계속 업데이트 - 30 FPS 또는 그 이하로 제한 MMO 게임 (와우, 리니지 등) ─────────────────────────────────────────────────── → 선택적 처리 - 렌더링 중지 - 네트워크만 유지 (채팅, 파티 정보) - 중요 이벤트 알림 (공성전 시작 등) 게임 서버 ─────────────────────────────────────────────────── → 항상 풀 성능 - 백그라운드여도 플레이어들 처리해야 함 - 서비스로 실행 (우선순위 자동 관리)

Part 6. 스레드별 우선순위

게임 안에서도 스레드마다 중요도가 다르지 않아?

맞아! 게임은 보통 여러 스레드로 동작해:

게임의 멀티스레드 구조: ┌─────────────────────────────────────────────────┐ │ 게임.exe │ ├─────────────────────────────────────────────────┤ │ │ │ ┌───────────────┐ ┌───────────────┐ │ │ │ 메인 스레드 │ │ 렌더링 스레드 │ │ │ │ (게임 로직) │ │ (그래픽) │ │ │ │ 우선순위: 높음│ │ 우선순위: 높음│ │ │ └───────────────┘ └───────────────┘ │ │ │ │ ┌───────────────┐ ┌───────────────┐ │ │ │ 오디오 스레드 │ │ 네트워크 스레드│ │ │ │ (소리) │ │ (서버 통신) │ │ │ │ 우선순위: 최고│ │ 우선순위: 중간 │ │ │ └───────────────┘ └───────────────┘ │ │ │ │ ┌───────────────┐ ┌───────────────┐ │ │ │ 로딩 스레드 │ │ AI 스레드 │ │ │ │ (에셋 로드) │ │ (NPC 행동) │ │ │ │ 우선순위: 낮음│ │ 우선순위: 보통 │ │ │ └───────────────┘ └───────────────┘ │ │ │ └─────────────────────────────────────────────────┘ 왜 이렇게 설정할까?
오디오가 왜 최고 우선순위야?

소리가 0.01초만 늦어도 사람이 느껴!

인간의 감각 민감도: ┌──────────────┬─────────────┬────────────────────┐ │ 감각 │ 허용 지연 │ 지연 시 증상 │ ├──────────────┼─────────────┼────────────────────┤ │ 시각 (영상) │ 30~50ms │ 끊김 느낌 │ │ 청각 (소리) │ 5~10ms │ 뚝뚝 끊김, 팝 노이즈│ │ 입력 (조작) │ 50~100ms │ 답답함 │ └──────────────┴─────────────┴────────────────────┘ 귀가 눈보다 지연에 민감해! 그래서: - 오디오 스레드 = TIME_CRITICAL (최고) - 렌더링 = HIGHEST (높음) - 로딩 = BELOW_NORMAL (낮음) → 로딩은 1초 늦어도 상관없음

Part 7. CPU 코어 지정 (Affinity)

"이 스레드는 코어 0에서만 돌려!" 이런 것도 가능해?

응! CPU 친화도 (Affinity)라고 해.

8코어 CPU에서 게임 최적화: ┌────────────────────────────────────────────────┐ │ Core 0 │ Core 1 │ Core 2 │ Core 3 │ │ │ 메인 │ 렌더링 │ 오디오 │ 물리 │ ← P-코어 │ │ 게임 │ │ │ │ (성능) │ ├────────┼────────┼────────┼────────┤ │ │ Core 4 │ Core 5 │ Core 6 │ Core 7 │ │ │ 로딩1 │ 로딩2 │ AI │네트워크│ ← E-코어 │ │ │ │ │ │ (효율) │ └────────────────────────────────────────────────┘ 장점: - 중요한 스레드는 빠른 P-코어에서 - 덜 중요한 건 E-코어에서 (전력 절약) - 캐시 효율 증가 (같은 코어 유지) 단점: - OS 자동 최적화 무시됨 - 다른 앱과 충돌 가능 - 설정 잘못하면 오히려 성능 저하 결론: 대부분의 경우 OS에 맡기는 게 나음! 특수한 경우 (콘솔 게임 등)에만 직접 설정

Part 8. 정리: 백그라운드 문제 해결법

처음 질문으로 돌아가면, 어떻게 해결해?

이제 완벽히 이해했지?

"게임 중 Alt+Tab 하면 프레임 떨어짐" 해결: 원인: ─────────────────────────────────────────────────── 1. 포그라운드 부스트 사라짐 (CPU 시간 1/3) 2. 타이머 정밀도 저하 (15.6ms) 3. 우선순위 부스트 사라짐 게임 개발자 해결책: ─────────────────────────────────────────────────── 1. 프로세스 우선순위 HIGH로 설정 2. timeBeginPeriod(1) 호출 3. 백그라운드 감지 + FPS 제한 유저 해결책: ─────────────────────────────────────────────────── 1. 게임 옵션: "백그라운드에서 실행" 체크 2. 작업 관리자: 게임 우선순위 "높음"으로 3. Windows 게임 모드 활성화 4. 창 모드 대신 전체 화면 모드 사용
Windows 게임 모드: 설정 > 게임 > 게임 모드 > 켬 효과: ┌────────────────────────────────────────────────┐ │ ✅ Windows Update 일시 중지 │ │ ✅ 드라이버 설치 중지 │ │ ✅ 알림 최소화 │ │ ✅ 백그라운드 앱 리소스 제한 │ │ ✅ 게임에 더 많은 CPU/GPU 할당 │ └────────────────────────────────────────────────┘ 게임할 때 자동으로 최적화해줌!

📌 핵심 정리

  • 포그라운드 부스트 - 활성 창에 3배 더 많은 CPU 시간
  • 타이머 정밀도 - 백그라운드에서 15.6ms로 저하 (1ms에서)
  • 우선순위 클래스 - HIGH 권장, REALTIME은 절대 금지
  • 스레드 우선순위 - 오디오 > 렌더링 > 로직 > 로딩
  • 백그라운드 대응 - 멀티플레이는 저FPS, 싱글은 일시정지
  • Windows 게임 모드 - 자동으로 게임 최적화
