게임이 백그라운드로 가면 왜 느려질까?

프로세스 우선순위와 CPU 스케줄링

Part 1. 백그라운드에서 느려지는 이유

게임 중에 Alt+Tab 하면 왜 프레임이 떨어져?

Windows가 포그라운드 프로세스에 더 많은 CPU 시간을 할당하기 때문이야!

포그라운드 vs 백그라운드: +------------------------------------------------------------+ | 포그라운드 프로세스 (게임이 활성화) | | | | CPU 타임 슬라이스: 더 김 (3배 정도) | | 우선순위 부스트: 있음 | | 타이머 정밀도: 높음 (1ms) | | | | -> 60 FPS 유지 가능! | +------------------------------------------------------------+ Alt+Tab 후: +------------------------------------------------------------+ | 백그라운드 프로세스 (게임이 최소화) | | | | CPU 타임 슬라이스: 짧음 (기본값) | | 우선순위 부스트: 없음 | | 타이머 정밀도: 낮음 (15.6ms) | | | | -> FPS 급락! (10~30 FPS) | +------------------------------------------------------------+ Windows의 설계 의도: - 사용자가 보고 있는 앱에 리소스 집중 - 백그라운드 앱은 최소한만 동작 - 배터리/발열 관리 (노트북)

Part 2. Windows 우선순위 시스템

프로세스 우선순위가 뭐야?

OS가 CPU 시간을 배분할 때 어떤 프로세스를 먼저 실행할지 결정하는 기준이야.

Windows 우선순위 클래스 (프로세스): +--------------------+--------+--------------------------------+ | 클래스 | 기본값 | 용도 | +--------------------+--------+--------------------------------+ | REALTIME | 24 | 시스템 위험! 커널보다 높음 | | HIGH | 13 | 게임, 미디어 플레이어 | | ABOVE_NORMAL | 10 | 중요한 백그라운드 작업 | | NORMAL | 8 | 대부분의 앱 (기본값) | | BELOW_NORMAL | 6 | 백그라운드 다운로드 | | IDLE | 4 | 화면 보호기, 인덱싱 | +--------------------+--------+--------------------------------+ 스레드 우선순위 (프로세스 클래스 기준으로 조정): +--------------------+----------+ | 스레드 우선순위 | 조정값 | +--------------------+----------+ | TIME_CRITICAL | +15 | | HIGHEST | +2 | | ABOVE_NORMAL | +1 | | NORMAL | 0 | | BELOW_NORMAL | -1 | | LOWEST | -2 | | IDLE | -15 | +--------------------+----------+ 최종 우선순위 = 프로세스 클래스 기본값 + 스레드 조정값 예: NORMAL 프로세스의 HIGHEST 스레드 = 8 + 2 = 10
우선순위가 높으면 무조건 빨라?

항상 그런 건 아니야. 우선순위 역전이나 기아 상태가 발생할 수 있어!

우선순위의 함정들: 1. 우선순위 역전 (Priority Inversion) +------------------------------------------------------------+ | 상황: | | - 낮은 우선순위 스레드 L이 락 획득 | | - 높은 우선순위 스레드 H가 같은 락 대기 | | - 중간 우선순위 스레드 M이 CPU 점유 | | | | 결과: H가 M보다 늦게 실행됨! (역전) | | | | 해결: 우선순위 상속 (L의 우선순위를 H로 임시 상승) | +------------------------------------------------------------+ 2. 기아 상태 (Starvation) +------------------------------------------------------------+ | 상황: | | - 높은 우선순위 스레드들이 계속 실행 | | - 낮은 우선순위 스레드가 영원히 대기 | | | | 해결: Windows의 "우선순위 부스트" | | - 오래 대기한 스레드 우선순위 임시 상승 | | - I/O 완료 시 우선순위 상승 | +------------------------------------------------------------+ 3. REALTIME 클래스의 위험 +------------------------------------------------------------+ | - 커널 스레드보다 높은 우선순위 | | - 시스템 응답 불가 상태 유발 가능 | | - 마우스, 키보드 입력 처리 지연 | | | | 게임에서 REALTIME 사용 금지! | +------------------------------------------------------------+

Part 3. 게임에서 우선순위 설정하기

게임 성능을 위해 어떻게 설정해야 해?

HIGH 우선순위가 적절해. 코드로 설정하는 방법을 보여줄게.

// 프로세스 우선순위 설정 #include <windows.h> void SetGamePriority() { // 현재 프로세스 핸들 얻기 HANDLE hProcess = GetCurrentProcess(); // HIGH 우선순위 설정 (게임에 적합) SetPriorityClass(hProcess, HIGH_PRIORITY_CLASS); // 확인 DWORD priority = GetPriorityClass(hProcess); printf("Priority: %d\n", priority); // 0x80 = HIGH } // 스레드 우선순위 설정 void SetThreadPriorities() { // 메인 스레드 (게임 로직): 높음 SetThreadPriority(GetCurrentThread(), THREAD_PRIORITY_HIGHEST); // 렌더링 스레드: 높음 SetThreadPriority(hRenderThread, THREAD_PRIORITY_HIGHEST); // 오디오 스레드: 타임 크리티컬 (끊김 방지) SetThreadPriority(hAudioThread, THREAD_PRIORITY_TIME_CRITICAL); // 백그라운드 로딩 스레드: 낮음 (게임 성능 영향 최소화) SetThreadPriority(hLoadingThread, THREAD_PRIORITY_BELOW_NORMAL); // 네트워크 스레드: 보통 이상 SetThreadPriority(hNetworkThread, THREAD_PRIORITY_ABOVE_NORMAL); }
게임 스레드별 권장 우선순위: +--------------------+--------------------+----------------------+ | 스레드 | 우선순위 | 이유 | +--------------------+--------------------+----------------------+ | 메인 (게임 로직) | HIGHEST | 프레임 유지 | | 렌더링 | HIGHEST | 화면 끊김 방지 | | 오디오 | TIME_CRITICAL | 소리 끊김 방지 | | 물리 시뮬레이션 | ABOVE_NORMAL | 안정적 업데이트 | | 네트워크 | ABOVE_NORMAL | 지연 최소화 | | AI 계산 | NORMAL | 기본 | | 리소스 로딩 | BELOW_NORMAL | 프레임 영향 최소화 | | 로그 기록 | LOWEST | 필요할 때만 | +--------------------+--------------------+----------------------+

Part 4. 백그라운드에서도 성능 유지하기

게임이 백그라운드여도 서버는 돌아가야 하는데?

몇 가지 방법이 있어!

// 1. 타이머 정밀도 유지 // 백그라운드에서 타이머 정밀도가 15.6ms로 떨어지는 것 방지 #include <timeapi.h> #pragma comment(lib, "winmm.lib") void KeepHighTimerResolution() { // 1ms 타이머 정밀도 요청 timeBeginPeriod(1); // 게임 종료 시 반드시 해제! // timeEndPeriod(1); } // 2. 백그라운드 감지 및 대응 HWND g_hWnd; bool g_isBackground = false; LRESULT CALLBACK WndProc(HWND hWnd, UINT msg, WPARAM w, LPARAM l) { switch (msg) { case WM_ACTIVATEAPP: g_isBackground = (w == FALSE); if (g_isBackground) { // 백그라운드 진입: FPS 제한으로 CPU 사용량 감소 SetTargetFPS(30); // 또는 일시정지 // PauseGame(); } else { // 포그라운드 복귀: 원래 FPS로 SetTargetFPS(60); } break; } return DefWindowProc(hWnd, msg, w, l); } // 3. "백그라운드에서도 실행" 옵션 구현 void GameLoop() { while (running) { if (g_isBackground && !g_runInBackground) { // 백그라운드 + 옵션 꺼짐 = 최소 동작 Sleep(100); // CPU 쉬게 함 ProcessNetworkOnly(); // 네트워크만 처리 } else { // 정상 실행 Update(); Render(); } } }
게임 백그라운드 처리 전략: +------------------------------------------------------------+ | 전략 1: 일시정지 | +------------------------------------------------------------+ | - 싱글플레이어 게임에 적합 | | - CPU/GPU 사용량 0에 가까움 | | - 복귀 시 바로 재개 | +------------------------------------------------------------+ +------------------------------------------------------------+ | 전략 2: FPS 제한 | +------------------------------------------------------------+ | - 멀티플레이어 게임에 적합 | | - 30 FPS 또는 그 이하로 제한 | | - 네트워크, AI는 계속 동작 | | - CPU 사용량 50% 이상 감소 | +------------------------------------------------------------+ +------------------------------------------------------------+ | 전략 3: 선택적 처리 | +------------------------------------------------------------+ | - 네트워크만 처리 (연결 유지) | | - 중요 타이머만 동작 (경매 종료 등) | | - 렌더링 완전 중지 | | - 게임 서버에 적합 | +------------------------------------------------------------+ 전문 MMO의 선택: - 포그라운드: 60 FPS 풀 렌더링 - 백그라운드: 렌더링 중지, 로직만 10 FPS - 최소화: 네트워크만 유지, 1초 간격 처리

Part 5. CPU 친화도 (Affinity)

특정 코어에서만 실행하게 할 수 있어?

CPU 친화도(Affinity)를 설정하면 돼!

// CPU 친화도 설정 void SetCPUAffinity() { // 현재 시스템의 CPU 정보 SYSTEM_INFO sysInfo; GetSystemInfo(&sysInfo); printf("CPU 코어 수: %d\n", sysInfo.dwNumberOfProcessors); // 프로세스를 특정 코어에 고정 HANDLE hProcess = GetCurrentProcess(); // 비트마스크: 코어 0, 1만 사용 // 0b0011 = 0x3 = 코어 0, 1 DWORD_PTR affinityMask = 0x3; SetProcessAffinityMask(hProcess, affinityMask); // 스레드별로 다른 코어 지정 // 렌더링: 코어 0 SetThreadAffinityMask(hRenderThread, 0x1); // 게임 로직: 코어 1 SetThreadAffinityMask(hGameThread, 0x2); // 오디오: 코어 2 SetThreadAffinityMask(hAudioThread, 0x4); // 로딩: 코어 3, 4, 5, 6, 7 (나머지 코어) SetThreadAffinityMask(hLoadingThread, 0xF8); } // 이상적인 코어 지정 (OS 추천) void UseIdealProcessor() { // OS가 추천하는 최적의 코어 DWORD ideal = SetThreadIdealProcessor( GetCurrentThread(), MAXIMUM_PROCESSORS // OS가 선택 ); printf("추천 코어: %d\n", ideal); }
CPU 친화도 활용 예시: 8코어 CPU에서 게임 최적화: +------+------+------+------+------+------+------+------+ | C0 | C1 | C2 | C3 | C4 | C5 | C6 | C7 | +------+------+------+------+------+------+------+------+ | Game | Rend | Audi | Phys | Load | Load | AI | Net | | Loop | er | o | ics | er1 | er2 | | work | +------+------+------+------+------+------+------+------+ ^ ^ | | P-코어 E-코어 (효율코어) (성능코어) (저전력 작업용) 인텔 12세대+ 하이브리드 CPU 팁: - 게임 로직, 렌더링 -> P-코어 고정 - 백그라운드 로딩, 네트워크 -> E-코어 - Windows 11이 자동 최적화하지만, 수동 설정이 더 효과적일 수 있음 주의: - 친화도 고정하면 OS 자동 최적화 무시됨 - 다른 프로그램과 충돌 가능 - 대부분의 경우 OS에 맡기는 게 나음

Part 6. 게임 최적화 설정

Windows 게임 모드가 뭐야?

Windows 10 이상에서 제공하는 게임 전용 최적화 모드야!

Windows 게임 모드 효과: +------------------------------------------------------------+ | 게임 모드 활성화 시: | | | | 1. Windows Update 일시 중지 | | 2. 드라이버 설치 중지 | | 3. 알림 최소화 | | 4. 백그라운드 앱 리소스 제한 | | 5. 게임에 더 많은 CPU/GPU 리소스 할당 | +------------------------------------------------------------+ 설정 방법: - 설정 > 게임 > 게임 모드 > 켬 - Win+G > 게임 바 > 성능 위젯 추가 최적화 (수동): +------------------------------------------------------------+ | 1. 고성능 전원 관리 | | 제어판 > 전원 옵션 > 고성능 | | | | 2. 하드웨어 가속 GPU 스케줄링 | | 설정 > 시스템 > 디스플레이 > 그래픽 > 켬 | | | | 3. 가변 새로 고침 빈도 (VRR) | | G-Sync / FreeSync 모니터 필요 | | | | 4. 게임 전용 GPU 지정 | | 설정 > 시스템 > 디스플레이 > 그래픽 > 앱 추가 | +------------------------------------------------------------+

핵심 정리

  • 포그라운드 부스트 - Windows가 활성 창에 더 많은 CPU 시간 할당
  • 우선순위 클래스 - REALTIME > HIGH > ABOVE_NORMAL > NORMAL > BELOW_NORMAL > IDLE
  • 게임 권장 - HIGH 클래스, 중요 스레드는 HIGHEST
  • REALTIME 금지 - 시스템 불안정 유발, 게임에서 사용하지 말 것
  • 백그라운드 대응 - FPS 제한, 선택적 처리, 타이머 정밀도 유지
  • CPU 친화도 - 특정 코어에 스레드 고정 가능, 대부분 OS에 맡기는 게 나음
  • Windows 게임 모드 - 백그라운드 앱 제한, 알림 최소화
