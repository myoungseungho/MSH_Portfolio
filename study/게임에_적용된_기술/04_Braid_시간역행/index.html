시간을 되돌리면 뭘 저장해야 할까?

Braid의 시간 역행 메커니즘 - 과거로 돌아가는 기술

Part 1. 시간 되돌리기가 뭐야?

Braid 게임은 뭐가 특별해?

언제든지 시간을 되감을 수 있어.

실수했으면? → Shift 누르면 과거로 돌아감.

체크포인트도, 세이브/로드도 없이 자유롭게.

그냥 "실행 취소" 아니야?

훨씬 복잡해.


"실행 취소"는 내 행동만 되돌려.

근데 Braid는 세상 전체가 되돌아가.

• 적이 움직인 것도 되돌아감

• 떨어지던 물체도 되돌아감

• 불이 꺼졌던 것도 다시 켜짐

📼 비유: VHS 되감기

• 영화 보다가 되감기 버튼 누르면?
• 배우만 되돌아가는 게 아니라 화면 전체가 되돌아가지
• 배경, 음악, 효과, 모든 게 같이 되감김

Braid = 게임 세계 전체를 "녹화"하고 "되감기"
왜 이게 기술적으로 어려워?

매 프레임마다 모든 것의 상태를 기억해야 해.


60 FPS × 60초 = 3,600 프레임

각 프레임마다 수백 개 오브젝트의 상태...


메모리가 터질 수 있어.

Part 2. 스냅샷 저장 - 매 프레임 "사진" 찍기

어떤 걸 저장해야 해?

되돌렸을 때 복원해야 하는 모든 것.


• 플레이어 위치, 속도, 방향

• 적 위치, 상태(살아있음/죽음)

• 오브젝트 위치(열쇠, 문, 레버...)

• 퍼즐 상태(스위치 ON/OFF...)

저장 안 해도 되는 건?

계산으로 복원 가능한 것은 저장 안 해도 돼.


예: 파티클 효과

→ 저장: "폭발 시작 시간, 위치"

→ 복원: 시간에 맞춰 다시 계산


이렇게 하면 메모리를 아낄 수 있어.

// 프레임 스냅샷 구조 struct FrameSnapshot { float timestamp; // 플레이어 상태 Vector2 playerPosition; Vector2 playerVelocity; bool isJumping; // 적들 상태 (배열) EnemyState[] enemies; // 오브젝트 상태 Dictionary<int, ObjectState> objects; } // 매 프레임마다 스냅샷 저장 List<FrameSnapshot> timeline = new List<FrameSnapshot>();
시간 흐름 → ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ │ F1 │→│ F2 │→│ F3 │→│ F4 │→│ F5 │ ... │ │ │ │ │ │ │ │ │ 현재│ └─────┘ └─────┘ └─────┘ └─────┘ └─────┘ Shift 누르면 (되감기): ┌─────┐ ┌─────┐ ┌─────┐ │ F1 │←│ F2 │←│ F3 │ ← 과거로 이동 └─────┘ └─────┘ └─────┘

타임라인 = 스냅샷들의 배열, 되감기 = 배열을 역순으로 재생

Part 3. 메모리 최적화 - 어떻게 용량을 줄여?

매 프레임 저장하면 메모리 터지지 않아?

그래서 최적화가 필요해.


몇 가지 기법이 있어:

첫 번째 최적화는?

델타 압축 (Delta Compression)


전체 상태 대신 "변한 것만" 저장해.


예: 적이 안 움직였으면 → 저장 안 함

플레이어만 움직였으면 → 플레이어 상태만 저장

❌ 풀 스냅샷 (비효율): F1: {플레이어:(10,5), 적A:(50,10), 적B:(80,10), 문:닫힘} F2: {플레이어:(12,5), 적A:(50,10), 적B:(80,10), 문:닫힘} F3: {플레이어:(14,5), 적A:(50,10), 적B:(80,10), 문:닫힘} ↑ 적과 문은 안 변했는데 계속 저장 ✅ 델타 압축 (효율): F1: {플레이어:(10,5), 적A:(50,10), 적B:(80,10), 문:닫힘} F2: {플레이어:(12,5)} ← 변한 것만! F3: {플레이어:(14,5)}

변하지 않은 값은 이전 프레임 값을 그대로 사용

두 번째 최적화는?

키프레임 (Keyframe)


N프레임마다 한 번씩 전체 스냅샷을 저장.

그 사이는 델타만 저장.


복원할 때: 가장 가까운 키프레임부터 시작해서 델타 적용.

// 키프레임 + 델타 저장 void SaveFrame(int frameNumber) { if (frameNumber % KEYFRAME_INTERVAL == 0) { // 키프레임: 전체 상태 저장 SaveFullSnapshot(frameNumber); } else { // 델타: 변경된 것만 저장 SaveDeltaSnapshot(frameNumber, previousFrame); } } // 특정 프레임으로 복원 void RestoreFrame(int targetFrame) { // 1. 가장 가까운 키프레임 찾기 int keyframe = (targetFrame / KEYFRAME_INTERVAL) * KEYFRAME_INTERVAL; // 2. 키프레임 로드 LoadFullSnapshot(keyframe); // 3. 타겟까지 델타 적용 for (int f = keyframe + 1; f <= targetFrame; f++) { ApplyDelta(f); } }
방법 장점 단점
매 프레임 풀 스냅샷 복원 빠름 메모리 많이 사용
델타 압축만 메모리 적음 처음부터 재계산 필요
키프레임 + 델타 균형 잡힘 구현 복잡

Part 4. 되감기 재생 - 어떻게 부드럽게?

되감기할 때 그냥 이전 프레임 보여주면 되는 거 아니야?

그러면 뚝뚝 끊겨 보여.


되감기 속도가 다를 수 있어:

• 천천히 되감기

• 빠르게 되감기


프레임 사이를 보간해야 부드러워.

보간이 뭐야?

두 상태 사이의 중간값을 계산하는 것.


예: F1에서 위치가 (10, 5), F2에서 (20, 5)

되감기 중 F1.5 시점이면? → (15, 5)

// 보간으로 부드러운 되감기 void UpdateRewind(float rewindSpeed) { // 되감기 시간 업데이트 currentTime -= rewindSpeed * deltaTime; // 현재 시간에 해당하는 두 프레임 찾기 int frameA = Floor(currentTime / frameDuration); int frameB = frameA + 1; // 두 프레임 사이의 비율 (0~1) float t = (currentTime % frameDuration) / frameDuration; // 보간 player.position = Lerp( snapshots[frameA].playerPosition, snapshots[frameB].playerPosition, t ); }
뭘 보간하고 뭘 안 해?

연속적인 값은 보간:

→ 위치, 회전, 크기


이산적인 값은 그대로:

→ 살았다/죽었다, 문 열림/닫힘, 아이템 획득 여부

Part 5. 시간 면역 - "빛나는" 오브젝트

Braid에서 빛나는 물체는 되감기해도 안 돌아가던데?

시간 면역 (Time Immune) 오브젝트야.


Braid 퍼즐의 핵심 메커니즘 중 하나.

시간을 되돌려도 현재 상태를 유지해.

어떻게 구현해?

되감기할 때 면역 플래그가 있는 오브젝트는 건너뛰기.

// 시간 면역 처리 void RestoreFrame(int targetFrame) { foreach (var obj in allObjects) { if (obj.isTimeImmune) { // 시간 면역: 현재 상태 유지 continue; } // 일반 오브젝트: 스냅샷에서 복원 obj.RestoreFromSnapshot(snapshots[targetFrame]); } }
이게 퍼즐에 어떻게 쓰여?

예시 퍼즐:


1. 열쇠(시간 면역)를 들고 문을 연다

2. 문 안으로 들어간다

3. 시간을 되돌린다

4. 열쇠는 여전히 손에 있음 (면역이니까)

5. 근데 과거의 "나"도 열쇠가 필요해!


이런 식으로 시간 패러독스를 퍼즐로 만듦.

🌟 비유: 영화 촬영

• 일반 오브젝트 = 배우 (되감으면 원래 위치로)
• 시간 면역 오브젝트 = 카메라맨 (필름 되감아도 그 자리에 있음)

시간 면역 = "메타 레이어"에 존재하는 오브젝트

Part 6. 그림자 시스템 - 과거의 "나"

Braid에서 "그림자"가 나오는 스테이지가 있던데?

World 4의 핵심 메커니즘이야.


시간을 되돌리면 "과거의 나"가 그림자로 나타나

이전에 했던 행동을 그대로 반복해.

어떻게 구현해?

입력 기록 (Input Recording)을 써.


1. 플레이어의 모든 입력을 프레임별로 기록

2. 되감기 후, 기록된 입력을 "그림자"에게 재생

3. 그림자는 과거의 나처럼 움직임

// 입력 기록 struct InputFrame { int frameNumber; bool left, right, jump; } List<InputFrame> inputHistory = new List<InputFrame>(); // 매 프레임 입력 저장 void RecordInput() { inputHistory.Add(new InputFrame { frameNumber = currentFrame, left = Input.GetKey(KeyCode.Left), right = Input.GetKey(KeyCode.Right), jump = Input.GetKey(KeyCode.Space) }); } // 그림자: 기록된 입력 재생 void UpdateShadow() { InputFrame input = inputHistory[shadow.playbackFrame]; if (input.left) shadow.MoveLeft(); if (input.right) shadow.MoveRight(); if (input.jump) shadow.Jump(); shadow.playbackFrame++; }
시간 흐름: [현재의 나] ─────────────────────→ (계속 진행) │ │ 되감기 ↓ [그림자 생성] ═══════════════════→ (과거 입력 재생) │ │ 다시 플레이 ↓ [현재의 나] ─────────────────────→ (새로운 입력) → 그림자와 현재의 나가 "협력"해서 퍼즐을 풂

그림자 = 과거 입력의 "녹화 재생", 나 = 새로운 입력

왜 상태가 아니라 입력을 기록해?

메모리 절약 + 물리 일관성


상태 저장: 위치, 속도, 애니메이션... 많은 데이터

입력 저장: 버튼 3개의 true/false... 아주 작음


그리고 입력을 재생하면 물리 엔진이 똑같이 계산해줘.

📌 핵심 정리

  • 스냅샷 저장 - 매 프레임 모든 오브젝트 상태를 타임라인에 기록
  • 델타 압축 - 변경된 값만 저장해서 메모리 절약
  • 키프레임 - N프레임마다 전체 스냅샷, 그 사이는 델타
  • 보간 - 프레임 사이를 부드럽게 연결, 위치/회전 등 연속값에 적용
  • 시간 면역 - 되감아도 현재 상태 유지하는 특수 오브젝트
  • 그림자 시스템 - 입력 기록 → 재생으로 "과거의 나" 구현
