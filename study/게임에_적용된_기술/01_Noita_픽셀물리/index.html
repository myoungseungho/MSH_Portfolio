모래 한 알이 어떻게 떨어질까?

Noita의 픽셀 물리 시뮬레이션 - 수백만 픽셀이 살아 움직이는 비밀

Part 1. 일반 게임이랑 뭐가 달라?

대부분 게임은 오브젝트 단위로 물리 처리하잖아. 플레이어, 적, 상자... 이런 식으로. Noita는 뭐가 달라?

픽셀 하나하나가 독립적인 물질이야.

모래 한 알, 물 한 방울, 불꽃 하나... 전부 개별적으로 시뮬레이션돼.

시뮬레이션: 전체 데모

모래, 물, 돌, 불이 모두 상호작용하며 복잡한 현상 발생

전통적 게임 Noita
플레이어 (1개 오브젝트) 플레이어 모양의 픽셀 집합
벽 (정적 충돌체) 벽 모양의 픽셀들 (부술 수 있음)
물 (파티클 효과) 물 픽셀 수천 개 (실제 흐름)
그래서 뭐가 좋은데?

창발적 게임플레이 (Emergent Gameplay)

개발자가 만드는 건:

• 기본 규칙: 물은 아래로, 불은 위로, 물+불=증기

• 물질 속성: 모래는 무거움, 물은 가벼움


개발자가 안 만드는 건:

• "폭발하면 물 나오는 이벤트" 같은 특정 시나리오

전통 게임 방식: if (폭발) { 벽.Destroy(); SpawnWaterParticle(); // 물 파티클 생성 (연출) if (아래에 불) { 물.Stop(); // 물 멈춤 SpawnSteam(); // 증기 연출 } } → 모든 경우의 수를 일일이 스크립팅 Noita 방식: // 기본 규칙만 정의 물 규칙: 아래 빈칸이면 이동, 불 만나면 증기로 변환 불 규칙: 위로 올라감, 물 만나면 증기로 변환 벽 규칙: 폭발 피해 받으면 사라짐 → 이 규칙들이 조합되어 자연스럽게: 1. 폭발 → 벽 사라짐 (벽 규칙) 2. 물 떨어짐 (물 규칙: 중력) 3. 물+불 만남 → 증기 (물+불 반응 규칙) → 개발자가 "폭발→물→불→증기" 전체 시퀀스를 일일이 프로그래밍 안 했는데 알아서 발생!

시뮬레이션: 댐 붕괴

돌로 만든 벽을 지우면 물이 쏟아져 나옴 - "댐 붕괴" 이벤트를 따로 안 만들었는데 자연스럽게 발생

그러면 물+불=증기 규칙은 있는 거네? 아까 "규칙 안 만든다"고 하지 않았어?

정확해! 헷갈리게 해서 미안해.

물+불=증기 규칙은 있어. (Part 5에서 자세히 다룰게)


차이점은:

전통 게임 Noita
"이 특정 상황에서 이렇게 해라"
(시나리오 중심)		 "이 물질들은 이런 속성을 가져"
(규칙 중심)
폭발 이벤트 안에
물 소멸 + 증기 생성 코드		 물 픽셀이 불 픽셀 만나면
각자 반응 (독립적)
100가지 상황 = 100개 스크립트 10가지 규칙 = 무수한 조합

예시로 이해해보자:

상황: 기름 웅덩이 위에 물이 있고, 불이 붙었다 전통 게임: → 개발자가 "기름+물+불" 이 특정 조합을 미리 예상하고 코딩했으면 → 작동 → 예상 못 했으면 → 이상하게 동작 또는 아무 일도 안 일어남 Noita: → 불이 기름 만남 → 기름 점화 (기름+불 규칙) → 기름 불이 물 만남 → 증기 (물+불 규칙) → 동시에 기름이 확산 (기름 규칙: 옆으로 퍼짐) → 폭발적으로 번짐 → 개발자가 "기름+물+불" 조합을 특별히 안 만들었는데 각 물질의 규칙이 조합되어 알아서 이렇게 됨!

Part 2. 어떻게 구현해? - Cellular Automata

수백만 픽셀을 어떻게 시뮬레이션해? 너무 복잡하지 않아?

핵심 아이디어: Cellular Automata (셀룰러 오토마타)

각 픽셀은 주변 픽셀만 보고 다음 상태를 결정

Cellular Automata 기본 개념: 1. 격자 (Grid) 구조 ┌─┬─┬─┐ │ │ │ │ ← 각 칸 = 1픽셀 ├─┼─┼─┤ │ │■│ │ ■ = 현재 픽셀 ├─┼─┼─┤ │ │ │ │ └─┴─┴─┘ 2. 각 픽셀은 상태(State)를 가짐 - 타입: 빈칸 / 모래 / 물 / 돌... - 속도, 온도 등 3. 규칙(Rule)에 따라 다음 상태로 전환 next_state = f(현재 상태, 주변 상태) 4. 모든 픽셀이 동시에 업데이트
아직도 추상적이야. 구체적 예시 없어?

유명한 예시: Conway's Game of Life

Game of Life 규칙 (4개뿐): 1. 살아있는 셀 + 이웃 2~3개 → 생존 2. 살아있는 셀 + 이웃 <2개 → 사망 (고립) 3. 살아있는 셀 + 이웃 >3개 → 사망 (과밀) 4. 죽은 셀 + 이웃 =3개 → 탄생 → 이 단순한 4개 규칙으로: - Glider (이동하는 패턴) - Spaceship (복잡한 구조체) - 예측 불가능한 진화 → 단순함 → 복잡성의 완벽한 사례
🐜 비유: 개미집

각 개미는 단순한 규칙만 따라:
- "페로몬 냄새 따라가기"
- "먹이 발견하면 집으로"
- "적 만나면 공격"

→ 개미 수백만 마리가 모이면?
복잡한 길 찾기, 협력, 전쟁 등 고도의 집단 지능 발현

Noita도 똑같아. 각 픽셀은 단순한 규칙만 따르는데,
수백만 픽셀이 모이면 → 복잡한 물리 현상

Part 3. 모래는 어떻게 떨어질까?

모래 픽셀 하나가 떨어지는 규칙은 뭐야?

생각해봐. 현실에서 모래 한 알이 어떻게 떨어져?

아래가 비었으면 떨어지고... 바닥 닿으면 멈추고...

정확해! 그게 규칙이야:

모래 규칙 (우선순위): 1. 아래 픽셀이 빈칸? → 아래로 이동 [모래] [ 빈 ] [ 빈 ] → [모래] 2. 아래가 막혔는데, 왼쪽 아래가 빈칸? → 왼쪽 아래로 [모래] [ 빈 ] [■■■] → [■모래■] 3. 오른쪽 아래도 체크 (랜덤 순서) 4. 둘 다 막혔으면 → 멈춤
왜 "랜덤 순서"야? 항상 왼쪽 먼저 체크하면 안 돼?

편향(Bias) 문제

항상 왼쪽 먼저: [모래] / 왼쪽으로만 쏠림 랜덤 순서: [모래] / \ 균등하게 분배 (자연스러운 산 모양)

시뮬레이션: 모래가 떨어지는 모습

위에서 그린 모래가 아래로 떨어지며 산 모양으로 자연스럽게 쌓임

🛠️ 직접 해보기: 모래 시뮬레이션

  1. HTML Canvas로 격자 그리기
  2. 마우스로 모래 픽셀 그리기
  3. 매 프레임 모든 모래 픽셀 업데이트:
    • isEmpty(x, y+1) → moveTo(x, y+1)
    • isEmpty(x-1, y+1) or isEmpty(x+1, y+1)

코드 100줄 안에 작동하는 모래 시뮬레이터 완성!

Part 4. 물은 어떻게 퍼질까?

모래는 이해했어. 근데 물은? 물은 옆으로도 퍼지잖아.

모래 규칙에 한 단계 추가하면 돼:

물 규칙: 1. 아래 빈칸? → 아래로 이동 (모래와 동일) 2. 대각선 아래 빈칸? → 대각선으로 (모래와 동일) 3. 옆으로 퍼지기 ← 물만의 특징! [물][빈] → [빈][물] (옆 칸이 비었으면 이동) 4. 추가: 모래와 만나면? [물] [모래] [모래] → [물] → 물이 모래보다 가벼워서 교환!
그럼 물이 무한히 퍼지는 거 아니야?

아니야. 매 프레임 한 칸씩만 이동해.

그래서 물이 천천히 퍼지는 것처럼 보여.

물질 규칙 특징
고체 (모래) 아래 + 대각선만
액체 (물) 아래 + 대각선 + 옆
기체 (증기) 위 + 대각선 위 + 옆 (물의 반대!)

시뮬레이션: 물이 퍼지는 모습

물이 아래로 떨어진 후 옆으로 퍼지며 공간을 채움

시뮬레이션: 모래와 물의 밀도 차이

모래가 물보다 무거워서 물 속을 뚫고 아래로 가라앉음

증기는 위로 올라가네?

맞아! 물 규칙을 y 방향만 반대로 하면 증기야.

추가로 수명(lifetime)을 줘서 시간 지나면 사라지게.

Part 5. 물 + 불 = 증기는 어떻게?

물이 불을 만나면 증기가 된다고 했잖아. 이건 어떻게 구현해?

반응 테이블 (Reaction Table)

매 프레임 픽셀 업데이트할 때 주변 확인:

불 픽셀 업데이트: 1. 수명 감소 (lifetime--) → 0 되면 사라짐 2. 주변 4칸 확인: 상하좌우에 물 있나? if (neighbor == 물): 나 → 증기 물 → 증기 return 3. 주변에 모래 있나? (확률적) if (random() < 0.1 && neighbor == 모래): 모래 → 불 (점화!)
모든 조합을 일일이 체크해?

그러면 조합 폭발이야.

물질 10개면 10×10 = 100개 조합...

해결책: 룩업 테이블 const REACTIONS = { "WATER + FIRE": { result: ["STEAM", "STEAM"], probability: 1.0 }, "LAVA + WATER": { result: ["STONE", "STEAM"], probability: 1.0 }, "OIL + FIRE": { result: ["FIRE", "FIRE"], // 폭발적 확산! probability: 0.8 } }; // 주변 픽셀과 반응 체크 for (reaction in REACTIONS) { if (matches(current, neighbor, reaction)) { applyReaction(reaction); break; } }

핵심: 우선순위를 정해야 해.

물+불+기름이 동시에 있으면? → 가장 위험한(폭발) 반응 먼저.

시뮬레이션: 불이 모래에 번지는 모습

불이 인접한 모래를 점화하며 옆으로 번져나감

시뮬레이션: 물 + 불 = 증기

물과 불이 만나면 증기로 변환되어 위로 올라감

Part 6. 근데 이거 느리지 않아?

1920×1080 화면 = 2백만 픽셀이야. 매 프레임 전부 업데이트하면 죽는 거 아니야?

맞아, 죽어.

순진한 방법: for (y = 0; y < 1080; y++) { for (x = 0; x < 1920; x++) { updatePixel(x, y); } } → 60 FPS = 초당 1억 2천만 번 업데이트 → 불가능
어떻게 해결해?

3가지 최적화:

1. 청크 시스템 (Chunk System)

화면을 16×16 청크로 나눔:

┌────┬────┬────┬────┐ │청크│청크│청크│청크│ 각 청크 = 16×16 픽셀 ├────┼────┼────┼────┤ │청크│청크│청크│청크│ └────┴────┴────┴────┘ 각 청크는 상태를 가짐: - active: 활성 픽셀 있음? (true/false) - sleepCounter: 몇 프레임 동안 변화 없었나? if (chunk.active == false): skip! // 이 청크는 업데이트 안 함 → 빈 공간 대부분 스킵!

2. Sleep 시스템

10프레임 동안 변화 없으면 "잠듦" 상태로:

모래가 바닥에 쌓임 → 1프레임: 움직임 없음 → 2프레임: 움직임 없음 → ... → 10프레임: chunk.active = false → 더 이상 업데이트 안 함 (CPU 절약) 누군가 건드리면? → 다시 active = true

3. 중복 업데이트 방지

한 픽셀이 이동하면 같은 프레임에 또 업데이트되는 버그:

문제: (5, 10): 물 → (6, 10)으로 이동 같은 프레임 내: (6, 10): 물 ← 방금 이동한 건데 또 업데이트! → (7, 10)으로 또 이동! → 한 프레임에 두 칸 이동 (비현실적) 해결: 각 픽셀에 플래그 추가: - updated: 이번 프레임에 업데이트했나? if (pixel.updated): skip!
최적화 효과
청크 시스템 빈 공간 스킵 → 90% 절감
Sleep 시스템 정적인 영역 스킵 → 50% 추가 절감
중복 방지 정확한 물리 + 약간의 속도 향상

📌 핵심 정리: Noita 픽셀 물리

  • Cellular Automata - 각 픽셀은 주변만 보고 다음 상태 결정
  • 단순한 규칙 - "아래 빈칸? 떨어져" 이게 전부
  • 복잡성의 창발 - 수백만 픽셀이 모이면 복잡한 물리 현상
  • 물질별 규칙 - 고체(아래), 액체(아래+옆), 기체(위+옆)
  • 반응 테이블 - 물+불=증기 같은 화학 반응
  • 청크 + Sleep - 빈 공간/정적 영역 스킵으로 성능 확보
  • 100줄 코드 - 기본 시뮬레이터는 매우 간단함
