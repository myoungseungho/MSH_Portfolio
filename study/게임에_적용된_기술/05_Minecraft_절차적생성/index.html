Part 1. 무한한 맵이 어떻게 가능해?

Minecraft 맵은 진짜 무한해?

기술적으로는 거의 무한해.

약 6,000만 × 6,000만 블록까지 갈 수 있어.

지구 표면적의 8배 정도 되는 크기야.

그 큰 맵을 다 미리 만들어놔?

그건 불가능해.

미리 만들어두면 파일 크기가 수천 테라바이트가 될 거야.


대신 필요할 때 즉시 생성해.

플레이어가 새로운 곳에 가면 → 그때 지형 생성.

매번 랜덤으로 만들어?

완전 랜덤은 아니야.


완전 랜덤이면 문제가 생겨:

• 같은 장소에 다시 가도 다른 지형이 나옴

• 친구와 같은 시드인데 지형이 다름


"시드(Seed)"가 같으면 항상 같은 지형이 나와야 해.

🎲 비유: 수학 공식으로 만드는 지형

• 랜덤 = 주사위 굴리기 (매번 다른 결과)
• Minecraft = 공식에 좌표 대입

→ f(x=100, z=200) = 산
→ f(x=300, z=400) = 바다

좌표가 같으면 항상 같은 결과가 나오는 "결정론적 생성"

Part 2. Perlin Noise - 자연스러운 랜덤

완전 랜덤이 왜 안 좋아?

완전 랜덤(White Noise)으로 높이를 정하면:

→ 옆 블록과 높이 차이가 들쭉날쭉

→ 스파이크처럼 뾰족뾰족한 지형


자연스러운 지형은 부드럽게 연결되어야 해.

완전 랜덤 (White Noise): ▓░▓░░▓▓░▓░░▓░▓▓░ ← 픽셀마다 완전히 다른 값 (너무 시끄러움) Perlin Noise: ░░▒▒▓▓▓▓▒▒░░░▒▒▓ ← 주변 값과 부드럽게 연결 (자연스러움)

Perlin Noise는 이웃 값과 부드럽게 이어지는 "연속적인 랜덤"

Perlin Noise가 뭐야?

1983년 Ken Perlin이 만든 노이즈 알고리즘.


특징:

• 연속적: 이웃 값과 부드럽게 이어짐

• 결정론적: 같은 좌표 → 같은 값

• 다차원: 1D, 2D, 3D, ... 지원

어떻게 작동해?

핵심 아이디어:


1. 격자점(Grid Point)마다 랜덤 기울기 벡터 배치

2. 좌표가 주어지면, 주변 격자점들의 영향을 보간

3. 결과: 부드럽게 변하는 값

// Perlin Noise 간소화 버전 float PerlinNoise(float x, float y) { // 1. 좌표가 속한 격자 셀 찾기 int x0 = floor(x), y0 = floor(y); // 2. 셀 내 상대 위치 (0~1) float dx = x - x0, dy = y - y0; // 3. 네 꼭짓점의 기울기 벡터로 내적 계산 float n00 = DotGridGradient(x0, y0, x, y); float n01 = DotGridGradient(x0, y0+1, x, y); float n10 = DotGridGradient(x0+1, y0, x, y); float n11 = DotGridGradient(x0+1, y0+1, x, y); // 4. 부드러운 보간 (fade 함수 적용) return Interpolate(n00, n01, n10, n11, dx, dy); }

Part 3. 옥타브 - 디테일 추가하기

Perlin Noise 하나로 충분해?

부족해.


Perlin Noise 하나는 너무 "부드러워".

실제 지형은 큰 산도 있고 작은 언덕도 있잖아.

어떻게 해결해?

여러 개의 노이즈를 합쳐!


• 1번 노이즈: 큰 스케일 (산맥)

• 2번 노이즈: 중간 스케일 (언덕)

• 3번 노이즈: 작은 스케일 (바위)


이걸 옥타브(Octave)라고 불러.

옥타브 1 (진폭 크고, 주파수 낮음): ╱╲ ╱ ╲ ╱╲ ╱ ╲ ╱ ╲ ╱ ╲ ╱ ╲ 옥타브 2 (진폭 작고, 주파수 높음): ╱╲╱╲╱╲╱╲╱╲╱╲╱╲ 합친 결과: ╱╲ ╱╲╱╲ ╱╲ ╱ ╲╱╲╱ ╲╱╲ ╱ ╲╱ ╲

여러 옥타브를 합치면 큰 형태 + 작은 디테일이 공존

// 옥타브를 이용한 지형 높이 계산 float GetTerrainHeight(float x, float z) { float height = 0; float amplitude = 1.0; // 진폭 (높이 영향) float frequency = 0.01; // 주파수 (스케일) for (int i = 0; i < NUM_OCTAVES; i++) { height += amplitude * PerlinNoise(x * frequency, z * frequency); amplitude *= 0.5; // 다음 옥타브는 진폭 감소 frequency *= 2.0; // 다음 옥타브는 주파수 증가 } return height; }
옥타브 주파수 진폭 역할
1 0.01 1.0 대륙/산맥
2 0.02 0.5 큰 언덕
3 0.04 0.25 작은 언덕
4 0.08 0.125 바위/울퉁불퉁

Part 4. 바이옴 - 사막, 숲, 설원

Minecraft는 지형마다 분위기가 달라. 어떻게 해?

바이옴(Biome) 시스템.


각 좌표에 "이 지역은 어떤 환경인가?"를 결정해.

• 사막: 모래 블록, 선인장

• 숲: 흙, 나무 많음

• 설원: 눈, 가문비나무

바이옴은 어떻게 결정해?

두 개의 노이즈를 사용해:


1. 온도 노이즈 (Temperature)

2. 습도 노이즈 (Humidity)


두 값을 조합해서 바이옴 결정.

습도 낮음 습도 높음 ───────────────────────────── 온도 │ 사막 │ 평원 │ 늪지 │ 높음 │ │ │ │ ├────────┼────────┼───────┤ 온도 │ 사바나 │ 숲 │ 정글 │ 중간 │ │ │ │ ├────────┼────────┼───────┤ 온도 │ 설원 │ 침엽수림│ 눈덮인│ 낮음 │ │ │ 타이가 │ ─────────────────────────────

온도×습도 조합으로 바이옴 결정

// 바이옴 결정 Biome GetBiome(float x, float z) { float temperature = PerlinNoise(x * 0.005, z * 0.005); float humidity = PerlinNoise(x * 0.007 + 1000, z * 0.007 + 1000); if (temperature > 0.6) { if (humidity > 0.5) return Biome.JUNGLE; else return Biome.DESERT; } else if (temperature < 0.3) { if (humidity > 0.5) return Biome.SNOWY_TAIGA; else return Biome.SNOWY_PLAINS; } else { if (humidity > 0.6) return Biome.SWAMP; else return Biome.FOREST; } }

Part 5. 동굴 생성 - 땅 속은 어떻게?

지표면은 2D 노이즈로 되는데, 동굴은?

동굴은 3D 노이즈를 써.


3D 노이즈 값이 특정 임계값보다 크면 → 빈 공간 (동굴)

임계값보다 작으면 → 돌 블록

그냥 3D 노이즈면 "스위스 치즈"처럼 구멍 뚫린 모양 아니야?

맞아. 그래서 추가 기법을 써.


Worm 알고리즘:

→ "벌레가 지나간 자리"처럼 동굴 생성

→ 시작점에서 랜덤 방향으로 터널을 파 나감

// Worm 동굴 알고리즘 (간소화) void GenerateCaveTunnel(Vector3 start, int seed) { Vector3 position = start; Vector3 direction = RandomDirection(seed); for (int i = 0; i < TUNNEL_LENGTH; i++) { // 현재 위치 주변 블록을 공기로 float radius = Noise(i * 0.1) * 3 + 1; // 반지름도 변함 CarveSpherc(position, radius); // 방향을 조금씩 랜덤하게 변경 direction += RandomOffset(seed + i) * 0.2; direction = Normalize(direction); // 다음 위치로 이동 position += direction * STEP_SIZE; } }
1.18 업데이트에서 동굴이 바뀌었다던데?

Noise Cave가 추가됐어.


기존: Worm 터널 → 좁고 긴 동굴

신규: 3D 노이즈 → 거대한 치즈 동굴, 스파게티 동굴


두 방식을 혼합해서 다양한 동굴 생성.

Part 6. 청크 시스템 - 16×16×256 단위

무한 맵을 어떻게 관리해?

청크(Chunk) 단위로 나눠서 관리해.


1 청크 = 16×16 블록 (세로 256)

= 총 65,536 블록

왜 청크로 나눠?

1. 필요한 것만 생성/로드

→ 플레이어 근처 청크만 메모리에


2. 필요한 것만 렌더링

→ 보이는 청크만 GPU에서 처리


3. 저장 효율

→ 변경된 청크만 저장

플레이어 시야 (예: 8청크) ┌───┬───┬───┬───┬───┐ │ L │ L │ L │ L │ L │ L = 로드됨 ├───┼───┼───┼───┼───┤ G = 생성 대기 │ L │ L │ L │ L │ L │ ├───┼───┼───┼───┼───┤ │ L │ L │👤 │ L │ L │ 👤 = 플레이어 ├───┼───┼───┼───┼───┤ │ L │ L │ L │ L │ L │ ├───┼───┼───┼───┼───┤ │ G │ G │ G │ G │ G │ ← 이동하면 생성 └───┴───┴───┴───┴───┘

플레이어 주변 청크만 로드, 멀어지면 언로드

거리 상태 메모리
0~2 청크 활성 (틱 처리) 로드됨
3~8 청크 로드됨 (렌더링만) 로드됨
9+ 청크 언로드 디스크 저장

📌 핵심 정리

  • 절차적 생성 - 미리 만들지 않고, 좌표를 넣으면 지형이 "계산"됨
  • Perlin Noise - 이웃 값과 부드럽게 연결되는 연속적 랜덤
  • 옥타브 - 여러 스케일의 노이즈를 합쳐 큰 형태 + 작은 디테일
  • 바이옴 - 온도×습도 노이즈로 사막/숲/설원 등 환경 결정
  • 동굴 생성 - 3D 노이즈 + Worm 알고리즘으로 터널과 공간 생성
  • 청크 시스템 - 16×16 단위로 관리, 필요한 것만 로드/언로드
