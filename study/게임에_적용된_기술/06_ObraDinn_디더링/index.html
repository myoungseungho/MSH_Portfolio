Return of the Obra Dinn의 1-bit 디더링 렌더링

Part 1. 1-bit 렌더링이 뭐야?

Return of the Obra Dinn은 왜 이렇게 생겼어?

의도적으로 1-bit 그래픽을 사용했어.

1980년대 Macintosh 초기 게임 느낌을 재현한 거야.

1-bit가 뭔데?

픽셀 하나가 1비트의 정보만 가짐.

→ 0 또는 1

→ 검정 또는 흰색


회색이 없어. 오직 흑/백만 있음.

일반 게임 (24-bit): 각 픽셀 = R(8bit) + G(8bit) + B(8bit) → 1,677만 가지 색상 표현 가능 1-bit 게임: 각 픽셀 = 0 (검정) 또는 1 (흰색) → 딱 2가지만 표현 가능

1-bit = 픽셀당 흑/백 두 가지 선택지만 존재

흑백만으로 어떻게 그림을 그려?

그게 핵심 기술이야.


회색을 표현하고 싶으면?

→ 검정과 흰색 점을 섞어서 "회색처럼 보이게" 해.


이 기법이 디더링 (Dithering).

📰 비유: 신문 사진

• 신문도 흑백 잉크만 사용해
• 근데 사진이 회색 톤으로 보이지?
• 자세히 보면 작은 점들의 패턴이야

점을 촘촘히 → 어둡게 보임, 점을 듬성듬성 → 밝게 보임

Part 2. Ordered Dithering - 규칙적인 패턴

디더링은 어떻게 해?

가장 기본적인 방법: Ordered Dithering


미리 정해진 패턴(Bayer Matrix)을 사용해서

각 픽셀을 흑/백으로 결정해.

Bayer Matrix가 뭐야?

임계값 패턴이야.


4×4 Bayer Matrix 예시:

Bayer 4×4 Matrix (0~15 범위): ┌────┬────┬────┬────┐ │ 0 │ 8 │ 2 │ 10 │ ├────┼────┼────┼────┤ │ 12 │ 4 │ 14 │ 6 │ ├────┼────┼────┼────┤ │ 3 │ 11 │ 1 │ 9 │ ├────┼────┼────┼────┤ │ 15 │ 7 │ 13 │ 5 │ └────┴────┴────┴────┘ 픽셀 밝기가 매트릭스 값보다 크면 → 흰색 픽셀 밝기가 매트릭스 값보다 작으면 → 검정

4×4 패턴이 타일처럼 반복되며 적용됨

실제로 어떻게 적용해?

1. 원본 픽셀의 밝기를 구해 (0~255)

2. Bayer Matrix에서 해당 위치의 임계값을 가져와

3. 밝기 > 임계값 → 흰색, 아니면 → 검정

// Ordered Dithering (Bayer 4x4) const int bayerMatrix[4][4] = { { 0, 8, 2, 10}, {12, 4, 14, 6}, { 3, 11, 1, 9}, {15, 7, 13, 5} }; bool Dither(int x, int y, float brightness) { // brightness: 0.0 (검정) ~ 1.0 (흰색) int threshold = bayerMatrix[x % 4][y % 4]; float normalizedThreshold = threshold / 16.0; return brightness > normalizedThreshold; // true = 흰색 }
Obra Dinn도 이걸 써?

기본은 이거지만, 더 복잡해.


Obra Dinn은 3D 정보를 활용해서

더 예술적인 디더링을 적용해.

Part 3. 깊이 기반 디더링 - 거리에 따라 다르게

Obra Dinn 디더링이 뭐가 특별해?

카메라와의 거리에 따라 디더 패턴이 달라져.


• 가까운 물체: 디더 패턴이 크고 선명

• 먼 물체: 디더 패턴이 작고 밀집

왜 거리에 따라 다르게 해?

깊이감을 표현하기 위해서야.


멀리 있는 건 작아 보이니까 패턴도 작아야 자연스럽고,

가까운 건 크게 보이니까 패턴도 커야 해.

가까운 물체: 먼 물체: ┌────────────┐ ┌────────────┐ │ ██ ██ │ │ █ █ █ █ █ │ │ │ │ █ █ █ █ │ │ ██ ██ │ │ █ █ █ █ █ │ │ │ │ █ █ █ █ │ │ ██ ██ │ │ █ █ █ █ █ │ └────────────┘ └────────────┘ 듬성듬성 큰 점 촘촘한 작은 점

같은 밝기라도 거리에 따라 다른 패턴

// 깊이 기반 디더링 float GetDitherScale(float depth) { // depth가 클수록 (멀수록) 스케일이 작아짐 return lerp(4.0, 1.0, saturate(depth / maxDepth)); } bool DitherWithDepth(int x, int y, float brightness, float depth) { float scale = GetDitherScale(depth); // 스케일에 따라 좌표 변환 int scaledX = (int)(x / scale) % 4; int scaledY = (int)(y / scale) % 4; float threshold = bayerMatrix[scaledX][scaledY] / 16.0; return brightness > threshold; }

Part 4. 윤곽선 강조 - 형태 알아보기

1-bit로 물체를 어떻게 구분해?

디더링만으로는 물체 경계가 흐릿해.


그래서 윤곽선(Edge)을 별도로 그려.

윤곽선은 어떻게 찾아?

여러 방법이 있어:


1. 깊이 차이: 옆 픽셀과 깊이가 크게 다르면 = 경계

2. 법선 차이: 표면 방향이 급격히 바뀌면 = 모서리

3. 색상 차이: 밝기가 크게 달라지는 곳 = 경계

// 윤곽선 검출 bool IsEdge(int x, int y) { // 깊이 기반 엣지 float depthCenter = GetDepth(x, y); float depthLeft = GetDepth(x-1, y); float depthRight = GetDepth(x+1, y); if (abs(depthCenter - depthLeft) > DEPTH_THRESHOLD || abs(depthCenter - depthRight) > DEPTH_THRESHOLD) { return true; } // 법선 기반 엣지 Vector3 normalCenter = GetNormal(x, y); Vector3 normalLeft = GetNormal(x-1, y); if (dot(normalCenter, normalLeft) < NORMAL_THRESHOLD) { return true; } return false; }
Obra Dinn에서 윤곽선은 어떻게 보여?

윤곽선은 항상 검정색으로 그려.

이게 1-bit 특유의 "판화/에칭" 느낌을 만들어.

Part 5. 전체 렌더링 파이프라인

Obra Dinn의 전체 렌더링 순서는?

여러 패스(Pass)를 거쳐:

[3D 씬] ↓ ┌─────────────────────────┐ │ 1. G-Buffer 생성 │ │ - 색상, 깊이, 법선 │ └───────────┬─────────────┘ ↓ ┌─────────────────────────┐ │ 2. 라이팅 계산 │ │ - 조명에 의한 밝기 │ └───────────┬─────────────┘ ↓ ┌─────────────────────────┐ │ 3. 깊이 기반 디더링 │ │ - Bayer + 깊이 스케일 │ └───────────┬─────────────┘ ↓ ┌─────────────────────────┐ │ 4. 윤곽선 오버레이 │ │ - 엣지 = 검정색 │ └───────────┬─────────────┘ ↓ [1-bit 최종 이미지]

일반 3D 렌더링 → 디더링 → 윤곽선 → 1-bit 출력

포스트 프로세싱으로 하는 거야?

맞아.


1. 먼저 일반적인 3D 렌더링을 해

2. 그 결과물에 포스트 프로세싱 셰이더를 적용

3. 모든 색상을 흑/백으로 변환

// 최종 1-bit 셰이더 (간소화) float4 ObraDinnShader(v2f i) : SV_Target { // 1. 기본 정보 float brightness = tex2D(_MainTex, i.uv).r; float depth = tex2D(_DepthTex, i.uv).r; // 2. 윤곽선 체크 if (IsEdge(i.uv)) { return float4(0, 0, 0, 1); // 검정 } // 3. 디더링 int px = i.uv.x * _ScreenWidth; int py = i.uv.y * _ScreenHeight; bool isWhite = DitherWithDepth(px, py, brightness, depth); return isWhite ? float4(1,1,1,1) : float4(0,0,0,1); }

Part 6. 색상 팔레트 - 흑백만은 아니야

Obra Dinn은 순수 흑백만 쓰는 건 아니지?

맞아. 여러 색상 팔레트 옵션이 있어.


• 기본: 흰색 + 검정

• Macintosh: 크림색 + 갈색

• IBM 5151: 녹색 + 검정

• Zenith: 앰버 + 검정

어떻게 적용해?

디더링 결과(흑/백)를 팔레트 색상으로 매핑하면 돼.

// 팔레트 적용 float4 ApplyPalette(bool isWhite, int paletteIndex) { float4 palettes[4][2] = { // [0] = 어두운 색, [1] = 밝은 색 { float4(0,0,0,1), float4(1,1,1,1) }, // 기본 흑백 { float4(0.2,0.15,0.1,1), float4(0.9,0.85,0.7,1) }, // Mac { float4(0,0.1,0,1), float4(0.2,1,0.2,1) }, // IBM 녹색 { float4(0.1,0.05,0,1), float4(1,0.7,0,1) } // 앰버 }; return isWhite ? palettes[paletteIndex][1] : palettes[paletteIndex][0]; }
팔레트 밝은 색 어두운 색 분위기
기본 흰색 검정 선명, 대비 강함
Macintosh 크림색 갈색 빈티지, 따뜻함
IBM 5151 녹색 검정 레트로 터미널
Zenith 앰버 검정 고풍스러움

📌 핵심 정리

  • 1-bit 렌더링 - 픽셀당 흑/백 두 가지만 사용, 옛날 Mac 느낌
  • Ordered Dithering - Bayer Matrix로 밝기를 흑백 패턴으로 변환
  • 깊이 기반 디더링 - 가까운 건 큰 패턴, 먼 건 작은 패턴으로 깊이감
  • 윤곽선 강조 - 깊이/법선 차이로 엣지 검출, 검정으로 그림
  • 포스트 프로세싱 - 3D 렌더링 후 셰이더로 1-bit 변환
  • 색상 팔레트 - 흑백 대신 Mac/IBM/앰버 등 레트로 팔레트 선택 가능
