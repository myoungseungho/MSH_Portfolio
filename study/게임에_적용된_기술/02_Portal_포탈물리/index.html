벽을 통과하면 어디로 나올까?

Portal의 공간 왜곡 기술 - 어떻게 "없는 공간"을 보여줄까?

Part 1. 포탈이 뭐야?

Portal 게임에서 포탈은 어떻게 작동해?

벽에 두 개의 구멍(오렌지, 블루)을 만들어.

오렌지로 들어가면 → 블루로 나옴.

블루로 들어가면 → 오렌지로 나옴.

마치 두 지점이 직접 연결된 것처럼.

근데 포탈 안을 들여다보면 뭐가 보여?

반대편 포탈에서 보이는 장면이 보여.

오렌지 포탈을 들여다보면 → 블루 포탈 위치에서 본 풍경이 보임.

마치 "창문"처럼 다른 공간이 보이는 거야.

🪟 비유: 마법의 창문

• 네 방에 창문이 하나 있어. 근데 이 창문은 특별해.
• 밖이 아니라 부엌이 보여. 부엌에도 같은 창문이 있어.
• 부엌 창문으로는 네 방이 보여.

• 창문으로 손을 넣으면? → 부엌에서 손이 나와.
• 포탈은 "공간을 연결하는 창문"이야.
이게 왜 어려운 기술이야?

게임에서 "있지도 않은 공간"을 보여줘야 하니까.

플레이어 앞에 벽이 있는데, 벽 뒤가 아닌 완전 다른 곳을 보여줘야 해.

이건 비유클리드 공간을 만드는 거야.

잠깐, 유클리드 공간이 뭐야?

고등학교 때 배운 일반적인 기하학이야.

기원전 300년, 그리스 수학자 유클리드가 정리한 공간 법칙.

유클리드 공간의 특징은?

우리가 "당연하다"고 느끼는 것들이야:

• 두 점 사이 최단 거리는 직선

• 평행선은 절대 만나지 않음

• 삼각형 내각의 합 = 180도

• A에서 B로 가려면 그 사이를 통과해야 함

📐 비유: 모눈종이

• 유클리드 공간 = 평평한 모눈종이
• 점(0,0)에서 점(10,10)으로 가려면?
• → 직선으로 가든, 돌아가든, 그 사이를 지나가야 함

"워프"나 "점프" 같은 건 없어. 공간은 연속적이야.
그럼 비유클리드 공간은?

유클리드 법칙이 깨지는 공간이야.

어떻게 깨져?

포탈 세계에서는:

• A에서 B로 가는데 중간을 건너뛸 수 있어

• 직선으로 걸어가면 원래 자리로 돌아올 수도

• 공간이 "접혀" 있는 거야

[ 유클리드 공간 (현실) ] A ●━━━━━━━━━━━━━━━━━━━━━━━━━━● B 직선으로 이동 (중간을 반드시 지나감) ════════════════════════════════════════ [ 비유클리드 공간 (포탈) ] A ●━━━🟠 🔵━━━● B ┃ ↭↭ ┃ ┗━━━━━━━━┛ 포탈로 "점프"! (중간 공간을 건너뜀)

포탈 = 공간을 "접어서" 두 지점을 직접 연결

왜 이걸 게임에서 구현하기 어려워?

게임 엔진은 기본적으로 유클리드 공간을 가정해.

카메라, 물리, 렌더링 모두 "정상적인 공간"에서 작동하도록 만들어져 있어.


포탈은 이 모든 걸 "속여야" 해.

→ 없는 공간을 보여주고

→ 물리 법칙을 비틀고

→ 플레이어를 순간이동시키면서도 자연스럽게!

Part 2. 포탈 안에 "다른 장소"를 어떻게 보여줘?

오렌지 포탈 안에 블루 포탈 쪽 풍경이 보이잖아. 어떻게 해?

핵심 아이디어: 카메라를 하나 더 만든다!


1. 메인 카메라 = 플레이어 눈 (평소 화면)

2. 포탈 카메라 = 반대편 포탈에 배치된 "숨겨진 카메라"

┌───────────────────────────────────────┐ │ [ 방 A - 플레이어 위치 ] │ │ │ │ 👤 플레이어 │ │ │ │ │ │ 👁️ 바라봄 │ │ ▼ │ │ 🟠 오렌지 포탈 │ │ "여기 안에 뭐가 보이지?" │ └───────────────────────────────────────┘ ⇓ 연결! ┌───────────────────────────────────────┐ │ [ 방 B - 블루 포탈 위치 ] │ │ │ │ 🎥 포탈 카메라 (숨겨진 카메라) │ │ │ │ │ │ 촬영 │ │ ▼ │ │ 🔵 블루 포탈 │ │ → 촬영 화면을 오렌지에 표시! │ └───────────────────────────────────────┘

플레이어가 오렌지 포탈을 보면, 블루 포탈 위치의 카메라 화면이 보임

포탈 카메라는 어디에 놓아?

여기가 중요해. 아무데나 놓으면 안 돼.


플레이어가 오렌지 포탈을 볼 때,

블루 포탈 쪽에서 "마치 플레이어가 거기 있는 것처럼" 보여야 해.

무슨 말이야? 예를 들어줘.

플레이어가 오렌지 포탈 앞 3m에 서 있어.

오렌지 포탈을 정면에서 바라보고 있어.


그럼 포탈 안에 뭐가 보여야 해?

→ 블루 포탈 앞 3m에서, 정면을 바라본 풍경!

아! 플레이어 위치를 그대로 "복사"하는 거구나?

정확해!


• 플레이어 ↔ 오렌지 포탈의 관계를

• 포탈 카메라 ↔ 블루 포탈의 관계로 똑같이 복사해.

🪞 비유: 거울 속의 나

거울 앞에 서면, 거울 속 "나"는:
• 내가 거울에서 1m 떨어지면 → 거울 속 나도 1m 뒤에
• 내가 왼쪽으로 가면 → 거울 속 나는 오른쪽으로
• 내가 거울을 바라보면 → 거울 속 나는 나를 바라봄

포탈 카메라 = "반대편 포탈에 비친 플레이어의 시점"
[ 플레이어가 오른쪽으로 이동하면? ] ┌────────────────┐ ┌────────────────┐ │ 방 A │ │ 방 B │ │ │ │ │ │ 👤 → 이동 │ ≋≋≋ │ 🎥 → 이동 │ │ ↓ │ │ ↓ │ │ 🟠 오렌지 │ │ 🔵 블루 │ └────────────────┘ └────────────────┘ • 플레이어가 오른쪽으로 → 포탈 카메라도 오른쪽으로! • 플레이어가 앞으로 → 포탈 카메라도 앞으로!

플레이어의 움직임을 포탈 카메라가 "거울처럼" 따라함

// 포탈 카메라 위치 계산 (핵심!) // 1. 플레이어가 오렌지 포탈에서 얼마나 떨어져 있나? Vector3 playerOffset = player.position - orangePortal.position; // 2. 그 거리/방향을 블루 포탈 기준으로 변환 Vector3 rotatedOffset = bluePortal.rotation * Quaternion.Inverse(orangePortal.rotation) * playerOffset; // 3. 블루 포탈에서 같은 위치에 카메라 배치! portalCamera.position = bluePortal.position + rotatedOffset;
이제 카메라 위치는 알겠어. 근데 그 카메라가 찍은 화면은 어떻게 포탈에 보여줘?

여기서 Render Texture라는 개념이 나와.

Render Texture가 뭐야?

보통 카메라는 화면에 직접 그리잖아?


근데 Render Texture를 쓰면

카메라가 찍은 화면을 "이미지 파일처럼" 저장할 수 있어.

📺 비유: CCTV 모니터

• CCTV 카메라가 주차장을 찍고 있어
• 그 화면은 경비실 모니터에 표시되지
• 카메라 → 녹화 → 모니터에 출력

포탈도 똑같아:
• 포탈 카메라 → Render Texture에 저장 → 포탈 표면에 출력

Render Texture = "카메라 화면을 담는 그릇"
그래서 전체 흐름이 어떻게 돼?

매 프레임마다 이 과정을 반복해:

[ 포탈 렌더링 전체 흐름 ] ┌──────────────────────────────────────────┐ │ 1단계: 포탈 카메라 위치 계산 │ │ 플레이어↔오렌지 관계를 │ │ 카메라↔블루 관계로 복사 │ └──────────────────────────────────────────┘ ▼ ┌──────────────────────────────────────────┐ │ 2단계: 포탈 카메라로 촬영 │ │ 블루 포탈 위치에서 보이는 풍경을 │ │ Render Texture에 저장 │ └──────────────────────────────────────────┘ ▼ ┌──────────────────────────────────────────┐ │ 3단계: 오렌지 포탈 표면에 붙이기 │ │ 저장된 Render Texture를 │ │ 포탈 표면에 매핑 │ └──────────────────────────────────────────┘ ▼ 🎉 포탈이 "창문"처럼 보임!

이 과정이 매 프레임(1초에 60번) 반복됨

단계 무엇을 왜
1. 카메라 위치 플레이어 위치를 반대편에 복사 시점이 자연스럽게 연결되려면
2. Render Texture 카메라 화면을 이미지로 저장 포탈 표면에 붙이려면 이미지가 필요
3. 포탈에 표시 저장된 이미지를 포탈에 매핑 플레이어가 "다른 공간"을 보게

Part 3. 스텐실 버퍼 - "여기만 그려!"

근데 포탈은 동그라미(타원)잖아. 어떻게 딱 그 모양만 보여줘?

여기서 스텐실 버퍼 (Stencil Buffer)가 등장해.

스텐실 버퍼가 뭐야?

직역하면 "도장/형판 버퍼".


스프레이 낙서할 때 종이 모양대로 오려서 대고 뿌리면

그 모양만 칠해지잖아? 그게 스텐실이야.

🎨 비유: 스프레이 스텐실

1. 벽에 별 모양 종이를 붙여
2. 스프레이로 뿌려
3. 종이 뗀다 → 별 모양만 칠해져 있음

스텐실 버퍼 = "이 영역에만 그려라"고 GPU에게 알려주는 마스크
포탈에서 어떻게 쓰여?

1. 먼저 포탈 모양(타원)을 스텐실 버퍼에 "마킹"

2. 포탈 카메라 화면을 그릴 때, 마킹된 영역에만 그림

3. 결과: 타원 모양 안에만 다른 공간이 보임!

// 1단계: 포탈 모양을 스텐실에 마킹 Stencil { Ref 1 Comp Always Pass Replace // 포탈 영역에 "1" 표시 } // 2단계: 포탈 화면은 마킹된 영역에만 그림 Stencil { Ref 1 Comp Equal // 스텐실 값이 1인 곳에만 그림 }
스텐실 안 쓰면 어떻게 돼?

포탈 카메라 화면이 화면 전체에 그려짐.

또는 사각형 텍스처가 보이거나...

스텐실 = 포탈 "모양"을 만드는 핵심 기술

Part 4. 포탈을 통과할 때 - 물리는 어떻게 이어져?

포탈로 뛰어들면 어떻게 돼?

오렌지로 들어가면 → 블루에서 나와.

근데 중요한 건... 속도가 유지된다는 거야!

왜 속도 유지가 중요해?

Portal 게임의 핵심 퍼즐이 여기서 나와.


예: 높은 곳에서 떨어지면서 바닥 포탈로 들어가면?

→ 벽 포탈에서 그 속도 그대로 튀어나와!


수직 낙하 에너지가 → 수평 발사 에너지로 전환됨.

"Speedy thing goes in, speedy thing comes out"

[ 속도 유지 + 방향 전환 ] │ │ 👤 낙하 (빠름!) ▼ ┌───────────┐ │ 🟠 바닥 │ │ 포탈 │ └───────────┘ ⇓ 텔레포트! ┌─────┐ │ 🔵 │━━━━━▶ 👤 수평으로 발사! (같은 속도) │ 벽 │ └─────┘

"떨어진 속도 = 날아가는 속도" - 포탈의 핵심 물리 법칙

속도 방향은 어떻게 바꿔?

입장 포탈의 "앞 방향"과

출구 포탈의 "앞 방향"을 비교해서

속도 벡터를 회전 변환해.

// 포탈 통과 시 속도 변환 Vector3 entryVelocity = player.velocity; // 입장 포탈 기준 → 출구 포탈 기준으로 회전 Quaternion rotation = exitPortal.rotation * Quaternion.Inverse(entryPortal.rotation); Vector3 exitVelocity = rotation * entryVelocity; // 속도 크기는 유지, 방향만 변환됨! player.velocity = exitVelocity;
위치는 어떻게 계산해?

속도랑 같은 원리야.

입장 포탈에서 "얼마나 안쪽으로 들어왔나"를 계산해서

출구 포탈에서 "그만큼 앞으로" 위치시켜.

물리량 통과 시 변환
위치 포탈 간 상대 위치로 재계산
속도 크기 유지 (에너지 보존)
속도 방향 포탈 방향 차이만큼 회전
플레이어 방향 바라보는 방향도 함께 회전

Part 5. 포탈 안에 포탈이 보인다? - 재귀 렌더링

오렌지 포탈 안에 블루 포탈이 보이면... 그 안에 또 오렌지가 보여?

맞아, 무한히 보일 수 있어!

두 포탈이 마주보면 마치 거울이 거울을 비추는 것처럼

끝없이 반복되는 화면이 보여.

무한히 렌더링하면 컴퓨터 터지는 거 아냐?

당연히 제한을 둬야 해.


보통 재귀 깊이 (Recursion Depth)를 2~4로 제한해.

→ "포탈 안에 포탈 안에 포탈" 정도까지만 그림.

→ 그 이상은 너무 작아서 안 보여, 그냥 검은색 처리.

// 재귀 포탈 렌더링 void RenderPortal(Portal portal, int depth) { if (depth > MAX_RECURSION) return; // 보통 2~4 // 1. 상대편 포탈 위치에 카메라 배치 SetupPortalCamera(portal); // 2. 상대편 포탈도 보인다면? 또 렌더링 (재귀!) if (CanSeeOtherPortal(portalCamera, otherPortal)) { RenderPortal(otherPortal, depth + 1); } // 3. 이 포탈의 화면 렌더링 RenderToTexture(portalCamera, portal.renderTexture); }
왜 재귀 렌더링이 필요해?

생략하면 포탈 안에 보이는 포탈이 "검은 구멍"으로 보여.

몰입감이 깨지는 거지.


재귀 렌더링을 하면 진짜 공간이 연결된 느낌이 남.

재귀 깊이 렌더링 횟수 품질
0 1번 포탈 안이 검은색
1 2번 기본 (포탈 안 장면만)
2 4번 양호 (포탈 안의 포탈까지)
4 16번 고품질 (거울 효과처럼)

Part 6. 포탈을 "통과하는 중"인 물체는?

포탈에 반쯤 들어간 상태면 어떻게 보여?

이게 가장 어려운 부분 중 하나야.


물체의 절반은 여기, 절반은 저기에 있어야 해.

양쪽 다 제대로 보여야 하고!

물체가 포탈을 통과하는 중일 때, 양쪽에서 모두 보여야 함

어떻게 "반쪽"만 그려?

방법 1: 클리핑 플레인 (Clipping Plane)

→ "이 평면 앞/뒤만 그려라"고 지정

→ 포탈 평면을 기준으로 잘라서 렌더링


방법 2: 오브젝트 복제

→ 물체를 복사해서 양쪽 포탈 앞에 하나씩 배치

→ 각각 클리핑으로 절반만 보이게

// 클리핑 플레인 설정 // 포탈 평면 = 포탈 위치 + 포탈이 바라보는 방향 Vector4 clipPlane = CalculateClipPlane(portal.position, portal.forward); // 카메라에 클리핑 플레인 적용 // → 이 평면 뒤쪽은 렌더링 안 함 portalCamera.SetClipPlane(clipPlane);
물리 충돌은 어떻게 처리해?

더 복잡해.


통과 중인 물체는 양쪽 공간에서 충돌 검사를 해야 해.

A 방에서 벽에 부딪히는지도 체크하고,

B 방에서 바닥에 부딪히는지도 체크해야 함.


Portal 게임은 이걸 "유령 콜라이더"로 해결했어.

→ 복제된 물체에 충돌체를 붙여서 양쪽 충돌을 동시에 처리.

문제 해결 방법
양쪽에서 보여야 함 오브젝트 복제 + 클리핑
양쪽에서 충돌해야 함 유령 콜라이더 (Ghost Collider)
포탈 "안쪽"이 안 보임 Near Clip Plane 조정

📌 핵심 정리

  • 포탈 = 마법의 창문 - 두 지점을 직접 연결하는 비유클리드 공간
  • 두 번째 카메라 - 반대편 포탈 위치에 카메라를 두고 Render Texture로 표시
  • 스텐실 버퍼 - 포탈 모양(타원) 영역에만 렌더링하는 마스크 기술
  • 텔레포트 물리 - 속도 크기 유지 + 방향만 포탈 기준으로 회전 변환
  • 재귀 렌더링 - 포탈 안의 포탈을 위해 2~4번 반복 렌더링
  • 오브젝트 분할 - 통과 중인 물체는 복제 + 클리핑으로 양쪽에 표시
