벽을 통과하면 어디로 나올까?

Portal의 공간 왜곡 기술 - 어떻게 "없는 공간"을 보여줄까?

Part 1. 포탈이 뭐야?

Portal 게임에서 포탈은 어떻게 작동해?

벽에 두 개의 구멍(오렌지, 블루)을 만들어.

오렌지로 들어가면 → 블루로 나옴.

블루로 들어가면 → 오렌지로 나옴.

마치 두 지점이 직접 연결된 것처럼.

근데 포탈 안을 들여다보면 뭐가 보여?

반대편 포탈에서 보이는 장면이 보여.

오렌지 포탈을 들여다보면 → 블루 포탈 위치에서 본 풍경이 보임.

마치 "창문"처럼 다른 공간이 보이는 거야.

🪟 비유: 마법의 창문

• 네 방에 창문이 하나 있어. 근데 이 창문은 특별해.
• 밖이 아니라 부엌이 보여. 부엌에도 같은 창문이 있어.
• 부엌 창문으로는 네 방이 보여.

• 창문으로 손을 넣으면? → 부엌에서 손이 나와.
• 포탈은 "공간을 연결하는 창문"이야.
이게 왜 어려운 기술이야?

게임에서 "있지도 않은 공간"을 보여줘야 하니까.

플레이어 앞에 벽이 있는데, 벽 뒤가 아닌 완전 다른 곳을 보여줘야 해.

이건 비유클리드 공간을 만드는 거야.

비유클리드 공간이 뭐야?

우리가 사는 현실 = 유클리드 공간

→ A에서 B로 가려면 그 사이를 지나가야 해.


포탈이 있는 세계 = 비유클리드 공간

→ A에서 B로 "점프"할 수 있어. 중간 공간을 건너뛸 수 있어.


물리적으로 불가능한 공간 구조를 만드는 거야.

Part 2. 포탈 안에 "다른 장소"를 어떻게 보여줘?

오렌지 포탈 안에 블루 포탈 쪽 풍경이 보이잖아. 어떻게 해?

핵심 아이디어: 카메라를 하나 더 만든다!


1. 메인 카메라 = 플레이어 눈 (평소 화면)

2. 포탈 카메라 = 반대편 포탈에 배치된 "숨겨진 카메라"

[플레이어] ─── 👁️ 메인 카메라 ───→ 오렌지 포탈 바라봄 │ ┌───────┘ ▼ 🎥 포탈 카메라 (블루 포탈 위치에서 촬영) │ ▼ [포탈 안에 표시되는 화면]

플레이어가 오렌지 포탈을 보면, 블루 포탈 위치의 카메라 화면이 보임

포탈 카메라는 어디에 놓아?

플레이어와 포탈의 관계를 "거울처럼" 복사해서 배치해.


예를 들어:

• 플레이어가 오렌지 포탈 앞 3m에 있어

• → 포탈 카메라는 블루 포탈 앞 3m에 배치

• 플레이어가 오른쪽으로 이동하면

• → 포탈 카메라도 같은 방향으로 이동

// 포탈 카메라 위치 계산 Vector3 playerOffset = player.position - orangePortal.position; Vector3 rotatedOffset = bluePortal.rotation * Quaternion.Inverse(orangePortal.rotation) * playerOffset; portalCamera.position = bluePortal.position + rotatedOffset;
그 카메라가 찍은 화면은 어디에 보여줘?

포탈 표면에 텍스처로 붙여.


1. 포탈 카메라가 찍은 화면 → Render Texture에 저장

2. 이 텍스처를 포탈 표면에 표시

3. 결과: 포탈이 "창문"처럼 보임!

단계 설명
1. 포탈 카메라 배치 반대편 포탈 위치에, 플레이어 위치를 거울상으로 복사
2. Render Texture 포탈 카메라가 찍은 화면을 텍스처에 저장
3. 포탈에 표시 저장된 텍스처를 포탈 표면에 매핑

Part 3. 스텐실 버퍼 - "여기만 그려!"

근데 포탈은 동그라미(타원)잖아. 어떻게 딱 그 모양만 보여줘?

여기서 스텐실 버퍼 (Stencil Buffer)가 등장해.

스텐실 버퍼가 뭐야?

직역하면 "도장/형판 버퍼".


스프레이 낙서할 때 종이 모양대로 오려서 대고 뿌리면

그 모양만 칠해지잖아? 그게 스텐실이야.

🎨 비유: 스프레이 스텐실

1. 벽에 별 모양 종이를 붙여
2. 스프레이로 뿌려
3. 종이 뗀다 → 별 모양만 칠해져 있음

스텐실 버퍼 = "이 영역에만 그려라"고 GPU에게 알려주는 마스크
포탈에서 어떻게 쓰여?

1. 먼저 포탈 모양(타원)을 스텐실 버퍼에 "마킹"

2. 포탈 카메라 화면을 그릴 때, 마킹된 영역에만 그림

3. 결과: 타원 모양 안에만 다른 공간이 보임!

// 1단계: 포탈 모양을 스텐실에 마킹 Stencil { Ref 1 Comp Always Pass Replace // 포탈 영역에 "1" 표시 } // 2단계: 포탈 화면은 마킹된 영역에만 그림 Stencil { Ref 1 Comp Equal // 스텐실 값이 1인 곳에만 그림 }
스텐실 안 쓰면 어떻게 돼?

포탈 카메라 화면이 화면 전체에 그려짐.

또는 사각형 텍스처가 보이거나...

스텐실 = 포탈 "모양"을 만드는 핵심 기술

Part 4. 포탈을 통과할 때 - 물리는 어떻게 이어져?

포탈로 뛰어들면 어떻게 돼?

오렌지로 들어가면 → 블루에서 나와.

근데 중요한 건... 속도가 유지된다는 거야!

왜 속도 유지가 중요해?

Portal 게임의 핵심 퍼즐이 여기서 나와.


예: 높은 곳에서 떨어지면서 바닥 포탈로 들어가면?

→ 벽 포탈에서 그 속도 그대로 튀어나와!


수직 낙하 에너지가 → 수평 발사 에너지로 전환됨.

"Speedy thing goes in, speedy thing comes out"

│ │ 낙하 (빠름!) ▼ ┌───────────┐ │ 🟠 바닥 │ │ 포탈 │ └───────────┘ ⇓ 텔레포트! ┌─────┐ │ 🔵 │→→→→→→→ 수평으로 발사! (같은 속도) │벽포탈│ └─────┘

"떨어진 속도 = 날아가는 속도" - 포탈의 핵심 물리 법칙

속도 방향은 어떻게 바꿔?

입장 포탈의 "앞 방향"과

출구 포탈의 "앞 방향"을 비교해서

속도 벡터를 회전 변환해.

// 포탈 통과 시 속도 변환 Vector3 entryVelocity = player.velocity; // 입장 포탈 기준 → 출구 포탈 기준으로 회전 Quaternion rotation = exitPortal.rotation * Quaternion.Inverse(entryPortal.rotation); Vector3 exitVelocity = rotation * entryVelocity; // 속도 크기는 유지, 방향만 변환됨! player.velocity = exitVelocity;
위치는 어떻게 계산해?

속도랑 같은 원리야.

입장 포탈에서 "얼마나 안쪽으로 들어왔나"를 계산해서

출구 포탈에서 "그만큼 앞으로" 위치시켜.

물리량 통과 시 변환
위치 포탈 간 상대 위치로 재계산
속도 크기 유지 (에너지 보존)
속도 방향 포탈 방향 차이만큼 회전
플레이어 방향 바라보는 방향도 함께 회전

Part 5. 포탈 안에 포탈이 보인다? - 재귀 렌더링

오렌지 포탈 안에 블루 포탈이 보이면... 그 안에 또 오렌지가 보여?

맞아, 무한히 보일 수 있어!

두 포탈이 마주보면 마치 거울이 거울을 비추는 것처럼

끝없이 반복되는 화면이 보여.

무한히 렌더링하면 컴퓨터 터지는 거 아냐?

당연히 제한을 둬야 해.


보통 재귀 깊이 (Recursion Depth)를 2~4로 제한해.

→ "포탈 안에 포탈 안에 포탈" 정도까지만 그림.

→ 그 이상은 너무 작아서 안 보여, 그냥 검은색 처리.

// 재귀 포탈 렌더링 void RenderPortal(Portal portal, int depth) { if (depth > MAX_RECURSION) return; // 보통 2~4 // 1. 상대편 포탈 위치에 카메라 배치 SetupPortalCamera(portal); // 2. 상대편 포탈도 보인다면? 또 렌더링 (재귀!) if (CanSeeOtherPortal(portalCamera, otherPortal)) { RenderPortal(otherPortal, depth + 1); } // 3. 이 포탈의 화면 렌더링 RenderToTexture(portalCamera, portal.renderTexture); }
왜 재귀 렌더링이 필요해?

생략하면 포탈 안에 보이는 포탈이 "검은 구멍"으로 보여.

몰입감이 깨지는 거지.


재귀 렌더링을 하면 진짜 공간이 연결된 느낌이 남.

재귀 깊이 렌더링 횟수 품질
0 1번 포탈 안이 검은색
1 2번 기본 (포탈 안 장면만)
2 4번 양호 (포탈 안의 포탈까지)
4 16번 고품질 (거울 효과처럼)

Part 6. 포탈을 "통과하는 중"인 물체는?

포탈에 반쯤 들어간 상태면 어떻게 보여?

이게 가장 어려운 부분 중 하나야.


물체의 절반은 여기, 절반은 저기에 있어야 해.

양쪽 다 제대로 보여야 하고!

[방 A] [방 B] ┌────┐ ┌────┐ │ │ │ │ │ 🟠 │ ←─ 상자가 │ 🔵 │ ←─ 상자의 나머지 절반이 │ ██ │ 반쯤 들어감 │ ██ │ 여기서 튀어나옴 └────┘ └────┘ 포탈 포탈

물체가 포탈을 통과하는 중일 때, 양쪽에서 모두 보여야 함

어떻게 "반쪽"만 그려?

방법 1: 클리핑 플레인 (Clipping Plane)

→ "이 평면 앞/뒤만 그려라"고 지정

→ 포탈 평면을 기준으로 잘라서 렌더링


방법 2: 오브젝트 복제

→ 물체를 복사해서 양쪽 포탈 앞에 하나씩 배치

→ 각각 클리핑으로 절반만 보이게

// 클리핑 플레인 설정 // 포탈 평면 = 포탈 위치 + 포탈이 바라보는 방향 Vector4 clipPlane = CalculateClipPlane(portal.position, portal.forward); // 카메라에 클리핑 플레인 적용 // → 이 평면 뒤쪽은 렌더링 안 함 portalCamera.SetClipPlane(clipPlane);
물리 충돌은 어떻게 처리해?

더 복잡해.


통과 중인 물체는 양쪽 공간에서 충돌 검사를 해야 해.

A 방에서 벽에 부딪히는지도 체크하고,

B 방에서 바닥에 부딪히는지도 체크해야 함.


Portal 게임은 이걸 "유령 콜라이더"로 해결했어.

→ 복제된 물체에 충돌체를 붙여서 양쪽 충돌을 동시에 처리.

문제 해결 방법
양쪽에서 보여야 함 오브젝트 복제 + 클리핑
양쪽에서 충돌해야 함 유령 콜라이더 (Ghost Collider)
포탈 "안쪽"이 안 보임 Near Clip Plane 조정

📌 핵심 정리

  • 포탈 = 마법의 창문 - 두 지점을 직접 연결하는 비유클리드 공간
  • 두 번째 카메라 - 반대편 포탈 위치에 카메라를 두고 Render Texture로 표시
  • 스텐실 버퍼 - 포탈 모양(타원) 영역에만 렌더링하는 마스크 기술
  • 텔레포트 물리 - 속도 크기 유지 + 방향만 포탈 기준으로 회전 변환
  • 재귀 렌더링 - 포탈 안의 포탈을 위해 2~4번 반복 렌더링
  • 오브젝트 분할 - 통과 중인 물체는 복제 + 클리핑으로 양쪽에 표시
