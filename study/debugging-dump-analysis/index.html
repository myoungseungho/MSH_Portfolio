Part 1. 덤프 파일이 뭐야?

크래시가 났는데 재현이 안 돼요

재현이 안 되면 덤프 파일(Dump File)이 필요하다.

덤프 파일 = 크래시 순간의 메모리 스냅샷

프로세스가 죽기 직전의 상태를 그대로 저장해둔 것이다.

덤프 종류 크기 포함 내용
Mini Dump 수 MB 스택, 스레드, 모듈 목록
Mini + Heap 수십 MB + 힙 메모리 (변수 값 확인 가능)
Full Dump 수 GB 전체 메모리 (거의 안 씀)

Part 2. 덤프 파일 만들기

크래시 나면 자동으로 덤프를 남기게 하려면?

코드에서 MiniDumpWriteDump API를 사용한다.

// 크래시 덤프 생성 코드 #include <DbgHelp.h> #pragma comment(lib, "DbgHelp.lib") LONG WINAPI MyUnhandledExceptionFilter(EXCEPTION_POINTERS* pExceptionInfo) { // 덤프 파일 생성 HANDLE hFile = CreateFile( L"crash.dmp", GENERIC_WRITE, 0, NULL, CREATE_ALWAYS, FILE_ATTRIBUTE_NORMAL, NULL); if (hFile != INVALID_HANDLE_VALUE) { MINIDUMP_EXCEPTION_INFORMATION mei; mei.ThreadId = GetCurrentThreadId(); mei.ExceptionPointers = pExceptionInfo; mei.ClientPointers = FALSE; MiniDumpWriteDump( GetCurrentProcess(), GetCurrentProcessId(), hFile, MiniDumpWithDataSegs, // 또는 MiniDumpWithFullMemory &mei, NULL, NULL); CloseHandle(hFile); } return EXCEPTION_EXECUTE_HANDLER; } // main() 시작 시 등록 SetUnhandledExceptionFilter(MyUnhandledExceptionFilter);

Part 3. VS에서 덤프 열기

1 덤프 파일 열기

File → Open → File → .dmp 파일 선택

2 심볼 경로 설정

Tools → Options → Debugging → Symbols

→ .pdb 파일이 있는 폴더 추가 (빌드 폴더)

3 디버깅 시작

덤프 요약 페이지에서 "Debug with Native Only" 클릭

4 크래시 위치 확인

자동으로 크래시 위치로 이동 → 콜스택, 변수 값 확인

심볼 로드가 안 되면?

심볼(.pdb)과 바이너리(.exe/.dll) 버전이 정확히 일치해야 한다.

빌드할 때마다 .pdb 파일을 버전별로 보관해두자.

Part 4. 덤프 분석 실전

덤프 종류에 따라 다르다:

덤프 종류 지역 변수 힙 객체 전역 변수
Mini Dump O (스택에 있으면) X X
Mini + Heap O O O

Part 5. WinDbg 기초 (고급)

VS로 안 열리는 덤프도 있어?

커널 덤프나 복잡한 경우 WinDbg를 쓴다.

Windows SDK에 포함되어 있고, Microsoft Store에서도 설치 가능.

// WinDbg 기본 명령어 !analyze -v // 자동 분석 (크래시 원인 요약) k // 콜스택 보기 ~*k // 모든 스레드 콜스택 .ecxr // 예외 컨텍스트로 전환 r // 레지스터 값 dv // 지역 변수 dt pPlayer // 구조체 내용 보기 !heap -s // 힙 요약 // 심볼 경로 설정 .sympath+ C:\Symbols .reload

Part 6. 덤프 운영 팁

항목 권장사항
덤프 종류 MiniDumpWithDataSegs (힙 포함, 적당한 크기)
PDB 보관 빌드할 때마다 버전별로 보관 (심볼 서버 권장)
파일명 날짜_시간_버전.dmp (예: 20240115_143052_v1.2.3.dmp)
수집 크래시 리포터로 서버에 자동 업로드
분석 우선순위 동일 콜스택 그룹핑 → 빈도 높은 것부터

핵심 정리

  • 덤프 파일 = 크래시 순간의 메모리 스냅샷
  • MiniDumpWriteDump: 코드에서 덤프 생성
  • VS에서 열기: File → Open → Debug with Native Only
  • 심볼 필수: .pdb 파일이 있어야 콜스택/변수 확인 가능
  • 운영: 버전별 PDB 보관 + 크래시 리포터 구축
