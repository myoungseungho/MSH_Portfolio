코드 스멜 인식하기

"이 코드 문제있어"를 어떻게 알 수 있나?

Part 1. 코드 스멜(Code Smell)이 뭐야?

스멜? 코드에서 냄새가 나?

비유야. "뭔가 이상한데?" 하는 느낌.

버그는 아닌데, 앞으로 문제가 될 것 같은 신호.

냉장고 비유

냉장고에서 뭔가 냄새가 나. 아직 상한 건 아닌 것 같은데...

무시하면? → 며칠 뒤 완전히 상함
바로 확인하면? → 먹을 수 있을 때 처리

코드 스멜도 마찬가지. 일찍 잡을수록 비용이 적어.
어떤 종류가 있어?

Martin Fowler가 정리한 게 22가지나 돼. 그 중 자주 보는 5가지를 알려줄게.

Part 2. Long Method (긴 함수)

👃 스멜 #1: Long Method

함수가 너무 길어서 한눈에 안 들어옴

긴 게 왜 문제야?

읽는 데 시간이 오래 걸려.

버그 찾기도, 수정하기도 힘들어져.

// 실제 프로젝트 예시: ServerMsgProcess.cpp void CServerMsgProcess::HandleServerMsg(int iClient, BYTE* pPacket) { switch (*pwHeader) { case SSM_SERVER_CONNECTED: // 여기부터... MP_Server_Connected* pPacketStruct = (MP_Server_Connected*)pPacket; int iServer = pPacketStruct->m_nServer; printf(" %s ", g_Server.m_ServerManage.m_SocInfo[iClient].szTitle); printf("(%3d) Recv SSM_SERVER_CONNECTED\n", iClient); // ... 중간에 80줄 더 ... if (TRUE == CGameManager::GetInstance()->CheckGameServer(iClient)) { CGameManager::GetInstance()->GetGroupServerItemUnique(iClient); CDBManager::RankLoadLastList(iClient, 100); } // ...여기까지 약 100줄 break; case SSM_SERVER_DISCONNECTED: // 또 50줄... break; // 30개 이상의 case문... } } // 전체 파일: 1019줄 😱
몇 줄이면 "긴" 거야?

정답은 없지만, 경험적으로:

길이 상태 액션
~20줄 이상적 유지
20~50줄 괜찮음 기회되면 분리
50~100줄 주의 분리 검토
100줄+ 위험 반드시 분리
해결책: Extract Method

의미 있는 단위로 함수를 쪼개라. (다음 주제에서 자세히!)

Part 3. Duplicated Code (중복 코드)

👃 스멜 #2: Duplicated Code

비슷한 코드가 여러 곳에 복붙되어 있음

복붙이 왜 문제야? 빨리 끝나잖아.

하나 고치면 나머지도 다 고쳐야 해.

근데 어디어디 복붙했는지 기억이 안 나...

// 실제 프로젝트: Procedure_*.h 파일들 // 거의 같은 구조가 150개 이상 반복됨 // Procedure_LoadCharacter.h struct _PROCEDURE_LOAD_CHARACTER_PARAM { _PROCEDURE_LOAD_CHARACTER_PARAM() { memset(m_SpecialDungeonRemainTime, 0x00, sizeof(DWORD) * DUNGEON_TYPE_MAX); memset(m_SpecialDungeonChargeTime, 0x00, sizeof(DWORD) * DUNGEON_TYPE_MAX); // ... 초기화 코드 ... } int out_iResult; INT32 m_i32OsType; // ... 필드들 ... }; // Procedure_SavePC.h struct _PROCEDURE_SAVE_PC_PARAM { // 거의 비슷한 구조! int out_iResult; INT32 m_i32OsType; // ... 비슷한 필드들 ... }; // 문제: 공통 필드 수정하면 150개 파일 다 수정해야 함
어떻게 알 수 있어?

이런 증상이 있으면:

증상 의미
"이거 어디서 본 것 같은데..." 중복 있음
Ctrl+C, Ctrl+V 누르고 있음 중복 생성 중
버그 수정했는데 다른 데서 또 발생 중복 놓침
해결책: Extract Method / Extract Class

공통 코드를 한 곳으로 모아라.

Part 4. Large Class (거대한 클래스)

👃 스멜 #3: Large Class

하나의 클래스가 너무 많은 일을 함

클래스가 큰 게 왜 문제야?

"한 가지 일만 잘하자"의 원칙 위반.

God Class라고도 불러. 모든 걸 다 아는 신처럼.

// 가상의 예시 (실제 프로젝트 기반) class CGamePC { public: // 캐릭터 기본 정보 CharInfo _CharInfo; Skill_Info Skills[MAX_USERSKILL_COUNT]; // 인벤토리 ItemInfo Inventory[MAX_INVENTORY_COUNT]; // 퀘스트 QuestInfo Quests[MAX_QUEST_COUNT]; // 길드 WCHAR m_munpaName[MAX_MUNPA_NAME]; BYTE m_munpaGrade; // 던전 DWORD m_SpecialDungeonRemainTime[DUNGEON_TYPE_MAX]; // PK DWORD m_dwPK_Score; int m_iPK_Kill; // 펫 stSinsuUpgradeInfo _stSinsuUpgradeInfo[MAX_SINSU_LIST]; // ... 200개 이상의 멤버 변수 ... // 캐릭터, 인벤토리, 퀘스트, 길드, 던전, PK, 펫... // 이 클래스 하나가 모든 걸 다 처리! }; // 이 클래스 수정하면 게임 전체에 영향
어떻게 쪼개?

책임별로 분리해.

// 책임별로 분리한 버전 class CPlayerInventory { // 인벤토리만 }; class CPlayerQuest { // 퀘스트만 }; class CPlayerGuild { // 길드만 }; class CPlayerDungeon { // 던전만 }; class CGamePC { CPlayerInventory* m_pInventory; CPlayerQuest* m_pQuest; CPlayerGuild* m_pGuild; CPlayerDungeon* m_pDungeon; }; // 각 클래스가 자기 역할만 담당

Part 5. Primitive Obsession (기본 타입 집착)

👃 스멜 #4: Primitive Obsession

int, string 같은 기본 타입만 쓰고 의미있는 타입을 안 만듦

int 쓰면 안 돼?

int가 무슨 의미인지 모르잖아.

레벨? 체력? 돈? 경험치?

// 실제 프로젝트 예시 struct _PROCEDURE_LOAD_CHARACTER_PARAM { int out_iResult; // 뭔 결과? INT32 m_i32OsType; // OS 타입이 숫자? DWORD m_dwAccunique; // Account 고유값? DWORD m_dwPK_Score; // PK 점수? int m_iPK_Kill; // PK 킬 수? int m_iPK_Death; // PK 데스 수? }; // 문제1: 타입만 보면 의미를 모름 // 문제2: 잘못된 값을 넣어도 컴파일 됨 m_dwPK_Score = m_iPK_Kill; // 실수! 근데 컴파일 통과
어떻게 고쳐?

의미있는 타입을 만들어.

// 개선된 버전 enum class OSType { Windows, Mac, Linux }; enum class DBResult { Success, NotFound, Error }; struct PKStats { int score; int kills; int deaths; float GetKDRatio() { return deaths > 0 ? (float)kills / deaths : kills; } }; struct _PROCEDURE_LOAD_CHARACTER_PARAM { DBResult result; // 명확! OSType osType; // 명확! AccountID accId; // 타입이 다르면 컴파일 에러 PKStats pkStats; // 관련 데이터 묶음 };

Part 6. Shotgun Surgery (산탄총 수술)

👃 스멜 #5: Shotgun Surgery

하나를 바꾸면 여러 파일을 동시에 수정해야 함

왜 산탄총이야?

산탄총 쏘면 여러 곳에 구멍이 나잖아.

코드 하나 바꾸면 여기저기 다 수정해야 해.

// 예시: 캐릭터 저장 로직 수정하려면? // 1. Procedure_SavePC.h 수정 // 2. DBManager.cpp에서 호출부 수정 // 3. GameManager.cpp에서 호출부 수정 // 4. ServerMsgProcess.cpp에서 호출부 수정 // 5. DB 프로시저 gp_SavePC 수정 // 5개 파일 동시에 수정해야 함! // 하나라도 빠뜨리면 버그
왜 이렇게 됐어?

관련 코드가 여러 곳에 흩어져 있기 때문.

한 곳에 모아야 해.

해결책: Move Method / Move Field

관련된 코드를 한 클래스로 모아라.
"캐릭터 저장"과 관련된 모든 것 → CPlayerSaveManager 하나에

핵심 정리: 5가지 대표 코드 스멜

  • Long Method: 함수가 너무 김 → Extract Method
  • Duplicated Code: 복붙 천국 → 공통 함수 추출
  • Large Class: 하나가 다 함 → 책임별 분리
  • Primitive Obsession: int만 씀 → 의미있는 타입
  • Shotgun Surgery: 여러 파일 동시 수정 → 관련 코드 한 곳에
