Refactoring #17

Remove Dead Code

죽은 코드 제거 - 과감하게 삭제하라

죽은 코드가 뭐예요?
더 이상 실행되지 않는 코드예요.

여러 형태가 있어요:

- 아무 데서도 호출하지 않는 함수
- 주석 처리된 옛날 코드
- 절대 참이 될 수 없는 조건 분기
- 더 이상 쓰이지 않는 변수
- 삭제된 기능의 잔해

컴파일은 되지만, 실제로는 아무 역할도 안 해요.
해롭지 않으면 그냥 놔두면 안 되나요?
"해롭지 않다"는 건 착각이에요. 죽은 코드의 비용:

1. 인지 부하
코드를 읽는 사람이 "이건 뭐지? 중요한가?"라고 생각하게 만들어요. 실제론 의미 없는데 시간을 뺏겨요.

2. 잘못된 이해
"이 함수가 있으니 어디선가 쓰이겠지"라고 착각해요.

3. 유지보수 비용
리팩토링할 때 죽은 코드도 함께 수정해야 할 것 같은 착각.

4. 검색 오염
함수 이름 검색하면 죽은 코드도 나와서 혼란스러워요.

🏠 비유: 안 쓰는 가구

집에 안 쓰는 가구가 쌓여있으면?

- 공간이 좁아짐
- 청소할 때 불편함
- 뭐가 어디 있는지 찾기 어려움

코드베이스도 깔끔해야 살기 좋아요.
"나중에 쓸 수도 있으니까"라는 생각이 드는데요...
가장 흔한 함정이에요!

하지만 생각해보세요:

1. 버전 관리가 있잖아요
Git에 다 남아있어요. 필요하면 언제든 복구할 수 있어요. 주석으로 보관할 필요 없어요.

2. "나중에"는 대부분 오지 않음
통계적으로, 주석 처리해둔 코드를 다시 쓰는 경우는 극히 드물어요.

3. 오래된 코드는 어차피 못 씀
6개월 후에 복구하면? 주변 코드가 바뀌어서 그대로 못 써요. 어차피 다시 작성해야 해요.

💡 핵심 마인드

"삭제해도 Git에 남아있다."

과감하게 삭제하세요. 필요하면 히스토리에서 꺼내면 됩니다.
어떤 것들이 죽은 코드인지 어떻게 알아요?
찾는 방법들:

1. IDE/컴파일러 경고
"unused variable", "unreachable code" 등의 경고를 무시하지 마세요.

2. "Find All References"
함수/변수를 우클릭해서 참조 찾기. 0개면 죽은 코드.

3. 코드 커버리지 도구
테스트 실행 후 커버리지 리포트에서 빨간 줄(미실행) 확인.

4. 주석 처리된 코드 블록
/* */ 로 감싸진 옛날 코드 → 바로 삭제 대상.

5. TODO 주석의 코드
"TODO: 나중에 다시 활성화" → 6개월 지났으면 삭제.
삭제하기 무서운데, 안전하게 하는 방법이 있나요?
안전한 삭제 절차:

1. 참조 확인
→ IDE에서 "Find All References" 실행

2. 삭제 전 커밋
→ 현재 상태를 커밋해서 롤백 지점 확보

3. 삭제
→ 과감하게 지우기

4. 빌드
→ 컴파일 에러 없는지 확인

5. 테스트 실행
→ 기존 테스트가 통과하는지 확인

6. 커밋
→ "Remove dead code: [설명]" 메시지로 커밋

⚠️ 주의: 리플렉션/동적 호출

문자열로 함수명을 호출하는 경우, IDE가 참조를 못 찾을 수 있어요.

예: eval("funcName()"), GetMethod("FuncName")

이런 패턴이 있다면 전체 검색으로 문자열도 확인하세요.
팀에서 "왜 지웠어?"라고 하면요?
커밋 메시지로 소통하세요:

"Remove dead code: OldPaymentSystem"
→ 새 결제 시스템으로 교체 후 미사용

"Remove commented code from 2019"
→ 2년간 주석 상태로 방치됨

필요하면 PR 설명에 근거 추가: - 마지막 호출이 언제였는지 - 대체된 코드가 무엇인지 - Git 히스토리에서 복구 가능함을 언급

투명하게 기록하면 팀원들도 납득해요.

📌 Remove Dead Code 핵심 정리

  • 실행되지 않는 코드는 과감히 삭제
  • 죽은 코드는 인지 부하와 혼란을 야기
  • "나중에 쓸 수도" → Git에 있으니 걱정 마세요
  • IDE 경고, Find References, 커버리지로 찾기
  • 삭제 전 커밋, 삭제 후 테스트
