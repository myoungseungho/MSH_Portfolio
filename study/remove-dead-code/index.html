Remove Dead Code

죽은 코드 제거 - 과감하게 삭제하라

Part 1. 죽은 코드가 뭐야?

죽은 코드가 뭔데?

더 이상 실행되지 않는 코드야.

아무 데서도 호출 안 하는 함수, 주석 처리된 옛날 코드,

절대 참이 안 되는 조건 분기. 다 죽은 코드야.

해가 안 되면 그냥 둬도 되잖아?

"해가 안 된다"는 착각이야.

죽은 코드의 비용

1. 인지 부하 - "이건 뭐지? 중요한가?" 시간 뺏김
2. 잘못된 이해 - "어디선가 쓰이겠지" 착각
3. 유지보수 비용 - 리팩토링 때 같이 수정해야 할 것 같은 느낌
4. 검색 오염 - 함수명 검색하면 죽은 코드도 나와서 혼란
안 쓰는 가구 비유

집에 안 쓰는 가구가 쌓이면?
공간 좁아지고, 청소 불편하고, 뭐가 어딨는지 못 찾아.

코드베이스도 깔끔해야 살기 좋아.

Part 2. "나중에 쓸 수도" 함정

나중에 쓸 수도 있잖아?

가장 흔한 함정이야!

왜 삭제해도 되는가

1. Git에 다 있어 - 필요하면 히스토리에서 복구
2. "나중에"는 안 와 - 주석 코드 다시 쓰는 경우 거의 없어
3. 오래된 건 어차피 못 써 - 6개월 후엔 주변 코드 다 바뀌어서 그대로 못 써
정말 지워도 돼?

과감하게 삭제해.

필요하면 Git 히스토리에서 꺼내면 돼.

Part 3. 어떻게 찾아?

죽은 코드인지 어떻게 알아?

찾는 방법들:

죽은 코드 찾기

1. IDE 경고 - "unused variable", "unreachable code"
2. Find All References - 참조 0개면 죽은 코드
3. 코드 커버리지 - 테스트 후 빨간 줄(미실행)
4. 주석 처리된 블록 - /* */ 감싸진 옛날 코드
5. TODO 주석 - 6개월 넘은 "나중에 활성화" → 삭제
주의: 리플렉션/동적 호출

문자열로 함수명 호출하면 IDE가 참조 못 찾아.
eval("funcName()"), GetMethod("FuncName") 같은 거.

이런 패턴 있으면 전체 검색으로 문자열도 확인해.

Part 4. 안전하게 삭제하기

무서운데, 안전하게 하는 법?

절차를 따라:

안전한 삭제 절차

1단계: 참조 확인 - IDE에서 Find All References
2단계: 삭제 전 커밋 - 롤백 지점 확보
3단계: 삭제 - 과감하게
4단계: 빌드 - 컴파일 에러 없는지
5단계: 테스트 - 기존 테스트 통과하는지
6단계: 커밋 - "Remove dead code: [설명]"
팀에서 "왜 지웠어?" 하면?

커밋 메시지로 소통해.

"Remove dead code: OldPaymentSystem - 새 결제 시스템으로 교체 후 미사용"

투명하게 기록하면 팀원들도 납득해.

핵심 정리: Remove Dead Code

  • 대상: 실행되지 않는 코드는 과감히 삭제
  • 비용: 인지 부하, 혼란, 유지보수 비용
  • 안심: Git에 있으니 나중에 필요하면 복구
  • 찾기: IDE 경고, Find References, 커버리지
  • 절차: 삭제 전 커밋, 삭제 후 테스트
