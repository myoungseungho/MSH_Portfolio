⚡ SIMD로 4배 빠르게 계산하는 법

벡터 연산으로 게임 최적화하기

1️⃣ SIMD가 뭔데?

SIMD? 처음 들어보는데 뭐야?

SIMD = Single Instruction, Multiple Data

"하나의 명령으로 여러 데이터를 동시에 처리"라는 뜻이야.

무슨 소리야? 예를 들어줘.

4개의 숫자를 더하는 상황을 생각해봐:

일반 방식 (하나씩): 1 + 10 = 11 2 + 20 = 22 3 + 30 = 33 4 + 40 = 44 총 4번의 덧셈 SIMD 방식 (한 번에): [1, 2, 3, 4] + [10, 20, 30, 40] = [11, 22, 33, 44] 총 1번의 덧셈 (하지만 4개를 동시에!)

4배 빠르다!

🍔 비유: 햄버거 포장

일반 직원: 햄버거 하나씩 포장
1번 → 2번 → 3번 → 4번 (4번 작업)

SIMD 직원: 햄버거 4개를 동시에 포장
[1, 2, 3, 4] 한 번에! (1번 작업)

같은 일을 4배 빠르게 끝낼 수 있어.

2️⃣ 어떻게 4개를 동시에 처리해?

CPU가 마법을 부려?

아니야. CPU에 특별한 레지스터가 있어.

특별한 레지스터?

일반 레지스터는 32비트 (float 1개)만 담을 수 있지만,

SIMD 레지스터는 128비트야.

일반 레지스터 (32비트): [ float 1개 ] SIMD 레지스터 (128비트): [ float | float | float | float ] 32비트 32비트 32비트 32비트 → float 4개를 동시에 담을 수 있음!

그래서 한 번에 4개를 계산할 수 있는 거야.

📊 SIMD 레지스터 크기

이름 크기 float 개수 지원 CPU
SSE 128비트 4개 Pentium 3 이후 (1999년~)
AVX 256비트 8개 Sandy Bridge (2011년~)
AVX-512 512비트 16개 Skylake-X (2017년~)

대부분의 현대 PC는 최소 SSE를 지원해!

3️⃣ 정확히 얼마나 빠른데? (실제 측정)

이론상 4배면 실제로도 4배야?

직접 실측해봤어!

Visual Studio 2022 / SSE 활성화 / Release 빌드로 테스트했어.

📊 실험 환경

CPU: Intel/AMD 64비트 (SSE 지원) 컴파일러: Visual Studio 2022 (MSVC 19.38) 최적화: /Od (비활성화) - 순수 비교를 위해 SIMD: SSE (128비트 레지스터) 측정: std::chrono::high_resolution_clock

주의: /O2 최적화 시 컴파일러가 일반 코드도 자동으로 SIMD화하므로, 순수 비교를 위해 최적화를 끔

📈 실험 1: 벡터 덧셈 (1,000만 개)

// 일반 방식 float a[10000000], b[10000000], result[10000000]; for (int i = 0; i < 10000000; i++) { result[i] = a[i] + b[i]; } // SIMD 방식 (SSE) __m128* pA = (__m128*)a; __m128* pB = (__m128*)b; __m128* pResult = (__m128*)result; for (int i = 0; i < 10000000 / 4; i++) { pResult[i] = _mm_add_ps(pA[i], pB[i]); }

📊 실측 결과:

일반 방식: 11.29 ms SIMD 방식: 7.97 ms → 1.42배 빠름! ✨

📈 실험 2: 벡터 내적 (100만 번)

// 일반 방식 float result = a[0]*b[0] + a[1]*b[1] + a[2]*b[2] + a[3]*b[3]; // SIMD 방식 __m128 vecA = _mm_load_ps(a); __m128 vecB = _mm_load_ps(b); __m128 mul = _mm_mul_ps(vecA, vecB); // Horizontal Add로 합산

📊 실측 결과:

일반 방식: 1.58 ms SIMD 방식: 1.61 ms → 거의 비슷 (0.98배)

주의: 내적은 Horizontal Add 오버헤드 때문에 SIMD 이점이 적음.

📈 실험 3: 거리 계산 (몬스터 100만 마리)

// 일반 방식 (하나씩) float dx = monsterX[i] - playerX; float dy = monsterY[i] - playerY; float dz = monsterZ[i] - playerZ; float dist = sqrt(dx*dx + dy*dy + dz*dz); // SIMD 방식 (4마리씩) __m128 dx = _mm_sub_ps(monsterX_vec, playerX_vec); __m128 dy = _mm_sub_ps(monsterY_vec, playerY_vec); __m128 dz = _mm_sub_ps(monsterZ_vec, playerZ_vec); __m128 distSq = _mm_add_ps(_mm_add_ps(dx2, dy2), dz2); __m128 dist = _mm_sqrt_ps(distSq);

📊 실측 결과:

일반 방식: 2.79 ms SIMD 방식: 1.52 ms → 1.84배 빠름! ✨
어? 이론상 4배인데 실제로는 1.4~1.8배밖에 안 나왔어. 왜?

여러 가지 이유가 있어:

1. 메모리 병목 (Memory Bottleneck) → CPU는 빠른데 메모리 읽기가 느림 → 4개를 동시에 계산해도 메모리 대역폭이 한계 → 특히 1000만 개는 캐시에 안 들어감 2. 최적화 비활성화 (/Od) → 컴파일러 최적화를 꺼서 순수 비교 → /O2 켜면 일반 코드도 자동 SIMD화됨 → 실제 게임에서는 /O2 사용 → 더 빠름 3. 포인터 캐스팅 오버헤드 → float* → __m128* 변환 → 16바이트 정렬 확인 4. Horizontal Add (내적의 경우) → SIMD로 곱셈은 빠르지만 → 4개 합치는 건 추가 작업 필요 → 오히려 느려질 수 있음

결론: 순수 비교에서는 1.4~1.8배지만, 실제 최적화 켜면 훨씬 더 빠름!

그럼 실제 게임에서는 어떻게 돼?

실제 게임은 /O2 최적화를 켜고 빌드해:

상황 1: SIMD 직접 사용 안 함 → 컴파일러가 자동으로 벡터화 (Auto-vectorization) → 일반 코드도 알아서 SIMD 사용 상황 2: SIMD 직접 사용 → 컴파일러 자동 벡터화 + 명시적 SIMD → 복잡한 연산에서 더 유리 → 예: 행렬 곱셈, 복잡한 물리 연산

교훈: 일단 일반 코드로 짜고, 프로파일링 후 병목 지점에만 SIMD 적용!

📌 핵심 정리: SIMD

  • SIMD - Single Instruction, Multiple Data (하나의 명령으로 여러 데이터 동시 처리)
  • SSE - 128비트 레지스터, float 4개 동시 처리 (대부분의 PC 지원)
  • AVX - 256비트 레지스터, float 8개 동시 처리
  • 실측 성능 (/Od) - 벡터 덧셈 1.42배, 거리 계산 1.84배 (메모리 병목)
  • 실제 성능 (/O2) - 컴파일러 자동 벡터화 + SIMD로 훨씬 더 빠름
  • 게임 활용 - 위치 업데이트, 충돌 검사, 물리 시뮬레이션
  • 주의사항 - 메모리 정렬(16/32바이트), 나머지 처리, 코드 복잡도
  • SoA > AoS - 배열의 구조체가 SIMD에 유리
  • 컴파일러 최적화 - /O2 켜면 일반 코드도 자동으로 SIMD 사용
  • 사용 시기 - 일반 코드 작성 → 프로파일링 → 핫스팟만 SIMD 적용
