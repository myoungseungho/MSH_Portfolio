서버 틱레이트와 시간 동기화

게임 서버의 심장박동 - 초당 몇 번 뛰어야 할까?

Part 1. 틱(Tick)이 뭐야?

게이머들이 "128틱 서버 아니면 안 한다"고 하는데, 틱이 뭔가요?

틱(Tick)은 서버가 게임 상태를 업데이트하는 최소 시간 단위예요.

틱레이트(Tickrate)는 초당 몇 번 업데이트하는지를 나타내요.

비유: 심장박동

사람의 심장이 1분에 60번 뛰면 60 BPM이죠?

게임 서버가 1초에 64번 업데이트하면 64 Tick이에요.

심장이 빨리 뛰면 더 민첩하듯, 틱레이트가 높으면 게임이 더 정밀해요!

틱레이트 기본 개념: ┌─────────────────────────────────────────────────────────────┐ │ │ │ 64 Tick Server (64Hz): │ │ 1초를 64개로 나눔 → 1틱 = 15.625ms │ │ │ │ Time: 0ms 15.6ms 31.2ms 46.9ms 62.5ms ... │ │ Tick: │─────►│─────►│─────►│─────►│ │ │ Tick 0 Tick 1 Tick 2 Tick 3 │ │ │ │ 각 틱마다 하는 일: │ │ ✓ 플레이어 위치 업데이트 │ │ ✓ 총알 발사 계산 │ │ ✓ 히트박스 충돌 감지 │ │ ✓ 스킬 쿨다운 감소 │ │ │ │ 128 Tick Server (128Hz): │ │ 1초를 128개로 나눔 → 1틱 = 7.8125ms │ │ │ │ │──►│──►│──►│──►│──►│──►│──►│──►│ 같은 시간에 2배 계산! │ │ │ └─────────────────────────────────────────────────────────────┘
틱레이트가 높으면 뭐가 좋아?

정밀도와 반응성이 좋아져요!

틱레이트 틱 간격 적합한 게임 느낌
20 Tick 50ms 옛날 MMO 느릿느릿
30 Tick 33.3ms LoL, Dota 2 전략 게임에 충분
64 Tick 15.6ms CS:GO 일반, 오버워치 일반 유저에겐 OK
128 Tick 7.8ms 발로란트, CS 프로 정밀 슈팅에 필수
왜 MOBA는 30틱인데 FPS는 128틱?
• MOBA: 스킬 타이밍이 0.1초 차이나도 괜찮음 (전략 위주)
• FPS: 0.01초 차이로 헤드샷 성패가 갈림 (반응 위주)

Part 2. 64틱 vs 128틱, 진짜 차이 나?

7.8ms 차이가 그렇게 중요해요? 사람이 느낄 수 있나요?

일반인은 못 느끼지만, 프로 게이머나 고수들은 확실히 느껴요!

특히 피킹(Peeking)과 헤드샷에서 큰 차이가 나요.

비유: 연속 사진 vs 동영상

64틱 = 1초에 64장 사진 (애니메이션)

128틱 = 1초에 128장 사진 (더 부드러운 애니메이션)

빠르게 움직이는 피사체일수록 프레임 차이가 확 느껴져요!

실제 시나리오: 코너 피킹 (FPS 게임) ┌─────────────────────────────────────────────────────────────┐ │ │ │ 64 Tick 서버: │ │ ──────────────────────────────────────── │ │ Time 0ms: 플레이어가 코너에서 튀어나옴 👤 │ │ (서버는 아직 모름, 다음 틱 대기) │ │ │ │ Time 7ms: 플레이어가 헤드샷 조준 완료 🎯 │ │ (서버는 여전히 모름) │ │ │ │ Time 12ms: 플레이어가 발사! 💥 │ │ (서버는 여전히 모름!) │ │ │ │ Time 15.6ms: ← 드디어 서버 틱 발생! │ │ 서버가 이제야 "나왔구나" 인지 │ │ │ │ ⚠️ 최대 15.6ms 지연 발생! │ │ │ │ 128 Tick 서버: │ │ ──────────────────────────────────────── │ │ Time 0ms: 플레이어가 코너에서 튀어나옴 👤 │ │ Time 7.8ms: ← 서버 틱! 즉시 인지 ✅ │ │ Time 12ms: 플레이어가 발사! 💥 │ │ Time 15.6ms: ← 서버 틱! 즉시 처리 ✅ │ │ │ │ ✅ 최대 7.8ms 지연 (절반!) │ │ │ └─────────────────────────────────────────────────────────────┘
실제 게임에서 얼마나 차이 나?
상황 64 Tick 128 Tick 영향도
빠른 피킹 히트박스 뒤쳐짐 정확한 위치 🔴 매우 큼
헤드샷 가끔 안 맞음 대부분 맞음 🔴 큼
움직이는 적 리드샷 필요 정확히 조준 가능 🟠 보통
유틸 타이밍 애매함 정밀 타이밍 🟠 보통

🎮 프로 선수들의 증언

CS:GO 프로들이 매치메이킹(64틱)을 안 하고 FACEIT/ESEA(128틱)만 하는 이유:

"감이 달라서 연습이 안 돼요. 64틱에서 맞는 건 128틱에서 안 맞고, 128틱에서 맞는 건 64틱에서 안 맞아요."

Part 3. 같은 입력 = 같은 결과? (Deterministic)

e스포츠에서 "같은 입력 → 같은 결과"가 왜 중요해요?

e스포츠는 공정성이 생명이에요!

같은 상황에서 같은 입력을 했는데 결과가 다르면 안 되죠.

비유: 주사위 vs 계산기

Non-Deterministic: 주사위 굴리기 - 결과 예측 불가

Deterministic: 계산기 - 같은 입력 = 항상 같은 결과

게임 서버는 계산기처럼 작동해야 리플레이도, 공정성도 보장돼요!

Deterministic vs Non-Deterministic: ┌─────────────────────────────────────────────────────────────┐ │ │ │ ❌ Non-Deterministic (매번 달라짐) │ │ ───────────────────────────────── │ │ 크리티컬 확률 25%를 Math.random()으로 계산 │ │ │ │ 실행 1: random() = 0.523 → 크리 발생! │ │ 실행 2: random() = 0.847 → 크리 안 남 │ │ │ │ → 리플레이할 때마다 다른 결과 😱 │ │ │ │ ✅ Deterministic (항상 같음) │ │ ───────────────────────────── │ │ Seeded Random 사용 (seed = 프레임 번호 + 플레이어 ID) │ │ │ │ seed=12345: seededRandom() = 0.523 → 크리 발생! │ │ seed=12345: seededRandom() = 0.523 → 크리 발생! (항상!) │ │ │ │ → 리플레이 100% 재현 가능 ✅ │ │ │ └─────────────────────────────────────────────────────────────┘
Lockstep은 뭐예요?

Lockstep은 모든 클라이언트가 서로를 기다리는 방식이에요.

가장 느린 플레이어를 기준으로 게임이 진행돼요.

Lockstep 작동 원리: ┌─────────────────────────────────────────────────────────────┐ │ │ │ Frame N 시작: │ │ ┌─────────────────────────────────────────────────────┐ │ │ │ Client A: 입력 전송 → 서버 (핑 20ms) │ │ │ │ Client B: 입력 전송 → 서버 (핑 50ms) │ │ │ │ Client C: 입력 전송 → 서버 (핑 100ms) ← 가장 느림 │ │ │ └─────────────────────────────────────────────────────┘ │ │ ↓ │ │ 서버: 모든 클라이언트 입력 도착까지 대기... │ │ (C가 도착할 때까지 100ms 대기!) │ │ ↓ │ │ 서버: 모든 입력을 모든 클라이언트에 브로드캐스트 │ │ ↓ │ │ Frame N+1: │ │ 모든 클라이언트가 동일한 입력으로 시뮬레이션 │ │ → Deterministic이므로 결과도 동일! │ │ │ │ ⚠️ 단점: 느린 플레이어에게 모두가 맞춰져야 함 │ │ │ └─────────────────────────────────────────────────────────────┘

🎮 LoL의 하이브리드 접근

LoL은 순수 Lockstep 대신 하이브리드 방식을 써요:

  • Deterministic: 모든 랜덤 요소를 Seeded Random으로
  • 서버 권위: 서버가 최종 판정 (치팅 방지)
  • 클라이언트 예측: 즉각 반응 (느낌 개선)
  • Input Delay ~130ms: 핑 차이 보정

Part 4. 왜 버튼 누르면 바로 반응 안 해? (Input Delay)

MOBA 게임에서 버튼 눌러도 살짝 느린 느낌이에요. 왜 그래요?

의도적인 지연이에요! 이걸 Input Delay라고 해요.

공정성을 위해 약간의 반응성을 희생하는 거예요.

비유: 동시 출발 신호

100m 달리기에서 출발 신호를 모두가 동시에 듣도록 해야 공정하죠?

게임도 마찬가지! 핑이 다른 플레이어들이 동시에 반응하도록 일부러 지연을 넣어요.

Input Delay가 필요한 이유: ┌─────────────────────────────────────────────────────────────┐ │ │ │ Input Delay 없이: │ │ ───────────────── │ │ Player A (핑 20ms): Time 20ms에 스킬 발동 │ │ Player B (핑 100ms): Time 100ms에 스킬 발동 │ │ │ │ → 80ms 차이! A가 불공평하게 유리! │ │ │ │ Input Delay 150ms 적용: │ │ ───────────────────── │ │ 모든 입력을 150ms 뒤에 실행 │ │ │ │ Player A: 입력 → 150ms 후 실행 │ │ Player B: 입력 → 150ms 후 실행 │ │ │ │ → 동시 실행! 공평! │ │ │ │ 트레이드오프: │ │ 반응성 ↓ (느린 느낌) but 공정성 ↑ (핑 차이 무효화) │ │ │ └─────────────────────────────────────────────────────────────┘
Input Delay 장점 단점 적합한 게임
0ms 즉각 반응 핑 차이로 불공평 싱글플레이어
50ms 빠른 느낌 여전히 불공평 캐주얼 게임
100~150ms 균형 약간 느림 LoL, Dota 2
200ms+ 완전 공평 너무 느림 턴제 게임
💡 LoL의 "손맛"
LoL의 Input Delay는 약 130ms. 프로 게이머들이 말하는 "손맛"이 바로 이 지연 때문에 생기는 느낌이에요!

Part 5. 서버가 터질 것 같으면? 시간을 늦춘다! (Time Dilation)

EVE Online에서 4000명이 한 전장에서 싸우는데 서버가 안 터져요?

EVE Online은 Time Dilation (TiDi)이라는 독특한 방식을 써요!

서버가 바쁘면 게임 내 시간을 천천히 흐르게 만드는 거예요.

비유: 영화의 슬로우 모션

영화에서 폭발 장면을 슬로우 모션으로 보여주면, 한 프레임에 더 많은 디테일을 담을 수 있죠?

EVE도 마찬가지! 서버가 바쁘면 게임을 슬로우 모션으로 돌려서, 모든 계산을 처리할 시간을 벌어요.

Time Dilation 원리: ┌─────────────────────────────────────────────────────────────┐ │ │ │ 정상 상태 (TiDi 100%): │ │ ═════════════════════════════════════════ │ │ 현실 시간 : 0초 ─────→ 1초 ─────→ 2초 │ │ 게임 시간 : 0초 ─────→ 1초 ─────→ 2초 │ │ 서버 부하 : ████░░░░░░ (40%) │ │ │ │ 과부하 상태 (TiDi 10%): │ │ ═════════════════════════════════════════ │ │ 현실 시간 : 0초 ───────────────────────────→ 10초 │ │ 게임 시간 : 0초 ─→ 1초 │ │ 서버 부하 : ██████████ (100%) │ │ │ │ 게임 1초가 현실 10초! │ │ → 서버가 여유롭게 모든 계산을 처리 │ │ │ └─────────────────────────────────────────────────────────────┘

🚀 실제 사례: B-R5RB 전투 (2014)

7,548명이 한 성계에서 전투를 벌인 역대 최대 전투!

  • TiDi 10%가 대부분 → 현실 21시간 진행
  • 게임 내 시간으로는 약 2시간만 흐름
  • 미사일 발사 1초 → 현실 10초 (슬로우 모션 전투)
  • 서버는 안 터지고 모든 액션 처리 완료!
TiDi가 적용되면 어떤 느낌이에요?
행동 정상 시간 TiDi 10% 느낌
미사일 발사 1초 10초 슬로우 모션 영화
워프 준비 10초 100초 (1분 40초) 좀 답답함
함선 폭발 3초 30초 장엄한 최후
채팅 메시지 즉시 즉시 정상 (TiDi 무관)
TiDi의 철학
"서버 성능은 한계가 있어. 그럼 게임을 서버에 맞춰버리면 되지 않을까?"
→ 기술적 한계를 게임 디자인으로 해결한 혁신적인 방법!

Part 6. Delay-based vs Rollback (넷코드 비교)

격투 게임에서 "롤백 넷코드"가 좋다고 하는데 뭐가 달라요?

네트워크 지연을 처리하는 두 가지 대표적인 방식이에요:

A
Delay-based: 입력을 의도적으로 늦춰서 동기화
B
Rollback: 일단 예측하고, 틀리면 되돌림
Delay-based vs Rollback: ┌─────────────────────────────────────────────────────────────┐ │ │ │ [Delay-based] 입력을 지연시킴 │ │ ═════════════════════════════════ │ │ Time 0ms: 버튼 누름 │ │ Time 100ms: 서버에 도착 │ │ Time 150ms: 상대에게 전달 │ │ Time 150ms: ← 양쪽 모두 동시에 실행 │ │ │ │ 장점: 완벽한 동기화, 롤백 없음 │ │ 단점: 항상 느린 느낌 (핑 ÷ 2만큼 지연) │ │ │ │ [Rollback] 일단 예측, 틀리면 되돌림 │ │ ═════════════════════════════════ │ │ Time 0ms: 버튼 누름 → 즉시 실행! (예측) │ │ Time 100ms: 서버에 도착, 상대 입력 수신 │ │ Time 100ms: 예측이 틀렸다면? → 과거로 되돌아가 재계산 │ │ │ │ 장점: 즉각 반응, 부드러운 느낌 │ │ 단점: 예측 실패 시 "순간이동" 현상 │ │ │ └─────────────────────────────────────────────────────────────┘
항목 Delay-based Rollback
반응 속도 느림 (핑만큼 지연) 빠름 (즉시 반응)
동기화 완벽 예측 실패 시 보정
고핑 환경 매우 느려짐 순간이동 발생
적합한 게임 MOBA, 전략 격투, FPS
대표 게임 LoL, Dota 2 길티기어, 모탈 컴뱃 11

🎮 격투 게임에서 Rollback이 중요한 이유

격투 게임은 프레임 단위로 승부가 갈려요 (1프레임 = 16ms)

Delay-based에서 핑 100ms면? → 6프레임 지연 → 사실상 플레이 불가!

Rollback은 일단 즉시 반응하므로 핑이 높아도 플레이 가능!

Part 7. 게임별로 왜 다른 선택을 할까?

왜 모든 게임이 128틱 + 롤백을 안 써요?

게임 장르, 비용, 플레이 경험에 따라 최적의 선택이 다르기 때문이에요!

🎯 발로란트 - 128틱의 정석

  • 128틱 서버 제공 (CS:GO 대비 경쟁력)
  • 연간 수천만 달러 서버 비용
  • 마케팅 효과로 투자 회수
  • "CS:GO보다 정밀하다"는 이미지 확보

🔫 CS2 - Sub-tick 혁신

  • 64틱이지만 Sub-tick 기술 도입
  • 틱 사이에 발생한 이벤트의 정확한 시간 기록
  • 64틱 비용으로 128틱 정밀도 달성
  • 2023년 게임 업계 화제의 기술!

⚔️ LoL / Dota 2 - 30틱으로 충분

  • MOBA는 전략 위주 → 틱레이트보다 공정성 중요
  • Input Delay 130ms로 핑 차이 보정
  • Deterministic으로 리플레이 100% 재현
  • 30틱으로 서버 비용 절감

🚀 EVE Online - Time Dilation

  • 대규모 전투 지원이 핵심 가치
  • 틱레이트 대신 시간을 늦추는 방식
  • 7000명+ 동시 전투 가능
  • 게임 디자인으로 기술 한계 극복
💡 핵심 교훈
"완벽한 네트워크 모델은 없다. 게임 장르와 목표(공정성 vs 반응성 vs 규모)에 맞춰 트레이드오프를 선택해야 한다."

핵심 정리

  • 틱레이트 = 서버의 초당 업데이트 횟수. 높을수록 정밀하지만 비용↑
  • 64틱 vs 128틱 = FPS에서 프로는 차이 느낌. 히트박스 정확도 10% 차이
  • Deterministic = 같은 입력 → 같은 결과. 공정성과 리플레이의 핵심
  • Lockstep = 모든 클라이언트가 동기화. 느린 플레이어에게 맞춤
  • Input Delay = 의도적 지연. 핑 차이로 인한 불공정 제거
  • Time Dilation = 서버 과부하 시 게임 시간을 늦춤. EVE의 혁신
  • Rollback = 예측 후 보정. 격투 게임에서 필수
