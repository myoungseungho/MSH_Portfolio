심리스 월드가 뭐예요? 로딩 없이 어떻게?

Zone Seamless Transition

Part 1: 옛날 게임은 맵 이동할 때 로딩이 있었나요?

네, 초기 MMO들은 존(Zone) 경계를 넘을 때마다 로딩 화면이 떴습니다.

리니지 1: 던전 입장 시 "잠시만 기다려주세요..." 화면

라그나로크: 마을 → 필드 이동 시 로딩 화면 + BGM 변경

왜 로딩이 필요했나요? 서버가 바뀌기 때문입니다. 프론테라 마을 서버와 남쪽 필드 서버가 물리적으로 다른 프로세스였죠.
[리니지 스타일 - 존 경계] 던전 밖 서버 던전 안 서버 ┌─────────┐ ┌─────────┐ │ ● │ │ │ │ 플레이어 │ ──던전입장→ │ LOADING │ │ │ │ ● │ └─────────┘ └─────────┘ ↑ ↓ 연결 끊김 새로 연결됨

플레이어 입장에서는 이렇게 느껴집니다:

  1. 던전 입구 클릭
  2. 화면이 검게 변함 (로딩 화면)
  3. 3~5초 대기
  4. 던전 안에서 캐릭터 등장

이 시간 동안 뒤에서는:

  • 기존 서버와 연결 해제
  • 캐릭터 데이터 저장
  • 새 서버에 연결 요청
  • 캐릭터 데이터 로드
  • 주변 플레이어/NPC 정보 수신

Part 2: 그럼 심리스(Seamless)는 뭐예요?

로딩 화면 없이 맵을 이동하는 기술입니다.

대표적인 예시가 월드 오브 워크래프트(WoW)입니다. 동부 왕국 대륙을 남쪽 끝에서 북쪽 끝까지 달려도 로딩이 없어요.

심리스의 정의 플레이어는 끊김 없이 걷고 있지만, 뒤에서는 서버가 바뀌고 있습니다. 마치 "이음새(seam) 없는" 천처럼 느껴지죠.
[WoW 스타일 - 심리스 전환] 서부 역병지대 서버 은빛소나무 숲 서버 ┌─────────────┐ ┌─────────────┐ │ ●────→ │ [경계선] │ ────→ │ │ 플레이어 │ │ 계속 이동 │ └─────────────┘ └─────────────┘ 연결 중 연결 중 └────── 양쪽 동시 연결 ──────┘ (핸드오프)

플레이어 경험:

  • 그냥 걷고 있을 뿐
  • 화면 끊김 없음
  • BGM만 자연스럽게 전환
  • "은빛소나무 숲" 지역명만 바뀜

하지만 기술적으로는:

  • 존 A 서버와 연결 유지
  • 존 B 서버에 미리 연결
  • 두 서버가 동시에 내 위치 추적
  • 경계를 완전히 넘으면 존 A 연결 해제

Part 3: 존 경계에서 정확히 무슨 일이 일어나요?

핸드오프(Handoff) 프로토콜이 실행됩니다.

// 존 전환 단계 (의사코드) // 1단계: 경계 접근 감지 if (DistanceToBorder < 100m) { // 존 B 서버에 "곧 갈게요" 예고 ZoneBServer.PreloadPlayer(myCharacterID); } // 2단계: 경계선 도달 if (CrossedBorder()) { // 양쪽 서버에 동시 연결 ConnectionA.KeepAlive(); ConnectionB.Establish(); // 두 서버가 내 위치 동기화 SyncPosition(ZoneA, ZoneB); } // 3단계: 경계를 완전히 벗어남 if (DistanceFromBorder > 50m) { // 구 서버 연결 해제 ZoneAServer.Disconnect(); // 구 서버 데이터 정리 ZoneAServer.UnloadNearbyObjects(); }
핵심: 이중 연결 경계선 근처에서는 두 서버에 동시에 연결되어 있습니다. 이를 통해 끊김 없는 전환이 가능해요.
[핸드오프 타임라인] 시간 → ───────────────────────────────────────── 존A만 연결 │ A+B 동시 │ 존B만 연결 ● │ ● │ ● ──────────── │ ──────── │ ──────── 100m 전 │ 경계 │ 50m 후

실제 구현 디테일:

  1. PreLoad 단계: 100m 전부터 존 B 서버가 내 캐릭터 데이터를 미리 메모리에 로드
  2. Dual Connection: 경계선에서 TCP 연결 2개 동시 유지
  3. Position Sync: 두 서버가 같은 좌표를 공유 (존 A: (4999, 2000), 존 B: (0, 2000))
  4. Object Migration: 주변 플레이어/NPC 정보를 존 B에서 다시 받음
  5. Clean Disconnect: 존 A에서 내 데이터 언로드

Part 4: 경계선에 서 있으면 어느 서버 소속이에요?

둘 다입니다! 하지만 "권위(Authority)"는 하나만 가집니다.

이중 소속 문제 경계선에서 양쪽 서버에 연결되어 있지만, 게임 로직(전투, 아이템 획득 등)은 한 서버만 처리해야 합니다.

해결 방법: Primary Zone 규칙

// 권위 서버 결정 if (PlayerCenterPoint.X < ZoneBorderX) { PrimaryZone = ZoneA; // A가 게임 로직 처리 SecondaryZone = ZoneB; // B는 위치만 추적 } else { PrimaryZone = ZoneB; SecondaryZone = ZoneA; } // 전투 예시 if (MonsterAttacksMe) { // Primary 서버만 데미지 계산 PrimaryZone.ProcessDamage(monster, player); // Secondary는 결과만 받음 SecondaryZone.UpdateHealth(player.HP); }
[경계에서의 권위] 존 A (Primary) 존 B (Secondary) ┌────────┬────┐ ┌────┬────────┐ │ 로직 │ ● │ [경계] │ ● │ 대기 │ │ 처리 │플레이어 │복사본 대기 │ └────────┴────┘ └────┴────────┘ ↓ ↑ 데미지 계산 결과만 수신 아이템 획득 HP 동기화 스킬 사용 위치 업데이트

구체적인 예시:

상황: 경계에 서서 몬스터와 전투 중

  • 존 A 서버 (내 몸의 60%가 여기 있음)
    • 데미지 계산 ✓
    • 경험치 지급 ✓
    • 아이템 드롭 ✓
  • 존 B 서버 (내 몸의 40%가 여기 있음)
    • 내 HP 복사본 유지
    • 내 위치 추적
    • 주변 플레이어에게 나를 보여줌

만약 전투 중에 경계를 넘으면?

  1. 권위가 존 A → 존 B로 이전
  2. 존 B가 전투 상태를 이어받음
  3. 몬스터도 존 B로 이관 (또는 전투 취소)

Part 5: 대륙 전체가 심리스면 서버가 하나인가요?

아니요! 보이지 않게 여러 개로 나뉘어 있습니다.

WoW의 동부 왕국 대륙은 약 20~30개의 존으로 나뉩니다:

[동부 왕국 존 분할 (간략화)] [서부역병지대-1] [동부역병지대-2] │ │ [은빛소나무숲-3] [동부내륙-4] │ │ [스톰윈드-5]──[엘윈숲-6] │ [붉은마루산맥-7]

각 존은 독립된 서버 프로세스:

  • 스톰윈드: 대도시라 서버 1개 전담
  • 엘윈 숲: 초보 지역, 서버 1개
  • 서부 역병지대: 고레벨 지역, 서버 1개
대륙 스트리밍 vs 인스턴스 던전
  • 대륙: 존 경계가 보이지 않음 (심리스 전환)
  • 던전: 입구에서 로딩 O (완전히 다른 인스턴스)
// 로딩 여부 결정 // Case 1: 대륙 내부 이동 (심리스) if (destination.IsSameContinentZone) { TransitionType = SEAMLESS; // 로딩 없음 UseHandoff(); } // Case 2: 던전 입장 (인스턴스) if (destination.IsDungeonInstance) { TransitionType = LOADING_SCREEN; // 로딩 O CreateNewInstance(); TeleportPlayer(); } // Case 3: 대륙 간 이동 (비행선, 포탈) if (destination.IsDifferentContinent) { TransitionType = LOADING_SCREEN; // 로딩 O DisconnectCurrentZones(); ConnectToNewContinent(); }

왜 던전은 로딩이 있나요?

  • 던전은 파티마다 별도 인스턴스(복사본)를 생성
  • 같은 던전에 100개 파티가 있으면 서버 100개 필요
  • 대륙처럼 고정된 존이 아니라 동적 생성
  • → 미리 연결할 수 없어서 로딩 화면 필요

Part 6: 기술적으로 어떻게 끊김 없이 보이게 해요?

관심 영역(AOI)과 점진적 로딩을 사용합니다.

관심 영역(Area of Interest): 내 주변 일정 반경만 서버에서 보내줌

[관심 영역 시스템] 존 A │ 존 B │ ○ ○ ○ ○ ○ │ ○ ○ ○ ○ ○ ○ ○ │ ○ ○ ○ ┌──────────────┐ │ ┌───── │ ● ○ ○ │ │ │ ○ ○ │ 플레이어 │ [경계선]│ │ │ ○ ○ ○ │ │ │ ○ ○ └──────────────┘ │ └───── 시야 200m │ 존A 객체 수신 │ 존B 객체 수신 시작

점진적 로딩 단계:

// 1. 멀리 있을 때 (500m) ZoneBServer.SendTo(player, { TerrainMesh, // 지형 메시 LowDetailTextures // 저해상도 텍스처 }); // 2. 가까워짐 (200m) ZoneBServer.SendTo(player, { HighDetailTextures, // 고해상도 텍스처 NPCList, // NPC 목록 QuestGiverIcons // 느낌표 아이콘 }); // 3. 경계 진입 (50m) ZoneBServer.SendTo(player, { NearbyPlayers, // 주변 플레이어 MonsterAI, // 몬스터 AI 상태 SoundAmbient // 환경음 }); // 4. 경계 통과 (0m) ZoneBServer.Handoff(player, { FullAuthority, // 게임 로직 권한 InventorySync, // 인벤토리 동기화 QuestProgressSync // 퀘스트 진행 상태 });
핵심 기술 3가지
  1. AOI(Area of Interest): 시야 범위만 데이터 전송
  2. LOD(Level of Detail): 거리에 따라 디테일 조절
  3. Preloading: 도착하기 전에 미리 로드

네트워크 최적화:

  • Priority Queue: 가까운 객체 우선 전송
  • Delta Compression: 변경된 부분만 전송
  • Interest Management: 관심 없는 객체는 업데이트 안 함

예를 들어:

  • 내 뒤에 있는 플레이어: 1초에 1번 위치 업데이트
  • 내 앞 10m 플레이어: 1초에 20번 업데이트
  • 500m 밖 플레이어: 업데이트 안 함 (AOI 밖)
[점진적 로딩 타임라인] 거리 500m 200m 50m 0m │ │ │ │ 지형 ████ │ │ │ 텍스처 ░░░░ ████ │ │ NPC ░░░░ ░░░░ ████ │ 플레이어 ░░░░ ░░░░ ░░░░ ████ 로직 ░░░░ ░░░░ ░░░░ ████ ████ = 로드 완료 ░░░░ = 대기 중

결과적으로 플레이어는:

  • 로딩 화면을 보지 않음
  • 모든 게 자연스럽게 나타남
  • 지형 → 건물 → NPC → 플레이어 순서로 페이드인
  • BGM과 환경음이 부드럽게 전환

📚 핵심 요약

  • 심리스 월드: 로딩 화면 없이 맵을 이동하는 기술 (WoW가 대표적)
  • 핸드오프: 존 경계에서 두 서버에 동시 연결 후 점진적 전환
  • 이중 소속: 경계선에서는 Primary Zone만 게임 로직 처리
  • 대륙 분할: 하나의 대륙도 20~30개 존으로 나뉘어 있음
  • AOI + LOD: 관심 영역과 점진적 로딩으로 끊김 없는 경험 제공
  • 던전은 예외: 동적 인스턴스는 여전히 로딩 필요
