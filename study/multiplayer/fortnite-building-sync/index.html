100명이 동시에 건물 짓는데 어떻게 동기화해요?

건축 시스템 네트워크 최적화

Part 1: 포트나이트 건축의 특수성

Q: "포트나이트 건축은 뭐가 그렇게 어려운가요?"

A: 실시간, 대량, 전투 중이라는 3가지가 동시에 일어나서 어렵습니다.

일반 건축 게임 (마인크래프트):

  • 천천히 지음 (평화 모드)
  • 가까운 곳만 신경씀
  • 초당 1~2개 배치

포트나이트 건축:

  • 초고속 건축 (프로는 초당 10개 이상)
  • 전투 중 건축 (총 쏘면서 동시에)
  • 100명 동시 (각자 건물 지음)
  • 실시간 파괴 (적이 부숨)
포트나이트 건축의 도전 과제: ┌─────────────────────────────────────┐ │ 전투 중 건축 (동시 다발) │ │ │ │ 플레이어 A: 벽-계단-벽-천장 (1초) │ │ 플레이어 B: 계단-바닥-벽 (1초) │ │ 플레이어 C: 총 쏘면서 부숨 │ │ │ │ 서버가 처리해야 할 것: │ │ ├─ 건물 배치 검증 (충돌, 자원) │ │ ├─ 건물 상태 동기화 (HP, 재질) │ │ ├─ 건물 파괴 전파 (연쇄 붕괴) │ │ └─ 100명 × 초당 10개 = 1000개/초 │ └─────────────────────────────────────┘ 네트워크 부하: 건물 생성/파괴 이벤트: 초당 1000개 상태 업데이트: 초당 3000개 (3 ticks × 1000) → 대역폭 폭발! 💥

Part 2: 건축물 = 네트워크 오브젝트

Q: "건축물 하나를 서버에 어떻게 저장하나요?"

A: 네트워크 리플리케이션 오브젝트로 관리합니다.

// 건축물 네트워크 객체 class BuildingPiece: // 고유 식별자 netID: int64 // 서버가 부여한 ID // 위치 정보 position: Vector3 // 월드 좌표 rotation: int // 0/90/180/270도 gridX, gridY, gridZ: int // 그리드 좌표 // 건물 정보 type: enum // WALL, FLOOR, STAIRS, ROOF material: enum // WOOD, BRICK, METAL health: int // 현재 체력 maxHealth: int // 최대 체력 // 소유권 ownerPlayerID: int // 누가 지었는가 teamID: int // 팀 (편집 권한) // 상태 isBuilding: bool // 건설 중 (체력 증가 중) buildProgress: float // 0.0 ~ 1.0 // 연결 정보 supportedBy: BuildingPiece[] // 이 건물을 지탱하는 건물들 supporting: BuildingPiece[] // 이 건물이 지탱하는 건물들
왜 이렇게 복잡한가요?
건축물은 단순한 "정적 오브젝트"가 아닙니다:
✅ 체력이 변한다 (총 맞으면 깎임)
✅ 상태가 변한다 (건설 중 → 완성)
✅ 구조적 의존성 (바닥 부수면 위 건물 붕괴)
✅ 플레이어와 상호작용 (편집, 수리)
→ 게임 내 "살아있는" 엔티티처럼 취급해야 함

Part 3: 건축 예측 (클라이언트가 먼저 배치)

Q: "클릭하면 바로 건물이 나타나잖아요. 서버 응답 기다리면 느린데?"

A: 클라이언트가 먼저 "예측"해서 배치하고, 서버가 나중에 검증합니다.

// 클라이언트: 즉시 예측 배치 OnPlayerClickBuild(type, position): // 1. 로컬 검증 (빠른 피드백) if not HasEnoughResources(type): ShowError("자원 부족") return if IsPositionBlocked(position): ShowError("배치 불가") return // 2. 즉시 로컬에 배치 (예측) ghostBuilding = CreateLocalBuilding(type, position) ghostBuilding.isPredicted = true // 서버 확인 전 ghostBuilding.alpha = 0.7 // 반투명 표시 ConsumeResourcesLocal(type) // 로컬 자원 차감 // 3. 서버에 요청 전송 sequenceID = nextSequenceID++ SendToServer(BUILD_REQUEST, { type: type, position: position, rotation: currentRotation, sequenceID: sequenceID }) // 4. 응답 대기 (비동기) WaitForServerResponse(sequenceID, timeout=1000ms) // 서버 응답 처리 OnServerBuildResponse(sequenceID, result): ghostBuilding = GetPredictedBuilding(sequenceID) if result.success: // 승인: 예측이 맞음 ghostBuilding.isPredicted = false ghostBuilding.netID = result.netID ghostBuilding.alpha = 1.0 // 불투명 else: // 거부: 롤백 RemoveBuilding(ghostBuilding) RefundResourcesLocal(type) ShowError(result.reason) // "다른 플레이어가 먼저 배치"
건축 예측 타임라인: T=0ms: 플레이어 클릭 클라: 즉시 배치 (반투명) 🏗️ 클라: 서버에 요청 전송 → T=50ms: 서버 수신 서버: 검증 시작 ├─ 자원 체크 ✓ ├─ 위치 체크 ✓ ├─ 충돌 체크 ✓ └─ 승인! 서버: 네트워크 ID 부여 (#12345) 서버: 모든 클라이언트에 브로드캐스트 → T=100ms: 응답 도착 원래 클라: 확정 (불투명) 🏢 다른 클라: 새 건물 생성 🏢 결과: 클릭 후 즉시 반응 (0ms) + 검증 (100ms)

Part 4: 서버 검증 및 롤백

Q: "서버가 거부하면 어떻게 되나요?"

A: 롤백 - 클라이언트에서 건물을 삭제하고 자원을 돌려줍니다.

// 서버: 건축 요청 검증 OnClientBuildRequest(playerID, type, position, rotation): player = GetPlayer(playerID) // 1. 자원 검증 cost = GetBuildingCost(type) if player.resources[material] < cost: return REJECT, reason: "자원 부족" // 2. 위치 검증 if not IsValidBuildLocation(position): return REJECT, reason: "배치 불가능한 위치" // 3. 충돌 검증 (다른 건물, 플레이어) existingBuildings = GetBuildingsAt(position) if existingBuildings.length > 0: return REJECT, reason: "이미 건물이 있음" // 4. 동시 배치 충돌 (Race Condition) if IsPositionReserved(position): return REJECT, reason: "다른 플레이어가 먼저 배치" // 5. 승인 ReservePosition(position) // 다른 요청 차단 player.resources[material] -= cost building = CreateBuilding(type, position, rotation) building.ownerID = playerID building.netID = GenerateNetID() AddToReplicationList(building) // 모든 클라이언트에 전파 return SUCCESS, netID: building.netID
롤백 시나리오:
1. 자원 부족: 클라이언트 카운트 오차 (패킷 손실)
2. 위치 충돌: 두 플레이어가 동시에 같은 곳 배치
3. 치트 탐지: 비정상적으로 빠른 건축 (초당 100개)
4. 물리 오류: 공중에 떠있는 건물 (지지대 없음)

Part 5: AOI 기반 동기화 범위 제한

Q: "100명이 각각 건물을 지으면 모든 건물을 다 받나요?"

A: 아니요. 가까운 건물만 받습니다. (Area of Interest - AOI)

// AOI 기반 리플리케이션 class PlayerReplicationContext: playerID: int position: Vector3 viewDistance: float = 300m // 렌더 거리 knownBuildings: Set[int64] // 이 플레이어가 알고 있는 건물 ID OnServerTick(): for player in allPlayers: // 1. 현재 AOI 내 건물 찾기 nearbyBuildings = GetBuildingsInRange( player.position, player.viewDistance ) // 2. 새로 보이는 건물 (진입) for building in nearbyBuildings: if building.netID not in player.knownBuildings: // 새 건물 전송 (전체 상태) SendFullBuildingState(player, building) player.knownBuildings.add(building.netID) // 3. 멀어진 건물 (퇴장) for buildingID in player.knownBuildings: if buildingID not in nearbyBuildings: // 삭제 명령 SendBuildingDestroy(player, buildingID) player.knownBuildings.remove(buildingID) // 4. 계속 보이는 건물 (업데이트) for building in nearbyBuildings: if building.isDirty: // 상태 변경됨 SendBuildingUpdate(player, building)
AOI 기반 리플리케이션: ┌───────────────────────────────────────┐ │ 전체 맵 │ │ 🏠🏠 (너무 멀어서 안 보냄) │ │ │ │ ┌─────────────┐ │ │ │ 플레이어 │ ← 300m 반경 │ │ │ AOI 범위 │ │ │ │ ● │ │ │ │ 🏢🏢🏢 │ ← 이 건물들만 │ │ │ 🏗️🏗️ │ 전송 │ │ └─────────────┘ │ │ │ │ 🏰🏰 (너무 멀어서 안 보냄) │ └───────────────────────────────────────┘ 대역폭 절감: 전체: 10000개 건물 × 100명 = 1,000,000 업데이트 AOI: 50개 건물 × 100명 = 5,000 업데이트 절감률: 99.5% 🎉

Part 6: 건물 파괴의 연쇄 처리

Q: "아래층 부수면 위층이 같이 무너지는 건 어떻게 처리하나요?"

A: 구조적 의존성 그래프를 만들고, 연쇄적으로 파괴합니다.

// 건물 배치 시 지지 관계 설정 OnBuildingPlaced(building): // 1. 아래에 뭐가 있는지 찾기 below = GetBuildingBelow(building.position) if below: // 지지 관계 설정 building.supportedBy.add(below) below.supporting.add(building) else: // 땅 위면 자체 지지 building.isGrounded = true // 건물 파괴 시 연쇄 전파 OnBuildingDestroyed(building): // 1. 자신을 지지하던 목록에서 제거 for supporter in building.supportedBy: supporter.supporting.remove(building) // 2. 자신이 지지하던 건물들 확인 for dependent in building.supporting: dependent.supportedBy.remove(building) // 3. 지지대가 없어졌나? if dependent.supportedBy.isEmpty() and not dependent.isGrounded: // 연쇄 파괴! ScheduleDestruction(dependent, delay=0.1s) // 연쇄 파괴 애니메이션 ScheduleDestruction(building, delay): Wait(delay) PlayCollapseAnimation(building) DestroyBuilding(building) // 재귀적으로 위층도 파괴 OnBuildingDestroyed(building)
건물 붕괴 연쇄 반응: 초기 상태: 🏠 (3층) | 🏢 (2층) ← 플레이어가 파괴 | 🏗️ (1층) | ═══ (땅) T=0s: 2층 파괴 🏠 (지지대 사라짐!) ✗ 💥 (폭발) | 🏗️ | ═══ T=0.1s: 3층 연쇄 파괴 💥 (떨어지며 폭발) 🏗️ (살아남음 - 땅 위) | ═══ 결과: 중간층 파괴 → 위층 연쇄 붕괴
// 구조적 안정성 검증 ValidateStructuralIntegrity(building): // BFS로 땅까지 경로 찾기 queue = [building] visited = Set() while queue.notEmpty(): current = queue.pop() if current.isGrounded: return STABLE // 땅까지 경로 있음 visited.add(current) for supporter in current.supportedBy: if supporter not in visited: queue.add(supporter) return UNSTABLE // 땅까지 경로 없음 → 붕괴!
최적화:
연쇄 파괴가 동시에 수백 개 발생하면 서버 과부하!
→ 배치 처리: 0.1초마다 묶어서 처리
→ 애니메이션 지연: 순차적으로 무너지는 효과 (시각적 + 성능)
→ 최대 깊이 제한: 100개 이상 연쇄는 즉시 전부 파괴

📚 핵심 요약

  • 특수성: 초고속(초당 10개), 전투 중, 100명 동시 → 네트워크 폭발
  • 건축물 = 네트워크 오브젝트: 체력, 상태, 의존성 모두 동기화
  • 예측 배치: 클라이언트가 먼저 배치 (즉시 반응) → 서버 검증 → 거부 시 롤백
  • 충돌 해결: 동시 배치 시 서버가 먼저 도착한 요청만 승인
  • AOI 최적화: 300m 이내 건물만 전송 (99.5% 대역폭 절감)
  • 연쇄 파괴: 구조 그래프로 지지 관계 추적 → 중간층 파괴 시 위층 붕괴

핵심 트레이드오프: 반응성 (즉시 배치) vs 일관성 (서버 검증)
포트나이트는 예측 + AOI + 연쇄 최적화로 100명 동시 건축을 가능하게 만들었습니다.
