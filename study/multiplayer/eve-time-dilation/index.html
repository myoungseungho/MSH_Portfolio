멀티플레이어 게임 네트워킹으로 돌아가기

4000명이 한 전장에서 싸우는데 서버가 안 터져요?

EVE Online의 Time Dilation (TiDi) 시스템

Part 1: 문제 상황 - 4000명이 동시에 미사일을 쏜다면?

2014년 1월 27일, EVE Online에서 7,548명의 플레이어가 한 성계(Solar System)에서 전투를 벌였어요. 어떻게 서버가 안 터졌을까요?

일반적인 게임 서버라면 당연히 터졌을 거예요. 그런데 EVE Online은 Time Dilation(TiDi)이라는 독특한 시스템을 사용해서 이 문제를 해결했어요.

전통적인 MMO의 한계

보통 MMO 게임에서 한 지역에 플레이어가 몰리면:

플레이어 100명: 서버 부하 ████░░░░░░ (40%) → 정상 작동 플레이어 500명: 서버 부하 ████████░░ (80%) → 약간 느림 플레이어 1000명: 서버 부하 ██████████ (100%) → 크래시! 플레이어 4000명: 💥 서버 터짐!
핵심 문제: 서버는 1초에 처리할 수 있는 계산량이 정해져 있어요. 플레이어가 많아지면 계산이 밀리고, 결국 서버가 터지거나 플레이어를 강제로 쫓아내야 해요.

Part 2: 일반적인 해결책의 한계

그럼 다른 게임들은 어떻게 하나요?

대부분의 게임은 이렇게 해요:

해결책 방법 단점
서버 분리 WoW처럼 수백 개의 서버(렐름)로 나눔 친구와 다른 서버면 함께 못 놀음
인원 제한 한 지역에 최대 100명까지만 허용 대규모 전투 불가능
인스턴스 같은 지역을 여러 복사본으로 분리 진짜 대규모 전투가 아님
서버 업그레이드 더 좋은 하드웨어 사용 한계가 있고 비용 폭증
EVE의 철학: "서버 성능은 한계가 있어. 그럼 게임을 서버에 맞춰버리면 되지 않을까?"

Part 3: Time Dilation - 게임 내 시간을 늦춰버리기

Time Dilation이 뭔가요?

간단히 말하면, 서버가 바쁘면 게임 내 시간을 천천히 흐르게 만드는 거예요.

아인슈타인의 상대성 이론처럼, EVE 세계에서는 서버 부하가 높을수록 시간이 느리게 흘러요!

정상 상태 (TiDi 100%): ═══════════════════════════════════════════════════════ 현실 시간 : 0초 ─────→ 1초 ─────→ 2초 ─────→ 3초 게임 시간 : 0초 ─────→ 1초 ─────→ 2초 ─────→ 3초 서버 부하 : ████░░░░░░ (40%) ═══════════════════════════════════════════════════════ 과부하 상태 (TiDi 10%): ═══════════════════════════════════════════════════════ 현실 시간 : 0초 ───────────────────────────→ 10초 게임 시간 : 0초 ─→ 1초 (게임에서 1초가 현실의 10초!) 서버 부하 : ██████████ (100%) ═══════════════════════════════════════════════════════

TiDi의 작동 원리

// 의사코드: Time Dilation 계산
function calculateTiDi() {
    serverLoad = getCurrentServerLoad();  // 0.0 ~ 1.0

    if (serverLoad < 0.7) {
        return 1.0;  // 100% - 정상 속도
    }
    else if (serverLoad < 0.9) {
        return 0.5;  // 50% - 절반 속도
    }
    else if (serverLoad < 0.95) {
        return 0.3;  // 30% - 1/3 속도
    }
    else {
        return 0.1;  // 10% - 1/10 속도 (최소값)
    }
}

// 모든 게임 이벤트에 TiDi 적용
function processGameTick() {
    tidiRate = calculateTiDi();

    // 1초에 한 번 실행되어야 하는 것을
    // TiDi에 따라 조절
    if (shouldExecute(tidiRate)) {
        updateShipPositions();
        processWeaponFire();
        calculateDamage();
    }

    // 클라이언트에 TiDi 정보 전송
    broadcastTiDiStatus(tidiRate);
}

Part 4: 구현 원리 - 서버 부하 측정부터 클라이언트 동기화까지

1단계: 서버 부하 측정

function measureServerLoad() {
    startTime = getCurrentTime();

    // 1틱 동안의 작업 처리
    processAllPlayers();      // 4000명의 위치 업데이트
    processAllWeapons();      // 수천 발의 미사일 계산
    processAllDamage();       // 충돌 및 데미지 계산

    elapsedTime = getCurrentTime() - startTime;
    targetTickTime = 1000ms;  // 목표: 1초당 1틱

    load = elapsedTime / targetTickTime;
    return load;  // 1.0 = 100%, 2.0 = 200% (과부하!)
}

2단계: TiDi 비율 결정

서버 부하에 따른 TiDi 비율: Load │ TiDi │ 현실 1초 = 게임 ?초 │ 상태 ═══════╪══════╪═══════════════════╪════════════════ 30% │ 100% │ 1초 = 1초 │ ✓ 정상 70% │ 100% │ 1초 = 1초 │ ✓ 정상 80% │ 50% │ 1초 = 0.5초 │ ⚠ TiDi 시작 90% │ 30% │ 1초 = 0.3초 │ ⚠ 심각 100% │ 10% │ 1초 = 0.1초 │ 🔴 극심

3단계: 모든 클라이언트 동기화

핵심: TiDi가 적용되면 모든 플레이어가 동일하게 느려져요. 어떤 플레이어만 빠르거나 느린 게 아니라, 우주 전체의 시간이 느려지는 거예요. 
// 클라이언트에서의 TiDi 처리
function onReceiveTiDi(tidiRate) {
    // 모든 애니메이션 속도 조절
    shipAnimation.speed = tidiRate;
    weaponAnimation.speed = tidiRate;

    // 쿨다운 시간 조절
    weaponCooldown *= tidiRate;  // 10초 → 100초 (TiDi 10%)

    // UI에 표시
    displayTiDiIndicator(tidiRate);  // "Time Dilation: 10%"
}

Part 5: 10% TiDi의 현실 - 1초가 10초처럼 흐른다

TiDi 10%면 실제로 어떻게 느껴지나요?

1초짜리 행동이 10초가 걸려요. 전투 예시로 보면:

행동 정상 시간 TiDi 10% 시간 느낌
미사일 발사 1초 10초 슬로우 모션 영화
워프 준비 10초 100초 (1분 40초) 답답함
함선 폭발 3초 30초 엄청 느린 폭발
채팅 메시지 즉시 즉시 정상 (TiDi 무관)
실제 대규모 전투 타임라인: 14:00 | TiDi 100% | 전투 시작, 500명 집결 | | "적 발견! 공격 개시!" │ 14:10 | TiDi 50% | 1000명 도착, 서버 부하 증가 | | 미사일이 조금 느리게 날아감 │ 14:30 | TiDi 30% | 2000명 전투 중 | | 모든 동작이 1/3 속도로 │ 15:00 | TiDi 10% | 4000명! 최대 부하 | | ← 이 시점부터 시간이 1/10로! │ | 15:10 | TiDi 10% | (게임 내에선 1분만 지남) | | 플레이어들은 전략적으로 움직임 │ 16:00 | TiDi 30% | 전투 종료, 인원 분산 | | 서버 부하 감소 │ 16:30 | TiDi 100% | 정상 속도 복귀
실제 사례: 2014년 B-R5RB 전투는 21시간 동안 진행됐는데, TiDi 10%가 대부분이었어요. 게임 내 시간으로는 약 2시간 정도만 흐른 거죠!

Part 6: 장단점 - 공정성 vs 플레이 경험

TiDi의 장점

  • 서버가 안 터짐: 4000명이 동시에 싸워도 서버가 견딤
  • 공정성 보장: 모든 플레이어가 똑같이 느려지므로 불공평하지 않음
  • 전략적 플레이 가능: 느린 전투 = 더 많이 생각할 시간
  • 모든 액션이 처리됨: 입력 손실이나 롤백 없음

TiDi의 단점

  • 답답함: 버튼 누르고 10초씩 기다리는 건 지루함
  • 시간 소모: 1시간 전투가 10시간으로 늘어남
  • 신규 유저 진입장벽: "이게 정상인가?" 싶은 경험
  • 몰입감 저하: 슬로우 모션 전투는 박진감이 떨어짐
비교 항목 TiDi (EVE) 인원 제한 (일반 MMO)
최대 동시 플레이어 7,000명 이상 가능 보통 100~200명
서버 안정성 항상 안정적 안정적 (인원 강제 제한)
플레이 경험 느리지만 공정함 빠르지만 참여 불가능
전략적 깊이 높음 (생각할 시간 많음) 보통

💡 핵심 정리

Time Dilation이란?

서버가 과부하 상태가 되면, 게임 내 시간을 느리게 흐르게 만들어서 서버가 모든 계산을 완료할 수 있도록 하는 시스템이에요.

핵심 아이디어: ┌────────────────────────────────────────────┐ │ 서버가 1초에 할 일을 1초 안에 못 끝낸다 │ │ ↓ │ │ 그럼 게임 내 1초를 현실 10초로 늘리자! │ │ ↓ │ │ 플레이어는 느리지만 서버는 여유롭게! │ └────────────────────────────────────────────┘

왜 혁신적인가?

  • 서버 한계를 인정하고, 게임 디자인으로 해결
  • 하드웨어 업그레이드 없이 대규모 전투 가능
  • 모든 플레이어에게 공정함 (똑같이 느림)
  • MMO 역사상 최대 규모의 전투 가능하게 만듦

다른 게임에 적용 가능할까?

TiDi는 EVE처럼 전략적이고 느린 페이스의 게임에만 적합해요. FPS나 액션 게임에서 10% TiDi를 적용하면 게임이 안 돼요!

EVE의 교훈: "기술적 한계를 게임 디자인으로 풀 수 있다. 중요한 건 플레이어 경험의 공정성이다."
