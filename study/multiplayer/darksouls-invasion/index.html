침입자가 내 월드에 끼어드는 구조가 뭐예요?

Dark Souls P2P Invasion System
← 멀티플레이어 목록으로

한 줄 요약

다크소울은 P2P (Peer-to-Peer) 구조로 호스트(월드 주인)가 게임 서버 역할을 하며, 침입자는 호스트에게 직접 연결되어 호스트의 규칙을 따릅니다.

Part 1: 침입 시스템의 게임 디자인

Q. 침입이 뭐예요? 왜 갑자기 다른 사람이 내 게임에 들어와요?

다크소울의 침입(Invasion)은 다른 플레이어가 여러분의 월드에 적으로 등장하는 비대칭 PVP 시스템입니다.

침입의 조건
  • 플레이어가 인간성을 회복한 상태 (Embered/Human form)
  • 해당 지역의 보스를 아직 처치하지 않았을 때
  • 온라인 모드 활성화

침입자는 Red Phantom으로 등장하며, 호스트를 죽이는 것이 목표입니다. 반대로 호스트는 침입자를 물리치거나 보스 방으로 도망가야 합니다.

Q. 이게 게임 디자인 관점에서 왜 중요한가요?

침입 시스템은 다크소울의 긴장감을 극대화합니다:

  • 언제 어디서 침입당할지 모르는 불안감 - 안전한 구간이 없음
  • 인간성이라는 리스크/리워드 - 강해지려면 위험을 감수해야 함
  • 예측 불가능한 적 - AI가 아닌 사람이라 패턴이 없음

Part 2: P2P 연결 구조 (Host = 월드 주인)

Q. 서버가 중간에서 중계해주는 게 아니에요?

아닙니다! 다크소울은 P2P (Peer-to-Peer) 구조입니다. 호스트(월드 주인)가 서버 역할을 합니다.

┌─────────────────────────────────────────────────────┐ │ 다크소울 침입 P2P 구조 │ └─────────────────────────────────────────────────────┘ [매치메이킹 서버] │ ┌─────────┴─────────┐ │ │ ▼ ▼ [호스트]◄──────P2P────►[침입자] (월드 주인) (Red Phantom) │ └──► 게임 세계 소유 물리 시뮬레이션 실행 적 AI 제어 아이템 드랍 결정
매치메이킹 서버의 역할
  • 침입 가능한 호스트 목록 제공 (레벨, 지역 기준)
  • 두 플레이어의 IP 주소 교환
  • 연결 성공 후에는 관여하지 않음
Q. 호스트가 서버라는 게 구체적으로 무슨 뜻이에요?

호스트의 게임 클라이언트가 권위(Authority)를 가집니다:

// 의사코드: 침입자가 공격했을 때 [침입자 클라이언트] 1. 칼을 휘두름 (로컬 애니메이션 재생) 2. "나 공격했어" 메시지 → 호스트에게 전송 { action: "ATTACK", position: (x, y, z), direction: (dx, dy, dz), weaponID: 12345 } [호스트 클라이언트] 3. 메시지 수신 4. 호스트의 게임 세계에서 검증: - 침입자가 정말 그 위치에 있나? - 공격 범위 안에 호스트가 있나? - 타이밍이 맞나? (치팅 방지) 5. 검증 통과 → 데미지 계산 6. "너 70 데미지 받았어" → 호스트 자신에게 적용 7. "침입자가 공격 성공" → 침입자에게 전송

모든 게임 로직은 호스트가 최종 결정합니다. 침입자는 요청만 보낼 뿐입니다.

Part 3: 매칭 시스템 (소울 레벨, 무기 강화)

Q. 레벨 1 캐릭터가 레벨 100 침입자 만나면 어떡해요?

그런 일이 일어나지 않도록 레벨 범위 제한(Soul Level Range)이 있습니다:

// 다크소울 3 침입 레벨 공식 호스트 레벨: H 침입자 레벨: I 침입 가능 조건: I >= H - (10 + H * 0.1) I <= H + (10 + H * 0.1) 예시: 호스트 레벨 50 → 침입 가능 범위: 35 ~ 65 호스트 레벨 100 → 침입 가능 범위: 80 ~ 120
무기 강화도 체크
  • 최대 강화 무기 +10을 가진 플레이어는 +8 ~ +10 범위만 매칭
  • 초보자가 +0 무기로 플레이 중이면 고강화 침입자 안 옴
Q. 같은 지역에 있어야만 침입당하나요?

네! 지역(Area)도 매칭 조건입니다:

┌─────────────────────────────────────────────────────┐ │ 지역 기반 매칭 │ └─────────────────────────────────────────────────────┘ [호스트] 로스릭 성벽 (High Wall of Lothric) ↓ [매치메이킹 서버] "로스릭 성벽에서 침입 가능한 호스트 검색" ↓ 결과: - 호스트 A (레벨 20, 로스릭 성벽) ✓ - 호스트 B (레벨 22, 로스릭 성벽) ✓ - 호스트 C (레벨 25, 불의 계승자) ✗ (다른 지역)

Part 4: NAT 문제와 연결 실패

Q. 왜 가끔 "침입 실패" 메시지가 뜨나요?

P2P의 최대 약점: NAT (Network Address Translation) 문제입니다.

NAT란?

공유기가 내부 IP를 외부 IP로 변환하는 기술. 대부분의 가정용 인터넷은 NAT 뒤에 있습니다.

┌─────────────────────────────────────────────────────┐ │ NAT 연결 실패 시나리오 │ └─────────────────────────────────────────────────────┘ [침입자] [호스트] │ │ │ 내부 IP: 192.168.0.5 │ 내부 IP: 192.168.0.10 │ (공유기 A 뒤) │ (공유기 B 뒤) │ │ └──► P2P 연결 시도 ───✗───► 실패 (양쪽 다 NAT 뒤라 직접 연결 불가) 해결책: - UPnP (자동 포트 포워딩) - NAT 펀치스루 (STUN/TURN 프로토콜) - 다크소울은 Steam NAT 서비스 활용

하지만 완벽한 해결은 불가능합니다. 특정 공유기는 P2P를 차단하기도 합니다.

Part 5: 호스트 어드밴티지 (지연 이점)

Q. 침입자가 불리하다는 말이 많던데 왜 그런가요?

P2P 구조 특성상 호스트 어드밴티지가 발생합니다:

// 롤 공격 예시 [침입자 클라이언트] 1. 롤 버튼 누름 (Ping 50ms) 2. "롤 시작" → 호스트에게 전송 (50ms 지연) 3. 침입자 화면에는 이미 롤 중 [호스트 클라이언트] 4. 50ms 후 "롤 시작" 메시지 수신 5. 호스트의 세계에서는 침입자가 아직 서 있음 6. 호스트가 공격 → 명중 판정 7. "너 맞았어" → 침입자에게 전송 [침입자 클라이언트] 8. "내 화면엔 롤로 피했는데 맞았다고?"
왜 이런 일이?
  • 호스트는 지연 없이 자신의 세계에서 판정
  • 침입자의 행동은 네트워크 지연만큼 늦게 호스트에게 도착
  • Ping이 높을수록 불리함 증가
Q. 이 문제를 해결할 방법은 없나요?

P2P 구조에서는 근본적 해결 불가합니다. 대안은:

  • 전용 서버 - 호스트도 침입자도 서버에 연결 (공정함, 하지만 비용 증가)
  • 클라이언트 예측 + 서버 조정 - 현대 FPS 방식 (복잡도 증가)
  • 래그 보상(Lag Compensation) - 과거 시점으로 되돌려 판정

다크소울은 비용과 단순함을 위해 P2P를 선택했고, 그 대가로 공정성을 일부 포기했습니다.

Part 6: 안티치트의 어려움 (P2P 한계)

Q. 해커들이 체력 무한, 순간이동 하는 건 어떻게 막나요?

P2P 구조에서는 안티치트가 매우 어렵습니다:

┌─────────────────────────────────────────────────────┐ │ P2P 치팅 시나리오 │ └─────────────────────────────────────────────────────┘ [정상 침입자] [해커 호스트] │ │ │ "나 공격했어" ───────────► │ │ │ │ (메모리 해킹) │ - HP = 999999 │ - 데미지 무시 │ │ │ ◄───────────── "데미지 0" │ │ │ │ "???" │ → 서버가 없으니 검증할 방법이 없음!
다크소울의 안티치트 시도
  • 통계 기반 탐지 - 비정상적 레벨/아이템 소지 시 플래그
  • Soft Ban Pool - 해커끼리만 매칭
  • Invalid Data 차단 - 말도 안 되는 값은 연결 끊기

하지만 교묘한 해킹은 막기 어렵습니다 (예: 스탯을 살짝만 올림).

Q. 왜 전용 서버를 안 쓰나요?

비용과 게임 디자인 때문입니다:

  • 서버 운영 비용 - 전 세계 플레이어를 위한 서버 인프라 유지
  • 매치 속도 - P2P는 매칭만 하면 바로 연결
  • 게임 특성 - 1:1 또는 1:3 정도의 소규모 전투 (대규모 MMO 아님)

다크소울은 싱글플레이 중심 게임이라 P2P가 합리적 선택이었습니다.

정리

  • 침입 시스템: 긴장감을 위한 비대칭 PVP 설계
  • P2P 구조: 호스트가 게임 서버 역할, 모든 판정 권한
  • 레벨 매칭: 레벨/무기 강화/지역 기준으로 공정성 유지
  • NAT 문제: P2P의 태생적 한계, 연결 실패 가능
  • 호스트 어드밴티지: 지연 없는 판정으로 유리함
  • 안티치트 한계: 중앙 서버 없이 치팅 방지 어려움

핵심 교훈: P2P는 비용 효율적이지만 공정성/보안을 희생합니다. 게임 특성에 맞는 선택이 중요합니다.
