죽은 사람 유령이 보이는 건 어떻게 구현해요?

Asynchronous Multiplayer

Part 1: 비동기 멀티플레이어란 뭔가요?

플레이어들이 동시에 접속하지 않아도 상호작용하는 방식입니다.

[전통 멀티 vs 비동기 멀티] 전통 멀티 (실시간): A ●────● B (동시 접속 필수) │ │ 실시간 전투/협동 비동기 멀티: A ● (12:00) │ └─ 데이터 저장 (혈흔, 메시지) ↓ DB B ● (15:00) ← 데이터 로드 │ A의 흔적 확인 (A는 오프라인)
비동기 멀티플레이어의 특징
  • 실시간 동기화 불필요 (세션 없음)
  • 시간차 상호작용 (과거 플레이어의 흔적)
  • 서버 부하 낮음 (P2P 연결 없음)
  • 혼자서도 멀티플레이어 느낌

다크소울의 비동기 시스템:

  • 혈흔: 다른 플레이어가 죽은 위치 표시
  • 메시지: 바닥에 남긴 글 (힌트, 경고, 트롤)
  • 유령: 다른 플레이어의 반투명 잔상
// 비동기 멀티의 기본 구조 class AsyncMultiplayer { // 실시간 연결 없음! // TCP/UDP 세션 없음! // 데이터 공유 방식 void OnPlayerDeath(Player player) { // 1. 죽음 데이터 생성 DeathData data = new DeathData { playerID = player.ID, position = player.position, timestamp = DateTime.Now, replayData = player.last10Seconds // 마지막 10초 액션 }; // 2. 서버에 업로드 UploadToServer(data); // 3. 끝! (다른 플레이어와 연결 안 함) } // 다른 플레이어가 로드 void OnEnterArea(Area area) { // 1. 서버에서 혈흔 목록 다운로드 List deaths = DownloadDeathsInArea(area); // 2. 화면에 표시 foreach (DeathData death in deaths) { SpawnBloodstain(death.position); } // 3. 원본 플레이어는 오프라인일 수 있음! } }

왜 비동기 방식을 선택했나?

  • 서버 부하 감소: 실시간 동기화 불필요
  • 매칭 불필요: 혼자서도 즐김
  • 분위기 연출: 고독한 세계에 타인의 흔적만
  • 간접 협력: 힌트 제공 (강요 없음)

Part 2: 혈흔 시스템은 어떻게 작동하나요?

죽음 위치 + 리플레이 데이터를 저장했다가 보여줍니다.

[혈흔 생성 → 재생 과정] 플레이어 A: 보스전 중 → 죽음! → 데이터 업로드 │ ├─ 위치 (X, Y, Z) ├─ 타임스탬프 ├─ 캐릭터 외형 └─ 마지막 10초 입력/액션 ↓ [서버 DB] ↓ 플레이어 B (1시간 후): 같은 장소 → 혈흔 발견 → 터치 → 리플레이 재생 ● 👻 (A의 죽음)
혈흔 데이터 구조 실시간 비디오가 아니라 "입력 리플레이"입니다. → 작은 용량 (수십 KB)
// 혈흔 데이터 구조 struct BloodstainData { // 기본 정보 PlayerID ownerID; Vector3 position; DateTime timestamp; // 외형 정보 CharacterAppearance appearance; // 갑옷, 무기 등 int soulLevel; // 리플레이 데이터 (마지막 10초) List inputs; // 입력 기록 /* InputFrame 예시: { time: 0.0, action: MOVE_FORWARD } { time: 0.5, action: ROLL } { time: 1.2, action: ATTACK } { time: 2.5, action: HIT_BY_BOSS } ← 죽음 원인 */ // 메타 정보 int viewCount; // 몇 명이 봤는지 float averageRating; // 평가 (유용했나?) } // 혈흔 생성 void OnPlayerDeath(Player player) { BloodstainData data = new BloodstainData(); // 위치 저장 data.position = player.position; // 외형 저장 data.appearance = player.GetAppearance(); // 마지막 10초 입력 기록 data.inputs = inputRecorder.GetLast10Seconds(); // 서버 업로드 ServerAPI.UploadBloodstain(data); } // 혈흔 재생 void OnActivateBloodstain(Bloodstain stain) { // 1. 데이터 다운로드 BloodstainData data = ServerAPI.Download(stain.ID); // 2. 유령 스폰 Ghost ghost = SpawnGhost(data.appearance); ghost.position = data.position; // 3. 입력 리플레이 foreach (InputFrame frame in data.inputs) { WaitForTime(frame.time); ghost.ApplyInput(frame.action); } // 4. 죽음 애니메이션 ghost.PlayDeathAnimation(); // 5. 페이드 아웃 ghost.FadeOut(); }

서버 최적화:

// 혈흔 필터링 (모든 죽음을 저장하지 않음) void FilterBloodstain(BloodstainData data) { // 1. 지역별 개수 제한 int count = GetBloodstainCountInArea(data.position); if (count > MAX_PER_AREA) { // 오래된 것 삭제 DeleteOldestBloodstain(data.position); } // 2. 품질 필터 if (data.soulLevel < 10) { // 초보 죽음은 50% 확률로만 저장 if (Random() > 0.5) return; } // 3. 중복 위치 제거 if (HasRecentBloodstainNearby(data.position, radius: 5m)) { // 5m 이내 최근 혈흔 있으면 스킵 return; } // 4. 저장 SaveBloodstain(data); } // 클라이언트 로딩 최적화 List LoadBloodstains(Area area) { // 1. 지역 내 혈흔 조회 List all = QueryBloodstains(area); // 2. 샘플링 (너무 많으면) if (all.Count > 50) { // 최신 30개 + 랜덤 20개 var recent = all.OrderByDescending(b => b.timestamp).Take(30); var random = all.Except(recent).OrderBy(x => Random()).Take(20); return recent.Concat(random).ToList(); } return all; }
[혈흔 밀도 관리] 보스 앞 (죽음 많음): ●●●●●●●●●● (100개 혈흔) ↓ 샘플링 ● ● ● ● ● (50개만 표시) 안전 지역 (죽음 적음): ● ● ● (3개 그대로)

게임플레이 효과:

  • 경고: "여기 혈흔 많네? 위험하겠다"
  • 힌트: 죽음 리플레이로 함정 파악
  • 연대감: "나만 죽는 게 아니구나"
  • 트롤: 일부러 낭떠러지에서 떨어진 혈흔 (속임수)

Part 3: 메시지 시스템은 어떻게 구현하나요?

정해진 문구 조합으로 메시지를 만들고 공유합니다.

왜 자유 입력이 아니라 템플릿인가?
  • 욕설/스팸 방지
  • 다국어 자동 번역 가능
  • 데이터 크기 최소화 (텍스트 대신 ID)
// 메시지 템플릿 시스템 enum MessageTemplate { // 주어 WORD_ENEMY, // "적" WORD_TREASURE, // "보물" WORD_TRAP, // "함정" WORD_BOSS, // "보스" // 동사 WORD_AHEAD, // "앞에" WORD_BEHIND, // "뒤에" WORD_BELOW, // "아래" // 형용사 WORD_STRONG, // "강한" WORD_WEAK, // "약한" WORD_HIDDEN, // "숨겨진" // 조합 예시: // "강한 적 앞에" = [WORD_STRONG, WORD_ENEMY, WORD_AHEAD] } // 메시지 데이터 struct MessageData { MessageID id; PlayerID author; Vector3 position; Rotation rotation; // 메시지 방향 (화살표) DateTime timestamp; // 템플릿 조합 TemplateWord[] words; // [WORD_TREASURE, WORD_AHEAD] // 평가 int upvotes; // "도움됨" 투표 int downvotes; // "도움 안 됨" 투표 } // 메시지 작성 void WriteMessage(Player player) { // 1. UI 표시 (단어 선택) List selected = ShowMessageEditor(); // 예: [WORD_TRAP, WORD_BELOW] // 2. 메시지 생성 MessageData msg = new MessageData { author = player.ID, position = player.position, rotation = player.rotation, // 플레이어가 보는 방향 words = selected }; // 3. 서버 업로드 ServerAPI.UploadMessage(msg); } // 메시지 읽기 void ReadMessage(Message msg) { // 1. 데이터 로드 MessageData data = ServerAPI.Download(msg.ID); // 2. 템플릿 → 현지화 텍스트 string text = LocalizeMessage(data.words); // 한국어: "함정 아래" // 영어: "Trap below" // 일본어: "罠の下" // 3. 표시 ShowMessageUI(text); }
[메시지 작성 → 공유 흐름] 플레이어 A (한국): 비밀 통로 발견 → 메시지 작성 [숨겨진] [문] [왼쪽] ↓ [서버 DB] ID: 12345 Words: [HIDDEN, DOOR, LEFT] ↓ 플레이어 B (미국): 메시지 읽기 → "Hidden door to the left" 플레이어 C (일본): 메시지 읽기 → "隠された扉が左に"

평가 시스템:

// 메시지 평가 void RateMessage(Message msg, bool helpful) { if (helpful) { msg.upvotes++; // 작성자에게 보상 (작성자가 오프라인이어도) RewardAuthor(msg.author, HP_RESTORE); // → 다음 접속 시 체력 회복 아이템 받음 } else { msg.downvotes++; } // 낮은 평가 메시지 삭제 if (msg.downvotes > msg.upvotes * 3) { DeleteMessage(msg.ID); // 트롤 메시지 제거 } } // 인기 메시지 우선 표시 List LoadMessages(Area area) { List all = QueryMessages(area); // 평가 점수 계산 foreach (Message msg in all) { msg.score = msg.upvotes - msg.downvotes * 0.5; } // 상위 30개만 표시 return all.OrderByDescending(m => m.score).Take(30).ToList(); }

게임플레이 효과:

  • 힌트: "비밀 벽 앞에" (숨겨진 길 알려줌)
  • 경고: "강한 적 앞에" (준비 시간 제공)
  • 트롤: "보물 아래" (낭떠러지) 😈
  • 밈: "개 앞에" (개 동상 앞에 남김) 😄
간접 협력의 묘미 강요 없이 자연스럽게 도움을 주고받습니다. 도움을 주면 자신도 보상받고요.

Part 4: 유령 시스템은 뭔가요?

다른 플레이어의 실시간 플레이를 반투명하게 보여줍니다.

[유령 시스템 동작] 플레이어 A (현재 플레이 중): 위치: (100, 200, 50) 액션: 달리기 ↓ 주기적 업로드 (5초마다) [서버 DB] 최근 위치 저장 ↓ 플레이어 B (같은 장소): 위치: (105, 198, 51) ← A와 가까움 ↓ 다운로드 A의 유령 표시 👻 (반투명, 상호작용 불가)
유령의 특성
  • 실시간 아님 (5~10초 지연된 과거)
  • 한 방향만 보임 (나는 상대 유령을 보지만, 상대는 내 유령 안 보임)
  • 상호작용 불가 (충돌 없음)
  • 무작위 표시 (모든 플레이어 유령 다 보이면 혼잡)
// 유령 위치 공유 void UpdateGhostData(Player player) { // 5초마다 실행 if (Time.time % 5 == 0) { GhostData data = new GhostData { playerID = player.ID, position = player.position, animation = player.currentAnimation, timestamp = DateTime.Now }; // 서버 업로드 (비동기) ServerAPI.UploadGhostData(data); } } // 유령 로드 void LoadGhosts(Player viewer) { // 1. 내 위치 근처 유령 조회 List nearby = ServerAPI.QueryGhostsNearby( viewer.position, radius: 50m, maxCount: 5 // 최대 5명만 ); // 2. 필터링 foreach (GhostData ghost in nearby) { // 너무 오래된 데이터 제외 (10초 이상) if (DateTime.Now - ghost.timestamp > 10 seconds) { continue; } // 이미 표시 중인 유령 제외 if (activeGhosts.Contains(ghost.playerID)) { continue; } // 3. 유령 스폰 SpawnGhost(ghost); } } // 유령 렌더링 void RenderGhost(Ghost ghost) { // 반투명 쉐이더 ghost.material.alpha = 0.3f; // 흰색 실루엣 ghost.material.color = Color.white; // 충돌 비활성화 ghost.collider.enabled = false; // 애니메이션 재생 (원본 플레이어 동작) ghost.PlayAnimation(ghost.data.animation); }

최적화 전략:

// 유령 샘플링 (너무 많으면) List SampleGhosts(List all) { if (all.Count <= 5) { return all; } // 우선순위 계산 foreach (GhostData ghost in all) { ghost.priority = 0; // 가까울수록 높은 우선순위 ghost.priority += 100 / Distance(viewer, ghost); // 최신일수록 높은 우선순위 ghost.priority += 10 / (DateTime.Now - ghost.timestamp).TotalSeconds; // 레벨 비슷할수록 높은 우선순위 ghost.priority += 5 / Abs(viewer.level - ghost.level); } // 상위 5개만 return all.OrderByDescending(g => g.priority).Take(5).ToList(); } // 유령 수명 관리 void UpdateGhostLifetime(Ghost ghost) { // 1. 원본 플레이어가 멀어지면 페이드 아웃 if (Distance(viewer, ghost) > 60m) { ghost.FadeOut(duration: 2s); RemoveGhost(ghost); } // 2. 데이터가 오래되면 제거 if (DateTime.Now - ghost.timestamp > 15 seconds) { ghost.FadeOut(duration: 1s); RemoveGhost(ghost); } }
[유령 가시성 관리] 내 위치 (플레이어): ● 유령들: ● 10m (표시 O, 우선순위 높음) ● 25m (표시 O) ● 40m (표시 O) ● 55m (표시 O) ● 70m (표시 X, 너무 멀음)

게임플레이 효과:

  • 분위기: "이 세계에 나만 있는 게 아니구나"
  • 힌트: 유령이 가는 길 따라가면 비밀 발견
  • 경고: 유령이 갑자기 사라짐 (죽음?) → 조심
  • 동질감: 같은 장소에서 같은 고생 중인 사람들

Part 5: 서버 구조는 어떻게 생겼나요?

세션 없는 데이터 공유 서버입니다.

[비동기 멀티 서버 구조] [데이터 공유 서버] │ ┌────────────┼────────────┐ │ │ │ [혈흔 DB] [메시지 DB] [유령 DB] │ │ │ ┌───┴───┐ ┌──┴──┐ ┌──┴──┐ 업로드 다운로드 업로드 다운로드 업로드 다운로드 │ │ │ 클라A 클라B 클라C ● ● ● (각자 싱글플레이 중, 실시간 연결 없음)
전통 멀티 서버와의 차이
  • 전통: 세션 유지, 실시간 동기화, 높은 부하
  • 비동기: 세션 없음, 데이터만 공유, 낮은 부하
// 서버 API (RESTful 스타일) // 혈흔 업로드 POST /api/bloodstains { "position": [100, 200, 50], "replayData": [...], "timestamp": "2024-01-15T12:00:00Z" } Response: { "id": 12345 } // 지역 내 혈흔 조회 GET /api/bloodstains?area=boss_room&limit=50 Response: [ { "id": 12345, "position": [...], ... }, { "id": 12346, "position": [...], ... }, ... ] // 메시지 업로드 POST /api/messages { "position": [100, 200, 50], "words": ["WORD_TRAP", "WORD_AHEAD"], "rotation": [0, 90, 0] } // 메시지 평가 POST /api/messages/12345/rate { "helpful": true } // 유령 위치 업로드 POST /api/ghosts { "position": [100, 200, 50], "animation": "running", "timestamp": "2024-01-15T12:00:05Z" } // 근처 유령 조회 GET /api/ghosts?x=100&y=200&z=50&radius=50&limit=5 Response: [ { "playerID": "abc123", "position": [...], "animation": "running" }, ... ]

데이터베이스 스키마:

-- 혈흔 테이블 CREATE TABLE Bloodstains ( id BIGINT PRIMARY KEY, player_id VARCHAR(50), position_x FLOAT, position_y FLOAT, position_z FLOAT, replay_data BLOB, -- 압축된 리플레이 timestamp DATETIME, view_count INT DEFAULT 0, INDEX idx_position (position_x, position_y, position_z), INDEX idx_timestamp (timestamp) ); -- 메시지 테이블 CREATE TABLE Messages ( id BIGINT PRIMARY KEY, player_id VARCHAR(50), position_x FLOAT, position_y FLOAT, position_z FLOAT, words JSON, -- ["WORD_TRAP", "WORD_AHEAD"] upvotes INT DEFAULT 0, downvotes INT DEFAULT 0, timestamp DATETIME, INDEX idx_position (position_x, position_y, position_z), INDEX idx_rating (upvotes, downvotes) ); -- 유령 테이블 (TTL: 15초) CREATE TABLE Ghosts ( player_id VARCHAR(50) PRIMARY KEY, position_x FLOAT, position_y FLOAT, position_z FLOAT, animation VARCHAR(50), timestamp DATETIME, EXPIRE_AT timestamp + INTERVAL 15 SECOND -- 자동 삭제 );

서버 최적화:

// 지역 기반 샤딩 class RegionSharding { // 월드를 100x100 그리드로 분할 int GetShardID(Vector3 position) { int gridX = (int)(position.x / 100); int gridY = (int)(position.z / 100); return gridX * 1000 + gridY; } // 예: 위치 (150, 0, 250) → Shard 1002 // gridX = 1, gridY = 2 → 1*1000 + 2 = 1002 // 조회 시 해당 샤드만 검색 Database GetShard(int shardID) { return shards[shardID]; } } // 캐싱 class DataCache { // Redis 캐시 void CachePopularMessages(Area area) { // 인기 메시지는 메모리 캐싱 List popular = GetTopRatedMessages(area, limit: 10); redis.Set($"messages:{area.id}:popular", popular, ttl: 5분); } // 클라 요청 시 캐시 우선 List GetMessages(Area area) { var cached = redis.Get($"messages:{area.id}:popular"); if (cached != null) { return cached; // 캐시 히트 } // 캐시 미스 → DB 조회 var messages = DB.QueryMessages(area); CachePopularMessages(area); return messages; } }

스케일링:

  • 읽기 위주 워크로드 → 읽기 레플리카 다수
  • 지역별 샤딩 → 부하 분산
  • 인기 데이터 캐싱 → DB 부하 감소
  • CDN 활용 → 리플레이 데이터 전송 가속

Part 6: 게임플레이에 어떤 영향을 주나요?

간접적 상호작용으로 독특한 커뮤니티를 만듭니다.

1. 힌트와 경고

  • 혈흔 많은 곳 = 위험
  • 메시지 "강한 적 앞에" = 준비 시간
  • 유령이 뛰어내림 = 숨겨진 길?
// 게임플레이 패턴 void OnEnterDangerousArea(Player player) { // 혈흔 밀도 확인 int bloodstainCount = GetBloodstainCount(player.position, 20m); if (bloodstainCount > 10) { // 플레이어에게 간접 경고 // (UI 없이 분위기로) ShowBloodstains(); // 플레이어 반응: // "여기 혈흔 엄청 많네... 조심해야겠다" // → 방패 들기, 천천히 이동 } }

2. 트롤과 밈

[트롤 메시지 예시] 낭떠러지 앞: "보물 아래" 메시지 📜 ↓ 플레이어 뛰어내림 💀 죽음 ↓ 혈흔 생성 다음 플레이어: "또 속았네..." 😂 ↓ 메시지에 "도움 안 됨" 투표

커뮤니티 문화:

  • "개 앞에" (개 동상 앞 필수 메시지)
  • "환상 앞에" (아무것도 없는 벽 앞)
  • "점프 필수" (낭떠러지 앞) 😈

3. 간접 협력

// 도움 보상 시스템 void OnMessageRatedHelpful(Message msg) { // 작성자가 오프라인이어도 보상 적립 Player author = GetPlayer(msg.author); // 누적 포인트 author.helpPoints++; // 10포인트마다 아이템 보상 if (author.helpPoints % 10 == 0) { author.inventory.Add(ITEM_HUMANITY); // 인성 아이템 Notify(author, "당신의 메시지가 도움이 되었습니다!"); } } // 선순환 유도 // 도움 → 보상 → 더 많은 메시지 작성 → 커뮤니티 활성화

4. 고독과 연대의 균형

디자인 철학
  • 기본은 혼자 (싱글플레이어 느낌)
  • 가끔 타인의 흔적 (외롭지 않음)
  • 직접 대화 없음 (부담 없음)
  • 도움 선택적 (강요 없음)

플레이어 경험:

  1. 어려운 보스 앞 도착
  2. 혈흔 수십 개 발견 "다들 여기서 죽었구나"
  3. 메시지 읽기 "왼쪽 먼저" → 전략 힌트
  4. 유령 관찰 → 움직임 패턴 학습
  5. 보스 클리어!
  6. 메시지 남김 "해냈다!" → 다음 사람에게 희망

5. 실시간 멀티와의 조합

다크소울은 비동기 + 실시간도 지원:

  • 비동기: 혈흔, 메시지, 유령 (항상)
  • 실시간: 협력/침입 (선택적)
// 하이브리드 멀티플레이어 class DarkSoulsMultiplayer { // 항상 활성화 (비동기) AsyncSystems async = { bloodstains: true, messages: true, ghosts: true }; // 선택적 활성화 (실시간) SyncSystems sync = { coop: player.UsedEmber(), // 엠버 사용 시만 invasion: player.UsedEmber() && !SafeArea() }; }

결과: 혼자서도 즐겁고, 함께해도 즐거운 게임

📚 핵심 요약

  • 비동기 멀티: 실시간 동기화 없이 데이터만 공유 (세션 불필요)
  • 혈흔 시스템: 죽음 위치 + 리플레이 데이터 저장 (입력 기록)
  • 메시지 시스템: 템플릿 조합으로 힌트/경고 공유 (욕설 방지)
  • 유령 시스템: 5~10초 지연된 다른 플레이어 실루엣 (분위기 연출)
  • 서버 구조: RESTful API + 지역 샤딩 + 캐싱 (낮은 부하)
  • 게임플레이: 간접 협력 + 트롤 + 고독과 연대의 균형
