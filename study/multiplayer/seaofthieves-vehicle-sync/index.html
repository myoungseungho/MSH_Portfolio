배가 파도에 출렁이는데 다 똑같이 보여요?

Sea of Thieves 물리 기반 Vehicle 동기화

한 줄 요약

씨오브시브즈는 파도 시뮬레이션 시드를 동기화하고, 배의 물리 상태만 전송하여 모든 클라이언트가 같은 파도에서 같은 배를 봅니다.

Part 1: 배 = 움직이는 플랫폼 위의 플레이어

Q. 배는 왜 동기화하기 어려운가요?

배는 계층 구조를 가진 복잡한 엔티티입니다:

┌─────────────────────────────────────────────────────┐ │ 배의 계층 구조 │ └─────────────────────────────────────────────────────┘ [배 (Ship)] ├─ 위치 (World Position) ├─ 회전 (Pitch, Roll, Yaw) ← 파도에 따라 실시간 변화 ├─ 속도 (Velocity) │ ├─ [돛 (Sails)] │ ├─ 펼침 정도 (0% ~ 100%) │ └─ 각도 (-90° ~ +90°) │ ├─ [키 (Wheel)] │ └─ 회전 각도 (-180° ~ +180°) │ ├─ [대포 (Cannons)] │ ├─ 각 대포의 각도 │ └─ 장전 상태 │ └─ [플레이어들] ├─ 플레이어 A (배 기준 상대 좌표) ├─ 플레이어 B (배 기준 상대 좌표) └─ ...
동기화 과제
  • 배 자체 - 물리 시뮬레이션 (파도 영향)
  • 배 위 플레이어 - 배의 움직임 + 자기 움직임
  • 배의 부품 - 돛, 키, 대포 상태
  • 환경 - 파도, 바람 (모두가 같아야 함)
Q. 일반 FPS와 뭐가 다른가요?

움직이는 좌표계 문제입니다:

// 일반 FPS (정적 월드) 플레이어 위치 = 월드 좌표 (x, y, z) → 동기화: 절대 좌표만 전송 // 씨오브시브즈 (동적 플랫폼) 플레이어 위치 = 배 위치 + 배 기준 상대 좌표 → 동기화: 1. 배 상태 (위치, 회전, 속도) 2. 플레이어의 배 기준 상대 위치 예시: 배 위치: (100, 0, 200) 플레이어 상대 위치: (5, 2, 3) ← 배 갑판 위 5m 앞 파도로 배 회전: Pitch +10°, Roll -5° → 플레이어 실제 위치: (100+5, 0+2, 200+3) + 회전 적용

Part 2: 파도 시뮬레이션 동기화 (Gerstner Waves 시드)

Q. 파도는 랜덤인데, 어떻게 모두가 똑같이 보나요?

Gerstner Waves라는 결정론적 알고리즘을 사용합니다:

// Gerstner Waves 공식 (간소화 버전) float WaveHeight(Vector2 position, float time) { float height = 0; // 여러 파도를 합성 for (int i = 0; i < waveCount; i++) { Wave wave = waves[i]; // 위상 계산 float phase = dot(wave.direction, position) * wave.frequency + time * wave.speed + wave.seed; // ← 핵심! 시드로 재현 가능 // 사인파로 높이 계산 height += wave.amplitude * sin(phase); } return height; } // 동기화 방법 [서버] waves = [ { amplitude: 2.0, frequency: 0.5, speed: 1.0, seed: 12345 }, { amplitude: 1.0, frequency: 1.0, speed: 1.5, seed: 67890 }, ... ]; // 게임 시작 시 모든 클라이언트에게 전송 SendWaveConfig(waves); [클라이언트] // 같은 시드, 같은 시간 → 같은 파도! 매 프레임: WaveHeight(shipPosition, gameTime);
왜 동기화가 자동으로 되는가?
  • 파도 설정(시드)은 게임 시작 시 1번만 전송
  • 게임 시간(gameTime)은 서버와 동기화
  • 같은 위치, 같은 시간 → 같은 파도 높이
  • 매 프레임 파도 데이터 전송 불필요!
Q. 시간이 어긋나면요?

서버 시간 동기화가 필수입니다:

┌─────────────────────────────────────────────────────┐ │ 서버 시간 동기화 │ └─────────────────────────────────────────────────────┘ [클라이언트] 게임 시작 ↓ "현재 시간이 뭐예요?" → [서버] ↓ [서버] 응답: serverTime = 12345.67 ↓ [클라이언트] 시간 동기화 localTime = serverTime; offset = serverTime - localTime; 매 프레임: syncedTime = Time.now + offset; WaveHeight(position, syncedTime); 주기적 재동기화 (30초마다): → Ping 변화, 클럭 드리프트 보정

Part 3: 배의 물리 상태 (위치, 회전, 속도)

Q. 배는 어떤 데이터를 동기화하나요?

배의 물리 상태(Rigidbody State)를 전송합니다:

// 배 동기화 데이터 구조 struct ShipState { // 기본 Transform Vector3 position; // 12 bytes Quaternion rotation; // 16 bytes (쿼터니언) // 물리 상태 Vector3 velocity; // 12 bytes (이동 속도) Vector3 angularVelocity; // 12 bytes (회전 속도) // 배 특화 상태 float sailsDeployment; // 4 bytes (0.0 ~ 1.0) float wheelAngle; // 4 bytes (라디안) float waterLevel; // 4 bytes (침수량) int holeCount; // 4 bytes (구멍 개수) }; 총 크기: 68 bytes per ship 업데이트 주기: 10Hz (초당 10회) 대역폭: 680 bytes/s per ship
왜 속도(Velocity)도 보내나?

위치만 보내면 보간이 부정확합니다. 속도를 함께 보내면 예측(Prediction)이 가능해집니다.

Q. 배가 회전하는 건 어떻게 동기화하나요?

쿼터니언(Quaternion) 보간을 사용합니다:

// 회전 보간 (의사코드) class Ship { Quaternion lastRotation; Quaternion targetRotation; float lastUpdateTime; void OnServerUpdate(ShipState state) { lastRotation = currentRotation; targetRotation = state.rotation; lastUpdateTime = Time.now; } void Update() { float t = (Time.now - lastUpdateTime) / updateInterval; // 쿼터니언 구면 선형 보간 (Slerp) currentRotation = Quaternion.Slerp( lastRotation, targetRotation, t ); // 물리 엔진 적용 (파도 영향) float waveHeight = WaveHeight(position, Time.now); float wavePitch = WavePitch(position, Time.now); float waveRoll = WaveRoll(position, Time.now); // 네트워크 회전 + 파도 회전 합성 finalRotation = currentRotation * waveRotation; } }
┌─────────────────────────────────────────────────────┐ │ 회전 동기화 + 파도 시뮬레이션 합성 │ └─────────────────────────────────────────────────────┘ [서버에서 받은 회전] Yaw: 45° (배가 북동쪽 향함) Pitch: 0° Roll: 0° [로컬 파도 시뮬레이션] 현재 파도에 의한 회전: Pitch: +10° (배 앞부분이 위로) Roll: -5° (배가 왼쪽으로 기울음) [최종 렌더링] Yaw: 45° Pitch: 0° + 10° = 10° Roll: 0° - 5° = -5° → 배가 북동쪽 향하면서 파도에 흔들림!

Part 4: 배 위 플레이어의 상대 좌표

Q. 플레이어가 배 위에서 걸어다니는 건 어떻게 처리하나요?

부모-자식 변환(Parenting Transform)을 사용합니다:

// 배 위 플레이어 위치 계산 class Player { Vector3 localPosition; // 배 기준 상대 좌표 Ship parentShip; // 타고 있는 배 Vector3 GetWorldPosition() { if (parentShip == null) { // 물에 떠있거나 섬에 있음 return absolutePosition; } // 배 위에 있음 return parentShip.position + parentShip.rotation * localPosition; // ↑ 회전 적용 (배가 돌면 플레이어도 돌아감) } void OnPlayerMove(Vector3 inputDirection) { // 입력은 배 기준 좌표계 localPosition += inputDirection * speed * deltaTime; // 서버에 전송 SendToServer({ playerID: myID, localPosition: localPosition, shipID: parentShip.ID }); } }
장점
  • 적은 데이터 - 절대 좌표보다 상대 좌표가 작음
  • 자동 동기화 - 배가 움직이면 플레이어도 따라감
  • 물리 일관성 - 배가 기울면 플레이어도 기울어짐
Q. 배에서 떨어지면요?

부모 연결 해제(Unparent)가 발생합니다:

// 배에서 떨어지는 시퀀스 [클라이언트] 1. 충돌 감지: 플레이어가 배 밖으로 2. 절대 좌표로 전환 absolutePosition = GetWorldPosition(); parentShip = null; 3. 서버에 알림 SendToServer({ action: "UNPARENT", newPosition: absolutePosition, velocity: shipVelocity + jumpVelocity }); [서버] 4. 검증 및 상태 변경 player.parentShip = null; player.position = absolutePosition; player.inWater = true; 5. 브로드캐스트 "플레이어 X가 물에 빠졌습니다" [다른 클라이언트] 6. 플레이어를 배에서 분리 player.parentShip = null; player.position = receivedPosition;

Part 5: 대포, 돛, 키 상호작용

Q. 여러 명이 동시에 돛을 올리면 어떻게 되나요?

서버가 최종 상태를 관리합니다:

// 돛 조작 동기화 [클라이언트 A] 돛을 올림 1. 로컬 애니메이션 시작 (즉각 반응) 2. "돛 올리는 중" → 서버 전송 { action: "RAISE_SAIL", shipID: 123, playerID: A } [서버] 3. 상태 업데이트 ship.sailRaising = true; ship.sailState += 0.1 * deltaTime; // 매 프레임 증가 4. 브로드캐스트 (10Hz) { shipID: 123, sailState: 0.65 // 65% 올라감 } [클라이언트 B가 동시에 내림] 5. "돛 내리는 중" → 서버 전송 { action: "LOWER_SAIL", playerID: B } [서버] 6. 충돌 해결 raisingPlayers = [A] loweringPlayers = [B] // 더 많은 쪽이 이김 if (raisingPlayers.count > loweringPlayers.count) { sailState += speed; // 계속 올라감 } else { sailState -= speed; // 내려감 } → 협동하면 빠르게, 싸우면 느리게!
Q. 대포는 어떻게 동기화하나요?

대포는 이벤트 기반으로 처리합니다:

┌─────────────────────────────────────────────────────┐ │ 대포 발사 동기화 흐름 │ └─────────────────────────────────────────────────────┘ [플레이어] 대포에 탑승 → 조준 → 발사! ↓ [클라이언트] - 발사 이펙트 재생 (즉시) - 탄환 궤적 시뮬레이션 (로컬) ↓ "대포 발사" → [서버] { cannonID: 5, angle: 45°, direction: (1, 0.5, 0), power: 100% } ↓ [서버] 검증 및 시뮬레이션 - 플레이어가 정말 대포에 있나? - 장전되어 있나? - 궤적 계산 (물리 엔진) - 착탄 지점 계산 ↓ [서버] 브로드캐스트 "배 123의 5번 대포 발사" + 궤적 데이터 ↓ [다른 클라이언트] - 대포 발사 이펙트 재생 - 탄환 궤적 렌더링 - 착탄 시 데미지/이펙트

Part 6: 충돌과 침몰 동기화

Q. 배끼리 부딪히면 어떻게 되나요?

서버가 물리 시뮬레이션을 실행합니다:

// 배 충돌 처리 [서버 물리 엔진] 1. 충돌 감지 Ship A (속도 10m/s) vs Ship B (속도 5m/s) 2. 운동량 보존 법칙 적용 newVelocityA = ... newVelocityB = ... 3. 데미지 계산 collisionForce = mass * velocityDiff; damage = collisionForce / durability; 4. 구멍 생성 (충돌 강도에 따라) if (damage > threshold) { CreateHole(shipA, collisionPoint); } 5. 모든 클라이언트에게 브로드캐스트 { shipA: { velocity: newVelocityA, holes: [pos1, pos2] }, shipB: { velocity: newVelocityB, holes: [pos3] } } [클라이언트] 6. 충돌 이펙트 재생 (파티클, 사운드) 7. 구멍 오브젝트 생성 8. 물 유입 시뮬레이션 시작
Q. 침몰은요?

침수량(Water Level)이 임계값을 넘으면 침몰합니다:

// 침몰 시뮬레이션 [서버] 매 프레임: 1. 구멍마다 물 유입 속도 계산 for (hole in ship.holes) { if (!hole.isRepaired) { waterInflow += hole.size * flowRate; } } 2. 플레이어가 물 퍼내는 속도 for (player in ship.players) { if (player.isBailing) { waterOutflow += bailRate; } } 3. 침수량 업데이트 ship.waterLevel += (waterInflow - waterOutflow) * deltaTime; 4. 침몰 체크 if (ship.waterLevel > SINK_THRESHOLD) { ship.isSinking = true; StartSinkAnimation(); } 5. 브로드캐스트 (10Hz) { shipID: 123, waterLevel: 0.75, // 75% 침수 isSinking: false } [클라이언트] - 배가 물에 잠기는 애니메이션 - 물 시뮬레이션 (Particle System) - 침몰 시: 배 제거, 플레이어 물에 빠뜨림
협동의 중요성

구멍을 수리하는 플레이어 + 물을 퍼내는 플레이어 + 배를 조종하는 플레이어가 모두 필요합니다. 이것이 멀티플레이어 협동의 핵심입니다!

정리

  • 계층 구조: 배 → 부품 → 플레이어 (부모-자식 변환)
  • 파도 동기화: Gerstner Waves 시드로 결정론적 시뮬레이션
  • 배 물리 상태: 위치, 회전, 속도, 각속도 전송 (68 bytes, 10Hz)
  • 상대 좌표: 플레이어는 배 기준 로컬 좌표로 관리
  • 상호작용: 돛/키/대포는 서버 권위, 충돌 해결
  • 침몰 시뮬레이션: 침수량 기반, 협동으로 방지

핵심 교훈: 복잡한 물리 시뮬레이션은 서버가 관리하고, 클라이언트는 결정론적 알고리즘(파도)으로 보조하여 대역폭을 절약합니다.
