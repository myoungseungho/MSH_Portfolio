울트 타이밍이 어떻게 전 세계가 똑같아요?

Ability 동기화와 서버 권위

Part 1: 어빌리티 게임의 복잡성

Q: "일반 총쏘기랑 궁극기는 뭐가 다른가요?"

A: 어빌리티는 지속 시간, 상태 변화, 광역 효과가 있어서 훨씬 복잡합니다.

일반 사격:

  • 순간적 (클릭 → 즉시 판정)
  • 단일 대상 또는 직선
  • 상태 변화 없음

어빌리티:

  • 지속 시간 (라인하르트 방벽: 계속 유지)
  • 상태 변화 (겐지 용검: 7초간 칼 모드)
  • 광역 효과 (한조 용: 벽 뚫고 이동)
  • 복잡한 상호작용 (디바 방어매트릭스: 투사체 삭제)
일반 사격 vs 어빌리티 동기화: [일반 사격 - 간단] 클라: 클릭! → 서버: 판정 → 결과: Hit/Miss (단발성) [어빌리티 - 복잡] 클라: Q 키! ↓ 서버: 궁 시작 승인 ↓ ┌─────── 7초 동안 ───────┐ │ • 클라: 애니메이션 재생 │ │ • 서버: 상태 추적 │ │ • 판정: 매 프레임 체크 │ │ • 동기화: 모든 플레이어 │ └────────────────────────┘ ↓ 서버: 궁 종료 ↓ 모든 클라: 정상 상태 복귀

Part 2: 서버 권위 vs 클라이언트 예측

Q: "궁극기를 누가 '진짜로' 발동시키나요? 클라이언트? 서버?"

A: 클라이언트가 먼저 시작하고, 서버가 승인합니다. (Predicted + Server Authority)

// 클라이언트: 즉시 예측 실행 OnPlayerPressQ(): if ult.charge < 100: return // 게이지 부족 if player.isStunned: return // CC기 걸림 // 즉시 로컬에서 시작 (반응성) PlayUltAnimation() PlayUltSound() SetPlayerState(ULTING) // 서버에 요청 SendToServer(REQUEST_ULT_ACTIVATE) // 서버: 검증 후 승인/거부 OnClientRequestUlt(playerID): player = GetPlayer(playerID) // 1. 게이지 확인 if player.ultCharge < 100: return REJECT // 게이지 부족 (치트 시도?) // 2. 상태 확인 if player.isStunned or player.isDead: return REJECT // 3. 쿨다운 확인 if currentTime < player.lastUltTime + COOLDOWN: return REJECT // 4. 승인 player.ultCharge = 0 player.isUlting = true player.ultStartTime = currentTime // 5. 모든 클라이언트에게 브로드캐스트 BroadcastToAll(PLAYER_ULT_START, playerID) return ACCEPT
왜 클라이언트가 먼저 시작하나요?
서버 왕복 시간(RTT) 때문에 서버 응답을 기다리면:
→ Q 누름 → 100ms 대기 → 궁 발동 (느려터짐)

클라이언트 예측으로:
→ Q 누름 → 즉시 발동! (반응적)
→ 서버가 거부하면? → 롤백 (게이지 복구 + "스킬 사용 불가" 메시지)
궁극기 동기화 타임라인: T=0ms: 플레이어 Q 누름 클라: 즉시 애니메이션 시작 🗡️ 클라: 서버에 요청 전송 → T=50ms: 요청 도착 서버: 검증 시작 ├─ 게이지 체크 ✓ ├─ 상태 체크 ✓ └─ 승인! T=50ms: 서버가 브로드캐스트 서버 → 모든 클라이언트: "겐지 궁 시작!" T=100ms: 응답 도착 원래 클라: 승인 확인 (이미 재생 중) 다른 클라: 애니메이션 시작 🗡️ 결과: 모두가 (거의) 동시에 궁을 봄

Part 3: 쿨다운 동기화

Q: "스킬 쿨다운은 클라이언트가 세나요, 서버가 세나요?"

A: 둘 다 셉니다. 하지만 서버가 진실입니다.

// 클라이언트: 예측 쿨다운 OnSkillUse(skillID): skill = GetSkill(skillID) skill.cooldownRemaining = skill.cooldownDuration skill.readyTime = currentTime + skill.cooldownDuration // UI 업데이트 (숫자 카운트다운) UpdateCooldownUI(skill) // 매 프레임 UpdateCooldowns(): for skill in skills: skill.cooldownRemaining -= deltaTime if skill.cooldownRemaining <= 0: skill.isReady = true PlayReadySound() // 띠링! // 서버: 권위 있는 쿨다운 OnClientUseSkill(playerID, skillID): player = GetPlayer(playerID) skill = player.skills[skillID] // 서버가 계산한 쿨다운 확인 if currentTime < skill.readyTime: timeDiff = skill.readyTime - currentTime return REJECT, remainingCooldown: timeDiff // 사용 승인 skill.lastUsedTime = currentTime skill.readyTime = currentTime + skill.cooldownDuration return ACCEPT
클라이언트-서버 쿨다운 불일치 가능성:
1. 시간 동기화 오차 (클라이언트 시계 != 서버 시계)
2. 패킷 손실 (쿨다운 감소 이벤트 누락)
3. 렉 스파이크 (프레임 드랍으로 카운트 느려짐)

해결책: 주기적으로 서버가 "진짜 쿨다운" 전송 → 클라이언트 보정

Part 4: 광역 궁극기 판정 (한조 용, 디바 자폭)

Q: "한조 용이나 디바 자폭 같은 거대한 AOE는 어떻게 판정하나요?"

A: 서버가 매 틱마다 범위 안의 플레이어를 계산합니다.

// 한조 용 (이동하는 AOE) class DragonStrike: position: Vector3 direction: Vector3 speed: float radius: float damagePerSecond: float OnServerTick(deltaTime): // 1. 용 이동 dragonStrike.position += dragonStrike.direction * speed * deltaTime // 2. 범위 내 플레이어 탐색 playersInRange = FindPlayersInSphere( dragonStrike.position, dragonStrike.radius ) // 3. 각 플레이어에게 데미지 for player in playersInRange: // 벽 뒤인지 확인 (용은 벽 뚫음) // 아군인지 확인 (아군은 안 맞음) if player.team != casterTeam: damage = damagePerSecond * deltaTime ApplyDamage(player, damage) // 4. 모든 클라이언트에게 위치 브로드캐스트 BroadcastDragonPosition(dragonStrike.position)
디바 자폭 판정 (순간 AOE): 자폭 발동 시점: ┌─────────────────────────────┐ │ 폭발 중심 💣 │ │ 반경 20m 구체 │ │ ●A (10m, 시야 확보) │ │ |█|●B (15m, 벽 뒤) │ │ ●C (25m, 범위 밖) │ └─────────────────────────────┘ 서버 판정: ├─ 플레이어 A: │ ├─ 거리: 10m ✓ (범위 내) │ ├─ 레이캐스트: 시야 확보 ✓ │ └─ 데미지: 500 (즉사) │ ├─ 플레이어 B: │ ├─ 거리: 15m ✓ (범위 내) │ ├─ 레이캐스트: 벽 차단 ✓ │ └─ 데미지: 0 (안전) │ └─ 플레이어 C: └─ 거리: 25m ✗ (범위 밖) └─ 판정 안 함

라인 오브 사이트(Line of Sight) 체크

// 벽 뒤 숨었는지 확인 CheckDVaBombDamage(player, bombPosition): distance = Distance(player.position, bombPosition) if distance > BOMB_RADIUS: return 0 // 범위 밖 // 레이캐스트로 장애물 확인 ray = CreateRay(bombPosition, player.position) hit = RaycastWorld(ray) if hit.hitObject == player: // 직접 보임 → 데미지 적용 damageRatio = 1.0 - (distance / BOMB_RADIUS) return MAX_DAMAGE * damageRatio else: // 벽 뒤 → 안전 return 0

Part 5: 투사체 vs 히트스캔 차이

Q: "파라 로켓이랑 위도우 총은 동기화가 다른가요?"

A: 네, 완전히 다릅니다.

히트스캔 (위도우메이커, 맥크리)

// 히트스캔: 즉시 판정 OnClientFireHitscan(): 클라: 쏜다! (즉시 레이캐스트) 클라: 서버에 전송 (타임스탬프, 조준 방향) 서버: Lag Compensation 적용 서버: 과거 시점으로 되감기 서버: 레이캐스트 재계산 서버: Hit/Miss 판정 → 물리 객체 없음 (빛의 속도)

투사체 (파라 로켓, 한조 화살)

// 투사체: 서버가 시뮬레이션 OnClientFireProjectile(): 클라: 쏜다! (로컬에서 투사체 생성) 클라: 서버에 요청 서버: 투사체 생성 (권위 있는 버전) 서버: 매 틱마다 이동 시뮬레이션 ├─ 중력 적용 ├─ 충돌 체크 └─ 위치 브로드캐스트 서버: 적중 시 데미지 처리 모든 클라: 투사체 위치 업데이트 (서버 위치로 보정) → 물리 객체 존재 (날아가는 시간 있음)
히트스캔 vs 투사체 동기화: [히트스캔 - 위도우] T=0: 클라 쏨 → 서버 판정 (과거로 되감기) → 즉시 결과 ━━━━━━━━━━━━━━━💥 (레이캐스트) [투사체 - 파라 로켓] T=0: 클라 발사 ●→ T=50ms: 서버 생성 ●→ (서버가 시뮬레이션) T=100ms: 비행 중 →→●→→ T=500ms: 충돌! 💥 차이: 히트스캔은 즉시, 투사체는 시간 걸림

Part 6: "Trading" 현상 (서로 죽이기)

Q: "둘이 동시에 쏴서 둘 다 죽는 게 어떻게 가능한가요?"

A: Lag Compensation과 Favor the Shooter 때문입니다.

Trading 발생 시나리오: 플레이어 A (Ping 100ms) 플레이어 B (Ping 100ms) ────────────────────────────────────────────────── T=0: A가 쏨 [발사!] → T=50: A의 패킷 도착 서버: A 시점으로 되감기 → B는 살아있음 ✓ → A의 샷 적중 판정 → B 죽음 처리 T=100: B가 쏨 (자기 화면엔 살아있음) [발사!] → T=150: B의 패킷 도착 서버: B 시점으로 되감기 → A는 살아있음 ✓ (B가 쏜 순간엔) → B의 샷 적중 판정 → A 죽음 처리 결과: 둘 다 죽음 (Trading)
왜 Trading을 허용하나요?
만약 "먼저 죽은 사람은 샷 취소"라고 하면:
→ 핑이 낮은 사람이 압도적으로 유리
→ B 입장: "내가 쏜 건데 왜 안 맞았어?" (억울)

Trading 허용하면:
→ 각자 화면에서 쏜 건 인정 (Favor the Shooter)
→ 공정성 (핑 차이 보상)
// Trading 방지 로직 (일부 게임) OnPlayerDeath(playerID): player = GetPlayer(playerID) player.isDead = true player.deathTime = currentTime // 죽은 후 발사된 샷 무효화 InvalidateShotsAfter(playerID, currentTime) // 샷 검증 시 OnClientReportHit(shooterID, timestamp): shooter = GetPlayer(shooterID) if shooter.isDead and timestamp > shooter.deathTime: return REJECT // 죽은 후 샷 // ... 나머지 판정

📚 핵심 요약

  • 어빌리티 복잡성: 지속 시간, 상태 변화, 광역 효과로 일반 사격보다 어려움
  • 동기화 모델: 클라이언트 예측 + 서버 권위 (즉시 반응 + 치트 방지)
  • 쿨다운: 클라이언트는 예측, 서버가 진실 (주기적 동기화)
  • 광역 판정: 서버가 매 틱마다 범위 내 플레이어 계산 (레이캐스트로 LoS 확인)
  • 투사체 vs 히트스캔: 투사체는 서버가 시뮬레이션, 히트스캔은 즉시 판정
  • Trading: Lag Compensation으로 동시 킬 가능 (각자 화면에서 쏜 건 인정)

핵심 원칙: 클라이언트는 즉시 반응 (반응성) → 서버가 검증 (공정성)
이 균형이 오버워치의 부드러운 플레이 경험을 만듭니다.
