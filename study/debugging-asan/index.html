AddressSanitizer (ASan)

컴파일 타임 메모리 검사 — 가장 강력한 메모리 디버깅

Part 1. ASan이란?

AddressSanitizer가 뭐야?

Google이 개발한 메모리 오류 탐지 도구.

컴파일 시 코드에 검사 로직이 삽입되어 런타임에 오류를 잡아낸다.

탐지 가능한 버그설명
Heap Buffer Overflow힙 배열 범위 초과 접근
Stack Buffer Overflow스택 배열 범위 초과 접근
Use-After-Free해제된 메모리 접근
Double Free같은 메모리 두 번 해제
Memory Leak메모리 누수 (종료 시 리포트)

Part 2. 설정 방법

VS에서 어떻게 켜?

프로젝트 속성 → C/C++ → General

Enable Address Sanitizer: Yes (/fsanitize=address)

// VS 2019 16.9+ 또는 VS 2022 필요 // 프로젝트 설정 C/C++ → General → Enable Address Sanitizer: Yes // 또는 명령줄 cl /fsanitize=address mycode.cpp // 주의: Debug 빌드에서 사용 권장 // /RTC (런타임 체크)와 충돌할 수 있음

Part 3. 오류 리포트 읽기

오류가 나면 뭐가 출력돼?

상세한 오류 리포트가 출력된다:

==ERROR: AddressSanitizer: heap-buffer-overflow READ of size 1 at 0x602000000014 thread T0 #0 main example.cpp:8 ← 오류 발생 위치 #1 __scrt_common_main_seh 0x602000000014 is located 0 bytes to the right of 4-byte region [0x602000000010,0x602000000014) allocated by thread T0 here: #0 operator new[] #1 main example.cpp:5 ← 할당 위치 // 해석: // - 힙 버퍼 오버플로우 발생 // - example.cpp 8번 줄에서 읽기 시도 // - 4바이트 할당했는데 바로 뒤(0 bytes to the right)를 읽음 // - 할당은 example.cpp 5번 줄에서 함

Part 4. App Verifier vs ASan

둘 다 비슷한 거 아니야?

둘 다 메모리 오류를 잡지만 방식이 다르다:

항목App VerifierASan
적용 방식외부 도구 (레지스트리)컴파일 옵션
스택 오버런❌ 못 잡음✅ 잡음
오버헤드10~100배2~3배
리포트간단상세
재컴파일불필요필요

핵심 정리

  • /fsanitize=address 컴파일 옵션
  • 힙/스택 오버런, UAF, 누수 모두 탐지
  • 상세한 리포트로 원인 파악 쉬움
  • App Verifier보다 빠르고 더 많이 잡음
