PCH - 헤더 반복 파싱 제거하기

Precompiled Header로 컴파일 시간 획기적으로 줄이기

Part 1. 왜 헤더가 문제야?

헤더 파일이 왜 컴파일 느리게 만들어?

지난 시간에 봤듯이, #include는 복붙이야.

그런데 대부분의 .cpp 파일이 같은 헤더를 include해!

📊 일반적인 게임 서버 프로젝트 ┌─────────────────────────────────────────────────────────────┐ │ main.cpp → #include <windows.h> → 5만 줄 파싱 │ │ game.cpp → #include <windows.h> → 5만 줄 파싱 │ │ player.cpp → #include <windows.h> → 5만 줄 파싱 │ │ monster.cpp → #include <windows.h> → 5만 줄 파싱 │ │ item.cpp → #include <windows.h> → 5만 줄 파싱 │ │ ... → ... → ... │ │ (200개 파일) → (200번 반복) → 1억 줄 파싱! │ └─────────────────────────────────────────────────────────────┘ 💥 같은 헤더를 200번 파싱하는 낭비!
아 매번 같은 걸 처음부터 다시 하는구나!

맞아! windows.h는 절대 바뀌지 않는데

매번 처음부터 파싱하니까 시간 낭비가 엄청나.

Part 2. PCH가 뭐야?

그래서 PCH가 뭔데?

Pre-Compiled Header = 미리 컴파일된 헤더!

자주 쓰는 헤더를 한 번만 파싱하고 결과를 저장해둬.

💡 PCH의 아이디어 1️⃣ 처음 한 번: StdAfx.h (공통 헤더 모음) → 파싱 → StdAfx.pch 저장 (3초) 2️⃣ 이후 모든 파일: main.cpp → StdAfx.pch 로드 (0.01초) → 나머지만 파싱 game.cpp → StdAfx.pch 로드 (0.01초) → 나머지만 파싱 player.cpp → StdAfx.pch 로드 (0.01초) → 나머지만 파싱 ... 결과: 3초 + 0.01초 × 200 = 5초! 원래: 3초 × 200 = 600초 = 10분
10분이 5초가 된다고?!

헤더 파싱 부분에서는 그래! 실제로는 다른 작업도 있으니까

전체 빌드 시간이 50~70% 줄어드는 경우가 많아.

Part 3. StdAfx.h에 뭘 넣어?

StdAfx.h가 뭐야?

공통으로 쓰는 헤더를 모아놓은 파일이야!

Visual Studio에서 관례적으로 쓰는 이름.

(pch.h라고도 해)

// StdAfx.h - 미리 컴파일할 헤더 모음 #pragma once // Windows 헤더 #include <windows.h> #include <winsock2.h> // 표준 라이브러리 #include <string> #include <vector> #include <map> #include <memory> // 프로젝트 공통 헤더 #include "TIDefine.h" #include "TIStruct.h"
어떤 기준으로 넣어?

두 가지 조건을 만족하는 헤더:

조건 설명
✅ 자주 쓰는 헤더 대부분의 .cpp에서 include
✅ 변경이 거의 없는 헤더 windows.h, STL, 외부 라이브러리
❌ 자주 바뀌는 헤더 StdAfx.h 바뀌면 전체 재컴파일!

⚠️ StdAfx.h를 수정하면?

.pch 파일을 다시 생성해야 해서 모든 파일이 재컴파일됨!

그래서 자주 바뀌는 헤더는 StdAfx.h에 넣지 않는 게 좋아.

Part 4. Create vs Use

프로젝트 설정에 Create랑 Use가 있던데?

Create: .pch 파일을 만드는 역할

Use: 만들어진 .pch 파일을 사용하는 역할

📁 파일별 역할 StdAfx.cpp → [Create] → StdAfx.pch 생성 (한 번) ↓ main.cpp → [Use] → StdAfx.pch 로드 game.cpp → [Use] → StdAfx.pch 로드 player.cpp → [Use] → StdAfx.pch 로드
// StdAfx.cpp - 딱 이것만! #include "StdAfx.h" // 이 파일의 유일한 목적: // StdAfx.h를 컴파일해서 .pch 파일을 만드는 것
StdAfx.cpp가 그냥 한 줄이네?

맞아! 이 파일은 .pch 생성만을 위해 존재해.

다른 코드 넣으면 안 돼!

Part 5. Visual Studio에서 설정하기

실제로 어떻게 설정해?

프로젝트 속성에서 설정하면 돼!

🔧 Visual Studio 설정 1️⃣ 프로젝트 전체 설정: 프로젝트 속성 → C/C++ → Precompiled Headers ├── Precompiled Header: Use (/Yu) └── Precompiled Header File: StdAfx.h 2️⃣ StdAfx.cpp만 개별 설정: StdAfx.cpp 우클릭 → 속성 → C/C++ → Precompiled Headers └── Precompiled Header: Create (/Yc)
모든 .cpp 파일 앞에 #include "StdAfx.h" 써야 해?

맞아! 반드시 첫 줄에 있어야 해.

// ✅ 올바른 예 #include "StdAfx.h" // 반드시 첫 줄! #include "Player.h" void Player::Attack() { ... } // ❌ 잘못된 예 #include "Player.h" #include "StdAfx.h" // 첫 줄이 아님 → 에러!

Part 6. NotUsing은 언제 써?

어떤 파일은 NotUsing으로 해야 한다던데?

다른 프로젝트의 파일을 가져다 쓸 때!

📂 실제 상황: server_Event 프로젝트 server_Event/ ├── StdAfx.cpp ← Create (이 프로젝트의 PCH 생성) ├── StdAfx.h └── main.cpp ← Use server_Common/ ← 다른 폴더의 공용 파일들 ├── Global.cpp ← ❓ 어떻게 해야 해? ├── Server.cpp └── ...
server_Common 파일들은 StdAfx.h가 없는데?

그 파일들은 자체적으로 필요한 헤더를 include해!

그래서 NotUsing으로 설정해야 해.

🔧 파일별 PCH 설정 server_Event 프로젝트: ├── StdAfx.cpp → Create ├── main.cpp → Use (기본) ├── ..\server_Common\Global.cpp → NotUsing ⚡ ├── ..\server_Common\Server.cpp → NotUsing ⚡ └── ..\server_Game\Event.cpp → Use (StdAfx.h 포함됨) NotUsing = "이 파일은 PCH 안 쓸게. 자체 헤더로 컴파일해줘"

💡 우리 프로젝트에서의 적용

조선협객전 서버에서 server_Event, server_World 프로젝트는

server_Common 폴더의 파일들을 공유해서 사용합니다.

이 파일들(14개)에 NotUsing을 설정하여 PCH 충돌을 해결했습니다.

Part 7. 실제 성능 향상

실제로 얼마나 빨라졌어?

조선협객전 서버 프로젝트 적용 결과:

상태 빌드 시간 단축
PCH 없음 3분 30초 -
PCH 적용 2분 10초 1분 20초 (38%)
📊 왜 이렇게 빨라졌나? Before: ├── windows.h 파싱: 200번 × 1.5초 = 300초 ├── STL 헤더 파싱: 200번 × 0.8초 = 160초 └── 실제 코드 컴파일: 50초 총: 510초 (8분 30초) After: ├── StdAfx.pch 생성: 1번 × 3초 = 3초 ├── .pch 로드: 200번 × 0.01초 = 2초 └── 실제 코드 컴파일: 50초 총: 55초!

📝 핵심 정리

  • PCH = 자주 쓰는 헤더를 한 번만 파싱하고 재사용
  • StdAfx.h에는 자주 쓰고 안 바뀌는 헤더만
  • Create: StdAfx.cpp에만 / Use: 나머지 파일
  • NotUsing: 다른 프로젝트 파일처럼 PCH 안 쓰는 파일
  • #include "StdAfx.h"는 반드시 첫 줄에!
  • 빌드 시간 30~50% 단축 효과
