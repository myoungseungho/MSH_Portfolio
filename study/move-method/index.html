Move Method

메서드 이동 - 책임을 올바른 곳으로

Part 1. 왜 메서드를 옮겨?

메서드가 잘못된 위치에 있다는 게 무슨 말이야?

메서드가 자기 클래스보다 다른 클래스 데이터를 더 많이 쓰면, 잘못된 위치야.

그 다른 클래스로 옮겨야 해.

주방 도구 비유

프라이팬은 주방에 있어야지, 거실에 두면 매번 가져와야 하잖아.

메서드도 마찬가지야. 주로 사용하는 데이터가 있는 클래스에 두는 게 자연스러워.

Part 2. Feature Envy

이동해야 하는지 어떻게 알아?

Feature Envy(기능 편애)를 찾아.

메서드가 자기 클래스보다 다른 클래스에 더 관심을 보이는 상황이야.

Feature Envy 신호

1. 다른 객체의 getter를 여러 번 호출
2. 자기 클래스 멤버보다 다른 클래스 멤버를 더 많이 참조
3. 계산에 필요한 데이터가 대부분 다른 클래스에 있음
예시 들어줘.

Order 클래스에 "배송비 계산" 메서드가 있는데,

고객의 등급, 지역, 멤버십 여부를 다 Customer에서 가져온다면?

그 메서드는 Customer로 이동해야 해.

Part 3. 이동 절차

어떻게 옮겨?

안전하게 단계별로:

Move Method 절차

1단계: 대상 클래스 결정 - 어디가 데이터를 가장 많이 갖고 있나?
2단계: 메서드를 대상 클래스에 복사
3단계: 원본 클래스 참조 필요하면 파라미터로 전달
4단계: 기존 메서드를 위임으로 변경
5단계: 테스트
6단계: 호출부 수정 → 원본 메서드 삭제
한번에 옮기면 안 돼?

절대 안 돼.

위임 단계를 거쳐야 안전해. 테스트하면서 진행해야지.

Part 4. 주의할 점

옮기면 안 되는 경우도 있어?

있어:

Move Method 주의

1. 다형성 필요 - 오버라이드되는 메서드면 계층 구조 고려
2. 순환 의존성 - A→B로 옮겼는데 B가 다시 A 참조하면 문제
3. 캡슐화 위반 - 이동 후 private 멤버 접근해야 하면 재고려
Extract Class랑 같이 쓰기도 해?

자주 같이 써.

Extract Class로 새 클래스 만들고, Move Method로 관련 메서드 이동하면 깔끔해져.

핵심 정리: Move Method

  • 신호: Feature Envy - 다른 클래스 데이터를 더 많이 사용
  • 원칙: 메서드는 다루는 데이터와 가까이
  • 절차: 복사 → 위임 → 테스트 → 삭제
  • 주의: 순환 의존성, 캡슐화 위반
  • 조합: Extract Class와 함께 쓰면 효과적
