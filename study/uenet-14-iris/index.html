Iris — Epic이 복제를 새로 만든 이유

Quantize + Delta로 더 짜내고, 데이터 지향으로 빠르게

30초 요약

Iris = UE5의 차세대 복제 시스템. 같은 정보를 더 적은 바이트로, 더 빠르게(데이터 지향) 보내려는 것.

핵심 기법: Quantize(정밀도 낮춰 비트 절감) + Delta(바뀐 것만) — 우리 quantization·델타압축과 같은 개념.

주의: Iris는 '복제 효율 개선'이지, 영속 MMO를 가능하게 하는 건 아님(Ch15).

Part 1. 왜 또 새로 만들어?

ReplicationGraph로 충분하지 않아?

ReplicationGraph는 '누구에게'를 빠르게 했지. Iris는 '무엇을 어떻게'를 더 짜내. 기존 복제 코드는 객체지향이라 캐시 효율·배치 처리가 약했어.

Iris는 데이터 지향(필요한 데이터를 모아 한꺼번에)으로 재설계해서, 같은 100명을 더 적은 CPU·대역폭으로 처리해.

체감 효과는?

Epic 자료 기준 같은 상황에서 복제 비용이 줄어 프레임 여유가 늘어(예: 100명 붙었을 때 더 안정적). '없던 걸 가능하게'가 아니라 '있던 걸 더 싸게'야.

Part 2. Quantize + Delta로 짜내기

바이트가 얼마나 줄어드는지 봐.

탭으로 ① raw ② Quantize ③ Quantize+Delta 를 바꿔봐. 막대는 틱당 보내는 바이트야. raw 12B 기준선 대비 얼마나 낮아지는지, 누적 절감률을 봐.

Delta는 안 움직이면 거의 0까지 떨어져.

0B누적 전송
0%raw 대비 절감

변경분만더티플래그Delta(이전 상태 대비)
처리 방식구조체 단위Iris = 데이터 지향(배치)
결국 새로운 마법은 아니네?

맞아. Quantize·Delta는 우리도(그리고 모든 네트워크 게임이) 쓰던 기본기야. Iris의 진짜 새로움은 '그걸 엔진 구조 자체를 데이터 지향으로 갈아 더 빠르게·일관되게' 한 거지.

개념은 익숙하고, 구현 수준이 진화한 거야.

Part 4. 오해 정리

Iris 나왔으니 이제 UE로 MMO 되는 거 아냐?

아니. 그게 가장 흔한 오해야. Iris는 '세션형 복제의 효율'을 올린 거지, MMO의 본질(영속 상태·DB 연동·서버간 메시징·수천 명 상시)을 주는 게 아니야.

복제가 빨라져 한 서버 수용 인원이 늘 순 있어도, 'UE 데디서버 하나 = 한 월드'라는 구조는 그대로야. 이 결론을 다음 마지막 챕터에서 못 박아.

핵심 정리

  • Iris = UE5 차세대 복제. '있던 걸 더 싸게'(효율 개선), 데이터 지향 재설계
  • Quantize(정밀도↓ 비트↓) + Delta(바뀐 것만) — 우리 quantization·더티플래그와 같은 개념
  • 막대로 본 절감: raw 12B → Quantize 6B → +Delta 평균 수 B
  • 오해 주의: Iris는 MMO를 가능하게 하는 게 아님 — 복제 효율 개선
  • 개념은 익숙, 구현 수준이 진화한 것
