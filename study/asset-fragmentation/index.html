메모리 단편화와의 전쟁

에셋 로드/언로드 반복으로 발생하는 메모리 조각화 문제와 해결 전략

Part 1. 개념: 메모리 단편화란 무엇인가

메모리 단편화(Memory Fragmentation)가 뭐야?

메모리 공간이 작은 조각으로 분산되어, 총 여유 공간은 충분해도 연속된 큰 블록을 할당할 수 없는 상태야. 게임에서 에셋을 반복적으로 로드/언로드하면 "구멍 뚫린 치즈" 같은 메모리 상태가 돼.

[메모리 단편화 발생 과정]

초기 상태 (깨끗한 메모리)
┌────────────────────────────────────────────────────────────┐
│                      1GB Free                              │
└────────────────────────────────────────────────────────────┘

에셋 A, B, C 로드 후
┌──────────┬───────────┬────────────┬────────────────────────┐
│  A 100MB │  B 200MB  │  C 150MB   │       550MB Free       │
└──────────┴───────────┴────────────┴────────────────────────┘

에셋 B 언로드 (스테이지 전환)
┌──────────┬───────────┬────────────┬────────────────────────┐
│  A 100MB │  🕳️ HOLE  │  C 150MB   │       550MB Free       │
│          │   200MB   │            │                        │
└──────────┴───────────┴────────────┴────────────────────────┘

새 에셋 D (250MB) 로드 시도
총 여유: 200MB + 550MB = 750MB → 충분해 보임
연속 공간: 550MB max → 250MB 할당 가능!

하지만 몇 시간 후...
┌────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬────┐
│ A  │🕳️│ C  │🕳️│ E  │🕳️│ G  │🕳️│ I  │🕳️│ K  │
│50MB│30MB│80MB│20MB│40MB│50MB│60MB│40MB│30MB│60MB│40MB│
└────┴────┴────┴────┴────┴────┴────┴────┴────┴────┴────┘

총 여유: 200MB (조각 합계)
최대 연속 공간: 60MB
→ 100MB 텍스처도 로드 불가! 💥 Out of Memory
외부 단편화와 내부 단편화의 차이가 뭐야?
[단편화의 두 가지 유형]

◆ 외부 단편화 (External Fragmentation)
  - 할당된 블록들 "사이"에 사용 불가능한 작은 공간 발생
  - 위 예시처럼 구멍이 여러 개 뚫린 상태
  - 게임에서 가장 흔한 문제

  ┌──────┐     ┌──────┐     ┌──────┐
  │ Used │ 🕳️ │ Used │ 🕳️ │ Used │
  └──────┘     └──────┘     └──────┘
           ↑           ↑
        외부 단편화 (사이 공간)

◆ 내부 단편화 (Internal Fragmentation)
  - 할당된 블록 "내부"에서 낭비되는 공간
  - 고정 크기 풀에서 작은 객체 할당 시 발생
  - 메모리 정렬(alignment) 요구사항으로도 발생

  요청: 60바이트
  할당: 64바이트 블록 (2^n 정렬)
  ┌─────────────────────────────────┐
  │ 사용: 60바이트 │ 낭비: 4바이트 │  ← 내부 단편화
  └─────────────────────────────────┘

[게임에서의 영향]
┌─────────────────────────────────────────────────────────┐
│ 유형          │ 발생 원인              │ 주요 영향     │
├─────────────────────────────────────────────────────────┤
│ 외부 단편화   │ 다양한 크기의 에셋     │ 할당 실패     │
│               │ 로드/언로드 반복       │ OOM 크래시    │
├─────────────────────────────────────────────────────────┤
│ 내부 단편화   │ 풀 할당자 사용 시      │ 메모리 낭비   │
│               │ 메모리 정렬            │ 효율 저하     │
└─────────────────────────────────────────────────────────┘
왜 게임에서 특히 문제가 돼?

게임은 장시간 연속 실행 + 동적 에셋 로드/언로드의 조합이 일반적이라 단편화에 취약해:

[게임이 단편화에 취약한 이유]

1. 장시간 세션
   ├── MMO: 몇 시간 연속 플레이
   ├── 오픈월드: 스트리밍 지속
   └── 콘솔: 절전모드로 며칠간 유지

2. 동적 에셋 교체
   ├── 스테이지 전환
   ├── 적/NPC 스폰/디스폰
   ├── 이펙트 생성/소멸
   └── UI 팝업/닫기

3. 다양한 에셋 크기
   ├── 텍스처: 256KB ~ 64MB
   ├── 메시: 1KB ~ 10MB
   ├── 사운드: 100KB ~ 50MB
   └── 애니메이션: 500KB ~ 5MB

4. 제한된 메모리 환경
   ├── 모바일: 2~8GB (시스템 공유)
   ├── Switch: 4GB
   ├── PS5/XSX: 16GB (GPU 공유)
   └── 가상 메모리 사용 제한적

[타임라인 예시: 4시간 RPG 세션]
0h   ────────────────────────────────▶ 4h
│ 던전1 ─▶ 마을 ─▶ 던전2 ─▶ 필드 ─▶ ...
│   ↓       ↓        ↓        ↓
│ 로드   언로드    로드    언로드 ... (반복)
│
└▶ 단편화 점점 심화 → 후반부에 크래시 위험!

Part 2. 왜 필요해: 단편화의 실제 비용

단편화 때문에 실제로 어떤 문제가 생겨?

단편화로 인한 실제 장애 시나리오들이야:

[단편화로 인한 실제 장애]

◆ Case 1: OOM 크래시 (가장 흔함)
  상황: 오픈월드 게임 3시간 플레이 후 새 지역 진입
  증상: "Out of Memory" 크래시
  원인: 총 1GB 여유지만 최대 연속 50MB
       256MB 지형 텍스처 할당 실패

  유저 리포트: "왜 램 16GB인데 메모리 부족이죠?"
  실제 원인: GPU 메모리 단편화

◆ Case 2: 성능 저하 (점진적)
  상황: 로비 → 전투 → 로비 반복
  증상: 플레이 시간에 비례해 로딩 느려짐
  원인: 단편화로 할당자가 빈 공간 검색에 시간 소모

  [로딩 시간 증가 그래프]
  로딩시간
    5s │                         ╭──
    4s │                    ╭────╯
    3s │              ╭─────╯
    2s │        ╭─────╯
    1s │  ──────╯
       └────────────────────────────▶ 시간
       0h    1h    2h    3h    4h

◆ Case 3: 비결정적 크래시 (디버깅 악몽)
  상황: QA에서 재현 안 되지만 라이브에서 발생
  증상: 특정 조합/순서에서만 크래시
  원인: 유저마다 다른 플레이 패턴 → 다른 단편화 상태

  재현 조건:
  - 3번째 던전 클리어 후
  - 마을에서 NPC 대화 중
  - 보스 소환 이펙트 로드 시
  → 정확히 이 순서로만 발생!

◆ Case 4: 콘솔 인증 실패
  상황: PS/Xbox 인증 테스트
  증상: "장시간 테스트"에서 불합격
  원인: 8시간 연속 테스트 중 메모리 누수처럼 보임
        (실제로는 단편화)

  콘솔 벤더: "메모리 누수 수정하세요"
  실제 원인: 단편화 관리 미흡
단편화 수준을 어떻게 측정해?

단편화 지표(Fragmentation Metrics)로 정량화할 수 있어:

// Unity - 메모리 단편화 지표 측정 using System; using System.Collections.Generic; using UnityEngine; using UnityEngine.Profiling; public class FragmentationAnalyzer : MonoBehaviour { [Serializable] public struct FragmentationReport { public long TotalFreeBytes; public long LargestFreeBlockBytes; public int FreeBlockCount; public float FragmentationRatio; // 0 = 완벽, 1 = 최악 public float EffectiveUsableRatio; } private List<byte[]> _probeAllocations = new(); /// <summary> /// 메모리 단편화 수준을 프로빙으로 측정 /// 주의: 측정 자체가 메모리에 영향을 주므로 개발 빌드에서만 사용 /// </summary> public FragmentationReport MeasureFragmentation() { var report = new FragmentationReport(); // 1. 현재 여유 메모리 측정 long reservedBefore = Profiler.GetTotalReservedMemoryLong(); long usedBefore = Profiler.GetTotalAllocatedMemoryLong(); report.TotalFreeBytes = reservedBefore - usedBefore; // 2. 프로빙으로 최대 연속 블록 크기 찾기 report.LargestFreeBlockBytes = FindLargestContiguousBlock(); // 3. 단편화 비율 계산 // ratio = 1 - (최대블록 / 총여유) // 0에 가까울수록 좋음 (큰 블록 할당 가능) if (report.TotalFreeBytes > 0) { report.FragmentationRatio = 1f - (float)report.LargestFreeBlockBytes / report.TotalFreeBytes; } // 4. 실효 사용 가능 비율 // 예: 100MB 여유 중 최대 블록이 10MB면 10%만 큰 할당에 사용 가능 report.EffectiveUsableRatio = (float)report.LargestFreeBlockBytes / report.TotalFreeBytes; return report; } private long FindLargestContiguousBlock() { // 이진 탐색으로 할당 가능한 최대 블록 크기 찾기 long low = 1 * 1024 * 1024; // 1MB long high = 512 * 1024 * 1024; // 512MB long largest = 0; while (low <= high) { long mid = (low + high) / 2; if (TryAllocate((int)mid)) { largest = mid; low = mid + 1; } else { high = mid - 1; } } return largest; } private bool TryAllocate(int size) { try { byte[] buffer = new byte[size]; // 할당 성공, 즉시 해제 (GC에 맡김) return true; } catch (OutOfMemoryException) { return false; } } public void LogFragmentationStatus() { var report = MeasureFragmentation(); Debug.Log($"[Memory Fragmentation Report]\n" + $" 총 여유 메모리: {report.TotalFreeBytes / (1024*1024):F1} MB\n" + $" 최대 연속 블록: {report.LargestFreeBlockBytes / (1024*1024):F1} MB\n" + $" 단편화율: {report.FragmentationRatio * 100:F1}%\n" + $" 실효 사용률: {report.EffectiveUsableRatio * 100:F1}%"); // 경고 임계값 if (report.FragmentationRatio > 0.5f) { Debug.LogWarning("⚠️ 단편화율 50% 초과! 메모리 정리 권장"); } if (report.LargestFreeBlockBytes < 64 * 1024 * 1024) { Debug.LogError("🚨 최대 블록 64MB 미만! 큰 에셋 로드 실패 위험"); } } }

Part 3. 실전 적용: 풀 할당자(Pool Allocator)

풀 할당자가 뭐고 어떻게 단편화를 막아?

풀 할당자(Pool Allocator)는 동일한 크기의 객체를 미리 할당해두고 재사용하는 방식이야. 같은 크기만 할당하니까 외부 단편화가 원천적으로 발생하지 않아:

[풀 할당자의 원리]

◆ 일반 할당자 (단편화 발생)
  malloc(100) → malloc(50) → free(100) → malloc(80)

  메모리 상태:
  ┌────────┬───────┬───────────────────────┐
  │  🕳️   │ 50B   │        Free           │
  │ 100B   │       │                       │
  │(빈공간)│       │                       │
  └────────┴───────┴───────────────────────┘
  → 80B 할당 시 100B 구멍 사용? 아니면 뒤에 새로?

◆ 풀 할당자 (단편화 없음)
  Pool<64B>에서 할당/해제

  ┌──────┬──────┬──────┬──────┬──────┬──────┐
  │ 64B  │ 64B  │ 64B  │ 64B  │ 64B  │ 64B  │
  │ Used │ Free │ Used │ Free │ Free │ Used │
  └──────┴──────┴──────┴──────┴──────┴──────┘
  → 모든 블록이 같은 크기 → 어떤 Free든 재사용 가능!

[풀 할당자 종류]
┌─────────────────────────────────────────────────────────┐
│ 유형              │ 특징                │ 용도          │
├─────────────────────────────────────────────────────────┤
│ Fixed-Size Pool   │ 단일 크기 블록      │ 특정 객체     │
│ Slab Allocator    │ 여러 크기 클래스    │ 범용         │
│ Free List Pool    │ 연결 리스트 관리    │ 빈번한 할당  │
│ Ring Buffer       │ FIFO 순환 버퍼      │ 스트리밍 데이터│
└─────────────────────────────────────────────────────────┘
Unity에서 풀 할당자를 어떻게 구현해?

Unity의 ObjectPool<T>을 활용하거나, 에셋용 커스텀 풀을 만들 수 있어:

using System; using System.Collections.Generic; using UnityEngine; using UnityEngine.Pool; // 1. Unity 내장 ObjectPool 활용 public class ProjectilePool : MonoBehaviour { [SerializeField] private GameObject _projectilePrefab; [SerializeField] private int _initialCapacity = 50; [SerializeField] private int _maxSize = 200; private ObjectPool<GameObject> _pool; private void Awake() { _pool = new ObjectPool<GameObject>( createFunc: () => Instantiate(_projectilePrefab), actionOnGet: obj => obj.SetActive(true), actionOnRelease: obj => obj.SetActive(false), actionOnDestroy: obj => Destroy(obj), collectionCheck: true, defaultCapacity: _initialCapacity, maxSize: _maxSize ); // 미리 워밍업 (단편화 방지) WarmUp(_initialCapacity); } private void WarmUp(int count) { var temp = new List<GameObject>(count); for (int i = 0; i < count; i++) { temp.Add(_pool.Get()); } foreach (var obj in temp) { _pool.Release(obj); } } public GameObject Spawn(Vector3 position, Quaternion rotation) { var proj = _pool.Get(); proj.transform.SetPositionAndRotation(position, rotation); return proj; } public void Despawn(GameObject projectile) { _pool.Release(projectile); } } // 2. 텍스처 에셋용 메모리 풀 public class TextureMemoryPool { // 크기별 풀 (2의 제곱 크기) private Dictionary<int, Stack<Texture2D>> _pools = new(); private static readonly int[] SizeClasses = { 64, 128, 256, 512, 1024, 2048, 4096 }; public void Initialize(int texturesPerSize = 5) { foreach (var size in SizeClasses) { _pools[size] = new Stack<Texture2D>(texturesPerSize); // 미리 할당 for (int i = 0; i < texturesPerSize; i++) { var tex = new Texture2D(size, size, TextureFormat.RGBA32, false); _pools[size].Push(tex); } } Debug.Log("TextureMemoryPool 초기화 완료 - " + $"{SizeClasses.Length * texturesPerSize}개 텍스처 사전 할당"); } public Texture2D Acquire(int width, int height) { // 요청 크기를 포함하는 가장 작은 2의 제곱 크기 찾기 int requiredSize = Mathf.Max(width, height); int sizeClass = GetSizeClass(requiredSize); if (_pools.TryGetValue(sizeClass, out var pool) && pool.Count > 0) { return pool.Pop(); } // 풀이 비었으면 새로 생성 (단편화 발생 가능) Debug.LogWarning($"TexturePool[{sizeClass}] 확장 - 단편화 주의"); return new Texture2D(sizeClass, sizeClass, TextureFormat.RGBA32, false); } public void Release(Texture2D texture) { int size = texture.width; if (_pools.TryGetValue(size, out var pool)) { // 내용 초기화 (선택적) // texture.SetPixels32(new Color32[size * size]); pool.Push(texture); } else { // 풀에 맞지 않는 크기는 파괴 UnityEngine.Object.Destroy(texture); } } private int GetSizeClass(int size) { foreach (var s in SizeClasses) { if (s >= size) return s; } return SizeClasses[SizeClasses.Length - 1]; } }

Part 4. 심화 개념: 청크 기반 메모리 관리

청크(Chunk) 관리가 뭐야?

청크 관리는 관련 에셋들을 하나의 큰 연속 메모리 블록으로 묶어 관리하는 방식이야. 한 번에 로드/언로드하므로 단편화가 발생하지 않아:

[청크 기반 메모리 관리]

◆ 개별 에셋 로드 (단편화 발생)
  Stage1 에셋들을 개별 할당:
  ┌──────┬──────┬──────┬──────┬──────┐
  │Tex_A │Mesh_A│Sound │Tex_B │Mesh_B│
  │ 10MB │ 5MB  │ 2MB  │ 8MB  │ 3MB  │
  └──────┴──────┴──────┴──────┴──────┘

  Stage2로 전환 시 일부만 언로드:
  ┌──────┬──────┬──────┬──────┬──────┐
  │ 🕳️  │Mesh_A│ 🕳️  │ 🕳️  │Mesh_B│
  │ 10MB │(공유)│ 2MB  │ 8MB  │(공유)│
  └──────┴──────┴──────┴──────┴──────┘
  → 구멍 발생! (20MB 조각)

◆ 청크 단위 로드 (단편화 없음)
  Stage1 청크 = 모든 에셋을 하나로:
  ┌───────────────────────────────────┐
  │        Stage1 Chunk (28MB)        │
  │ Tex_A + Mesh_A + Sound + Tex_B + …│
  └───────────────────────────────────┘

  Stage2로 전환 시 청크 통째로 교체:
  ┌───────────────────────────────────┐
  │        Stage2 Chunk (32MB)        │
  │         (새로 연속 할당)           │
  └───────────────────────────────────┘
  → 이전 청크 전체 해제 → 구멍 없음!

[공유 에셋 처리]
┌────────────────────────────────────────────────────────┐
│ 청크 계층 구조                                         │
├────────────────────────────────────────────────────────┤
│ [Persistent Chunk] - 절대 언로드 안 함                │
│ ├── 공통 UI                                           │
│ ├── 플레이어 캐릭터                                   │
│ └── 자주 쓰는 이펙트                                  │
│                                                        │
│ [Stage Chunk] - 스테이지별 교체                       │
│ ├── Stage1_Chunk                                      │
│ ├── Stage2_Chunk                                      │
│ └── ...                                               │
│                                                        │
│ [Dynamic Chunk] - 필요시 로드                         │
│ ├── Boss_Chunk                                        │
│ └── CutScene_Chunk                                    │
└────────────────────────────────────────────────────────┘
청크를 코드로 어떻게 구현해?
using System; using System.Collections.Generic; using System.Runtime.InteropServices; using UnityEngine; /// <summary> /// 청크 기반 메모리 관리자 /// 관련 에셋들을 연속된 네이티브 메모리에 할당 /// </summary> public class MemoryChunk : IDisposable { public string Name { get; } public int TotalSize { get; } public int UsedSize { get; private set; } private IntPtr _basePtr; private int _offset; private Dictionary<string, (IntPtr ptr, int size)> _allocations = new(); private bool _disposed; public MemoryChunk(string name, int sizeBytes) { Name = name; TotalSize = sizeBytes; // 네이티브 메모리 할당 (연속된 큰 블록) _basePtr = Marshal.AllocHGlobal(sizeBytes); _offset = 0; Debug.Log($"[MemoryChunk] '{name}' 생성: {sizeBytes / (1024*1024)}MB"); } /// <summary> /// 청크 내에서 메모리 할당 (선형 할당자) /// </summary> public IntPtr Allocate(string assetName, int size, int alignment = 16) { // 정렬 조정 int alignedOffset = (_offset + alignment - 1) & ~(alignment - 1); if (alignedOffset + size > TotalSize) { throw new OutOfMemoryException( $"[MemoryChunk] '{Name}' 공간 부족: " + $"요청 {size}B, 여유 {TotalSize - alignedOffset}B"); } IntPtr ptr = IntPtr.Add(_basePtr, alignedOffset); _allocations[assetName] = (ptr, size); _offset = alignedOffset + size; UsedSize = _offset; return ptr; } /// <summary> /// 데이터를 청크에 복사 /// </summary> public void CopyData(string assetName, byte[] data) { IntPtr ptr = Allocate(assetName, data.Length); Marshal.Copy(data, 0, ptr, data.Length); } /// <summary> /// 특정 에셋의 포인터 가져오기 /// </summary> public IntPtr GetPointer(string assetName) { if (_allocations.TryGetValue(assetName, out var alloc)) { return alloc.ptr; } return IntPtr.Zero; } /// <summary> /// 청크 전체 초기화 (재사용) /// 개별 해제 없이 한 번에 리셋 /// </summary> public void Reset() { _allocations.Clear(); _offset = 0; UsedSize = 0; // 선택적: 메모리 제로화 // unsafe { NativeMemory.ZeroMemory(_basePtr, TotalSize); } } public void Dispose() { if (!_disposed) { Marshal.FreeHGlobal(_basePtr); _disposed = true; Debug.Log($"[MemoryChunk] '{Name}' 해제"); } } } /// <summary> /// 스테이지별 청크 관리자 /// </summary> public class StageChunkManager { private MemoryChunk _persistentChunk; // 상주 에셋 private MemoryChunk _stageChunkA; // 더블 버퍼 A private MemoryChunk _stageChunkB; // 더블 버퍼 B private MemoryChunk _currentStage; private bool _useChunkA = true; public void Initialize( int persistentSizeMB = 64, int stageSizeMB = 128) { _persistentChunk = new MemoryChunk("Persistent", persistentSizeMB * 1024 * 1024); // 더블 버퍼링: 전환 시 단편화 방지 _stageChunkA = new MemoryChunk("Stage_A", stageSizeMB * 1024 * 1024); _stageChunkB = new MemoryChunk("Stage_B", stageSizeMB * 1024 * 1024); _currentStage = _stageChunkA; } public MemoryChunk PrepareNextStage() { // 사용하지 않는 청크 가져오기 var nextChunk = _useChunkA ? _stageChunkB : _stageChunkA; nextChunk.Reset(); return nextChunk; } public void SwitchToNextStage() { // 청크 전환 _useChunkA = !_useChunkA; _currentStage = _useChunkA ? _stageChunkA : _stageChunkB; Debug.Log($"[StageChunkManager] 스테이지 전환: {_currentStage.Name}"); } }
Addressables와 청크 관리를 어떻게 연동해?
using System.Collections.Generic; using System.Threading.Tasks; using UnityEngine; using UnityEngine.AddressableAssets; using UnityEngine.ResourceManagement.AsyncOperations; /// <summary> /// Addressables 청크 로더 /// 관련 에셋을 그룹으로 묶어 한 번에 로드/언로드 /// </summary> public class AddressableChunkLoader { private Dictionary<string, List<AsyncOperationHandle>> _loadedChunks = new(); /// <summary> /// 청크(라벨) 단위로 에셋 로드 /// </summary> public async Task LoadChunkAsync(string chunkLabel) { if (_loadedChunks.ContainsKey(chunkLabel)) { Debug.LogWarning($"청크 '{chunkLabel}' 이미 로드됨"); return; } var handles = new List<AsyncOperationHandle>(); // 1. 청크의 모든 에셋 주소 가져오기 var locationsHandle = Addressables.LoadResourceLocationsAsync( chunkLabel, typeof(Object)); await locationsHandle.Task; if (locationsHandle.Status != AsyncOperationStatus.Succeeded) { Debug.LogError($"청크 '{chunkLabel}' 위치 로드 실패"); return; } // 2. 모든 에셋 병렬 로드 var loadTasks = new List<Task>(); foreach (var location in locationsHandle.Result) { var handle = Addressables.LoadAssetAsync<Object>(location); handles.Add(handle); loadTasks.Add(handle.Task); } // 모든 에셋 로드 완료 대기 await Task.WhenAll(loadTasks); _loadedChunks[chunkLabel] = handles; Debug.Log($"[AddressableChunk] '{chunkLabel}' 로드 완료: " + $"{handles.Count}개 에셋"); } /// <summary> /// 청크 단위로 에셋 언로드 /// </summary> public void UnloadChunk(string chunkLabel) { if (!_loadedChunks.TryGetValue(chunkLabel, out var handles)) { Debug.LogWarning($"청크 '{chunkLabel}' 로드되지 않음"); return; } // 모든 핸들 해제 foreach (var handle in handles) { Addressables.Release(handle); } _loadedChunks.Remove(chunkLabel); // 메모리 압축 요청 (GC + 언로드) Resources.UnloadUnusedAssets(); System.GC.Collect(); Debug.Log($"[AddressableChunk] '{chunkLabel}' 언로드 완료"); } /// <summary> /// 스테이지 전환: 이전 청크 언로드 → 새 청크 로드 /// 단편화 최소화를 위해 순서 중요 /// </summary> public async Task TransitionStageAsync(string fromChunk, string toChunk) { Debug.Log($"스테이지 전환: {fromChunk} → {toChunk}"); // 1. 새 청크 먼저 다운로드 (로드는 안 함) var downloadHandle = Addressables.DownloadDependenciesAsync(toChunk); await downloadHandle.Task; Addressables.Release(downloadHandle); // 2. 이전 청크 언로드 (메모리 확보) UnloadChunk(fromChunk); // 3. 잠시 대기 (GC 완료) await Task.Yield(); // 4. 새 청크 로드 await LoadChunkAsync(toChunk); Debug.Log("스테이지 전환 완료"); } }

Part 5. 고급 패턴: 디프래그멘테이션

이미 단편화가 발생했으면 어떻게 해?

디프래그멘테이션(Defragmentation)으로 메모리를 압축할 수 있지만, 게임 런타임에서는 제한적이야:

[디프래그멘테이션 전략]

◆ 불가능한 방법: 직접 메모리 이동
  - 게임 런타임에서 에셋 포인터 변경 불가
  - 텍스처, 메시 등은 GPU 메모리에 있음
  - 이동하면 모든 참조 무효화 → 크래시

◆ 가능한 방법 1: Unload → Reload
  현재 상태:
  ┌──────┬───────┬──────┬───────┬──────┐
  │ A    │ 🕳️   │ B    │ 🕳️   │ C    │
  └──────┴───────┴──────┴───────┴──────┘

  1. 활성 에셋 목록 수집 (A, B, C)
  2. 전체 언로드
  ┌─────────────────────────────────────┐
  │              Empty                  │
  └─────────────────────────────────────┘

  3. 순서대로 다시 로드
  ┌──────┬──────┬──────┬────────────────┐
  │ A    │ B    │ C    │     Free       │
  └──────┴──────┴──────┴────────────────┘
  → 연속된 큰 Free 블록 확보!

  ⚠️ 단점: 로딩 화면 필요, 긴 중단 시간

◆ 가능한 방법 2: 점진적 압축
  - 로딩 화면 없이 프레임마다 조금씩
  - 사용 빈도 낮은 에셋부터 재로드
  - 완전 압축은 불가, 부분 개선
Unload-Reload 디프래그를 코드로 어떻게 해?
using System; using System.Collections; using System.Collections.Generic; using System.Linq; using UnityEngine; using UnityEngine.AddressableAssets; using UnityEngine.ResourceManagement.AsyncOperations; public class MemoryDefragmenter : MonoBehaviour { public event Action<float> OnProgress; public event Action OnComplete; private Dictionary<string, Type> _loadedAssets = new(); private Dictionary<string, AsyncOperationHandle> _handles = new(); /// <summary> /// 메모리 디프래그멘테이션 실행 /// 로딩 화면 중에 호출 권장 /// </summary> public IEnumerator DefragmentAsync() { Debug.Log("[Defrag] 시작..."); // 1. 현재 로드된 에셋 정보 수집 var assetInfo = _loadedAssets.ToList(); int total = assetInfo.Count; int processed = 0; if (total == 0) { Debug.Log("[Defrag] 로드된 에셋 없음"); OnComplete?.Invoke(); yield break; } // 2. 모든 에셋 언로드 Debug.Log($"[Defrag] {total}개 에셋 언로드 중..."); foreach (var handle in _handles.Values) { Addressables.Release(handle); } _handles.Clear(); // GC 실행 Resources.UnloadUnusedAssets(); GC.Collect(); GC.WaitForPendingFinalizers(); GC.Collect(); yield return new WaitForSeconds(0.5f); // GC 완료 대기 OnProgress?.Invoke(0.3f); // 3. 에셋 순서대로 다시 로드 Debug.Log("[Defrag] 에셋 재로드 중..."); foreach (var (address, type) in assetInfo) { var handle = Addressables.LoadAssetAsync<UnityEngine.Object>(address); while (!handle.IsDone) { yield return null; } if (handle.Status == AsyncOperationStatus.Succeeded) { _handles[address] = handle; } processed++; OnProgress?.Invoke(0.3f + 0.7f * processed / total); } Debug.Log("[Defrag] 완료!"); OnComplete?.Invoke(); } /// <summary> /// 점진적 디프래그: 프레임당 1개씩 재로드 /// 로딩 화면 없이 백그라운드에서 실행 /// </summary> public IEnumerator IncrementalDefragAsync(int assetsPerFrame = 1) { // 사용 빈도 낮은 순으로 정렬 (예: 최근 접근 시간 기준) var candidates = GetLowPriorityAssets(); int processed = 0; foreach (var address in candidates) { // 언로드 if (_handles.TryGetValue(address, out var oldHandle)) { Addressables.Release(oldHandle); _handles.Remove(address); } // 재로드 var newHandle = Addressables.LoadAssetAsync<UnityEngine.Object>(address); yield return newHandle; if (newHandle.Status == AsyncOperationStatus.Succeeded) { _handles[address] = newHandle; } processed++; if (processed % assetsPerFrame == 0) { yield return null; // 프레임 양보 } } } private IEnumerable<string> GetLowPriorityAssets() { // 실제 구현: 접근 시간, 사용 빈도 기준 정렬 return _loadedAssets.Keys.Take(10); } }
