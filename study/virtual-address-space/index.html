게임이 "메모리 부족"이라는데 RAM은 남았는데?

가상 주소 공간(Virtual Address Space)의 이해

Part 1. 이상한 메모리 부족 현상

유저가 "메모리 16GB인데 왜 튕겨요?" 라고 물어봐. 뭐라고 해?

이건 물리 메모리(RAM)와 가상 주소 공간의 차이 때문이야!

유저 컴퓨터의 RAM이 아무리 많아도, 프로그램이 사용할 수 있는 "주소"가 부족하면 튕겨.

흔한 오해: 유저: "제 컴퓨터 RAM 16GB인데요?" ┌────────────────────────────────────────────────────┐ │ 물리 메모리 (RAM) │ │ [████████████████░░░░░░░░░░░░░░░░░░░░] │ │ 8GB 사용중 8GB 남음 │ │ │ │ "RAM이 남았으니까 프로그램이 더 쓸 수 있겠지?" │ │ ↓ │ │ 틀렸습니다! │ └────────────────────────────────────────────────────┘ 실제 상황: 유저의 32비트 게임: ┌────────────────────────────────────────────────────┐ │ 가상 주소 공간 (Virtual Address Space) │ │ [████████████████████████████████████████] │ │ 0x00000000 0xFFFFFFFF │ │ ↑ │ │ 2GB 한계에 도달! (32비트 프로세스) │ │ │ │ RAM이 16GB 있어도, "주소"를 쓸 수 없으면 끝! │ └────────────────────────────────────────────────────┘

Part 2. 가상 주소 공간이란?

가상 주소 공간이 뭐야?

프로세스가 마치 "혼자서 전체 메모리를 다 쓰는 것처럼" 보이게 해주는 시스템이야.

실제로는 OS가 가상 주소를 물리 주소로 변환해주고 있어.

가상 주소 공간의 핵심 개념: ┌──────────────────────────────────────────────────────────────┐ │ │ │ 프로세스 A 프로세스 B │ │ "내가 0x1000 쓴다!" "나도 0x1000 쓴다!" │ │ │ │ │ │ ▼ ▼ │ │ ┌─────────────┐ ┌─────────────┐ │ │ │ 가상 주소 │ │ 가상 주소 │ │ │ │ 0x1000 │ │ 0x1000 │ │ │ └──────┬──────┘ └──────┬──────┘ │ │ │ │ │ │ └─────────┬──────────────────┘ │ │ ▼ │ │ ┌──────────────────┐ │ │ │ 페이지 테이블 │ (OS가 관리하는 변환 테이블) │ │ │ A: 0x1000 → 물리 0x5000 │ │ │ B: 0x1000 → 물리 0x8000 │ │ └──────────────────┘ │ │ │ │ │ ▼ │ │ ┌───────────────────────────────────────────────────┐ │ │ │ 물리 메모리 (RAM) │ │ │ │ 0x5000: [프로세스 A 데이터] │ │ │ │ 0x8000: [프로세스 B 데이터] │ │ │ └───────────────────────────────────────────────────┘ │ │ │ │ 같은 가상 주소 0x1000이 다른 물리 주소로 매핑! │ │ │ └──────────────────────────────────────────────────────────────┘
왜 이런 복잡한 걸 만들었어?

여러 가지 이유가 있어:

가상 메모리의 장점: 1. 프로세스 격리 ┌─────────────────────────────────────────────────┐ │ 프로세스 A가 0x1000에 뭘 써도 │ │ 프로세스 B의 0x1000은 영향 없음! │ │ │ │ → 한 프로그램 크래시해도 다른 프로그램 안전 │ └─────────────────────────────────────────────────┘ 2. 메모리 보호 ┌─────────────────────────────────────────────────┐ │ 페이지별로 권한 설정 가능: │ │ - 읽기 전용 (코드 영역) │ │ - 읽기/쓰기 (데이터 영역) │ │ - 실행 금지 (스택, 힙) │ │ │ │ → 버퍼 오버플로우 공격 방어에 필수! │ └─────────────────────────────────────────────────┘ 3. RAM보다 큰 메모리 사용 ┌─────────────────────────────────────────────────┐ │ RAM: 4GB │ │ 프로세스가 원하는 메모리: 8GB │ │ │ │ → 안 쓰는 부분은 디스크(페이지 파일)에 저장 │ │ → 필요할 때 다시 RAM으로 로드 │ └─────────────────────────────────────────────────┘

Part 3. 페이지 테이블의 동작

페이지 테이블이 어떻게 동작해?

가상 주소를 페이지 단위(보통 4KB)로 나눠서 물리 주소와 매핑해.

페이지 테이블 동작 원리: 가상 주소: 0x12345678 (32비트) ┌────────────────────────────────────────────────────┐ │ │ │ [0x12345] [0x678] │ │ ↓ ↓ │ │ 페이지 번호 페이지 내 오프셋 │ │ │ └────────────────────────────────────────────────────┘ │ ▼ ┌────────────────────────────────────────────────────┐ │ 페이지 테이블 (프로세스마다 별도) │ ├───────────────┬─────────────┬──────────────────────┤ │ 가상 페이지 │ 물리 프레임 │ 플래그 │ ├───────────────┼─────────────┼──────────────────────┤ │ 0x12344 │ 0xABC00 │ R/W, Present │ │ 0x12345 │ 0x78900 │ R/W, Present │ │ 0x12346 │ - │ Not Present (swap) │ └───────────────┴─────────────┴──────────────────────┘ │ ▼ 물리 주소 = 0x78900 + 0x678 = 0x78F78 플래그 설명: - Present: RAM에 있음 (없으면 페이지 폴트!) - R/W: 읽기/쓰기 가능 - User: 유저 모드 접근 가능 - Dirty: 수정됨 (swap 시 디스크에 써야 함)
페이지 폴트가 뭐야?

접근하려는 페이지가 RAM에 없을 때 발생하는 인터럽트야.

OS가 디스크에서 해당 페이지를 읽어서 RAM에 올려줘.

페이지 폴트 처리 과정: ┌────────────────────────────────────────────────────────────┐ │ 1. CPU가 가상 주소 0x12346678 접근 시도 │ │ ↓ │ │ 2. 페이지 테이블 확인 → 0x12346 페이지가 "Not Present"! │ │ ↓ │ │ 3. 페이지 폴트 발생! (CPU 예외) │ │ ↓ │ │ 4. OS 페이지 폴트 핸들러 실행 │ │ ├─ 빈 물리 프레임 찾기 │ │ ├─ (없으면) 안 쓰는 페이지를 디스크로 swap-out │ │ └─ 디스크에서 필요한 페이지를 RAM으로 swap-in │ │ ↓ │ │ 5. 페이지 테이블 업데이트 (Present = 1) │ │ ↓ │ │ 6. 원래 명령어 다시 실행 │ └────────────────────────────────────────────────────────────┘ 페이지 폴트가 너무 자주 일어나면? → 쓰래싱(Thrashing)! → 디스크 I/O가 병목이 되어 시스템이 매우 느려짐

Part 4. 실제 게임에서의 메모리 부족 사례

실제로 어떤 문제가 생겨?

32비트 게임에서 가장 흔한 문제는 가상 주소 공간 고갈이야.

실제 사례: 32비트 MMORPG ┌──────────────────────────────────────────────────────────────┐ │ 가상 주소 공간 (2GB 한계) │ ├──────────────────────────────────────────────────────────────┤ │ │ │ 0x00000000 ┌────────────────────┐ │ │ │ EXE 코드 │ 100MB │ │ 0x00400000 ├────────────────────┤ │ │ │ DLL들 │ 300MB │ │ │ (DirectX, 물리엔진)│ │ │ 0x10000000 ├────────────────────┤ │ │ │ 텍스처 메모리 │ 800MB │ │ │ (VRAM 미러링) │ │ │ 0x40000000 ├────────────────────┤ │ │ │ 3D 모델 데이터 │ 400MB │ │ │ │ │ │ 0x60000000 ├────────────────────┤ │ │ │ 게임 오브젝트 힙 │ 300MB │ │ │ │ │ │ 0x70000000 ├────────────────────┤ │ │ │ 단편화된 빈 공간 │ 100MB (조각조각) │ │ │ │ │ │ 0x7FFFFFFF └────────────────────┘ │ │ │ │ 총 사용: ~1.9GB / 한계: 2GB │ │ 100MB 남았지만, 50MB 연속 공간이 없어서 할당 실패! │ │ │ └──────────────────────────────────────────────────────────────┘
왜 조각나는 거야?

동적 할당/해제가 반복되면서 외부 단편화가 발생해.

// 게임 플레이 중 메모리 상태 변화 초기 상태: [████████████████████████████████████████░░░░░░░░░░] 텍스처A 모델B 텍스처C 모델D 사운드E 빈 공간 존 이동 후 (일부 언로드): [████████░░░░░░░░████████░░░░░░░░████████░░░░░░░░░░] 텍스처A (해제) 텍스처F (해제) 사운드E 빈 공간 ↓ 새 텍스처 G (200MB) 로드 시도 ↓ 연속된 200MB 공간이 없어서 실패! (빈 공간 총합은 300MB지만, 가장 큰 연속 공간은 100MB)
해결 방법은?

여러 가지 전략이 있어:

메모리 단편화 해결 전략: 1. 64비트로 전환 ┌────────────────────────────────────────────────┐ │ 가상 주소 공간: 2GB → 128TB │ │ 단편화가 있어도 공간이 넉넉함 │ └────────────────────────────────────────────────┘ 2. 메모리 풀 사용 ┌────────────────────────────────────────────────┐ │ 같은 크기 객체끼리 모아서 관리 │ │ → 외부 단편화 최소화 │ │ │ │ 예: 몬스터 풀, 이펙트 풀, 네트워크 패킷 풀 │ └────────────────────────────────────────────────┘ 3. 대용량 할당 미리 예약 ┌────────────────────────────────────────────────┐ │ 게임 시작 시 텍스처용 1GB 미리 VirtualAlloc │ │ → 나중에 단편화로 못 잡는 상황 방지 │ └────────────────────────────────────────────────┘ 4. /LARGEADDRESSAWARE 플래그 ┌────────────────────────────────────────────────┐ │ 32비트 프로세스도 최대 4GB까지 사용 가능 │ │ (64비트 Windows에서 실행 시) │ └────────────────────────────────────────────────┘

Part 5. 디버깅: 메모리 상태 확인하기

가상 주소 공간 상태를 어떻게 확인해?

VMMap 도구가 가장 직관적이야 (Sysinternals 제공, 무료).

// 코드로 가상 메모리 상태 확인하기 #include <windows.h> #include <psapi.h> void PrintMemoryInfo() { MEMORYSTATUSEX memInfo; memInfo.dwLength = sizeof(MEMORYSTATUSEX); GlobalMemoryStatusEx(&memInfo); printf("물리 메모리 전체: %llu MB\n", memInfo.ullTotalPhys / (1024 * 1024)); printf("물리 메모리 사용 가능: %llu MB\n", memInfo.ullAvailPhys / (1024 * 1024)); printf("가상 메모리 전체: %llu MB\n", memInfo.ullTotalVirtual / (1024 * 1024)); printf("가상 메모리 사용 가능: %llu MB\n", memInfo.ullAvailVirtual / (1024 * 1024)); } // 프로세스 메모리 상세 정보 void PrintProcessMemory() { PROCESS_MEMORY_COUNTERS_EX pmc; GetProcessMemoryInfo(GetCurrentProcess(), (PROCESS_MEMORY_COUNTERS*)&pmc, sizeof(pmc)); printf("작업 집합 (RAM에 있는 양): %zu MB\n", pmc.WorkingSetSize / (1024 * 1024)); printf("커밋 크기 (할당받은 총량): %zu MB\n", pmc.PrivateUsage / (1024 * 1024)); }
VMMap으로 본 실제 게임 메모리: ┌────────────────────────────────────────────────────────────┐ │ Type Size Committed Private │ ├────────────────────────────────────────────────────────────┤ │ Image 312 MB 312 MB 0 KB (.exe, .dll)│ │ Mapped File 128 MB 128 MB 0 KB (메모리맵) │ │ Shareable 64 MB 64 MB 0 KB │ │ Heap 1,024 MB 1,024 MB 1,024 MB ← 주목! │ │ Stack 16 MB 2 MB 2 MB │ │ Private Data 256 MB 256 MB 256 MB │ │ Free 200 MB - - ← 남은 공간│ ├────────────────────────────────────────────────────────────┤ │ Total 2,000 MB │ │ Largest Free Block: 45 MB ← 연속 공간 부족! │ └────────────────────────────────────────────────────────────┘

핵심 정리

  • 가상 주소 공간 - 프로세스가 사용할 수 있는 주소의 범위 (RAM과 별개!)
  • 페이지 테이블 - 가상 주소를 물리 주소로 변환하는 OS 테이블
  • 페이지 폴트 - 필요한 페이지가 RAM에 없을 때 발생하는 인터럽트
  • 32비트 한계 - 가상 주소 공간 2GB (RAM이 16GB여도 2GB만 사용 가능)
  • 외부 단편화 - 연속된 빈 공간이 없어서 큰 할당 실패
  • 해결책 - 64비트 전환, 메모리 풀, /LARGEADDRESSAWARE
  • 디버깅 - VMMap, Process Explorer, GlobalMemoryStatusEx()
