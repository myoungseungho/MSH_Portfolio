🔄 서버 업데이트하는데 왜 점검 안 해?

무중단 배포 (Zero-Downtime Deployment) - 코드 바꾸면서 서비스 안 끊는 법

Part 1. 잠깐, 코드 바꾸려면 서버 꺼야 하는 거 아니야?

서버 코드를 수정했어. 적용하려면?

당연히 서버 재시작해야지. 새 코드를 메모리에 올려야 하니까.

재시작하면 접속 중인 유저는?

튕겨 나가.

서버 1대일 때: [서버] ←── 유저 1000명 접속 중 1. 서버 끔 → 유저 1000명 전원 튕김 ❌ 2. 코드 교체 3. 서버 켬 → 유저 재접속 = "점검 중입니다" 공지 필요
근데 요즘 게임들 보면 점검 없이 패치하던데?

비밀은 "서버가 여러 대"라는 거야.

Part 2. 여러 대면 왜 가능해?

서버 10대 있으면 어떻게 되는 건데?

생각해보자:

서버 10대, 유저 1만 명 [로드밸런서] → 서버 A (1000명) → 서버 B (1000명) → 서버 C (1000명) → ... (7대 더) Q. A만 끄면? A. 나머지 9대가 트래픽 처리 → 서비스 유지!
🏪 비유: 24시간 편의점

직원 1명 → 화장실 가려면 "잠시 쉽니다" 걸어야 함
직원 3명 → 1명 화장실 가도 나머지 2명이 계산대 지킴

서버도 똑같아. 여러 대면 돌아가면서 재시작 가능!
그게 무중단 배포야?

정확해!

이걸 롤링 업데이트 (Rolling Update)라고 불러.

"굴러가듯이" 하나씩 순차적으로 업데이트한다는 뜻.

Part 3. 롤링 업데이트 동작 원리

구체적으로 어떻게 진행돼?

단계별로 보자:

유저 입장에선 어떻게 느껴져?

"어? 패치됐네?" 끝.

접속 끊김 없이 그냥 새 기능이 적용되어 있음.

Part 4. 근데 접속 중인 유저는 어떡해?

A 서버에 500명 있는데, 그 유저들은?

여기서 Stateless냐 Stateful이냐에 따라 달라져.

Stateless가 뭔데?

서버가 유저 상태를 안 가지고 있는 것.

🏪 비유: 편의점 vs 단골 카페

편의점 (Stateless):
어느 점원한테 가도 OK. "신분증만 보여주세요"
→ 상태가 서버에 없음. DB만 확인하면 됨.

단골 카페 (Stateful):
"저번에 아이스 아메리카노 드셨잖아요~"
→ 특정 점원이 내 취향 기억 중. 그 점원한테 가야 함.
Stateless Stateful
상태 저장 DB/Redis (서버 외부) 서버 메모리 (서버 내부)
서버 끄면? 바로 가능 (상태 없음) 유저 로그아웃 기다려야 함
무중단 난이도 쉬움 복잡
적합한 게임 턴제, 카드, 캐주얼 FPS, MMORPG (실시간)
Stateful이면 어떻게 해?

두 가지 방법:

방법 1: 드레인 (Drain) - 자연스럽게 빠지길 기다림 → A에 새 유저 안 받음 → 기존 유저가 로그아웃할 때까지 대기 → 다 나가면 재시작 방법 2: 세션 이관 (Session Migration) → A의 유저 상태를 B로 옮김 → 유저는 B로 자동 재접속 → A 비워지면 재시작

방법 2가 빠르지만 구현이 훨씬 복잡해.

Part 5. 롤링 말고 다른 방법 없어?

롤링 업데이트의 단점은?

업데이트 도중에 v1.0과 v2.0이 공존해.

문제 상황: 서버 A: v2.0 (새 아이템 추가됨) 서버 B: v1.0 (아직 구버전) 서버 C: v1.0 (아직 구버전) Q. A에서 새 아이템 얻은 유저가 B로 접속하면? A. "이 아이템 뭐야?" 에러 가능성!
그럼 어떻게 해?

Blue-Green 배포라는 방법이 있어.

롤백은 어떻게 해?

로드밸런서만 다시 Blue로 전환하면 끝!

Blue가 아직 v1.0으로 살아있으니까.

롤링 업데이트는 롤백하려면 다시 전부 돌려야 해서 느려.

Part 6. 일부 유저한테만 먼저 테스트하고 싶은데?

새 버전에 버그 있을까봐 무서워. 조금씩 배포할 수 없어?

카나리 배포 (Canary Deployment)가 딱 그거야.

🐤 이름의 유래

옛날 광부들이 카나리아 새를 들고 탄광에 들어감.
→ 유독 가스 있으면 카나리아가 먼저 죽음.
→ "새가 괜찮네? 안전하군!" 확인용.

새 버전 = 카나리아. 일부 유저로 먼저 테스트!

도식: 카나리 배포

Part 7. 뭘 써야 해?

롤링, Blue-Green, 카나리 중 뭘 골라?

상황에 따라 달라:

방식 장점 단점 적합한 상황
롤링 서버 비용 효율적 버전 혼재
롤백 느림		 비용 절감 중요
호환성 문제 적음
Blue-Green 즉시 전환
즉시 롤백		 서버 비용 2배 빠른 롤백 필수
중요 서비스
카나리 위험 최소화
점진적 테스트		 배포 시간 김
모니터링 필수		 신규 기능 불안
유저 많은 서비스
실제로는 어떻게 써?

보통 조합해서 사용해:

일반적인 조합: 1. 카나리로 시작 (5% 유저에게 테스트) 2. 문제 없으면 롤링으로 전체 배포 3. 긴급 상황 대비 Blue 환경 유지 or 1. Blue-Green으로 전환 2. 문제 생기면 즉시 롤백

📌 핵심 정리: 무중단 배포

  • 핵심 원리 = 서버 여러 대 → 돌아가면서 업데이트
  • 롤링 = 하나씩 순차 업데이트 (비용 효율, 버전 혼재)
  • Blue-Green = 두 환경 교체 (즉시 전환/롤백, 비용 2배)
  • 카나리 = 일부 유저로 테스트 후 확대 (안전, 느림)
  • Stateless = 무중단 쉬움 / Stateful = 세션 처리 복잡
