조건문 분해

Decompose Conditional - 복잡한 if문을 읽기 쉽게

Part 1. 조건문이 왜 문제야?

if문이 뭐가 문제야?

복잡한 조건문은 코드에서 가장 읽기 어려운 부분이야.

조건이 무엇을 검사하는지, 각 분기에서 무엇을 하는지 한눈에 안 보여.

// 이 조건이 뭘 검사하는 건지 알겠어? if (pPC->GetLevel() >= 50 && pPC->GetGold() >= 100000 && pPC->GetParty() != nullptr && pPC->GetParty()->GetMemberCount() >= 4 && !pPC->HasDebuff(DEBUFF_CURSED) && (GetTickCount() - pPC->GetLastDungeonTime()) > 3600000) { pDungeon->AddPlayer(pPC); pPC->SetLastDungeonTime(GetTickCount()); pPC->SubGold(100000); SendEnterDungeonResult(pPC, RESULT_SUCCESS); } else { SendEnterDungeonResult(pPC, RESULT_FAIL); }
6개 조건이 AND로 연결되어 있네...

그리고 각 분기 안에도 여러 작업이 섞여 있어. 읽기 싫어지지?

Part 2. 조건문을 어떻게 분해해?

Decompose Conditional이 뭐야?

복잡한 조건문을 의도가 드러나는 함수로 추출하는 거야.

분해의 3단계

조건부 → "무엇을 검사하는가"를 함수로
then절 → "조건이 참일 때 무엇을 하는가"를 함수로
else절 → "조건이 거짓일 때 무엇을 하는가"를 함수로
// ✅ After - 분해된 조건문 if (CanEnterDungeon(pPC)) { ProcessDungeonEntry(pPC, pDungeon); } else { SendEnterDungeonResult(pPC, RESULT_FAIL); } // 조건부를 함수로 추출 bool CanEnterDungeon(CGamePC* pPC) { return MeetsLevelRequirement(pPC) && HasEnoughGold(pPC) && HasValidParty(pPC) && IsNotCursed(pPC) && CooldownExpired(pPC); } // then절을 함수로 추출 void ProcessDungeonEntry(CGamePC* pPC, CDungeon* pDungeon) { pDungeon->AddPlayer(pPC); pPC->SetLastDungeonTime(GetTickCount()); pPC->SubGold(DUNGEON_ENTRY_FEE); SendEnterDungeonResult(pPC, RESULT_SUCCESS); }

Part 3. 조건부도 더 쪼갤 수 있어

CanEnterDungeon 안의 조건도 분리해?

응! 각 조건을 의미 있는 함수로 분해할 수 있어.

// 각 조건을 의미 있는 함수로 분해 bool MeetsLevelRequirement(CGamePC* pPC) { return pPC->GetLevel() >= DUNGEON_MIN_LEVEL; } bool HasEnoughGold(CGamePC* pPC) { return pPC->GetGold() >= DUNGEON_ENTRY_FEE; } bool HasValidParty(CGamePC* pPC) { CParty* pParty = pPC->GetParty(); return pParty != nullptr && pParty->GetMemberCount() >= DUNGEON_MIN_PARTY_SIZE; } bool IsNotCursed(CGamePC* pPC) { return !pPC->HasDebuff(DEBUFF_CURSED); } bool CooldownExpired(CGamePC* pPC) { DWORD elapsed = GetTickCount() - pPC->GetLastDungeonTime(); return elapsed > DUNGEON_COOLDOWN_MS; }
장점

• 각 조건의 의도가 명확해짐
• 조건 재사용 가능
• 테스트하기 쉬움
• 디버깅 시 어떤 조건이 실패했는지 파악 쉬움

Part 4. Guard Clause로 중첩 제거

if 안에 if 안에 if가 있는데...

Guard Clause(보호절)로 평탄화할 수 있어!

조건을 만족하지 않으면 즉시 반환하는 패턴이야.

// ❌ 중첩 조건 - 화살표 코드 void EnterDungeon(CGamePC* pPC) { if (pPC != nullptr) { if (pPC->GetLevel() >= 50) { if (pPC->GetGold() >= 100000) { if (pPC->GetParty() != nullptr) { // 실제 로직이 여기에 묻혀있음 DoEnter(pPC); } } } } }
// ✅ Guard Clause - 평탄하고 읽기 쉬움 void EnterDungeon(CGamePC* pPC) { // 보호절: 조건 불충족 시 즉시 반환 if (pPC == nullptr) return; if (pPC->GetLevel() < DUNGEON_MIN_LEVEL) return; if (pPC->GetGold() < DUNGEON_ENTRY_FEE) return; if (pPC->GetParty() == nullptr) return; // 모든 조건 통과 → 실제 로직 DoEnter(pPC); }
Guard Clause의 장점

• 들여쓰기가 평탄해짐
• "예외 상황 처리 → 정상 흐름" 순서로 읽힘
• 각 조건에서 에러 메시지 추가하기 쉬움

Part 5. 우리 프로젝트에서 적용

실제로 어디에 적용해?

메시지 처리 함수에 많아:

// ❌ Before void OnRecv_CM_USE_SKILL(CGamePC* pPC, CMsg* pMsg) { int skillId = pMsg->GetInt(); if (pPC->IsAlive() && !pPC->HasDebuff(DEBUFF_SILENCE) && pPC->GetMP() >= GetSkillMPCost(skillId) && !pPC->IsSkillCooldown(skillId) && pPC->HasSkill(skillId)) { CSkill* pSkill = pPC->GetSkill(skillId); pPC->SubMP(pSkill->GetMPCost()); pSkill->Execute(pPC); pPC->SetSkillCooldown(skillId); } }
// ✅ After void OnRecv_CM_USE_SKILL(CGamePC* pPC, CMsg* pMsg) { int skillId = pMsg->GetInt(); if (!CanUseSkill(pPC, skillId)) return; ExecuteSkill(pPC, skillId); } bool CanUseSkill(CGamePC* pPC, int skillId) { if (!pPC->IsAlive()) return false; if (pPC->HasDebuff(DEBUFF_SILENCE)) return false; if (!pPC->HasSkill(skillId)) return false; if (pPC->IsSkillCooldown(skillId)) return false; CSkill* pSkill = pPC->GetSkill(skillId); if (pPC->GetMP() < pSkill->GetMPCost()) return false; return true; }

핵심 정리: 조건문 분해

  • 복잡한 조건부 → 의도를 드러내는 함수로 추출
  • then절/else절도 별도 함수로 분리
  • Guard Clause로 중첩 제거
  • 각 조건을 개별 함수로 분해 → 재사용 + 테스트 용이
  • 디버깅 시 어떤 조건이 실패했는지 바로 파악
