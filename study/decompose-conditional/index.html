조건문 분해

리팩토링 #9 기본 기법 Decompose Conditional

조건문이 왜 문제야?

복잡한 조건문은 코드에서 가장 읽기 어려운 부분 중 하나입니다. 조건이 무엇을 검사하는지, 각 분기에서 무엇을 하는지 한눈에 파악하기 어렵습니다.

❌ 복잡한 조건문 
// 이 조건이 뭘 검사하는 건지 알겠어?
if (pPC->GetLevel() >= 50 &&
    pPC->GetGold() >= 100000 &&
    pPC->GetParty() != nullptr &&
    pPC->GetParty()->GetMemberCount() >= 4 &&
    !pPC->HasDebuff(DEBUFF_CURSED) &&
    (GetTickCount() - pPC->GetLastDungeonTime()) > 3600000)
{
    // 입장 가능
    pDungeon->AddPlayer(pPC);
    pPC->SetLastDungeonTime(GetTickCount());
    pPC->SubGold(100000);
    SendEnterDungeonResult(pPC, RESULT_SUCCESS);
}
else
{
    // 입장 실패
    SendEnterDungeonResult(pPC, RESULT_FAIL);
}

조건문 안에 6개의 조건이 AND로 연결되어 있고, 각 분기 안에도 여러 작업이 섞여 있습니다.

조건문 분해가 뭐야?

Decompose Conditional은 복잡한 조건문을 의도가 드러나는 함수로 추출하는 기법입니다. 조건부, then절, else절 각각을 별도 함수로 만듭니다.

🎯 분해의 3단계

  • 조건부 → "무엇을 검사하는가"를 함수로
  • then절 → "조건이 참일 때 무엇을 하는가"를 함수로
  • else절 → "조건이 거짓일 때 무엇을 하는가"를 함수로

실제로 어떻게 분해해?

❌ Before 복잡한 조건문 
if (pPC->GetLevel() >= 50 &&
    pPC->GetGold() >= 100000 &&
    pPC->GetParty() != nullptr &&
    pPC->GetParty()->GetMemberCount() >= 4 &&
    !pPC->HasDebuff(DEBUFF_CURSED) &&
    (GetTickCount() - pPC->GetLastDungeonTime()) > 3600000)
{
    pDungeon->AddPlayer(pPC);
    pPC->SetLastDungeonTime(GetTickCount());
    pPC->SubGold(100000);
    SendEnterDungeonResult(pPC, RESULT_SUCCESS);
}
else
{
    SendEnterDungeonResult(pPC, RESULT_FAIL);
}
✅ After 분해된 조건문 
if (CanEnterDungeon(pPC))
{
    ProcessDungeonEntry(pPC, pDungeon);
}
else
{
    SendEnterDungeonResult(pPC, RESULT_FAIL);
}

// 조건부를 함수로 추출
bool CanEnterDungeon(CGamePC* pPC)
{
    return MeetsLevelRequirement(pPC) &&
           HasEnoughGold(pPC) &&
           HasValidParty(pPC) &&
           IsNotCursed(pPC) &&
           CooldownExpired(pPC);
}

// then절을 함수로 추출
void ProcessDungeonEntry(CGamePC* pPC, CDungeon* pDungeon)
{
    pDungeon->AddPlayer(pPC);
    pPC->SetLastDungeonTime(GetTickCount());
    pPC->SubGold(DUNGEON_ENTRY_FEE);
    SendEnterDungeonResult(pPC, RESULT_SUCCESS);
}

조건부도 더 분해할 수 있어?

네, 복잡한 조건은 의미 단위로 더 쪼갤 수 있습니다:

조건부 세분화 
// 각 조건을 의미 있는 함수로 분해
bool MeetsLevelRequirement(CGamePC* pPC)
{
    return pPC->GetLevel() >= DUNGEON_MIN_LEVEL;
}

bool HasEnoughGold(CGamePC* pPC)
{
    return pPC->GetGold() >= DUNGEON_ENTRY_FEE;
}

bool HasValidParty(CGamePC* pPC)
{
    CParty* pParty = pPC->GetParty();
    return pParty != nullptr &&
           pParty->GetMemberCount() >= DUNGEON_MIN_PARTY_SIZE;
}

bool IsNotCursed(CGamePC* pPC)
{
    return !pPC->HasDebuff(DEBUFF_CURSED);
}

bool CooldownExpired(CGamePC* pPC)
{
    DWORD elapsed = GetTickCount() - pPC->GetLastDungeonTime();
    return elapsed > DUNGEON_COOLDOWN_MS;
}

✅ 장점

  • 각 조건의 의도가 명확해짐
  • 조건 재사용 가능
  • 테스트하기 쉬움
  • 디버깅 시 어떤 조건이 실패했는지 파악 용이

Guard Clause로 더 단순화할 수 있어?

Guard Clause(보호절)는 조건을 만족하지 않으면 즉시 반환하는 패턴입니다. 중첩 if문을 평탄화합니다:

❌ 중첩 조건 
void EnterDungeon(CGamePC* pPC)
{
    if (pPC != nullptr)
    {
        if (pPC->GetLevel() >= 50)
        {
            if (pPC->GetGold() >= 100000)
            {
                if (pPC->GetParty() != nullptr)
                {
                    // 실제 로직
                    DoEnter(pPC);
                }
            }
        }
    }
}
✅ Guard Clause 
void EnterDungeon(CGamePC* pPC)
{
    // 보호절: 조건 불충족 시 즉시 반환
    if (pPC == nullptr)
        return;

    if (pPC->GetLevel() < DUNGEON_MIN_LEVEL)
        return;

    if (pPC->GetGold() < DUNGEON_ENTRY_FEE)
        return;

    if (pPC->GetParty() == nullptr)
        return;

    // 모든 조건 통과 → 실제 로직
    DoEnter(pPC);
}

💡 Guard Clause의 장점

  • 들여쓰기가 평탄해짐
  • "예외 상황 처리 → 정상 흐름" 순서로 읽힘
  • 각 조건에서 에러 메시지 추가하기 쉬움

우리 프로젝트에서 적용할 곳은?

메시지 처리 함수에서 자주 발견됩니다:

❌ 실제 코드 패턴 
void OnRecv_CM_USE_SKILL(CGamePC* pPC, CMsg* pMsg)
{
    int skillId = pMsg->GetInt();

    // 조건들이 한 덩어리로...
    if (pPC->IsAlive() &&
        !pPC->HasDebuff(DEBUFF_SILENCE) &&
        pPC->GetMP() >= GetSkillMPCost(skillId) &&
        !pPC->IsSkillCooldown(skillId) &&
        pPC->HasSkill(skillId))
    {
        // 스킬 사용 처리
        CSkill* pSkill = pPC->GetSkill(skillId);
        pPC->SubMP(pSkill->GetMPCost());
        pSkill->Execute(pPC);
        pPC->SetSkillCooldown(skillId);
    }
}
✅ 리팩토링 후 
void OnRecv_CM_USE_SKILL(CGamePC* pPC, CMsg* pMsg)
{
    int skillId = pMsg->GetInt();

    if (!CanUseSkill(pPC, skillId))
        return;

    ExecuteSkill(pPC, skillId);
}

bool CanUseSkill(CGamePC* pPC, int skillId)
{
    if (!pPC->IsAlive())
        return false;

    if (pPC->HasDebuff(DEBUFF_SILENCE))
        return false;

    if (!pPC->HasSkill(skillId))
        return false;

    CSkill* pSkill = pPC->GetSkill(skillId);
    if (pPC->GetMP() < pSkill->GetMPCost())
        return false;

    if (pPC->IsSkillCooldown(skillId))
        return false;

    return true;
}

void ExecuteSkill(CGamePC* pPC, int skillId)
{
    CSkill* pSkill = pPC->GetSkill(skillId);
    pPC->SubMP(pSkill->GetMPCost());
    pSkill->Execute(pPC);
    pPC->SetSkillCooldown(skillId);
}

핵심 요약

📌 조건문 분해 핵심

  • 복잡한 조건부 → 의도를 드러내는 함수로 추출
  • then절/else절도 별도 함수로 분리 가능
  • Guard Clause로 중첩 제거
  • 각 조건을 개별 함수로 분해하면 재사용 + 테스트 용이
  • 디버깅 시 어떤 조건이 실패했는지 파악 쉬움
