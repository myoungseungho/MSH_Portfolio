원격 서버에서 디버깅하기

Remote Debugging — 서버 PC에서 VS 없이 디버깅

Part 1. 언제 필요해?

로컬에서 재현 안 되는 버그가 있어

서버 환경에서만 발생하는 버그는 원격 디버깅으로 해결.

VS가 설치되지 않은 서버에서도 디버깅 가능.

Part 2. 원격 도구 설치

서버에 뭘 설치해야 해?

Remote Tools for Visual Studio를 설치.

VS 버전과 맞는 버전을 다운로드.

// 다운로드 위치 https://visualstudio.microsoft.com/downloads/ → "Remote Tools for Visual Studio 2022" 검색 // 서버에서 실행 msvsmon.exe // 실행 옵션 msvsmon.exe /noauth /anyuser /nosecuritywarn // /noauth: 인증 없이 (개발 환경에서만!) // /anyuser: 모든 사용자 접속 허용 // 기본 포트: 4026

Part 3. VS에서 연결

로컬 VS에서 어떻게 연결해?

Debug → Attach to Process

Connection target에 서버IP:포트 입력

// Attach to Process 설정 Connection type: Remote (no authentication) Connection target: 192.168.1.100:4026 // 프로세스 목록이 뜨면 디버깅할 exe 선택 // Attach 클릭 // 필요한 것: // 1. 서버의 exe와 동일한 버전의 로컬 PDB // 2. 소스 코드 (로컬에 있어야 함)

Part 4. 심볼/소스 설정

Call Stack에 함수 이름이 안 나와

로컬에 PDB 파일이 있어야 한다.

서버의 exe와 같은 빌드의 PDB여야 함.

// 심볼 경로 설정 Debug → Options → Debugging → Symbols → PDB 경로 추가 // 소스 경로 설정 (없으면 자동으로 물어봄) // 버전이 안 맞으면? "The source file is different from when the module was built" → 같은 커밋의 소스로 맞추기

Part 5. 보안 주의

프로덕션 서버에서도 써도 돼?

/noauth는 개발 환경에서만!

프로덕션은 인증 모드 사용 + 방화벽 제한.

핵심 정리

  • 서버에 Remote Tools 설치
  • msvsmon.exe 실행
  • VS에서 Attach to Process → 원격 연결
  • PDB 버전 일치 필수
