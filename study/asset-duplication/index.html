중복 에셋의 함정

같은 텍스처가 여러 번들에 포함되어 빌드 크기와 메모리를 낭비하는 현상

Part 1. 개념: 에셋 중복이란 무엇인가

에셋 중복(Asset Duplication)이 뭐야?

동일한 에셋이 여러 번들에 각각 복사되어 포함되는 현상이야. 번들 A와 번들 B가 같은 텍스처를 참조할 때, 이 텍스처가 공유되지 않고 각 번들에 중복 저장되면 빌드 크기가 2배가 되는 거지.

왜 이런 일이 발생해?

번들 시스템의 암묵적 의존성(Implicit Dependency) 처리 방식 때문이야:

[에셋 중복 발생 시나리오]

Bundle_A.bundle                    Bundle_B.bundle
┌────────────────────┐            ┌────────────────────┐
│  CharacterA.prefab │            │  CharacterB.prefab │
│        │           │            │        │           │
│        ▼           │            │        ▼           │
│  ┌──────────────┐  │            │  ┌──────────────┐  │
│  │SharedMat.mat │  │            │  │SharedMat.mat │  │ ← 같은 머티리얼!
│  │      │       │  │            │  │      │       │  │
│  │      ▼       │  │            │  │      ▼       │  │
│  │ HeroTex.png  │  │            │  │ HeroTex.png  │  │ ← 같은 텍스처!
│  │   (4MB)      │  │            │  │   (4MB)      │  │
│  └──────────────┘  │            │  └──────────────┘  │
└────────────────────┘            └────────────────────┘

결과: HeroTex.png가 8MB 차지 (원래 4MB면 충분)

[원인 분석]
SharedMat.mat이 어떤 번들에도 명시적으로 할당되지 않음
→ 각 번들이 빌드될 때 의존성을 "내부에 포함"시킴
→ 결과적으로 같은 에셋이 여러 번들에 복사됨

핵심 원인은 명시적 할당(Explicit Assignment) 누락이야. 공유 에셋을 특정 번들에 명시적으로 할당하지 않으면, 각 번들이 독립적으로 해당 에셋을 포함시켜.

명시적 의존성과 암묵적 의존성의 차이가 뭐야?
[명시적 vs 암묵적 의존성]

◆ 명시적 의존성 (Explicit Dependency)
  - 에셋이 Addressables Group이나 AssetBundle에 직접 할당됨
  - 빌드 시스템이 "이 에셋은 이 번들에서 로드한다"고 인식
  - 다른 번들은 참조만 하고, 실제 에셋은 공유

◆ 암묵적 의존성 (Implicit Dependency)
  - 에셋이 어떤 번들에도 직접 할당되지 않음
  - 그러나 번들 내 에셋이 이 에셋을 참조함
  - 빌드 시스템: "참조하니까 번들에 포함시켜야지"
  - 여러 번들이 참조하면 → 여러 번 복사됨

[예시: Character.prefab → SharedMaterial.mat → BaseTexture.png]

Case 1: SharedMaterial이 번들에 미할당

│   Bundle_Char   │     │   Bundle_Env    │
│ ┌─────────────┐ │     │ ┌─────────────┐ │

Part 2. 왜 필요해: 중복의 실제 비용

에셋 중복이 실제로 얼마나 문제가 돼?

실제 프로젝트에서 빌드 크기의 20~40%가 중복인 경우가 흔해. 특히 텍스처처럼 큰 에셋이 중복되면 영향이 막대해:

[실제 중복 비용 분석 - 중규모 모바일 게임 사례]

원본 에셋 현황:
├── 텍스처: 800MB (평균 2MB × 400개)
├── 머티리얼: 50MB
├── 프리팹: 100MB
├── 사운드: 200MB
└── 기타: 50MB
    총합: 1.2GB

번들 구성 (잘못된 설계):
├── Bundle_Character (150MB)
│   └── 50MB가 공유 텍스처 (다른 번들과 중복)
├── Bundle_Environment (200MB)
│   └── 80MB가 공유 텍스처 (다른 번들과 중복)
├── Bundle_UI (100MB)
│   └── 30MB가 공유 아틀라스 (다른 번들과 중복)
├── Bundle_Effects (120MB)
│   └── 40MB가 공유 텍스처 (다른 번들과 중복)
└── ... (20개 번들)

중복 분석 결과:

영향:
├── 다운로드 크기: 1.2GB → 1.55GB (+29%)
├── 설치 용량: 1.5GB → 1.95GB (+30%)
├── 패치 크기 증가: 중복 에셋 변경 시 여러 번들 갱신 필요
└── CDN 비용: 월 $500 → $650 (+$150)

Part 3. 실전 적용: 중복 탐지 도구

Unity에서 중복을 어떻게 찾아?

Addressables Analyze 창의 "Check Duplicate Bundle Dependencies" 규칙을 사용해:

// Unity Editor에서 중복 분석 실행 // Window > Asset Management > Addressables > Analyze using UnityEditor; using UnityEditor.AddressableAssets; using UnityEditor.AddressableAssets.Build.AnalyzeRules; using System.Collections.Generic; public static class DuplicateAnalyzer { [MenuItem("Tools/Addressables/Analyze Duplicates")] public static void AnalyzeDuplicates() { var settings = AddressableAssetSettingsDefaultObject.Settings; if (settings == null) { Debug.LogError("Addressables Settings not found"); return; } // Check Duplicate Bundle Dependencies 규칙 실행 var rule = new CheckBundleDupeDependencies(); var results = rule.RefreshAnalysis(settings); // 결과 분석 var duplicates = new Dictionary<string, List<string>>(); foreach (var result in results) { if (result.severity == MessageType.Warning || result.severity == MessageType.Error) { // result.resultName: 중복 에셋 경로 // result.data: 포함된 번들 목록 Debug.LogWarning( $"중복 발견: {result.resultName}\n" + $" 포함된 번들: {string.Join(", ", result.data)}" ); } } Debug.Log($"분석 완료: {results.Count}개 항목 검사됨"); } }

중복을 자동으로 수정할 수 있어?

Addressables는 "Fix Selected" 버튼으로 중복 에셋을 새 Shared 그룹으로 이동시켜줘. 하지만 커스텀 로직으로 더 세밀하게 제어할 수도 있어:

using UnityEditor; using UnityEditor.AddressableAssets; using UnityEditor.AddressableAssets.Settings; using UnityEditor.AddressableAssets.Settings.GroupSchemas; using System.Collections.Generic; using System.Linq; public class AutoDuplicateFixer { [MenuItem("Tools/Addressables/Auto Fix Duplicates")] public static void AutoFixDuplicates() { var settings = AddressableAssetSettingsDefaultObject.Settings; // 1. 중복 분석 실행 var duplicates = FindDuplicateAssets(settings); if (duplicates.Count == 0) { Debug.Log("중복 에셋이 없습니다."); return; } // 2. 카테고리별로 Shared 그룹 생성 또는 가져오기 var sharedGroups = new Dictionary<string, AddressableAssetGroup> { ["Texture"] = GetOrCreateSharedGroup(settings, "Shared_Textures"), ["Material"] = GetOrCreateSharedGroup(settings, "Shared_Materials"), ["Font"] = GetOrCreateSharedGroup(settings, "Shared_Fonts"), ["Default"] = GetOrCreateSharedGroup(settings, "Shared_Common") }; // 3. 중복 에셋을 적절한 Shared 그룹으로 이동 int movedCount = 0; foreach (var duplicate in duplicates) { string assetPath = duplicate.Key; var category = GetAssetCategory(assetPath); var targetGroup = sharedGroups.ContainsKey(category) ? sharedGroups[category] : sharedGroups["Default"]; // 현재 엔트리 찾기 var guid = AssetDatabase.AssetPathToGUID(assetPath); var entry = settings.FindAssetEntry(guid); if (entry != null) { // 기존 그룹에서 제거하고 Shared 그룹으로 이동 settings.MoveEntry(entry, targetGroup, false, false); movedCount++; } else { // 엔트리가 없으면 (암묵적 의존성) 새로 생성 entry = settings.CreateOrMoveEntry(guid, targetGroup, false, false); entry.address = System.IO.Path.GetFileNameWithoutExtension(assetPath); movedCount++; } } settings.SetDirty(AddressableAssetSettings.ModificationEvent.EntryMoved, null, true); AssetDatabase.SaveAssets(); Debug.Log($"완료: {movedCount}개 에셋을 Shared 그룹으로 이동"); } private static Dictionary<string, List<string>> FindDuplicateAssets( AddressableAssetSettings settings) { var assetToBundles = new Dictionary<string, List<string>>(); // 각 그룹의 의존성 수집 foreach (var group in settings.groups) { if (group == null) continue; foreach (var entry in group.entries) { var dependencies = AssetDatabase.GetDependencies(entry.AssetPath, true); foreach (var dep in dependencies) { // 스크립트 제외 if (dep.EndsWith(".cs")) continue; if (!assetToBundles.ContainsKey(dep)) assetToBundles[dep] = new List<string>(); if (!assetToBundles[dep].Contains(group.Name)) assetToBundles[dep].Add(group.Name); } } } // 2개 이상 그룹에 포함된 에셋만 반환 return assetToBundles .Where(kvp => kvp.Value.Count > 1) .ToDictionary(kvp => kvp.Key, kvp => kvp.Value); } private static AddressableAssetGroup GetOrCreateSharedGroup( AddressableAssetSettings settings, string groupName) { var group = settings.FindGroup(groupName); if (group == null) { group = settings.CreateGroup(groupName, false, false, false, null, typeof(BundledAssetGroupSchema), typeof(ContentUpdateGroupSchema)); // Shared 그룹 설정: Pack Together로 하나의 번들에 var schema = group.GetSchema<BundledAssetGroupSchema>(); schema.BundleMode = BundledAssetGroupSchema.BundlePackingMode.PackTogether; } return group; } private static string GetAssetCategory(string assetPath) { var extension = System.IO.Path.GetExtension(assetPath).ToLower(); return extension switch { ".png" or ".jpg" or ".tga" or ".psd" => "Texture", ".mat" => "Material", ".ttf" or ".otf" => "Font", _ => "Default" }; } }
Unreal에서는 어떻게 해?

Unreal에서는 Asset Audit과 Size Map을 사용해:

// C++ - 청크 중복 분석 Commandlet // 프로젝트명Commandlets.cpp #include "AssetRegistry/AssetRegistryModule.h" #include "Engine/AssetManager.h" void UChunkDuplicateAnalyzer::AnalyzeChunkDuplicates() { IAssetRegistry& AssetRegistry = FModuleManager::LoadModuleChecked<FAssetRegistryModule>( "AssetRegistry").Get(); // 청크별 에셋 수집 TMap<FName, TArray<int32>> AssetToChunks; TArray<FAssetData> AllAssets; AssetRegistry.GetAllAssets(AllAssets); for (const FAssetData& Asset : AllAssets) { TArray<int32> ChunkIDs; // Primary Asset이면 할당된 청크 가져오기 FPrimaryAssetId PrimaryId = UAssetManager::Get() .GetPrimaryAssetIdForPath(Asset.ObjectPath); if (PrimaryId.IsValid()) { UAssetManager::Get().GetPrimaryAssetIdChunkIds(PrimaryId, ChunkIDs); } else { // Secondary Asset - 참조하는 모든 Primary의 청크 수집 ChunkIDs = GetChunksContainingAsset(Asset.ObjectPath); } if (ChunkIDs.Num() > 1) { AssetToChunks.Add(Asset.AssetName, ChunkIDs); UE_LOG(LogTemp, Warning, TEXT("중복 발견: %s - 청크 [%s]에 포함"), *Asset.AssetName.ToString(), *FString::JoinBy(ChunkIDs, TEXT(", "), [](int32 Id) { return FString::FromInt(Id); })); } } // 중복 크기 계산 int64 TotalWaste = 0; for (const auto& Pair : AssetToChunks) { int64 AssetSize = GetAssetDiskSize(Pair.Key); int32 DuplicateCount = Pair.Value.Num() - 1; // 원본 제외 TotalWaste += AssetSize * DuplicateCount; } UE_LOG(LogTemp, Warning, TEXT("총 중복 낭비: %.2f MB"), TotalWaste / (1024.0 * 1024.0)); }
[Unreal Asset Audit 활용법]

1. 에디터에서 Asset Audit 열기

Part 4. 심화 개념: 중복 방지 아키텍처

처음부터 중복이 발생하지 않게 설계하려면?

계층적 번들 구조(Hierarchical Bundle Structure)를 설계해:

[중복 방지 번들 아키텍처]

Layer 0: Core (항상 로드됨, 변경 거의 없음)

[핵심 규칙]
1. 하위 레이어 → 상위 레이어만 참조 가능
2. 같은 레이어 간 참조는 공유 레이어를 통해서만
3. 새 에셋 추가 시, 2개 이상 번들에서 필요하면 상위로 승격
이 구조를 자동으로 유지하려면?

빌드 전 검증 스크립트로 계층 규칙 위반을 잡아:

using UnityEditor; using UnityEditor.AddressableAssets; using UnityEditor.AddressableAssets.Settings; using UnityEditor.Build; using UnityEditor.Build.Reporting; using System.Collections.Generic; using System.Linq; public class BundleHierarchyValidator : IPreprocessBuildWithReport { public int callbackOrder => 0; // 레이어 정의 (낮을수록 기반 레이어) private static readonly Dictionary<string, int> LayerDefinitions = new() { ["Bundle_Core"] = 0, ["Shared_"] = 1, // prefix 매칭 ["Bundle_Characters"] = 2, ["Bundle_Environment"] = 2, ["Bundle_Items"] = 2, ["Bundle_Stage_"] = 3, ["Bundle_Event_"] = 3, }; public void OnPreprocessBuild(BuildReport report) { var violations = ValidateBundleHierarchy(); if (violations.Count > 0) { var message = "번들 계층 위반 발견:\n" + string.Join("\n", violations); throw new BuildFailedException(message); } } public static List<string> ValidateBundleHierarchy() { var violations = new List<string>(); var settings = AddressableAssetSettingsDefaultObject.Settings; foreach (var group in settings.groups) { if (group == null) continue; int groupLayer = GetGroupLayer(group.Name); foreach (var entry in group.entries) { var dependencies = AssetDatabase.GetDependencies( entry.AssetPath, true); foreach (var depPath in dependencies) { if (depPath == entry.AssetPath) continue; if (depPath.EndsWith(".cs")) continue; // 의존 에셋이 어떤 그룹에 있는지 확인 var depGuid = AssetDatabase.AssetPathToGUID(depPath); var depEntry = settings.FindAssetEntry(depGuid); if (depEntry != null) { int depLayer = GetGroupLayer(depEntry.parentGroup.Name); // 상위 레이어(낮은 숫자)를 참조해야 함 if (depLayer > groupLayer) { violations.Add( $"[위반] {group.Name}(L{groupLayer}) → " + $"{depEntry.parentGroup.Name}(L{depLayer})\n" + $" 에셋: {entry.AssetPath}\n" + $" 참조: {depPath}"); } } } } } return violations; } private static int GetGroupLayer(string groupName) { foreach (var kvp in LayerDefinitions.OrderByDescending(x => x.Key.Length)) { if (groupName.StartsWith(kvp.Key) || groupName == kvp.Key) return kvp.Value; } return int.MaxValue; // 정의되지 않은 그룹은 최하위 } }
런타임에서 중복 로드를 막으려면?

번들 빌드 시 중복을 제거해도, 런타임 로드 순서에 따라 문제가 생길 수 있어. 의존 번들을 먼저 로드하는 것이 핵심이야:

using System.Collections.Generic; using System.Threading.Tasks; using UnityEngine; using UnityEngine.AddressableAssets; using UnityEngine.ResourceManagement.AsyncOperations; public class HierarchicalBundleLoader { // 번들 의존성 정의 (상위 레이어가 먼저) private static readonly Dictionary<string, string[]> BundleDependencies = new() { ["Bundle_Core"] = new string[0], ["Shared_UI"] = new[] { "Bundle_Core" }, ["Shared_VFX"] = new[] { "Bundle_Core" }, ["Bundle_Characters"] = new[] { "Bundle_Core", "Shared_VFX" }, ["Bundle_Stage_01"] = new[] { "Bundle_Core", "Shared_UI", "Bundle_Characters" }, }; private HashSet<string> _loadedBundles = new(); public async Task<AsyncOperationHandle<T>> LoadAssetWithDependencies<T>( string bundleLabel, string assetAddress) where T : Object { // 1. 의존 번들 먼저 로드 await EnsureBundleHierarchyLoaded(bundleLabel); // 2. 실제 에셋 로드 var handle = Addressables.LoadAssetAsync<T>(assetAddress); await handle.Task; return handle; } private async Task EnsureBundleHierarchyLoaded(string bundleLabel) { if (_loadedBundles.Contains(bundleLabel)) return; // 의존성 재귀적으로 로드 if (BundleDependencies.TryGetValue(bundleLabel, out var deps)) { foreach (var dep in deps) { await EnsureBundleHierarchyLoaded(dep); } } // 이 번들의 에셋 중 하나를 로드하여 번들 활성화 // (또는 DownloadDependenciesAsync 사용) var downloadHandle = Addressables.DownloadDependenciesAsync(bundleLabel); await downloadHandle.Task; if (downloadHandle.Status == AsyncOperationStatus.Succeeded) { _loadedBundles.Add(bundleLabel); Debug.Log($"번들 로드 완료: {bundleLabel}"); } Addressables.Release(downloadHandle); } public void UnloadBundle(string bundleLabel) { // 이 번들에 의존하는 다른 번들이 있으면 언로드 불가 foreach (var kvp in BundleDependencies) { if (kvp.Value.Contains(bundleLabel) && _loadedBundles.Contains(kvp.Key)) { Debug.LogWarning( $"{bundleLabel} 언로드 불가: {kvp.Key}가 의존 중"); return; } } // 안전하게 언로드 _loadedBundles.Remove(bundleLabel); Resources.UnloadUnusedAssets(); } }

Part 5. 고급 패턴: 중복 비용 분석

중복을 완전히 없애는 게 항상 좋아?

무조건 중복 제거가 정답은 아니야. 공유 번들을 너무 잘게 쪼개면 오히려 성능이 나빠질 수 있어:

[중복 제거 vs 로드 오버헤드 트레이드오프]

시나리오: 4MB 텍스처가 3개 번들에서 사용됨

◆ Option A: 중복 허용
  Bundle_A: 50MB (4MB 텍스처 포함)
  Bundle_B: 50MB (4MB 텍스처 포함)
  Bundle_C: 50MB (4MB 텍스처 포함)

  총 크기: 150MB + 8MB 중복 = 158MB
  로드 시 네트워크 요청: 1개 (해당 번들만)

◆ Option B: 완전 분리
  Bundle_A: 46MB
  Bundle_B: 46MB
  Bundle_C: 46MB
  Bundle_Shared_Tex: 4MB

  총 크기: 138MB + 4MB = 142MB (16MB 절약)
  로드 시 네트워크 요청: 2개 (번들 + Shared)

[분석]
┌─────────────────────────────────────────────────────────┐
│ 고려 요소                  │ Option A  │ Option B      │
├─────────────────────────────────────────────────────────┤
│ 빌드 크기                  │ 158MB     │ 142MB ✓      │
│ 네트워크 요청 수           │ 1개 ✓    │ 2개          │
│ 초기 로딩 복잡도           │ 낮음 ✓   │ 높음         │
│ 부분 다운로드 효율         │ 낮음     │ 높음 ✓       │
│ 패치 크기 (텍스처 변경 시) │ 12MB     │ 4MB ✓        │
└─────────────────────────────────────────────────────────┘

결론: 상황에 따라 다름!
- 크기가 작은 에셋(< 100KB): 중복 허용이 나을 수 있음
- 크기가 큰 에셋(> 1MB): 분리 권장
- 자주 변경되는 에셋: 분리 필수
- 거의 변경 안 되는 에셋: 중복 허용 고려
중복 허용 임계값을 어떻게 정해?

비용-편익 분석(Cost-Benefit Analysis)으로 결정해:

public class DuplicationCostAnalyzer { // 설정 가능한 임계값 public float NetworkRequestCostMB = 0.5f; // 추가 요청의 등가 비용 (MB) public float PatchMultiplier = 3.0f; // 패치 비용 가중치 public int ExpectedPatchesPerYear = 12; // 연간 예상 패치 횟수 public DuplicationDecision AnalyzeAsset( string assetPath, float assetSizeMB, int duplicateCount, bool isFrequentlyUpdated) { // 중복 허용 시 비용 float duplicationCost = assetSizeMB * (duplicateCount - 1); // 패치 시 추가 비용 (중복된 만큼 패치도 커짐) if (isFrequentlyUpdated) { duplicationCost += assetSizeMB * (duplicateCount - 1) * PatchMultiplier * ExpectedPatchesPerYear; } // 분리 시 비용 (추가 번들 로드 오버헤드) float separationCost = NetworkRequestCostMB * duplicateCount; // 분리로 인한 메모리 관리 복잡도 if (assetSizeMB < 0.1f) // 100KB 미만 { separationCost += 0.2f; // 작은 파일 분리는 오버헤드가 큼 } Debug.Log($"[{assetPath}] 중복 비용: {duplicationCost:F2}MB, " + $"분리 비용: {separationCost:F2}MB"); if (duplicationCost > separationCost * 2.0f) { return new DuplicationDecision { ShouldSeparate = true, Reason = $"중복 비용({duplicationCost:F1}MB)이 " + $"분리 비용({separationCost:F1}MB)의 2배 초과", Priority = Priority.High }; } else if (duplicationCost > separationCost) { return new DuplicationDecision { ShouldSeparate = true, Reason = "중복 비용이 분리 비용보다 큼", Priority = Priority.Medium }; } else { return new DuplicationDecision { ShouldSeparate = false, Reason = "중복 허용이 효율적", Priority = Priority.Low }; } } } public struct DuplicationDecision { public bool ShouldSeparate; public string Reason; public Priority Priority; } public enum Priority { Low, Medium, High }

Part 6. 실무 사례: CI/CD 통합

CI/CD에서 중복을 자동으로 체크하려면?

빌드 파이프라인에 중복 검사 게이트를 추가해:

# .github/workflows/unity-build.yml name: Unity Build with Duplicate Check on: push: branches: [main, develop] pull_request: branches: [main] jobs: analyze-duplicates: runs-on: ubuntu-latest steps: - uses: actions/checkout@v3 - name: Setup Unity uses: game-ci/unity-builder@v2 with: unityVersion: 2022.3.10f1 targetPlatform: Android buildMethod: BuildScript.AnalyzeDuplicatesOnly - name: Check Duplicate Threshold run: | # 분석 결과 파일 확인 DUPLICATE_MB=$(cat duplicate_report.json | jq '.totalDuplicateSizeMB') THRESHOLD=50 # 50MB 임계값 if (( $(echo "$DUPLICATE_MB > $THRESHOLD" | bc -l) )); then echo "::error::중복 에셋이 ${DUPLICATE_MB}MB로 임계값(${THRESHOLD}MB) 초과" exit 1 fi echo "✅ 중복 에셋: ${DUPLICATE_MB}MB (임계값: ${THRESHOLD}MB)" - name: Upload Report uses: actions/upload-artifact@v3 with: name: duplicate-report path: duplicate_report.json
// BuildScript.cs - CI용 분석 메서드 using UnityEditor; using UnityEditor.AddressableAssets; using UnityEditor.AddressableAssets.Build.AnalyzeRules; using System.IO; using System.Linq; public static class BuildScript { public static void AnalyzeDuplicatesOnly() { var settings = AddressableAssetSettingsDefaultObject.Settings; var rule = new CheckBundleDupeDependencies(); var results = rule.RefreshAnalysis(settings); // 중복 에셋 집계 var duplicates = results .Where(r => r.severity >= MessageType.Warning) .Select(r => new { AssetPath = r.resultName, BundleCount = r.data?.Count ?? 0, SizeMB = GetAssetSizeMB(r.resultName) }) .ToList(); var totalDuplicateMB = duplicates.Sum(d => d.SizeMB * (d.BundleCount - 1)); // JSON 리포트 생성 var report = new { timestamp = System.DateTime.UtcNow.ToString("o"), totalDuplicateSizeMB = totalDuplicateMB, duplicateCount = duplicates.Count, details = duplicates }; var json = JsonUtility.ToJson(report, true); File.WriteAllText("duplicate_report.json", json); Debug.Log($"중복 분석 완료: {totalDuplicateMB:F2}MB"); // CI 환경에서는 exit code로 결과 전달 if (Application.isBatchMode) { EditorApplication.Exit(totalDuplicateMB > 50 ? 1 : 0); } } private static float GetAssetSizeMB(string assetPath) { var fileInfo = new FileInfo(assetPath); return fileInfo.Exists ? fileInfo.Length / (1024f * 1024f) : 0f; } }
PR에서 중복 증가를 막으려면?

베이스라인 비교로 중복이 증가하면 PR을 블록해:

# duplicate_check.py - PR 중복 비교 스크립트 import json import sys import os def load_report(path): with open(path, 'r') as f: return json.load(f) def compare_duplicates(base_report, pr_report): base_mb = base_report['totalDuplicateSizeMB'] pr_mb = pr_report['totalDuplicateSizeMB'] diff = pr_mb - base_mb print(f"베이스: {base_mb:.2f}MB") print(f"PR: {pr_mb:.2f}MB") print(f"변화: {diff:+.2f}MB") # 새로 추가된 중복 에셋 식별 base_assets = {d['AssetPath'] for d in base_report['details']} pr_assets = {d['AssetPath'] for d in pr_report['details']} new_duplicates = pr_assets - base_assets if new_duplicates: print("\n⚠️ 새로 추가된 중복 에셋:") for asset in new_duplicates: print(f" - {asset}") # 5MB 이상 증가하면 실패 if diff > 5.0: print("\n❌ 중복 에셋이 5MB 이상 증가했습니다.") print(" 공유 그룹으로 이동하거나 중복을 제거해주세요.") return 1 print("\n✅ 중복 에셋 체크 통과") return 0 if __name__ == "__main__": base = load_report("baseline_duplicate_report.json") pr = load_report("duplicate_report.json") sys.exit(compare_duplicates(base, pr))

Part 7. 종합 정리: 중복 관리 체크리스트

실무에서 바로 쓸 수 있는 체크리스트 있어?
[에셋 중복 관리 완전 체크리스트]

□ 설계 단계
  ├── □ 계층적 번들 구조 정의 (Core → Shared → Domain → Content)
  ├── □ 각 레이어의 참조 규칙 문서화
  ├── □ 공유 에셋 기준 정의 (크기, 사용 빈도)
  └── □ 중복 허용 임계값 설정 (예: 100KB 미만은 허용)

□ 개발 단계
  ├── □ 새 에셋 추가 시 의존성 확인
  ├── □ 2개 이상 번들에서 사용되면 Shared로 이동
  ├── □ 주기적으로 Analyze 실행 (주 1회 이상)
  └── □ 큰 텍스처/메시 변경 시 영향 범위 확인

□ 빌드 단계
  ├── □ CI에서 중복 분석 자동 실행
  ├── □ 임계값 초과 시 빌드 실패 처리
  ├── □ 베이스라인 대비 증가량 모니터링
  └── □ 빌드 리포트에 중복 현황 포함

□ 릴리스 단계
  ├── □ 최종 빌드 중복 현황 리뷰
  ├── □ 플랫폼별 빌드 크기 비교
  ├── □ 패치 크기 예측 및 검증
  └── □ 베이스라인 업데이트

□ 모니터링
  ├── □ 빌드 크기 트렌드 추적
  ├── □ 중복 비율 대시보드
  ├── □ 패치 크기 히스토리
  └── □ 메모리 프로파일링 (런타임 중복 확인)
💡 핵심 원칙 3가지:
  1. 명시적 할당: 공유될 에셋은 반드시 Shared 그룹에 명시적으로 할당
  2. 계층적 구조: 하위 레이어는 상위 레이어만 참조하도록 설계
  3. 자동화된 검증: CI/CD에서 중복 증가를 자동으로 감지하고 차단

핵심 요약: 중복 에셋의 함정

  • 중복 원인: 명시적 할당 없이 여러 번들이 같은 에셋 참조 → 각 번들에 복사됨
  • 영향: 빌드 크기 20-40% 증가, 메모리 낭비, 패치 크기 배가
  • 탐지: Unity Analyze "Check Duplicate Bundle Dependencies", Unreal Asset Audit
  • 해결: 공유 에셋을 Shared 그룹으로 이동, 계층적 번들 구조 설계
  • 예방: CI/CD에서 자동 검사, 임계값 초과 시 빌드 실패
  • 트레이드오프: 작은 에셋은 중복 허용이 효율적일 수 있음 (요청 오버헤드 고려)
