INSERT 하고 바로 ID 받기, SELECT 없이

OUTPUT 절 - INSERT/UPDATE/DELETE의 숨겨진 능력

Part 1. 흔한 상황

아이템 INSERT 하고 나서 그 아이템의 ID(자동 생성된 키)를 알고 싶어. 어떻게 해?

보통 이렇게 하지:

-- 흔한 패턴 INSERT INTO TItem (owner, itemcode, count) VALUES (@charunique, @itemcode, @count) -- 방금 생성된 ID 가져오기 SELECT @newItemUID = SCOPE_IDENTITY()
SCOPE_IDENTITY()? 그게 뭐야?

"현재 세션에서 마지막으로 생성된 IDENTITY 값"을 반환해.

IDENTITY는 자동 증가 컬럼이야. 1, 2, 3, 4... 자동으로 올라가는.

그럼 이 방식이 문제가 있어?

작동은 해. 근데 두 가지 한계가 있어:

1. 한 번에 여러 개 INSERT하면 마지막 ID만 알 수 있음

2. IDENTITY 컬럼에서만 동작함

-- 문제 상황: 여러 개 INSERT INSERT INTO TItem (owner, itemcode, count) VALUES (@char, 1001, 10), -- 이 ID는? (@char, 1002, 5), -- 이 ID는? (@char, 1003, 1) -- SCOPE_IDENTITY()는 이것만 반환 SELECT SCOPE_IDENTITY() -- 마지막 것만!

Part 2. OUTPUT 절이 뭐야?

그래서 더 좋은 방법이 있어?

OUTPUT 절! SQL Server 2005부터 추가된 기능이야.

INSERT INTO TItem (owner, itemcode, count) OUTPUT inserted.itemuid -- 이게 OUTPUT 절! VALUES (@charunique, @itemcode, @count)
inserted가 뭐야?

inserted는 "방금 INSERT된 행"을 담고 있는 가상 테이블이야.

마치 트리거에서 쓰는 것처럼.

가상 테이블 사용 가능한 곳 내용
inserted INSERT, UPDATE 새로 추가/변경된 행
deleted DELETE, UPDATE 삭제된/변경 전 행

UPDATE에서는 둘 다 쓸 수 있어:

• deleted = 변경 전 값

• inserted = 변경 후 값

Part 3. INSERT에서 OUTPUT 쓰기

아까 여러 개 INSERT할 때 문제 있다고 했잖아. OUTPUT으로 어떻게 해결해?

OUTPUT은 INSERT된 모든 행을 반환할 수 있어!

INSERT INTO TItem (owner, itemcode, count) OUTPUT inserted.itemuid, inserted.itemcode VALUES (@char, 1001, 10), (@char, 1002, 5), (@char, 1003, 1)

결과:

itemuid itemcode ------- -------- 50001 1001 50002 1002 50003 1003 (3개 행 모두 반환됨!)
오, 진짜 3개 다 나오네! 변수에 저장하려면?

테이블 변수에 저장할 수 있어:

DECLARE @InsertedItems TABLE ( itemuid bigint, itemcode int ) INSERT INTO TItem (owner, itemcode, count) OUTPUT inserted.itemuid, inserted.itemcode INTO @InsertedItems -- 테이블 변수에 저장! VALUES (@char, 1001, 10), (@char, 1002, 5), (@char, 1003, 1) -- 이제 @InsertedItems에서 조회 가능 SELECT * FROM @InsertedItems

Part 4. UPDATE에서 OUTPUT 쓰기

UPDATE할 때도 쓸 수 있어?

응! 변경 전과 후 값을 동시에 알 수 있어.

-- 레벨업 처리 UPDATE TCharacter SET level = level + 1 OUTPUT deleted.level AS old_level, -- 변경 전 inserted.level AS new_level -- 변경 후 WHERE charunique = @uid

결과:

old_level new_level --------- --------- 49 50 한 쿼리로 "49 → 50 레벨업!" 메시지 만들 수 있음
이거 쓸 데가 많겠다!

활용 예시:

• 골드 차감 후 잔액 확인

• 아이템 수량 변경 후 결과 확인

• 상태 변경 로그 기록

-- 골드 차감 + 잔액 확인 (한 쿼리로) DECLARE @result TABLE (old_gold bigint, new_gold bigint) UPDATE TCharacter SET gold = gold - @price OUTPUT deleted.gold, inserted.gold INTO @result WHERE charunique = @uid AND gold >= @price -- 잔액 체크 -- 결과 확인 IF @@ROWCOUNT = 0 RETURN -1 -- 잔액 부족 SELECT @remaining = new_gold FROM @result

Part 5. DELETE에서 OUTPUT 쓰기

DELETE도 가능해?

당연하지! 삭제된 데이터를 반환받을 수 있어.

-- 만료된 메일 삭제 + 뭐가 삭제됐는지 로그 DELETE FROM TMail OUTPUT deleted.mailuid, deleted.sender, deleted.receiver, deleted.itemcode WHERE expiredate < GETDATE()

실전 활용:

• 삭제 전 백업 테이블로 복사

• 삭제 로그 자동 기록

• 삭제된 아이템 복구 지원

-- 삭제하면서 백업 테이블로 이동 DELETE FROM TItem OUTPUT deleted.*, GETDATE() AS delete_time INTO TItem_Deleted -- 백업 테이블로! WHERE owner = @charunique AND itemcode = @itemcode

Part 6. 기존 방식과 비교

SCOPE_IDENTITY()랑 뭐가 달라?

표로 비교해볼게:

항목 SCOPE_IDENTITY() OUTPUT 절
여러 행 INSERT 마지막 ID만 모든 ID
IDENTITY 아닌 컬럼 불가 가능
UPDATE에서 사용 불가 가능 (전/후 값)
DELETE에서 사용 불가 가능
여러 컬럼 반환 불가 가능
트리거와 충돌 가능 안전

OUTPUT 절이 훨씬 유연하고 안전해.

기존 방식 (2번 쿼리)
INSERT INTO TItem ... SELECT @id = SCOPE_IDENTITY()
VS
OUTPUT (1번 쿼리)
INSERT INTO TItem ... OUTPUT inserted.itemuid

Part 7. 실전 예제: 아이템 지급

게임에서 실제로 어떻게 쓸 수 있어?

아이템 지급 프로시저를 개선해보자.

Before: 기존 방식

CREATE PROCEDURE gp_Add_Item @charunique bigint, @itemcode int, @count int, @newItemUID bigint OUTPUT -- OUTPUT 파라미터 AS BEGIN INSERT INTO TItem (owner, itemcode, count) VALUES (@charunique, @itemcode, @count) -- 별도 쿼리로 ID 가져오기 SET @newItemUID = SCOPE_IDENTITY() END

After: OUTPUT 절 활용

CREATE PROCEDURE gp_Add_Item @charunique bigint, @itemcode int, @count int, @newItemUID bigint OUTPUT AS BEGIN SET NOCOUNT ON; DECLARE @result TABLE (itemuid bigint) INSERT INTO TItem (owner, itemcode, count) OUTPUT inserted.itemuid INTO @result VALUES (@charunique, @itemcode, @count) SELECT @newItemUID = itemuid FROM @result END
근데 이거 더 길어 보이는데?

단일 INSERT면 차이가 크지 않아. 여러 개 처리할 때 진가가 나타나.

응용: 여러 아이템 동시 지급

CREATE PROCEDURE gp_Add_Items_Batch @charunique bigint, @items nvarchar(max) -- JSON: [{"code":1001,"cnt":10},...] AS BEGIN SET NOCOUNT ON; -- 결과 테이블 DECLARE @result TABLE ( itemuid bigint, itemcode int, count int ) -- JSON 파싱 + INSERT + OUTPUT 한 번에! INSERT INTO TItem (owner, itemcode, count) OUTPUT inserted.itemuid, inserted.itemcode, inserted.count INTO @result SELECT @charunique, JSON_VALUE(value, '$.code'), JSON_VALUE(value, '$.cnt') FROM OPENJSON(@items) -- 모든 생성된 아이템 정보 반환 SELECT * FROM @result END

Part 8. 주의사항

OUTPUT 절 쓸 때 주의할 거 있어?

몇 가지 있어:

주의사항 설명
트리거와 함께 사용 트리거가 있는 테이블에서 OUTPUT INTO 사용 시 제한
원격 테이블 링크드 서버 테이블에서는 OUTPUT 불가
뷰에서 사용 일부 뷰에서 제한
OLE DB 클라이언트 결과셋으로 반환되므로 처리 필요

우리 프로젝트 관련:

OLE DB로 결과셋 받을 때는 프로시저 설계를 잘 해야 해.

OUTPUT 결과가 별도 결과셋으로 반환되니까.

-- OLE DB에서 주의: OUTPUT이 결과셋으로 반환됨 INSERT INTO TItem ... OUTPUT inserted.itemuid -- 이게 첫 번째 결과셋 VALUES (...) SELECT @result = ... -- 다른 SELECT가 있다면 두 번째 결과셋 -- C++ 코드에서 GetFirstRecord() 호출 시 -- 어떤 결과셋을 받을지 주의!

Part 9. 우리 프로젝트 현황

우리 프로젝트에서 OUTPUT 절 쓰고 있어?

분석 결과, OUTPUT 파라미터는 많이 쓰지만

OUTPUT 절은 거의 안 씀.

구분 설명 우리 사용
OUTPUT 파라미터 프로시저 파라미터에 OUTPUT 키워드 많이 사용
OUTPUT 절 INSERT/UPDATE/DELETE 내 OUTPUT 거의 안 씀

현재 주로 SCOPE_IDENTITY()를 사용 중.

새 프로시저에서 OUTPUT 절 도입 고려해볼 만함.

핵심 정리

  • OUTPUT 절 = INSERT/UPDATE/DELETE 결과를 즉시 반환
  • inserted = 새로 추가/변경된 행 (INSERT, UPDATE)
  • deleted = 삭제된/변경 전 행 (DELETE, UPDATE)
  • 여러 행 한 번에 처리할 때 진가 발휘
  • OUTPUT INTO = 테이블 변수나 실제 테이블에 저장
  • SCOPE_IDENTITY()보다 유연하고 안전
  • 우리 프로젝트: OUTPUT 파라미터는 많이 씀, OUTPUT 절은 도입 검토
