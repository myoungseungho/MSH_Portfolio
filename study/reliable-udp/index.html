UDP는 안 믿음인데, 어떻게 '꼭 도착'을 만들까? — 신뢰성 UDP

한 UDP 채널에 unreliable과 reliable을 섞어 쓰는 법

30초 요약

UDP는 기본이 '안 믿음'(유실·순서 미보장). 대신 빠름.

그래서 '꼭 도착해야 하는' 메시지에만 ACK + 재전송을 직접 얹어 신뢰성을 만들어.

한 UDP 채널에 unreliable(이동)과 reliable(중요)을 섞어 쓴다 — UE의 Bunch reliable 플래그가 이것.

Part 1. 왜 TCP 안 쓰고 굳이?

꼭 도착시킬 거면 그냥 TCP 쓰면 되잖아?

TCP는 '전부 reliable + 순서 보장'이라, 잃은 옛 패킷 하나를 재전송하느라 최신 패킷까지 다 막혀(HOL 블로킹). 액션 게임엔 치명적이야.

그래서 UDP를 깔고, '이 메시지는 꼭, 저 메시지는 잃어도 됨'을 메시지별로 고르는 거야. TCP의 전부-아니면-전무를 피하는 거지.

어떻게 '꼭 도착'을 만들어?

보낼 때 순번(seq)을 붙이고, 받는 쪽이 ACK를 보내. 일정 시간 ACK가 안 오면 재전송. 순번으로 중복 제거·순서 정렬도 해.

TCP가 OS 안에서 해주는 일을, 필요한 메시지에만 골라서 직접 구현하는 거야.

Part 2. 섞어 쓰는 걸 봐

두 종류가 한 채널에 어떻게 흐르나 봐.

파랑=이동(unreliable, 잃으면 빨갛게 사라지고 끝), 노랑=중요(reliable, 잃으면 주황으로 재전송돼 결국 도착).

탭으로 유실률을 올려봐 — 이동은 유실 카운트가 늘지만, 중요는 재전송으로 끝까지 보장돼.

0이동 유실(무시)
0중요 재전송(보장)

UE는 이걸 어디서?

UE는 데이터를 Bunch로 보내는데, 각 Bunch에 bReliable 플래그가 있어. reliable이면 ACK·재전송·순서 보장, 아니면 그냥 보내고 잊어.

우리(조선협객전)는 TCP 기반이라 모든 게 reliable이지만, 그래서 이동처럼 '최신만 중요한' 것도 순서 보장 비용을 내는 셈. 장르(MMO vs FPS)에 따라 선택이 갈려.

핵심 정리

  • UDP = 기본 안 믿음(빠름). 신뢰성은 필요한 메시지에만 직접 얹음
  • reliable = 순번(seq) + ACK + 재전송 + 중복제거. TCP가 OS에서 하는 걸 선택적으로
  • 한 채널에 unreliable(이동) + reliable(중요) 혼합
  • TCP를 안 쓰는 이유 = 전부-reliable의 HOL 블로킹 회피
  • UE = Bunch의 bReliable 플래그, 우리 = TCP(전부 reliable)
