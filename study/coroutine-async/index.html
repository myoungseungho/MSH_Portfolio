코루틴 기반 비동기

C++20 비동기 프로그래밍
Coroutine co_await co_return 비동기 콜백 지옥

1. 출발점: 콜백 지옥을 본 적 있나?

게임 서버에서 "캐릭터 로그인"을 처리한다고 합시다. DB에서 여러 데이터를 순차적으로 가져와야 합니다.

동기 코드 (직관적이지만 블로킹)

void OnLogin(Player* player) {
    // 1. 캐릭터 정보 로드
    CharInfo info = DB_LoadCharacter(player->id);  // 50ms 블로킹!

    // 2. 인벤토리 로드
    Inventory inv = DB_LoadInventory(player->id);   // 30ms 블로킹!

    // 3. 퀘스트 로드
    QuestList quests = DB_LoadQuests(player->id);   // 20ms 블로킹!

    // 4. 클라이언트에 전송
    SendToClient(player, info, inv, quests);
}

블로킹의 문제

DB 응답을 기다리는 동안 이 스레드는 아무것도 못 합니다.
100ms 동안 멈춰있으면, 그 사이에 다른 유저의 패킷도 처리 못 합니다. IOCP 워커 스레드가 몇 개뿐인데, 전부 DB 대기 중이면 서버가 멈춰요.

콜백 기반 비동기 (블로킹 없지만 지옥)

void OnLogin(Player* player) {
    DB_LoadCharacterAsync(player->id, [player](CharInfo info) {
        // 1번 완료 → 2번 요청
        DB_LoadInventoryAsync(player->id, [player, info](Inventory inv) {
            // 2번 완료 → 3번 요청
            DB_LoadQuestsAsync(player->id, [player, info, inv](QuestList quests) {
                // 3번 완료 → 전송
                SendToClient(player, info, inv, quests);
                // 여기서 에러 나면? 어디서 잡지?
            });
        });
    });
}

// → 들여쓰기 지옥 (Callback Hell)
// → 에러 처리 어디서?
// → 중간에 player가 접속 끊으면?

콜백 지옥의 문제

  • 가독성 최악: 들여쓰기가 깊어지고, 흐름을 따라가기 어려움
  • 에러 처리 분산: 각 콜백마다 에러 처리가 따로 필요
  • 수명 관리 복잡: 콜백 실행 시점에 player가 유효한지 확인 필요
  • 디버깅 불가: 콜 스택이 끊겨서 브레이크포인트로 추적 어려움

2. 코루틴의 발상

코루틴의 핵심 아이디어

"함수를 중간에 멈추고, 나중에 이어서 실행할 수 있으면 어떨까?"
DB 응답 기다리는 동안 멈춰두고, 응답 오면 멈춘 지점부터 다시 시작. 

// 코루틴 버전 (C++20)
Task OnLogin(Player* player) {
    // 1. DB 요청 → 여기서 멈춤 → 응답 오면 다시 시작
    CharInfo info = co_await DB_LoadCharacterAsync(player->id);

    // 2. 다음 DB 요청 → 또 멈춤 → 응답 오면 다시 시작
    Inventory inv = co_await DB_LoadInventoryAsync(player->id);

    // 3. 또 멈춤 → 응답 오면 다시 시작
    QuestList quests = co_await DB_LoadQuestsAsync(player->id);

    // 4. 전송
    SendToClient(player, info, inv, quests);
}

동기 코드처럼 읽히지만, co_await에서 스레드를 블로킹하지 않습니다. 멈추는 동안 스레드는 다른 유저의 패킷을 처리합니다.

콜백 기반

코드가 쪼개져서 흐름 파악 어려움

에러 처리가 각 콜백에 분산

디버깅 시 콜 스택 끊김

코루틴 기반

위에서 아래로 자연스럽게 읽힘

try-catch로 한 곳에서 에러 처리

중단점에서 로컬 변수 전부 확인 가능

3. 코루틴 동작 원리: 중단과 재개

일반 함수는 호출되면 끝까지 실행됩니다. 코루틴은 중간에 멈출 수 있는 함수입니다.

[일반 함수] 호출 ──── 실행 ──── 실행 ──── 실행 ──── 리턴 (중간에 멈출 수 없음) [코루틴] 호출 ── 실행 ── co_await ── 중단(suspend) ─┐ │ (스레드 해방, │ 다른 일 처리) 재개(resume) ◄──────────────────────────────┘ ── 실행 ── co_await ── 중단 ─┐ │ 재개 ◄─────────────────────────┘ ── 실행 ── co_return ── 완료

중단 시 무슨 일이 벌어지나?

co_await에서 일어나는 일

  1. 상태 저장: 로컬 변수, 실행 위치를 힙 메모리에 저장 (코루틴 프레임)
  2. 스레드 해방: 현재 스레드는 코루틴을 떠나 다른 일을 하러 감
  3. 비동기 작업 시작: DB 쿼리 등 비동기 작업이 백그라운드에서 진행
  4. 완료 시 재개: 비동기 작업이 끝나면, 저장된 상태를 복원하고 이어서 실행
[코루틴 프레임 (힙 메모리)] ┌─────────────────────────┐ │ 실행 위치: line 15 │ ← 어디서 멈췄는지 │ 로컬 변수: │ │ info = {...} │ ← 이미 받은 데이터 │ player = 0x7FF... │ ← 포인터 │ 반환 타입 정보 │ └─────────────────────────┘ co_await 시: 이 프레임을 남겨두고 스레드가 떠남 resume 시: 이 프레임을 불러와서 line 15부터 다시 실행
비유로 이해하기
[일반 함수 = 전화 통화] 전화 걸기 → 상대가 받을 때까지 계속 들고 있음 (블로킹) → 그 동안 아무것도 못 함 [코루틴 = 카톡 메시지] 메시지 보내기 → 폰 내려놓고 다른 일 하기 → 답장 오면 알림 → 이어서 대화 co_await = "메시지 보내고 알림 올 때까지 다른 일 하기"

4. C++20 코루틴 키워드 3개

함수 안에 아래 키워드 중 하나라도 있으면, 컴파일러가 자동으로 코루틴으로 변환합니다.

키워드 의미 비유
co_await 비동기 작업 완료까지 중단. 완료되면 결과를 받고 재개 "이거 기다릴 동안 다른 일 할게"
co_return 코루틴 종료. 결과값 반환 "다 끝났어, 결과 여기 있어"
co_yield 값을 하나 내보내고 중단. 다음 호출 시 재개 "하나 줄게, 다음 거는 나중에"

co_await 예시: DB 쿼리

Task<CharInfo> LoadCharacter(int playerId) {
    // DB에 비동기 쿼리 요청
    DbResult result = co_await db.QueryAsync(
        "SELECT * FROM Character WHERE id = ?", playerId
    );
    // ↑ 여기서 중단. DB 응답 오면 재개

    CharInfo info;
    info.name = result.GetString("name");
    info.level = result.GetInt("level");

    co_return info;  // 결과 반환하고 코루틴 종료
}

co_yield 예시: 순차 생성기

Generator<int> Range(int start, int end) {
    for (int i = start; i < end; i++) {
        co_yield i;  // 값 하나 내보내고 중단
    }
}

// 사용
for (int v : Range(0, 10)) {
    print(v);  // 0, 1, 2, ... 9
}

// 게임 활용: 몬스터 웨이브 생성
Generator<Wave> DungeonWaves() {
    co_yield Wave{"고블린", 5};   // 1웨이브
    co_yield Wave{"오크", 3};     // 2웨이브
    co_yield Wave{"보스", 1};     // 3웨이브
}

활용 1: DB 쿼리 체이닝

Task ProcessTrade(Player* buyer, Player* seller, int itemId) {
    // 1. 판매자 아이템 확인
    bool hasItem = co_await DB_CheckItemAsync(seller->id, itemId);
    if (!hasItem) {
        SendError(buyer, "아이템 없음");
        co_return;
    }

    // 2. 구매자 골드 확인
    int gold = co_await DB_GetGoldAsync(buyer->id);
    if (gold < price) {
        SendError(buyer, "골드 부족");
        co_return;
    }

    // 3. 거래 실행
    bool success = co_await DB_ExecuteTradeAsync(buyer->id, seller->id, itemId);

    if (success) {
        SendSuccess(buyer, "거래 완료!");
        SendSuccess(seller, "아이템 판매 완료!");
    }
}

활용 2: 타이머 대기

Task RespawnMonster(Monster* mob) {
    mob->SetDead();

    // 5초 대기 (스레드 블로킹 아님!)
    co_await Timer::After(5000);  // 5000ms

    // 5초 후 여기서 재개
    mob->Respawn();
    mob->SetAlive();
}

// Sleep(5000) 과의 차이:
// Sleep → 스레드가 5초 동안 아무것도 못 함
// co_await Timer → 스레드가 다른 일 하다가 5초 후 돌아옴

6. IOCP + 코루틴 조합

기존 IOCP 서버에 코루틴을 접목하는 개념입니다. IOCP가 "완료 통보"를 해주면, 코루틴을 "재개"하는 방식입니다.

[기존 IOCP 방식] WSARecv 완료 → GetQueuedCompletionStatus → 콜백 함수 호출 [IOCP + 코루틴] WSARecv 완료 → GetQueuedCompletionStatus → 코루틴 resume 코루틴 내부: auto data = co_await RecvAsync(socket); // WSARecv + 중단 // ↑ IOCP 완료 시 자동으로 여기서 재개 ProcessPacket(data); co_await SendAsync(socket, response); // WSASend + 중단 // ↑ IOCP 완료 시 자동으로 여기서 재개
// 개념적 구현 (단순화)
Task HandleClient(SOCKET sock) {
    while (true) {
        // 수신 대기 (IOCP 기반, 블로킹 아님)
        Packet pkt = co_await RecvAsync(sock);

        if (pkt.type == PKT_ATTACK) {
            // DB 조회도 비동기
            auto dmg = co_await CalcDamageAsync(pkt);
            co_await SendAsync(sock, MakeResult(dmg));
        }
    }
}

// 워커 스레드에서:
while (true) {
    GetQueuedCompletionStatus(hIOCP, ...);
    // 완료된 코루틴을 찾아서 resume
    coroutine_handle.resume();
}

조합의 장점

  • IOCP: 소수 스레드로 수만 연결 처리 (성능)
  • 코루틴: 비동기 로직을 동기처럼 작성 (가독성)
  • 두 장점을 결합: 고성능 + 읽기 쉬운 코드

7. 주의사항

주의점 설명
힙 할당 코루틴 프레임이 힙에 할당됨. 대량 생성 시 메모리 주의
재개 스레드 중단 전과 재개 후의 스레드가 다를 수 있음. thread-local 주의
수명 관리 co_await 중에 참조하는 객체가 소멸되면 댕글링 포인터
디버깅 일반 함수보다 콜 스택 추적이 복잡함. 전용 디버깅 도구 필요
컴파일러 지원 MSVC 2019 16.8+, GCC 11+, Clang 14+

수명 관리 함정

Task Dangerous() {
    Player player;  // 스택 변수
    co_await SomeAsync();
    // ↑ 여기서 중단되면, 호출자가 리턴할 수 있음
    // → player가 이미 파괴됨!
    player.DoSomething();  // 위험!
}

// 해결: 코루틴 내부 로컬 변수는 코루틴 프레임에 저장되므로 안전
// 위험한 건 "외부에서 받은 참조/포인터"

Task Safe(shared_ptr<Player> player) {
    // shared_ptr로 수명 보장
    co_await SomeAsync();
    player->DoSomething();  // 안전!
}

8. 정리: 언제 코루틴을 쓸까?

상황 추천 이유
DB 쿼리 체이닝 코루틴 순차 비동기를 깔끔하게
타이머/딜레이 코루틴 Sleep 없이 대기
연출/시퀀스 코루틴 대본처럼 읽히는 코드
단순 패킷 처리 콜백 단일 콜백이면 코루틴 오버헤드 불필요
초고성능 루프 콜백/직접 힙 할당 오버헤드가 부담될 수 있음

한 줄 정리

코루틴은 "중간에 멈추고 나중에 이어서 실행할 수 있는 함수"입니다.
콜백 지옥 없이 비동기 코드를 동기 코드처럼 작성할 수 있고, IOCP와 결합하면 고성능 게임 서버에서도 읽기 쉬운 비동기 로직을 구현할 수 있습니다.
