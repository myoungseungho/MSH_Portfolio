Part 1. 문제: 4K 텍스처의 딜레마

4K 텍스처 하나가 메모리를 얼마나 먹어?

4096 × 4096 텍스처, RGBA 포맷이면:

4096 × 4096 × 4바이트 = 64MB

캐릭터 하나에 텍스처가 5장이면? 320MB

캐릭터 100명이면? 32GB... RAM 전체를 잡아먹는다!

텍스처 크기 계산: 해상도 계산식 메모리 ─────────────────────────────────────────────── 256 × 256 256 × 256 × 4 = 256 KB 512 × 512 512 × 512 × 4 = 1 MB 1024 × 1024 1024 × 1024 × 4 = 4 MB 2048 × 2048 2048 × 2048 × 4 = 16 MB 4096 × 4096 4096 × 4096 × 4 = 64 MB ← 4K 8192 × 8192 8192 × 8192 × 4 = 256 MB ← 8K 압축 포맷 (BC7) 사용 시 약 1/4: 4096 × 4096 BC7 = 16MB (여전히 큼!)
근데 멀리 있는 건 어차피 작게 보이잖아?

바로 그거다!

화면에서 10픽셀로 보이는 물체에 4K 텍스처는 낭비

멀리 있으면 저해상도, 가까우면 고해상도 → 이게 텍스처 스트리밍

Part 2. Mipmap이 뭔데?

Mipmap이 뭐야?

하나의 텍스처를 여러 해상도 버전으로 미리 만들어 두는 것

원본 4K → 2K → 1K → 512 → 256 → ... → 1×1

각 단계를 Mip Level이라고 함

Mipmap 체인: Level 0 (원본): 4096 × 4096 = 64 MB ████████████████████████████████ Level 1: 2048 × 2048 = 16 MB ████████████████ Level 2: 1024 × 1024 = 4 MB ████████ Level 3: 512 × 512 = 1 MB ████ Level 4: 256 × 256 = 256 KB ██ Level 5: 128 × 128 = 64 KB █ Level 6: 64 × 64 = 16 KB ▪ Level 7: 32 × 32 = 4 KB · ... Level 12: 1 × 1 = 4 B · 전체 Mipmap 용량 = 원본의 약 1.33배 (64MB → 85MB)
왜 미리 만들어 둬?

1. 실시간 축소는 느리다 - GPU가 매 프레임 축소 연산?

2. 품질 문제 - 실시간 축소는 모아레 패턴 발생

3. GPU가 Mipmap 선택을 하드웨어로 지원

Part 3. GPU가 Mip Level을 선택하는 방법

GPU가 어떻게 알아서 골라?

GPU는 화면에 그려지는 픽셀 크기를 계산한다

텍스처의 1 텍셀(texel)이 화면의 1 픽셀에 가까운 Mip을 선택

Mip Level 선택 기준: 카메라와 오브젝트 거리 → 화면에 보이는 크기 → Mip Level 예시: 4K 텍스처가 붙은 벽 거리 화면 픽셀 필요 해상도 Mip Level ──────────────────────────────────────────────── 1m 2000 px 4096 (원본) Level 0 5m 400 px 512 Level 3 20m 100 px 128 Level 5 100m 20 px 32 Level 7 500m 4 px 4 Level 10 → 멀어질수록 낮은 Mip 사용 = 메모리 절약!
그게 스트리밍이랑 무슨 상관?

핵심 아이디어: 필요한 Mip Level만 메모리에 올리자!

100m 밖에 있으면 Level 5까지만 로딩 (64KB)

가까워지면 Level 0까지 추가 로딩 (64MB)

Part 4. 텍스처 스트리밍의 실제 동작

구체적으로 어떻게 동작해?

1. 처음에는 최저 Mip만 로딩 (Level 7~12)

2. 카메라가 가까워지면 높은 Mip 요청

3. 백그라운드에서 비동기 로딩

4. 로딩 완료되면 GPU 텍스처 업데이트

Part 5. 게임에서 보이는 현상

텍스처가 흐릿했다가 선명해지는 거?

맞다! 그게 바로 텍스처 스트리밍

로딩이 늦으면 저해상도가 먼저 보이고, 고해상도가 나중에 팝!

이걸 "텍스처 팝인(Pop-in)"이라고 함

텍스처 팝인 현상: 시간 → [처음] [0.5초 후] [1초 후] ┌────────┐ ┌────────┐ ┌────────┐ │ ░░░░░░ │ │ ▒▒▒▒▒▒ │ │ ██████ │ │ ░░░░░░ │ → │ ▒▒▒▒▒▒ │ → │ ██████ │ │ ░░░░░░ │ │ ▒▒▒▒▒▒ │ │ ██████ │ └────────┘ └────────┘ └────────┘ Mip 7 Mip 3 Mip 0 (흐릿) (중간) (선명) 너무 급격하면 눈에 거슬림! → 부드럽게 블렌딩하거나, 미리 로딩(예측)으로 해결
팝인 줄이는 방법은?

1. 예측 로딩 - 플레이어 이동 방향 예측

2. Mip 블렌딩 - 두 Mip을 서서히 전환

3. 높은 I/O 대역폭 - SSD가 빠르면 팝인 짧음

4. 메모리 여유 - 더 많이 미리 로딩

Part 6. 간단한 구현 개념

코드로 보면?

간략화된 텍스처 스트리밍 시스템:

// 텍스처 스트리밍 매니저 class TextureStreamer { void Update() { for (auto& texture : allTextures) { // 1. 필요한 Mip Level 계산 float distance = GetDistanceToCamera(texture); int desiredMip = CalculateMipLevel(distance); // 2. 현재 로딩된 것보다 더 높은 품질 필요? if (desiredMip < texture.loadedMip) { // 스트리밍 요청 RequestMipLoad(texture, desiredMip); } // 3. 메모리 예산 초과 시 낮은 우선순위 해제 if (IsOverMemoryBudget()) { UnloadLowPriorityMips(); } } } int CalculateMipLevel(float distance) { // 거리에 따른 Mip Level 계산 // 가까우면 0(최고), 멀면 높은 숫자(저품질) return log2(distance / screenPixelRatio); } };
// Unity에서의 텍스처 스트리밍 설정 // Project Settings > Quality > Texture Streaming Texture Streaming: Enabled Memory Budget: 512 MB // VRAM 예산 Max Level Reduction: 2 // 최대 몇 Mip 낮출 수 있나 Max IO Requests: 8 // 동시 로딩 요청 수 // 개별 텍스처 설정 textureImporter.streamingMipmaps = true; textureImporter.streamingMipmapsPriority = 0; // 높을수록 우선

Part 7. 더 발전된 형태: Virtual Texture

Mipmap 스트리밍의 한계는?

Mip 단위로 스트리밍 → 전체 레벨을 한 번에 로딩해야 함

4K 텍스처 Mip 0 = 16~64MB 한 번에 로딩

Virtual Texture는 뭐가 달라?

텍스처를 작은 타일(예: 128×128)로 쪼갬

화면에 보이는 타일만 로딩

→ 거대한 텍스처도 필요한 부분만 메모리에

Mipmap Streaming vs Virtual Texture: Mipmap Streaming: ┌────────────────────────────┐ │ 전체 Mip Level │ ← 레벨 단위 로딩 │ 한 번에 로딩 │ └────────────────────────────┘ Virtual Texture: ┌────┬────┬────┬────┬────┐ │ ▓▓ │ ░░ │ ░░ │ ░░ │ ░░ │ ← 타일 단위 로딩 ├────┼────┼────┼────┼────┤ ▓▓ = 로딩됨 │ ▓▓ │ ▓▓ │ ░░ │ ░░ │ ░░ │ ░░ = 안 로딩 ├────┼────┼────┼────┼────┤ │ ░░ │ ▓▓ │ ▓▓ │ ░░ │ ░░ │ 화면에 보이는 부분만! ├────┼────┼────┼────┼────┤ │ ░░ │ ░░ │ ▓▓ │ ░░ │ ░░ │ └────┴────┴────┴────┴────┘ → 더 세밀한 메모리 관리 가능

핵심 정리

  • Mipmap = 같은 텍스처의 여러 해상도 버전
  • GPU가 거리에 따라 적절한 Mip 선택
  • 텍스처 스트리밍 = 필요한 Mip만 메모리에 로딩
  • 가까워지면 로딩, 멀어지면 해제 → 메모리 절약
  • 텍스처 팝인 = 저해상도→고해상도 전환이 보이는 현상
  • Virtual Texture = 타일 단위로 더 세밀하게 관리
