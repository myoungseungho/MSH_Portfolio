Rename - 이름 변경의 힘

리팩토링 #6 기본 기법 실전 필수

가장 쉬우면서 가장 효과적인 리팩토링이 있다던데?

네, Rename(이름 변경)입니다. 마틴 파울러는 "좋은 이름은 시스템을 이해하는 데 드는 시간을 크게 줄여준다"고 했습니다.

🎯 왜 이름 변경이 그렇게 강력한가?

  • 코드를 읽는 시간이 쓰는 시간보다 10배 이상
  • 좋은 이름 = 주석 없이도 의도 전달
  • 잘못된 이름 = 버그의 원인 (오해 유발)
  • 다른 리팩토링의 기초 작업

우리 프로젝트에서 바꿔야 할 이름들은 어떤 게 있어?

실제 프로젝트의 이름 변경 후보들을 살펴봅시다:

현재 이름 개선된 이름 이유
i32 level 타입이 아닌 의미를 담아야
dwFlag characterStatus 무슨 Flag인지 알 수 없음
pPC playerCharacter 약어 풀어서 명확하게
temp damageMultiplier 임시변수도 역할을 가짐
Process() ProcessDamageCalculation() 무엇을 처리하는지 명시

실제로 어떻게 변경하면 되는 거야?

함수 이름 변경 예시를 봅시다:

❌ Before 불명확한 함수명 
// 뭘 하는 함수인지 알 수 없다
int CGamePC::Check(int type)
{
    if (type == 1)
        return m_i32Level >= 50;
    else if (type == 2)
        return m_i32Gold >= 10000;
    else if (type == 3)
        return m_bInParty;
    return 0;
}

// 사용하는 곳
if (pPC->Check(1)) {
    // 레벨 체크인지
    // 추측해야 함
}
✅ After 의도가 드러나는 함수명 
// 이름만 봐도 역할이 명확
bool CGamePC::CanEnterDungeon()
{
    return m_level >= 50;
}

bool CGamePC::HasEnoughGold(int required)
{
    return m_gold >= required;
}

bool CGamePC::IsInParty()
{
    return m_isInParty;
}

// 사용하는 곳
if (pPC->CanEnterDungeon()) {
    // 의미가 바로 보인다
}

변수 이름 변경 시 헝가리안 표기법은 어떻게 해?

우리 프로젝트는 헝가리안 표기법을 사용합니다. 완전히 제거하기보다 점진적으로 의미를 추가하는 전략을 씁니다:

점진적 개선 전략 
// 1단계: 기존 코드 (타입 접두어만 있음)
int m_i32Flag;
DWORD m_dwTime;
char* m_szName;

// 2단계: 의미를 추가 (타입 접두어 유지)
int m_i32CharacterState;      // Flag → CharacterState
DWORD m_dwLastSaveTime;       // Time → LastSaveTime
char* m_szCharacterName;      // Name → CharacterName

// 3단계: (선택적) 새 코드는 현대적 스타일
int characterState_;          // 밑줄 접미어 스타일
uint32_t lastSaveTime_;       // 명시적 타입명 사용

⚠️ 주의: 전면 교체는 위험

기존 코드의 헝가리안을 한꺼번에 제거하면 git diff가 폭발합니다. 수정하는 파일에서만 점진적으로 개선하세요.

안전하게 이름을 바꾸는 절차는?

  1. 1

    사용처 전체 검색

    Ctrl+Shift+F로 해당 이름이 쓰이는 모든 곳을 찾습니다. 문자열 안의 사용도 주의!

  2. 2

    IDE 리팩토링 기능 활용

    Visual Studio: Ctrl+R, Ctrl+R (Rename Symbol). 문자열 교체보다 안전합니다.

  3. 3

    컴파일 테스트

    이름 변경 후 빌드하여 누락된 곳이 없는지 확인합니다.

  4. 4

    작은 단위로 커밋

    "Rename pPC to playerCharacter in DamageCalc" 처럼 변경 내용을 명확히 기록합니다.

클래스/파일 이름은 어떻게 바꿔?

클래스와 파일 이름은 영향 범위가 크므로 더 신중해야 합니다:

클래스 이름 변경 예시 
// Before: 역할이 불명확
class CManager {
    void Process();      // 뭘 관리하고 뭘 처리하는지?
    void Execute();
};

// After: 책임이 명확
class CDungeonInstanceManager {
    void ProcessDungeonTick();
    void ExecuteMonsterSpawn();
};

📁 파일 이름 변경 체크리스트

  • 헤더 파일과 소스 파일 함께 변경
  • #include 경로 모두 수정
  • .vcxproj 파일에서 파일 참조 확인
  • SVN/Git에서 mv 명령으로 히스토리 유지

좋은 이름을 짓는 원칙이 있어?

✅ 좋은 이름의 특징

  • 의도를 드러낸다: CanEnterDungeon() (O) vs Check() (X)
  • 발음할 수 있다: generationTimestamp (O) vs genymdhms (X)
  • 검색 가능하다: MAX_PARTY_SIZE (O) vs 8 (X)
  • 한 개념에 한 단어: get/fetch/retrieve 중 하나만 일관되게

❌ 피해야 할 이름

  • 줄임말 남용: pcMgr, svrProc, msgHndlr
  • 숫자 구분: data1, data2, item3
  • 의미없는 접두어: thePlayer, aMonster
  • 인코딩 정보: phoneNumberString, nameArray

핵심 요약

📌 Rename 리팩토링 핵심

  • 가장 쉽고 가장 효과적인 리팩토링
  • 타입보다 의도와 역할을 이름에 담아라
  • IDE의 Rename 기능 사용 (Ctrl+R, R)
  • 헝가리안 표기법은 점진적으로 개선
  • 클래스/파일 변경 시 영향 범위 확인 필수
