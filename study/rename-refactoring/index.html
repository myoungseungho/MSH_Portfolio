Rename - 이름 변경의 힘

가장 쉬우면서 가장 효과적인 리팩토링

Part 1. 이름 바꾸기가 리팩토링이야?

이름만 바꾸는 게 무슨 리팩토링이야?

가장 쉬우면서 가장 효과적인 리팩토링이야!

마틴 파울러도 "좋은 이름은 시스템을 이해하는 데 드는 시간을 크게 줄여준다"고 했어.

왜 이름이 그렇게 중요할까?

코드는 쓰는 시간보다 읽는 시간이 10배 이상이야.

좋은 이름 = 주석 없이도 의도 전달
나쁜 이름 = 매번 "이게 뭐였지?" 찾아봐야 함
구체적으로 뭘 바꾸는 건데?

변수, 함수, 클래스, 파일 - 전부 대상이야.

Part 2. 우리 프로젝트에서 바꿀 것들

조선협객전 코드에서 예시 좀 보여줘

실제로 개선할 수 있는 이름들:

현재 이름 개선된 이름 이유
i32 level 타입이 아닌 의미를 담아야
dwFlag characterStatus 무슨 Flag인지 알 수 없음
pPC playerCharacter 약어 풀어서 명확하게
temp damageMultiplier 임시변수도 역할을 가짐
Process() ProcessDamageCalculation() 무엇을 처리하는지 명시
함수 이름 바꾸면 어떻게 달라져?

읽는 순간 의도가 바로 보여.

// ❌ Before - 뭘 체크하는지 알 수 없음 int CGamePC::Check(int type) { if (type == 1) return m_i32Level >= 50; else if (type == 2) return m_i32Gold >= 10000; else if (type == 3) return m_bInParty; return 0; } // 사용하는 곳 - 1이 뭐야? 추측해야 함 if (pPC->Check(1)) { ... } // ✅ After - 이름만 봐도 명확 bool CGamePC::CanEnterDungeon() { return m_level >= 50; } bool CGamePC::HasEnoughGold(int required) { return m_gold >= required; } bool CGamePC::IsInParty() { return m_isInParty; } // 사용하는 곳 - 의미가 바로 보임! if (pPC->CanEnterDungeon()) { ... }

Part 3. 헝가리안 표기법은 어떻게 해?

우리 코드에 m_i32, m_dw 이런 게 많은데?

한번에 다 바꾸면 diff가 폭발해.

점진적으로 의미를 추가하는 전략을 써.

// 1단계: 기존 코드 (타입 접두어만 있음) int m_i32Flag; DWORD m_dwTime; char* m_szName; // 2단계: 의미를 추가 (타입 접두어 유지) int m_i32CharacterState; // Flag → CharacterState DWORD m_dwLastSaveTime; // Time → LastSaveTime char* m_szCharacterName; // Name → CharacterName // 3단계: (선택) 새 코드는 현대적 스타일 int characterState_; uint32_t lastSaveTime_;
주의: 전면 교체는 위험

기존 코드의 헝가리안을 한꺼번에 제거하면 git diff가 엄청나게 커져.
수정하는 파일에서만 점진적으로 개선해.

Part 4. 안전하게 이름 바꾸는 법

막 바꾸다가 빌드 깨지면 어떡해?

IDE 리팩토링 기능을 써!

Visual Studio에서 이름 바꾸기

1. 바꿀 이름에 커서 놓기
2. Ctrl+R, Ctrl+R (Rename Symbol)
3. 새 이름 입력 → Enter

모든 사용처가 자동으로 함께 변경됨!
그래도 확인은 해야 하지 않아?

당연히. 이 순서를 따라:

// 안전한 Rename 절차 1️⃣ 사용처 전체 검색 (Ctrl+Shift+F) → 문자열 안에 쓰인 것도 주의! 2️⃣ IDE Rename 실행 (Ctrl+R, R) → 단순 치환보다 안전 3️⃣ 빌드 테스트 → 누락된 곳 없는지 확인 4️⃣ 작은 단위로 커밋 → "Rename pPC to playerCharacter in DamageCalc"

Part 5. 좋은 이름의 원칙

어떤 이름이 좋은 이름이야?

몇 가지 원칙이 있어:

✅ 좋은 이름의 특징

• 의도를 드러낸다: CanEnterDungeon() (O) vs Check() (X)
• 발음할 수 있다: generationTimestamp (O) vs genymdhms (X)
• 검색 가능하다: MAX_PARTY_SIZE (O) vs 8 (X)
• 한 개념에 한 단어: get/fetch/retrieve 중 하나만 일관되게
❌ 피해야 할 이름

• 줄임말 남용: pcMgr, svrProc, msgHndlr
• 숫자 구분: data1, data2, item3
• 의미없는 접두어: thePlayer, aMonster
• 타입 정보 중복: phoneNumberString, nameArray

핵심 정리: Rename 리팩토링

  • 가장 쉽고 가장 효과적인 리팩토링
  • 타입보다 의도와 역할을 이름에 담아라
  • IDE의 Rename 기능 사용 (Ctrl+R, R)
  • 헝가리안 표기법은 점진적으로 개선
  • 한 개념에 한 단어로 일관되게
