Sparse Texture / Tiled Resource

GPU 가상 메모리로 거대 텍스처 다루기

Part 1. 일반 텍스처의 한계

왜 거대한 텍스처가 문제야?

GPU 메모리는 모든 텍스처를 한꺼번에 올려야 했습니다:

일반 텍스처의 문제: ┌────────────────────────────────────────────────────────────┐ │ │ │ 게임에서 16K 지형 텍스처 사용: │ │ 16384 × 16384 × 4 bytes = 1GB per texture │ │ │ │ 실제로 화면에 보이는 영역: │ │ ┌────────────────────────────────────────┐ │ │ │ 전체 지형 텍스처 (16K × 16K) │ │ │ │ │ │ │ │ ┌────┐ │ │ │ │ │ 화면│ ← 실제 보이는 건 │ │ │ │ │ 영역│ 전체의 1% 미만! │ │ │ │ └────┘ │ │ │ │ │ │ │ └────────────────────────────────────────┘ │ │ │ │ 문제: 1%만 보는데 100%를 메모리에 올림 │ │ → GPU 메모리 낭비, 로딩 시간 증가 │ │ │ └────────────────────────────────────────────────────────────┘

Part 2. Sparse Texture 개념

Sparse Texture가 어떻게 해결해?

OS 가상 메모리와 같은 개념을 GPU에 적용합니다:

Sparse Texture (= Tiled Resource = Mega Texture): ┌────────────────────────────────────────────────────────────┐ │ │ │ 핵심 아이디어: 필요한 타일만 메모리에 상주 │ │ │ │ 가상 텍스처 (논리적) 물리 메모리 (실제) │ │ ┌──┬──┬──┬──┬──┬──┐ ┌──────────────┐ │ │ │T1│T2│T3│T4│T5│T6│ │ Tile Pool │ │ │ ├──┼──┼──┼──┼──┼──┤ │ │ │ │ │T7│▓▓│▓▓│T10│T11│T12│ │ ┌──┐ ┌──┐ │ │ │ ├──┼──┼──┼──┼──┼──┤ │ │T8│ │T9│ │ │ │ │T13│T14│T15│T16│T17│T18│ │ └──┘ └──┘ │ │ │ └──┴──┴──┴──┴──┴──┘ │ │ │ │ ↑ ↑ └──────────────┘ │ │ │ │ ↑ │ │ └───┴── 매핑됨 ───────────────┘ │ │ │ │ ▓▓ = Resident (메모리에 있음) │ │ T = Non-resident (필요 시 로드) │ │ │ │ 결과: 1GB 가상 텍스처를 64MB 물리 메모리로 사용 가능! │ │ │ └────────────────────────────────────────────────────────────┘
OS 가상 메모리랑 뭐가 다른 거야?

원리는 같지만 GPU 전용으로 최적화되어 있습니다:

비교: OS 가상 메모리 vs GPU Sparse Texture ┌────────────────────────┬────────────────────────┐ │ OS 가상 메모리 │ GPU Sparse Texture │ ├────────────────────────┼────────────────────────┤ │ 페이지 단위: 4KB │ 타일 단위: 64KB (일반) │ │ Page Fault → OS 핸들링 │ Miss → Fallback mip │ │ 디스크 스왑 │ 스트리밍 시스템 연동 │ │ CPU 접근 │ GPU 셰이더 접근 │ │ 동기적 (느림) │ 비동기적 (매끄러움) │ └────────────────────────┴────────────────────────┘ 핵심 차이: Page Fault 대신 저해상도 Fallback → 타일이 없으면 상위 mip 사용 (끊김 없음)

Part 3. 타일 매핑 구조

타일 매핑은 어떻게 작동해?

Page Table 같은 구조로 가상→물리 주소를 변환합니다:

Sparse Texture 메모리 구조: ┌────────────────────────────────────────────────────────────┐ │ │ │ 1. 가상 텍스처 (Virtual Texture) │ │ - 논리적 크기: 16K × 16K │ │ - 실제 메모리 할당 없음 │ │ │ │ 2. 타일 매핑 테이블 (Page Table) │ │ ┌───────────────────────────────────────────┐ │ │ │ Virtual Tile │ Physical Tile │ Resident │ │ │ ├───────────────┼───────────────┼──────────┤ │ │ │ (0, 0, mip0) │ Pool[42] │ ✓ │ │ │ │ (1, 0, mip0) │ Pool[17] │ ✓ │ │ │ │ (2, 0, mip0) │ NULL │ ✗ │ │ │ │ (0, 0, mip1) │ Pool[3] │ ✓ │ (fallback) │ │ └───────────────┴───────────────┴──────────┘ │ │ │ │ 3. 물리 타일 풀 (Tile Pool) │ │ - 고정 크기 메모리 (예: 256MB) │ │ - LRU로 타일 교체 │ │ - 실제 텍스처 데이터 저장 │ │ │ └────────────────────────────────────────────────────────────┘
// DirectX 12 Tiled Resource 생성 // 1. Reserved Resource 생성 (메모리 없이 주소만) D3D12_RESOURCE_DESC desc = {}; desc.Dimension = D3D12_RESOURCE_DIMENSION_TEXTURE2D; desc.Width = 16384; desc.Height = 16384; desc.Format = DXGI_FORMAT_BC7_UNORM; desc.Layout = D3D12_TEXTURE_LAYOUT_64KB_UNDEFINED_SWIZZLE; device->CreateReservedResource( &desc, D3D12_RESOURCE_STATE_COMMON, nullptr, IID_PPV_ARGS(&sparseTexture) ); // 2. Heap 생성 (실제 물리 메모리 풀) D3D12_HEAP_DESC heapDesc = {}; heapDesc.SizeInBytes = 256 * 1024 * 1024; // 256MB 풀 heapDesc.Properties.Type = D3D12_HEAP_TYPE_DEFAULT; heapDesc.Flags = D3D12_HEAP_FLAG_DENY_BUFFERS | D3D12_HEAP_FLAG_DENY_RT_DS_TEXTURES; device->CreateHeap(&heapDesc, IID_PPV_ARGS(&tilePool)); // 3. 타일 매핑 업데이트 D3D12_TILED_RESOURCE_COORDINATE coord = { tileX, tileY, 0, subresource }; D3D12_TILE_REGION_SIZE regionSize = { 1, FALSE, 0, 0, 0 }; D3D12_TILE_RANGE_FLAGS flags = D3D12_TILE_RANGE_FLAG_NONE; UINT heapOffset = poolTileIndex; commandQueue->UpdateTileMappings( sparseTexture, 1, &coord, ®ionSize, tilePool, 1, &flags, &heapOffset, &tileCount, D3D12_TILE_MAPPING_FLAG_NONE );

Part 4. Residency 관리

어떤 타일을 메모리에 둘지 어떻게 결정해?

Feedback Buffer로 GPU가 어떤 타일을 사용하는지 알려줍니다:

Feedback 기반 Residency 관리: ┌────────────────────────────────────────────────────────────┐ │ │ │ Frame N: │ │ ┌─────────────────────────────────────────────────────┐ │ │ │ GPU 렌더링 중... │ │ │ │ │ │ │ │ 셰이더에서 텍스처 샘플링 시: │ │ │ │ → (tileX, tileY, mipLevel) 기록 │ │ │ │ │ │ │ │ Feedback Buffer: │ │ │ │ ┌────────────────────────────────────────────┐ │ │ │ │ │ Tile(3,2,mip0), Tile(3,3,mip0), Tile(4,2,mip0)│ │ │ │ │ │ Tile(1,1,mip1), Tile(2,1,mip1)... │ │ │ │ │ └────────────────────────────────────────────┘ │ │ │ └─────────────────────────────────────────────────────┘ │ │ │ │ │ ▼ │ │ Frame N+1: │ │ ┌─────────────────────────────────────────────────────┐ │ │ │ CPU가 Feedback 분석 │ │ │ │ → 필요한 타일 식별 │ │ │ │ → 스트리밍 요청 생성 │ │ │ │ → 타일 매핑 업데이트 │ │ │ └─────────────────────────────────────────────────────┘ │ │ │ │ 결과: GPU가 실제로 보는 것만 로드 │ │ │ └────────────────────────────────────────────────────────────┘
// Sampler Feedback (DX12 Ultimate) // 1. Feedback Map 생성 D3D12_RESOURCE_DESC feedbackDesc = {}; feedbackDesc.Format = DXGI_FORMAT_SAMPLER_FEEDBACK_MIN_MIP_OPAQUE; feedbackDesc.Width = sparseTextureWidth / 64; // 타일 단위 feedbackDesc.Height = sparseTextureHeight / 64; device->CreateCommittedResource(..., &feedbackMap); // 2. 셰이더에서 Feedback 기록 // HLSL: Texture2D SparseTexture : register(t0); FeedbackTexture2D FeedbackMap : register(u0); float4 PSMain(float2 uv : TEXCOORD) : SV_Target { // 자동으로 사용된 타일/mip 기록 FeedbackMap.WriteSamplerFeedback(SparseTexture, Sampler, uv); return SparseTexture.Sample(Sampler, uv); } // 3. CPU에서 Feedback 읽기 context->ResolveSubresource(feedbackReadback, 0, feedbackMap, 0, ...); // → 어떤 타일이 필요한지 분석

Part 5. Virtual Texture와의 관계

Virtual Texture랑 뭐가 달라?

Sparse Texture는 하드웨어 기능, Virtual Texture는 소프트웨어 기법입니다:

Sparse Texture vs Virtual Texture: ┌────────────────────────────────────────────────────────────┐ │ │ │ Sparse Texture (Hardware) │ │ ──────────────────────────────────────────────────────── │ │ - GPU 하드웨어 직접 지원 │ │ - API: DX12 Tiled Resources, Vulkan Sparse Binding │ │ - 타일 단위 메모리 매핑 │ │ - 모든 텍스처 타입 지원 │ │ │ │ Virtual Texture (Software) = Mega Texture │ │ ──────────────────────────────────────────────────────── │ │ - 소프트웨어 구현 (Sparse Texture 위에 구축 가능) │ │ - Indirection Table + Physical Cache │ │ - id Tech 5 (RAGE)에서 시작 │ │ - UE5: Runtime Virtual Texture │ │ │ │ 조합 사용: │ │ ┌─────────────────────────────────────────────────────┐ │ │ │ Virtual Texture 시스템 │ │ │ │ ├─ Feedback Rendering │ │ │ │ ├─ Indirection Table │ │ │ │ └─ Physical Cache ← Sparse Texture로 구현 │ │ │ └─────────────────────────────────────────────────────┘ │ │ │ └────────────────────────────────────────────────────────────┘

Part 7. 실제 활용 사례

어디에 주로 써?
Sparse Texture 활용 사례: ┌────────────────────────────────────────────────────────────┐ │ │ │ 1. 오픈월드 지형 │ │ - 거대한 지형 텍스처 (16K+ 해상도) │ │ - 플레이어 주변만 고해상도 로드 │ │ │ │ 2. 스트리밍 섀도우 맵 │ │ - Virtual Shadow Maps (UE5) │ │ - 16K 가상 해상도, 필요한 타일만 렌더링 │ │ │ │ 3. 대규모 텍스처 아틀라스 │ │ - UI 아틀라스 │ │ - 데칼/스프레이 시스템 │ │ │ │ 4. 프로시저럴 텍스처 │ │ - 런타임 생성 텍스처 │ │ - 무한 지형 시스템 │ │ │ │ 공통점: 거대하지만 전체가 동시에 필요하지 않은 경우 │ │ │ └────────────────────────────────────────────────────────────┘

핵심 정리

  • Sparse Texture는 GPU 가상 메모리 - 필요한 타일만 물리 메모리에 매핑
  • 타일 풀에서 LRU로 타일 교체, 메모리 사용량 고정
  • Feedback Buffer로 GPU가 사용하는 타일 추적
  • 타일 미로드 시 Fallback mip으로 끊김 없이 렌더링
  • DX12 Tiled Resources, Vulkan Sparse Binding
  • Virtual Texture는 소프트웨어 구현, Sparse Texture는 하드웨어
  • 오픈월드 지형, 섀도우 맵 등 거대 텍스처에 필수
