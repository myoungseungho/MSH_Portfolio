크로스 플랫폼 빌드: CMake

Windows, Linux, macOS — 하나의 소스코드로 세 플랫폼에서 빌드하는 방법

CMake = Cross-platform Make

Make = 빌드 도구. Makefile에 빌드 규칙을 적어서 자동 빌드

Cross-platform = 여러 OS에서 동작하는

CMake = 빌드 시스템을 생성하는 빌드 시스템 (메타 빌드 시스템)

CMake 자체가 빌드를 하는 게 아니라, 각 플랫폼에 맞는 빌드 파일(Visual Studio .sln, Makefile, Ninja 등)을 생성해준다.

Part 1. 빌드가 뭔데? — 소스코드 → 실행 파일

빌드가 뭐야?

소스코드(.cpp, .h)를 컴파일하고 링크해서 실행 가능한 파일(.exe, ELF)을 만드는 과정.

빌드 시스템은 왜 필요해?

파일이 1개면 g++ main.cpp하면 되지만, 파일이 수백 개면? 어떤 파일이 변경됐는지 추적하고, 의존성 순서대로 컴파일하고, 라이브러리 링크하는 걸 자동으로 해주는 게 빌드 시스템.

파일 1개: main.cpp → [g++ main.cpp] → a.out ✓ 파일 수백 개: main.cpp ─┐ net.cpp ─┤ db.cpp ─┼→ [빌드 시스템] → 의존성 분석 → 순서 결정 → 컴파일 → 링크 → server.exe ✓ ui.cpp ─┤ ...200개 ─┘ ❌ 수동으로 하면? g++ -c main.cpp -o main.o g++ -c net.cpp -o net.o g++ -c db.cpp -o db.o ... (200번 반복) g++ main.o net.o db.o ... -o server ← 지옥

Part 2. 왜 OS마다 빌드가 달라? — Windows(MSVC) vs Linux(GCC) vs macOS(Clang)

같은 C++ 소스인데 왜 OS마다 빌드 방법이 달라?

OS마다 기본 컴파일러, 빌드 도구, 실행 파일 형식이 다르기 때문.

Windows Linux macOS
컴파일러 MSVC (cl.exe) GCC (g++) Clang (clang++)
빌드 도구 MSBuild (.sln) Make (Makefile) Xcode / Make
실행 형식 .exe (PE) ELF Mach-O
라이브러리 .lib / .dll .a / .so .a / .dylib
그러면 OS마다 빌드 스크립트를 따로 만들어야 해?

CMake 없이는 그래야 했다. Windows용 .sln, Linux용 Makefile, macOS용 Xcode 프로젝트를 각각 관리해야 했음. → 유지보수 지옥

Part 3. CMake가 뭐야? — 빌드 시스템의 빌드 시스템

CMake가 뭐야?

CMakeLists.txt 하나 작성하면, CMake가 각 플랫폼에 맞는 빌드 파일을 자동 생성해주는 메타 빌드 시스템.

CMake 워크플로우: ┌──────────────────┐ │ CMakeLists.txt │ ← 개발자가 작성하는 유일한 파일 └────────┬─────────┘ │ [ cmake ] ← CMake가 변환 │ ┌──────────────────┼──────────────────┐ ▼ ▼ ▼ ┌────────────┐ ┌────────────┐ ┌──────────────┐ │ .sln │ │ Makefile │ │ Xcode proj │ │ (Windows) │ │ (Linux) │ │ (macOS) │ └────────────┘ └────────────┘ └──────────────┘ │ │ │ [MSBuild] [make] [xcodebuild] │ │ │ ▼ ▼ ▼ server.exe server server (Mach-O)
왜 "빌드 시스템의 빌드 시스템"이야?

CMake 자체는 빌드를 안 해. Visual Studio, Make, Ninja 같은 실제 빌드 도구가 빌드를 수행. CMake는 이 도구들이 이해할 수 있는 프로젝트 파일을 생성하는 역할.

CMake의 핵심 가치 = "CMakeLists.txt 하나로 모든 플랫폼에서 빌드"

Part 4. CMake 기본 사용법 — CMakeLists.txt 실제 예시

CMakeLists.txt는 어떻게 생겼어?

기본 예시를 보자. 게임 서버 프로젝트를 CMake로 구성하면 이렇게 된다:

cmake_minimum_required(VERSION 3.20) project(GameServer LANGUAGES CXX) set(CMAKE_CXX_STANDARD 17) set(CMAKE_CXX_STANDARD_REQUIRED ON) # 소스 파일 추가 add_executable(game_server src/main.cpp src/network/socket.cpp src/game/world.cpp ) # 헤더 경로 target_include_directories(game_server PRIVATE src/) # 외부 라이브러리 링크 find_package(Threads REQUIRED) target_link_libraries(game_server PRIVATE Threads::Threads) # OS별 분기 if(WIN32) target_link_libraries(game_server PRIVATE ws2_32) elseif(UNIX) target_link_libraries(game_server PRIVATE pthread) endif()
빌드는 어떻게 해?

2단계: Configure → Build

# 1. Configure (빌드 파일 생성) cmake -B build -G "Visual Studio 17 2022" # Windows cmake -B build -G "Unix Makefiles" # Linux cmake -B build -G "Ninja" # 범용 (가장 빠름) # 2. Build (실제 컴파일) cmake --build build --config Release

Part 5. 크로스 플랫폼이 왜 어려워? — OS별 API 차이

CMake 쓰면 크로스 플랫폼 완성이야?

빌드는 해결되지만, 코드 자체가 OS에 의존하면 여전히 안 됨.

// Windows 전용 #ifdef _WIN32 #include <windows.h> HANDLE h = CreateThread(...); SOCKET s = socket(AF_INET, ...); WSAStartup(MAKEWORD(2,2), &wsaData); #endif // Linux 전용 #ifdef __linux__ #include <pthread.h> pthread_t t; pthread_create(&t, NULL, func, NULL); int s = socket(AF_INET, ...); // WSAStartup 불필요 #endif
조건부 컴파일(#ifdef)을 많이 쓰면 되는 거야?

#ifdef가 너무 많으면 코드가 난잡해짐. 더 나은 방법은 추상 레이어를 만드는 것.

// platform.h - 추상 인터페이스 Thread createThread(Function func); Socket createSocket(int family, int type); // platform_win32.cpp - Windows 구현 // platform_linux.cpp - Linux 구현

CMake가 빌드를 통일하고, 추상 레이어가 코드를 통일한다

Part 6. WSL, Docker, 가상화 — Windows에서 Linux를 쓰는 방법들

Windows에서 개발하는데 Linux 빌드를 테스트하고 싶으면?

세 가지 방법이 있음:

방법 설명 장점 단점
WSL2 Windows 안에 Linux 커널 실행 가볍고 빠름, VS Code 연동 Windows 리소스 공유
Docker 컨테이너 기반 격리 환경 재현성 최고, CI/CD 연동 학습 비용
VM VirtualBox/Hyper-V 가상머신 완전한 OS 격리 무거움, 느림
게임 서버 CI/CD에서는 뭘 많이 써?

Docker + GitHub Actions (또는 Jenkins). Dockerfile에 빌드 환경 정의해두면 어디서든 동일한 빌드 재현 가능.

FROM ubuntu:22.04 RUN apt-get update && apt-get install -y cmake g++ ninja-build COPY . /app WORKDIR /app RUN cmake -B build -G Ninja && cmake --build build

핵심 정리

  • 빌드 = 소스코드를 실행 파일로 변환하는 과정 (컴파일 + 링크)
  • OS마다 컴파일러(MSVC/GCC/Clang), 빌드 도구(.sln/Makefile), 실행 형식(PE/ELF/Mach-O)이 다르다
  • CMake = 빌드 시스템의 빌드 시스템. CMakeLists.txt 하나로 모든 플랫폼 빌드 파일 생성
  • CMake는 빌드를 통일하지만, OS 의존 코드는 추상 레이어로 분리해야 한다
  • WSL2, Docker, VM으로 Windows에서 Linux 빌드를 테스트할 수 있다
  • 게임 서버 CI/CD는 Docker + 자동화 빌드가 주류
