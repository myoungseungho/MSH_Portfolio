Inline Method

메서드 인라인 - 불필요한 간접 계층 제거

Part 1. 인라인이 뭐야?

Extract Method 반대가 뭐야?

Inline Method야.

메서드 본문을 호출하는 곳에 직접 넣고, 그 메서드를 삭제하는 거야.

왜 메서드를 없애? Extract가 좋다며?

둘 다 도구야. 상황에 맞게 쓰는 거지.

때로는 메서드가 오히려 코드를 복잡하게 만들어.

불필요한 중간 관리자 비유

부장에게 보고 → 부장이 그대로 팀장에게 전달 → 팀장이 처리

부장이 아무것도 안 하고 그냥 전달만 한다면?
직접 팀장에게 가는 게 빨라.

Part 2. 언제 인라인해?

어떤 메서드를 인라인해야 해?

이런 경우들:

인라인 대상

1. 이름보다 본문이 명확할 때 - IsEmpty()가 count == 0이면, 그냥 count == 0 쓰는 게 나을 수도
2. 위임만 하는 메서드 - 다른 메서드 그냥 호출만 하고 끝
3. 리팩토링 중간 단계 - 일단 인라인해서 전체 그림 본 뒤 다시 추출
진짜 그냥 없애도 돼?

기준은 가독성이야.

"이 코드를 처음 보는 동료가 더 쉽게 이해할 수 있는 형태는?"

Part 3. 인라인하면 안 되는 경우

인라인하면 안 되는 건?

절대 인라인하면 안 되는 경우가 있어:

인라인 금지

1. 여러 곳에서 호출 - 3군데에서 쓰면 코드 3번 복사됨
2. 재귀 메서드 - 자기 자신 호출하면 인라인 불가
3. 복잡한 로직 - 10줄짜리 계산을 인라인하면 호출 쪽이 엉망
4. 의미 있는 추상화 - CalculateDamage() 같은 중요 개념은 유지
그럼 판단 기준이 뭐야?

한 곳에서만 쓰이고, 본문이 단순하면 인라인 고려.

여러 곳에서 쓰이거나, 복잡하면 유지.

Part 4. 절차

인라인 어떻게 해?

단계별로:

Inline Method 절차

1단계: 호출 위치 확인 - 몇 군데에서 호출하나?
2단계: 각 호출부에 본문 복사 - 파라미터 있으면 치환
3단계: 테스트
4단계: 원래 메서드 삭제
IDE가 해주는 거 있어?

Visual Studio: Ctrl+R, Ctrl+I

자동으로 모든 호출부 찾아서 치환해줘.

핵심 정리: Inline Method

  • 정의: 메서드 본문을 호출부에 넣고 삭제
  • 대상: 이름보다 본문이 명확할 때
  • 금지: 여러 곳에서 호출되는 메서드
  • 기준: 가독성이 좋아지는가?
  • 균형: Extract와 상황에 맞게 선택
