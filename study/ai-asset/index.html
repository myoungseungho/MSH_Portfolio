AI 스킬의 90%가 0원이 된 이유

52년차 개발자가 말하는 "천배 가치의 10%"와 배민의 AI 자산화 전략

Part 1. AI 자산화가 뭐야?

회사에서 AI 잘 쓰는 사람 한 명 있으면 됐지, 왜 자산화?

그 사람이 퇴사하면?

개인의 경험에만 머물러 있으면, 전문성이나 활용 방법이 제대로 전파되기 어려워.

AI를 잘 쓰는 건 개인 능력이지만, 자산화는 팀 전체가 잘 쓸 수 있게 만드는 거야.

자산화를 하면 뭐가 좋아?
  • 인턴도 2~3년차 수준으로 - 에센스가 자산화되면 신입도 빠르게 성장
  • 일관된 결과물 - 100개든 1000개든 한 사람이 만든 것 같은 퀄리티
  • 생산성 폭발 - 손으로 깎던 3D 디자인이 몇 분으로 단축
핵심

개인 경험 → 팀 자산

AI 활용의 핵심은 자산화다

Part 2. 배민은 어떻게 디자인을 자산화했을까?

배민의 3D 디자인은 어떻게 만들었어?

손으로 깎았어.

스컬프(조각칼)로 점토를 깎아서 캐릭터를 만들고, 사진 찍어서 포토샵으로 컬러 입히고...

한 땀 한 땀. 엄청나게 오래 걸렸지.

그럼 AI로 어떻게 바뀌었어?

에센스를 뽑았어.

Before: 손으로 깎기 → 사진 → 포토샵 → 컬러 → 그림자 = 며칠 After: 에센스 참조 → "오토바이 그려줘" → 완성 = 몇 분
에센스가 뭐야?

군더더기를 다 빼고 핵심만 남긴 것.

배민 디자인의 에센스:

  • 스컬프로 깎은듯한 느낌 (명도 대비)
  • 민트 컬러 (브랜드 색상)
  • 부드러운 곡선

이 에센스를 하나의 이미지로 만들어서 스타일 참조로 넣으면?

→ "배달 스쿠터 그려줘" 한 문장으로 배민 스타일 완성!

어떻게 에센스를 뽑아?

디자이너들이 잘하는 것: 본질을 뽑는 것

원본 디자인 (복잡) ↓ 군더더기 제거 ↓ 핵심 에센스만 남김 (단순) ↓ AI 스타일 참조로 사용

실험을 계속 해봐. 에센스를 어떻게 나누면 더 잘 나오는지.

🏪 비유: 벽돌 깎기

벽돌(원재료)을 깎아서 → 에센스(조각 완성품) → 그걸 찍어내기(AI 생성)

한 번 에센스를 잘 만들어 놓으면, 나머지는 쉬워진다.

핵심

디자인 자산화 = 에센스를 뽑아서 재사용 가능하게 만드는 것

Part 3. 프롬프트 쓰기 전에 해야 할 것

AI한테 뭔가 시키는데 잘 안 돼. 뭐가 문제야?

프롬프트 쓰기 전에 준비를 안 했어.

좋은 프롬프트를 쓰려면, 프리 프롬프팅(Pre-Prompting)이 필요해.

프리 프롬프팅이 뭐야?

프롬프트 쓰기 전에 하는 3단계 준비.

앤트로픽 공식 문서에서 "강력히 권장한다"라고 강조한 부분이야.

프리 프롬프팅 3단계 1. 명확한 성공 기준 정의 → "잘됐다"를 어떻게 알 수 있지? 2. 경험적 테스트 환경 세팅 → 반복 가능하게 만들기 3. 개선할 첫 번째 초안 프롬프트 → 괜찮은 시작점 만들기
1단계: 성공 기준이 왜 중요해?

램프가 없으면 진을 컨트롤 못 해.

🧞 비유: 알라딘의 램프

AI = 예측 불가능한 진

성공 기준 = 램프 (진을 컨트롤하는 도구)

램프 안에 집어넣으면 → 완전히 컨트롤 가능

성공 기준이 명확하지 않으면?

  • 계속 대화만 길어짐
  • "이거 맞아?" "저거 맞아?" 끝없는 핑퐁
  • 감정 싸움으로 번짐 ("똑바로 해!!!")
2단계: 테스트 환경은 왜 필요해?

엔지니어링은 반복 가능해야 해.

프롬프트도 버전 관리해. Git으로.

프롬프트 버전 관리 예시 v1.0: "코드 리뷰 해줘" v1.1: "코드 리뷰 해줘 (버그 찾기 중심)" v1.2: "코드 리뷰 해줘 (보안 취약점 중심)" ... → Git으로 관리하면 "어떤 프롬프트가 제일 잘 됐지?" 추적 가능
3단계: 첫 번째 초안은 뭐야?

첫 프롬프트가 별로면, 대화가 오염돼.

"좀 더 구체적으로" "아니 그게 아니라" 이런 대화 반복되면?

→ 불필요한 맥락이 쌓여서 성능 떨어짐

그래서 "꽤 괜찮은" 첫 초안을 만드는 게 중요해.

핵심

프리 프롬프팅 = 프롬프트 쓰기 전 준비

① 성공 기준 ② 테스트 환경 ③ 괜찮은 초안

켄트 벡이 누구야?

TDD(테스트 주도 개발)를 만든 전설.

  • 전 세계 개발자들이 다 아는 사람
  • 지금이 개발 인생에서 제일 재밌다고 함 (AI 덕분에)
그 사람이 한 충격 발언이 뭐야?

나머지 10%는 천배의 가치를 얻게 됐다."

AI 시대에 대부분 스킬은 가치가 사라졌다.

하지만 어떤 스킬은 천배로 뛰었다.

그럼 천배가 된 10%는 뭐야?

켄트 벡이 말한 3가지:

순서 에센스 설명
1 야심찬 비전 좋은 문제를 정의하는 능력. AI로 어디까지 할 수 있는지 한계 두지 마.
2 이정표 설정 복잡한 문제를 작게 쪼개서 중간 목표를 만드는 능력. 명확한 성공 기준.
3 복잡성 관리 큰 그림을 보면서 설계를 추적하고 복잡성을 통제하는 능력.
결국 뭐가 중요한 거야?

AI는 How를 해결해 줘. 하지만 What은 못 해.

AI 시대의 가치 변화 0원이 된 것: - 코드 짜는 스킬 (How) - 문법 외우는 것 - 반복 작업 천배가 된 것: - 문제를 정의하는 능력 (What) - 큰 그림을 보는 능력 - 이정표를 설정하는 능력
핵심

How 전문가는 AI로 대체됨

What 정의자는 대체 안 됨

Part 5. 테스트 = 램프

AI한테 코드 짜라고 했는데 자꾸 이상하게 짜. 화날 때 있지?

엄청 화나지.

  • "똑바로 해!!!" 느낌표 100개 찍기
  • "이거 안 하면 킬(kill) 해버린다" 영어권 표현
  • 감정 싸움으로 번짐
어떻게 해결해?

불변 테스트를 만들어.

"불변(Invariant)" = AI가 절대 수정 못하게 하는 것

불변 테스트 구조 테스트 명세 (불변) ← AI가 이건 못 건드림 ↓ 구현 (가변) ← AI가 이건 알아서 작성 내 의도 = 테스트 명세 AI 역할 = 그 의도에 맞춰 구현만
테스트가 자산이 되는 이유는?

켄트 벡의 말:

"테스트는 의도치 않은 유용한 부산물이다."

  • 원래는 내가 개발할 때 피드백 받으려고 작성
  • 근데 작성하고 나니 → 미래의 나와 동료들에게 자산으로 남음
  • 레거시 코드도 테스트만 있으면 두려움 없이 수정 가능
배민에서는 테스트를 어떻게 자산화했어?

테스트 템플릿을 만들었어.

테스트 자산화 프로세스 1. 플레이그라운드(템플릿) 만들기 → 일관된 컨벤션으로 테스트 구조 세팅 2. AI한테 내부 구현만 시키기 → 템플릿 안에서 AI가 테스트 코드 작성 3. Git으로 버전 관리 → 팀 전체가 공유 결과: 레거시 코드에 테스트 추가 → 안전하게 수정 가능
핵심

테스트 = 램프 (AI를 컨트롤하는 도구)

테스트 자체도 자산이 된다

Part 6. 버그와 싸우는 5단계 이정표

버그 나면 어떻게 해?

주니어: "뭔가 안 돼요..." (당황)

시니어: 5단계 이정표를 따라 차분하게 해결

디버깅 5단계가 뭐야?
디버깅 5단계 이정표 1️⃣ 문제를 한 문장으로 정의 ❌ "쿠폰이 이상해요" ✅ "쿠폰 로직에 따른 금액 계산 결과가 정확하지 않다" 2️⃣ 올바른 동작 정의 (Given-When-Then) Given: 조건 (회원 등급이 VIP일 때) When: 이벤트 (10% 쿠폰 적용) Then: 결과 (최종 금액이 X원이어야 함) 3️⃣ 최소 재현 환경 구축 전체 프로세스 X → 문제 함수만 떼서 테스트 4️⃣ 원인 옵션 나열 "이럴 수도 있고, 저럴 수도 있고..." AI한테 물어봐도 됨 5️⃣ 하나씩 검증 옵션들을 하나씩 테스트하면서 진짜 원인 찾기
이걸 어떻게 자산화해?

클로드 스킬(Claude Skills)로 만들어.

디버깅 스킬 자산화 1. 디버깅 5단계를 스킬로 작성 2. Git으로 팀 공유 3. 누구나 "/debug" 명령어로 사용 4. 더 좋은 방법 발견하면 → 스킬 업데이트 결과: 주니어도 시니어처럼 디버깅 가능
🎮 비유: 게임 장착템

스킬 = 게임 캐릭터의 장착템

디버깅 스킬을 장착하면 → 누구나 디버깅 능력 +100

핵심

이정표를 자산화하면 진통제가 된다

비타민(먹으면 좋은 것) X → 타이레놀(필요하면 찾게 되는 것) O

Part 7. 자산화 어떻게 해?

회사에서 자산화 하려면 뭐가 필요해?
단계 방법
1. 에센스 뽑기 잘하는 사람의 머릿속 들여다보기 (인터뷰, 관찰)
2. 프롬프트화 에센스를 프롬프트/스킬로 작성
3. Git 관리 버전 관리로 개선 추적
4. 팀 공유 챔피언이 주도해서 전파
5. 중앙화 플랫폼/허브로 중복 제거
자산화도 레거시가 될 수 있잖아. 어떻게 해?

수다를 AI로 자동 문서화.

레거시 방지 자동화 1. 팀 미팅/수다 → TTS(음성 → 텍스트) 2. AI 에이전트가 에센스 추출 3. 자동으로 문서화 + Git 업데이트 4. 계속 최신화 우리끼리 수다만 떨면 → 알아서 자산이 됨

예시: 노션 AI, 슬랙 봇, 디스코드 봇

대기업은 어떻게 해?

자체 AI 플랫폼을 만들어.

예: GS 미소, SK AI 플랫폼

  • 사내 구성원 누구나 사용
  • 사용 기록이 자동으로 DB에 쌓임
  • 반복 패턴 추출 → 자산화

📌 총정리: AI 자산화

1. AI 자산화란?

  • 개인 경험 → 팀 자산 전환
  • 인턴도 2~3년차 수준으로 만드는 힘
  • 일관된 퀄리티, 생산성 폭발

2. 배민의 에센스 추출

손으로 깎기 (며칠) → 에센스 뽑기 (한 번만) → AI 생성 (몇 분) 에센스 = 군더더기 빼고 핵심만 스타일 참조로 넣으면 → 일관된 결과물

3. 프리 프롬프팅 3단계

  • ① 명확한 성공 기준 - 램프로 진을 컨트롤
  • ② 테스트 환경 - 버전 관리로 반복 가능하게
  • ③ 괜찮은 초안 - 첫 프롬프트가 중요

4. 켄트 벡의 천배 가치

90% 스킬 = 0원 (How는 AI가 대체) 10% 스킬 = 천배 (What은 대체 불가) 천배 가치의 에센스: ① 야심찬 비전 (좋은 문제 정의) ② 이정표 설정 (명확한 성공 기준) ③ 복잡성 관리 (큰 그림 보기)

5. 테스트 = 램프

  • 불변 테스트 - AI가 수정 못하게
  • 테스트 = 미래의 나와 동료를 위한 자산
  • 템플릿 만들어서 AI한테 내부 구현만 시키기

6. 디버깅 5단계 이정표

1. 문제를 한 문장으로 2. 올바른 동작 정의 (Given-When-Then) 3. 최소 재현 환경 4. 원인 옵션 나열 5. 하나씩 검증 → 클로드 스킬로 만들면 누구나 사용 가능

7. 자산화 실전

  • 에센스 뽑기 - 잘하는 사람 인터뷰
  • 프롬프트화 - 스킬/템플릿으로
  • Git 관리 - 버전 관리 + 팀 공유
  • 자동화 - 수다 → AI → 문서화

마지막 조언

  • 프리 프롬프팅부터 시작하자
  • 이정표를 자산화하면 진통제가 된다
  • 자산화도 AI로 자동화하자
