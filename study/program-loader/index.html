프로그램이 실행되면 메모리에 어떻게 올라가는 걸까?

로더(Loader)의 역할과 실행 파일 로딩 과정

Part 1. 더블클릭하면 무슨 일이?

게임 아이콘 더블클릭하면 어떤 일이 일어나?

단순해 보이지만, OS 내부에서는 복잡한 로딩 과정이 일어나!

더블클릭 -> 게임 실행까지: +------------------------------------------------------------------+ | | | [게임.exe] 더블클릭 | | | | | v | | 1. Shell (탐색기) -> CreateProcess() 호출 | | | | | v | | 2. 커널 -> 새 프로세스 구조체 생성 | | | (PCB, 페이지 테이블, 핸들 테이블) | | | | | v | | 3. 로더 (ntdll.dll) -> EXE 파일 파싱 | | | - PE 헤더 읽기 | | | - 섹션들을 메모리에 매핑 | | | - Import 테이블 처리 (DLL 로드) | | | | | v | | 4. DLL 로드 -> 재귀적으로 의존 DLL 로드 | | | (kernel32.dll -> ntdll.dll -> ...) | | | | | v | | 5. 재배치 (Relocation) -> 기준 주소 조정 | | | (ASLR로 인해 매번 다른 주소에 로드) | | | | | v | | 6. TLS 초기화 -> 스레드 로컬 스토리지 설정 | | | | | v | | 7. CRT 초기화 -> C 런타임 초기화 | | | (전역 변수 초기화, atexit 등록) | | | | | v | | 8. main() 또는 WinMain() 호출! | | | +------------------------------------------------------------------+ 이 모든 과정이 게임 시작 전에 일어남!

Part 2. EXE 파일 파싱

EXE 파일에서 뭘 읽어오는 거야?

PE(Portable Executable) 포맷을 파싱해서 필요한 정보를 추출해.

로더가 PE 파일에서 읽는 정보: +----------------------------------------------------------------+ | PE 파일 구조 | +----------------------------------------------------------------+ | | | DOS Header | | - e_magic: "MZ" -> EXE 파일 시그니처 | | - e_lfanew: 0x100 -> PE 헤더 위치 | | | | PE Header (0x100~) | | - Machine: 0x8664 -> x64 아키텍처 | | - NumberOfSections: 5 -> 섹션 개수 | | - SizeOfOptionalHeader -> Optional 헤더 크기 | | | | Optional Header | | - ImageBase: 0x140000000 -> 선호하는 로드 주소 | | - AddressOfEntryPoint -> 프로그램 시작점 | | - SectionAlignment -> 메모리 정렬 단위 | | - SizeOfImage -> 메모리에 로드될 전체 크기 | | - DataDirectory[] -> Import, Export 테이블 위치 | | | | Section Headers | | - .text -> 코드 (실행 가능) | | - .data -> 초기화된 전역 변수 | | - .rdata -> 읽기 전용 데이터 | | - .bss -> 초기화 안 된 전역 변수 | | - .rsrc -> 리소스 (아이콘, 버전 등) | | | +----------------------------------------------------------------+
섹션이 뭐야?

EXE 파일 내의 "데이터 덩어리"야. 용도별로 분리되어 있어.

섹션별 역할과 메모리 권한: +----------+--------------------------------+-------------------+ | 섹션 | 내용 | 메모리 권한 | +----------+--------------------------------+-------------------+ | .text | 컴파일된 기계어 코드 | R-X (읽기, 실행) | | .data | 초기화된 전역/정적 변수 | RW- (읽기, 쓰기) | | .rdata | const 변수, 문자열 리터럴 | R-- (읽기 전용) | | .bss | 0으로 초기화된 전역 변수 | RW- (읽기, 쓰기) | | .idata | Import 테이블 (DLL 함수 주소) | R-- (읽기 전용) | | .edata | Export 테이블 (내보내는 함수) | R-- (읽기 전용) | | .rsrc | 리소스 (아이콘, 메뉴, 문자열) | R-- (읽기 전용) | | .reloc | 재배치 정보 (ASLR용) | R-- (읽기 전용) | +----------+--------------------------------+-------------------+ 왜 분리하나? 1. 보안: .text에 쓰기 금지 -> 코드 변조 방지 2. 메모리 공유: .text는 여러 프로세스가 공유 가능 3. Copy-on-Write: .data는 수정 시에만 복사

Part 3. 메모리 매핑

파일을 메모리에 어떻게 올려?

Memory-Mapped File 기술을 사용해. 파일 전체를 복사하지 않아!

메모리 매핑 방식: 전통적 방식 (비효율적): +------------------------------------------------------------+ | 1. 파일 전체 읽기 (디스크 -> RAM 복사) | | 2. 메모리 할당 | | 3. 데이터 복사 | | | | 문제: 100MB EXE -> 100MB RAM 즉시 사용 | +------------------------------------------------------------+ 메모리 매핑 방식 (실제 사용): +------------------------------------------------------------+ | | | 가상 주소 공간 디스크 (EXE 파일) | | +--------------+ +--------------+ | | | 0x140000000 | <-------- | 오프셋 0x0 | | | | (.text) | 페이지 | (.text 섹션) | | | | | 테이블 | | | | | 0x140100000 | <-------- | 오프셋 0x1000| | | | (.data) | | (.data 섹션) | | | +--------------+ +--------------+ | | | | 실제 RAM 사용: 0 (아직 접근 안 함) | | | | 코드 실행 시: | | CPU가 0x140000000 접근 -> 페이지 폴트! | | -> OS가 디스크에서 해당 페이지(4KB)만 로드 | | | | 필요한 페이지만 로드 = 빠른 시작! | | | +------------------------------------------------------------+
그래서 게임이 빨리 시작되는 거야?

맞아! Demand Paging 덕분에 실제로 필요한 코드만 로드해.

// 메모리 매핑 직접 해보기 (Windows API) // 1. 파일 열기 HANDLE hFile = CreateFile(L"game.exe", GENERIC_READ, FILE_SHARE_READ, NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL); // 2. 파일 매핑 객체 생성 HANDLE hMapping = CreateFileMapping(hFile, NULL, PAGE_READONLY, 0, 0, NULL); // 3. 뷰 매핑 (가상 주소 공간에 연결) LPVOID pBase = MapViewOfFile(hMapping, FILE_MAP_READ, 0, 0, 0); // 이제 pBase를 통해 파일 내용에 접근 가능 // 실제로 접근할 때만 디스크에서 로드됨! // 4. 정리 UnmapViewOfFile(pBase); CloseHandle(hMapping); CloseHandle(hFile);

Part 4. 동적 링킹과 재배치

DLL은 언제 로드돼?

두 가지 방식이 있어: 암시적 링킹과 명시적 링킹.

DLL 로딩 방식: 1. 암시적 링킹 (Implicit Linking) +--------------------------------------------------------+ | - 컴파일 시점에 .lib 파일 링크 | | - 프로그램 시작 시 자동으로 DLL 로드 | | - Import Table에 기록됨 | | | | 예: #pragma comment(lib, "user32.lib") | | MessageBox(...); // 바로 사용 가능 | +--------------------------------------------------------+ 2. 명시적 링킹 (Explicit Linking) +--------------------------------------------------------+ | - 런타임에 LoadLibrary()로 직접 로드 | | - GetProcAddress()로 함수 주소 획득 | | - 필요할 때만 로드 가능 (플러그인 시스템) | | | | 예: HMODULE h = LoadLibrary(L"plugin.dll"); | | auto func = GetProcAddress(h, "Initialize"); | +--------------------------------------------------------+ 암시적 링킹의 DLL 로드 순서: +--------------------------------------------------------+ | game.exe | | +-- kernel32.dll (필수) | | | +-- ntdll.dll | | +-- user32.dll | | | +-- gdi32.dll | | +-- d3d11.dll | | | +-- dxgi.dll | | +-- xinput1_4.dll | +--------------------------------------------------------+ DLL 하나가 없으면 프로그램 시작 실패!
재배치(Relocation)가 뭐야?

프로그램이 원하는 주소에 로드되지 못했을 때, 주소를 조정하는 작업이야.

재배치가 필요한 이유: +------------------------------------------------------------+ | EXE 파일 내부 코드: | | | | call 0x140001234 ; 함수 호출 (절대 주소) | | mov rax, [0x140005678] ; 전역 변수 접근 | | | | 이 코드는 ImageBase = 0x140000000 기준으로 컴파일됨 | +------------------------------------------------------------+ | v +------------------------------------------------------------+ | 하지만 ASLR(Address Space Layout Randomization)로 인해 | | 실제 로드 주소: 0x7FF6A0000000 (랜덤!) | | | | 그대로 실행하면? -> 잘못된 주소 접근 -> 크래시! | +------------------------------------------------------------+ | v +------------------------------------------------------------+ | 재배치 수행 (.reloc 섹션 사용): | | | | delta = 0x7FF6A0000000 - 0x140000000 = 0x7FF560000000 | | | | call 0x140001234 -> call 0x7FF6A0001234 | | mov rax, [0x140005678] -> mov rax, [0x7FF6A0005678] | | | | 모든 절대 주소에 delta를 더함! | +------------------------------------------------------------+
// ASLR 확인하기 #include <windows.h> #include <stdio.h> int main() { // 현재 EXE의 로드 주소 HMODULE hModule = GetModuleHandle(NULL); printf("EXE 로드 주소: %p\n", hModule); // 여러 번 실행해보면 매번 다른 주소! // (ASLR이 켜져 있으면) // DLL 로드 주소 확인 HMODULE hKernel = GetModuleHandle(L"kernel32.dll"); printf("kernel32.dll: %p\n", hKernel); return 0; }

Part 5. CRT 초기화와 main() 호출

main() 전에 뭐가 실행돼?

CRT(C Runtime) 초기화 코드가 먼저 실행돼!

실제 진입점 (Entry Point) 흐름: +------------------------------------------------------------+ | PE Header의 AddressOfEntryPoint | | | | | v | | +----------------------------------------------------------+ | | mainCRTStartup() 또는 WinMainCRTStartup() | | | | | | 1. 힙 초기화 (_heap_init) | | | 2. 전역 변수 초기화 (_initterm) | | | 3. C++ 정적 객체 생성자 호출 | | | 4. 명령줄 인자 파싱 | | | 5. 환경 변수 설정 | | | 6. stdio 초기화 | | | | | +----------------------------------------------------------+ | | | | v | | +----------------------------------------------------------+ | | main(argc, argv) 또는 WinMain(...) | | | | | | <-- 우리가 작성한 코드는 여기서부터! | | +----------------------------------------------------------+ | | | | v | | +----------------------------------------------------------+ | | exit() 또는 return | | | | | | 1. atexit() 등록된 함수들 호출 | | | 2. C++ 정적 객체 소멸자 호출 | | | 3. 파일 핸들 정리 | | | 4. ExitProcess() 호출 | | +----------------------------------------------------------+ +------------------------------------------------------------+
// main() 전에 실행되는 코드 예시 // 전역 변수 초기화 int g_value = ComputeInitialValue(); // main 전에 호출됨! // C++ 정적 객체 class Logger { public: Logger() { // main 전에 실행! printf("Logger 생성자\n"); } ~Logger() { // main 후에 실행! printf("Logger 소멸자\n"); } }; Logger g_logger; // 전역 객체 int main() { printf("main 시작\n"); return 0; } // 출력 순서: // Logger 생성자 // main 시작 // Logger 소멸자

핵심 정리

  • 로더 - OS가 실행 파일을 메모리에 올리고 실행 준비하는 시스템
  • PE 파싱 - 헤더에서 ImageBase, EntryPoint, 섹션 정보 추출
  • 메모리 매핑 - 파일을 가상 주소에 연결, 실제 접근 시에만 로드 (Demand Paging)
  • DLL 로딩 - Import Table 기반 암시적 링킹 또는 LoadLibrary 명시적 링킹
  • 재배치 - ASLR로 인한 주소 변경을 .reloc 섹션으로 보정
  • CRT 초기화 - main() 전에 힙, 전역 변수, 정적 객체 초기화
  • Entry Point - mainCRTStartup() -> main() -> exit()
