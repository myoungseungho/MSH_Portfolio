단축키 설계

Part 1. 왜 오토플로가 필요했나

QA 테스트 자동화가 필요한 이유는?

게임 서비스에서 QA는 반복 테스트의 연속이다.

패치마다, 핫픽스마다, 매번 같은 시나리오를 사람이 돌리는 건 비효율적이다.

기존에 시도했던 방법들은?

세 가지 방법을 시도했지만 모두 문제가 있었다:

시도 방법 문제점
1. 상용 솔루션 외부 테스트 자동화 도구 도입 게임에 특화되지 않음, 커스터마이징 어려움
2. 내부 개발 자체 자동화 프레임워크 개발 개발팀 리소스 부담, 유지보수 이슈
3. 파이썬 스크립팅 QA가 직접 스크립트 작성 러닝 커브가 너무 높음

파이썬 스크립팅의 현실

QA 담당자에게 "파이썬 배워서 스크립트 짜세요"는

"영어 배워서 영문 계약서 작성하세요"와 비슷한 말이다.

기술적으로 가능은 하지만, 현실적으로 채택률이 낮다.

Part 2. 가장 큰 고민: "이거 진짜 쓸까?"

"도구를 만드는 건 어렵지 않다. 어려운 건 사람들이 쓰게 만드는 것이다."

- 오토플로 개발팀
왜 이게 가장 큰 고민이었나?

지원 도구의 딜레마:

- 만들어도 안 쓰면 의미 없다

- 강제하면 반감만 생긴다

- 결국 자발적으로 쓰게 만들어야 한다

지원 도구가 실패하는 이유는?

"있으면 좋겠다"로 만들어서 "있긴 한데 안 쓴다"가 되는 패턴:

지원 도구의 전형적인 실패 경로: 1. "이런 도구 있으면 좋겠다" → 개발 시작 2. 열심히 만들어서 배포 3. 초기에 몇 명이 써봄 4. "쓰기 어렵다", "배울 시간 없다" 피드백 5. 사용자 줄어듦 6. 업데이트 동력 상실 7. 방치 → 죽음

핵심 질문

기능을 추가하기 전에 항상 물어야 할 질문:

"이걸 만들면 사람들이 진짜 쓸까?"

Part 3. 재미(Fun)라는 요소에 주목한 이유

왜 "재미"가 중요한가? 업무 도구인데?

업무 도구도 "쓰고 싶은 느낌"이 있어야 쓴다.

재미는 자발적 동기의 원천이다.

동기 특징 지속성
외적 동기 강제, 지시, 보상 감시가 없으면 안 함
내적 동기 재미, 성취감, 호기심 스스로 찾아서 함
업무 도구에서 재미는 어떻게 만드나?

게임 개발자답게 게임적 요소를 적용:

- 즉각적 피드백: 노드 연결하면 바로 결과

- 점진적 성취: 간단한 것부터 복잡한 것까지

- 창작의 즐거움: 레고처럼 조합

재미의 본질

"재미있다"는 것은 "계속하고 싶다"는 것이다.

도구가 재미있으면 사용자가 스스로 기능을 탐색한다.

Part 4. 러닝 커브 낮추기 전략

노드 베이스 비주얼 스크립팅을 선택한 이유는?

텍스트 코딩의 진입 장벽을 없애기 위해:

- 시각적으로 흐름이 보인다

- 오타 걱정이 없다

- 언어 문법을 몰라도 된다

텍스트 스크립팅 vs 노드 베이스 [텍스트] if player.login(): player.move_to(100, 200) player.click_npc("상점") player.buy_item("포션", 10) [노드 베이스] ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ │ 로그인 │──▶│ 이동 │──▶│ NPC │──▶│ 아이템 │ │ │ │ (100,200)│ │ 클릭 │ │ 구매 │ └─────────┘ └─────────┘ └─────────┘ └─────────┘ → 같은 기능, 다른 진입 장벽
"레고처럼 단계적"이라는 게 무슨 뜻?

작은 성공부터 쌓아가는 구조:

단계 학습 내용 소요 시간
1단계 노드 2개 연결해보기 5분
2단계 간단한 시나리오 만들기 30분
3단계 조건 분기 추가 1시간
4단계 반복, 변수 활용 반나절

귀찮음 줄이기

사용자가 "귀찮아서 안 쓴다"고 하면 그건 도구의 문제다.

- 자주 쓰는 기능은 기본값 제공

- 반복 작업은 템플릿화

- 설정은 최소화

"스타크래프트 단축키"가 뭔가?

파워 유저를 위한 단축키 설계:

- 초보자는 마우스로 클릭

- 숙련자는 단축키로 빠르게

- 같은 도구, 다른 효율

Progressive Skill Ceiling (점진적 숙련 천장) [초보] 마우스로 노드 드래그 → 연결 → 실행 버튼 클릭 → 느리지만 직관적 [중급] Ctrl+N으로 노드 생성 → Tab으로 빠른 연결 → 더 빠름 [고급] 단축키 조합으로 복잡한 플로우 순식간에 생성 → 스타처럼 APM이 높아짐

Part 5. 노드 하나에 기능 많이 안 넣은 이유

노드 하나에 기능을 많이 넣으면 안 되나?

기능이 많으면 복잡해 보인다.

복잡해 보이면 안 쓴다.

설계 장점 단점
하나에 많이 노드 수 적음 복잡, 학습 비용 높음
하나에 하나 단순, 이해 쉬움 노드 수 많아짐

레고 조합의 재미

레고 블록 하나는 단순하다. 하지만 조합하면 뭐든 만들 수 있다.

노드도 마찬가지:

- 단순한 노드 + 단순한 노드 = 복잡한 시나리오

- 조합하는 과정 자체가 재미

그러면 노드가 너무 많아지지 않나?

검색과 카테고리로 해결:

- 검색: 원하는 노드 바로 찾기

- 카테고리: 입력/조건/액션/출력

- 즐겨찾기: 자주 쓰는 것만

노드 설계 철학: "이 노드로 뭘 할 수 있지?" (X) → 옵션이 많아서 헷갈림 "이 노드는 딱 이것만 한다" (O) → 명확해서 조합하기 쉬움

Part 6. 자발적 참여 유도

빠른 업데이트가 왜 중요한가?

사용자의 피드백 루프를 짧게 만들기 위해:

- "이거 불편해요" → 다음 주에 개선

- "이런 기능 있으면 좋겠어요" → 검토 후 빠른 반영

빠른 업데이트의 효과

"내 의견이 반영됐다" → 주인 의식 형성

"이 도구는 계속 좋아진다" → 신뢰 형성

"다음엔 뭐가 나올까" → 기대감 형성

커스텀 노드는 뭔가?

파워 유저가 직접 노드를 만들 수 있게 열어둔 것:

- 자기 프로젝트에 맞는 전용 노드

- 반복되는 패턴을 노드로 묶기

- 도구의 확장을 사용자가 한다

"크레딧 문화"가 뭔가?

커스텀 노드를 만든 사람의 이름을 남기는 것:

[인벤토리 정리 노드] 제작자: 김QA 버전: 1.2.3 설명: 인벤토리의 모든 아이템을 정리합니다 → "이거 김QA님이 만드셨네" → 인정과 명예의 동기 부여
방법 효과
빠른 업데이트 "내 의견이 반영된다" → 참여 의지
커스텀 노드 "내가 기여할 수 있다" → 주인 의식
크레딧 문화 "내 이름이 남는다" → 명예 동기

커뮤니티 형성

결국 도구 사용자들이 커뮤니티가 된다:

- 서로 만든 노드 공유

- 사용 팁 교환

- 문제 해결 도움

→ 도구가 살아있는 생태계가 됨

Part 7. 핵심 메시지

"지원 도구 개발에도 전략이 필요하다."

왜 "전략"이 필요한가?

지원 도구는 만들면 끝이 아니다:

- 사용자가 채택해야 하고

- 지속적으로 써야 하고

- 자발적으로 퍼져야 한다

관점 질문
기능 이 기능이 필요한가? ✓
채택 사람들이 쓸까? ← 여기가 핵심
지속 계속 쓸까?
확산 다른 팀도 쓸까?

오토플로의 전략 요약

1. 재미 - 자발적 동기의 원천

2. 낮은 진입장벽 - 첫 성공까지의 거리 최소화

3. 높은 숙련 천장 - 파워유저도 만족

4. 빠른 피드백 - 사용자 목소리 반영

5. 커뮤니티 - 사용자가 기여하는 생태계

핵심 정리: 오토플로의 생존 전략

  • 기존 시도의 실패 - 상용솔루션(커스터마이징 어려움), 내부개발(리소스 부담), 파이썬(러닝커브)
  • 가장 큰 고민 - "이거 진짜 쓸까?" → 자발적 채택이 핵심
  • 재미에 주목 - 재미있으면 스스로 찾아서 쓴다
  • 노드 베이스 - 시각적, 직관적, 진입장벽 낮음
  • 레고처럼 단계적 - 작은 성공부터 쌓아가는 구조
  • 귀찮음 줄이기 - 기본값, 템플릿, 최소 설정
  • 스타크래프트 단축키 - 초보는 마우스, 고수는 단축키
  • 노드 하나에 기능 하나 - 단순해야 조합이 재미있다
  • 빠른 업데이트 - 피드백 루프 짧게
  • 커스텀 노드 - 사용자가 도구를 확장
  • 크레딧 문화 - 이름이 남는 명예 동기
  • 핵심 메시지 - 지원 도구 개발에도 전략이 필요하다

적용 포인트

내 프로젝트에 적용한다면

1. "쓸까?" 질문부터

기능 개발 전에 "이걸 만들면 사람들이 진짜 쓸까?" 자문


2. 진입장벽 측정

"처음 사용자가 첫 성공까지 몇 분 걸리나?" 측정하고 줄이기


3. 피드백 루프

사용자 의견 → 빠른 반영 → 신뢰 형성의 사이클 만들기


4. 기여 경로

파워유저가 도구 발전에 기여할 수 있는 길 열어두기
