롤백 시스템

패치 실패 시 안전하게 이전 버전으로 복구하는 기술

Part 1. 개념: 롤백 시스템이란?

롤백 시스템이 뭐야? 왜 게임에서 중요해?

롤백 시스템은 패치나 업데이트 실패 시 이전의 정상 상태로 복구하는 메커니즘이야. 라이브 서비스 게임에서 핫픽스나 콘텐츠 패치가 문제를 일으킬 때, 빠르게 안정된 버전으로 돌아갈 수 있어야 하거든.

생각해봐. 금요일 저녁에 새 던전 패치를 배포했는데, 특정 보스에서 게임이 크래시한다면? 주말 내내 유저들이 플레이를 못 하면 매출 손실과 유저 이탈이 발생해. 롤백 시스템이 있으면 5분 안에 이전 버전으로 복구하고, 월요일에 수정된 패치를 다시 배포할 수 있어.

롤백이 필요한 상황들을 구체적으로 알려줘.

롤백이 필요한 대표적인 시나리오들이야:

// 롤백 시스템 핵심 컴포넌트 public class RollbackManager : MonoBehaviour { private static RollbackManager _instance; public static RollbackManager Instance => _instance; [SerializeField] private int maxVersionHistory = 3; private VersionHistory _versionHistory; private IntegrityValidator _validator; private StateSnapshot _snapshot; private BackupStorage _backup; // 현재 버전 정보 public VersionInfo CurrentVersion => _versionHistory.Current; public VersionInfo LastStableVersion => _versionHistory.LastStable; private void Awake() { if (_instance != null) { Destroy(gameObject); return; } _instance = this; DontDestroyOnLoad(gameObject); InitializeComponents(); } private void InitializeComponents() { _versionHistory = new VersionHistory(maxVersionHistory); _validator = new IntegrityValidator(); _snapshot = new StateSnapshot(); _backup = new BackupStorage(GetBackupPath()); } private string GetBackupPath() { return Path.Combine(Application.persistentDataPath, "Backup"); } }
버전 히스토리는 어떻게 관리해?

VersionHistory는 설치된 버전들의 이력을 관리하고, 롤백할 대상을 결정해:

// 버전 히스토리 관리 public class VersionHistory { private readonly int _maxHistory; private LinkedList<VersionInfo> _versions; private const string HISTORY_FILE = "version_history.json"; public VersionInfo Current => _versions.Last?.Value; public VersionInfo LastStable => FindLastStable(); public VersionHistory(int maxHistory) { _maxHistory = maxHistory; _versions = new LinkedList<VersionInfo>(); LoadHistory(); } public void RecordVersion(VersionInfo version) { // 새 버전 추가 _versions.AddLast(version); // 히스토리 제한 초과 시 가장 오래된 것 제거 while (_versions.Count > _maxHistory) { var oldest = _versions.First.Value; _versions.RemoveFirst(); // 백업 파일도 정리 CleanupVersionBackup(oldest); } SaveHistory(); } public void MarkAsStable(VersionInfo version) { version.IsStable = true; version.StabilizedAt = DateTime.UtcNow; SaveHistory(); Debug.Log($"Version {version.VersionCode} marked as stable"); } public void MarkAsFailed(VersionInfo version, string reason) { version.IsFailed = true; version.FailureReason = reason; version.FailedAt = DateTime.UtcNow; SaveHistory(); Debug.LogError($"Version {version.VersionCode} marked as failed: {reason}"); } private VersionInfo FindLastStable() { // 가장 최근의 안정 버전 찾기 var node = _versions.Last; while (node != null) { if (node.Value.IsStable && !node.Value.IsFailed) { return node.Value; } node = node.Previous; } return null; } public IEnumerable<VersionInfo> GetRollbackCandidates() { // 롤백 가능한 버전들 (현재 제외, 실패 제외) return _versions .Where(v => v != Current && !v.IsFailed) .OrderByDescending(v => v.InstalledAt); } }

Part 3. 무결성 검증과 롤백 트리거

롤백이 필요한 상황을 어떻게 자동으로 감지해?

IntegrityValidator가 에셋의 무결성을 검증하고, 문제 발생 시 롤백을 트리거해:

// 무결성 검증기 public class IntegrityValidator { private Dictionary<string, string> _expectedHashes; private HashSet<string> _corruptedAssets; public event Action<IntegrityFailure> OnIntegrityFailed; public async Task<ValidationResult> ValidateAllAsync() { _corruptedAssets.Clear(); var result = new ValidationResult(); foreach (var entry in _expectedHashes) { var assetPath = entry.Key; var expectedHash = entry.Value; try { var actualHash = await ComputeHashAsync(assetPath); if (actualHash != expectedHash) { _corruptedAssets.Add(assetPath); result.CorruptedFiles.Add(assetPath); Debug.LogError($"Hash mismatch: {assetPath}"); } } catch (FileNotFoundException) { result.MissingFiles.Add(assetPath); } catch (Exception ex) { result.Errors.Add(new ValidationError(assetPath, ex)); } } result.IsValid = result.CorruptedFiles.Count == 0 && result.MissingFiles.Count == 0; if (!result.IsValid) { OnIntegrityFailed?.Invoke(new IntegrityFailure(result)); } return result; } private async Task<string> ComputeHashAsync(string path) { using var stream = File.OpenRead(path); using var sha256 = SHA256.Create(); var buffer = new byte[81920]; int bytesRead; while ((bytesRead = await stream.ReadAsync(buffer)) > 0) { sha256.TransformBlock(buffer, 0, bytesRead, null, 0); } sha256.TransformFinalBlock(Array.Empty<byte>(), 0, 0); return BitConverter.ToString(sha256.Hash).Replace("-", ""); } }
자동 롤백 트리거 조건은 어떻게 설정해?

RollbackTrigger가 다양한 조건을 모니터링하고 자동으로 롤백을 시작해:

// 롤백 트리거 시스템 public class RollbackTrigger : MonoBehaviour { [Header("크래시 감지")] [SerializeField] private int crashThreshold = 3; [SerializeField] private float crashWindowMinutes = 10f; [Header("로딩 실패 감지")] [SerializeField] private int loadFailureThreshold = 5; [SerializeField] private float loadTimeoutSeconds = 60f; [Header("메모리 감지")] [SerializeField] private float memoryThresholdMB = 1800f; private Queue<DateTime> _crashTimes = new(); private int _consecutiveLoadFailures = 0; public event Action<RollbackReason> OnRollbackRequired; private void Start() { // 이전 세션 크래시 체크 CheckPreviousCrash(); // 메모리 모니터링 시작 StartCoroutine(MonitorMemory()); // 로딩 이벤트 구독 AssetLoader.OnLoadFailed += HandleLoadFailure; AssetLoader.OnLoadSuccess += ResetLoadFailureCount; } private void CheckPreviousCrash() { // 정상 종료 플래그 확인 if (!PlayerPrefs.HasKey("CleanExit") || PlayerPrefs.GetInt("CleanExit") == 0) { // 이전 세션이 크래시로 종료됨 RecordCrash(); } // 새 세션 시작 - 플래그 리셋 PlayerPrefs.SetInt("CleanExit", 0); PlayerPrefs.Save(); } private void RecordCrash() { var now = DateTime.UtcNow; _crashTimes.Enqueue(now); // 오래된 크래시 기록 제거 var windowStart = now.AddMinutes(-crashWindowMinutes); while (_crashTimes.Count > 0 && _crashTimes.Peek() < windowStart) { _crashTimes.Dequeue(); } // 임계치 체크 if (_crashTimes.Count >= crashThreshold) { Debug.LogError($"Crash threshold reached: {_crashTimes.Count} crashes in {crashWindowMinutes} minutes"); OnRollbackRequired?.Invoke(RollbackReason.RepeatedCrashes); } } private void HandleLoadFailure(string assetPath, Exception error) { _consecutiveLoadFailures++; Debug.LogError($"Load failed ({_consecutiveLoadFailures}/{loadFailureThreshold}): {assetPath}"); if (_consecutiveLoadFailures >= loadFailureThreshold) { OnRollbackRequired?.Invoke(RollbackReason.AssetLoadFailure); } } private IEnumerator MonitorMemory() { var wait = new WaitForSeconds(5f); while (true) { var memoryMB = Profiler.GetTotalAllocatedMemoryLong() / (1024f * 1024f); if (memoryMB > memoryThresholdMB) { Debug.LogWarning($"Memory critical: {memoryMB:F1}MB / {memoryThresholdMB}MB"); OnRollbackRequired?.Invoke(RollbackReason.MemoryExhaustion); } yield return wait; } } private void OnApplicationQuit() { // 정상 종료 플래그 설정 PlayerPrefs.SetInt("CleanExit", 1); PlayerPrefs.Save(); } } public enum RollbackReason { Manual, // 수동 요청 RepeatedCrashes, // 반복 크래시 AssetLoadFailure, // 에셋 로드 실패 IntegrityFailure, // 무결성 검증 실패 MemoryExhaustion, // 메모리 부족 ServerCommand // 서버 명령 }

RollbackExecutor가 전체 롤백 프로세스를 관리해:

// 롤백 실행기 public class RollbackExecutor { private readonly BackupStorage _backup; private readonly IntegrityValidator _validator; private readonly StateSnapshot _snapshot; public event Action<RollbackProgress> OnProgress; public event Action<RollbackResult> OnComplete; public async Task<RollbackResult> ExecuteAsync(VersionInfo targetVersion) { var result = new RollbackResult(); string tempBackupPath = null; try { // Phase 1: 사전 검증 ReportProgress(RollbackPhase.Validation, 0f); if (!await ValidateRollbackPossible(targetVersion)) { result.Success = false; result.Error = "Rollback validation failed"; return result; } // Phase 2: 준비 ReportProgress(RollbackPhase.Preparation, 0.1f); // 진행 중인 작업 중단 AssetLoader.CancelAll(); PatchDownloader.Cancel(); // 현재 상태 스냅샷 (롤백 실패 시 복구용) tempBackupPath = await _snapshot.CreateSnapshotAsync(); // 롤백 진행 중 플래그 SetRollbackInProgress(true); // Phase 3: 복원 ReportProgress(RollbackPhase.Restoration, 0.2f); await RestoreVersionAsync(targetVersion, progress => { ReportProgress(RollbackPhase.Restoration, 0.2f + progress * 0.5f); }); // Phase 4: 검증 ReportProgress(RollbackPhase.Verification, 0.7f); var validationResult = await _validator.ValidateAllAsync(); if (!validationResult.IsValid) { // 검증 실패 - 스냅샷으로 원복 Debug.LogError("Rollback verification failed, reverting..."); await _snapshot.RestoreSnapshotAsync(tempBackupPath); result.Success = false; result.Error = "Verification failed after rollback"; return result; } // Phase 5: 완료 ReportProgress(RollbackPhase.Completion, 0.9f); // 임시 파일 정리 if (tempBackupPath != null) { Directory.Delete(tempBackupPath, true); } // 버전 정보 업데이트 UpdateVersionInfo(targetVersion); // 서버 보고 await ReportRollbackToServerAsync(targetVersion); SetRollbackInProgress(false); result.Success = true; result.RolledBackTo = targetVersion; ReportProgress(RollbackPhase.Completion, 1f); } catch (Exception ex) { Debug.LogException(ex); // 롤백 실패 시 스냅샷으로 복구 시도 if (tempBackupPath != null) { try { await _snapshot.RestoreSnapshotAsync(tempBackupPath); } catch (Exception restoreEx) { Debug.LogError($"Failed to restore snapshot: {restoreEx.Message}"); } } SetRollbackInProgress(false); result.Success = false; result.Error = ex.Message; } OnComplete?.Invoke(result); return result; } private async Task RestoreVersionAsync(VersionInfo target, Action<float> onProgress) { var backupPath = _backup.GetVersionPath(target); var targetPath = Application.persistentDataPath; var files = Directory.GetFiles(backupPath, "*", SearchOption.AllDirectories); var total = files.Length; for (int i = 0; i < total; i++) { var sourceFile = files[i]; var relativePath = sourceFile.Substring(backupPath.Length + 1); var destFile = Path.Combine(targetPath, relativePath); // 디렉토리 생성 var destDir = Path.GetDirectoryName(destFile); if (!Directory.Exists(destDir)) { Directory.CreateDirectory(destDir); } // 파일 복사 (비동기) await CopyFileAsync(sourceFile, destFile); onProgress?.Invoke((float)(i + 1) / total); } } }

// Addressables 롤백 시스템 public class AddressablesRollback { private const string CATALOG_VERSION_KEY = "AddressablesCatalogVersion"; private const string CATALOG_URL_FORMAT = "{0}/catalogs/catalog_v{1}.json"; private readonly string _cdnBaseUrl; private List<string> _availableVersions; public AddressablesRollback(string cdnBaseUrl) { _cdnBaseUrl = cdnBaseUrl; } public async Task<bool> RollbackToVersionAsync(string targetVersion) { try { Debug.Log($"Rolling back Addressables to v{targetVersion}"); // 1. 현재 로드된 모든 에셋 해제 await UnloadAllAddressablesAsync(); // 2. 캐시 정리 (선택적) ClearIncompatibleCache(targetVersion); // 3. 대상 버전 카탈로그 URL 설정 var catalogUrl = string.Format(CATALOG_URL_FORMAT, _cdnBaseUrl, targetVersion); // 4. 카탈로그 다시 로드 var handle = Addressables.LoadContentCatalogAsync(catalogUrl); await handle.Task; if (handle.Status != AsyncOperationStatus.Succeeded) { Debug.LogError($"Failed to load catalog: {handle.OperationException}"); return false; } // 5. 로컬에 버전 기록 PlayerPrefs.SetString(CATALOG_VERSION_KEY, targetVersion); PlayerPrefs.Save(); Debug.Log($"Successfully rolled back to v{targetVersion}"); return true; } catch (Exception ex) { Debug.LogException(ex); return false; } } private async Task UnloadAllAddressablesAsync() { // 모든 AsyncOperationHandle 해제 Resources.UnloadUnusedAssets(); await Task.Yield(); GC.Collect(); } private void ClearIncompatibleCache(string targetVersion) { // 대상 버전과 호환되지 않는 번들 캐시 정리 var cacheDirectories = Caching.GetAllCachePaths(); foreach (var cacheDir in cacheDirectories) { var bundleDirs = Directory.GetDirectories(cacheDir); foreach (var bundleDir in bundleDirs) { // 번들 해시로 호환성 체크 if (!IsCompatibleWithVersion(bundleDir, targetVersion)) { try { Directory.Delete(bundleDir, true); Debug.Log($"Cleared incompatible cache: {bundleDir}"); } catch (Exception ex) { Debug.LogWarning($"Failed to clear cache: {ex.Message}"); } } } } } /// <summary> /// 서버에서 롤백 가능한 버전 목록 조회 /// </summary> public async Task<List<string>> GetAvailableVersionsAsync() { using var client = new HttpClient(); var response = await client.GetStringAsync($"{_cdnBaseUrl}/catalogs/versions.json"); var versions = JsonUtility.FromJson<VersionList>(response); _availableVersions = versions.versions .Where(v => v.isStable) .Select(v => v.version) .ToList(); return _availableVersions; } }
카탈로그 버전 관리 서버 측은 어떻게 구성해?

서버에서 versions.json으로 이용 가능한 카탈로그를 관리해:

// versions.json - CDN에 배포 { "versions": [ { "version": "1.2.2", "releaseDate": "2024-01-15T10:00:00Z", "isStable": false, "isFailed": true, "failureReason": "Critical crash on iOS devices" }, { "version": "1.2.1", "releaseDate": "2024-01-10T10:00:00Z", "isStable": true, "isFailed": false, "minClientVersion": "1.0.0" }, { "version": "1.2.0", "releaseDate": "2024-01-05T10:00:00Z", "isStable": true, "isFailed": false, "minClientVersion": "1.0.0" } ], "currentRecommended": "1.2.1", "forceRollbackTo": null }

forceRollbackTo가 설정되면 클라이언트는 해당 버전으로 강제 롤백해. 서버에서 긴급하게 문제 버전을 무효화할 때 사용해.

Part 6. 서버 주도 롤백 시스템

서버에서 강제로 롤백을 시키려면?

긴급 상황에서는 서버가 롤백을 명령할 수 있어야 해. 클라이언트가 문제 버전을 사용 중이면 강제로 안전한 버전으로 전환시키는 거야:

// 서버 주도 롤백 시스템 public class ServerDrivenRollback : MonoBehaviour { [SerializeField] private float checkIntervalSeconds = 300f; // 5분 [SerializeField] private string versionCheckEndpoint; private AddressablesRollback _rollback; private string _currentVersion; public event Action<ForceRollbackInfo> OnForceRollbackRequired; private void Start() { _currentVersion = PlayerPrefs.GetString("AddressablesCatalogVersion"); StartCoroutine(PollVersionStatus()); } private IEnumerator PollVersionStatus() { var wait = new WaitForSeconds(checkIntervalSeconds); while (true) { yield return CheckVersionStatusAsync(); yield return wait; } } private IEnumerator CheckVersionStatusAsync() { using var request = UnityWebRequest.Get( $"{versionCheckEndpoint}?version={_currentVersion}"); yield return request.SendWebRequest(); if (request.result != UnityWebRequest.Result.Success) { Debug.LogWarning($"Version check failed: {request.error}"); yield break; } var response = JsonUtility.FromJson<VersionCheckResponse>( request.downloadHandler.text); if (response.forceRollback) { Debug.LogWarning($"Force rollback required to v{response.targetVersion}"); Debug.LogWarning($"Reason: {response.reason}"); OnForceRollbackRequired?.Invoke(new ForceRollbackInfo { TargetVersion = response.targetVersion, Reason = response.reason, IsUrgent = response.isUrgent, GracePeriodMinutes = response.gracePeriodMinutes }); if (response.isUrgent) { // 즉시 롤백 yield return ExecuteForceRollback(response.targetVersion); } else { // 유예 기간 후 롤백 (유저가 저장할 시간) yield return new WaitForSeconds(response.gracePeriodMinutes * 60); yield return ExecuteForceRollback(response.targetVersion); } } } private IEnumerator ExecuteForceRollback(string targetVersion) { // UI로 롤백 진행 표시 LoadingUI.Show("긴급 업데이트 중..."); var task = _rollback.RollbackToVersionAsync(targetVersion); while (!task.IsCompleted) { yield return null; } if (task.Result) { _currentVersion = targetVersion; // 씬 리로드 SceneManager.LoadScene(SceneManager.GetActiveScene().buildIndex); } else { // 롤백 실패 - 앱 재시작 필요 ErrorUI.Show("업데이트 실패. 앱을 재시작해주세요.", () => Application.Quit()); } } } [Serializable] public class VersionCheckResponse { public bool forceRollback; public string targetVersion; public string reason; public bool isUrgent; public int gracePeriodMinutes; }
서버 API 설계는 어떻게 해야 해?

서버 측 버전 관리 API 설계:

// Node.js 서버 예시 - 버전 관리 API const express = require('express'); const router = express.Router(); // 버전 상태 데이터 (실제로는 DB에서 관리) let versionConfig = { versions: { '1.2.2': { status: 'failed', failReason: 'iOS crash' }, '1.2.1': { status: 'stable' }, '1.2.0': { status: 'stable' } }, forceRollbackTo: null, isUrgent: false, gracePeriodMinutes: 5 }; // 클라이언트 버전 체크 API router.get('/api/version/check', (req, res) => { const clientVersion = req.query.version; const versionInfo = versionConfig.versions[clientVersion]; // 강제 롤백 설정 확인 if (versionConfig.forceRollbackTo) { return res.json({ forceRollback: true, targetVersion: versionConfig.forceRollbackTo, reason: 'Server-initiated rollback', isUrgent: versionConfig.isUrgent, gracePeriodMinutes: versionConfig.gracePeriodMinutes }); } // 현재 버전이 실패 상태인지 확인 if (versionInfo?.status === 'failed') { const stableVersion = findLatestStableVersion(); return res.json({ forceRollback: true, targetVersion: stableVersion, reason: versionInfo.failReason, isUrgent: false, gracePeriodMinutes: 5 }); } res.json({ forceRollback: false }); }); // 관리자 API: 버전 실패 처리 router.post('/api/admin/version/fail', authenticate, (req, res) => { const { version, reason, forceImmediate } = req.body; versionConfig.versions[version] = { status: 'failed', failReason: reason, failedAt: new Date().toISOString() }; if (forceImmediate) { const stableVersion = findLatestStableVersion(); versionConfig.forceRollbackTo = stableVersion; versionConfig.isUrgent = true; } // 롤백 이벤트 로깅 logRollbackEvent(version, reason); res.json({ success: true, rollbackTarget: versionConfig.forceRollbackTo }); }); // 관리자 API: 강제 롤백 해제 router.post('/api/admin/version/clear-force-rollback', authenticate, (req, res) => { versionConfig.forceRollbackTo = null; versionConfig.isUrgent = false; res.json({ success: true }); });

Part 7. 롤백 UI와 모니터링

사용자에게 롤백 상황을 어떻게 알려줘야 해?

롤백은 투명하게 진행되어야 해. 사용자가 불안하지 않도록 명확한 UI를 제공해:

// 롤백 UI 시스템 public class RollbackUI : MonoBehaviour { [SerializeField] private GameObject rollbackPanel; [SerializeField] private TMP_Text statusText; [SerializeField] private TMP_Text reasonText; [SerializeField] private Slider progressBar; [SerializeField] private TMP_Text progressText; [SerializeField] private Button cancelButton; private RollbackManager _rollbackManager; private void Start() { _rollbackManager = RollbackManager.Instance; 핵심 요약: 롤백 시스템 체크리스트

  • 버전 히스토리 - 최근 N개 버전 백업 유지, 안정/실패 상태 관리
  • 무결성 검증 - 해시 기반 파일 검증, 손상 감지 시 자동 롤백
  • 자동 트리거 - 반복 크래시, 로드 실패, 메모리 부족 감지
  • 원자적 실행 - 롤백 중 실패해도 복구 가능한 스냅샷 보존
  • Addressables 통합 - 카탈로그 버전 관리로 CDN 기반 롤백
  • 서버 주도 롤백 - 긴급 상황 시 서버에서 강제 롤백 명령
  • 투명한 UI - 사용자에게 진행 상황과 이유 명확히 표시
  • 모니터링 - 롤백 지표 수집 및 대시보드로 실시간 파악
