현재까지 압축

// 플레이어 100명 동기화 패킷 (초당 20회) 원본: 21 bytes * 100 * 20 = 42 KB/s 델타 압축: 13 bytes * 100 * 20 = 26 KB/s (38% 절약) 양자화: 10 bytes * 100 * 20 = 20 KB/s (23% 추가 절약) 비트 패킹: 7.5 bytes * 100 * 20 = 15 KB/s (25% 추가 절약) // 현재: 15 KB/s (원본 대비 64% 절약)

하지만 이 패킷들을 보면...

// 플레이어 100명의 패킷 Player 1: [01 05 1A 3F 82 C4 09] Player 2: [01 05 1A 42 82 C4 09] ← 거의 비슷! Player 3: [01 05 1A 3F 83 C4 09] ← 거의 비슷! ... Player 100: [01 05 1A 41 82 C4 09] // playerId와 방향만 다르고 나머지는 반복!

반복되는 패턴이 엄청 많아요.

이걸 압축하면 40~60% 더 줄일 수 있어요.

💡 압축 알고리즘이 뭐예요?

어떻게 반복을 찾아?

이전에 나온 데이터를 참조하는 방식이에요.

📝 비유: 논문 작성

압축 안 한 버전:
"게임 서버 최적화는 중요하다. 게임 서버 최적화를 통해..."
"게임 서버 최적화" 반복 (9글자 * 3번 = 27글자)

압축한 버전:
"게임 서버 최적화는 중요하다. [위 9글자]를 통해... [위 9글자]..."
"게임 서버 최적화" (9글자) + "[위 9글자]" (5글자) * 2 = 19글자

절약: 30%
실제로는?

압축 전

원본 데이터 (20 bytes): ABCDEFGHIJ ABCDEFGHIJ // "ABCDEFGHIJ"가 2번 반복

압축 후

압축 데이터 (14 bytes): ABCDEFGHIJ <10,10> // "ABCDEFGHIJ" (10 bytes) // <10,10> = "10바이트 전으로 돌아가서 10바이트 복사" (4 bytes) // 20 bytes → 14 bytes (30% 절약)

이게 LZ 계열 압축 알고리즘의 핵심이에요.

⚡ LZ4 vs Zstd

LZ4랑 Zstd는 뭐가 달라?

둘 다 반복 패턴을 찾는데, 속도 vs 압축률 차이예요.

항목 LZ4 Zstd
압축률 중간 (1.5~2.5배) 높음 (2~4배)
압축 속도 매우 빠름 (500 MB/s) 중간 (100~300 MB/s)
압축 해제 속도 극도로 빠름 (2 GB/s) 빠름 (500 MB/s)
CPU 사용량 낮음 중간~높음
레이턴시 거의 없음 (1ms) 약간 있음 (5~10ms)
사용 사례 실시간 게임 파일 전송, 다운로드
💡 선택 기준:
• LZ4: 실시간성 중요 (FPS, 레이싱)
• Zstd: 압축률 중요 (리플레이, 에셋 다운로드)

🔧 LZ4 구현

코드로 보여주세요.

LZ4 라이브러리 사용

#include // 압축 int CompressPacket(const uint8_t* src, int srcSize, uint8_t* dst, int dstCapacity) { int compressedSize = LZ4_compress_default( (const char*)src, (char*)dst, srcSize, dstCapacity ); if (compressedSize <= 0) { // 압축 실패 return -1; } return compressedSize; } // 압축 해제 int DecompressPacket(const uint8_t* src, int srcSize, uint8_t* dst, int dstCapacity) { int decompressedSize = LZ4_decompress_safe( (const char*)src, (char*)dst, srcSize, dstCapacity ); if (decompressedSize < 0) { // 압축 해제 실패 return -1; } return decompressedSize; }

실제 사용 예시

// 100명 플레이어 패킷 (이미 델타+양자화+비트패킹 적용) uint8_t originalPackets[750]; // 7.5 bytes * 100 // ... 패킷 채우기 // 압축 버퍼 (최악의 경우 더 커질 수 있음) uint8_t compressedBuffer[1024]; int compressedSize = CompressPacket( originalPackets, 750, compressedBuffer, 1024 ); printf("원본: %d bytes\n", 750); printf("압축: %d bytes\n", compressedSize); printf("비율: %.1fx\n", 750.0f / compressedSize); // 실제 결과: 750 → 450 bytes (1.67배, 40% 절약)

전송

// 압축된 패킷 전송 // 헤더: [원본 크기 (2 bytes)][압축 크기 (2 bytes)] uint16_t header[2] = { 750, compressedSize }; send(socket, &header, 4, 0); send(socket, compressedBuffer, compressedSize, 0); // 총 전송: 4 + 450 = 454 bytes (vs 원본 750 bytes)

수신 측

// 헤더 읽기 uint16_t header[2]; recv(socket, &header, 4, 0); int originalSize = header[0]; int compressedSize = header[1]; // 압축된 데이터 읽기 uint8_t compressedBuffer[1024]; recv(socket, compressedBuffer, compressedSize, 0); // 압축 해제 uint8_t originalPackets[750]; int decompressedSize = DecompressPacket( compressedBuffer, compressedSize, originalPackets, 750 ); // 복원 완료!

🎯 실전 적용: 언제 압축할까?

모든 패킷을 압축해야 해?

아니에요. 선택적으로 해야 해요.

✅ 압축하면 좋은 경우

  • 큰 패킷 (100 bytes 이상) - 압축 효과 큼
  • 반복 패턴 많음 - 여러 플레이어 동기화
  • 일괄 전송 - 배칭된 패킷
  • 텍스트 데이터 - 채팅, 로그
  • 맵 데이터 - 타일맵, 오브젝트 배치
  • 리플레이 데이터 - 녹화 파일

❌ 압축하면 안 되는 경우

  • 작은 패킷 (< 100 bytes) - 압축 오버헤드 > 절약
  • 이미 압축된 데이터 - 이미지, 오디오
  • 랜덤 데이터 - 암호화된 데이터
  • 극저지연 필요 - 총알 발사, 즉시 이벤트
  • CPU 부족 - 모바일 저사양 기기
// 조건부 압축 if (packetSize > 100 && cpuUsage < 70%) { // 압축 compressedSize = CompressPacket(packet, packetSize, buffer, bufferSize); if (compressedSize < packetSize * 0.8) // 20% 이상 절약되면 { SendCompressed(buffer, compressedSize); } else { SendRaw(packet, packetSize); // 압축 효과 없으면 원본 전송 } } else { SendRaw(packet, packetSize); }

⚠️ 주의사항

압축할 때 조심할 점은?

1. CPU 오버헤드

// LZ4 압축 압축: ~0.5ms (750 bytes) 해제: ~0.2ms // 프레임 예산 (60fps = 16.67ms) 압축 0.5ms + 렌더링 10ms + 기타 5ms = 15.5ms → 여유 있음 // 하지만 Zstd (레벨 10) 압축: ~5ms 해제: ~1ms → 프레임 드랍 위험!

2. 압축 실패 처리

int compressedSize = LZ4_compress_default(...); if (compressedSize <= 0) { // 압축 실패: 원본 전송 SendRaw(packet, packetSize); } else if (compressedSize >= packetSize) { // 압축했는데 더 커짐: 원본 전송 SendRaw(packet, packetSize); } else { // 압축 성공 SendCompressed(compressedBuffer, compressedSize); }

3. 작은 패킷은 역효과

// 10 bytes 패킷 원본: 10 bytes LZ4 압축: 14 bytes (헤더 오버헤드) // 100 bytes 패킷 원본: 100 bytes LZ4 압축: 60 bytes (효과 있음) // 최소 크기 확인 if (packetSize < MIN_COMPRESS_SIZE) // 예: 100 bytes SendRaw(packet, packetSize);

4. 레이턴시 증가

// 압축 없이 전송 시간: 네트워크 지연 (50ms) // LZ4 압축 전송 시간: 압축(0.5ms) + 네트워크(30ms) + 해제(0.2ms) = 30.7ms // Zstd 압축 (레벨 5) 전송 시간: 압축(3ms) + 네트워크(25ms) + 해제(1ms) = 29ms // FPS 게임: 압축 안 함 (50ms 레이턴시 중요) // MMO: LZ4 (대역폭 절약 중요) // 파일 다운로드: Zstd (압축률 최우선)
⚠️ 실시간 게임 주의사항:

• FPS/레이싱: 압축 안 함 (레이턴시 중요)
• MMO/전략: LZ4 (균형)
• 턴제: Zstd (압축률 중요)
• 파일 전송: Zstd 레벨 10 (최대 압축)

압축은 만능이 아닙니다. 상황에 맞게 선택하세요!

💼 실무 구현 가이드

Step 1: 프로파일링

// 1000개 패킷 샘플링 for (int i = 0; i < 1000; i++) { int originalSize = GetPacketSize(); int lz4Size = CompressLZ4(packet); int zstdSize = CompressZstd(packet, level); printf("Original: %d, LZ4: %d, Zstd: %d\n", originalSize, lz4Size, zstdSize); } // 평균 압축률 계산 // 압축률이 20% 미만이면 압축 안 함

Step 2: 압축 레벨 선택

// Zstd 레벨별 테스트 for (int level = 1; level <= 10; level++) { auto start = HighResolutionClock::now(); int compressedSize = ZSTD_compress(dst, dstSize, src, srcSize, level); auto end = HighResolutionClock::now(); auto duration = duration_cast(end - start); float ratio = (float)srcSize / compressedSize; printf("레벨 %d: 압축률 %.2fx, 시간 %lld ms\n", level, ratio, duration.count()); } // 결과: // 레벨 1: 1.8x, 2ms // 레벨 3: 2.1x, 5ms ← 최적 // 레벨 5: 2.3x, 12ms // 레벨 10: 2.5x, 50ms

Step 3: 조건부 압축 로직

enum class PacketType { MOVEMENT, // 압축 안 함 (작고 빠름) CHAT, // Zstd (텍스트) SYNC_BATCH, // LZ4 (반복 많음) MAP_DATA, // Zstd 레벨 5 (큰 데이터) REPLAY // Zstd 레벨 10 (저장 파일) }; void SendPacket(PacketType type, const uint8_t* data, int size) { switch (type) { case PacketType::MOVEMENT: SendRaw(data, size); break; case PacketType::CHAT: if (size > 50) SendCompressedZstd(data, size, 3); else SendRaw(data, size); break; case PacketType::SYNC_BATCH: if (size > 100) SendCompressedLZ4(data, size); else SendRaw(data, size); break; case PacketType::MAP_DATA: SendCompressedZstd(data, size, 5); break; case PacketType::REPLAY: SendCompressedZstd(data, size, 10); break; } }

Step 4: 헤더 설계

// 압축 패킷 헤더 struct CompressedPacketHeader { uint8_t compressed; // 1: 압축됨, 0: 원본 uint8_t algorithm; // 0: None, 1: LZ4, 2: Zstd uint16_t originalSize; // 원본 크기 (압축 해제용) uint16_t compressedSize; // 압축된 크기 } __attribute__((packed)); // 총 6 bytes 헤더 // 전송 CompressedPacketHeader header = { .compressed = 1, .algorithm = 1, // LZ4 .originalSize = 750, .compressedSize = 450 }; send(socket, &header, sizeof(header), 0); send(socket, compressedData, header.compressedSize, 0);

📌 핵심 정리: LZ4/Zstd 압축

  • 압축 알고리즘 - 반복 패턴을 참조로 바꿔서 크기 줄이기
  • LZ4 - 빠른 속도, 중간 압축률 (실시간 게임)
  • Zstd - 높은 압축률, 중간 속도 (파일 전송)
  • 적용 대상 - 큰 패킷(100+ bytes), 반복 많은 데이터, 배칭
  • 실측 결과 - 대역폭 40~60% 추가 절약
  • 주의사항 - CPU 오버헤드, 레이턴시, 작은 패킷 역효과
  • 최종 조합 - 델타+양자화+비트패킹+LZ4 = 78.6% 절약
