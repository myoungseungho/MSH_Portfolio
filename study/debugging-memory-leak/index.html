메모리가 계속 늘어나요

메모리 누수(Memory Leak) 찾기 — CRT 디버그 힙, 스냅샷 비교

Part 1. 메모리 누수가 뭐야?

서버가 오래 돌면 메모리가 계속 늘어나요

메모리 누수(Memory Leak): new로 할당한 메모리를 delete하지 않아서 계속 쌓이는 현상

게임 서버처럼 24시간 돌아가는 프로그램에서는 작은 누수도 큰 문제가 된다.

// 누수 예시 void ProcessPacket(Packet* pPacket) { char* pBuffer = new char[1024]; // 할당 if (pPacket->IsInvalid()) { return; // 🚨 여기서 리턴하면 pBuffer가 해제 안 됨! } // ... 처리 ... delete[] pBuffer; // 여기까지 안 옴 }

Part 2. CRT 디버그 힙으로 찾기

Visual Studio에서 누수를 찾으려면?

CRT 디버그 힙을 활성화하면 프로그램 종료 시 누수된 메모리를 출력해준다.

// main.cpp 또는 stdafx.cpp 맨 위에 추가 #define _CRTDBG_MAP_ALLOC #include <stdlib.h> #include <crtdbg.h> // main() 시작 부분에 추가 int main() { // 프로그램 종료 시 누수 리포트 출력 _CrtSetDbgFlag(_CRTDBG_ALLOC_MEM_DF | _CRTDBG_LEAK_CHECK_DF); // ... 프로그램 코드 ... return 0; }
어떻게 출력되는데?
// 프로그램 종료 시 출력 창에: Detected memory leaks! Dumping objects -> {18364} normal block at 0x00A23B40, 1024 bytes long. Data: < > CD CD CD CD CD CD CD CD {18363} normal block at 0x00A23700, 256 bytes long. Data: <Player > 50 6C 61 79 65 72 00 00 // {18364} = 할당 번호 (중요!) // 1024 bytes = 크기 // CD CD CD = 초기화 안 된 메모리 패턴

Part 3. 할당 번호로 범인 찾기

{18364}가 어디서 할당됐는지 어떻게 알아?

해당 할당 번호에서 자동으로 멈추게 설정할 수 있다.

// main() 시작 부분에 추가 _CrtSetBreakAlloc(18364); // 18364번째 할당에서 중단점! // 또는 Watch 창에서 실행 중에 설정: {,,ucrtbased.dll}_crtBreakAlloc = 18364

1 누수 리포트에서 할당 번호 확인

예: {18364}

2 _CrtSetBreakAlloc(18364) 추가

main() 시작 부분에 넣고 재실행

3 자동으로 멈춤

18364번째 할당이 일어날 때 중단점 히트 → 콜스택 확인

4 콜스택으로 누수 위치 파악

어디서 할당했는지, 왜 해제가 안 됐는지 분석

Part 4. 메모리 스냅샷 비교

실행 중에 누수를 찾고 싶어 (종료 안 하고)

메모리 스냅샷을 찍어서 비교한다.

Debug → Windows → Diagnostic Tools → Memory 탭

// 코드로 스냅샷 비교하기 _CrtMemState s1, s2, sDiff; // 스냅샷 1 (시작 시점) _CrtMemCheckpoint(&s1); // ... 테스트 코드 실행 ... // 스냅샷 2 (종료 시점) _CrtMemCheckpoint(&s2); // 차이 계산 if (_CrtMemDifference(&sDiff, &s1, &s2)) { _CrtMemDumpStatistics(&sDiff); // 증가한 메모리 출력 }
출력이 어떻게 나와?
// 스냅샷 차이 출력 예: 0 bytes in 0 Free Blocks. 102400 bytes in 100 Normal Blocks. ← 100개의 블록이 해제 안 됨! 0 bytes in 0 CRT Blocks. 0 bytes in 0 Ignore Blocks. 0 bytes in 0 Client Blocks. Largest number used: 204800 bytes. Total allocations: 307200 bytes.

Part 5. VS 진단 도구 사용

GUI로 편하게 보고 싶어

기능 설명

Part 6. 일반적인 누수 패턴

패턴 예시 해결책
조기 리턴 예외 상황에서 delete 전에 return RAII, unique_ptr 사용
예외 발생 throw 전에 delete 안 함 스마트 포인터
컨테이너에 포인터 vector<T*> 클리어 시 delete 누락 vector<unique_ptr<T>>
순환 참조 shared_ptr끼리 서로 참조 weak_ptr 사용
// 나쁜 코드 → 좋은 코드 // ❌ 누수 위험 void Process() { char* pBuffer = new char[1024]; if (Error()) return; // 누수! delete[] pBuffer; } // ✅ 안전 (unique_ptr) void Process() { auto pBuffer = std::make_unique<char[]>(1024); if (Error()) return; // 자동 해제! } // ✅ 안전 (RAII) void Process() { std::vector<char> buffer(1024); if (Error()) return; // 자동 해제! }

핵심 정리

  • CRT 디버그 힙: _CRTDBG_LEAK_CHECK_DF로 종료 시 누수 리포트
  • _CrtSetBreakAlloc: 특정 할당 번호에서 자동 중단
  • 메모리 스냅샷: 두 시점 간 메모리 차이 비교
  • VS 진단 도구: GUI로 스냅샷 찍고 비교
  • 예방: unique_ptr, RAII 패턴 사용
