Unity Addressables 완전 정복

경로 대신 "주소"로 에셋을 관리하는 현대적 방법

Part 1. 기존 방식의 문제

Resources 폴더의 뭐가 문제야?

Unity의 Resources 폴더는 안티패턴이 되었어

Resources 폴더 문제점: 1. 빌드 시 모두 포함 ┌─────────────────────────────────────────────┐ │ Resources/ │ │ ├── 캐릭터_1.prefab ← 안 쓰여도 빌드에 │ │ ├── 캐릭터_2.prefab ← 포함됨! │ │ ├── 미사용_텍스처.png ← 용량만 차지 │ │ └── 테스트_에셋.fbx ← 삭제 깜빡! │ └─────────────────────────────────────────────┘ → 빌드 용량 ↑, 시작 시간 ↑ 2. 경로 하드코딩 Resources.Load("Characters/Warrior/Prefabs/WarriorPrefab") → 경로 바뀌면? 전부 찾아서 수정! → 오타나면? 런타임 에러! 3. 에디터에서만 빠름 개발 중: 빠름 (에디터 직접 접근) 빌드 후: 느림 (바이너리 검색 필요)

Part 2. Addressables란?

Addressables가 뭔데?

Addressables = 에셋을 "주소"로 관리하는 시스템

경로가 아닌 논리적 주소 (Address)로 에셋 참조

Resources vs Addressables: Resources (경로 기반): ┌─────────────────────────────────────────────┐ │ Resources.Load("Prefabs/Characters/Warrior")│ │ ↑ │ │ 물리적 경로 (바뀔 수 있음) │ └─────────────────────────────────────────────┘ Addressables (주소 기반): ┌─────────────────────────────────────────────┐ │ Addressables.LoadAssetAsync("warrior") │ │ ↑ │ │ 논리적 주소 (경로와 무관!) │ │ │ │ "warrior" 주소 → 실제 위치는 어디든 OK │ │ - 로컬 번들 │ │ - 리모트 CDN │ │ - 빌드 안에 포함 │ └─────────────────────────────────────────────┘

Part 3. 핵심 개념

Addressables의 핵심 개념은?

Address, Label, Group 3가지를 이해하면 끝!

Addressables 핵심 개념: 1. Address (주소) ┌─────────────────────────────────────────────┐ │ 에셋의 고유 식별자 (문자열) │ │ 예: "character_warrior", "weapon_sword" │ │ │ │ 에셋 파일: Assets/Models/Char/warrior.fbx │ │ 주소: "warrior" ← 짧고 의미있게! │ └─────────────────────────────────────────────┘ 2. Label (라벨) ┌─────────────────────────────────────────────┐ │ 에셋에 붙이는 태그 (여러 개 가능) │ │ │ │ warrior.prefab: [character] [stage1] │ │ archer.prefab: [character] [stage2] │ │ boss.prefab: [character] [boss] │ │ │ │ → "character" 라벨로 전체 캐릭터 로드! │ │ → "stage1" 라벨로 1스테이지 에셋만 로드! │ └─────────────────────────────────────────────┘ 3. Group (그룹) ┌─────────────────────────────────────────────┐ │ 에셋 번들 단위 (빌드/배포 단위) │ │ │ │ [Local Group] → 빌드에 포함 │ │ ├── core_ui │ │ └── player_character │ │ │ │ [Remote Group] → 서버에서 다운로드 │ │ ├── stage1_assets │ │ └── stage2_assets │ └─────────────────────────────────────────────┘

Part 4. 기본 사용법

코드에서 어떻게 써?

비동기 로딩이 기본! async/await 또는 콜백

// 1. 단일 에셋 로드 (async/await) async void LoadCharacter() { var handle = Addressables.LoadAssetAsync<GameObject>("warrior"); GameObject prefab = await handle.Task; Instantiate(prefab); // 사용 후 해제 필수! Addressables.Release(handle); } // 2. 라벨로 여러 에셋 로드 async void LoadAllCharacters() { var handle = Addressables.LoadAssetsAsync<GameObject>( "character", // 라벨 (obj) => { Debug.Log($"Loaded: {obj.name}"); } ); await handle.Task; } // 3. 씬 로드 async void LoadStage() { var handle = Addressables.LoadSceneAsync("stage1"); await handle.Task; }

Part 5. 메모리 관리

메모리 관리는 어떻게 해?

Reference Counting 기반! Release 안 하면 메모리 누수

Reference Counting 동작: LoadAssetAsync("warrior") 호출: ┌─────────────────────────────────────┐ │ warrior.prefab │ │ RefCount: 0 → 1 │ └─────────────────────────────────────┘ 또 LoadAssetAsync("warrior") 호출: ┌─────────────────────────────────────┐ │ warrior.prefab │ │ RefCount: 1 → 2 (새로 로드 안 함!) │ └─────────────────────────────────────┘ Release(handle) 호출: ┌─────────────────────────────────────┐ │ warrior.prefab │ │ RefCount: 2 → 1 (아직 메모리에) │ └─────────────────────────────────────┘ Release(handle) 또 호출: ┌─────────────────────────────────────┐ │ warrior.prefab │ │ RefCount: 1 → 0 (메모리에서 해제!)│ └─────────────────────────────────────┘ 주의! - Load 횟수 = Release 횟수 (반드시!) - Release 안 하면 영원히 메모리에 - 씬 전환해도 자동 해제 안 됨!
// 올바른 메모리 관리 class CharacterSpawner : MonoBehaviour { AsyncOperationHandle<GameObject> _handle; async void Start() { _handle = Addressables.LoadAssetAsync<GameObject>("warrior"); var prefab = await _handle.Task; Instantiate(prefab); } void OnDestroy() { // 반드시 해제! if (_handle.IsValid()) Addressables.Release(_handle); } }

Part 6. 원격 에셋 배포

CDN에서 에셋 다운로드는 어떻게?

Group 설정에서 Remote로 바꾸면 끝!

원격 배포 설정: 1. Addressables Groups 창에서: ┌─────────────────────────────────────────────┐ │ [Remote_Characters] │ │ Build Path: Remote │ │ Load Path: https://cdn.mygame.com/ │ │ ├── warrior.prefab │ │ └── archer.prefab │ └─────────────────────────────────────────────┘ 2. 빌드 후 생성되는 파일: ┌─────────────────────────────────────────────┐ │ ServerData/ │ │ ├── remote_characters_xxx.bundle ← CDN에! │ │ ├── catalog_xxx.json ← CDN에! │ │ └── catalog_xxx.hash ← CDN에! │ └─────────────────────────────────────────────┘ 3. 코드는 동일! (위치 신경 안 씀) Addressables.LoadAssetAsync("warrior"); → 로컬에 없으면 자동으로 CDN에서 다운로드!
// 다운로드 크기 확인 및 진행률 async void DownloadWithProgress() { // 다운로드 크기 확인 var sizeHandle = Addressables.GetDownloadSizeAsync("stage2"); long size = await sizeHandle.Task; Debug.Log($"Download size: {size / 1024}KB"); if (size > 0) { // 다운로드 실행 var downloadHandle = Addressables.DownloadDependenciesAsync("stage2"); while (!downloadHandle.IsDone) { float progress = downloadHandle.PercentComplete; progressBar.value = progress; await Task.Yield(); } Addressables.Release(downloadHandle); } }

Part 7. 베스트 프랙티스

실전에서 주의할 점은?

그룹 설계와 메모리 관리가 핵심!

그룹 설계 가이드: 좋은 그룹 설계: ┌─────────────────────────────────────────────┐ │ [Local_Core] 항상 필요한 것 │ │ ├── 플레이어 캐릭터 │ │ ├── UI 프리팹 │ │ └── 공통 셰이더 │ ├─────────────────────────────────────────────┤ │ [Remote_Stage1] 스테이지 1 전용 │ │ ├── stage1 맵 │ │ ├── stage1 적 │ │ └── stage1 BGM │ ├─────────────────────────────────────────────┤ │ [Remote_Stage2] 스테이지 2 전용 │ │ ... │ └─────────────────────────────────────────────┘ 피해야 할 패턴: ┌─────────────────────────────────────────────┐ │ ✗ 모든 에셋을 하나의 그룹에 │ │ ✗ 작은 에셋을 각각 개별 그룹으로 │ │ ✗ 상호 참조가 많은 에셋을 다른 그룹에 │ │ ✗ Release 호출 안 함 │ └─────────────────────────────────────────────┘

핵심 정리

  • Addressables: 경로 대신 주소로 에셋 관리
  • Address: 에셋 식별자, Label: 태그, Group: 빌드 단위
  • 비동기 로딩 기본 (LoadAssetAsync)
  • Reference Counting: Load ↔ Release 짝 맞추기
  • Remote Group으로 CDN 배포 가능
