IPC, 프로세스끼리 어떻게 통신해?

공유 메모리 vs 파이프 vs 소켓, 2.2배 성능 차이의 비밀

Part 1. IPC가 왜 필요해?

프로세스끼리 그냥 변수로 통신하면 안 돼?

안 돼! 프로세스는 각자 독립된 메모리 공간을 가지거든.

[프로세스 A] [프로세스 B] ┌──────────┐ ┌──────────┐ │ 내 메모리 │ ? │ 내 메모리 │ │ (독립적) │ │ (독립적) │ └──────────┘ └──────────┘ A의 0x1000 주소 ≠ B의 0x1000 주소 → 완전히 다른 물리 메모리!
그럼 프로세스끼리 데이터 주고받으려면?

"중간 다리"가 필요해.

그게 바로 IPC (Inter-Process Communication)야.

[IPC 방식들 = 중간 다리 역할] • 파이프 (Pipe) • 공유 메모리 (Shared Memory) • 소켓 (Socket) • 메시지 큐 (Message Queue) ...

Part 2. 파이프는 어떻게 동작해?

[파이프 동작] [프로세스 A] [프로세스 B] │ │ │ write() read() │ ▼ ▼ ┌──────────────────────────────────────────────────┐ │ 커널 버퍼 (파이프) │ │ [ 데이터 데이터 데이터 ] │ └──────────────────────────────────────────────────┘

• A가 파이프에 쓰면 → 커널이 버퍼에 보관

• B가 파이프에서 읽으면 → 커널이 전달

근데 매번 커널을 거치잖아?

응, 그래서 시스템 콜 오버헤드가 있어.

하지만 커널이 동기화를 알아서 해줘!

// 파이프 코드 - 엄청 간단 [A: 쓰기] WriteFile(pipe, data, size); // 끝! [B: 읽기] ReadFile(pipe, buffer, size); // 끝! → 데이터 없으면 자동으로 대기 (blocking) → 동기화 코드 안 써도 됨!

Part 3. 공유 메모리는 어떻게 동작해?

[공유 메모리 동작] [프로세스 A] [프로세스 B] │ │ │ 매핑 매핑 │ ▼ ▼ ┌───────────────────────────────────────────┐ │ 물리 메모리 (공유 영역) │ │ [ 데이터 ] │ └───────────────────────────────────────────┘

• A와 B가 같은 물리 메모리를 자기 주소에 매핑

• A가 쓰면 → B도 바로 보임 (같은 메모리니까)

어? 그럼 커널 안 거쳐?

맞아! 최초 매핑할 때만 커널 가고, 그 뒤론 안 감.

그래서 가장 빠름!

그럼 무조건 공유 메모리 쓰면 되겠네?

함정이 있어...

[공유 메모리의 함정] [A가 쓰는 중...] [B가 읽는 중...] ↓ ↓ 같은 메모리 동시 접근 = 💥 Race Condition! → 동기화를 직접 구현해야 해!
// 공유 메모리 코드 - 동기화 직접 해야 함 [A: 쓰기] Lock(); memcpy(sharedMem, data, size); Unlock(); Signal(); // "다 썼어!" [B: 읽기] Wait(); // "썼다고 신호 올 때까지 대기" Lock(); memcpy(buffer, sharedMem, size); Unlock(); → 락, 시그널, 대기 다 직접 구현해야 함! → 실수하면 데드락, 레이스 컨디션...

Part 4. 그래서 파이프 vs 공유 메모리, 뭘 써?

[비유] [파이프] = 우체통 → 편지 넣으면 우체부(커널)가 배달 → 내가 신경 쓸 거 없음 [공유 메모리] = 화이트보드에 직접 쓰기 → 지우개, 마커 관리 내가 함 → 누가 언제 쓰고 읽는지 내가 관리
파이프 공유 메모리
속도 느림 (커널 거침) 빠름 (커널 안 거침)
동기화 커널이 해줌 직접 구현
구현 난이도 쉬움 어려움
버그 가능성 낮음 높음 (레이스 컨디션)

결론:

• 성능 최우선 + 동기화 자신 있음 → 공유 메모리

• 빠른 구현 + 안정성 중요 → 파이프

Part 5. 소켓은 왜 쓰는 거야?

파이프랑 공유 메모리 있는데 소켓은 왜?

파이프, 공유 메모리는 같은 PC에서만 가능해.

다른 PC랑 통신하려면? 소켓 필수!

[소켓 동작] [프로세스 A] [프로세스 B] │ │ │ send() recv() │ ▼ ▼ ┌──────────────────────────────────────────────────┐ │ TCP/IP 스택 (커널) │ │ 패킷화 → 버퍼 → 프로토콜 처리 → 전달 │ └──────────────────────────────────────────────────┘ → localhost로 쓰면 같은 PC에서도 IPC 가능 → 하지만 TCP/IP 프로토콜 처리 = 오버헤드

Part 6. 실측 테스트

테스트: 64KB 데이터를 10,000번 전송 (총 625MB)

공유 메모리가 소켓보다 2.2배 빠름!
왜 이런 차이가 나?
[공유 메모리] 프로세스 A ──memcpy──> 공유영역 ──memcpy──> 프로세스 B (유저모드) (유저모드) [파이프/소켓] 프로세스 A ──WriteFile──> 커널버퍼 ──ReadFile──> 프로세스 B (시스템 콜) (시스템 콜) → 커널 개입이 적을수록 빠르다!

Part 7. 실제로 어떻게 써?

파이프는 언제 쓰면 좋아?

간단한 단방향 통신. 예: 로그 수집기

// 파이프 예시: 로그 수집기 HANDLE hRead, hWrite; CreatePipe(&hRead, &hWrite, NULL, 0); // 메인 프로세스: 로그 전송 void SendLog(const char* msg) { WriteFile(hWrite, msg, strlen(msg), &written, NULL); // 끝! 동기화 코드 없음 } // 로그 수집 프로세스: 수신 void LogReceiver() { while (ReadFile(hRead, buf, size, &read, NULL)) { // 데이터 없으면 자동 대기 printf("[LOG] %s\n", buf); } }
공유 메모리는 언제 쓰면 좋아?

대용량 + 고성능. 예: 게임 물리엔진 ↔ 렌더러

// 공유 메모리 예시: 물리엔진 ↔ 렌더러 struct SharedState { LONG lock; float positions[1000][3]; // 위치 데이터 }; // 공유 메모리 생성 HANDLE hMap = CreateFileMapping(..., "GameState"); SharedState* state = MapViewOfFile(hMap, ...); // 물리 엔진: 위치 업데이트 void PhysicsUpdate() { while (InterlockedExchange(&state->lock, 1)) { } // 락 // 위치 데이터 업데이트 state->positions[i][1] -= 0.1f; // 중력 InterlockedExchange(&state->lock, 0); // 언락 } // 렌더러: 위치 읽기 void RenderUpdate() { while (InterlockedExchange(&state->lock, 1)) { } // 락 // 위치 데이터 복사해서 렌더링 InterlockedExchange(&state->lock, 0); // 언락 }

Part 8. 상황별 선택 가이드

// 선택 로직 IPCType Choose(bool samePC, bool highPerf, bool simple) { if (!samePC) return Socket; // 다른 PC면 소켓 필수 if (highPerf) return SharedMem; // 고성능 필요하면 공유메모리 return Pipe; // 기본은 파이프 (안전) }
상황 추천 이유
Gate ↔ Game 서버 소켓 다른 PC일 수 있음
Game ↔ DB 서버 소켓 DB는 보통 별도 서버
같은 프로세스 내 스레드 공유 메모리 (락) 이미 메모리 공유됨
로그 수집 프로세스 파이프 간단한 단방향
고성능 데이터 공유 공유 메모리 2배 빠름

핵심 정리

  • IPC = 프로세스 간 통신 (독립된 메모리라서 필요)
  • 파이프 = 커널 버퍼 경유, 동기화 자동, 구현 쉬움
  • 공유 메모리 = 직접 메모리 공유, 가장 빠름, 동기화 직접
  • 소켓 = 다른 PC 통신 가능, TCP/IP 오버헤드
  • 실측 = 공유 메모리 15,252 MB/s, 소켓 6,989 MB/s (2.2배)
  • 선택 = 다른 PC면 소켓, 고성능이면 공유메모리, 기본은 파이프
