예측 로딩

플레이어가 어디로 갈지 어떻게 알까?

Part 1. 예측 로딩이란?

예측 로딩이 뭐야?

예측 로딩 = 플레이어가 필요로 하기 전에 미리 에셋을 로드

"지금 필요해!"가 아니라 "곧 필요할 거야"를 예측

반응형 로딩 (나쁜 예): ─────────────────────────────────────────────→ 시간 플레이어: ───────────────────→ 문 열기! 에셋 로드: ┌──────┐ │로딩! │ └──────┘ ↑ 여기서 히치 발생! 예측 로딩 (좋은 예): ─────────────────────────────────────────────→ 시간 플레이어: ── 문 앞으로 이동 ──→ 문 열기! 에셋 로드: ──┌──────┐─────────────────────── │로딩 │ (미리 완료) └──────┘ ↑ 문 앞에 왔을 때 로딩 시작 → 문 열 때는 이미 로딩 완료! ✓

Part 2. 예측의 종류

어떻게 예측해?

크게 4가지 예측 방법이 있어:

예측 방법 비교: 1. 거리 기반 (Distance-based) ┌─────────────────────────────────────┐ │ ●──────────────→ │ │ 플레이어 반경 내 에셋 로드 │ │ └─── 100m 반경 ───┘ │ └─────────────────────────────────────┘ 장점: 구현 간단 단점: 방향 무시, 불필요한 로딩 많음 2. 방향 기반 (Velocity-based) ┌─────────────────────────────────────┐ │ ○ 예측 위치 │ │ ↗ │ │ ●───→ 이동 방향 │ │ 플레이어 │ └─────────────────────────────────────┘ 장점: 이동 방향만 로드 단점: 급회전 시 예측 실패 3. 시선 기반 (Look-at) ┌─────────────────────────────────────┐ │ ●───👁───→ 보는 방향 로드 │ │ 플레이어 │ └─────────────────────────────────────┘ 장점: 플레이어 의도 반영 단점: VR/FPS 외엔 적용 어려움 4. 게임 로직 기반 (Context-aware) ┌─────────────────────────────────────┐ │ 퀘스트: "보스방으로 가라" │ │ ●─ ─ ─ ─ ─→ 🚪 보스방 │ │ 플레이어 (보스 에셋 로드!) │ └─────────────────────────────────────┘ 장점: 가장 정확 단점: 구현 복잡

Part 3. 속도 기반 예측

이동 방향으로 예측하는 건 어떻게 해?

현재 속도 × 시간으로 미래 위치 예측

속도 기반 예측 공식: 예측 위치 = 현재 위치 + (속도 × 예측 시간) 예시: 현재 위치: (100, 0, 200) 속도: (10, 0, 5) m/s 예측 시간: 3초 예측 위치 = (100, 0, 200) + (10, 0, 5) × 3 = (100 + 30, 0, 200 + 15) = (130, 0, 215) ┌───────────────────────────────────────┐ │ │ │ (100,200) ●────────→ ○ (130,215) │ │ 현재 예측 위치 │ │ │ │ 이 위치의 청크 에셋을 미리 로드! │ └───────────────────────────────────────┘
// C++ 속도 기반 예측 FVector PredictFuturePosition(float PredictionTime) { FVector CurrentPos = Player->GetActorLocation(); FVector Velocity = Player->GetVelocity(); // 단순 선형 예측 return CurrentPos + Velocity * PredictionTime; } void UpdatePredictiveLoading() { // 3초 후 위치 예측 FVector FuturePos = PredictFuturePosition(3.0f); // 해당 위치의 청크 로드 요청 StreamingManager->RequestChunkAt(FuturePos); }

Part 4. 트리거 볼륨

특정 지역에 들어가면 로딩 시작하는 건?

트리거 볼륨: 특정 영역 진입 시 로딩 시작

가장 확실하고 간단한 예측 방법

트리거 볼륨 배치: ┌─────────────────────────────────────────────┐ │ │ │ ┌───────────┐ ┌─────────────────────┐ │ │ │ 트리거 │ │ 다음 방 │ │ │ │ 볼륨 │ │ (에셋 로드 대상) │ │ │ │ │ │ │ │ │ └───────────┘ └─────────────────────┘ │ │ ↑ │ │ ● 플레이어가 진입하면 │ │ 다음 방 에셋 로드 시작! │ │ │ └─────────────────────────────────────────────┘ 실제 게임 예시: ┌──────────────────────────────────────────────────┐ │ 현재 방 │ 복도 (트리거) │ 보스방 (로드 대상) │ │ │ │ │ │ ●────→ [진입] │ 보스 모델, 텍스처, │ │ │ │ 이펙트, BGM 로드 │ └──────────────────────────────────────────────────┘ 보스방 문 앞에 도착할 때쯤 로딩 완료!

Part 5. 예측 실패 처리

예측이 틀리면 어떻게 해?

예측은 틀릴 수 있다! 대비책이 필요

예측 실패 시나리오: 예측: 플레이어가 동쪽으로 갈 것 현실: 플레이어가 갑자기 서쪽으로 회전! ┌─────────────────────────────────────────────┐ │ │ │ 서쪽 청크 ●→→→→ 동쪽 청크 │ │ (로드 안됨) 플레이어 (로드 중) │ │ ↓ │ │ 갑자기 회전! │ │ ↓ │ │ ←←←←←←← ● │ │ (로드 시작!) │ │ │ └─────────────────────────────────────────────┘ 대비책: 1. 폴백 에셋: 저품질 에셋을 항상 준비 고품질 로딩 안됨 → 저품질 먼저 보여주기 2. 최소 거리 로딩: 플레이어 바로 주변은 항상 로드 예측과 무관하게 안전 영역 확보 3. 로드 우선순위 재조정: 방향 바뀌면 즉시 우선순위 변경 동쪽 로딩 중단 → 서쪽 로딩 시작

Part 7. 예측 로딩 최적화

예측 로딩을 더 효율적으로 하려면?

로딩 우선순위와 버짓 관리가 핵심

우선순위 기반 예측 로딩: 우선순위 = (필요 확률) × (중요도) / (로딩 시간) 예시: ┌────────────────────────────────────────────────┐ │ 에셋 │ 확률 │ 중요도 │ 우선순위 │ ├────────────────────────────────────────────────┤ │ 이동 방향 텍스처 │ 90% │ 1.0 │ HIGH │ │ 플레이어 뒤 청크 │ 10% │ 0.5 │ LOW │ │ 퀘스트 목적지 │ 70% │ 1.0 │ HIGH │ │ 랜덤 NPC 대화 │ 20% │ 0.3 │ LOW │ └────────────────────────────────────────────────┘ 로딩 버짓 분배: ┌─────────────────────────────────────────┐ │ 프레임당 스트리밍 버짓: 2ms │ ├─────────────────────────────────────────┤ │ HIGH 우선순위: 1.5ms │ │ MEDIUM 우선순위: 0.4ms │ │ LOW 우선순위: 0.1ms │ └─────────────────────────────────────────┘ → 예측 확률 높은 것에 버짓 집중!
