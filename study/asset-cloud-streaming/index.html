Cloud Streaming

클라우드 기반 에셋 전송과 실시간 스트리밍 기술

Part 1: 클라우드 스트리밍이란

Q1: 게임에서 "클라우드 스트리밍"이 필요한 이유가 뭔가요?

게임 설치 없이 즉시 플레이하고 싶기 때문입니다.

전통적인 게임 설치 방식의 문제:

[전통 방식 - 설치 후 플레이]

사용자: "이 게임 해보고 싶다!"
    ↓
다운로드: 100GB (30분~2시간 대기)
    ↓
설치: 디스크 공간 필요 (120GB)
    ↓
패치: 추가 20GB 다운로드
    ↓
드디어 플레이!

→ 총 소요시간: 1~3시간
→ 필요 디스크: 120GB+

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[클라우드 스트리밍 - 즉시 플레이]

사용자: "이 게임 해보고 싶다!"
    ↓
클릭!
    ↓
5초 후 플레이!

→ 총 소요시간: 5초
→ 필요 디스크: 0GB

클라우드 스트리밍의 두 가지 형태:

1. 에셋 스트리밍 (Asset Streaming)
   - 게임은 로컬에서 실행
   - 에셋만 필요할 때 클라우드에서 다운로드
   - 예: Fortnite의 온디맨드 텍스처

2. 클라우드 게이밍 (Cloud Gaming)
   - 게임이 서버에서 실행
   - 영상만 클라이언트로 스트리밍
   - 예: GeForce NOW, Xbox Cloud Gaming
Q2: 클라우드에서 데이터를 받아오면 로컬보다 얼마나 느린가요?

1000배 이상 느립니다. 하지만 "미리 받아두기"로 체감 차이를 없앨 수 있습니다.

이 격차를 극복하는 방법:

// 예측적 프리페칭 (Predictive Prefetching)
class CloudAssetPrefetcher {
    void OnPlayerMovement(Vector3 newPosition, Vector3 velocity) {
        // 플레이어가 향하는 방향 예측
        Vector3 predictedPosition = newPosition + velocity * PREFETCH_TIME_AHEAD;

        // 해당 영역의 에셋 미리 요청
        std::vector<AssetID> neededAssets =
            m_WorldGrid.GetAssetsInRadius(predictedPosition, PREFETCH_RADIUS);

        for (const auto& assetId : neededAssets) {
            if (!m_LocalCache.Contains(assetId)) {
                // 클라우드에서 미리 다운로드 시작
                m_CloudFetcher.BeginDownloadAsync(assetId, Priority::Prefetch);
            }
        }
    }

    static constexpr float PREFETCH_TIME_AHEAD = 10.0f;  // 10초 앞
    static constexpr float PREFETCH_RADIUS = 500.0f;      // 500m 반경
};

Part 2: CDN과 에지 서버

Q3: CDN이 뭔가요? 왜 게임 배포에 필수인가요?

CDN(Content Delivery Network)은 전 세계에 분산된 서버 네트워크입니다.

CDN 없이 배포할 때의 문제:

[CDN 없음 - 단일 서버]

                    미국 서버
                        │
        ┌───────────────┼───────────────┐
        │               │               │
    한국 유저        미국 유저       유럽 유저
    (200ms)          (10ms)         (150ms)

문제점:
1. 한국 유저: 매 요청마다 태평양 왕복 (200ms)
2. 서버 부하 집중: 전세계 트래픽이 한 곳으로
3. 대역폭 비용: 모든 트래픽이 오리진에서 발생

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[CDN 사용 - 에지 서버 분산]

                    미국 오리진
                        │
         ┌──────────────┼──────────────┐
         ↓              ↓              ↓
    한국 에지        미국 에지       유럽 에지
    (서울 IDC)      (시카고)        (프랑크푸르트)
         │              │              │
    한국 유저        미국 유저       유럽 유저
    (5ms)           (10ms)          (5ms)

장점:
1. 모든 유저가 가까운 서버에서 다운로드
2. 오리진 부하 분산
3. 대역폭 비용 절감 (에지에서 캐시 히트)

주요 CDN 서비스 비교:

CloudFront (AWS)
├─ 엣지 로케이션: 400+
├─ 한국 POP: 서울, 인천
├─ 가격: $0.085/GB (첫 10TB)
└─ 특징: Lambda@Edge로 로직 실행 가능

Fastly
├─ 엣지 로케이션: 90+
├─ 특징: 즉시 캐시 무효화 (~150ms)
├─ 가격: $0.12/GB
└─ 게임사: Epic Games 사용

Akamai
├─ 엣지 로케이션: 4,200+
├─ 특징: 가장 큰 네트워크
├─ 가격: 협상 기반
└─ 게임사: PlayStation, Xbox 사용
Q4: 에지 서버는 어떻게 "가까운 서버"를 결정하나요?

DNS 기반 라우팅과 Anycast IP를 사용합니다.

[DNS 기반 라우팅]

클라이언트: "cdn.mygame.com의 IP 주소는?"
      │
      ↓
DNS 서버: 클라이언트 IP 확인 → 위치 추정
      │
      ├─ 한국 IP → "서울 에지 IP: 1.2.3.4"
      ├─ 미국 IP → "시카고 에지 IP: 5.6.7.8"
      └─ 유럽 IP → "프랑크푸르트 에지 IP: 9.10.11.12"

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[Anycast IP 라우팅]

동일한 IP (예: 192.0.2.1)가 전세계 여러 서버에 할당

클라이언트 → 192.0.2.1 요청
      │
      ↓ BGP 라우팅 (네트워크 레벨)
      │
      └─ 자동으로 가장 가까운 서버로 연결

장점: DNS TTL 대기 없이 즉시 최적 서버 연결
단점: 설정 복잡, AS 번호 필요

CDN 요청 흐름:

1. 클라이언트 → 에지 서버 요청
   GET /assets/texture_001.dds

2. 에지 서버 캐시 확인
   ├─ Cache Hit: 즉시 응답 (5ms)
   └─ Cache Miss: 오리진에서 가져옴

3. Cache Miss 시:
   에지 → 오리진 서버 요청
   오리진 → 에지 응답 (100ms)
   에지 → 클라이언트 응답
   에지: 캐시에 저장 (다음 요청을 위해)

4. 캐시 정책:
   Cache-Control: public, max-age=31536000
   → 1년간 캐시 (에셋은 버전으로 관리)

Q5: 네트워크 상태가 나빠지면 어떻게 대응하나요?

적응형 비트레이트(ABR)로 품질을 동적 조절합니다.

비디오 스트리밍(Netflix, YouTube)에서 시작된 기술:

[적응형 비트레이트 동작]

시간 →

대역폭:  ████████░░░░████████████████░░░░░░████
         고속     저속    고속              저속   고속

품질:    1080p    720p    1080p            480p   1080p
         ─────────────────────────────────────────────
                  ↑                        ↑
              품질 하향                 추가 하향
              (버퍼링 방지)            (네트워크 악화)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[게임 에셋에 적용]

대역폭:  ████████░░░░████████████████░░░░░░████

텍스처:  4K       2K      4K               1K     4K
LOD:     High    Medium   High             Low    High

→ 느린 네트워크: 저해상도 에셋 먼저 로드
→ 빠른 네트워크: 고해상도로 점진적 업그레이드

게임용 ABR 구현:

class AdaptiveBitrateController {
public:
    enum class QualityTier {
        Ultra,   // 4K 텍스처, 최고 LOD
        High,    // 2K 텍스처
        Medium,  // 1K 텍스처
        Low,     // 512 텍스처, 저품질 메시
        Minimal  // 256 텍스처, 최저 LOD
    };

    QualityTier DetermineQuality() {
        float bandwidth = MeasureBandwidth();     // Mbps
        float latency = MeasureLatency();         // ms
        float bufferLevel = GetBufferLevel();     // 초

        // 대역폭 기반 기본 품질 결정
        QualityTier baseTier;
        if (bandwidth > 100) baseTier = QualityTier::Ultra;
        else if (bandwidth > 50) baseTier = QualityTier::High;
        else if (bandwidth > 20) baseTier = QualityTier::Medium;
        else if (bandwidth > 5) baseTier = QualityTier::Low;
        else baseTier = QualityTier::Minimal;

        // 버퍼 레벨에 따른 조정
        if (bufferLevel < 2.0f) {
            // 버퍼 부족 - 품질 낮춤
            baseTier = std::min(baseTier + 1, QualityTier::Minimal);
        } else if (bufferLevel > 10.0f && latency < 50) {
            // 버퍼 여유 + 낮은 지연 - 품질 높임 시도
            baseTier = std::max(baseTier - 1, QualityTier::Ultra);
        }

        return baseTier;
    }

private:
    float MeasureBandwidth() {
        // 최근 다운로드 속도의 이동평균
        return m_BandwidthSamples.GetEWMA(0.3f);
    }
};
Q6: 대역폭은 어떻게 측정하나요?

실제 다운로드 속도를 지속적으로 샘플링합니다.

class BandwidthEstimator {
public:
    void OnDownloadComplete(size_t bytes, float duration) {
        float bps = (bytes * 8) / duration;  // bits per second
        float mbps = bps / 1'000'000.0f;

        // 지수 가중 이동 평균 (EWMA)
        // 최신 샘플에 더 높은 가중치
        m_EstimatedBandwidth =
            m_Alpha * mbps + (1.0f - m_Alpha) * m_EstimatedBandwidth;

        // 변동성 추적 (네트워크 안정성 판단)
        float deviation = std::abs(mbps - m_EstimatedBandwidth);
        m_Variance = m_Alpha * deviation + (1.0f - m_Alpha) * m_Variance;
    }

    float GetConservativeEstimate() {
        // 안전한 추정치: 평균 - 표준편차
        // 불안정한 네트워크에서 버퍼링 방지
        return m_EstimatedBandwidth - std::sqrt(m_Variance);
    }

    float GetAggressiveEstimate() {
        // 공격적 추정치: 품질 우선
        return m_EstimatedBandwidth;
    }

private:
    float m_EstimatedBandwidth = 50.0f;  // 초기값 50Mbps
    float m_Variance = 10.0f;
    float m_Alpha = 0.3f;  // 학습률
};
핵심: 단순 평균이 아닌 EWMA(지수 가중 이동 평균)를 사용하여 최근 네트워크 상태를 더 정확히 반영합니다.

Q8: MIP 레벨이나 LOD를 부분적으로 다운로드할 수 있나요?

네, HTTP Range 요청으로 파일의 일부분만 다운로드합니다.

class PartialAssetFetcher {
public:
    // 텍스처의 특정 MIP 레벨만 다운로드
    void FetchMipLevel(const std::string& assetPath, int mipLevel) {
        const auto& manifest = m_Manifest.GetAsset(assetPath);
        const auto& mipInfo = manifest.mip_levels[mipLevel];

        // HTTP Range 요청 생성
        HttpRequest request;
        request.url = GetCDNUrl(assetPath);
        request.headers["Range"] =
            fmt::format("bytes={}-{}",
                mipInfo.offset,
                mipInfo.offset + mipInfo.size - 1);

        // 비동기 다운로드
        m_HttpClient.GetAsync(request,
            [this, assetPath, mipLevel](const HttpResponse& response) {
                if (response.status == 206) {  // Partial Content
                    // MIP 데이터만 텍스처에 업로드
                    m_TextureManager.UploadMipLevel(
                        assetPath, mipLevel, response.body);
                }
            });
    }
};

// HTTP Range 요청 예시:
// GET /assets/texture_001.dds HTTP/1.1
// Host: cdn.mygame.com
// Range: bytes=2097152-2621439
//
// 응답:
// HTTP/1.1 206 Partial Content
// Content-Range: bytes 2097152-2621439/4194304
// Content-Length: 524288

추가 지연 감소 기법:

1. 예측 렌더링 (Speculative Rendering)
   - 서버가 예상 입력으로 미리 다음 프레임 렌더링
   - 입력 도착 시 이미 렌더링된 프레임 전송
   - 예측 실패 시 보정 프레임 전송

2. 네거티브 레이턴시 (NVIDIA Reflex 스타일)
   - 입력 → 렌더링 큐 우회
   - 현재 프레임 렌더링 중에도 최신 입력 반영

3. 슬라이스 인코딩 (Slice-based Encoding)
   - 프레임을 여러 조각으로 나눠 병렬 인코딩
   - 첫 슬라이스 완료 즉시 전송 시작

4. 하이브리드 접근
   - UI/커서: 클라이언트에서 로컬 렌더링
   - 게임월드: 서버에서 스트리밍
   - 입력 즉시 반응하는 것처럼 느껴짐

Part 6: 구현 아키텍처

Q11: 실제 클라우드 에셋 시스템은 어떻게 구현하나요?

로컬 캐시 + 백그라운드 다운로더 + 우선순위 스케줄러 조합입니다.

class CloudAssetSystem {
public:
    void Initialize() {
        // 로컬 캐시 초기화 (디스크 + 메모리)
        m_DiskCache.Initialize("./cache", MAX_CACHE_SIZE_GB * 1024 * 1024 * 1024);
        m_MemoryCache.Initialize(MAX_MEMORY_CACHE_MB * 1024 * 1024);

        // 매니페스트 다운로드
        m_Manifest = FetchManifest(MANIFEST_URL);

        // 다운로드 스레드풀 시작
        m_DownloadPool.Start(NUM_DOWNLOAD_THREADS);

        // 대역폭 모니터 시작
        m_BandwidthMonitor.Start();
    }

    AssetHandle LoadAsset(const std::string& path, Priority priority) {
        // 1. 메모리 캐시 확인
        if (auto asset = m_MemoryCache.Get(path)) {
            return asset;
        }

        // 2. 디스크 캐시 확인
        if (m_DiskCache.Contains(path)) {
            auto data = m_DiskCache.Load(path);
            auto asset = DecompressAndLoad(data);
            m_MemoryCache.Put(path, asset);
            return asset;
        }

        // 3. 클라우드에서 다운로드 필요
        AssetHandle handle = CreatePendingHandle(path);

        DownloadRequest request{
            .path = path,
            .url = GetAssetUrl(path),
            .hash = m_Manifest.GetHash(path),
            .priority = priority,
            .callback = [this, path, handle](const std::vector<uint8_t>& data) {
                // 다운로드 완료
                m_DiskCache.Store(path, data);
                auto asset = DecompressAndLoad(data);
                m_MemoryCache.Put(path, asset);
                handle.Resolve(asset);
            }
        };

        m_DownloadScheduler.Enqueue(request);
        return handle;
    }

private:
    DiskCache m_DiskCache;
    LRUCache m_MemoryCache;
    Manifest m_Manifest;
    DownloadScheduler m_DownloadScheduler;
    ThreadPool m_DownloadPool;
    BandwidthMonitor m_BandwidthMonitor;
};
Q12: 다운로드 우선순위는 어떻게 정하나요?

거리, 가시성, 에셋 타입, 품질 레벨을 종합하여 동적으로 결정합니다.

class DownloadScheduler {
public:
    float CalculatePriority(const DownloadRequest& request) {
        float priority = 0.0f;

        // 1. 기본 우선순위 (요청자가 지정)
        switch (request.priority) {
            case Priority::Critical: priority += 1000; break;  // UI, 필수
            case Priority::High:     priority += 100;  break;  // 플레이어 캐릭터
            case Priority::Normal:   priority += 10;   break;  // 일반 오브젝트
            case Priority::Low:      priority += 1;    break;  // 배경
            case Priority::Prefetch: priority += 0.1f; break;  // 미리 로드
        }

        // 2. 카메라 거리 (가까울수록 높은 우선순위)
        if (auto* spatial = request.GetSpatialInfo()) {
            float distance = spatial->GetDistanceToCamera();
            priority += 100.0f / (1.0f + distance * 0.01f);
        }

        // 3. 화면 점유율 (크게 보일수록 높은 우선순위)
        if (auto* bounds = request.GetScreenBounds()) {
            float screenArea = bounds->GetScreenArea();
            priority += screenArea * 50.0f;
        }

        // 4. 에셋 타입 가중치
        priority *= GetTypeWeight(request.assetType);
        // 텍스처 > 메시 > 오디오 > 애니메이션

        // 5. 대기 시간 보정 (오래 기다린 요청 우선순위 상승)
        float waitTime = GetWaitTime(request);
        priority += waitTime * 0.5f;

        return priority;
    }

    void Tick() {
        // 매 프레임 우선순위 재계산
        std::vector<DownloadRequest*> requests = m_PendingQueue.GetAll();

        for (auto* req : requests) {
            req->currentPriority = CalculatePriority(*req);
        }

        // 우선순위 순으로 정렬
        std::sort(requests.begin(), requests.end(),
            [](auto* a, auto* b) {
                return a->currentPriority > b->currentPriority;
            });

        // 대역폭 할당
        float availableBandwidth = m_BandwidthMonitor.GetAvailable();
        AllocateBandwidth(requests, availableBandwidth);
    }
};
주의: 우선순위 역전(Priority Inversion) 방지를 위해 최소 대역폭 보장(starvation prevention)이 필요합니다.

Q14: 오프라인 모드는 어떻게 지원하나요?

핵심 에셋은 미리 다운로드하고, 나머지는 그레이스풀 디그레이드합니다.

class OfflineModeManager {
public:
    enum class ContentTier {
        Essential,   // 게임 실행에 필수 (메뉴, UI, 튜토리얼)
        Core,        // 메인 스토리 컨텐츠
        Optional,    // 사이드 컨텐츠, 고해상도 에셋
        Streaming    // 항상 스트리밍 (유저 생성 컨텐츠)
    };

    void PrepareOfflineMode() {
        // 1. 필수 에셋 다운로드 (필수)
        DownloadTier(ContentTier::Essential);  // ~2GB

        // 2. 코어 에셋 다운로드 (권장)
        if (HasEnoughSpace(CORE_SIZE)) {
            DownloadTier(ContentTier::Core);   // ~10GB
        }

        // 3. 선택 에셋 (공간 여유 시)
        if (HasEnoughSpace(OPTIONAL_SIZE)) {
            DownloadTier(ContentTier::Optional); // ~30GB
        }
    }

    AssetHandle LoadAssetWithFallback(const std::string& path) {
        // 온라인 시도
        if (IsOnline()) {
            return m_CloudSystem.LoadAsset(path);
        }

        // 오프라인 폴백
        if (m_DiskCache.Contains(path)) {
            return m_DiskCache.Load(path);
        }

        // 대체 에셋 사용
        std::string fallbackPath = GetFallbackAsset(path);
        if (!fallbackPath.empty()) {
            return m_DiskCache.Load(fallbackPath);
            // 예: hero_4k.dds → hero_1k.dds
        }

        // 플레이스홀더 반환
        return GetPlaceholderAsset(GetAssetType(path));
    }
};
핵심 원칙: "플레이 가능" > "최고 품질". 에셋이 없어도 게임은 진행 가능해야 하며, 에셋 도착 시 품질 향상.
