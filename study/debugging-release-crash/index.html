릴리즈에서만 터지는 크래시

Debug에서 재현 안 될 때 — Release 디버깅 전략

Part 1. 왜 Release에서만 터지나?

Debug에서는 문제없는데?

Debug와 Release는 완전히 다른 코드다.

최적화, 메모리 레이아웃, 타이밍이 모두 다르다.

// Release에서만 터지는 주요 원인 1. 미초기화 변수 - Debug: 0xCCCCCCCC (항상 같은 값) - Release: 이전 스택 쓰레기 (예측 불가) 2. 타이밍 차이 - Debug: 느려서 레이스 컨디션 안 남 - Release: 빨라서 레이스 컨디션 발생 3. 인라인/최적화 - Debug: 함수 호출 순서 보장 - Release: 인라인 + 재배치로 순서 변경 4. assert 제거 - Debug: assert()에서 멈춤 - Release: assert() 코드 자체가 없음

Part 2. Release 빌드에 PDB 생성

Release에서도 디버깅하려면?

Release 빌드에도 PDB 파일을 생성하면 디버깅 가능.

// Release 설정에서 C/C++ → General → Debug Information Format: /Zi Linker → Debugging → Generate Debug Info: /DEBUG // 최적화는 유지 (/O2) // PDB만 생성하면 됨 // 주의: PDB는 exe와 함께 보관!

Part 3. 부분 최적화 끄기

특정 함수만 최적화를 끄고 싶어

#pragma optimize로 함수 단위 제어 가능.

// 문제 함수만 최적화 끄기 #pragma optimize("", off) void ProblematicFunction() { // 이 함수는 최적화 안 됨 // 변수가 레지스터로 사라지지 않음 // 디버거에서 값 확인 가능 } #pragma optimize("", on) // 다시 켜기 // 또는 전체 파일 최적화 끄기 // 프로젝트 속성 → 파일 선택 → C/C++ → Optimization: Disabled

Part 4. 크래시 덤프 활용

현장에서 덤프를 받았어

1. 덤프 파일과 PDB 파일 준비

2. VS에서 덤프 열기 (File → Open → File)

3. "Debug with Native Only" 클릭

4. Call Stack에서 크래시 위치 확인

Part 5. 로깅 추가

디버거 붙이기 어려운 환경이면?

Release용 로깅을 추가:

// OutputDebugString (DebugView로 확인) OutputDebugString(L"[DEBUG] HP = %d\n", nHP); // 파일 로깅 FILE* fp = fopen("debug.log", "a"); fprintf(fp, "[%s:%d] value = %d\n", __FILE__, __LINE__, value); fclose(fp); // ETW (Windows Event Tracing) - 가장 효율적 TraceLoggingWrite(g_hProvider, "MyEvent", TraceLoggingInt32(value, "Value"));

핵심 정리

  • 미초기화 변수가 가장 흔한 원인
  • Release에도 PDB 생성 (/Zi /DEBUG)
  • #pragma optimize로 부분 최적화 끄기
  • 덤프 + PDB로 사후 분석
