스켈레톤 UI - 인지적 로딩 시간을 줄이는 UX 기법

Part 1. 로딩 스피너 vs 스켈레톤

페이스북이나 유튜브 들어가면 회색 박스가 반짝이다가 내용이 나오던데, 그게 뭐야?

그게 바로 스켈레톤 UI (Skeleton Screen)야!

콘텐츠가 로딩되기 전에 "대략적인 모양"을 미리 보여주는 거야.

스켈레톤 UI 데모 (아래 애니메이션 참고)

예전에는 그냥 빙글빙글 도는 로딩 스피너 썼잖아. 뭐가 다른 거야?

체감 로딩 시간이 달라!

[로딩 스피너 vs 스켈레톤] 로딩 스피너: ┌────────────────────────────┐ │ │ │ ( 빙글빙글 ) │ │ "로딩 중..." │ │ │ └────────────────────────────┘ => 유저: "아무것도 안 보이네... 느리다..." 스켈레톤 UI: ┌────────────────────────────┐ │ ████ ██████████████████ │ │ ████████████ │ │ ████ ██████████████████ │ │ ████████████ │ └────────────────────────────┘ => 유저: "뭔가 나오고 있네! 조금만 기다리자"
🍽️ 비유: 레스토랑

로딩 스피너: "잠시만 기다려주세요" 팻말만 보여줌
=> 언제 나올지 모름, 불안함

스켈레톤 UI: 접시, 포크, 나이프를 먼저 세팅
=> "음식이 곧 나올 것 같다!" 기대감

Part 2. 인지적 로딩 시간 (Perceived Performance)

실제로 더 빨라지는 건 아니잖아?

맞아! 실제 로딩 시간은 같아.

하지만 느껴지는 시간이 다른 거야.

[심리학 연구 결과] Nielsen Norman Group 연구: "사용자는 진행 상황이 보이면 대기 시간을 더 짧게 인식한다" 실험: - 같은 3초 로딩 - 스피너 그룹: "5초쯤 걸린 것 같아요" - 스켈레톤 그룹: "2초쯤 걸린 것 같아요" => 체감 시간 40% 감소!
왜 그런 현상이 일어나?
[인지적 원리] 1. 불확실성 감소 ───────────────────────────────── 스피너: "뭐가 나올지 모름" (불안) 스켈레톤: "이런 형태가 나올 거야" (예측 가능) 2. 진행감 제공 ───────────────────────────────── 스피너: 반복 애니메이션 (진행 안 되는 느낌) 스켈레톤: 점진적 로딩 (뭔가 되고 있는 느낌) 3. 주의 분산 ───────────────────────────────── 스피너: 스피너만 쳐다봄 (시간에 집중) 스켈레톤: 레이아웃 탐색 (시간 인지 감소) 4. 첫 콘텐츠까지 시간 (FCP) ───────────────────────────────── 스피너: 의미 있는 콘텐츠 0% 스켈레톤: 레이아웃이라도 보임 = 일부 완성된 느낌
지표 로딩 스피너 스켈레톤 UI
체감 속도 느리게 느낌 빠르게 느낌
이탈률 높음 낮음
사용자 만족도 낮음 높음
레이아웃 시프트 발생 최소화

Part 3. 스켈레톤 UI 구현 방법

스켈레톤 UI는 어떻게 만들어?

기본적으로 CSS 애니메이션으로 구현해!

[기본 스켈레톤 CSS] /* 스켈레톤 기본 스타일 */ .skeleton { background: linear-gradient( 90deg, #e0e0e0 25%, #f5f5f5 50%, #e0e0e0 75% ); background-size: 200% 100%; animation: shimmer 1.5s infinite; border-radius: 4px; } /* 반짝이는 애니메이션 */ @keyframes shimmer { 0% { background-position: 200% 0; } 100% { background-position: -200% 0; } } /* 다양한 형태 */ .skeleton-circle { width: 48px; height: 48px; border-radius: 50%; } .skeleton-text { height: 16px; margin-bottom: 8px; } .skeleton-text.short { width: 60%; } .skeleton-text.long { width: 100%; }
[React 컴포넌트 예시] // Skeleton.jsx function Skeleton({ width, height, circle }) { return ( <div className="skeleton" style={{ width: width || '100%', height: height || '16px', borderRadius: circle ? Part 4. 좋은 스켈레톤 UI 디자인

그냥 회색 박스 넣으면 되는 거 아니야?

아니! 몇 가지 규칙을 따라야 효과적이야.

[스켈레톤 UI 디자인 원칙] 1. 실제 레이아웃과 일치 ───────────────────────────────── 나쁜 예: ┌──────────────────┐ │ ████████████████ │ <= 그냥 큰 박스 └──────────────────┘ 좋은 예: ┌──────────────────┐ │ ○ ██████████ │ <= 프로필 사진 + 이름 │ ████████ │ <= 서브 텍스트 │ ██████████████ │ <= 본문 └──────────────────┘ 2. 움직임 추가 (Shimmer Effect) ───────────────────────────────── 정적 스켈레톤: "멈춘 것 같은데?" 반짝이는 스켈레톤: "로딩 중이구나!" => 반짝이는 애니메이션으로 "진행 중" 표현 3. 콘텐츠 양 힌트 ───────────────────────────────── 3줄짜리 스켈레톤 → 3줄 정도 텍스트 예상 => 실제 콘텐츠와 크게 다르면 안 됨 4. 색상 일관성 ───────────────────────────────── 배경: #f0f0f0 (밝은 회색) 반짝임: #e0e0e0 ~ #f8f8f8 => 브랜드 색상과 조화
언제 스켈레톤을 쓰고, 언제 스피너를 써야 해?
[상황별 로딩 UI 선택] 스켈레톤 UI 적합: - 리스트/피드 (SNS 타임라인, 상품 목록) - 카드 형태 콘텐츠 - 프로필 페이지 - 대시보드 - 첫 페이지 로드 로딩 스피너 적합: - 버튼 클릭 후 액션 (제출, 저장) - 짧은 지연 (1초 미만) - 오버레이 모달 - 파일 업로드 진행률 프로그레스 바 적합: - 파일 다운로드/업로드 - 긴 작업 (설치, 변환) - 정확한 진행률 표시 가능할 때
로딩 시간 권장 UI
0~200ms 아무것도 표시 안 함 (너무 짧음)
200ms~1초 스피너 또는 아무것도 없음
1초~5초 스켈레톤 UI 권장
5초 이상 프로그레스 바 + 예상 시간

Part 5. 게임 UI에 적용하기

게임에서도 스켈레톤 UI를 쓸 수 있어?

물론! 특히 웹 기반 게임 UI나 런처에서 많이 써.

[게임에서 스켈레톤 UI 적용 사례] 1. 게임 런처 ───────────────────────────────── ┌─────────────────────────────────┐ │ [○ ████████] ← 친구 목록 │ │ [○ ██████] │ │ [○ ████████████] │ ├─────────────────────────────────┤ │ ████████████ ← 뉴스/공지 │ │ ██████████████████ │ └─────────────────────────────────┘ 2. 인게임 상점 ───────────────────────────────── ┌────┐ ┌────┐ ┌────┐ ┌────┐ │████│ │████│ │████│ │████│ ← 아이템 이미지 │████│ │████│ │████│ │████│ │ ██ │ │ ██ │ │ ██ │ │ ██ │ ← 가격 └────┘ └────┘ └────┘ └────┘ 3. 랭킹/리더보드 ───────────────────────────────── │ 1. ○ ████████ ████ │ │ 2. ○ ██████ ████ │ │ 3. ○ ████████ ████ │ 4. 길드/클랜 목록 ───────────────────────────────── │ [엠블럼] ████████████ │ │ 멤버: ██ 레벨: ██ │
Unity나 Unreal 같은 게임 엔진에서도 적용 가능해?
[게임 엔진에서의 구현] Unity UI (C#): ───────────────────────────────── public class SkeletonUI : MonoBehaviour { public Image skeletonImage; public float shimmerSpeed = 2f; private Material shimmerMaterial; void Start() { // 반짝임 효과용 쉐이더 머티리얼 shimmerMaterial = new Material(Shader.Find("UI/Skeleton")); skeletonImage.material = shimmerMaterial; } void Update() { // 쉐이더에 시간 전달 (반짝임 애니메이션) float offset = Mathf.Repeat(Time.time * shimmerSpeed, 1f); shimmerMaterial.SetFloat("_ShimmerOffset", offset); } public void ShowSkeleton() => skeletonImage.enabled = true; public void HideSkeleton() => skeletonImage.enabled = false; } 쉐이더 (Unity ShaderGraph 또는 HLSL): ───────────────────────────────── // 단순화된 반짝임 쉐이더 개념 float shimmer = smoothstep(0.4, 0.6, frac(uv.x + _ShimmerOffset)); float3 color = lerp(_BaseColor, _HighlightColor, shimmer); return float4(color, 1);
[게임 로딩 화면 개선 아이디어] 전통적인 로딩 화면: "Loading... 45%" => 지루함 개선된 로딩 화면: ┌──────────────────────────────────────┐ │ [스켈레톤으로 표시된 UI 미리보기] │ │ │ │ ┌────────┐ "곧 모험이 시작됩니다" │ │ │ 캐릭터 │ 팁: ████████████ │ │ │ 실루엣 │ │ │ └────────┘ [████████──] 45% │ │ │ └──────────────────────────────────────┘ => UI 레이아웃 미리 표시 + 팁 + 진행률

핵심 정리

  • 스켈레톤 UI - 로딩 중 콘텐츠 형태를 미리 보여주는 기법
  • 인지적 로딩 시간 - 실제 시간은 같아도 체감 시간 40% 감소
  • Shimmer 효과 - 반짝이는 애니메이션으로 "진행 중" 표현
  • 디자인 원칙 - 실제 레이아웃과 일치, 적절한 개수
  • 적용 상황 - 리스트, 카드, 대시보드 (1~5초 로딩)
  • 게임 적용 - 런처, 상점, 랭킹, 로딩 화면
  • CLS 방지 - 스켈레톤과 콘텐츠 크기 일치
