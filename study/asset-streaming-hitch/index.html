왜 갑자기 화면이 뚝뚝 끊길까?

Part 1. 히치(Hitch)란?

히치가 뭐야?

히치(Hitch) = 게임이 잠깐 멈추는 현상

프레임 드랍과 비슷하지만, 특정 순간에만 발생하는 "버벅임"

정상적인 프레임: Frame 1 ─── Frame 2 ─── Frame 3 ─── Frame 4 ─── Frame 5 16ms 16ms 16ms 16ms 16ms ↓ ↓ ↓ ↓ ↓ 부드러운 60fps 유지 ✓ 히치 발생 시: Frame 1 ─── Frame 2 ───────────────── Frame 3 ─── Frame 4 16ms 16ms 150ms 16ms 16ms ↓ ↓ 정상 히치 발생! (150ms = 약 9프레임 정지) 체감: 60fps로 달리다가 갑자기 "뚝!" 하고 멈춤

Part 2. 스트리밍 히치의 원인

왜 스트리밍 때 히치가 생겨?

동기적 대기(Sync Wait)가 주요 원인

에셋이 "지금 당장" 필요한데, 아직 로딩 안 됐을 때!

Part 3. 히치 측정하기

히치가 발생하는지 어떻게 알아?

프레임 타임을 측정해서 임계값 초과 시 히치로 판단

Part 4. 히치 방지 기법 - 예측 로딩

히치를 어떻게 막아?

핵심: "필요하기 전에 미리 로드"

플레이어 이동 방향을 예측해서 에셋을 선제적으로 로드

예측 로딩 원리: 플레이어 이동 방향 → 현재 위치 미래 예측 위치 ●────────────────────→○ │ │ │ 이미 로드됨 │ 미리 로드 시작! ▼ ▼ ┌─────────────┐ ┌─────────────┐ │ 청크 A │ │ 청크 B │ │ (로드됨) │ │ (로딩 중) │ └─────────────┘ └─────────────┘ 타이밍: ─────────────────────────────────────────────→ 시간 T=0: 청크 A에 있음, 청크 B 로드 시작 T=3: 청크 B 로드 완료 T=5: 플레이어가 청크 B 진입 ← 히치 없음! 비예측 로딩 (나쁜 예): T=0: 청크 A에 있음 T=5: 플레이어가 청크 B 진입, 로드 시작 T=5~8: 히치 발생! (로딩 대기)

Part 5. 히치 방지 기법 - 스트리밍 버짓

한번에 너무 많이 로드하면 어떻게 돼?

동시에 많이 로드하면 그것도 히치 원인!

스트리밍 버짓: 프레임당 로딩 작업량 제한

스트리밍 버짓 개념: 프레임 타임 예산 (16.67ms): ┌───────────────────────────────────────────────┐ │ 게임 로직 │ 렌더링 │ 스트리밍 │ 여유 │ │ 5ms │ 8ms │ 2ms │ 1.67ms │ └───────────────────────────────────────────────┘ ↑ 스트리밍 버짓 = 2ms 버짓 초과 시: ┌───────────────────────────────────────────────┐ │ 게임 로직 │ 렌더링 │ 스트리밍 (초과!) │ │ 5ms │ 8ms │ 10ms │ └───────────────────────────────────────────────┘ 총 = 23ms → 프레임 드랍! 해결: 나눠서 처리 프레임 1: 텍스처 A 일부 로드 (2ms) 프레임 2: 텍스처 A 나머지 로드 (2ms) 프레임 3: 텍스처 B 로드 (2ms) → 각 프레임 버짓 내에서 처리!

Part 6. 히치 방지 기법 - 비동기 로딩

로딩하는 동안 게임이 멈추면 안되잖아?

비동기 로딩: 별도 스레드에서 로딩, 게임은 계속 실행

동기 로딩 (나쁜 예): ┌────────────────────────────────────────────────────┐ │ 메인 스레드 │ │ ─── 게임 ─── [로딩 대기 ████] ─── 게임 계속 ─── │ │ ↑ │ │ 히치 발생! │ └────────────────────────────────────────────────────┘ 비동기 로딩 (좋은 예): ┌────────────────────────────────────────────────────┐ │ 메인 스레드 │ │ ─── 게임 ─── 게임 ─── 게임 ─── 게임 ─── 게임 ─── │ │ │ │ 로딩 스레드 │ │ ────────── [로딩 ████████] ─── 완료 콜백 ─── │ │ │ │ → 메인 스레드는 멈추지 않음! │ └────────────────────────────────────────────────────┘
// Unity 비동기 로딩 async void LoadAssetAsync() { // 비동기로 로드 (게임 안 멈춤) var handle = Addressables.LoadAssetAsync<Texture2D>(address); await handle.Task; // 로드 완료 후 처리 texture = handle.Result; } // ❌ 절대 하면 안 되는 것 void BadSyncLoad() { // WaitForCompletion = 동기 대기 = 히치! texture = handle.WaitForCompletion(); // 금지! }

Part 7. 히치 디버깅

히치가 발생하면 어떻게 찾아?

프로파일러로 스파이크를 찾고, 원인 분석

Unreal Insights 타임라인: 시간 →→→→→→→→→→→→→→→→→→→→→→→→→→→→→→→→ Game Thread: ────────────────────────────────── │ │███│ │ │ │스파이크! │ │ │ │ Render Thread: ────────────────────────────────── │ │██│ │ │ │대기│ │ Streaming: ────────────────────────────────── │ │████████████│ │ │ │대용량 텍스처 로드│ │ 원인 분석: 1. 스파이크 클릭 2. 콜스택 확인: LoadTexture2D → SyncWait 3. 해결: 비동기로 변경 또는 예측 로딩

핵심 정리

  • 히치: 특정 순간 프레임이 길어지는 버벅임
  • 주 원인: 동기적 대기 (에셋 로딩 대기)
  • 예측 로딩: 필요하기 전에 미리 로드
  • 스트리밍 버짓: 프레임당 로딩량 제한
  • 비동기 로딩: 별도 스레드에서 로드
  • 프로파일러로 스파이크 찾아 디버깅
