히트 리액션

칼에 맞으면 맞은 방향으로 젖혀지는 법

Part 1. 히트 리액션이 왜 필요해?

캐릭터가 칼에 맞았을 때 그냥 서있으면?

타격감이 없어! 제대로 맞았는지 알 수가 없어:

타격감의 요소들: 히트 리액션 없음: ┌─────────────────────────────────────────┐ │ 공격! │ │ ⚔️ → 🧍 │ │ 🧍 (그냥 서있음) │ │ │ │ "맞은 거 맞아? 데미지는 들어갔어?" │ └─────────────────────────────────────────┘ 히트 리액션 있음: ┌─────────────────────────────────────────┐ │ 공격! │ │ ⚔️ → 😖＼ │ │ 🧍 (맞은 방향으로 젖혀짐) │ │ │ │ "확실히 맞았네! 강력한 타격!" │ └─────────────────────────────────────────┘
그냥 맞는 애니메이션 재생하면 되는 거 아냐?

그건 8방향 문제가 있어:

8방향 히트 문제: 최소 애니메이션 필요: ┌────────────────────────────────────────┐ │ │ │ 앞에서 맞음 │ │ ↓ │ │ ← 🧍 → │ │ ↑ │ │ 뒤에서 맞음 │ │ │ │ 4방향 × 맞는 부위 × 강도 │ │ = 애니메이션 수십 개 필요 │ │ │ └────────────────────────────────────────┘ 문제점: - 왼쪽 45도에서 맞으면? → 정확한 애니메이션 없음 - 맞는 강도가 다르면? → 또 다른 애니메이션 필요 - 상체/하체 따로 맞으면? → 조합 폭발

Part 2. 히트 방향 계산

어느 방향에서 맞았는지 어떻게 알아?

벡터 연산으로 계산해:

히트 방향 계산: 공격자 위치: (3, 0, 5) 피격자 위치: (5, 0, 5) 히트 방향 = 공격자 → 피격자 방향 = 피격자 위치 - 공격자 위치 = (2, 0, 0) = 정규화 → (1, 0, 0) (오른쪽 방향) [공격자] → [피격자] 🧍 → 😖＼ (오른쪽으로 젖혀짐)
// 히트 방향 계산 Vector3 CalculateHitDirection(Vector3 attackerPos, Vector3 victimPos) { // 공격자 → 피격자 방향 Vector3 hitDir = victimPos - attackerPos; hitDir.y = 0; // Y축 무시 (수평 방향만) return hitDir.normalized; } // 로컬 좌표로 변환 (캐릭터 기준) Vector3 ToLocalHitDirection(Vector3 worldHitDir, Transform victimTransform) { // 월드 방향 → 캐릭터 로컬 방향 return victimTransform.InverseTransformDirection(worldHitDir); // 결과 예시: // (1, 0, 0) = 오른쪽에서 맞음 // (-1, 0, 0) = 왼쪽에서 맞음 // (0, 0, 1) = 뒤에서 맞음 // (0, 0, -1) = 앞에서 맞음 } // 각도로 변환 (애니메이션 선택용) float GetHitAngle(Vector3 localHitDir) { // Atan2로 각도 계산 float angle = Mathf.Atan2(localHitDir.x, localHitDir.z) * Mathf.Rad2Deg; // 결과: -180 ~ 180도 // 0도 = 뒤, 180도 = 앞, 90도 = 오른쪽, -90도 = 왼쪽 return angle; }

Part 3. 애니메이션 블렌딩 방식

8방향 애니메이션을 섞어서 쓸 수 있어?

Blend Space를 사용하면 돼:

2D Blend Space (히트 리액션): (뒤에서 맞음) ↑ Z │ -45° │ 45° ↖ │ ↗ ↖ │ ↗ ←────────●────────→ X (왼쪽) ↙ │ ↘ (오른쪽) -135° │ 135° │ ↓ (앞에서 맞음) 각 모서리에 애니메이션 배치: - (0, 1): Hit_Back - (1, 0): Hit_Right - (0, -1): Hit_Front - (-1, 0): Hit_Left - 대각선: Hit_FrontLeft, Hit_FrontRight 등 히트 방향에 따라 자동 블렌딩!
// 블렌드 스페이스 기반 히트 리액션 class HitReactionBlendSpace { // 4-8개의 히트 애니메이션 Animation* hitFront; Animation* hitBack; Animation* hitLeft; Animation* hitRight; // + 대각선 애니메이션 (선택) void PlayHitReaction(Vector3 localHitDir) { // Blend Space 파라미터 설정 float x = localHitDir.x; // 좌우 float z = localHitDir.z; // 앞뒤 // Animator Parameter 설정 animator.SetFloat("HitX", x); animator.SetFloat("HitZ", z); // 블렌드 트리가 자동으로 적절한 애니메이션 혼합 animator.SetTrigger("Hit"); // 예: x=0.7, z=-0.7 (오른쪽 앞) // → Hit_Right 70% + Hit_Front 70% 블렌딩 } };

Part 4. Additive 애니메이션

걷는 중에 맞으면 멈춰야 해?

Additive 애니메이션을 쓰면 기본 동작 위에 "더할" 수 있어:

Additive Animation: 기본 동작: 히트 리액션: 결과: ┌───────────┐ ┌───────────┐ ┌───────────┐ │ 🚶 │ + │ 😖 │ = │ 😖🚶 │ │ 걷기 │ │ 젖혀짐 │ │ 걸으면서 │ │ │ │ (상체만) │ │ 젖혀짐 │ └───────────┘ └───────────┘ └───────────┘ 일반 블렌딩 vs Additive: ┌──────────────────────────────────────────────┐ │ 일반 블렌딩: │ │ 걷기 50% + 히트 50% = 중간 어딘가 │ │ → 걷지도 않고 맞지도 않은 애매한 동작 │ │ │ │ Additive: │ │ 걷기 100% + 히트 리액션 "추가" │ │ → 걷는 동작에 상체 젖혀짐이 더해짐 │ └──────────────────────────────────────────────┘
// Additive 애니메이션 원리 struct BoneTransform { Vector3 position; Quaternion rotation; }; // 일반 블렌딩 BoneTransform NormalBlend(BoneTransform a, BoneTransform b, float weight) { return BoneTransform{ Lerp(a.position, b.position, weight), Slerp(a.rotation, b.rotation, weight) }; } // Additive 블렌딩 BoneTransform AdditiveBlend(BoneTransform base, BoneTransform additive, float weight) { // Additive 애니메이션은 "변화량"만 저장 // basepose에서 얼마나 변했는지 // Reference Pose (T-Pose 등)에서의 차이값 Vector3 positionDelta = additive.position - referencePose.position; Quaternion rotationDelta = Inverse(referencePose.rotation) * additive.rotation; return BoneTransform{ base.position + positionDelta * weight, // 위치 더하기 base.rotation * Slerp(Identity, rotationDelta, weight) // 회전 곱하기 }; } // Unity에서 Additive 레이어 설정 void SetupAdditiveLayer() { // Animator Controller에서: // 1. 새 레이어 추가 (Hit Reaction) // 2. Blending: Additive // 3. Weight: 1.0 // 4. Mask: Upper Body (상체만) }

Part 5. Procedural 히트 리액션

애니메이션 없이도 할 수 있어?

Procedural (절차적) 방식으로 코드로 직접 뼈대를 움직여:

Procedural 히트 리액션: 애니메이션 기반: Procedural: ┌────────────────────┐ ┌────────────────────┐ │ 미리 만든 동작 재생 │ │ 실시간 뼈대 회전 │ │ │ │ │ │ 장점: 품질 보장 │ │ 장점: 무한한 방향 │ │ 단점: 방향 한정 │ │ 단점: 튜닝 어려움 │ └────────────────────┘ └────────────────────┘ Procedural 원리: 맞은 부위 (Spine)를 히트 방향 반대로 회전 ┌─────────────────────────────────────────┐ │ │ │ 히트 방향: → │ │ │ │ 😐 → 😖＼ │ │ ┃┃ → ┃╲ │ │ ╱╲ → ╱ ＼ │ │ (Spine 회전) │ │ │ │ 시간에 따라 원래대로 복귀 (Spring) │ └─────────────────────────────────────────┘
// Procedural 히트 리액션 class ProceduralHitReaction { struct HitImpact { int boneIndex; // 맞은 부위 Quaternion currentOffset; // 현재 오프셋 회전 Quaternion targetOffset; // 목표 오프셋 float intensity; // 강도 float decay; // 감쇠율 }; std::vector<HitImpact> activeImpacts; void ApplyHit(Vector3 hitPoint, Vector3 hitDirection, float force) { // 1. 가장 가까운 뼈 찾기 int boneIdx = FindNearestBone(hitPoint); // 2. 히트 방향의 반대로 회전 (밀려나는 느낌) Vector3 reactionDir = -hitDirection; // 회전축 계산 (히트 방향과 수직) Vector3 rotationAxis = Vector3.Cross(Vector3.up, reactionDir); // 회전량 (force에 비례) float rotationAngle = force * 30.0f; // 최대 30도 // 3. 충격 추가 HitImpact impact; impact.boneIndex = boneIdx; impact.targetOffset = Quaternion.AngleAxis(rotationAngle, rotationAxis); impact.intensity = 1.0f; impact.decay = 0.9f; // 프레임당 10% 감쇠 activeImpacts.push_back(impact); } void Update() { for (auto& impact : activeImpacts) { // 현재 오프셋 → 목표 오프셋으로 빠르게 이동 impact.currentOffset = Slerp( impact.currentOffset, impact.targetOffset, 0.5f // 빠르게 도달 ); // 목표 오프셋 → 원점으로 감쇠 impact.targetOffset = Slerp( impact.targetOffset, Quaternion.identity, 1.0f - impact.decay ); // 강도 감소 impact.intensity *= impact.decay; // 뼈대에 적용 Bone* bone = skeleton->GetBone(impact.boneIndex); bone->localRotation = bone->animatedRotation * impact.currentOffset; } // 강도 0에 가까운 충격 제거 activeImpacts.erase( std::remove_if(activeImpacts.begin(), activeImpacts.end(), [](const HitImpact& i) { return i.intensity < 0.01f; }), activeImpacts.end() ); } };

Part 6. 고급 기법

실제 게임에서는 어떻게 조합해?

대부분 여러 기법을 조합해서 써:

실제 게임의 히트 리액션 시스템: ┌─────────────────────────────────────────────────┐ │ 레이어 1: 기본 동작 │ │ - 걷기, 뛰기, Idle 등 │ └─────────────────────────────────────────────────┘ ↓ Additive ┌─────────────────────────────────────────────────┐ │ 레이어 2: 히트 리액션 (Additive) │ │ - Blend Space로 방향별 애니메이션 │ │ - 상체만 적용 (Avatar Mask) │ └─────────────────────────────────────────────────┘ ↓ Procedural 보정 ┌─────────────────────────────────────────────────┐ │ 레이어 3: Procedural 미세 조정 │ │ - 정확한 히트 방향으로 추가 회전 │ │ - 충격 강도에 따른 강약 조절 │ └─────────────────────────────────────────────────┘ ↓ Physics ┌─────────────────────────────────────────────────┐ │ 레이어 4: 부분 Ragdoll (강한 타격 시) │ │ - 맞은 팔만 Ragdoll │ │ - 전신 Ragdoll로 전환 (사망 시) │ └─────────────────────────────────────────────────┘
// 완성된 히트 리액션 시스템 class AdvancedHitReaction { // 각 레이어 컴포넌트 AnimatorBlendSpace* blendSpace; ProceduralHitReaction* procedural; PartialRagdoll* ragdoll; void OnHit(HitInfo hit) { float damage = hit.damage; Vector3 direction = hit.direction; Vector3 point = hit.point; // 1. 강도에 따른 반응 선택 if (damage >= LETHAL_DAMAGE) { // 사망 → 전신 Ragdoll ragdoll->EnableFullBody(); ragdoll->ApplyForce(direction * damage); } else if (damage >= HEAVY_HIT_THRESHOLD) { // 강한 타격 → 전용 애니메이션 + Procedural blendSpace->PlayHeavyHit(direction); procedural->ApplyHit(point, direction, damage * 0.5f); } else if (damage >= MEDIUM_HIT_THRESHOLD) { // 중간 타격 → Additive 애니메이션 blendSpace->PlayMediumHit(direction); procedural->ApplyHit(point, direction, damage * 0.3f); } else { // 약한 타격 → Procedural만 procedural->ApplyHit(point, direction, damage * 0.2f); } // 2. 카메라 셰이크 (타격감 증폭) cameraShake->Shake(damage * 0.1f); // 3. 히트스톱 (순간 정지) if (damage >= HEAVY_HIT_THRESHOLD) { TimeManager->SetTimeScale(0.1f, 0.05f); // 0.05초간 슬로모션 } // 4. VFX/SFX vfxManager->PlayHitEffect(point, direction); audioManager->PlayHitSound(damage); } };

핵심 정리

  • 히트 리액션은 타격감의 핵심 요소
  • 히트 방향은 벡터 연산으로 계산 (공격자 → 피격자)
  • Blend Space로 8방향 애니메이션 자동 블렌딩
  • Additive로 기본 동작 위에 히트 반응 "추가"
  • Procedural로 무한한 방향에 대응 (코드로 뼈대 회전)
  • 실제 게임은 여러 기법 조합 (Blend + Procedural + Ragdoll)
  • 타격감 = 히트 리액션 + 카메라 셰이크 + 히트스톱 + VFX/SFX
