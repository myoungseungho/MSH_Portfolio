🔧 컴파일 / 빌드

소스코드가 실행파일이 되기까지의 여정

왜 빌드 최적화가 중요한가?

대규모 C++ 프로젝트에서 빌드 시간은 개발 생산성에 직접적인 영향을 미칩니다.

코드 한 줄 수정하고 3분씩 기다리면, 하루에 수십 번의 빌드로 1시간 이상을 낭비하게 됩니다.

이 시리즈에서는 빌드 과정의 원리를 이해하고, 최적화 기법을 배웁니다.

1

빌드의 기초 - 전체 그림 이해하기

소스코드(.cpp)가 실행파일(.exe)이 되기까지의 전체 흐름을 이해합니다. 컴파일과 링킹이 왜 분리되어 있는지, .obj 파일은 무엇인지 알아봅니다.

컴파일 링킹 .obj
2

컴파일 단계 - 코드가 기계어가 되기까지

전처리 → 어휘분석 → 구문분석 → 의미분석 → 코드생성. 각 단계에서 무슨 일이 일어나는지, 왜 #include가 비용이 큰지 이해합니다.

전처리 파싱 #include
3

PCH - 헤더 반복 파싱 제거하기

100개 파일에서 windows.h를 include하면 100번 파싱할까요? Precompiled Header로 헤더 파싱을 한 번만 하고 재사용하는 방법을 배웁니다.

StdAfx.h Create/Use NotUsing
4

병렬 빌드 - CPU 코어 전부 활용하기

8코어 CPU인데 1코어만 쓰고 있다면? /MP 옵션으로 컴파일을, /CGTHREADS로 링킹을 병렬화하여 빌드 시간을 획기적으로 줄입니다.

/MP /CGTHREADS 병렬화
5

링킹 단계 - .obj를 .exe로 조립하기

컴파일이 끝나면 링커가 등장합니다. 심볼 해결, 재배치, 라이브러리 연결 과정을 이해하고 "unresolved external symbol" 에러의 원인을 파악합니다.

심볼 해결 /Gy /Gw
6

Debug vs Release - 왜 속도가 다른가

Debug 빌드는 빠르게 되는데 Release는 왜 오래 걸릴까요? 최적화 옵션(/O2)이 하는 일과 Debug/Release의 근본적인 차이를 이해합니다.

/Od vs /O2 최적화 디버그 정보
