트랜잭션 중 오류 발생, 자동으로 롤백시키기

SET XACT_ABORT ON - 에러 시 "알아서" 롤백되게 만들기

Part 1. 이상한 현상

트랜잭션 안에서 에러가 나면 자동으로 롤백되는 거 아니야?

아니, 기본값은 "에러 나도 계속 진행"이야.

놀랍지? 직접 보여줄게.

BEGIN TRAN INSERT INTO TCharacter (charunique, name) VALUES (1, '용사1') -- 성공 INSERT INTO TCharacter (charunique, name) VALUES (1, '용사2') -- 💥 중복키 에러! INSERT INTO TCharacter (charunique, name) VALUES (2, '용사3') -- ??? COMMIT TRAN
두 번째 INSERT에서 에러 났으니까 전부 롤백되겠지?

실행 결과를 보면...

결과: - 용사1: 저장됨 ✅ - 용사2: 에러 (중복키) ❌ - 용사3: 저장됨 ✅ <-- 어?!

에러 나도 다음 줄 실행하고, COMMIT까지 됐어!

용사1, 용사3은 DB에 저장되고, 용사2만 안 들어감.

뭐야? 트랜잭션은 "전부 성공 아니면 전부 실패"라며?

그건 네가 직접 롤백을 호출했을 때 이야기야.

기본적으로 SQL Server는 에러가 나도 다음 문장을 계속 실행해.

Part 2. 왜 이렇게 동작해?

왜 이게 기본값이야? 이상하잖아.

"모든 에러가 치명적인 건 아니다"라는 철학 때문이야.

-- 예시: 로그 테이블에 기록하는데 중복이 나도 괜찮은 경우 BEGIN TRAN INSERT INTO TLoginLog VALUES (...) -- 중복? 그냥 무시하고 싶을 수도 UPDATE TCharacter SET lastLogin = GETDATE() -- 이건 반드시 해야 함 COMMIT

어떤 에러는 무시하고 계속 진행하고 싶을 수 있거든.

그래서 SQL Server는 "에러 처리는 개발자가 직접 해라"라는 입장.

그럼 우리가 직접 롤백 로직을 짜야 하네?

맞아. 두 가지 방법이 있어:

1. @@error로 매번 체크 (귀찮음)

2. SET XACT_ABORT ON (자동화)

Part 3. SET XACT_ABORT ON이 뭐야?

XACT는 뭐고 ABORT는 뭐야?

XACT = Transaction (트랜잭션의 약어)

ABORT = 중단하다

즉, "에러 발생 시 트랜잭션을 중단(롤백)해라"

SET XACT_ABORT ON; -- 이 한 줄 추가! BEGIN TRAN INSERT INTO TCharacter (charunique, name) VALUES (1, '용사1') -- 성공 INSERT INTO TCharacter (charunique, name) VALUES (1, '용사2') -- 💥 에러! INSERT INTO TCharacter (charunique, name) VALUES (2, '용사3') -- 실행 안 됨 COMMIT TRAN -- 실행 안 됨

이제 결과가 달라져:

결과: - 용사1: 롤백됨 ❌ - 용사2: 에러 ❌ - 용사3: 실행 안 됨 ❌ 전체 트랜잭션 자동 롤백! ✅

에러 발생 즉시 트랜잭션 자동 롤백 + 이후 문장 실행 안 함

Part 4. 흐름 비교

XACT_ABORT OFF (기본값)

1
INSERT 용사1 → 성공
2
INSERT 용사2 → 에러 (중복키)
3
INSERT 용사3 → 성공 (계속 실행됨!)
4
COMMIT → 성공 (1, 3 저장됨)

XACT_ABORT ON

1
INSERT 용사1 → 성공
2
INSERT 용사2 → 에러 → 자동 ROLLBACK 실행!
3
INSERT 용사3 → 실행 안 됨 (건너뜀)
4
COMMIT → 실행 안 됨 (이미 롤백됨)

Part 5. 언제 써야 해?

그럼 항상 XACT_ABORT ON을 쓰면 되는 거야?

대부분의 경우 그래. 특히 게임 서버처럼 데이터 정합성이 중요한 곳에서는 필수야.

상황 권장 설정 이유
캐릭터 생성 (여러 테이블 INSERT) ON 하나라도 실패하면 전부 롤백해야
아이템 거래 ON 돈 빠지고 아이템 안 가면 안 됨
인벤토리 저장 ON 부분 저장은 재앙
로그 기록 (중요도 낮음) OFF 가능 실패해도 본 작업에 영향 없음

실무 원칙: 기본적으로 ON, 예외적인 경우에만 OFF

Part 6. TRY-CATCH와 함께 쓰기

TRY-CATCH가 있으면 XACT_ABORT 안 써도 되는 거 아니야?

아니, 같이 쓰는 게 베스트야.

TRY-CATCH만 쓰면 함정이 있거든.

-- TRY-CATCH만 쓴 경우 BEGIN TRY BEGIN TRAN UPDATE TCharacter SET level = level + 1 -- 여기서 심각한 에러 발생! COMMIT TRAN END TRY BEGIN CATCH ROLLBACK TRAN -- 롤백하려는데... END CATCH

문제: 에러 종류에 따라 트랜잭션 상태가 달라져.

에러 종류 XACT_ABORT OFF XACT_ABORT ON
제약조건 위반 트랜잭션 유지 (커밋 가능) 자동 롤백
문법 오류 트랜잭션 유지 자동 롤백
치명적 오류 커밋 불가 상태 자동 롤백

XACT_ABORT OFF면 CATCH 블록에서 트랜잭션 상태를 직접 확인해야 해.

-- XACT_ABORT OFF일 때 CATCH 블록 BEGIN CATCH IF XACT_STATE() = -1 -- 커밋 불가능 ROLLBACK TRAN ELSE IF XACT_STATE() = 1 -- 커밋 가능 (???) ROLLBACK TRAN -- 그래도 롤백해야 함 END CATCH
복잡하네... XACT_ABORT ON이면?

간단해져:

SET XACT_ABORT ON; -- 이거 하나면 BEGIN TRY BEGIN TRAN UPDATE TCharacter SET level = level + 1 COMMIT TRAN END TRY BEGIN CATCH -- 여기 오면 이미 자동 롤백됨 -- 에러 로깅만 하면 됨 PRINT ERROR_MESSAGE() END CATCH

XACT_ABORT ON + TRY-CATCH = 최고의 조합

• 에러 시 자동 롤백 (XACT_ABORT)

• 에러 정보 캡처 + 추가 처리 (CATCH)

Part 7. 우리 프로젝트 현황

우리 프로젝트는 XACT_ABORT 쓰고 있어?

분석 결과:

프로시저 XACT_ABORT 상태
gp_LoadCharacter ON 최적화됨
gp_save_pc_inventory ON 최적화됨
gp_save_pc 없음 @@error로 체크
gp_make_pc 없음 @@error로 체크

실제 코드 - gp_save_pc_inventory (좋은 예)

ALTER PROCEDURE gp_save_pc_inventory @pc_uid BIGINT, @bySaveBits TINYINT, ... AS BEGIN SET NOCOUNT ON; SET XACT_ABORT ON; -- ✅ 둘 다 있음! BEGIN TRAN UPDATE TInventory ... ... COMMIT TRAN END

실제 코드 - gp_save_pc (개선 필요)

ALTER PROCEDURE gp_save_pc ... AS BEGIN SET NOCOUNT ON; -- SET XACT_ABORT ON 없음! BEGIN TRAN UPDATE TCharacter SET ... IF @@error <> 0 BEGIN ROLLBACK RETURN -1 END UPDATE TInventory SET ... IF @@error <> 0 BEGIN ROLLBACK RETURN -2 END ... COMMIT TRAN END

최신 프로시저는 적용됨, 레거시는 @@error 방식

Part 8. 권장 템플릿

새 프로시저 만들 때 어떻게 시작하면 돼?

이 템플릿을 추천해:

CREATE PROCEDURE gp_새프로시저 @param1 int, @param2 nvarchar(50) AS BEGIN SET NOCOUNT ON; -- 1. 불필요한 메시지 차단 SET XACT_ABORT ON; -- 2. 에러 시 자동 롤백 BEGIN TRY BEGIN TRAN -- 비즈니스 로직 INSERT INTO ... UPDATE ... COMMIT TRAN END TRY BEGIN CATCH -- 에러 로깅 (이미 롤백됨) PRINT 'Error: ' + ERROR_MESSAGE() RETURN -1 END CATCH END

3단 콤보:

• SET NOCOUNT ON - 네트워크 절약

• SET XACT_ABORT ON - 자동 롤백

• TRY-CATCH - 에러 정보 캡처

핵심 정리

  • 기본값: 에러 나도 다음 문장 실행됨 (위험!)
  • SET XACT_ABORT ON = 에러 시 자동 롤백 + 실행 중단
  • XACT = Transaction, ABORT = 중단
  • TRY-CATCH와 함께 쓰면 최고의 조합
  • 게임 서버처럼 정합성 중요한 곳에서는 필수
  • 우리 프로젝트: 최신 프로시저에만 적용됨, 레거시 개선 필요
