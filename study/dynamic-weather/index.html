비 오면 땅이 반짝이는 이유

게임의 동적 날씨 시스템

Part 1. 비 오는 날 거리 풍경

비 오는 날 아스팔트 도로 본 적 있어?

응, 번쩍번쩍 반사가 생기잖아. 가로등 불빛이 바닥에 비치고.

마른 날에는 뿌옇던 도로가 비 오면 거울처럼 반짝이는 거 말이야.

마른 도로 vs 젖은 도로: [마른 도로] 빛 → /\/\/\/\/\ 표면이 거칠어서 │ │ │ │ │ 빛이 사방으로 흩어짐 ↙ ↓ ↘ ↙ ↓ (난반사 = Diffuse) 결과: 뿌옇고 무광택 [젖은 도로] 빛 → ~~~~~~~~ 물이 표면을 매끄럽게 덮어서 │ 빛이 한 방향으로 반사 ↓ (정반사 = Specular) 결과: 반짝이고 광택
왜 물이 있으면 반짝이는 거야?

물이 표면의 틈새를 채우기 때문이야.

🪞 비유: 사포와 유리

사포는 울퉁불퉁해서 빛이 사방으로 튕겨. 그래서 반짝이지 않아.
유리는 매끄러워서 빛이 한 방향으로 쫙 반사돼. 그래서 반짝여.

물은 사포의 틈새를 채워서 유리처럼 만들어주는 거야!

Part 2. 젖음 효과 구현하기

게임에서 이걸 어떻게 표현해?

Wetness(젖음도) 값 하나로 조절해.

0이면 마른 상태, 1이면 완전히 젖은 상태.

Wetness에 따른 변화: ┌────────────────────────────────────────────┐ │ 속성 │ 마름(0) │ 젖음(1) │ ├────────────────────────────────────────────┤ │ 밝기(Albedo) │ 밝음 │ 어두워짐 ↓ │ │ 거칠기 │ 거침 │ 매끄러움 ↓ │ │ 반사 │ 약함 │ 강함 ↑ │ └────────────────────────────────────────────┘ 물이 빛을 흡수해서 색이 어두워지고, 표면을 매끄럽게 해서 반사가 강해지는 거야.
위를 향한 면만 젖어야 하지 않아?

맞아! 비가 위에서 내리니까.

노말(표면 방향)과 젖음: 비 ↓↓↓↓↓ ┌────────────┐ ← 위를 향함 = 많이 젖음 │ │ │ 지붕 │ │ │ └────┬──┬────┘ │ │ ← 옆을 향함 = 조금 젖음 (튀는 물방울만) │ │ ═════╧══╧═════ ← 땅 = 많이 젖음 계산: 젖음도 = Wetness × dot(노말, 위쪽방향) dot(위, 위) = 1.0 → 완전히 젖음 dot(옆, 위) = 0.0 → 안 젖음

Part 3. 웅덩이 만들기

비가 많이 오면 웅덩이도 생기잖아

웅덩이는 완전한 물 표면이야. 단순히 젖은 거랑 달라.

젖음 vs 웅덩이: 젖음 (Wetness 0.5~0.9): 표면의 색이 보이면서 약간 반사 ░░░░░░░░░░░░░░ ← 원래 텍스처 + 반사 웅덩이 (Wetness 1.0 + 평평한 곳): 완전한 거울 반사 + 물결 ≈≈≈≈≈≈≈≈≈≈≈≈≈≈ ← 하늘/주변이 비침 + 물결 노이즈 웅덩이 조건: 1. Wetness 높음 (비 많이 옴) 2. 지형이 평평함 (오목한 곳) 3. 노이즈로 불규칙한 모양
물결도 표현해야 하지 않아?

맞아. 비가 계속 떨어지면 파문(Ripple)이 생겨야 해.

빗방울 파문: ○ ← 빗방울 착지 ───────────────── ╭─╮ ╭╯ ╰╮ ← 동심원으로 퍼져나감 ╭╯ ╰╮ 구현 방식: 1. 노말맵에 원형 파문 패턴 그리기 2. 시간에 따라 원이 커지다가 사라짐 3. 랜덤 위치에 계속 새로운 파문 생성

Part 4. 눈 쌓이는 효과

눈은 비랑 다르지?

완전히 달라. 눈은 쌓이니까.

비는 표면 속성만 바꾸면 되지만, 눈은 실제로 "뭔가 덮여야" 해.

비 vs 눈: [비] 물체 모양 그대로 표면만 젖음 시간 지나면 마름 [눈] 물체 위에 흰 층이 쌓임 볼륨(높이)이 생김 녹기 전까지 유지 눈 쌓임 조건: - 위를 향한 면만 (비랑 같음) - 하지만 기울기 제한 있음 (너무 가파르면 눈이 안 쌓이고 미끄러짐)
눈 텍스처만 씌우면 안 돼?

간단히 하면 그렇게 해도 돼. 하지만 볼륨감이 없어.

눈 표현 방법들: [Level 1: 텍스처 블렌딩] 원래 텍스처 + 눈 텍스처 섞기 빠르지만 평면적 [Level 2: 노말맵 변경] 눈 표면의 울퉁불퉁함 추가 조금 더 입체적 [Level 3: Tessellation] 실제로 메시 높이를 올림 진짜 눈이 쌓인 것처럼 보임 비용 높음 [Level 4: 파티클 + Decal] 눈송이 파티클 + 쌓인 눈 데칼 가장 사실적이지만 복잡
🎂 비유: 케이크 위 슈가파우더

케이크 위에 슈가파우더를 뿌리면 살짝 덮이잖아?
위쪽만 덮이고, 옆면은 덜 묻고, 너무 가파른 곳은 흘러내려.

눈도 똑같아. 중력 때문에 위에만 쌓여.

Part 5. 빗방울과 눈송이 파티클

떨어지는 빗방울은 어떻게 만들어?

수만 개의 파티클을 GPU에서 처리해.

비 파티클 시스템: [생성] 플레이어 주변 하늘에서 랜덤하게 스폰 · · · · · · · · · · · · · · [업데이트] - 중력으로 아래로 떨어짐 - 바람에 따라 옆으로 밀림 - 지면에 닿으면 스플래시 파생 [렌더링] 세로로 길쭉한 선(속도 때문) | | ← 떨어지는 방향으로 늘여서 그림 | 실제 빗방울은 빠르게 떨어지니까 선처럼 보이잖아?
그걸 CPU가 처리해?

CPU로는 너무 느려. 수만 개니까.

GPU 파티클을 써. Compute Shader로 병렬 처리해.

GPU 파티클 vs CPU 파티클: [CPU] for (int i = 0; i < 50000; i++) { UpdateParticle(i); ← 순차적으로 하나씩 } → 느림! [GPU] Compute Shader에서: 50,000개 스레드가 동시에 실행 각 스레드가 자기 파티클 1개 담당 → 빠름! GPU는 수천 개의 코어가 있어서 단순한 계산을 동시에 처리하면 엄청 빨라.

Part 6. 화면에 물방울 맺힘

비 오면 카메라 렌즈에도 물방울 맺히잖아

그건 포스트 프로세스로 처리해. 3D 공간이 아니라 2D 화면에서.

화면 물방울 효과: [1단계] 물방울 마스크 ○ ○ ○ ○ ○ ○ ○ ○ 랜덤한 위치에 물방울 모양 [2단계] 굴절(Distortion) 물방울 안의 픽셀을 살짝 왜곡 정상: 물방울 안: ───── ╭─────╮ ───── │~~~~~│ ───── ╰─────╯ [3단계] 하이라이트 물방울 가장자리에 밝은 반사 추가 이러면 비 오는 느낌이 확 살아나!

Part 7. 날씨 전환

맑음에서 비로 갑자기 바뀌면 이상하잖아

그래서 서서히 블렌딩해야 해.

날씨 전환 타임라인 (맑음 → 비): 시간: 0분 5분 10분 15분 20분 ───────────────────────────────────────────── 구름: 10% ──→ 30% ──→ 60% ──→ 80% ──→ 95% 비: 0% ──→ 0% ──→ 20% ──→ 60% ──→ 100% 밝기: 100% ──→ 90% ──→ 70% ──→ 50% ──→ 40% 안개: 0% ──→ 10% ──→ 20% ──→ 30% ──→ 40% 먼저 구름이 끼고, 점점 어두워지다가, 비가 조금씩 내리기 시작해. 갑자기 확 바뀌면 어색하니까 5~10분에 걸쳐 자연스럽게 전환.
다 계산하면 느리지 않아?

최적화가 중요해. LOD 시스템으로 거리에 따라 다르게 처리해.

날씨 LOD: [가까움 - 상세] 개별 빗방울 파티클 물방울 튀는 스플래시 웅덩이 파문 [중간] 텍스처 시트로 비 표현 간단한 젖음 효과 [멀리 - 간략] 안개만으로 비 분위기 표현 파티클 없음 멀리 있는 건 어차피 잘 안 보이니까 간단하게 처리해서 성능 확보!

📌 핵심 정리

  • 젖음 효과 - 색 어두워짐 + 거칠기↓ + 반사↑ (물이 틈새를 채움)
  • 위를 향한 면만 - 노말과 위쪽 벡터의 내적으로 판단
  • 웅덩이 - 완전한 물 표면 + 빗방울 파문(Ripple)
  • 눈 쌓임 - 텍스처 블렌딩 → 노말맵 → Tessellation 순으로 사실적
  • GPU 파티클 - 수만 개 빗방울을 Compute Shader로 병렬 처리
  • 날씨 전환 - 5~10분에 걸쳐 서서히 블렌딩
