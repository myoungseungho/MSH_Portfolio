게임 실행파일(.exe)은 어떻게 생겼을까?

PE(Portable Executable) 포맷의 구조

Part 1. EXE 파일의 정체

EXE 파일이 뭐야?

Windows에서 실행 가능한 프로그램 파일이야.

PE(Portable Executable) 포맷이라는 정해진 구조를 따르고 있어.

PE 포맷이란? ┌────────────────────────────────────────────────────────────┐ │ PE = Portable Executable │ │ │ │ "이식 가능한 실행 파일" │ │ │ │ Windows의 모든 실행 파일이 사용하는 포맷: │ │ - .exe (실행 파일) │ │ - .dll (동적 라이브러리) │ │ - .sys (드라이버) │ │ - .ocx (ActiveX 컨트롤) │ │ │ │ 유래: │ │ - Unix의 COFF 포맷을 기반으로 설계 │ │ - Windows NT 3.1 (1993)부터 사용 │ │ - 32비트/64비트 모두 지원 (PE32/PE32+) │ └────────────────────────────────────────────────────────────┘
Hex 에디터로 EXE 열면 뭐가 보여?

처음에 "MZ"라는 글자가 보여. 이게 EXE 파일의 시그니처야!

EXE 파일 시작 부분 (Hex): Offset 00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F ASCII ────────────────────────────────────────────────────────────────── 0x0000 4D 5A 90 00 03 00 00 00 04 00 00 00 FF FF 00 00 MZ............. 0x0010 B8 00 00 00 00 00 00 00 40 00 00 00 00 00 00 00 ........@....... ... 0x003C F8 00 00 00 .... ← PE 헤더 위치 0x00F8 50 45 00 00 64 86 ... PE..d. ← PE 시그니처 MZ = Mark Zbikowski (DOS 개발자 이름) PE = Portable Executable

Part 3. 중요한 헤더 필드들

File Header에서 중요한 건 뭐야?

Machine과 NumberOfSections가 핵심이야.

File Header (IMAGE_FILE_HEADER): ┌───────────────────────┬──────────┬────────────────────────────┐ │ 필드 │ 크기 │ 의미 │ ├───────────────────────┼──────────┼────────────────────────────┤ │ Machine │ 2 bytes │ CPU 아키텍처 │ │ │ │ 0x014C = i386 (32비트) │ │ │ │ 0x8664 = AMD64 (64비트) │ │ │ │ 0xAA64 = ARM64 │ ├───────────────────────┼──────────┼────────────────────────────┤ │ NumberOfSections │ 2 bytes │ 섹션 개수 │ ├───────────────────────┼──────────┼────────────────────────────┤ │ TimeDateStamp │ 4 bytes │ 빌드 시간 (Unix timestamp) │ ├───────────────────────┼──────────┼────────────────────────────┤ │ SizeOfOptionalHeader │ 2 bytes │ Optional Header 크기 │ ├───────────────────────┼──────────┼────────────────────────────┤ │ Characteristics │ 2 bytes │ 파일 속성 플래그 │ │ │ │ 0x0002 = 실행 가능 │ │ │ │ 0x2000 = DLL │ │ │ │ 0x0020 = Large Address │ └───────────────────────┴──────────┴────────────────────────────┘
Optional Header에서 제일 중요한 건?

ImageBase, AddressOfEntryPoint, Data Directory!

// Optional Header 주요 필드 typedef struct _IMAGE_OPTIONAL_HEADER64 { WORD Magic; // 0x20B = PE32+ (64비트) // 코드/데이터 크기 DWORD SizeOfCode; DWORD SizeOfInitializedData; DWORD SizeOfUninitializedData; // 핵심 필드들 DWORD AddressOfEntryPoint; // 프로그램 시작점 RVA ULONGLONG ImageBase; // 선호하는 로드 주소 // 정렬 DWORD SectionAlignment; // 메모리 섹션 정렬 (보통 0x1000) DWORD FileAlignment; // 파일 섹션 정렬 (보통 0x200) // 크기 DWORD SizeOfImage; // 메모리에 로드될 전체 크기 DWORD SizeOfHeaders; // 모든 헤더 크기 // 서브시스템 WORD Subsystem; // 2 = GUI, 3 = Console // Data Directory (핵심!) IMAGE_DATA_DIRECTORY DataDirectory[16]; } IMAGE_OPTIONAL_HEADER64;

Part 4. Import/Export 테이블

Import 테이블이 뭐야?

이 프로그램이 사용하는 외부 DLL 함수 목록이야.

로더가 이 정보를 보고 DLL을 로드하고 함수 주소를 채워줘.

Import Table 예시: game.exe가 사용하는 외부 함수들: ┌────────────────────────────────────────────────────────────┐ │ │ │ kernel32.dll │ │ ├─ CreateFileW │ │ ├─ ReadFile │ │ ├─ VirtualAlloc │ │ └─ GetTickCount64 │ │ │ │ user32.dll │ │ ├─ CreateWindowExW │ │ ├─ ShowWindow │ │ ├─ GetMessageW │ │ └─ DispatchMessageW │ │ │ │ d3d11.dll │ │ ├─ D3D11CreateDevice │ │ └─ D3D11CreateDeviceAndSwapChain │ │ │ └────────────────────────────────────────────────────────────┘ 로딩 과정: ┌────────────────────────────────────────────────────────────┐ │ 1. 로더가 Import Table 읽음 │ │ 2. kernel32.dll 로드 → GetProcAddress로 함수 주소 획득 │ │ 3. IAT(Import Address Table)에 실제 주소 기록 │ │ 4. 프로그램에서 CreateFileW 호출 시 IAT를 통해 점프 │ └────────────────────────────────────────────────────────────┘
Export 테이블은?

DLL이 외부에 공개하는 함수 목록이야.

Export Table 예시 (kernel32.dll): ┌────────────────────────────────────────────────────────────┐ │ kernel32.dll Export Table │ ├──────────────────────┬─────────────────────────────────────┤ │ Ordinal │ Name │ Address (RVA) │ ├─────────┼────────────┼─────────────────────────────────────┤ │ 0 │ - │ (사용 안 함) │ │ 1 │ AcquireSRW │ 0x0001A3F0 │ │ ... │ ... │ ... │ │ 287 │ CreateFile │ 0x0002B100 │ │ ... │ ... │ ... │ │ 1423 │ WriteFile │ 0x0003C200 │ └─────────┴────────────┴─────────────────────────────────────┘ 함수 찾기: 1. 이름으로: "CreateFileW" → Export Name Table에서 검색 2. 순번으로: Ordinal 287 → 바로 주소 테이블 접근 GetProcAddress()가 바로 이 테이블을 검색하는 함수!

Part 5. 리소스 섹션

게임 아이콘은 EXE 어디에 있어?

.rsrc 섹션에 있어! 아이콘, 버전 정보, 다국어 문자열 등이 저장돼.

리소스 섹션 구조: ┌────────────────────────────────────────────────────────────┐ │ .rsrc 섹션 (트리 구조) │ │ │ │ Root │ │ ├─ RT_ICON (3) ← 아이콘 │ │ │ ├─ ID: 1 │ │ │ │ ├─ LANG: 1033 (영어) │ │ │ │ └─ LANG: 1042 (한국어) │ │ │ └─ ID: 2 │ │ │ │ │ ├─ RT_GROUP_ICON (14) ← 아이콘 그룹 │ │ │ │ │ ├─ RT_VERSION (16) ← 버전 정보 │ │ │ └─ 파일 버전, 제품 버전, 회사명, 저작권 등 │ │ │ │ │ ├─ RT_MANIFEST (24) ← 어플리케이션 매니페스트 │ │ │ └─ DPI 인식, UAC 권한, Side-by-Side 어셈블리 │ │ │ │ │ └─ RT_STRING (6) ← 문자열 테이블 │ │ └─ 다국어 UI 문자열 │ │ │ └────────────────────────────────────────────────────────────┘
// 리소스 접근 API // 현재 EXE의 리소스 핸들 얻기 HMODULE hModule = GetModuleHandle(NULL); // 아이콘 로드 HICON hIcon = LoadIcon(hModule, MAKEINTRESOURCE(IDI_MYICON)); // 문자열 로드 WCHAR buffer[256]; LoadString(hModule, IDS_GREETING, buffer, 256); // 커스텀 리소스 로드 HRSRC hRes = FindResource(hModule, MAKEINTRESOURCE(IDR_GAMEDATA), L"BINARY"); HGLOBAL hGlobal = LoadResource(hModule, hRes); LPVOID pData = LockResource(hGlobal); DWORD size = SizeofResource(hModule, hRes); // pData로 리소스 데이터 접근 가능!

Part 6. PE 분석 도구

PE 파일을 분석하려면 어떤 도구를 써?

여러 유용한 도구들이 있어:

PE 분석 도구들: 1. dumpbin (Visual Studio 포함) ┌────────────────────────────────────────────────────────┐ │ dumpbin /headers game.exe ← 헤더 정보 │ │ dumpbin /imports game.exe ← Import 목록 │ │ dumpbin /exports game.dll ← Export 목록 │ │ dumpbin /disasm game.exe ← 디스어셈블리 │ └────────────────────────────────────────────────────────┘ 2. PE Explorer / CFF Explorer (GUI) - 시각적으로 PE 구조 탐색 - 리소스 편집 가능 - 무료/유료 버전 존재 3. x64dbg / IDA (리버싱) - 디버깅 + 디스어셈블리 - 동적/정적 분석 4. Resource Hacker (리소스 전문) - 아이콘, 문자열, 버전 수정 - 무료
// 프로그래밍으로 PE 파싱하기 #include <windows.h> #include <stdio.h> void ParsePE(const char* filePath) { // 파일 메모리 매핑 HANDLE hFile = CreateFileA(filePath, GENERIC_READ, FILE_SHARE_READ, NULL, OPEN_EXISTING, 0, NULL); HANDLE hMapping = CreateFileMapping(hFile, NULL, PAGE_READONLY, 0, 0, NULL); LPVOID pBase = MapViewOfFile(hMapping, FILE_MAP_READ, 0, 0, 0); // DOS 헤더 PIMAGE_DOS_HEADER pDos = (PIMAGE_DOS_HEADER)pBase; printf("DOS Magic: %c%c\n", pDos->e_magic & 0xFF, pDos->e_magic >> 8); // PE 헤더 PIMAGE_NT_HEADERS pNT = (PIMAGE_NT_HEADERS)((BYTE*)pBase + pDos->e_lfanew); printf("PE Signature: %08X\n", pNT->Signature); printf("Machine: %04X\n", pNT->FileHeader.Machine); printf("Sections: %d\n", pNT->FileHeader.NumberOfSections); // 섹션 순회 PIMAGE_SECTION_HEADER pSection = IMAGE_FIRST_SECTION(pNT); for (int i = 0; i < pNT->FileHeader.NumberOfSections; i++) { printf("Section: %.8s, Size: %08X\n", pSection[i].Name, pSection[i].Misc.VirtualSize); } // 정리 UnmapViewOfFile(pBase); CloseHandle(hMapping); CloseHandle(hFile); }

핵심 정리

  • PE 포맷 - Windows 실행 파일(.exe, .dll)의 표준 포맷
  • MZ 시그니처 - DOS 호환을 위한 헤더 (e_lfanew로 PE 헤더 위치 지정)
  • File Header - Machine(아키텍처), NumberOfSections, Characteristics
  • Optional Header - ImageBase, EntryPoint, Data Directories
  • Import Table - 외부 DLL에서 가져오는 함수 목록
  • Export Table - DLL이 외부에 공개하는 함수 목록
  • .rsrc 섹션 - 아이콘, 버전 정보, 문자열 등 리소스
  • 분석 도구 - dumpbin, CFF Explorer, Resource Hacker
