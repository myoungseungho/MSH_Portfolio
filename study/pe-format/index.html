EXE 파일을 더블클릭하면 무슨 일이 일어날까?

PE(Portable Executable) 포맷 - Windows 실행 파일의 구조

Part 1. 우리가 매일 하는 행동부터

게임 아이콘 더블클릭하면 게임이 실행되잖아. 그 사이에 뭐가 일어나?

좋은 질문이야! 우리가 당연하게 여기는 이 과정에 엄청난 일들이 일어나.

일단 Windows가 그 파일을 "읽어야" 해. 근데 어떻게 읽지?

그냥... 파일 열면 되는 거 아냐?

그럼 이렇게 생각해봐.

너한테 두 개의 파일을 줄게:

1. game.exe (100MB)

2. photo.jpg (5MB)

둘 다 "파일"이야. 근데 하나는 실행되고, 하나는 이미지로 열려.

Windows는 어떻게 구분할까?

확장자? .exe니까 실행파일이고, .jpg니까 이미지?

반만 맞아! 확장자는 힌트일 뿐이야.

실험해볼까?

1. photo.jpg 파일 이름을 photo.exe로 바꿔봐

2. 더블클릭해봐

→ 실행될까? 안 돼! 오류가 나.

왜냐하면 Windows는 파일 내용을 직접 확인하거든!

Part 2. 파일의 "신분증" - 매직 넘버

파일 내용을 어떻게 확인해?

모든 파일은 맨 앞에 "나는 이런 파일이야"라고 적혀있어.

이걸 매직 넘버(Magic Number) 또는 시그니처라고 해.

📋 비유: 책의 첫 페이지

도서관에서 책을 빌렸어. 표지가 없어졌어.
이게 소설인지, 요리책인지, 사전인지 어떻게 알까?

→ 첫 페이지를 펼쳐봐!
- "옛날 옛적에..." → 아, 동화책이구나
- "재료: 소금 2스푼..." → 아, 요리책이구나
- "aardvark [명사] 땅돼지..." → 아, 사전이구나

파일도 마찬가지야. 첫 몇 바이트를 보면 뭔지 알 수 있어!
그럼 EXE 파일 처음엔 뭐가 적혀있어?

"MZ"라는 두 글자가 적혀있어!

여러 파일 형식의 매직 넘버: ┌─────────────────────────────────────────────────────┐ │ 파일 형식 │ 첫 바이트들 │ 의미 │ ├─────────────────────────────────────────────────────┤ │ .exe / .dll │ 4D 5A (MZ) │ 실행 파일 │ │ .png │ 89 50 4E 47 │ PNG 이미지 │ │ .jpg │ FF D8 FF │ JPEG 이미지 │ │ .pdf │ 25 50 44 46 (%PDF) │ PDF 문서 │ │ .zip │ 50 4B (PK) │ 압축 파일 │ │ .mp3 │ 49 44 33 (ID3) │ MP3 오디오 │ └─────────────────────────────────────────────────────┘ Windows가 game.exe를 더블클릭했을 때: 1. 파일 맨 앞 2바이트 읽기 2. "4D 5A"인지 확인 (MZ인지) 3. 맞으면 → 실행 파일로 처리! 4. 아니면 → "올바른 Win32 응용 프로그램이 아닙니다" 에러
"MZ"가 뭔데? 왜 하필 MZ야?

Mark Zbikowski라는 사람 이름 이니셜이야!

1983년, MS-DOS를 만든 마이크로소프트 개발자야.

자기 이름을 실행 파일 시그니처로 넣은 거지. 😄

40년이 지난 지금도 모든 Windows EXE 파일은 "MZ"로 시작해!

Part 3. 실행 파일 = 설명서 + 실제 내용

MZ 확인했으면 바로 실행하면 되는 거 아냐?

아직 멀었어! Windows는 더 많은 정보가 필요해.

무슨 정보?

생각해봐. 게임을 실행하려면:

1. 이 프로그램은 32비트야? 64비트야?

2. 메모리를 얼마나 할당해줘야 해?

3. 프로그램 시작점이 어디야? (어디서부터 실행해?)

4. 다른 DLL이 필요해? (예: DirectX)

5. 프로그램 아이콘은 어디 있어?

📦 비유: 이케아 가구

이케아에서 책장을 샀어. 박스를 열면 뭐가 있지?

1. 조립 설명서 - 어떻게 조립하는지
2. 부품 목록 - 나사 몇 개, 판자 몇 개
3. 실제 부품들 - 나무 판자, 나사, 볼트

EXE 파일도 똑같아!
1. 헤더 (Header) - 설명서 (이 프로그램은 이렇게 생겼어요)
2. 섹션 정보 - 부품 목록 (코드는 여기, 데이터는 저기)
3. 실제 코드/데이터 - 진짜 프로그램 내용
EXE 파일의 구조 (단순화): ┌────────────────────────────────────────────────────┐ │ │ │ 📋 헤더 (Header) - "설명서" │ │ ┌──────────────────────────────────────────────┐ │ │ │ "나는 64비트 프로그램이야" │ │ │ │ "메모리 주소 0x140000000에 로드해줘" │ │ │ │ "시작점은 offset 0x1234야" │ │ │ │ "kernel32.dll이 필요해" │ │ │ │ "섹션은 4개야" │ │ │ └──────────────────────────────────────────────┘ │ │ │ ├────────────────────────────────────────────────────┤ │ │ │ 📦 섹션들 (Sections) - "실제 내용" │ │ ┌──────────────────────────────────────────────┐ │ │ │ .text - 실행할 코드 (CPU 명령어들) │ │ │ │ .data - 전역 변수들 │ │ │ │ .rdata - 읽기 전용 데이터 (문자열 등) │ │ │ │ .rsrc - 리소스 (아이콘, 버전 정보) │ │ │ └──────────────────────────────────────────────┘ │ │ │ └────────────────────────────────────────────────────┘

Part 4. 헤더를 더 자세히 보자

헤더에 뭐가 들어있어?

헤더도 여러 부분으로 나뉘어:

헤더의 구조: ┌─────────────────────────────────────────────────────┐ │ 1️⃣ DOS Header (64바이트) │ │ └─ "MZ" 시그니처 │ │ └─ PE 헤더 위치 (e_lfanew) │ ├─────────────────────────────────────────────────────┤ │ 2️⃣ DOS Stub (옛날 호환용) │ │ └─ "This program cannot be run in DOS mode." │ │ └─ DOS에서 실행하면 이 메시지 출력 │ ├─────────────────────────────────────────────────────┤ │ 3️⃣ PE Signature (4바이트) │ │ └─ "PE\0\0" (0x50450000) │ │ └─ 여기부터 진짜 PE 포맷 시작! │ ├─────────────────────────────────────────────────────┤ │ 4️⃣ File Header (20바이트) │ │ └─ CPU 종류 (x86? x64? ARM?) │ │ └─ 섹션 개수 │ │ └─ 빌드 시간 │ ├─────────────────────────────────────────────────────┤ │ 5️⃣ Optional Header (224~240바이트) │ │ └─ 프로그램 시작점 (EntryPoint) │ │ └─ 원하는 메모리 주소 (ImageBase) │ │ └─ Import/Export 테이블 위치 │ │ └─ 리소스 위치 │ └─────────────────────────────────────────────────────┘
왜 DOS Header가 있어? DOS는 옛날 거 아냐?

맞아! 1981년 DOS 시절 얘기야.

근데 하위 호환성 때문에 아직도 있어.

만약 누가 옛날 DOS에서 Windows EXE를 실행하면?

→ "This program cannot be run in DOS mode." 메시지 출력!

크래시 대신 친절한 안내를 해주는 거지. 40년 전 코드가 아직도 살아있어!

Part 5. Import Table - "나 이거 필요해!"

Import Table이 뭐야?

게임이 혼자서 모든 걸 할 수 있을까?

예를 들어:

- 화면에 그림 그리기 → GPU 드라이버 필요

- 파일 읽기 → 운영체제 기능 필요

- 소리 재생 → 오디오 드라이버 필요

아, 그래서 DLL이 필요한 거구나?

맞아! Import Table은 이 프로그램이 필요로 하는 외부 함수 목록이야.

🍳 비유: 요리 레시피

김치찌개 레시피를 보면 맨 위에 "재료"가 있지?
- 김치 200g (냉장고에서 꺼내기)
- 돼지고기 100g (정육점에서 사오기)
- 두부 1모 (마트에서 사오기)

Import Table도 마찬가지야:
- CreateWindowEx (user32.dll에서 가져오기)
- ReadFile (kernel32.dll에서 가져오기)
- D3D11CreateDevice (d3d11.dll에서 가져오기)

요리 시작 전에 재료 준비하듯,
프로그램 시작 전에 필요한 함수들을 준비해!
게임 EXE의 Import Table 예시: ┌─────────────────────────────────────────────────────┐ │ game.exe가 필요로 하는 것들: │ ├─────────────────────────────────────────────────────┤ │ │ │ 📁 kernel32.dll (Windows 기본 기능) │ │ ├─ CreateFileW (파일 열기) │ │ ├─ ReadFile (파일 읽기) │ │ ├─ VirtualAlloc (메모리 할당) │ │ └─ GetTickCount64 (시간 측정) │ │ │ │ 🖼️ user32.dll (창, UI 관련) │ │ ├─ CreateWindowExW (창 만들기) │ │ ├─ ShowWindow (창 보여주기) │ │ └─ GetMessageW (입력 받기) │ │ │ │ 🎮 d3d11.dll (DirectX 11 그래픽) │ │ ├─ D3D11CreateDevice │ │ └─ D3D11CreateDeviceAndSwapChain │ │ │ └─────────────────────────────────────────────────────┘ 프로그램 시작 시: 1. Windows가 Import Table을 읽음 2. "kernel32.dll 로드해야겠다" 3. kernel32.dll을 메모리에 올림 4. CreateFileW 함수 주소를 찾아서 EXE에 알려줌 5. 모든 DLL 로드 완료 → 프로그램 시작!

Part 6. Export Table - "나 이거 제공해!"

Export Table은 뭐야?

Import의 반대야!

Import = "나 이 함수 필요해"

Export = "나 이 함수 제공해"

EXE도 Export가 있어?

EXE는 보통 없고, DLL이 Export를 제공해!

DLL은 "나한테 이런 함수들 있어, 가져다 써!"라고 광고하는 거야.

kernel32.dll의 Export Table (일부): ┌─────────────────────────────────────────────────────┐ │ kernel32.dll이 제공하는 함수들: │ ├─────────────────────────────────────────────────────┤ │ 이름 │ 주소 │ 설명 │ ├─────────────────────────────────────────────────────┤ │ CreateFileW │ 0x0002B100 │ 파일 열기 │ │ ReadFile │ 0x0002C200 │ 파일 읽기 │ │ WriteFile │ 0x0002C300 │ 파일 쓰기 │ │ VirtualAlloc │ 0x0001A000 │ 메모리 할당 │ │ GetTickCount64 │ 0x00015000 │ 시간 측정 │ │ ... │ ... │ ... │ │ (총 1500개 이상의 함수!) │ └─────────────────────────────────────────────────────┘ GetProcAddress() 함수가 하는 일: "kernel32.dll에서 CreateFileW 함수 주소 찾아줘" → Export Table 검색 → "0x0002B100이야!"

Part 7. 리소스 섹션 - 아이콘은 어디에?

게임 EXE 아이콘은 어디 저장돼 있어?

.rsrc 섹션에 있어!

리소스(Resource) 섹션에는:

- 프로그램 아이콘

- 버전 정보 (1.0.0 같은)

- 저작권 정보

- 다국어 문자열 (한국어, 영어, 일본어...)

그래서 Resource Hacker 같은 프로그램으로 아이콘을 바꿀 수 있는 거구나!

맞아! EXE 파일의 .rsrc 섹션만 수정하면 아이콘이 바뀌어.

코드는 건드리지 않고 리소스만 바꾸는 거지.

.rsrc 섹션 구조: ┌─────────────────────────────────────────────────────┐ │ 리소스 트리 (폴더처럼 계층 구조) │ ├─────────────────────────────────────────────────────┤ │ │ │ 📁 Root │ │ ├─ 📁 RT_ICON (아이콘) │ │ │ ├─ 🖼️ 16x16 │ │ │ ├─ 🖼️ 32x32 │ │ │ ├─ 🖼️ 48x48 │ │ │ └─ 🖼️ 256x256 │ │ │ │ │ ├─ 📁 RT_VERSION (버전 정보) │ │ │ └─ 📄 "1.0.0.0" │ │ │ └─ "MyGame Inc." │ │ │ └─ "Copyright 2024" │ │ │ │ │ ├─ 📁 RT_STRING (문자열) │ │ │ ├─ 🌐 한국어: "게임 시작" │ │ │ ├─ 🌐 영어: "Start Game" │ │ │ └─ 🌐 일본어: "ゲーム開始" │ │ │ │ │ └─ 📁 RT_MANIFEST (앱 설정) │ │ └─ DPI 인식, UAC 권한 등 │ │ │ └─────────────────────────────────────────────────────┘

Part 8. 정리: EXE 더블클릭하면 일어나는 일

처음 질문으로 돌아가서, 전체 과정을 정리해줘!

이제 전체 그림이 보이지?

game.exe 더블클릭 → 실행까지: 1️⃣ 파일 시그니처 확인 └─ 첫 2바이트 = "MZ"? ✓ 실행 파일 맞음! 2️⃣ PE 헤더 읽기 └─ DOS Header의 e_lfanew → PE 헤더 위치 └─ PE Signature = "PE\0\0"? ✓ PE 포맷 맞음! 3️⃣ File Header 확인 └─ Machine = 0x8664? ✓ 64비트 프로그램 └─ 내 Windows가 64비트? ✓ 실행 가능! 4️⃣ Optional Header 확인 └─ ImageBase = 0x140000000 (원하는 메모리 주소) └─ EntryPoint = 0x1234 (시작점) 5️⃣ Import Table 처리 └─ kernel32.dll 로드 └─ user32.dll 로드 └─ d3d11.dll 로드 └─ 각 함수 주소 연결 6️⃣ 섹션들을 메모리에 배치 └─ .text → 실행 가능 영역에 └─ .data → 읽기/쓰기 영역에 └─ .rdata → 읽기 전용 영역에 7️⃣ EntryPoint로 점프! └─ 드디어 게임 코드 실행 시작! 총 소요 시간: 수십 밀리초 (0.0X초) 우리 눈엔 그냥 "클릭하니까 바로 실행됨"

📌 핵심 정리

  • 매직 넘버 "MZ" - 모든 Windows 실행 파일은 MZ로 시작 (Mark Zbikowski)
  • 헤더 - 프로그램의 "설명서" (어떻게 실행할지 정보)
  • 섹션 - 프로그램의 "실제 내용" (.text=코드, .data=데이터, .rsrc=리소스)
  • Import Table - "나 이 DLL 함수 필요해" 목록
  • Export Table - DLL이 "나 이 함수 제공해" 광고
  • .rsrc 섹션 - 아이콘, 버전 정보, 다국어 문자열
