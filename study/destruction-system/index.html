건물이 1만 조각으로 부서지는데 60fps가 나온다고?

현실처럼 와르르 무너지는 파괴 시스템의 원리와 최적화

왜 조각내야 해?

왜 건물이 통째로 사라지지 않고 조각나야 해?

몰입감 때문이야.

건물에 로켓이 맞았는데 "뻥!" 하고 통째로 사라지면 → 게임 티가 난다.

하지만 현실처럼 조각나면서 무너지면 → 플레이어가 "진짜로 부쉈다"고 느낀다.

예전 게임들은 왜 안 그랬어?

성능 문제 때문.

조각 1개 = 오브젝트 1개 = 물리 시뮬레이션 1개

건물 하나가 1000개 조각으로 쪼개지면? → CPU가 물리 계산하느라 폭발

그래서 예전에는:

  • 건물이 통째로 사라지거나
  • 미리 만든 "부서진 모델"로 교체하거나
  • 조각을 5~10개만 만들어서 대충 처리했다

조각은 몇 개나 만들어?

현실적으로 보이려면 조각이 몇 개나 필요해?

게임마다 다르지만:

  • 작은 물체 (상자, 병): 10~50개
  • 중간 물체 (벽, 기둥): 100~500개
  • 큰 건물: 1,000~10,000개

Teardown 같은 게임은 복셀 기반이라 수십만 개도 처리한다.

10,000개 조각을 다 렌더링해? 물리 계산도 다 해?

당연히 아니야.

그렇게 하면 FPS가 0.1로 떨어진다.

그래서 최적화 기법들을 사용한다. (뒤에서 설명)

어떻게 조각을 만드는가?

실시간으로 조각을 만들어? 미리 만들어?

두 가지 방법이 있어:

Pre-fractured (미리 만들기) Runtime Fracture (실시간 생성)
개발할 때 미리 조각내서 저장 게임 중 충돌 지점에서 즉시 생성
✅ 런타임 부하 없음 ⚠️ CPU 부하 큼
⚠️ 항상 같은 패턴으로 부서짐 ✅ 매번 다르게 부서짐
⚠️ 메모리 사용량 증가 ✅ 메모리 효율적

대부분의 게임은 Pre-fractured를 사용한다. 성능이 우선이니까.

조각은 어떻게 나누는 거야?

대표적인 방법: Voronoi Diagram (보로노이 다이어그램)

🍕 비유: 피자 나누기

10명이 피자를 나눠 먹는다고 생각해봐.
각자 랜덤한 위치에 서 있어.

규칙: "각자 가장 가까운 피자 조각을 가져간다"

그러면 피자가 10조각으로 자연스럽게 나뉘지?
이게 Voronoi 방식이야.

Voronoi Fracture 동작 방식:

1. 건물 안에 랜덤하게 "시드 포인트" N개 배치
2. 각 점에서 가장 가까운 공간을 계산
3. 그 공간들이 조각이 된다
4. 조각마다 메시 생성 + 물리 콜라이더 추가

결과: 자연스럽고 불규칙한 조각들

최적화: 어떻게 60fps를 유지하는가?

10,000개 조각을 어떻게 처리해?

핵심: 보이거나 중요한 것만 처리한다

1. LOD (Level of Detail)

거리에 따라 디테일을 줄인다.

  • 가까이 (0~10m): 모든 조각 렌더링 (1000개)
  • 중간 (10~50m): 작은 조각 제거 → 100개만 표시
  • 멀리 (50m+): 조각 전체를 하나의 "잔해 더미" 메시로 교체 → 1개

결과: 멀리서는 1개 오브젝트만 렌더링

2. Instancing

비슷한 조각들을 한 번에 그린다.

예를 들어, 벽돌 건물이 부서졌을 때:

  • 벽돌 조각 A가 500개
  • 각각 다른 위치/회전

일반 렌더링: 500번 Draw Call → 느림

Instancing: 1번 Draw Call → 빠름

GPU Instancing:
1. 벽돌 메시 1개 준비
2. 위치/회전 데이터 500개를 배열로 전송
3. GPU가 알아서 500개 그림 → Draw Call 1번!

3. Frustum Culling

카메라 밖 조각은 안 그린다.

화면 밖에 있는 조각들을 매 프레임마다 체크:

  • 카메라 시야 안에 있어? → 렌더링
  • 화면 밖이야? → 건너뛰기

10,000개 중 실제로 그리는 건 500~1000개 정도

4. Sleep (물리 엔진)

움직이지 않는 조각은 물리 계산 중지

조각이 땅에 떨어진 후:

  • 2~3초 동안 굴러다님 → 물리 계산 ON
  • 멈춤 → Sleep 상태 전환 → 물리 계산 OFF

10,000개 중 실제로 계산하는 건 20~50개 정도

PhysX/Bullet 물리 엔진:
- 속도가 일정 임계값 이하로 떨어지면 자동 Sleep
- Sleep 중인 물체는 충돌 체크도 간소화
- 다시 충돌하면 Wake up → 물리 계산 재개

5. Object Pooling

조각을 재활용한다.

파괴가 반복되는 게임 (예: 멀티플레이어 슈팅)에서:

  • 건물 1 부서짐 → 조각 1000개 생성
  • 5초 후 조각들 소멸 → 메모리 해제
  • 건물 2 부서짐 → 조각 1000개 다시 생성

이렇게 하면 GC(가비지 컬렉션)가 계속 발동 → 렉 발생

Object Pooling 방식:

1. 게임 시작 시 조각 2000개를 미리 생성 (Pool)
2. 건물 부서질 때 Pool에서 꺼내 씀
3. 5초 후 소멸 대신 Pool에 반환
4. 다음 건물이 부서지면 Pool에서 다시 꺼냄

→ 생성/삭제 없음 → GC 없음 → 부드러운 프레임

6. Time-Sliced Processing

파괴가 발생하는 순간 CPU 스파이크가 발생할 수 있어.

예: 10,000개 조각 생성 → 1프레임에 10ms 소요 → 렉 발생

해결책: 여러 프레임에 나눠서 생성

Frame 1: 조각 500개 생성 (2ms)
Frame 2: 조각 500개 생성 (2ms)
Frame 3: 조각 500개 생성 (2ms)
...

→ 20프레임에 걸쳐 10,000개 생성
→ 프레임당 2ms만 소요 → 렉 없음

단점: 파괴가 0.3초에 걸쳐 점진적으로 발생하지만, 플레이어는 잘 못 느낌

실제 게임 사례

1. Red Faction: Guerrilla (2009)

최초로 완전한 건물 파괴를 구현한 게임.

  • 기법: Pre-fractured + Structural Simulation
  • 건물을 구조적 요소(기둥, 벽, 지붕)로 분해
  • 기둥이 파괴되면 → 지붕이 무게를 못 버티고 무너짐
  • 실시간 물리가 아니라 힘 분산 시뮬레이션

최적화:

  • 조각 수를 100~300개로 제한
  • 멀리 떨어지면 조각 제거
  • 땅에 닿은 조각은 즉시 Sleep

2. Teardown (2022)

복셀 기반 파괴 시스템.

  • 건물을 작은 복셀(큐브)로 구성 → 수십만 개
  • 파괴 시 복셀 단위로 제거/분리
  • 최적화: GPU에서 복셀 렌더링 (Compute Shader)

핵심: 모든 복셀을 개별 오브젝트로 처리하지 않고, Chunk 단위로 묶어서 처리

예: 벽이 100x100x10 = 100,000개 복셀
→ 10x10x10 Chunk로 분할 → 1000개 Chunk
→ Chunk가 연결되어 있으면 하나의 물리 Body
→ 파괴되면 Chunk가 분리되어 개별 Body로 전환

→ 물리 계산은 수백 개만 처리

3. Control (2019)

PhysX + Nvidia Flex 기반 파괴.

  • 벽/가구가 실시간으로 부서짐
  • 조각들이 바닥에 쌓이고 상호작용
  • 최적화: 조각이 일정 시간 후 페이드 아웃
  • 많은 조각이 쌓이면 오래된 것부터 제거

상용 엔진의 파괴 시스템

상용 엔진에서는 이런 파괴 시스템이 이미 있어?

Unreal Engine에는 완벽하게 내장되어 있고, Unity는 외부 에셋이 필요해.

Unreal Engine: Chaos Destruction

Chaos Destruction이 뭐야?

Unreal Engine 4.26+와 UE5에 내장된 올인원 파괴 시스템이야.

포함된 기능:

  • Voronoi Fracture - 조각 나누기 (자동)
  • 충돌 기반 파괴 - 충돌 지점/힘 자동 계산
  • 힘 전파 - 주변 조각으로 힘이 퍼짐
  • 구조 붕괴 - 기둥 부러지면 건물 무너짐
충돌 기반 파괴가 뭔데?

무거운 구가 건물에 떨어졌을 때, 구의 무게/속도에 따라 파괴 범위가 달라지는 것.

원리:

1. 충돌 감지 → 충돌 지점 P 계산
2. 충돌 힘 F = 질량 × 속도²
3. 충돌 지점 근처 조각들에게 힘 분배:
   - 가까운 조각 = 큰 힘 (멀리 날아감)
   - 먼 조각 = 작은 힘 (조금만 움직임)
   - 거리에 따라 감쇠 (1/distance²)

예:
- 100kg 구 → 반경 2m만 파괴
- 1000kg 구 → 반경 6m 파괴
Chaos는 뭘 자동으로 해줘?

거의 모든 걸 자동으로 처리해:

  • ✅ Voronoi Fracture - 버튼 한 번에 조각 생성
  • ✅ 충돌 감지 - 어디에 부딪혔는지 자동 계산
  • ✅ 힘 계산 - 질량 × 속도로 파괴력 계산
  • ✅ 힘 전파 - 주변 조각으로 힘이 퍼짐
  • ✅ 물리 시뮬레이션 - 조각들이 날아가고 굴러감
  • ✅ 최적화 - Clustering, Sleep, LOD 자동

개발자는 숫자 몇 개만 조정하면 됨 (Damage Threshold, Mass 등)

Geometry Collection이 뭐야?

Chaos에서 사용하는 파괴 가능한 오브젝트야.

일반 Static Mesh와의 차이:

Static Mesh Geometry Collection
하나의 통 덩어리 수천 개의 조각으로 구성
부딪혀도 안 부서짐 충돌 시 조각으로 분리
Physics Body 1개 조각마다 Physics Body (동적 생성)

작동 방식:

평상시:
- 모든 조각이 하나로 붙어있음 (1개 Physics Body)
- 렌더링도 1개로 처리 (빠름)

충돌 발생:
- 충돌 지점 근처 조각들이 분리됨
- 각 조각이 개별 Physics Body로 전환
- 힘을 받아 날아감

→ 필요한 부분만 분리 = 최적화

Unity

Unity는 기본 엔진에 파괴 시스템이 없음.

Asset Store에서 구매 필요:

📌 핵심 정리: 건물 파괴 시스템

  • Voronoi Fracture - 건물을 자연스러운 조각으로 분해하는 알고리즘
  • 충돌 기반 파괴 - 충돌 지점/힘에 따라 파괴 범위와 힘이 달라짐
  • 힘 전파 - 충돌 지점에서 주변 조각으로 힘이 거리에 따라 감쇠하며 퍼짐
  • Pre-fractured - 미리 조각내서 저장 → 런타임 부하 없음 (대부분 사용)
  • Runtime Fracture - 실시간 생성 → 매번 다른 패턴, 하지만 CPU 부하 큼
  • LOD - 거리에 따라 조각 수 감소 (10,000개 → 100개 → 1개)
  • Instancing - 비슷한 조각을 한 번에 그려서 Draw Call 감소
  • Culling - 화면 밖 조각은 렌더링 안 함
  • Sleep - 멈춘 조각은 물리 계산 중지 (10,000개 → 50개만 계산)
  • Object Pooling - 조각 재활용으로 GC 방지
  • Time-Sliced - 여러 프레임에 나눠 생성해서 스파이크 방지
  • Chaos Destruction (UE) - Voronoi + 충돌 파괴 + 최적화를 자동으로 처리하는 올인원 시스템

결론: 1만 개 조각도 실제론 50~500개만 처리하면 60fps 나온다!
