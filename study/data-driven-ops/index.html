배달앱처럼 게임 문제를 미리 아는 법

게임 운영자가 뭐하는 사람이야?

대부분 사람들이 생각하는 운영자:

  • 공지 올리는 사람
  • 업데이트 안내하는 사람
  • 고객센터 답변하는 사람

하지만 이건 2022년까지 이야기야.

2025년 넥슨 네트웍스 운영자는 데이터 과학자이기도 해.

1️⃣ 왜 데이터 드리븐 운영이 필요했을까?

기존 운영 방식은 뭐가 문제였어?

고객이 불편을 겪은 후에야 알 수 있었어.

이게 무슨 말이냐면...

🍕 비유: 배달 서비스

당신이 치킨을 시켰는데 식어서 도착했어.

기존 방식:
1. 고객이 식은 치킨을 받음
2. 고객이 고객센터에 전화함
3. 문제를 확인하고 재발송
→ 이미 고객은 불편을 겪었어

데이터 드리븐 방식:
1. 배달 시간이 평소보다 10분 길어짐 (데이터 감지)
2. 자동으로 쿠폰 발송 + 다음엔 더 빠른 배달원 배정
→ 고객이 말하기 전에 문제 해결!
게임에서는 어떻게 적용해?

데이터 드리븐 운영 = 데이터를 기반으로 판단하고 대응하는 것

목표: 문제없는 게임 환경 제공

고객이 게임 본연의 재미에만 집중할 수 있도록!

2️⃣ 3가지 핵심 변화

1고객 경험 여정 관리

경험 여정이 뭐야?

경험 = 재미, 불편, 성취감 같은 감정

여정 = 캐릭터 생성 → 성장 → 던전 클리어 같은 플레이 단계

경험 여정 = 플레이 전 과정에서 고객이 겪는 모든 것

기존 방식:

플레이어 상황:
┌────────────┐
│ 퀘스트 위치│
│  못 찾음   │  ← 10분 헤맴...
└──────┬─────┘
       ↓
┌──────────────────┐
│ 고객센터 문의    │
└──────┬───────────┘
       ↓
┌──────────────────┐
│  운영자 답변     │
└──────┬───────────┘
       ↓
┌──────────────────┐
│ 플레이어 찾아감  │
└──────────────────┘

⚠️ 문제: 이미 플레이어는 10분을 허비했어

데이터 드리븐 방식:

┌──────────────────────┐
│  데이터 모니터링     │ ← 실시간 감지
│  3분간 정지 감지!    │
└──────┬───────────────┘
       ↓
┌──────────────────────┐
│ 자동 힌트 발송       │
│ "북쪽 숲으로!"       │
└──────┬───────────────┘
       ↓
┌──────────────────────┐
│ 플레이어 바로 찾음   │ ✓
└──────────────────────┘

✅ 결과: 플레이어는 불편을 겪지 않았어!
어떻게 자동으로 메시지를 보내?

1. 과거 데이터를 분석해서 "이 구간에서 많이 헤맨다"는 패턴 발견

2. 조건 설정: "3분 이상 정지 + 퀘스트 미완료"

3. 조건 충족 시 자동 메시지 발송 프로세스 구축

운영자가 24시간 모니터링 안 해도 돼!

2문제 정의 방식의 변화

무슨 게임 버그가 문제인지 어떻게 판단해?

예시: 고가 장비를 실수로 재료로 사용해서 삭제됨

기존 운영자 A 데이터 드리븐 운영자 B
판단 기준:
- VOC 100건 접수
- 전체 문의의 5%
- 이전 대비 2배 증가

"이거 문제인가?"
→ 주관적 판단 		판단 기준:
- 실수한 전체 고객: 1,200명
- 당장 이탈: 30% (360명)
- 실수 안 한 유저 대비 1주일 후 이탈률 50% 더 높음

"이거 심각한 문제야!"
→ 객관적 데이터
데이터로 뭘 더 분석해?

확장된 분석 영역:

1. 가방 분석
   - 아이템이 너무 많아서 게임 플레이에 지장?
   - 필요 없는 아이템 자동 정리 기능 제안

2. 이탈 패턴 분석
   - 어떤 플레이 패턴이 이탈로 이어지나?
   - 사전에 리텐션 이벤트 발송

3. 푸시 메시지 분석
   - 자동 푸시가 실제로 유저에게 도움이 되나?
   - 효과 없는 푸시 OFF

4. 콘텐츠 밸런싱
   - 보상이 너무 짜거나 너무 많진 않나?
   - 고객 관점에서 밸런스 조정

VOC 1건이든 없든, 진짜 문제는 데이터로 찾아낸다!

3문제 조기 탐지

문제가 없는데 왜 탐지해?

조기 탐지 = 실시간 또는 준실시간 탐지

이유:

1. 게임 시스템은 유기적으로 연결되어 있어서 하나의 문제가 연쇄 영향을 미칠 수 있음

2. 조기 탐지 = 게임이 잘 돌아간다는 신뢰 데이터 확보

🏥 비유: 건강 검진

왜 아프지 않은데 건강 검진을 할까?

→ 병이 생기기 전에 조기 발견하려고
→ 건강하다는 확신을 얻으려고

게임도 마찬가지야.
문제가 없어도 계속 체크해야 문제가 생길 때 3시간 → 3분으로 발견할 수 있어! 
기존 방식:
문제 발생 → (3시간 후) → 내부 제보 → 확인 → 대응

3시간 동안 수천 명이 피해
데이터 드리븐 방식:
문제 발생 → (3분 후) → 실시간 알림 → 즉시 대응

3분 안에 탐지! 피해 최소화!

        

            
어떻게 3분 만에 알아?

            

                
1. 실시간 데이터 분석 환경 구축

                
2. 문제 발생 조건 미리 설정 (예: DAU 급감 10%, 던전 클리어율 0%)

                
3. 조건 충족 시 자동 알림

                
4. 운영자가 즉시 확인 및 조치

            

        


        
3️⃣ 어떻게 전 직원이 데이터를 다루게 됐을까?


        

            
운영자가 데이터 분석까지 해? 개발자 아니고?

            

                
운영자는 고객과 가장 가까운 사람

                
→ 게임을 제일 잘 알고

                
→ 고객을 제일 잘 이해하고

                
→ 어떤 데이터를 봐야 할지 제일 잘 알아

                
운영자가 데이터를 다루면:

                
→ 게임 특성에 맞는 정교한 인사이트 도출 가능

                
→ 데이터 전문 조직과 협업하면 의사결정 정확도 상승

            

        


        
1경험 전파 (네트워크 이펙트)


        

            
어떻게 전 직원이 데이터를 배웠어?

            

                
1. 전사 공유 채널 마련

                
2. 누구나 자신의 데이터 활용 경험을 공유

                
3. 리더가 시도 자체를 칭찬 (좋고 나쁨 떠나서)

                
4. 다른 팀이 공유한 내용을 우리 프로젝트에 적용

                
5. 효과를 체감 → 더 많이 공유 → 선순환

            

        



티핑 포인트:

처음: "내 경험을 전사에 공유? 부담스러운데..."

리더의 역할:
- "공유해 줘서 고마워!" (계속 표현)
- "이거 우리도 적용해 볼까?" (리소스 투입)
- "효과 있었어! 감사 메일 보냄" (피드백)

결과: "인사이트 있으니까 공유하자!"

1년 만에 전파 건수 4배 증가!
네트워크 이펙트 달성!

        

            
네트워크 이펙트가 뭐야?

            

                
네트워크 이펙트 = 사용자가 많아질수록 가치가 커지는 현상

                
예: 카카오톡 - 친구가 많을수록 유용해짐

                
넥슨에서:

                
→ 공유하는 사람이 많아질수록

                
→ 배울 게 많아지고

                
→ 더 많이 공유하게 되는 선순환

                
이제는 장치 없이도 자연스럽게 공유하는 문화 정착!

            

        


        
2직무 역량 온보딩 프로그램


        

            
신입사원은 어떻게 배워?

            

                
교육부터 하면 안 돼?

                
→ NO! 경험 전파가 먼저

                
→ 네트워크 이펙트 달성 후

                
→ 체계적인 온보딩 프로그램 탄생

            

        



온보딩 프로그램 구조:

[기본]
- 고객 이해
- 서비스 이해
- 게임 이해

[데이터 활용]
- 데이터 도구 사용법
- 분석 기법
- 챕터별 실습

[선순환]
신입사원이 온보딩 자료를 탐구
→ 보완점 제안
→ 다음 신입을 위해 개선
→ 실효성 있는 자료로 계속 발전

        
3데이터 활용 업무 표준화


        

            
표준화는 왜 필요해?

            

                
문제: 데이터 역량 격차 발생

                
- 어떤 사람은 코딩까지 다 함

                
- 어떤 사람은 특정 영역만 강함

                
목표: 상향 평준화 (바닥 끌어올리기)

                
→ 모두가 일정 수준 이상의 역량 갖추기

            

        



표준화 프로세스:

1. 유효한 자동화 업무 선별
   예: 일일 리포트, 이상 탐지, 지표 모니터링

2. 필요한 데이터 역량 정의
   예: SQL 기본, 파이썬 기초, 대시보드 제작

3. 실습 자료 제공
   예: 아카이빙된 사례, 단계별 튜토리얼

4. 필수 내제화
   → 누구나 기본은 할 수 있게

5. 더 나은 방법 연구 장려
   → 표준은 출발선일 뿐!

6. 결과 공유
   → 네트워크 이펙트로 전파
   → 보완 후 다시 표준화 흡수
   → 선순환!

📌 핵심 정리: 데이터 드리븐 운영

            
    
                
  • 데이터 드리븐 운영 - 데이터를 기반으로 판단하고 대응하는 운영 방식
    • 
                
  • 목표 - 문제없는 게임 환경 제공 (고객이 재미에만 집중)
    • 
                
  • 3가지 변화
                    
      
                        
    • 1. 고객 경험 여정 관리 (사전 힌트 제공)
      • 
                        
    • 2. 문제 정의 방식 변화 (VOC → 데이터 기반)
      • 
                        
    • 3. 조기 탐지 (3시간 → 3분)
      • 
                    
    
                
    • 
                
  • 전 직원 데이터 역량
                    
      
                        
    • 1. 경험 전파 → 네트워크 이펙트
      • 
                        
    • 2. 온보딩 프로그램
      • 
                        
    • 3. 업무 표준화 → 상향 평준화
      • 
                    
    
                
    • 
                
  • DAU (Daily Active Users) - 일일 활성 유저 수
    • 
                
  • VOC (Voice of Customer) - 고객의 소리 (문의, 피드백)
    • 
                
  • 리텐션 - 유저가 게임에 다시 접속하는 비율
    • 
                
  • 핵심 메시지 - 운영자는 더 이상 사후 대응만 하는 사람이 아니라, 데이터로 문제를 예측하고 사전에 해결하는 사람!
