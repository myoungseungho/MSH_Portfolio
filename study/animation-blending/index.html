애니메이션 블렌딩 (Animation Blending) 원리

1. "걷기"에서 "뛰기"로 바뀔 때 뭐가 문제야?

게임에서 W키 눌러서 걷다가 Shift 눌러서 뛰면?

블렌딩 없이 그냥 바꾸면:

프레임 1: 🚶 (걷기) 프레임 2: 🏃 (뛰기) ← 갑자기 확 바뀜!

→ 뚝뚝 끊겨 보임. 로봇 같음.

현실에서 걷다가 뛸 때 갑자기 확 바뀌어?

아니지. 점점 빨라지잖아.

걷기 → (점점 속도 증가) → 뛰기

그걸 게임에서 구현하는 게 애니메이션 블렌딩이야.

2. "섞는다"는 게 정확히 뭐야?

두 애니메이션을 어떻게 섞어?

동시에 재생하되, 비율을 조절하는 거야.

걷기 애니메이션: 🚶 (어깨 높이 = 100cm) 뛰기 애니메이션: 🏃 (어깨 높이 = 105cm) 블렌딩: 🚶 70% + 🏃 30% = 어깨 높이 101.5cm → 🚶‍💨 (걷는 것과 뛰는 것 사이!)
모든 뼈대를 다 섞어야 해?

그렇지! 캐릭터의 모든 뼈대를 똑같이 섞어.

뼈대 걷기 🚶 뛰기 🏃 블렌딩 (70% + 30%)
어깨 10도 45도 20.5도
팔꿈치 -5도 -30도 -11도
골반 2도 8도 4.6도
무릎 15도 60도 28.5도

전체 뼈대를 섞으니까 자연스럽게 중간 동작이 나와!

3. 블렌딩 원리: 어떻게 "섞어"?

각 뼈대를 어떻게 계산해?

단계별로 보자:

1️⃣ 걷기 애니메이션의 어깨 각도: shoulder->rotation = 10도 2️⃣ 뛰기 애니메이션의 어깨 각도: shoulder->rotation = 45도 3️⃣ 블렌딩 (70% 걷기 + 30% 뛰기): float walkWeight = 0.7f; // 70% float runWeight = 0.3f; // 30% shoulder->rotation = (10도 × 0.7) + (45도 × 0.3) = 7도 + 13.5도 = 20.5도 // 중간 값!
수학 공식으로 정리하면?
블렌딩 공식

최종값 = (A 애니메이션 × A 가중치) + (B 애니메이션 × B 가중치)

조건: A 가중치 + B 가중치 = 1.0
// C++ 예시 float walkShoulder = 10.0f; // 걷기 어깨 각도 float runShoulder = 45.0f; // 뛰기 어깨 각도 float walkWeight = 0.7f; float runWeight = 0.3f; float finalShoulder = (walkShoulder * walkWeight) + (runShoulder * runWeight); = (10 * 0.7) + (45 * 0.3) = 7 + 13.5 = 20.5도

4. 그럼 비율은 어떻게 바뀌어?

70%에서 30%로 갑자기 바뀌면 또 부자연스럽지 않아?

정확해! 시간에 따라 점진적으로 바뀌어야 해.

시간: 0.0초 → 0.5초 → 1.0초 걷기: 100% → 50% → 0% 뛰기: 0% → 50% → 100% 0.0초: 🚶 (100% 걷기) 0.25초: 🚶‍ (75% 걷기 + 25% 뛰기) 0.5초: 🚶‍💨 (50% 걷기 + 50% 뛰기) 0.75초: 💨🏃 (25% 걷기 + 75% 뛰기) 1.0초: 🏃 (100% 뛰기)
코드로는 어떻게 구현해?
float blendDuration = 1.0f; // 1초에 걸쳐 전환 float elapsedTime = 0.0f; void Update(float deltaTime) { elapsedTime += deltaTime; // 0 → 1로 증가 float t = elapsedTime / blendDuration; // 비율 계산 walkWeight = 1.0f - t; // 1 → 0으로 감소 runWeight = t; // 0 → 1로 증가 // 모든 뼈대에 적용 for (int i = 0; i < skeleton->boneCount; i++) { Bone* bone = skeleton->bones[i]; float walkRot = walkAnim->GetRotation(bone); float runRot = runAnim->GetRotation(bone); bone->rotation = walkRot * walkWeight + runRot * runWeight; } }

5. Lerp랑 Slerp는 뭐야?

블렌딩 할 때 자주 나오는 용어인데...

Lerp (Linear Interpolation) - 선형 보간

위치나 숫자를 섞을 때 사용:

float Lerp(float a, float b, float t) { return a + (b - a) * t; } // 예시 Lerp(10, 50, 0.0) = 10 // t=0일 때 a Lerp(10, 50, 0.5) = 30 // t=0.5일 때 중간 Lerp(10, 50, 1.0) = 50 // t=1일 때 b // 벡터도 가능 Vector3 Lerp(Vector3 a, Vector3 b, float t) { return a + (b - a) * t; }
Slerp는?

Slerp (Spherical Linear Interpolation) - 구면 선형 보간

회전(Quaternion)을 섞을 때 사용:

// 회전은 3D 공간에서 구(Sphere) 위를 움직이니까 // 직선이 아니라 곡선으로 섞어야 자연스러움 Quaternion Slerp(Quaternion a, Quaternion b, float t) { // 구면상의 최단 경로로 보간 // 내부 구현은 복잡하지만, // "자연스러운 회전"을 보장 return ...; }

왜 다를까?

대상 방법 이유
위치 섞기 Lerp (직선) 10m → 50m, 직선으로 30m ✅
회전 섞기 Slerp (곡선) 0도 → 180도, 구면으로 90도 ✅
직선은 부자연스러움 ❌

6. 진짜 코드는 어떻게 생겼어?

실제 게임 엔진 스타일로 보여줘
// C++ 간단 버전 struct Bone { Quaternion rotation; // 회전 Vector3 position; // 위치 }; // 뼈대 하나 블렌딩 Bone BlendBone(Bone boneA, Bone boneB, float weight) { Bone result; // 회전 섞기 (Slerp 사용) result.rotation = Slerp( boneA.rotation, boneB.rotation, weight ); // 위치 섞기 (Lerp 사용) result.position = Lerp( boneA.position, boneB.position, weight ); return result; } // 전체 스켈레톤 블렌딩 void BlendAnimations( Animation* walkAnim, Animation* runAnim, float runWeight // 0~1 ) { for (int i = 0; i < skeleton->boneCount; i++) { // 각 애니메이션에서 뼈대 상태 가져오기 Bone walkBone = walkAnim->GetBone(i); Bone runBone = runAnim->GetBone(i); // 블렌딩해서 스켈레톤에 적용 skeleton->bones[i] = BlendBone( walkBone, runBone, runWeight ); } }
3개 이상도 섞을 수 있어?

당연하지!

// 걷기 + 뛰기 + 점프 동시에 walkWeight = 0.4f; // 40% runWeight = 0.3f; // 30% jumpWeight = 0.3f; // 30% // 조건: 0.4 + 0.3 + 0.3 = 1.0 ✅ for (각 뼈대) { bone->rotation = walkAnim->GetRotation(bone) * walkWeight + runAnim->GetRotation(bone) * runWeight + jumpAnim->GetRotation(bone) * jumpWeight; }

실제 사례: 캐릭터가 달리면서 점프하면서 총 쏠 때!

📌 핵심 정리: 애니메이션 블렌딩

  • 블렌딩이란? - 두 개 이상의 애니메이션을 비율로 섞어서 자연스러운 전환을 만드는 것
  • 왜 필요? - 갑자기 애니메이션이 바뀌면 뚝뚝 끊겨 보이니까
  • 원리 - 각 뼈대의 값을 가중치(비율)로 곱해서 더함
  • 공식 - 최종값 = A×가중치A + B×가중치B (조건: 가중치 합 = 1.0)
  • Lerp - 위치/숫자를 직선으로 섞기
  • Slerp - 회전을 구면(곡선)으로 섞기
  • 시간 전환 - 가중치를 점진적으로 바꿔서 부드럽게 전환
  • 다중 블렌딩 - 3개 이상도 가능 (걷기+뛰기+점프)

🎮 실제 게임에서 어떻게 쓰여?

상황 블렌딩 방법
걷기 → 뛰기 1초에 걸쳐 가중치 100%→0%, 0%→100%
서있다가 앉기 0.5초에 걸쳐 Idle → Crouch 블렌딩
달리면서 총 쏘기 하체: 달리기 100%, 상체: 사격 100%
부상당한 상태로 걷기 걷기 70% + 부상 애니메이션 30%
경사면 걷기 평지 걷기 + 경사각도에 따른 기울임
