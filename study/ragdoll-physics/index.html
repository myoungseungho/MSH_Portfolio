Ragdoll 물리

넘어지면서 굴러가는 애니는 어떻게?

Part 1. Ragdoll이 뭐야?

캐릭터가 죽으면서 자연스럽게 쓰러지는 거 있잖아?

그게 바로 Ragdoll이야. "헝겊 인형"이라는 뜻인데:

일반 애니메이션 vs Ragdoll: 애니메이션 기반 사망: ┌──────────────────────────────────────────┐ │ 프레임 1 → 프레임 2 → 프레임 3 → 끝 │ │ 🧍 → 🧎 → 😵 → 고정 │ │ │ │ 문제: 어디서 맞든 똑같이 쓰러짐 │ │ 계단에서 맞아도 평지처럼 쓰러짐 ❌ │ └──────────────────────────────────────────┘ Ragdoll 기반 사망: ┌──────────────────────────────────────────┐ │ 물리 시뮬레이션이 실시간 계산 │ │ │ │ 왼쪽에서 맞음 → 오른쪽으로 쓰러짐 │ │ 계단에서 맞음 → 굴러떨어짐 │ │ 폭발에 맞음 → 날아감 │ │ │ │ 매번 다르게, 물리적으로 자연스럽게! │ └──────────────────────────────────────────┘
왜 "헝겊 인형"이라고 해?

근육에 힘이 빠진 상태를 시뮬레이션하니까. 힘 빠진 인형처럼 축 늘어져:

살아있을 때 vs Ragdoll 상태: 살아있을 때: Ragdoll 상태: ┌─────────────┐ ┌─────────────┐ │ 😊 │ │ 😵 │ │ ┌┴┐ │ │ ┌┴┐ │ │ ─┤ ├─ │ ← 근육 │ ─┤ ├─ │ ← 중력만 │ │ │ │ 제어 │ └┬┘ │ 작용 │ ┌┘ └┐ │ │ ／ ＼ │ │ │ │ │ │ ／ ＼ │ └─────────────┘ └─────────────┘ 팔, 다리를 의지로 제어 중력에 의해 축 늘어짐

Part 2. Ragdoll의 구조

어떻게 만들어?

캐릭터의 뼈대(Skeleton)를 물리 바디로 바꾸고, 조인트(관절)로 연결해:

Ragdoll 구조: 스켈레톤(애니메이션용) → Ragdoll(물리용) [Head] [Head Body] │ │ [Spine] → [Spine Body] / | \ / | \ [L.Arm][R.Arm] [L.Arm][R.Arm] │ Body Body [Pelvis] [Pelvis] / \ / \ [L.Leg][R.Leg] [L.Leg][R.Leg] Body Body 각 뼈 → 물리 충돌체 (캡슐, 박스 등) 뼈 연결점 → 조인트 (힌지, 볼소켓 등)
// Ragdoll 기본 구조 struct RagdollBody { PhysicsBody* body; // 물리 시뮬레이션용 바디 int boneIndex; // 연결된 스켈레톤 뼈대 인덱스 Transform localOffset; // 뼈대와의 오프셋 }; struct RagdollJoint { Joint* joint; // 물리 조인트 RagdollBody* bodyA; // 부모 바디 RagdollBody* bodyB; // 자식 바디 Vector3 limits; // 회전 제한 (관절 꺾임 방지) }; class Ragdoll { std::vector<RagdollBody> bodies; // 약 15-20개 std::vector<RagdollJoint> joints; // 약 14-19개 Skeleton* skeleton; // 원본 스켈레톤 참조 };
왜 충돌체를 따로 만들어?

스켈레톤 뼈대는 그냥 "선"이야. 물리 시뮬레이션하려면 부피가 필요해:

뼈대 vs 충돌체: 뼈대(Bone): 충돌체(Collider): ┌─────────────┐ ┌─────────────┐ │ │ │ ╭───╮ │ │ │ │ → │ │ │ │ │ │ │ ╰───╯ │ └─────────────┘ └─────────────┘ 선(Line) - 물리 불가 캡슐 - 물리 가능 신체 부위별 충돌체: ┌────────────┬────────────┬────────────┐ │ 부위 │ 충돌체 │ 이유 │ ├────────────┼────────────┼────────────┤ │ 머리 │ 구(Sphere) │ 둥글어서 │ │ 몸통 │ 박스(Box) │ 넓적해서 │ │ 팔/다리 │ 캡슐 │ 길쭉해서 │ │ 손/발 │ 박스/구 │ 작아서 │ └────────────┴────────────┴────────────┘

Part 3. 조인트 제약

관절이 반대로 꺾이면 어떡해?

그래서 조인트 제약(Constraints)을 걸어! 현실 관절처럼 움직임을 제한해:

조인트 종류: 1. 볼소켓(Ball-Socket) - 어깨, 골반 ┌─────────────────────────────────────┐ │ ○━━━ 모든 방향 회전 가능 │ │ ╱ (제한 각도 내에서) │ │ ○ │ └─────────────────────────────────────┘ 2. 힌지(Hinge) - 팔꿈치, 무릎 ┌─────────────────────────────────────┐ │ ┃━━━ 한 축으로만 회전 │ │ ┃ (경첩처럼) │ │ ▼ │ └─────────────────────────────────────┘ 3. 트위스트(Twist) - 목, 손목 ┌─────────────────────────────────────┐ │ ○───── 축 방향 회전만 │ │ ↺ (돌리기) │ └─────────────────────────────────────┘
// 조인트 제약 설정 예시 void SetupElbowJoint(RagdollJoint* elbow) { // 팔꿈치는 힌지 조인트 (한 방향으로만 꺾임) elbow->type = JointType::Hinge; // 제한: 0도(펴짐) ~ 145도(접힘) elbow->minAngle = 0.0f; elbow->maxAngle = 145.0f; // 반대로 꺾이면 안 됨! // 실제 팔꿈치처럼 동작 } void SetupShoulderJoint(RagdollJoint* shoulder) { // 어깨는 볼소켓 (거의 모든 방향) shoulder->type = JointType::BallSocket; // 콘(Cone) 제한: 원뿔 모양 범위 내에서만 shoulder->coneAngle = 90.0f; // 최대 90도 shoulder->twistMin = -80.0f; // 내회전 shoulder->twistMax = 80.0f; // 외회전 } void SetupKneeJoint(RagdollJoint* knee) { // 무릎은 힌지 (한 방향) knee->type = JointType::Hinge; // 제한: 0도(펴짐) ~ 150도(접힘) knee->minAngle = 0.0f; knee->maxAngle = 150.0f; // 반대로 꺾이면 공포 영화처럼 보임 }
제약이 없으면 어떻게 돼?
제약 없는 Ragdoll의 비극: 제약 없음: ┌─────────────────────────────────────┐ │ 😱 ← 머리가 360도 회전 │ │ ╲ ┌┴┐ ╱ ← 팔이 반대로 꺾임 │ │ ─┤ ├─ │ │ ╱└┬┘╲ ← 다리가 앞으로 꺾임 │ │ │ │ │ │ │ │ "괴물 같은 자세로 쓰러짐" │ └─────────────────────────────────────┘ 제약 있음: ┌─────────────────────────────────────┐ │ 😵 ← 자연스러운 고개 │ │ ┌┴┐ │ │ ─┤ ├─ ← 정상 범위 팔 │ │ └┬┘ │ │ ╱ ╲ ← 정상 범위 다리 │ │ ╱ ╲ │ │ "인간처럼 자연스럽게 쓰러짐" │ └─────────────────────────────────────┘

Part 4. 애니메이션에서 Ragdoll로 전환

걷다가 갑자기 Ragdoll 되면 어색하지 않아?

맞아! 그래서 속도/위치 전달이 중요해:

전환 시 속도 전달: 나쁜 전환: ┌──────────────────────────────────────────┐ │ 달리는 중 → Ragdoll │ │ │ │ 🏃💨 (시속 20km) → 😵 (속도 0) │ │ │ │ 문제: 갑자기 제자리에서 쓰러짐 │ │ 달리던 관성이 사라져서 부자연스러움 │ └──────────────────────────────────────────┘ 좋은 전환: ┌──────────────────────────────────────────┐ │ 달리는 중 → Ragdoll │ │ │ │ 🏃💨 (시속 20km) → 😵💨 (시속 20km) │ │ │ │ 달리던 속도 유지 → 앞으로 굴러감 │ │ 물리적으로 자연스러움! │ └──────────────────────────────────────────┘
// 애니메이션 → Ragdoll 전환 void TransitionToRagdoll() { // 1. 현재 애니메이션 상태에서 속도 계산 for (auto& body : ragdoll.bodies) { Bone* bone = skeleton->GetBone(body.boneIndex); // 애니메이션의 현재 위치 body.body->SetPosition(bone->worldPosition); body.body->SetRotation(bone->worldRotation); // 애니메이션의 현재 속도 (이전 프레임과의 차이) Vector3 velocity = (bone->worldPosition - bone->prevPosition) / deltaTime; body.body->SetVelocity(velocity); // 캐릭터 전체 이동 속도도 추가 body.body->AddVelocity(character->velocity); } // 2. 애니메이션 끄고 물리 시뮬레이션 시작 animator->Disable(); ragdoll.Enable(); } // 히트 시 추가 힘 적용 void ApplyHitForce(Vector3 hitPoint, Vector3 hitDirection, float force) { // 가장 가까운 Ragdoll 바디 찾기 RagdollBody* hitBody = FindNearestBody(hitPoint); // 그 바디에 충격 적용 hitBody->body->AddImpulse(hitDirection * force); // 결과: 맞은 방향으로 밀려나면서 쓰러짐 }

Part 5. 블렌딩과 부분 Ragdoll

상체만 Ragdoll 할 수 있어?

당연하지! 이걸 부분 Ragdoll (Partial Ragdoll)이라고 해:

부분 Ragdoll 예시: 맞았지만 살아있는 상태 (히트 리액션): ┌─────────────────────────────────────────┐ │ 😖 ← Ragdoll (물리) │ │ ┌─┴─┐ ← Ragdoll (상체) │ │ ╱│ │╲ │ │ ─┘ │ │ └─ │ │ ───┼───┼─── ← 경계선 │ │ │ │ ← 애니메이션 (하체) │ │ ┌┘ └┐ ← 여전히 걷는 중 │ │ ┌┘ └┐ │ │ │ │ 상체: 맞은 충격으로 흔들림 │ │ 하체: 계속 걸음 │ └─────────────────────────────────────────┘
// 부분 Ragdoll class PartialRagdoll { enum BodyPart { HEAD, SPINE, L_ARM, R_ARM, L_LEG, R_LEG }; // 각 부위별 Ragdoll 활성화 상태 std::map<BodyPart, float> ragdollWeight; // 0.0 = 애니메이션, 1.0 = Ragdoll void Update() { for (auto& body : bodies) { float weight = ragdollWeight[body.part]; // 애니메이션 포즈 Transform animPose = animator->GetBoneTransform(body.boneIndex); // Ragdoll 물리 포즈 Transform physicsPose = body.body->GetTransform(); // 블렌딩 body.finalTransform = Lerp(animPose, physicsPose, weight); } } // 상체만 Ragdoll void SetUpperBodyRagdoll() { ragdollWeight[HEAD] = 1.0f; ragdollWeight[SPINE] = 1.0f; ragdollWeight[L_ARM] = 1.0f; ragdollWeight[R_ARM] = 1.0f; ragdollWeight[L_LEG] = 0.0f; // 하체는 애니메이션 ragdollWeight[R_LEG] = 0.0f; } };
Ragdoll에서 다시 일어날 수도 있어?

이건 어려워! Ragdoll → 애니메이션 전환은 "Get Up" 시스템이 필요해:

// Ragdoll → 애니메이션 전환 (Get Up) void TransitionFromRagdoll() { // 1. Ragdoll 상태 분석 bool isFaceDown = IsFacingDown(); // 엎어졌나? bool isFaceUp = IsFacingUp(); // 젖혀졌나? // 2. 적절한 "일어나기" 애니메이션 선택 Animation* getUpAnim = nullptr; if (isFaceDown) { getUpAnim = animations["GetUp_FaceDown"]; } else { getUpAnim = animations["GetUp_FaceUp"]; } // 3. 블렌딩 시작 blendTime = 0.5f; // 0.5초에 걸쳐 전환 for (float t = 0; t < blendTime; t += deltaTime) { float weight = t / blendTime; for (auto& body : bodies) { // Ragdoll → 애니메이션 블렌딩 body.finalPose = Lerp( body.ragdollPose, getUpAnim->GetPose(body.boneIndex), weight ); } } // 4. 완전히 애니메이션으로 전환 ragdoll.Disable(); animator->Enable(); animator->Play(getUpAnim); }

Part 6. 성능 최적화

Ragdoll이 많으면 느려지지 않아?

느려져! 그래서 최적화가 중요해:

Ragdoll 성능 최적화: 1. LOD (Level of Detail) ┌────────────────────────────────────────┐ │ 거리에 따라 Ragdoll 품질 조절: │ │ │ │ 가까움: 20개 바디 (풀 Ragdoll) │ │ 중간: 10개 바디 (중요 부위만) │ │ 멀리: 5개 바디 (대충) │ │ 아주 멀리: 1개 바디 (그냥 통짜) │ └────────────────────────────────────────┘ 2. 슬립 상태 (Sleep) ┌────────────────────────────────────────┐ │ 움직임 멈추면 시뮬레이션 중지: │ │ │ │ 속도 < 0.01 → Sleep → 계산 안 함 │ │ │ │ 누가 건드리면 → Wake Up → 다시 계산 │ └────────────────────────────────────────┘ 3. 최대 개수 제한 ┌────────────────────────────────────────┐ │ 동시에 활성화 Ragdoll 제한: │ │ │ │ 최대 10개만 물리 시뮬레이션 │ │ 11번째부터는 바로 사망 애니메이션 │ └────────────────────────────────────────┘
// Ragdoll 풀 관리 class RagdollPool { static const int MAX_ACTIVE = 10; std::vector<Ragdoll*> activeRagdolls; std::queue<Ragdoll*> pool; Ragdoll* RequestRagdoll() { // 최대 개수 초과 시 if (activeRagdolls.size() >= MAX_ACTIVE) { // 가장 오래된 거 강제 종료 Ragdoll* oldest = activeRagdolls.front(); oldest->ForceFinish(); // 바로 사라지거나 정적 메시로 ReturnToPool(oldest); } // 풀에서 꺼내기 Ragdoll* ragdoll = pool.front(); pool.pop(); activeRagdolls.push_back(ragdoll); return ragdoll; } void Update() { for (auto* ragdoll : activeRagdolls) { // 슬립 체크 if (ragdoll->GetTotalVelocity() < 0.01f) { ragdoll->sleepTimer += deltaTime; if (ragdoll->sleepTimer > 2.0f) { // 2초간 안 움직이면 슬립 ragdoll->Sleep(); } } } } };

핵심 정리

  • Ragdoll은 스켈레톤을 물리 바디로 바꿔 실시간 시뮬레이션
  • 각 뼈마다 충돌체(캡슐, 박스, 구)를 붙임
  • 조인트 제약으로 관절이 반대로 꺾이는 걸 방지
  • 애니메이션 → Ragdoll 전환 시 속도 전달이 핵심
  • 부분 Ragdoll로 상체만/하체만 따로 제어 가능
  • 성능을 위해 LOD, Sleep, 최대 개수 제한 필수
  • Ragdoll → 애니메이션은 Get Up 시스템으로 블렌딩
