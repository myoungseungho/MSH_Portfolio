개요

C++26은 2026년에 공식 표준화될 예정이며, Contracts, Reflection, std::execution이라는 "Big Three" 기능이 추가됩니다. C++20 이후 가장 큰 변화입니다.

서버 개발자 관점에서 바로 쓸 수 있는 핵심 기능들을 스캐폴딩 방식으로 학습합니다.

1Contracts - 함수 계약

질문
서버에서 함수 호출할 때 "이 파라미터는 절대 null이면 안 돼", "반환값은 양수여야 해" 같은 조건을 주석으로만 적어봤어? 
// 기존 - 주석으로 계약
// @param userId 반드시 0보다 커야 함
// @return 성공 시 양수, 실패 시 -1
int getPlayerLevel(int userId) {
    // 방어적 코딩
    if (userId <= 0) {
        LOG_ERROR("Invalid userId");
        return -1;  // 근데 호출자가 체크 안 하면?
    }
    ...
}
문제점
  • 주석은 강제력이 없음 - 안 읽으면 그만
  • 방어적 코딩해도 호출자가 반환값 무시할 수 있음
  • 버그 발생 시 "어디서 잘못된 값이 들어왔지?" 추적이 어려움
C++26 Contracts
// 계약을 코드로!
int getPlayerLevel(int userId)
    pre(userId > 0)           // 사전조건: userId는 양수
    post(r: r >= 0)           // 사후조건: 반환값(r)은 0 이상
{
    return db.query(userId);
}

// 호출 시
getPlayerLevel(-1);  // 사전조건 위반! 런타임 에러 or 로그
추가 질문
그럼 조건 위반하면 뭐가 일어나? 프로그램이 죽어?
빌드 모드에 따라 다름
// 계약 위반 시 동작 설정 (컴파일러 옵션)

// 1. enforce (기본) - 위반 시 std::abort() 호출
// 2. observe - 위반 로깅만 하고 계속 진행
// 3. ignore - 계약 체크 안 함 (Release 빌드)
// 4. assume - 컴파일러가 조건을 참으로 가정 (최적화)
모드 위반 시 용도
enforce 프로그램 종료 개발/테스트
observe 로그만 찍고 진행 라이브 모니터링
ignore 체크 안 함 성능 최적화
assume UB (정의되지 않은 동작) 극한 최적화
CS 질문
assert랑 뭐가 달라? assert도 조건 체크하잖아.
계약은 인터페이스의 일부
assert Contracts
위치 함수 내부 함수 시그니처
가시성 구현 세부사항 API 계약
문서화 별도 필요 코드가 곧 문서
Release 보통 제거됨 모드 선택 가능

서버 개발자 관점

  • 사전조건: "이 함수 호출하려면 이 조건 만족해야 해"
  • 사후조건: "이 함수는 이 조건을 보장해"
  • 개발 때는 enforce, 라이브에선 observe/ignore 전략 가능
  • API 설계 시 계약이 곧 문서가 됨

2Reflection - 컴파일 타임 타입 정보

질문
struct 멤버 이름을 문자열로 가져오고 싶었던 적 있어? 예를 들어 자동 직렬화/역직렬화 만들 때? 
// 기존 - 수동으로 매핑
struct Player {
    int id;
    std::string name;
    int level;
};

// JSON 직렬화하려면?
std::string toJson(const Player& p) {
    return R"({"id":)" + std::to_string(p.id) +
           R"(,"name":")" + p.name +
           R"(","level":)" + std::to_string(p.level) + "}";
    // 멤버 추가하면? 여기도 수정해야 함...
}
현실 세계에서는...
  • 매크로 지옥 (REFLECT_MEMBER(id), REFLECT_MEMBER(name)...)
  • 외부 코드 생성기 (protobuf, flatbuffers)
  • 멤버 추가할 때마다 여러 곳 수정
C++26 Reflection
#include <meta>

struct Player {
    int id;
    std::string name;
    int level;
};

// 모든 멤버를 자동으로 순회!
template<typename T>
std::string toJson(const T& obj) {
    std::string result = "{";
    bool first = true;

    // 컴파일 타임에 멤버 정보 가져오기
    template for (constexpr auto member : std::meta::members_of(^T)) {
        if (!first) result += ",";
        first = false;

        // 멤버 이름
        result += "\"" + std::string(std::meta::name_of(member)) + "\":";
        // 멤버 값
        result += toJsonValue(obj.[:member:]);
    }
    return result + "}";
}

// 사용
Player p{123, "Hero", 50};
auto json = toJson(p);  // {"id":123,"name":"Hero","level":50}
추가 질문
^T랑 [:member:]는 뭐야? 처음 보는 문법인데?
Reflection 전용 문법
// ^T = T 타입의 "메타 정보" 얻기 (reflection)
constexpr auto playerMeta = ^Player;

// std::meta::members_of() = 멤버 목록
// std::meta::name_of() = 멤버/타입 이름 (문자열)

// [:member:] = 메타 정보를 실제 접근으로 "스플라이스"
Player p;
constexpr auto idMember = /* id 멤버의 메타 정보 */;
p.[:idMember:] = 100;  // p.id = 100과 동일
일반 코드 세계 메타 세계 ───────────────────────────────────── Player p; ^Player p.id members_of(^Player) "id" name_of(member) │ ▼ 스플라이스 [::] p.[:member:] ◄─────────────┘
CS 질문
이거 런타임에 동작하는 거야? 성능 걱정 안 해도 돼?
컴파일 타임!

핵심: 전부 컴파일 타임에 처리됨

// 컴파일러가 이걸...
template for (constexpr auto member : std::meta::members_of(^Player)) {
    result += name_of(member);
}

// 이렇게 풀어버림 (개념적으로)

Reflection 활용 예시

  • 자동 직렬화: JSON, XML, Binary 변환
  • ORM: DB 테이블 <-> struct 자동 매핑
  • RPC 생성: 함수 시그니처에서 네트워크 코드 자동 생성
  • 디버깅: 모든 멤버 자동 출력
  • enum to string: 더 이상 수동 매핑 불필요
// enum to string 예시
enum class Status { Active, Inactive, Pending };

template<typename E>
std::string enumToString(E value) {
    template for (constexpr auto e : std::meta::enumerators_of(^E)) {
        if (value == [:e:])
            return std::string(std::meta::name_of(e));
    }
    return "Unknown";
}

enumToString(Status::Active);  // "Active"

3std::execution - 표준 비동기

질문
C++20 코루틴 배웠는데, 표준 라이브러리에서 co_await 쓸 수 있는 게 거의 없었잖아. 직접 다 만들어야 했는데? 
// C++20 코루틴 - 뼈대만 제공
// Task, Generator 같은 타입을 직접 만들거나 라이브러리 사용해야 함

// 현실
Result co_await someAsyncOp();  // someAsyncOp 직접 구현해야 함...
현재 상황
  • 비동기 라이브러리마다 방식이 다름 (Boost.Asio, folly, ...)
  • 조합/연결이 어려움
  • 표준이 없어서 코드 이식성 낮음
C++26 std::execution
#include <execution>

// Sender = "나중에 값을 보낼게" 약속
// Receiver = "값 받으면 이렇게 처리할게"

// 작업 정의 (아직 실행 안 됨)
auto work = std::execution::just(42)           // 42를 보내는 sender
          | std::execution::then([](int x) {   // 받으면 2배
                return x * 2;
            })
          | std::execution::then([](int x) {   // 결과 출력
                std::cout << x;  // 84
            });

// 실행
std::this_thread::sync_wait(work);
추가 질문
그냥 함수 호출하면 되는 거 아냐? 왜 이렇게 복잡하게?
비동기 + 조합 가능
// 포인트: 실행 시점과 실행 위치를 분리

// 1. 작업 정의 (실행 X)
auto fetchUser = asyncDbQuery("SELECT * FROM users");
auto fetchItems = asyncDbQuery("SELECT * FROM items");

// 2. 두 작업을 병렬로 (실행 X, 조합만)
auto parallel = std::execution::when_all(fetchUser, fetchItems);

// 3. 결과 합치기 (실행 X)
auto combined = parallel | std::execution::then([](auto user, auto items) {
    return merge(user, items);
});

// 4. 특정 스레드풀에서 실행!
myThreadPool.execute(combined);
┌─────────────────────────────────────────┐ │ 작업 그래프 (DAG) │ │ │ │ fetchUser ──┐ │ │ ├──► when_all ──► then │ │ fetchItems ──┘ │ │ │ │ (아직 실행 안 됨, 설계도만 있음) │ └─────────────────────────────────────────┘ │ ▼ execute() ┌───────────────────┐ │ Thread Pool │ │ 실제 실행 시작 │ └───────────────────┘

핵심 개념

개념 설명
Sender "나중에 값을 보낼게" - 비동기 작업
Receiver "값 받으면 처리할게" - 콜백
Scheduler "여기서 실행해" - 스레드풀, IO 스레드 등

서버 개발자 관점

  • 드디어 표준 비동기 프레임워크!
  • 라이브러리 간 조합 가능
  • 에러 처리, 취소 처리 표준화
  • 근데 현실적으로 기존 코드베이스 마이그레이션은 오래 걸릴 것

4Pack Indexing - 파라미터 팩 접근

질문
variadic template 쓸 때 "첫 번째 인자만" 또는 "N번째 인자만" 가져오고 싶었던 적 있어? 
// 기존 - 재귀나 tuple 사용
template<typename... Args>
auto getFirst(Args... args) {
    return std::get<0>(std::make_tuple(args...));  // 귀찮...
}

// 또는 재귀로 하나씩 벗기기
template<typename First, typename... Rest>
auto getFirst(First first, Rest... rest) {
    return first;
}
C++26 Pack Indexing
// 배열처럼 인덱스로 접근!
template<typename... Args>
auto getFirst(Args... args) {
    return args...[0];  // 첫 번째
}

template<typename... Args>
auto getThird(Args... args) {
    return args...[2];  // 세 번째
}

// 타입에도 적용
template<typename... Ts>
using FirstType = Ts...[0];

FirstType<int, double, char> x;  // int x;
추가 질문
범위 밖 인덱스 접근하면?
컴파일 에러
template<typename... Args>
auto getBad(Args... args) {
    return args...[100];  // 컴파일 에러: 인덱스 범위 초과
}

getBad(1, 2, 3);  // 3개뿐인데 100번째? → 에러

실용 예시

// RPC 핸들러에서 특정 인자만 추출
template<typename... Args>
void handleRpc(int opcode, Args... args) {
    if constexpr (sizeof...(Args) >= 2) {
        auto playerId = args...[0];
        auto targetId = args...[1];
        processAction(playerId, targetId);
    }
}

5std::inplace_vector - 스택 기반 동적 벡터

질문
"최대 10개까지만 저장하면 되는데 vector 쓰자니 힙 할당이 아깝고, array 쓰자니 현재 몇 개인지 관리해야 하고..." 
// array = 고정 크기, 스택
std::array<int, 10> arr;  // 항상 10개 공간, size() 개념 없음

// vector = 가변 크기, 힙
std::vector<int> vec;     // 힙 할당, 느림
vec.reserve(10);          // 미리 잡아도 힙
게임 서버 상황
  • 파티원 목록 (최대 4명)
  • 인벤토리 슬롯 (최대 50개)
  • 버프 목록 (최대 10개)
  • → 상한선 있고, 매 프레임 생성/삭제되면 힙 할당 부담
std::inplace_vector
#include <inplace_vector>

// 최대 10개, 스택에 저장, vector처럼 사용
std::inplace_vector<int, 10> party;

party.push_back(1);
party.push_back(2);
party.size();       // 2
party.capacity();   // 10 (고정)
party[0];           // 1

party.push_back(...);  // 10개 초과 시 예외 or try_push_back 사용
