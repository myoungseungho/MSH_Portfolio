PART 1: 왜 커스텀 할당자가 필요한가?

new/delete의 비용과 게임 서버에서의 문제점

1new 한 번에 무슨 일이?

질문

PART 2: C++ STL Allocator

기존 방식과 그 문제점

4STL의 할당자(Allocator)란?

질문
vector에 push_back하면 메모리는 어디서 오는 거야? 
std::vector<int> vec;
vec.push_back(42);  // 이 메모리 어디서 왔어?
숨겨진 2번째 템플릿 파라미터
// 실제로는 이렇게 생김
std::vector<int, std::allocator<int>> vec;
//              ^^^^^^^^^^^^^^^^^^^^
//              기본 할당자 (new/delete 사용)
std::allocator 내부
template<typename T>
class allocator {
public:
    T* allocate(size_t n) {
        return static_cast<T*>(::operator new(n * sizeof(T)));
    }
    void deallocate(T* p, size_t n) {
        ::operator delete(p);
    }
};

결국 new/delete 호출 = 힙 할당

추가 질문
그럼 힙 대신 다른 곳에서 메모리 가져오려면?
커스텀 할당자!
// 내가 만든 할당자
template<typename T>
class MyPoolAllocator {
    T* allocate(size_t n) {
        return myPool.get();  // 힙 대신 내 풀에서!
    }
    void deallocate(T* p, size_t n) {
        myPool.release(p);
    }
};

// 사용
std::vector<int, MyPoolAllocator<int>> vec;

5기존 방식의 치명적 문제

질문
커스텀 할당자 만들어서 쓰면 되는 거 아냐? 뭐가 문제야? 
// 기본 할당자
std::vector<int> vec1;

// 커스텀 할당자
std::vector<int, MyPoolAllocator<int>> vec2;

// 둘이 같은 타입일까?
다른 타입!
vec1 = vec2;  // 컴파일 에러!
// error: no viable overloaded '='

// 왜? 템플릿 파라미터가 다르면 완전히 다른 타입
// vector<int, allocator<int>>  ≠  vector<int, MyPoolAlloc<int>>
실무에서 겪는 문제
// 함수를 만들 때...
void processData(std::vector<int>& data) {
    // 기본 할당자만 받음
}

// 커스텀 할당자 쓰는 벡터는?
std::vector<int, PoolAlloc<int>> myVec;
processData(myVec);  // 컴파일 에러!

// 해결하려면 템플릿으로 만들어야 함
template<typename Alloc>
void processData(std::vector<int, Alloc>& data);
// → 모든 함수를 템플릿으로? 컴파일 시간 폭발!

핵심 문제

할당자가 "타입"에 포함됨 → 할당자 다르면 호환 안 됨

  • 함수 오버로딩 지옥
  • 라이브러리 간 호환 불가
  • 템플릿 코드 폭발

PART 3: C++17 PMR - 해결책

할당자를 타입에서 분리하는 방법

6PMR - 할당자를 타입에서 분리

질문
할당자가 달라도 같은 타입으로 취급할 방법은 없을까?
PMR (Polymorphic Memory Resource)
#include <memory_resource>

// PMR 컨테이너 - 할당자가 타입에 안 들어감!
std::pmr::vector<int> vec1;                    // 기본
std::pmr::vector<int> vec2(&myPoolResource);   // 커스텀

// 둘 다 같은 타입!
vec1 = vec2;  // OK!
기존 STL PMR ───────────────────────────────────────────── vector<int, Alloc1> pmr::vector<int> vector<int, Alloc2> pmr::vector<int> ↓ ↓ 다른 타입! 같은 타입! ↓ ↓ 호환 안 됨 서로 대입 가능
추가 질문
어떻게 타입은 같은데 할당 방식은 다르게 할 수 있어?
런타임 다형성 (가상 함수)
// 핵심 구조
class memory_resource {  // 추상 클래스
public:
    void* allocate(size_t bytes) {
        return do_allocate(bytes);  // 가상 함수 호출
    }
private:
    virtual void* do_allocate(size_t) = 0;  // 파생 클래스가 구현
};

// pmr::vector 내부
class pmr::vector<T> {
    memory_resource* mr;  // 포인터로 들고 있음 (타입 아님!)

    void push_back(T val) {
        T* p = mr->allocate(sizeof(T));  // 다형성!
    }
};

기존 Allocator PMR

성능 인라인 가능 가상 함수 호출

7표준 제공 메모리 리소스

질문
PMR에서 쓸 수 있는 메모리 리소스는 뭐가 있어?
리소스 특징 용도
new_delete_resource 기본 new/delete 일반 (기본값)
monotonic_buffer_resource 해제 안 함, 빠름 임시 작업, 파싱
unsynchronized_pool_resource 풀 방식, 싱글스레드 단일 스레드 성능
synchronized_pool_resource 풀 방식, 멀티스레드 스레드 안전

monotonic_buffer_resource - 가장 빠름

// 스택에 버퍼 준비
char buffer[10000];

// 모노토닉 리소스 생성 (버퍼 + 크기)
std::pmr::monotonic_buffer_resource pool{buffer, sizeof(buffer)};

// 이 풀을 사용하는 벡터
std::pmr::vector<int> vec{&pool};

vec.push_back(1);  // buffer에서 할당 (힙 X)
vec.push_back(2);  // buffer에서 할당
vec.push_back(3);  // buffer에서 할당

// 개별 해제 없음!
// pool 소멸 시 한번에 정리
왜 "monotonic"?

메모리 포인터가 한 방향으로만 증가 (뒤로 안 감)

→ 개별 deallocate가 no-op (아무것도 안 함)

→ 관리 오버헤드 0, 가장 빠름!

[monotonic_buffer_resource] 할당 요청: ──────────────────────────▶ │████│████│████│ │ └────┴────┴────┴──────────┘ vec[0] vec[1] vec[2] 남은공간 개별 해제? 아무것도 안 함! (포인터 그대로) 전체 해제? pool 소멸 시 버퍼 통째로 반환

실전 예시: 패킷 파싱

void handlePacket(const char* data, size_t len) {
    // 이 함수 안에서만 쓸 임시 메모리
    char localBuffer[4096];
    std::pmr::monotonic_buffer_resource pool{localBuffer, sizeof(localBuffer)};

    // 파싱 중 생성되는 임시 객체들
    std::pmr::vector<Token> tokens{&pool};
    std::pmr::string tempStr{&pool};

    // ... 파싱 작업 ...

    // 함수 끝나면 localBuffer(스택)가 자동 정리
    // new/delete 호출 0번!
}

8실전 코드 비교

기존 방식

// 기본 (힙 할당)
std::vector<int> v1;

// 커스텀 할당자
std::vector<int, Pool<int>> v2;

// 서로 호환 안 됨!
void process(std::vector<int>& v);
process(v2);  // 에러!

PMR 방식

// 기본 (힙 할당)
std::pmr::vector<int> v1;

// 스택 버퍼 사용
std::pmr::vector<int> v2{&pool};

// 같은 타입! 호환 가능!
void process(std::pmr::vector<int>& v);
process(v2);  // OK!

성능 벤치마크

// 테스트: 10000번 vector 생성/삭제

// 1. 기본 new/delete
for (int i = 0; i < 10000; i++) {
    std::vector<int> v;
    v.resize(100);
}  // → 약 15ms

// 2. PMR monotonic (스택 버퍼)
char buf[1024 * 1024];
for (int i = 0; i < 10000; i++) {
    std::pmr::monotonic_buffer_resource pool{buf, sizeof(buf)};
    std::pmr::vector<int> v{&pool};
    v.resize(100);
}  // → 약 2ms (7배 빠름)

9PMR 사용 시 주의사항

1. 리소스 수명 관리

std::pmr::vector<int>* createVector() {
    char buf[1000];
    std::pmr::monotonic_buffer_resource pool{buf, sizeof(buf)};

    auto* vec = new std::pmr::vector<int>{&pool};
    return vec;  // 위험! pool과 buf가 사라짐!
}

auto* v = createVector();
v->at(0);  // Undefined Behavior!

규칙: 컨테이너보다 리소스가 오래 살아야 함!

2. monotonic은 해제 안 됨

std::pmr::monotonic_buffer_resource pool{...};
std::pmr::vector<int> vec{&pool};

vec.push_back(1);
vec.clear();       // 메모리 반환? NO!
vec.shrink_to_fit(); // 줄어듦? NO!

// 장기 실행 시 메모리 계속 증가!

해결: 범위 제한 또는 pool_resource 사용

핵심 정리

질문 답
new의 문제? 탐색, 시스템콜, 락, 단편화
커스텀 할당자란? 메모리를 직접 관리하는 방법
기존 STL 문제? 할당자가 타입에 포함 → 호환 불가
PMR 핵심? 런타임 다형성으로 타입 통일
가장 빠른 리소스? monotonic_buffer_resource

실전 가이드

  • 함수 내 임시 데이터 → monotonic + 스택버퍼
  • 장기 실행 풀 → pool_resource
  • 타입 호환 필요 → PMR 컨테이너
  • 극한 성능 → 기존 템플릿 할당자
