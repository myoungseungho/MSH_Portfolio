개요

WoW 애드온, Roblox 게임, Garry's Mod... 이 게임들의 공통점? 유저가 직접 코드를 짜서 게임을 바꿀 수 있다. 어떻게 가능할까?

1왜 스크립트 언어가 필요해?

질문
게임 로직을 C++로 다 짜면 되지, 왜 굳이 다른 언어를 섞어?
잠깐, 먼저 구분하자

"몬스터 HP 500에서 450으로 바꿔주세요" → 이건 CSV로 충분해.

Lua가 필요한 건 로직이 바뀔 때야.

CSV vs Lua 결정적 차이

CSV = 값(데이터)만 바꿀 수 있음

Lua = 조건문, 반복문, 함수 호출 = 로직을 바꿀 수 있음

-- CSV로 가능한 것
monster_id, hp, attack
goblin, 500, 30

-- CSV로 불가능한 것 (Lua 필요)
if target:HasDebuff("burn") then
    damage = damage * 2  -- 화상이면 데미지 2배
end

if GetTimeOfDay() == "night" then
    spawn_rate = spawn_rate * 1.5  -- 밤에 스폰 증가
end
질문
그런 로직은 C++로 짜면 되지 않아?
맞아, C++로 해도 돼. 하지만...

C++은 컴파일 언어야. 로직 한 줄 바꿔도 빌드해야 해.

상황을 생각해보자

기획자: "보스가 HP 30% 이하일 때 광폭화하는데, 50%로 바꿔주세요"

프로그래머: "네... (C++ 수정 → 컴파일 5분 → 빌드 → 테스트)"

기획자: "역시 40%가 나을 것 같아요"

프로그래머: "..."

Lua를 쓰면?

기획자가 직접 스크립트 파일 열어서 0.3 → 0.5 수정, 저장하면 끝.

컴파일 없음. 프로그래머 필요 없음. 10초만에 테스트.

C++ (컴파일) Lua (스크립트)
수정 후 컴파일 → 링크 → 실행 바로 실행
적용 시간 분~시간 즉시 (Hot Reload)
수정하는 사람 프로그래머만 기획자도 가능
용도 엔진, 렌더링, 물리 스킬 로직, AI, 퀘스트

핵심: Lua가 필요한 순간

  • 로직이 자주 바뀔 때 (밸런싱, 신규 콘텐츠)
  • 기획자가 직접 수정해야 할 때
  • 모딩을 지원해야 할 때 (WoW 애드온)

단순 데이터만 바뀌면? CSV로 충분해. Lua 필요 없어.

2왜 하필 Lua야?

질문
스크립트 언어 많잖아. Python, JavaScript... 왜 Lua?
세 가지 이유

1. 작다 (Tiny)

Lua 전체 소스코드가 약 3만 줄. Python은 수십만 줄.

실행 파일 크기도 수백 KB. 게임에 임베딩하기 딱 좋음.

2. 빠르다 (Fast)

스크립트 언어 중 최상위권 성능. LuaJIT 쓰면 더 빠름.

게임처럼 매 프레임 스크립트 돌리는 환경에서 중요.

3. 붙이기 쉽다 (Embeddable)

C/C++ 코드에 몇 줄만으로 Lua를 붙일 수 있음.

게임 엔진에서 Lua 함수 호출, Lua에서 C++ 함수 호출 양방향 가능.

언어 크기 속도 임베딩 난이도
Lua 작음 빠름 쉬움
Python 큼 느림 복잡함
JavaScript 중간 빠름 (V8) 복잡함

3Lua 문법 훑어보기

질문
Lua 문법은 어떻게 생겼어?
간단해. 5분이면 읽을 수 있어
-- 변수 (타입 선언 없음)
local hp = 100
local name = "Player"
local isAlive = true

-- 함수
function damage(target, amount)
    target.hp = target.hp - amount
    if target.hp <= 0 then
        target.isAlive = false
    end
end

-- 테이블 (Lua의 만능 자료구조)
local player = {
    name = "Hero",
    hp = 100,
    mp = 50,
    skills = {"Slash", "Fireball", "Heal"}
}

-- 반복문
for i, skill in ipairs(player.skills) do
    print(i, skill)
end

-- 조건문
if player.hp > 50 then
    print("Healthy")
elseif player.hp > 0 then
    print("Wounded")
else
    print("Dead")
end

Lua 특징

  • local = 지역 변수 (없으면 전역)
  • -- = 주석
  • nil = 값 없음 (다른 언어의 null)
  • 테이블 = 배열, 딕셔너리, 객체 전부 이걸로
  • 인덱스가 1부터 시작!
질문
테이블 하나로 다 된다고? 
-- 배열처럼
local inventory = {"Sword", "Potion", "Shield"}
print(inventory[1])  -- "Sword" (1부터 시작!)

-- 딕셔너리처럼
local stats = {hp = 100, mp = 50, str = 15}
print(stats.hp)      -- 100
print(stats["mp"])   -- 50 (같은 의미)

-- 객체처럼 (메서드 포함)
local enemy = {
    hp = 50,
    attack = function(self, target)
        target.hp = target.hp - 10
    end
}
enemy:attack(player)  -- self 자동 전달
맞아, 테이블이 Lua의 핵심

클래스? 없어. 테이블로 흉내내. 배열? 테이블. 해시맵? 테이블. 전부 테이블.

4C++에서 Lua 호출하기

질문
게임 엔진(C++)에서 Lua 스크립트를 어떻게 실행해?
Lua 인터프리터를 엔진에 내장
// C++ 코드
#include <lua.hpp>

int main() {
    // 1. Lua 상태 생성
    lua_State* L = luaL_newstate();
    luaL_openlibs(L);  // 표준 라이브러리 로드

    // 2. Lua 스크립트 실행
    luaL_dofile(L, "scripts/game.lua");

    // 3. Lua 함수 호출
    lua_getglobal(L, "onPlayerDamage");  // 함수 이름
    lua_pushnumber(L, 50);                // 인자: 데미지 양
    lua_pcall(L, 1, 0, 0);                // 호출 (인자 1개, 리턴 0개)

    // 4. 정리
    lua_close(L);
    return 0;
}
-- scripts/game.lua
function onPlayerDamage(amount)
    print("Player took " .. amount .. " damage!")
    -- 게임 로직...
end
질문
반대로 Lua에서 C++ 함수를 호출할 수도 있어?
당연하지! 그게 핵심이야
// C++ - Lua에서 호출할 수 있는 함수 등록
int cpp_spawnEnemy(lua_State* L) {
    const char* type = lua_tostring(L, 1);  // 첫 번째 인자
    int x = lua_tointeger(L, 2);
    int y = lua_tointeger(L, 3);

    // 실제 적 생성 로직 (C++ 엔진 코드)
    Enemy* enemy = game->SpawnEnemy(type, x, y);

    lua_pushinteger(L, enemy->GetID());  // 리턴값
    return 1;  // 리턴값 개수
}

// 함수 등록
lua_register(L, "SpawnEnemy", cpp_spawnEnemy);
-- Lua에서 C++ 함수 호출
local enemyID = SpawnEnemy("Goblin", 100, 200)
print("Spawned enemy: " .. enemyID)

양방향 통신

  • C++ → Lua: 이벤트 발생 시 Lua 콜백 호출
  • Lua → C++: 엔진 기능 사용 (스폰, 이동, 공격 등)

Lua는 "게임 로직"을 담당, C++은 "엔진 기능"을 제공

5Lua는 어떻게 실행돼? (VM 원리)

질문
Lua도 소스코드잖아. C++이 런타임에 호출하면, 컴파일 타임에 합쳐지는 거야?
아니, 런타임에 텍스트를 읽어서 실행해

Lua 코드는 C++에 합쳐지지 않아. Lua VM(가상 머신)이 실행 중에 텍스트를 해석해.

C++ 컴파일 vs Lua 실행

[ C++ ]
소스코드 → 컴파일러 → 기계어 → CPU가 직접 실행
  .cpp      (빌드)      .exe       (빠름)

[ Lua ]
소스코드 → Lua VM이 읽음 → 바이트코드 → VM이 해석하며 실행
  .lua       (런타임)       (메모리)         (느림)
질문
그럼 구체적으로 어떤 순서로 동작해? 
┌─────────────────────────────────────────────────────────────┐
│                     C++ 게임 실행파일                         │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │              Lua VM (인터프리터)                      │   │
│  │                                                     │   │
│  │   1. "skill.lua" 텍스트 파일 읽음                    │   │
│  │              ↓                                      │   │
│  │   2. 바이트코드로 변환 (런타임에!)                    │   │
│  │              ↓                                      │   │
│  │   3. VM이 바이트코드를 한 줄씩 해석하며 실행          │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
// C++ 코드에서 실제로 일어나는 일
lua_State* L = luaL_newstate();  // 1. Lua VM 인스턴스 생성

luaL_dofile(L, "skill.lua");     // 2. 텍스트 파일 읽기 → 바이트코드 변환
                                 //    이 순간 skill.lua를 열어서 파싱함!

lua_getglobal(L, "Fireball");    // 3. 함수 찾기
lua_pcall(L, 0, 0, 0);           // 4. VM이 바이트코드 실행
핵심: Lua 코드는 기계어가 아니야

C++은 CPU가 직접 실행하는 기계어로 변환됨.

Lua는 Lua VM이라는 "통역사"가 중간에서 해석하며 실행.

그래서 느리지만, 파일만 바꾸면 동작이 바뀌는 것.

질문
아, 그래서 Hot Reload가 가능한 거구나?
정확해!
// Hot Reload가 가능한 이유
if (FileChanged("skill.lua")) {
    luaL_dofile(L, "skill.lua");  // 그냥 다시 읽으면 됨!
                                   // 새 텍스트 → 새 바이트코드
                                   // C++ 재컴파일 필요 없음
}

양방향 호출 구조

┌──────────────┐              ┌──────────────┐
│     C++      │              │     Lua      │
│              │              │              │
│  게임 엔진    │ ──────────→ │  스킬 로직    │
│              │   lua_pcall  │              │
│  ApplyDamage │ ←────────── │  Fireball()  │
│  PlayEffect  │   등록된     │              │
│              │   C 함수     │              │
└──────────────┘              └──────────────┘

C++이 Lua 함수 호출 → Lua VM이 바이트코드 실행
Lua가 C++ 함수 호출 → VM이 등록된 함수 포인터로 점프

성능 비용 정리

항목 설명
Lua 함수 호출 스택에 값 복사, VM 컨텍스트 전환 오버헤드
바이트코드 해석 기계어 직접 실행보다 10~50배 느림
LuaJIT 사용 시 JIT 컴파일로 거의 C 수준 (2~5배 느림)

6Hot Reload - 게임 중 코드 수정

질문
"자주 바뀌는 부분에 스크립트 쓴다"고 했는데, 실제로 어떻게 바뀌어?
Hot Reload = 게임 실행 중에 코드 교체
// C++ - Hot Reload 구현
void ReloadScript(const char* filename) {
    // 1. 기존 함수들 언로드 (선택적)

    // 2. 새 스크립트 로드
    if (luaL_dofile(L, filename) != 0) {
        // 에러 처리
        printf("Error: %s\n", lua_tostring(L, -1));
        return;
    }

    printf("Reloaded: %s\n", filename);
}

// 파일 변경 감지 (매 프레임)
void Update() {
    if (FileWatcher::Changed("scripts/skills.lua")) {
        ReloadScript("scripts/skills.lua");
    }
}
시나리오

1. 게임 실행 중

2. 스킬 데미지가 너무 세다고 느껴짐

3. skills.lua 파일 열어서 데미지 100 → 50으로 수정

4. 저장하면 즉시 적용됨 (게임 재시작 없이!)

Hot Reload의 장점

  • 개발 속도: 수정 → 테스트 사이클이 초 단위
  • 기획자 협업: 프로그래머 없이 밸런스 조정 가능
  • 라이브 패치: 서버 재시작 없이 버그 수정

7모딩 시스템 만들기

질문
WoW 애드온이나 Garry's Mod 모드는 어떻게 가능한 거야?
유저에게 Lua 스크립트를 열어준 것
-- 유저가 만든 WoW 애드온 예시
local addon = CreateFrame("Frame")

addon:RegisterEvent("PLAYER_ENTERING_WORLD")
addon:RegisterEvent("UNIT_HEALTH")

addon:SetScript("OnEvent", function(self, event, ...)
    if event == "PLAYER_ENTERING_WORLD" then
        print("Welcome back!")
    elseif event == "UNIT_HEALTH" then
        local unit = ...
        if unit == "player" then
            local hp = UnitHealth("player")
            local maxHp = UnitHealthMax("player")
            if hp / maxHp < 0.2 then
                -- 화면에 경고 표시
                ShowLowHealthWarning()
            end
        end
    end
end)

보안 주의!

유저 스크립트에게 모든 권한을 주면 위험해.

  • 파일 시스템 접근 차단
  • 네트워크 접근 차단
  • 특정 API만 노출 (화이트리스트)
  • 실행 시간 제한 (무한 루프 방지)
// C++ - 샌드박스 환경 만들기
void CreateSandbox(lua_State* L) {
    // 위험한 함수들 제거
    lua_pushnil(L);
    lua_setglobal(L, "os");      // os.execute 등 차단

    lua_pushnil(L);
    lua_setglobal(L, "io");      // 파일 접근 차단

    lua_pushnil(L);
    lua_setglobal(L, "loadfile"); // 외부 파일 로드 차단

    // 허용할 게임 API만 등록
    lua_register(L, "GetPlayerHP", safe_GetPlayerHP);
    lua_register(L, "ShowMessage", safe_ShowMessage);
    // ...
}

경험 법칙

  • 매 프레임 수천 번 호출 = C++
  • 이벤트 기반, 가끔 호출 = Lua OK

질문
Lua 성능을 더 올릴 수는 없어?
LuaJIT!

Just-In-Time 컴파일러. Lua 코드를 기계어로 변환해서 실행. 일반 Lua보다 10~50배 빠름.

-- LuaJIT FFI - C 구조체 직접 사용
local ffi = require("ffi")

ffi.cdef[[
    typedef struct { float x, y, z; } Vector3;
    Vector3* GetPlayerPosition();
]]

local pos = ffi.C.GetPlayerPosition()
print(pos.x, pos.y, pos.z)  -- C++ 속도로 접근!

9Lua 임베딩의 현실

장점

  • 빠른 이터레이션 (Hot Reload)
  • 기획자/아티스트도 수정 가능
  • 모딩 시스템 제공 용이
  • 작은 바이너리 크기
  • 배우기 쉬운 문법
  • 크로스 플랫폼

단점

  • C++보다 느림
  • 타입 없음 → 런타임 에러
  • IDE 지원 부족
  • 디버깅 어려움
  • C++ 바인딩 작성 필요
  • 두 언어 유지보수

결론

Lua는 "게임 로직의 유연성"을 위한 선택.

성능이 중요하면 C++, 빠른 수정이 중요하면 Lua.

대부분의 대형 게임은 둘 다 사용.

핵심 정리

개념 설명
CSV vs Lua CSV는 값(데이터)만. Lua는 로직(조건, 흐름)까지.
왜 Lua? 작고, 빠르고, 붙이기 쉬움.

-- Lua 한눈에 보기
local player = {
    name = "Hero",
    hp = 100,

    takeDamage = function(self, amount)
        self.hp = self.hp - amount
        if self.hp <= 0 then
            OnPlayerDeath()  -- C++ 함수 호출
        end
    end
}

-- 이벤트 핸들러 (엔진에서 호출)
function OnEnemyAttack(enemyId, damage)
    player:takeDamage(damage)
    PlaySound("hit.wav")  -- C++ 함수 호출
    ShowDamageNumber(damage)
end
