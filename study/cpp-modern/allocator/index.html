커스텀 할당자 & PMR

게임 서버에서 메모리 할당을 최적화하는 방법

Part 1. 왜 커스텀 할당자가 필요해?

new/delete 쓰면 안 돼?

쓸 수는 있지만, 게임 서버에서는 문제가 됩니다!

비유: 창고 관리

new/delete (범용 할당자) = 대형 창고 관리 회사

  • 어떤 크기든 맡아줌 (범용)
  • 빈 공간 찾느라 창고 전체 탐색
  • 물건 크기가 제각각이라 정리가 어려움 (단편화)
  • 여러 사람이 동시에 요청하면 줄 서야 함 (락)

커스텀 할당자 = 내 물건 전용 선반

  • 같은 크기 물건만 담아서 정리 쉬움
  • 빈 칸 찾기 = O(1)
  • 내 선반이라 기다릴 필요 없음
new/delete의 문제점: ┌─────────────────────────────────────────────────────────────┐ │ │ │ [1] 할당 비용 │ │ ───────────────────────────────────────────── │ │ new → 힙 탐색 → 빈 공간 찾기 → 메타데이터 업데이트 │ │ 비용: ~100-1000 cycles │ │ │ │ [2] 멀티스레드 경합 │ │ ───────────────────────────────────────────── │ │ Thread A: new ──┐ │ │ Thread B: new ──┼─→ [Lock 대기] → [힙 접근] → [해제] │ │ Thread C: new ──┘ │ │ → 동시 할당 시 직렬화됨! │ │ │ │ [3] 메모리 단편화 │ │ ───────────────────────────────────────────── │ │ 할당 전: [ 빈 공간 ] │ │ 사용 후: [A][빈][BB][빈][C][빈빈빈][D] │ │ → 빈 공간은 있는데 큰 할당 실패! │ │ │ │ [4] 캐시 비친화적 │ │ ───────────────────────────────────────────── │ │ 같은 타입 객체들이 메모리에 흩어짐 │ │ → Cache Miss 증가 │ │ │ └─────────────────────────────────────────────────────────────┘
게임 서버에서 얼마나 문제가 돼?
상황 new/delete 커스텀 할당자
패킷 100만 개 할당 ~500ms ~10ms
16스레드 동시 할당 락 경합 심각 스레드별 풀
24시간 운영 후 단편화 심각 단편화 없음

Part 2. 오브젝트 풀 (Object Pool)

오브젝트 풀이 뭐야?

미리 만들어두고 재사용! 가장 흔한 커스텀 할당 방식이에요.

비유: 볼링장 신발

볼링장에서 신발을 빌려주잖아요?

  • 미리 여러 사이즈 신발을 준비 (Pool 초기화)
  • 손님 오면 빈 신발 줌 (Alloc)
  • 손님 가면 신발 회수 (Free)
  • 신발을 새로 사거나 버리지 않음!
// 간단한 오브젝트 풀 구현 template<typename T, size_t PoolSize = 1024> class ObjectPool { T objects[PoolSize]; bool used[PoolSize] = {false}; size_t nextFree = 0; public: T* Alloc() { for (size_t i = 0; i < PoolSize; i++) { size_t idx = (nextFree + i) % PoolSize; if (!used[idx]) { used[idx] = true; nextFree = (idx + 1) % PoolSize; return &objects[idx]; } } return nullptr; // 풀 가득 참 } void Free(T* obj) { size_t idx = obj - objects; if (idx < PoolSize) { used[idx] = false; } } }; // 사용 예시 ObjectPool<Packet, 10000> packetPool; Packet* pkt = packetPool.Alloc(); // O(1)! // 사용... packetPool.Free(pkt); // O(1)!
더 효율적인 방법은?

Free List를 사용하면 항상 O(1)!

// Free List 기반 오브젝트 풀 template<typename T, size_t PoolSize = 1024> class FreeListPool { union Slot { T object; Slot* next; // 비어있을 때: 다음 빈 슬롯 포인터 }; Slot slots[PoolSize]; Slot* freeList = nullptr; public: FreeListPool() { // 초기화: 모든 슬롯을 연결 리스트로 for (size_t i = 0; i < PoolSize - 1; i++) { slots[i].next = &slots[i + 1]; } slots[PoolSize - 1].next = nullptr; freeList = &slots[0]; } T* Alloc() { if (!freeList) return nullptr; Slot* slot = freeList; freeList = slot->next; return new(&slot->object) T(); // placement new } void Free(T* obj) { obj->~T(); // 소멸자 호출 Slot* slot = reinterpret_cast<Slot*>(obj); slot->next = freeList; freeList = slot; } };
Free List 동작: ┌─────────────────────────────────────────────────────────────┐ │ │ │ [초기 상태] │ │ freeList → [0] → [1] → [2] → [3] → [4] → nullptr │ │ │ │ [Alloc() 3번 호출 후] │ │ freeList → [3] → [4] → nullptr │ │ [0] [1] [2] 사용 중 │ │ │ │ [Free([1]) 호출] │ │ freeList → [1] → [3] → [4] → nullptr │ │ ^ │ │ 반환된 슬롯이 맨 앞으로! │ │ │ │ → Alloc: O(1) - 맨 앞에서 꺼냄 │ │ → Free: O(1) - 맨 앞에 추가 │ │ │ └─────────────────────────────────────────────────────────────┘

Part 3. 스택/선형 할당자

스택 할당자는 뭐야?

순차적으로 할당하고, 한 번에 리셋!

비유: 칠판에 글쓰기

칠판에 왼쪽부터 쭉 글을 써나가다가...

  • 중간에 지우기 어려움
  • 대신 한 번에 싹 지우면 끝!
  • 매 프레임 시작할 때 칠판을 지우고 새로 시작
// 스택/선형 할당자 class StackAllocator { char* buffer; size_t capacity; size_t offset = 0; public: StackAllocator(size_t size) { buffer = new char[size]; capacity = size; } void* Alloc(size_t size, size_t alignment = 8) { // 정렬 size_t alignedOffset = (offset + alignment - 1) & ~(alignment - 1); if (alignedOffset + size > capacity) return nullptr; // 공간 부족 void* ptr = buffer + alignedOffset; offset = alignedOffset + size; return ptr; } void Reset() { offset = 0; // 한 번에 리셋! O(1)! } ~StackAllocator() { delete[] buffer; } }; // 사용 예시: 프레임 임시 데이터 StackAllocator frameAlloc(1024 * 1024); // 1MB void OnFrame() { // 프레임 동안 임시 할당 auto* temp1 = frameAlloc.Alloc(1000); auto* temp2 = frameAlloc.Alloc(500); // 사용... // 프레임 끝: 한 번에 정리! frameAlloc.Reset(); }
스택 할당자 특징
• 할당: O(1) - 포인터 증가만
• 개별 해제: 불가능 (또는 LIFO 순서만)
• 리셋: O(1) - 포인터만 0으로
• 용도: 프레임 임시 데이터, 파티클 시스템

Part 4. PMR - C++17의 선물

PMR이 뭐야?

표준 라이브러리에서 커스텀 할당자를 쉽게 쓰게 해주는 것!

비유: USB 포트

예전에는 각 기기마다 전용 케이블이 필요했어요.

USB가 나오면서? → 아무 기기나 꽂으면 됨!

PMR = 메모리 할당자의 "USB 표준"

  • 어떤 할당자든 같은 인터페이스
  • STL 컨테이너에 바로 연결 가능
// PMR 기본 사용법 #include #include // 스택 버퍼 사용 char buffer[1024]; std::pmr::monotonic_buffer_resource pool{buffer, sizeof(buffer)}; // PMR 버전 vector - 커스텀 메모리 사용! std::pmr::vector<int> numbers{&pool}; numbers.push_back(1); // buffer에서 할당! numbers.push_back(2); // 힙 할당 없음! // 여러 컨테이너가 같은 메모리 풀 공유 std::pmr::string str{&pool}; std::pmr::map<int, std::pmr::string> map{&pool};
PMR의 종류는?
Memory Resource 특징 용도
monotonic_buffer_resource 스택 할당자, 리셋만 가능 프레임 임시 데이터
unsynchronized_pool_resource 싱글스레드 풀 스레드 로컬 할당
synchronized_pool_resource 멀티스레드 풀 공유 데이터
new_delete_resource 기본 new/delete fallback
// monotonic_buffer_resource - 프레임 할당용 class FrameAllocator { char buffer[1024 * 1024]; // 1MB std::pmr::monotonic_buffer_resource resource{buffer, sizeof(buffer)}; public: std::pmr::memory_resource* Get() { return &resource; } void Reset() { resource.release(); // 한 번에 해제! } }; // 게임 루프에서 사용 FrameAllocator frameAlloc; void GameLoop() { while (running) { // 프레임 시작 std::pmr::vector<Enemy*> visibleEnemies{frameAlloc.Get()}; std::pmr::string debugInfo{frameAlloc.Get()}; // 게임 로직... // 프레임 끝: 모든 메모리 한 번에 해제 frameAlloc.Reset(); } }

Part 5. 게임 서버 실전 패턴

실제로 어떻게 조합해서 써?
게임 서버 메모리 구조: ┌─────────────────────────────────────────────────────────────┐ │ │ │ [영구 데이터] - 전역 할당자 │ │ ───────────────────────────────────────────── │ │ • 플레이어 정보, 아이템 DB │ │ • 서버 시작 시 할당, 종료 시 해제 │ │ • synchronized_pool_resource 또는 new/delete │ │ │ │ [세션 데이터] - 세션별 풀 │ │ ───────────────────────────────────────────── │ │ • 접속 중인 플레이어 상태 │ │ • 세션 시작 시 풀 생성, 종료 시 풀 해제 │ │ • unsynchronized_pool_resource (세션별) │ │ │ │ [프레임 데이터] - 스택 할당자 │ │ ───────────────────────────────────────────── │ │ • 임시 계산, 디버그 정보 │ │ • 매 프레임 리셋 │ │ • monotonic_buffer_resource │ │ │ │ [패킷 데이터] - 오브젝트 풀 │ │ ───────────────────────────────────────────── │ │ • 네트워크 패킷 │ │ • 고정 크기, 대량 생성/소멸 │ │ • Free List 기반 Object Pool │ │ │ └─────────────────────────────────────────────────────────────┘
코드로 보여줘!
// 게임 서버 메모리 매니저 class MemoryManager { // 패킷 풀 FreeListPool<Packet, 100000> packetPool; // 프레임 할당자 (스레드별) thread_local static char frameBuffer[1 * 1024 * 1024]; thread_local static std::pmr::monotonic_buffer_resource frameResource; public: // 패킷 할당 Packet* AllocPacket() { return packetPool.Alloc(); } void FreePacket(Packet* pkt) { packetPool.Free(pkt); } // 프레임 할당자 얻기 std::pmr::memory_resource* GetFrameAllocator() { return &frameResource; } // 프레임 끝에 호출 void ResetFrameAllocator() { frameResource.release(); new(&frameResource) std::pmr::monotonic_buffer_resource{ frameBuffer, sizeof(frameBuffer) }; } }; // 사용 예시 MemoryManager g_memoryManager; void ProcessPacket() { Packet* pkt = g_memoryManager.AllocPacket(); // 처리... g_memoryManager.FreePacket(pkt); } void OnFrame() { auto* alloc = g_memoryManager.GetFrameAllocator(); std::pmr::vector<int> tempData{alloc}; // 프레임 작업... g_memoryManager.ResetFrameAllocator(); }

Part 7. 면접에서 물어보면?

"커스텀 할당자를 써본 적 있나요?"

✅ 핵심 답변 포인트

1. 필요성 설명

"new/delete는 범용이라 할당 비용, 멀티스레드 락, 단편화 문제가 있습니다. 게임 서버처럼 대량의 동일 객체를 다루면 커스텀 할당자가 유리합니다."

2. 종류별 설명

"오브젝트 풀은 고정 크기 객체용, 스택 할당자는 프레임 임시 데이터용, PMR은 표준 컨테이너와 통합용으로 사용합니다."

3. 실제 경험

"패킷 처리에 오브젝트 풀을 적용해서 할당 시간을 10배 개선했습니다." (경험 있다면)

4. 트레이드오프

"메모리를 미리 예약해야 해서 초기 메모리 사용량이 증가합니다. 풀 크기 튜닝이 필요합니다."

핵심 숫자는?
핵심 숫자 정리: ┌─────────────────────────────────────────────────────────────┐ │ │ │ [할당 비용] │ │ • new/delete: ~100-1000 cycles │ │ • Object Pool: ~10-20 cycles │ │ • Stack Allocator: ~5 cycles │ │ │ │ [멀티스레드] │ │ • 전역 힙 락: ~1000+ cycles (경합 시) │ │ • 스레드 로컬 풀: 락 없음 │ │ │ │ [메모리 오버헤드] │ │ • new/delete: 16~32바이트/할당 (메타데이터) │ │ • Object Pool: 0바이트 (미리 할당) │ │ │ │ [개선 효과] │ │ • 할당 속도: 10~50배 개선 │ │ • 멀티스레드: 20배+ 개선 (락 제거) │ │ • 단편화: 완전 제거 (풀 방식) │ │ │ └─────────────────────────────────────────────────────────────┘

핵심 정리

  • new/delete 문제: 느린 할당, 락 경합, 단편화
  • 오브젝트 풀: 고정 크기, Free List로 O(1) 할당/해제
  • 스택 할당자: 순차 할당, 한 번에 리셋 (프레임 데이터)
  • PMR: C++17 표준, STL과 쉽게 통합
  • monotonic_buffer_resource: 프레임 임시 할당용
  • 실전 패턴: 패킷=풀, 프레임=스택, 영구=표준
  • 성능 개선: 할당 10배, 멀티스레드 20배+
  • 트레이드오프: 초기 메모리 예약 필요, 풀 크기 튜닝
