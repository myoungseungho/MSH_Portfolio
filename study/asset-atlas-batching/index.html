Atlas와 Batching

Draw Call을 줄여 렌더링 성능을 극대화하는 핵심 기법

Part 1. 개념 이해 - Draw Call이 왜 문제인가?

Draw Call이 뭐고, 왜 줄여야 해?

Draw Call은 CPU가 GPU에게 "이거 그려"라고 명령하는 API 호출입니다. 문제는 각 Draw Call마다 CPU-GPU 간 상태 전환 비용이 발생한다는 점입니다.

┌─────────────────────────────────────────────────────────────────────┐
│                    Draw Call 처리 과정                               │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   CPU                           GPU                                  │
│   ────                          ────                                 │
│                                                                      │
│   ┌──────────────┐             ┌──────────────┐                     │
│   │ Draw Call #1 │ ──────────→ │ 상태 설정    │                     │
│   │ - 텍스처 A   │             │ - 텍스처 바인딩│                    │
│   │ - 쉐이더 X   │             │ - 쉐이더 설정  │                    │
│   │ - 메시 데이터│             │ - 버텍스 버퍼  │                    │
│   └──────────────┘             └───────┬──────┘                     │
│          │                             │                             │
│          ▼                             ▼                             │
│   ┌──────────────┐             ┌──────────────┐                     │
│   │ Draw Call #2 │ ──────────→ │ 상태 재설정  │  ← 비용 발생!       │
│   │ - 텍스처 B   │   상태변경!  │ - 다른 텍스처│                     │
│   │ - 쉐이더 X   │             │              │                     │
│   └──────────────┘             └──────────────┘                     │
│                                                                      │
│   문제: 1000개 오브젝트 = 1000번 상태 전환 = CPU 병목!               │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘

모바일에서 Draw Call 100~300개면 이미 CPU 병목이 시작됩니다. PC도 1000개 넘어가면 문제입니다.

그럼 Atlas가 뭐야?

Texture Atlas는 여러 작은 텍스처를 하나의 큰 텍스처로 합친 것입니다. 핵심 아이디어: 같은 텍스처를 쓰면 Draw Call을 합칠 수 있다!

┌─────────────────────────────────────────────────────────────────────┐
│                    Texture Atlas 개념                                │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   개별 텍스처 (Before)              Atlas (After)                    │
│   ─────────────────────             ─────────────────                │
│                                                                      │
│   ┌────┐ ┌────┐ ┌────┐            ┌─────────────────┐               │
│   │ A  │ │ B  │ │ C  │            │  A  │  B  │  C  │               │
│   │64² │ │64² │ │64² │   ───→    ├─────┼─────┼─────┤               │
│   └────┘ └────┘ └────┘            │  D  │  E  │  F  │               │
│   ┌────┐ ┌────┐ ┌────┐            ├─────┼─────┼─────┤               │
│   │ D  │ │ E  │ │ F  │            │  G  │  H  │  I  │               │
│   └────┘ └────┘ └────┘            └─────────────────┘               │
│   ┌────┐ ┌────┐ ┌────┐              512 × 512                       │
│   │ G  │ │ H  │ │ I  │                                              │
│   └────┘ └────┘ └────┘                                              │
│                                                                      │
│   9개 텍스처 바인딩              →  1개 텍스처 바인딩                │
│   최대 9번 Draw Call             →  1번 Draw Call 가능!             │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘

각 스프라이트는 Atlas 내에서 UV 좌표로 위치를 지정합니다.

// UV 좌표 변환 예시 struct AtlasSprite { Rect uvRect; // Atlas 내 UV 영역 (0~1 정규화) Vector2 pivot; // 스프라이트 기준점 float pixelsPerUnit; }; // 64×64 스프라이트가 512×512 Atlas의 (128, 0) 위치에 있다면: AtlasSprite sprite = { .uvRect = { .x = 128.0f / 512.0f, // 0.25 .y = 0.0f / 512.0f, // 0.0 .width = 64.0f / 512.0f, // 0.125 .height = 64.0f / 512.0f // 0.125 }, .pivot = { 0.5f, 0.5f }, .pixelsPerUnit = 100.0f };
Batching은 뭐야? Atlas랑 어떤 관계야?

Batching은 여러 오브젝트의 Draw Call을 하나로 합치는 기법입니다. Atlas는 Batching을 가능하게 하는 전제 조건입니다!

│                                                                      │
│   ┌──────────────────────────────────────────────┐                  │
│   │  ✓ 같은 Material (쉐이더 + 속성)             │                  │
│   │  ✓ 같은 Texture (Atlas로 해결!)              │ ← Atlas 역할     │
│   │  ✓ 같은 Render State (blend, cull 등)        │                  │
│   │  ✓ 같은 Lighting Mode                        │                  │
│   └──────────────────────────────────────────────┘                  │
│                                                                      │
│   예시: UI 버튼 10개                                                 │
│   ─────────────────                                                  │

│                                                                      │
└─────────────────────────────────────────────────────────────────────┘

Part 2. Batching 종류 - Static, Dynamic, GPU Instancing

Static Batching이 뭐야?

Static Batching은 움직이지 않는 오브젝트들의 메시를 빌드 타임에 하나로 합칩니다.

┌─────────────────────────────────────────────────────────────────────┐
│                    Static Batching                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   Build Time (에디터에서)                                            │
│   ─────────────────────                                              │
│                                                                      │
│   ┌─────┐ ┌─────┐ ┌─────┐     ┌───────────────────┐                │
│   │Mesh1│ │Mesh2│ │Mesh3│ ──→ │ Combined Mesh     │                │
│   │ 100 │ │ 150 │ │  80 │     │ 330 vertices      │                │
│   │verts│ │verts│ │verts│     │ World Space 좌표! │                │
│   └─────┘ └─────┘ └─────┘     └───────────────────┘                │
│                                                                      │
│   장점:                        단점:                                 │
│   ────                         ────                                  │
│   • 런타임 CPU 비용 0          • 추가 메모리 사용                    │
│   • 1 Draw Call로 처리         • 오브젝트 이동 불가                  │
│   • 가장 효율적                • 개별 컬링 불가 (큰 덩어리)          │
│                                                                      │
│   적합한 대상:                                                       │
│   ─────────────                                                      │
│   • 건물, 지형, 소품                                                 │
│   • 배경 나무, 바위                                                  │
│   • 절대 움직이지 않는 것                                            │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
// Unity에서 Static Batching 설정 // 1. Inspector에서 오브젝트 선택 → Static 체크 // 2. 또는 코드로: void SetupStaticBatching(GameObject[] staticObjects) { // Static 플래그 설정 foreach (var obj in staticObjects) { obj.isStatic = true; // 또는 특정 플래그만: StaticEditorFlags flags = StaticEditorFlags.BatchingStatic; GameObjectUtility.SetStaticEditorFlags(obj, flags); } // 런타임에 수동 배칭 (동적 생성 오브젝트용) StaticBatchingUtility.Combine(staticObjects, rootObject); }
💡 메모리 트레이드오프: Static Batching은 각 오브젝트의 메시 데이터를 월드 좌표로 변환하여 저장합니다. 같은 프리팹 100개 → 메시 100배 메모리 사용!
Dynamic Batching은?

Dynamic Batching은 런타임에 작은 메시들을 합칩니다. CPU에서 매 프레임 변환 계산!

┌─────────────────────────────────────────────────────────────────────┐
│                    Dynamic Batching                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   매 프레임 (런타임)                                                 │
│   ───────────────────                                                │
│                                                                      │
│   오브젝트 A, B, C (같은 Material)                                   │
│        │                                                             │
│        ▼                                                             │
│   ┌─────────────────────────────────────┐                           │
│   │ CPU: Transform 계산                  │                           │
│   │ ───────────────────                  │                           │
│   │ for each vertex:                     │                           │
│   │   worldPos = localPos × worldMatrix  │  ← 매 프레임 CPU 비용!   │
│   └─────────────────────────────────────┘                           │
│        │                                                             │
│        ▼                                                             │
│   ┌─────────────────────────────────────┐                           │
│   │ Combined Vertex Buffer               │                           │
│   │ → 1 Draw Call                        │                           │
│   └─────────────────────────────────────┘                           │
│                                                                      │
│   제한 조건 (Unity):                                                 │
│   ─────────────────                                                  │
│   • 버텍스 300개 이하                                                │
│   • 버텍스 속성 900개 이하 (위치+노말+UV = 3 → 300버텍스)            │
│   • 동일 스케일 (또는 uniform scale)                                 │
│   • 실시간 그림자 사용 시 비활성화                                   │
│   • Multi-pass 쉐이더 불가                                           │
│                                                                      │
│   적합한 대상:                                                       │
│   ─────────────                                                      │
│   • 파티클 (작은 quad들)                                             │
│   • UI 요소                                                          │
│   • 2D 스프라이트                                                    │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
⚠️ Dynamic Batching 주의: 버텍스가 많으면 CPU 오버헤드가 Draw Call 비용보다 커질 수 있습니다. Unity에서는 SRP Batcher 사용 시 자동 비활성화됩니다.
GPU Instancing은 뭐야?

GPU Instancing은 같은 메시를 여러 번 그릴 때, 메시 데이터는 1번만 보내고 인스턴스별 Transform만 별도 전송합니다.

┌─────────────────────────────────────────────────────────────────────┐
│                    GPU Instancing                                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   일반 렌더링                   GPU Instancing                       │
│   ────────────                  ──────────────                       │
│                                                                      │
│   Draw(Mesh, Transform1)        DrawInstanced(Mesh, count=1000)      │
│   Draw(Mesh, Transform2)        + Instance Buffer:                   │
│   Draw(Mesh, Transform3)          [Transform1, Transform2, ...]      │
│   ...                                                                │
│   Draw(Mesh, Transform1000)                                          │
│                                                                      │
│   = 1000 Draw Calls             = 1 Draw Call!                       │
│   = 메시 1000번 전송              = 메시 1번 전송                      │
│                                                                      │
│   Instance Buffer 구조:                                              │
│   ────────────────────                                               │
│   ┌────────────────────────────────────────┐                        │
│   │ Index │ Position      │ Rotation │ ... │                        │
│   ├───────┼───────────────┼──────────┼─────┤                        │
│   │   0   │ (10, 0, 5)    │ (0,90,0) │     │                        │
│   │   1   │ (15, 0, 8)    │ (0,45,0) │     │                        │
│   │   2   │ (20, 0, 3)    │ (0,0,0)  │     │                        │
│   │  ...  │ ...           │ ...      │     │                        │
│   └────────────────────────────────────────┘                        │
│                                                                      │
│   GPU가 SV_InstanceID로 각 인스턴스 구분                             │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
// GPU Instancing 쉐이더 (HLSL) struct InstanceData { float4x4 objectToWorld; float4 color; // 인스턴스별 색상 }; StructuredBuffer<InstanceData> _InstanceBuffer; v2f vert(appdata v, uint instanceID : SV_InstanceID) { v2f o; // 인스턴스별 Transform 적용 float4x4 objectToWorld = _InstanceBuffer[instanceID].objectToWorld; float4 worldPos = mul(objectToWorld, float4(v.vertex.xyz, 1.0)); o.vertex = mul(UNITY_MATRIX_VP, worldPos); o.color = _InstanceBuffer[instanceID].color; return o; } // Unity C# - 인스턴스 데이터 설정 void SetupInstancing() { Matrix4x4[] matrices = new Matrix4x4[1000]; Vector4[] colors = new Vector4[1000]; for (int i = 0; i < 1000; i++) { matrices[i] = Matrix4x4.TRS(positions[i], rotations[i], scales[i]); colors[i] = new Vector4(Random.value, Random.value, Random.value, 1); } // DrawMeshInstanced 호출 Graphics.DrawMeshInstanced(mesh, 0, material, matrices, 1000, propertyBlock, ShadowCastingMode.On, true); }

GPU Instancing 적합한 대상: 잔디, 나무, 군중, 파티클, 총알

SRP Batcher는 뭐야?

SRP Batcher는 Unity의 Scriptable Render Pipeline에서 사용하는 최신 배칭 방식입니다. Draw Call 수는 줄지 않지만, GPU 상태 변경을 최소화합니다.

┌─────────────────────────────────────────────────────────────────────┐
│                    SRP Batcher 원리                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   기존 방식 (Material Property 매번 업로드)                          │
│   ────────────────────────────────────                               │
│                                                                      │
│   Draw #1 → Upload(Material A props) → Upload(Transform) → Draw     │
│   Draw #2 → Upload(Material A props) → Upload(Transform) → Draw     │
│   Draw #3 → Upload(Material B props) → Upload(Transform) → Draw     │
│             ↑                                                        │
│             같은 Material인데도 매번 업로드!                         │
│                                                                      │
│   SRP Batcher (Persistent CBUFFER)                                   │
│   ────────────────────────────────                                   │
│                                                                      │
│   ┌────────────────────────────────────────────────────────┐        │
│   │ GPU Persistent Memory                                   │        │
│   │ ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │        │
│   │ │Material A    │  │Material B    │  │Per-Object    │  │        │
│   │ │CBUFFER       │  │CBUFFER       │  │CBUFFER       │  │        │
│   │ │(한번 업로드) │  │(한번 업로드) │  │(Transform만) │  │        │
│   │ └──────────────┘  └──────────────┘  └──────────────┘  │        │
│   └────────────────────────────────────────────────────────┘        │
│                                                                      │
│   Draw #1 → Bind(MatA CBUFFER) → Bind(Obj1 CBUFFER) → Draw          │
│   Draw #2 → (MatA 이미 바인딩)   → Bind(Obj2 CBUFFER) → Draw        │
│   Draw #3 → Bind(MatB CBUFFER) → Bind(Obj3 CBUFFER) → Draw          │
│             ↑                                                        │
│             Material 변경 시에만 바인딩!                             │
│                                                                      │
│   결과: Draw Call 수는 같지만 GPU 상태 변경 ↓↓↓ = 빨라짐            │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
// SRP Batcher 호환 쉐이더 작성법 // CBUFFER를 UnityPerMaterial로 그룹핑해야 함! CBUFFER_START(UnityPerMaterial) float4 _Color; float4 _MainTex_ST; float _Metallic; float _Smoothness; CBUFFER_END // 주의: Material Property Block 사용하면 SRP Batcher 깨짐! // renderer.SetPropertyBlock(block); // ← 호환 불가

Part 3. Atlas 제작 - 실전 가이드

Atlas를 어떻게 만들어?

Atlas 제작은 크게 빌드 타임 생성과 런타임 생성으로 나뉩니다.

// Unity Sprite Atlas 설정 코드 using UnityEngine; using UnityEngine.U2D; public class AtlasManager : MonoBehaviour { [SerializeField] SpriteAtlas uiAtlas; void Awake() { // Late Binding 콜백 등록 SpriteAtlasManager.atlasRequested += OnAtlasRequested; } void OnAtlasRequested(string tag, Action<SpriteAtlas> callback) { // 에셋 번들에서 Atlas 로드 if (tag == "UI") { StartCoroutine(LoadAtlasAsync(tag, callback)); } } IEnumerator LoadAtlasAsync(string tag, Action<SpriteAtlas> callback) { var request = Resources.LoadAsync<SpriteAtlas>($"Atlases/{tag}"); yield return request; callback(request.asset as SpriteAtlas); } // 특정 스프라이트 가져오기 public Sprite GetSprite(string name) { return uiAtlas.GetSprite(name); } }
런타임 Atlas는 어떻게 만들어?

Dynamic Atlas는 런타임에 텍스처를 합성합니다. 대표적인 알고리즘은 Binary Tree Bin Packing입니다.

// 런타임 Dynamic Atlas 구현 public class DynamicAtlas { private Texture2D m_Atlas; private AtlasNode m_RootNode; private int m_Padding = 2; // Bleeding 방지 패딩 public DynamicAtlas(int size) { m_Atlas = new Texture2D(size, size, TextureFormat.RGBA32, false); m_RootNode = new AtlasNode(0, 0, size, size); } // Binary Tree Packing public Rect? Insert(Texture2D texture) { int w = texture.width + m_Padding * 2; int h = texture.height + m_Padding * 2; AtlasNode node = m_RootNode.Insert(w, h); if (node == null) return null; // 공간 부족 // 텍스처 복사 (패딩 포함) Color[] pixels = texture.GetPixels(); m_Atlas.SetPixels( node.rect.x + m_Padding, node.rect.y + m_Padding, texture.width, texture.height, pixels); m_Atlas.Apply(); // UV 좌표 반환 (정규화) return new Rect( (node.rect.x + m_Padding) / (float)m_Atlas.width, (node.rect.y + m_Padding) / (float)m_Atlas.height, texture.width / (float)m_Atlas.width, texture.height / (float)m_Atlas.height ); } } // Binary Tree Node class AtlasNode { public RectInt rect; public AtlasNode left, right; public bool occupied; public AtlasNode Insert(int w, int h) { // 이미 사용 중 if (occupied) return null; // 리프 노드가 아님 - 자식에서 검색 if (left != null) { AtlasNode node = left.Insert(w, h); if (node != null) return node; return right.Insert(w, h); } // 공간이 부족 if (rect.width < w || rect.height < h) return null; // 딱 맞음! if (rect.width == w && rect.height == h) { occupied = true; return this; } // 분할 (더 긴 쪽을 기준으로) int dw = rect.width - w; int dh = rect.height - h; if (dw > dh) { // 수직 분할 left = new AtlasNode(rect.x, rect.y, w, rect.height); right = new AtlasNode(rect.x + w, rect.y, dw, rect.height); } else { // 수평 분할 left = new AtlasNode(rect.x, rect.y, rect.width, h); right = new AtlasNode(rect.x, rect.y + h, rect.width, dh); } return left.Insert(w, h); } }

// Unity에서 Texture2DArray 생성 public Texture2DArray CreateTextureArray(Texture2D[] textures, int size) { Texture2DArray array = new Texture2DArray( size, size, textures.Length, TextureFormat.DXT5, // 압축 포맷 true // 밉맵 ); for (int i = 0; i < textures.Length; i++) { // 리사이즈 필요시 Texture2D resized = ResizeTexture(textures[i], size, size); // 모든 밉맵 레벨 복사 for (int mip = 0; mip < resized.mipmapCount; mip++) { Graphics.CopyTexture( resized, 0, mip, // src array, i, mip // dst (layer i) ); } } array.Apply(false); return array; }

면접에서 Atlas/Batching 관련 예상 질문은?
🎯 예상 질문과 모범 답변:

Q1: Draw Call을 줄이는 방법들을 설명하세요.

A: "첫째, Texture Atlas로 여러 텍스처를 합쳐 Material을 통합합니다. 둘째, Static Batching으로 정적 오브젝트의 메시를 합칩니다. 셋째, GPU Instancing으로 같은 메시의 여러 인스턴스를 한 번에 그립니다. 넷째, SRP Batcher로 GPU 상태 변경을 최소화합니다."

Q2: Atlas 사용 시 주의점은?

A: "Texture Bleeding이 가장 큰 문제입니다. 밉맵이나 필터링 시 인접 텍스처 색이 섞일 수 있어, 2~4픽셀 패딩과 Edge Extrusion이 필요합니다. 또한 Atlas 크기가 너무 크면 메모리 낭비, 너무 작으면 여러 Atlas로 분리되어 배칭이 깨집니다."

Q3: Static Batching vs Dynamic Batching 차이점?

A: "Static은 빌드 타임에 월드 좌표로 메시를 합쳐 메모리를 더 쓰지만 런타임 비용이 없습니다. Dynamic은 런타임에 CPU가 매 프레임 변환 계산을 하므로 작은 메시(300버텍스 이하)에만 적합합니다."

Q4: 모바일에서 Draw Call 목표치는?

A: "일반적으로 100~200개가 안전 범위입니다. 300개 넘어가면 CPU 병목이 시작되고, UI+월드 합쳐서 관리해야 합니다. SetPass Call은 50개 이하를 목표로 합니다."

핵심 정리

  • Draw Call = CPU→GPU 명령. 상태 전환 비용 때문에 줄여야 함
  • Texture Atlas = 텍스처 합치기. 같은 Material = 배칭 가능
  • Static Batching = 정적 오브젝트. 메모리 ↑, CPU 비용 0
  • Dynamic Batching = 작은 메시 런타임 합성. 300버텍스 이하
  • GPU Instancing = 같은 메시 수천 개. 잔디, 군중에 최적
  • SRP Batcher = 상태 변경 최소화. URP/HDRP 필수
  • Texture Array = 같은 크기 텍스처 배열. 지형에 최적
