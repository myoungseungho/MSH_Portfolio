라이브 패칭

서비스 중단 없이 에셋을 업데이트하는 기술

Part 1. 개념: 라이브 패칭이란?

라이브 패칭이 뭐야?

서비스 중단 없이 게임 에셋을 업데이트하는 기술입니다. 사용자가 플레이하는 동안에도 새로운 콘텐츠나 버그 수정을 적용할 수 있습니다.

전통적인 패치 방식에서는 앱 스토어를 통한 전체 앱 업데이트가 필요했지만, 라이브 패칭은 번들 단위로 에셋만 교체하므로 즉각적인 배포가 가능합니다.

일반 업데이트와 뭐가 달라?

│                                                                 │

핵심 차이:

  • 배포 속도: 스토어 심사 없이 즉시 배포
  • 다운로드 크기: 변경된 부분만 차등 다운로드
  • 버전 관리: 서버에서 버전 강제 가능
  • 롤백: 문제 발생 시 즉시 이전 버전으로 복구

Part 2. 왜 필요해?

라이브 패칭 없으면 어떤 문제가 생겨?

라이브 서비스 게임에서 치명적인 문제들이 발생합니다:

💰 매출 손실

  • 긴급 버그 수정에 스토어 심사 1~7일 대기
  • 심사 기간 동안 이벤트/과금 장애 지속
  • 하루 매출 1억 게임 → 7일 지연 = 7억 손실 가능

👥 사용자 경험

  • 버전 파편화로 유저 간 호환성 문제
  • 전체 앱 재다운로드 강제 시 이탈
  • 업데이트 안 하면 플레이 불가 정책 → 불만

🔧 운영 비용

  • 매번 스토어 빌드 생성/업로드
  • 구버전 호환성 코드 유지 보수
  • 다중 버전 서버 로직 복잡도 증가
실제 사례 있어?

사례 1: 이벤트 긴급 패치

한정 이벤트 아이템의 드롭률이 설정 오류로 100배 높게 설정됨.

  • ❌ 스토어 업데이트: 3일 심사 동안 경제 붕괴
  • ✅ 라이브 패칭: 30분 내 수정본 배포, 이미 획득한 아이템만 후속 조치

사례 2: 보스 공략 버그

신규 레이드 보스가 특정 스킬 조합에 무한 스턴됨.

  • ❌ 스토어 업데이트: 공략 영상 확산, 랭킹 공정성 훼손
  • ✅ 라이브 패칭: 2시간 내 AI 패턴 데이터 교체

사례 3: 콜라보 이벤트 일정 변경

IP 홀더 요청으로 콜라보 시작일이 갑자기 당겨짐.

  • ❌ 스토어 업데이트: 일정 맞추기 불가능
  • ✅ 라이브 패칭: 에셋만 미리 배포, 서버 플래그로 활성화

플로우:
1. 클라이언트 시작 → Version Server에 최신 버전 조회
2. 로컬 버전과 비교 → 차이 목록 획득
3. CDN에서 변경된 번들만 다운로드
4. 로컬 캐시 업데이트 → 게임에 즉시 반영
버전 관리는 어떻게 해?

Catalog + Hash 기반 버전 관리를 사용합니다:

// catalog_[version].json - 에셋 카탈로그 { "version": "2024.01.15.001", "timestamp": 1705312800, "bundles": { "characters_hero": { "hash": "a1b2c3d4e5f6", "crc": 2847193856, "size": 15728640, "url": "bundles/characters_hero_a1b2c3d4.bundle" }, "ui_common": { "hash": "f6e5d4c3b2a1", "crc": 1938472651, "size": 8388608, "url": "bundles/ui_common_f6e5d4c3.bundle" } }, "forceUpdate": false, "minClientVersion": "1.5.0" }

Hash 기반 비교 장점:

  • 내용이 같으면 Hash가 같음 → 불필요한 다운로드 방지
  • 파일명에 Hash 포함 → CDN 캐시 무효화 자동 처리
  • CRC 검증 → 다운로드 무결성 보장
다운로드 시스템은 어떻게 구현해?
public class LivePatchManager : MonoBehaviour { private const string VERSION_URL = "https://api.game.com/version"; private const string CDN_BASE_URL = "https://cdn.game.com/"; public event Action<PatchProgress> OnProgress; public event Action<PatchResult> OnComplete; public async Task CheckAndApplyPatchAsync() { // 1. 서버 버전 정보 조회 var serverCatalog = await FetchCatalogAsync(VERSION_URL); var localCatalog = LoadLocalCatalog(); // 2. 변경된 번들 식별 var changedBundles = CompareAndGetChanges( localCatalog, serverCatalog ); if (changedBundles.Count == 0) { OnComplete?.Invoke(new PatchResult { Success = true, Message = "이미 최신 버전" }); return; } // 3. 다운로드 전 용량 확인 long totalSize = changedBundles.Sum(b => b.Size); if (!HasEnoughStorage(totalSize)) { OnComplete?.Invoke(new PatchResult { Success = false, Error = PatchError.InsufficientStorage }); return; } // 4. 번들 다운로드 및 적용 await DownloadBundlesAsync(changedBundles); // 5. 카탈로그 업데이트 SaveLocalCatalog(serverCatalog); OnComplete?.Invoke(new PatchResult { Success = true }); } private List<BundleInfo> CompareAndGetChanges( Catalog local, Catalog server) { var changes = new List<BundleInfo>(); foreach (var serverBundle in server.Bundles) { // 로컬에 없거나 Hash가 다르면 변경됨 if (!local.Bundles.TryGetValue(serverBundle.Key, out var localBundle) || localBundle.Hash != serverBundle.Value.Hash) { changes.Add(serverBundle.Value); } } return changes; } }
다운로드 중 네트워크 끊기면?

Resume 다운로드 + 트랜잭션 관리로 처리합니다:

public class ResumableDownloader { private readonly string _tempFolder; private readonly string _manifestPath; public async Task DownloadWithResumeAsync( BundleInfo bundle, IProgress<float> progress, CancellationToken ct) { string tempFile = Path.Combine(_tempFolder, bundle.Name + ".tmp"); string finalPath = GetBundlePath(bundle); long existingBytes = 0; // 이전 다운로드 이어받기 if (File.Exists(tempFile)) { existingBytes = new FileInfo(tempFile).Length; } using var request = new HttpRequestMessage(HttpMethod.Get, bundle.Url); // Range 헤더로 이어받기 요청 if (existingBytes > 0) { request.Headers.Range = new RangeHeaderValue(existingBytes, null); } using var response = await _httpClient.SendAsync( request, HttpCompletionOption.ResponseHeadersRead, ct ); // 서버가 Range 지원 안 하면 처음부터 if (response.StatusCode != HttpStatusCode.PartialContent) { existingBytes = 0; if (File.Exists(tempFile)) File.Delete(tempFile); } var totalBytes = existingBytes + (response.Content.Headers.ContentLength ?? 0); using var contentStream = await response.Content.ReadAsStreamAsync(); using var fileStream = new FileStream( tempFile, existingBytes > 0 ? FileMode.Append : FileMode.Create ); var buffer = new byte[81920]; // 80KB buffer long bytesRead = existingBytes; int read; while ((read = await contentStream.ReadAsync(buffer, ct)) > 0) { await fileStream.WriteAsync(buffer.AsMemory(0, read), ct); bytesRead += read; progress?.Report((float)bytesRead / totalBytes); } // 다운로드 완료 후 CRC 검증 await fileStream.FlushAsync(); fileStream.Close(); if (!VerifyCRC(tempFile, bundle.CRC)) { File.Delete(tempFile); throw new CorruptedDownloadException(bundle.Name); } // Atomic 이동 (트랜잭션) if (File.Exists(finalPath)) { File.Delete(finalPath); } File.Move(tempFile, finalPath); } }

Part 4. Addressables 연동

Unity Addressables로 라이브 패칭 어떻게 해?

Addressables는 Remote Catalog + Remote Bundles로 라이브 패칭을 지원합니다:

public class AddressablesLivePatcher { public async Task<PatchInfo> CheckForUpdatesAsync() { // 원격 카탈로그 체크 var checkHandle = Addressables.CheckForCatalogUpdates(false); var catalogs = await checkHandle.Task; if (catalogs == null || catalogs.Count == 0) { return new PatchInfo { HasUpdate = false }; } // 업데이트 필요한 에셋 크기 계산 var updateHandle = Addressables.UpdateCatalogs(catalogs, false); var locators = await updateHandle.Task; long totalSize = 0; foreach (var locator in locators) { var sizeHandle = Addressables.GetDownloadSizeAsync(locator.Keys); totalSize += await sizeHandle.Task; } return new PatchInfo { HasUpdate = true, TotalBytes = totalSize, CatalogCount = catalogs.Count }; } public async Task ApplyUpdatesAsync(IProgress<DownloadStatus> progress) { // 카탈로그 업데이트 var catalogs = await Addressables.CheckForCatalogUpdates(false).Task; var locators = await Addressables.UpdateCatalogs(catalogs, false).Task; // 변경된 번들 다운로드 foreach (var locator in locators) { var downloadHandle = Addressables.DownloadDependenciesAsync( locator.Keys, Addressables.MergeMode.Union ); while (!downloadHandle.IsDone) { progress?.Report(downloadHandle.GetDownloadStatus()); await Task.Yield(); } } } }

[AddressableAssetSettings]
├── Build Remote Catalog: ✅ 체크
├── Build Path: ServerData/[BuildTarget]
├── Load Path: https://cdn.game.com/[BuildTarget]
│
└── [Profile 설정]
    ├── RemoteLoadPath: https://cdn.game.com/bundles/[BuildTarget]
    └── RemoteBuildPath: ServerData/[BuildTarget]

[Asset Group 설정 - Remote Group]
├── Build Path: RemoteBuildPath
├── Load Path: RemoteLoadPath
├── Bundle Mode: Pack Separately (또는 Pack Together)
├── Compression: LZ4 (실시간 해제용) 또는 LZMA (작은 크기)
│
└── Content Update Restriction:
    ├── Cannot Change Post Release  ← 정적 에셋 (변경 적음)
    └── Can Change Post Release     ← 동적 에셋 (자주 변경)

[빌드 절차]
1. Build > New Build > Default Build Script
   → ServerData/에 번들 + catalog.json 생성

2. 내용 업데이트 시:
   Build > Update a Previous Build
   → 변경된 번들만 새로 생성
