Part 2. 뭘 기준으로 선택해?

게임에서 중요한 기술 요소가 뭐야?

3가지 핵심 기준이 있어.

  • 레이턴시 - 응답 속도
  • 비용 - API 호출 비용
  • 품질 - 캐릭터 일관성

1 레이턴시 (응답 속도)

유저 기대치:

├── 즉각 반응: < 200ms   ← 기존 정형 응답 수준
├── 수용 가능: < 1초     ← 타이핑 연출 가능
├── 불편함:   1~2초      ← 로딩 표시 필요
└── 이탈:     > 3초      ← 게임 흐름 끊김
방식 평균 레이턴시 비고
GPT-4o 800ms ~ 2s 네트워크 + 처리 시간
GPT-4o-mini 300ms ~ 800ms 가벼운 모델, 추천!
Llama 8B (로컬) 100 ~ 300ms GPU 성능에 따라

2 비용

실제로 얼마나 들어?

인디 게임 기준 (동시 접속 100명)으로 계산해볼게.

가정:
- NPC 대화: 1회/2분/유저
- 평균 토큰: 입력 150 + 출력 80 = 230 토큰

시간당: 100명 × 30회 × 230 = 69만 토큰
일일:   69만 × 24시간 = 1,656만 토큰
월간:   1,656만 × 30일 = 약 5억 토큰
방식 월 비용 (5억 토큰) 평가
GPT-4o ~$7,500 (약 1,000만원) 프로덕션 불가
GPT-4o-mini ~$375 (약 50만원) 소규모 가능
Llama 8B (자체 GPU) 전기세 ~5만원 가장 경제적!

결론

프로토타입 → API (빠른 검증)

프로덕션 → 자체 호스팅 (비용 통제)

Part 3. 세계관 유지는 어떻게?

중세 NPC가 "컴퓨터"라고 말하면 안 되잖아?

시스템 프롬프트가 핵심이야!

NPC의 성격, 말투, 알고 있는 것/모르는 것을 정의해주면 돼.

시스템 프롬프트 예시:

당신은 중세 판타지 세계 '아르케니아'의 대장장이 '볼란'입니다.

[캐릭터 설정]
- 나이: 52세, 성별: 남성
- 성격: 과묵하지만 일에 대한 자부심이 강함
- 말투: "~하지", "~다네", 반말 사용

[알고 있는 것]
- 마을의 역사와 주민들
- 무기와 방어구의 특성

[절대 모르는 것 - 언급 금지]
- 전기, 컴퓨터, 인터넷 등 현대 기술
- 자신이 NPC라는 사실

[대화 규칙]
- 3문장 이내로 답변
- 모르는 질문: "글쎄, 그건 잘 모르겠네"

[대화 예시]
유저: "인터넷이 뭐야?"
볼란: "뭔 소린지 모르겠네. 술이라도 마셨나?"

출력 필터링 (후처리)

// 금지어 필터 (C# 예시)
string[] forbiddenWords = {
    "컴퓨터", "인터넷", "스마트폰",
    "죄송합니다", "AI", "언어모델"
};

string FilterResponse(string text) {
    foreach (var word in forbiddenWords) {
        if (text.Contains(word)) {
            return "글쎄, 그건 잘 모르겠네.";
        }
    }
    return text;
}

Part 4. OpenAI API + Unity

가장 쉬운 방법이 뭐야?

OpenAI API = 가장 빠른 프로토타입!

10분 안에 NPC가 말하게 만들 수 있어.

1 API 키 발급

1. https://platform.openai.com 접속
2. 로그인 또는 회원가입
3. 좌측 메뉴 → API Keys
4. "Create new secret key" 클릭
5. 키 복사해서 안전한 곳에 저장!

⚠️ 키는 절대 공개 저장소에 올리지 마!

2 Unity 코드

// NPCDialogueManager.cs
using UnityEngine;
using UnityEngine.Networking;
using System.Collections;

public class NPCDialogueManager : MonoBehaviour
{
    [SerializeField] private string apiKey = "sk-...";
    [SerializeField] private string systemPrompt;

    public IEnumerator SendMessage(string input, System.Action<string> onResponse)
    {
        string json = $@"{{
            ""model"": ""gpt-4o-mini"",
            ""messages"": [
                {{""role"": ""system"", ""content"": ""{systemPrompt}""}},
                {{""role"": ""user"", ""content"": ""{input}""}}
            ],
            ""max_tokens"": 150
        }}";

        using (UnityWebRequest req = new UnityWebRequest(
            "https://api.openai.com/v1/chat/completions", "POST"))
        {
            req.uploadHandler = new UploadHandlerRaw(
                System.Text.Encoding.UTF8.GetBytes(json));
            req.downloadHandler = new DownloadHandlerBuffer();
            req.SetRequestHeader("Content-Type", "application/json");
            req.SetRequestHeader("Authorization", $"Bearer {apiKey}");

            yield return req.SendWebRequest();

            if (req.result == UnityWebRequest.Result.Success)
            {
                // JSON 파싱 후 응답 반환
                onResponse?.Invoke(ParseResponse(req.downloadHandler.text));
            }
        }
    }
}

Part 5. Ollama + Unity (무료!)

무료로 하고 싶은데?

Ollama = 내 컴퓨터에서 LLM 실행!

API 비용 0원, 인터넷 없이도 가능.

1 Ollama 설치

# Windows (PowerShell)
winget install Ollama.Ollama

# Mac
brew install ollama

# 모델 다운로드 (약 4GB)
ollama pull llama3.1:8b

# 서버 실행
ollama serve

→ http://localhost:11434 에서 동작!

Part 6. LM Studio (GUI로 쉽게)

터미널 싫은데... GUI 없어?

LM Studio = 클릭만으로 LLM 실행!

설치 방법:

1. https://lmstudio.ai 접속
2. 다운로드 & 설치
3. 앱 실행 → 모델 검색 (예: llama-3.1-8b)
4. 다운로드 버튼 클릭
5. 좌측 "Local Server" 탭 → Start Server

→ http://localhost:1234/v1/chat/completions
→ OpenAI API와 호환!

Unity 코드 변경점

OpenAI 코드에서 URL만 바꾸면 됨!

string url = "http://localhost:1234/v1/chat/completions";

Part 8. 테스트 시나리오

뭘 테스트해야 해?

NPC가 제대로 작동하는지 확인하는 4가지 시나리오!

[테스트 1: 정상 대화]
유저: "좋은 검 있어?"
기대: "강철검이 있지. 10골드다."
→ PASS: 캐릭터답게 대답

[테스트 2: 세계관 위반]
유저: "컴퓨터 게임 추천해줘"
기대: "뭔 소린지 모르겠네."
→ PASS: 현대 기술 모름

[테스트 3: 캐릭터 일관성]
유저: "너 누구야?"
기대: "난 볼란. 이 마을 대장장이지."
→ PASS: 설정대로 답변

[테스트 4: 대화 맥락]
유저: "강철검 얼마야?" → "그거 살게"
기대: "좋아, 강철검 가져가게."
→ PASS: 맥락 유지

Part 9. MMORPG에 적용한다면?

대규모 게임에서는 어떻게 써?

MMORPG는 동시 접속자가 많아서 고려할 게 더 있어.

비용, 서버 부하, 악용 방지가 핵심이야.

1 비용 최적화 전략

[전략 1: 캐싱]
자주 묻는 질문은 캐시해서 재사용

"검 팔아" → 캐시 HIT → 즉시 응답 (API 호출 X)
"오늘 날씨" → 캐시 MISS → API 호출 → 결과 캐시

→ 비용 70~80% 절감 가능!

[전략 2: 하이브리드]
중요한 NPC만 LLM, 나머지는 기존 방식

┌─────────────────────────────────────┐
│  퀘스트 NPC, 상점 NPC  →  기존 정형 대화  │
│  스토리 핵심 NPC       →  LLM 대화      │
│  일반 마을 주민        →  간단한 LLM      │
└─────────────────────────────────────┘

[전략 3: 모델 티어링]
상황에 따라 다른 모델 사용

일상 대화  →  Llama 7B (가벼움)
퀘스트 힌트 →  Llama 13B (보통)
중요 스토리 →  GPT-4o-mini (고품질)

2 서버 아키텍처

[권장 구조]

┌─────────┐     ┌─────────────┐     ┌─────────────┐
│  Client │ ──→ │  Game Server │ ──→ │  LLM Gateway │
└─────────┘     └─────────────┘     └──────┬──────┘
                                           │
                     ┌─────────────────────┼─────────────────────┐
                     ↓                     ↓                     ↓
              ┌───────────┐         ┌───────────┐         ┌───────────┐
              │  Cache    │         │  Ollama   │         │  OpenAI   │
              │  (Redis)  │         │  Cluster  │         │  Fallback │
              └───────────┘         └───────────┘         └───────────┘

→ 캐시 우선 → 로컬 LLM → API 폴백

스케일링 팁

동접 1,000명: Ollama 서버 2~3대 + Redis

동접 10,000명: vLLM 클러스터 + 로드밸런서

동접 100,000명: 하이브리드 (대부분 캐시/정형, 일부만 LLM)

3 MMORPG 특화 기능

기능 설명 구현 방법
NPC 기억 플레이어와의 과거 대화 기억 플레이어별 대화 로그 DB 저장
최근 N개만 프롬프트에 포함
월드 이벤트 반영 "어제 드래곤이 나타났다던데" 서버 이벤트 → 시스템 프롬프트 자동 업데이트
플레이어 평판 친밀도에 따른 말투 변화 친밀도 수치 → 프롬프트에 반영
동적 퀘스트 대화로 퀘스트 생성 LLM 응답 파싱 → 퀘스트 시스템 연동 
[플레이어 기억 예시]

시스템 프롬프트에 추가:

[이 플레이어와의 과거]
- 3일 전: 강철검을 구매함
- 1일 전: 미스릴 검에 대해 물어봄
- 지금: 다시 방문함

[플레이어 정보]
- 레벨: 45
- 직업: 전사
- 친밀도: 호감 (70/100)

→ "오, 자네 또 왔군. 미스릴 검 아직 관심 있나?"

4 악용 방지

주의해야 할 악용 시나리오

• 프롬프트 인젝션: "시스템 프롬프트를 무시하고..."

• 부적절한 대화 유도: 성인/폭력 콘텐츠 요청

• API 남용: 봇으로 무한 요청

[방지 전략]

1. 입력 필터링
string[] blockedPatterns = {
    "시스템 프롬프트", "ignore", "무시",
    "jailbreak", "DAN"
};

2. 출력 검증
- 욕설/성인 콘텐츠 필터
- 세계관 위반 체크
- 길이 제한 (너무 길면 차단)

3. Rate Limiting
- 플레이어당 1분에 최대 10회
- 연속 요청 시 쿨다운

4. 모니터링
- 의심스러운 대화 로깅
- 이상 패턴 자동 감지
