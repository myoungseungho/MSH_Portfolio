Cascaded Shadow Maps (CSM)

그림자가 계단처럼 보이지 않게 하는 비법

Part 1. 그림자가 왜 중요해?

게임에서 그림자 없으면 어떻게 돼?

그림자가 없으면 물체가 공중에 떠 있는 것처럼 보여요!

비유: 사진 vs 증명사진

증명사진처럼 조명이 고른 사진을 보면 얼굴이 평면처럼 보이죠?

반면 자연광 아래 사진은 코 그림자, 턱 그림자 덕분에 입체감이 살아나요.

게임도 마찬가지! 그림자가 있어야 캐릭터가 바닥에 "서 있다"고 느껴집니다.

그림자의 역할: ┌─────────────────────────────────────────────────────────────┐ │ │ │ [그림자 없음] [그림자 있음] │ │ │ │ 🧍 🧍 │ │ ▓▓▓▓▓ ← 그림자 │ │ ═══════════════ ═══════════════ │ │ │ │ "떠 있는 것 같아..." "바닥에 서 있구나!" │ │ │ │ 그림자가 제공하는 정보: │ │ ✓ 공간감 (바닥과의 거리) │ │ ✓ 입체감 (3D 형태 인식) │ │ ✓ 시간대 (그림자 길이 = 태양 높이) │ │ ✓ 광원 방향 (어디서 빛이 오는지) │ │ │ └─────────────────────────────────────────────────────────────┘
그림자를 실시간으로 그리는 게 어려워?

네, 아주 어렵습니다. 현실에서 그림자는 빛이 물체에 막혀서 생기는 건데...

컴퓨터는 "이 점에 빛이 닿는가?"를 수십억 번 계산해야 해요.

레이트레이싱 vs 래스터라이징
• 레이트레이싱: 빛을 진짜로 쏴서 추적 → 정확하지만 느림
• 래스터라이징: 속임수로 그림자 흉내 → 빠르지만 트릭 필요

대부분의 게임은 Shadow Map이라는 트릭을 써요!

Part 2. Shadow Map이 뭐야?

Shadow Map이 뭔지 쉽게 설명해줘

비유: CCTV 카메라

태양 위치에 CCTV 카메라를 설치했다고 상상해보세요.

CCTV가 찍는 건 색상이 아니라 "얼마나 가까이 있는지" (깊이)예요.

CCTV가 못 본 곳 = 뭔가에 가려진 곳 = 그림자!

Shadow Map 원리 (2단계): ┌─────────────────────────────────────────────────────────────┐ │ │ │ [1단계] 태양 시점에서 "깊이 지도" 만들기 │ │ │ │ ☀️ 태양 (= CCTV 위치) │ │ │ │ │ │ "내가 보이는 것들의 거리를 기록할게" │ │ ▼ │ │ ┌─────────────────┐ │ │ │ Shadow Map │ 각 픽셀 = 가장 가까운 물체 거리 │ │ │ (깊이 텍스처) │ 예: (100, 50) 픽셀 = 거리 25m │ │ │ 2048 x 2048 │ │ │ └─────────────────┘ │ │ │ │ [2단계] 실제 렌더링할 때 "비교" │ │ │ │ 👁️ 카메라 │ │ │ │ │ │ 픽셀 A를 그리려는데... │ │ ▼ │ │ 픽셀 A의 태양까지 거리 = 30m │ │ Shadow Map에 기록된 값 = 25m │ │ │ │ 30m > 25m → "앞에 뭔가 있다!" = 그림자! │ │ │ └─────────────────────────────────────────────────────────────┘
구체적으로 어떻게 비교해?
1
픽셀의 월드 좌표를 구한다 (예: x=10, y=5, z=20)
↓
2
태양 시점 좌표로 변환한다 (Light View-Projection)
↓
3
변환된 좌표로 Shadow Map 텍스처를 샘플링
↓
4
내 깊이 vs Shadow Map 값 비교 → 그림자 여부 결정
// Shadow Map 판정 기본 코드 float IsInShadow(float3 worldPos) { // 1. 월드 좌표 → 태양 시점 좌표로 변환 float4 lightSpacePos = mul(float4(worldPos, 1.0), LightViewProjection); // 2. NDC 좌표로 변환 (-1 ~ 1) float3 projCoords = lightSpacePos.xyz / lightSpacePos.w; // 3. 텍스처 좌표로 변환 (0 ~ 1) float2 shadowUV = projCoords.xy * 0.5 + 0.5; shadowUV.y = 1.0 - shadowUV.y; // Y 뒤집기 // 4. Shadow Map에서 "기록된 깊이" 읽기 float shadowMapDepth = ShadowMap.Sample(sampler, shadowUV).r; // 5. 현재 픽셀의 깊이 (태양 기준) float currentDepth = projCoords.z; // 6. 비교: 내가 더 멀면 = 앞에 뭔가 있음 = 그림자! return (currentDepth > shadowMapDepth) ? 0.3 : 1.0; }

Part 3. 근데 그림자가 왜 계단처럼 보여?

그림자 경계가 울퉁불퉁해! 왜 그래?

해상도 한계 때문이에요!

비유: 신문 확대 vs 포스터 확대

신문 사진을 돋보기로 보면? → 점(도트)이 보여요

Shadow Map도 마찬가지! 멀리서는 괜찮은데, 가까이 보면 픽셀이 드러나요.

문제는... 가까운 곳과 먼 곳을 같은 해상도로 커버하려니까 생기는 거예요.

계단 현상 (Shadow Aliasing) 원인: ┌─────────────────────────────────────────────────────────────┐ │ │ │ 하나의 Shadow Map이 커버하는 영역: │ │ │ │ 👁️ 카메라 │ │ * │ │ /|\ │ │ / | \ │ │ / | \ │ │ / | \ │ │ [가까움] [중간] [멀리] │ │ │ │ Shadow Map (2048 x 2048): │ │ ┌────────────────────────────────────────┐ │ │ │▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│ │ │ │▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│ │ │ └────────────────────────────────────────┘ │ │ │ │ 가까운 곳: 1픽셀 = 5cm x 5cm ✅ 정밀해! │ │ 먼 곳: 1픽셀 = 5m x 5m ❌ 계단 현상! │ │ │ │ → 같은 해상도로 넓은 범위를 커버하면 │ │ 멀리 있는 것도, 가까이 있는 것도 똑같이 나눠 가짐 │ │ = 가까운 곳은 충분, 먼 곳은 부족 │ │ │ └─────────────────────────────────────────────────────────────┘
그럼 해상도를 엄청 높이면 되지 않아?

좋은 생각이지만... 비용이 기하급수적으로 증가해요!

해상도 메모리 렌더링 비용 품질
1024 x 1024 4 MB 1x 거침
2048 x 2048 16 MB 4x 보통
4096 x 4096 64 MB 16x 양호
8192 x 8192 256 MB 64x 좋음

8K로 해도 먼 곳은 여전히 거칠어요. 근본적인 해결책이 필요합니다!

거리별로 여러 개의 Shadow Map을 만든다!

비유: 줌 렌즈가 여러 개 달린 카메라

하나의 카메라로 운동장 전체를 찍으면? → 선수 얼굴이 안 보여요

그래서 방송에서는 여러 대의 카메라를 씁니다:

  • 📷 1번 카메라: 클로즈업 (선수 얼굴)
  • 📷 2번 카메라: 중거리 (몇 명 묶음)
  • 📷 3번 카메라: 전체샷 (운동장 전체)

CSM도 마찬가지! 가까운 곳은 고해상도, 먼 곳은 저해상도로 나눠서!

CSM의 핵심 아이디어: ┌─────────────────────────────────────────────────────────────┐ │ │ │ [기존] 하나의 Shadow Map │ │ │ │ ┌───────────────────────────────┐ │ │ │ │ │ │ │ 2048 x 2048 │ │ │ │ (전체를 한 장으로) │ │ │ │ │ │ │ └───────────────────────────────┘ │ │ │ │ [CSM] 거리별 여러 Shadow Map │ │ │ │ 👁️ 카메라 시점에서 본 거리 분할: │ │ │ │ ├── 0~10m ──┼── 10~30m ──┼── 30~100m ──┼── 100~500m ──┤ │ │ │ │ Cascade 0 Cascade 1 Cascade 2 Cascade 3 │ │ (가까움) (중간) (멀리) (아주 멀리) │ │ ┌───────┐ ┌───────┐ ┌───────┐ ┌───────┐ │ │ │ 1024 │ │ 1024 │ │ 1024 │ │ 1024 │ │ │ │ │ │ │ │ │ │ │ │ │ └───────┘ └───────┘ └───────┘ └───────┘ │ │ │ │ 10m를 20m를 70m를 400m를 │ │ 1024픽셀로 1024픽셀로 1024픽셀로 1024픽셀로 │ │ = 1cm/픽셀 = 2cm/픽셀 = 7cm/픽셀 = 40cm/픽셀 │ │ │ │ 가까운 곳일수록 정밀! │ │ │ └─────────────────────────────────────────────────────────────┘
어떻게 나누는 게 좋아? 균등하게?

아뇨! 로그 분할이 더 효과적이에요.

사람 눈은 가까운 곳의 품질 차이에 더 민감하거든요.

분할 방식 비교: ┌─────────────────────────────────────────────────────────────┐ │ │ │ [선형 분할] 균등하게 나눔 │ │ │ │ 0m ──── 25m ──── 50m ──── 75m ──── 100m │ │ C0 C1 C2 C3 │ │ │ │ 문제: 가까운 곳(C0)이 25m나 커버 → 여전히 거침 │ │ │ │ [로그 분할] 가까울수록 촘촘하게 │ │ │ │ 0m ─ 5m ─── 15m ────── 40m ─────────── 100m │ │ C0 C1 C2 C3 │ │ │ │ 장점: 가까운 곳(C0)이 5m만 커버 → 정밀! │ │ 먼 곳(C3)은 어차피 눈에 덜 띄니까 괜찮음 │ │ │ └─────────────────────────────────────────────────────────────┘
// 캐스케이드 분할 거리 계산 void CalculateCascadeSplits( float nearZ, // 카메라 near (예: 0.1m) float farZ, // 카메라 far (예: 500m) float* splits, // 결과 배열 int cascadeCount // 캐스케이드 개수 (보통 4) ) { float lambda = 0.5f; // 선형/로그 혼합 비율 for (int i = 0; i < cascadeCount; i++) { float p = (float)(i + 1) / cascadeCount; // 로그 분할: 가까울수록 촘촘 float logSplit = nearZ * pow(farZ / nearZ, p); // 선형 분할: 균등 float linearSplit = nearZ + (farZ - nearZ) * p; // 둘을 섞음 (lambda로 조절) splits[i] = lambda * logSplit + (1.0f - lambda) * linearSplit; } } // 예시 결과 (nearZ=0.1, farZ=500, lambda=0.5): // splits[0] = 3.5m (Cascade 0: 0~3.5m) // splits[1] = 17.5m (Cascade 1: 3.5~17.5m) // splits[2] = 75m (Cascade 2: 17.5~75m) // splits[3] = 500m (Cascade 3: 75~500m)

Part 5. CSM 실제로 구현하기

전체 렌더링 흐름이 어떻게 돼?

크게 3단계로 나뉩니다:

1
준비: 각 캐스케이드의 Light Matrix 계산
↓
2
Shadow Pass: 4번 렌더링해서 4개의 Shadow Map 생성
↓
3
Main Pass: 픽셀 깊이에 따라 적절한 캐스케이드 선택
CSM 렌더링 파이프라인: ┌─────────────────────────────────────────────────────────────┐ │ │ │ [1단계] 각 캐스케이드별 Light Matrix 계산 │ │ │ │ for (int i = 0; i < 4; i++) { │ │ // 해당 캐스케이드가 커버할 프러스텀 영역 계산 │ │ // → 그 영역을 감싸는 직교 투영 행렬 생성 │ │ lightMatrix[i] = CalculateLightMatrix(i); │ │ } │ │ │ │ [2단계] Shadow Map 생성 (4번 렌더링) │ │ │ │ for (int i = 0; i < 4; i++) { │ │ SetRenderTarget(shadowMapArray[i]); // i번째 맵 │ │ SetViewProjection(lightMatrix[i]); // 광원 시점 │ │ RenderScene(DEPTH_ONLY); // 깊이만! │ │ } │ │ │ │ 결과: │ │ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ │ │ │ C0 │ │ C1 │ │ C2 │ │ C3 │ ← Texture2DArray │ │ └─────┘ └─────┘ └─────┘ └─────┘ │ │ │ │ [3단계] 실제 씬 렌더링 │ │ │ │ for each pixel: │ │ viewDepth = 카메라에서 이 픽셀까지 거리 │ │ cascadeIndex = 어떤 캐스케이드를 쓸지 결정 │ │ shadow = SampleShadowMap(cascadeIndex) │ │ finalColor = baseColor * shadow │ │ │ └─────────────────────────────────────────────────────────────┘
픽셀 셰이더에서 어떻게 캐스케이드를 선택해?

뷰 공간 깊이를 기준으로 선택합니다:

// 상수 버퍼: CPU에서 설정 cbuffer CascadeBuffer { matrix LightViewProj[4]; // 각 캐스케이드의 광원 행렬 float4 CascadeSplits; // 분할 거리 (x=C0끝, y=C1끝, ...) }; Texture2DArray ShadowMapArray; // 4개를 배열 텍스처로 float CalculateShadow(float3 worldPos, float viewDepth) { // 1. 어떤 캐스케이드를 사용할지 결정 int cascadeIndex = 3; // 기본값: 가장 먼 것 if (viewDepth < CascadeSplits.x) cascadeIndex = 0; else if (viewDepth < CascadeSplits.y) cascadeIndex = 1; else if (viewDepth < CascadeSplits.z) cascadeIndex = 2; // 2. 해당 캐스케이드의 Shadow Map 좌표 계산 float4 shadowCoord = mul(float4(worldPos, 1), LightViewProj[cascadeIndex]); shadowCoord.xyz /= shadowCoord.w; // 원근 나눔 // [-1,1] → [0,1] 변환 (텍스처 좌표) shadowCoord.xy = shadowCoord.xy * 0.5 + 0.5; shadowCoord.y = 1.0 - shadowCoord.y; // Y 뒤집기 // 3. Shadow Map 샘플링 float shadowMapDepth = ShadowMapArray.Sample( sampler, float3(shadowCoord.xy, cascadeIndex) // z = 배열 인덱스 ).r; // 4. 그림자 판정 float bias = 0.001 * (cascadeIndex + 1); // 먼 캐스케이드는 더 큰 bias return (shadowCoord.z - bias > shadowMapDepth) ? 0.3 : 1.0; }

Part 6. 그림자 품질 문제 해결하기

Shadow Acne가 뭐야? 표면에 줄무늬가 생겨!

자기 자신에게 그림자가 지는 현상이에요.

비유: 울퉁불퉁한 측정 도구

자로 물체 거리를 재는데, 자 눈금이 너무 굵어요.

1cm 단위로만 잴 수 있는데, 물체가 5.3cm에 있으면?

자는 "5cm!"라고 하고, 실제는 5.3cm... 0.3cm 차이 때문에 그림자?!

Shadow Acne 원인과 해결: ┌─────────────────────────────────────────────────────────────┐ │ │ │ [문제] Shadow Acne (여드름 그림자) │ │ │ │ ☀️ 광원 │ │ │ │ │ │ Shadow Map 픽셀 경계 │ │ │ │ │ │ ▼ ▼ │ │ ───────┬───────┬─────── ← 표면 │ │ │ │ │ │ 5.0cm │ 5.0cm │ 5.0cm ← Shadow Map에 기록된 값 │ │ │ │ │ │ 실제 거리: 5.0 5.1 5.2 5.3 5.4 cm │ │ ▲ │ │ │ │ │ 5.1cm > 5.0cm → "그림자다!" │ │ 하지만 실제로는 자기 자신이잖아! │ │ │ │ [해결] Depth Bias 추가 │ │ │ │ currentDepth - bias > shadowMapDepth │ │ ^^^^ │ │ 작은 오차를 무시하도록! │ │ │ │ 5.1cm - 0.2cm = 4.9cm │ │ 4.9cm < 5.0cm → "그림자 아님!" ✅ │ │ │ └─────────────────────────────────────────────────────────────┘
Peter Panning은 뭐야?

Bias를 너무 크게 주면 그림자가 물체에서 떨어져 보이는 현상!

피터팬처럼 공중에 뜬 것 같다고 해서 Peter Panning이에요.

Peter Panning 현상: ┌─────────────────────────────────────────────────────────────┐ │ │ │ [정상] [Peter Panning] │ │ │ │ ██ ██ │ │ ██ ██ │ │ ▓▓▓▓ ← 그림자 (gap) │ │ ──────────────── ────▓▓▓▓──────── │ │ ↑ │ │ 그림자가 떨어져 있음! │ │ │ │ 원인: Bias가 너무 큼 │ │ currentDepth - (큰 bias) → 그림자 시작점이 밀림 │ │ │ │ 해결: Slope Scale Bias (기울기 기반 동적 bias) │ │ │ │ 표면이 광원을 향하면 → bias 작게 │ │ 표면이 비스듬하면 → bias 크게 │ │ │ └─────────────────────────────────────────────────────────────┘
// Slope Scale Bias: 표면 기울기에 따른 동적 bias float CalculateBias(float3 normal, float3 lightDir) { // 표면이 광원을 얼마나 향하는지 (0~1) float cosAngle = saturate(dot(normal, lightDir)); // 기울기 계산 float sinAngle = sqrt(1.0 - cosAngle * cosAngle); float tanAngle = sinAngle / max(cosAngle, 0.0001); float baseBias = 0.0005; // 기본 bias float slopeBias = 0.001; // 기울기 비례 bias // 비스듬할수록 bias 증가 return baseBias + slopeBias * tanAngle; }
그림자 경계가 딱딱해 보여. 부드럽게 만들려면?

PCF (Percentage Closer Filtering)를 사용하세요!

비유: 투표로 결정하기

경계에 있는 픽셀이 "나 그림자야? 아니야?" 혼란스러워요.

그래서 주변 9명에게 투표를 받아요:

  • "그림자!" 4표, "밝음!" 5표 → 44% 그림자

이렇게 평균을 내면 경계가 부드러워져요!

// PCF 3x3 샘플링 float PCF_Shadow(float3 shadowCoord, int cascadeIndex) { float shadow = 0.0; float2 texelSize = 1.0 / float2(1024, 1024); // Shadow Map 크기 // 3x3 = 9개 샘플 for (int x = -1; x <= 1; x++) { for (int y = -1; y <= 1; y++) { float2 offset = float2(x, y) * texelSize; float depth = ShadowMapArray.Sample( sampler, float3(shadowCoord.xy + offset, cascadeIndex) ).r; // 그림자면 0, 아니면 1 shadow += (shadowCoord.z > depth) ? 0.0 : 1.0; } } return shadow / 9.0; // 평균 } // 더 자연스러운 Poisson Disk 샘플링 static const float2 poissonDisk[16] = { float2(-0.94, -0.30), float2(0.94, -0.30), float2(-0.40, -0.90), float2(0.40, -0.90), // ... 랜덤하게 분포된 16개 점 }; float PoissonPCF(float3 shadowCoord, int cascadeIndex) { float shadow = 0.0; float radius = 2.0 / 1024.0; // 샘플 반경 for (int i = 0; i < 16; i++) { float2 offset = poissonDisk[i] * radius; float depth = ShadowMapArray.Sample( sampler, float3(shadowCoord.xy + offset, cascadeIndex) ).r; shadow += (shadowCoord.z > depth) ? 0.0 : 1.0; } return shadow / 16.0; }

Part 7. 성능 최적화와 실전 팁

캐스케이드 경계에서 그림자가 튀어! 어떻게 해?

캐스케이드 블렌딩으로 부드럽게 전환하세요!

// 캐스케이드 경계에서 블렌딩 float CalculateShadowWithBlend(float3 worldPos, float viewDepth) { int cascadeIndex = GetCascadeIndex(viewDepth); float shadow = SampleShadowMap(worldPos, cascadeIndex); // 경계 근처인지 확인 (10% 영역) float blendRegion = CascadeSplits[cascadeIndex] * 0.1; float distToEdge = CascadeSplits[cascadeIndex] - viewDepth; if (distToEdge < blendRegion && cascadeIndex < 3) { // 다음 캐스케이드의 그림자도 샘플 float nextShadow = SampleShadowMap(worldPos, cascadeIndex + 1); // 부드럽게 섞기 float blendFactor = distToEdge / blendRegion; shadow = lerp(nextShadow, shadow, blendFactor); } return shadow; } // 디버그: 캐스케이드별 색상 표시 float3 DebugCascadeColor(int cascadeIndex) { const float3 colors[4] = { float3(1, 0, 0), // 빨강 - C0 (가까움) float3(0, 1, 0), // 초록 - C1 float3(0, 0, 1), // 파랑 - C2 float3(1, 1, 0) // 노랑 - C3 (멀리) }; return colors[cascadeIndex]; }

✅ 핵심 답변 포인트

1. 왜 필요한가?
"단일 Shadow Map은 해상도 한계로 먼 곳과 가까운 곳의 품질 차이가 심합니다."

2. 어떻게 해결하는가?
"거리별로 여러 Shadow Map을 두고, 가까운 곳에 더 많은 해상도를 할당합니다."

3. 품질 이슈는?
"Shadow Acne는 Depth Bias로, 캐스케이드 경계는 Blending으로 해결합니다."

4. 성능 최적화는?
"정적 오브젝트 캐싱, Shadow LOD, 프러스텀 컬링을 적용합니다."

핵심 정리

  • Shadow Map = 광원 시점에서 깊이를 텍스처에 저장 → 비교로 그림자 판정
  • 문제 = 하나의 맵으로 넓은 범위 커버 시 먼 곳 품질 저하 (계단 현상)
  • CSM 해결책 = 거리별 여러 Shadow Map → 가까운 곳에 고해상도
  • 로그 분할 = 가까울수록 촘촘하게 나눔 (사람 눈은 가까운 곳에 민감)
  • Shadow Acne = Depth Bias로 자기 그림자 방지
  • Peter Panning = Slope Scale Bias로 그림자 분리 방지
  • PCF = 주변 샘플 평균으로 부드러운 그림자 경계
  • 성능 팁 = Shadow LOD, 정적 캐싱, 먼 캐스케이드 저해상도
