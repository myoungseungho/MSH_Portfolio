네트워크 버짓

대규모 전쟁에서 100명이 동시에 안 끊기는 법

Part 1. 네트워크 버짓이란?

네트워크 버짓이 뭐야?

네트워크 버짓(Network Budget)은 매 틱마다 사용할 수 있는 대역폭의 상한선입니다:

네트워크 버짓 개념: +------------------------------------------------------------------+ | | | 플레이어 A의 네트워크 상황: | | | | 다운로드 속도: 50 Mbps (이론상) | | 실제 가용: ~30 Mbps (다른 앱, 변동) | | 게임 할당: 5 Mbps (다른 기기와 공유 고려) | | | | 초당 버짓: 5 Mbps = 625 KB/s | | 틱당 버짓 (20 Hz): 625 KB / 20 = 31.25 KB/tick | | | | +------------------------------------------------------------+ | | | 이 플레이어에게 틱당 31.25KB 이상 보내면 안 됨! | | | | 초과하면 -> 패킷 지연 -> 렉 -> 끊김 | | | +------------------------------------------------------------+ | | | | 대규모 전쟁 상황 (100명): | | - 100명 상태 패킷: 100 x 50 bytes = 5,000 bytes = 5 KB | | - 100명 공격 이벤트: 100 x 30 bytes = 3,000 bytes = 3 KB | | - 이펙트, 데미지 숫자 등: ~10 KB | | - 총: ~18 KB/tick | | | | 버짓 31 KB > 필요량 18 KB -> OK! | | 하지만 200명이면? 36 KB > 31 KB -> 터짐! | | | +------------------------------------------------------------------+
모바일이나 느린 네트워크는?

플레이어마다 개인별 버짓을 다르게 설정해야 합니다:

플레이어별 네트워크 프로파일: +------------------------------------------------------------------+ | | | Profile 버짓/틱 대상 | | ----------------------------------------------------------------| | PC (유선) 50 KB 광랜/기가인터넷 | | PC (WiFi) 30 KB 일반 WiFi | | 콘솔 40 KB PS5/Xbox (대부분 유선) | | 모바일 (WiFi) 20 KB 스마트폰 WiFi | | 모바일 (LTE) 10 KB 4G LTE (불안정) | | 모바일 (3G) 5 KB 3G/약한 신호 | | | | 자동 감지 방법: | | +------------------------------------------------------------+ | | | 1. 연결 시 RTT(왕복지연) 측정 | | | | 2. 패킷 로스율 측정 | | | | 3. 점진적으로 버짓 조절 (TCP Congestion Control 유사) | | | +------------------------------------------------------------+ | | | +------------------------------------------------------------------+

Part 2. 우선순위 기반 패킷 전송

버짓이 부족하면 어떤 패킷을 먼저 보내?

우선순위 큐로 중요한 패킷을 먼저 전송합니다:

우선순위 기반 전송: +------------------------------------------------------------------+ | | | Priority 0 (Critical) - 반드시 전송, 버짓 소모 없음 | | +------------------------------------------------------------+ | | | - 내 캐릭터 상태 | | | | - 내가 받은 데미지 | | | | - 게임 결과 (승패, 보상) | | | | - 연결 끊김 알림 | | | +------------------------------------------------------------+ | | | | Priority 1 (High) - 버짓의 50% 할당 | | +------------------------------------------------------------+ | | | - 적 위치 (PvP에서 중요) | | | | - 파티원 상태 | | | | - 보스 패턴/스킬 | | | | - 중요 게임 이벤트 | | | +------------------------------------------------------------+ | | | | Priority 2 (Normal) - 버짓의 30% 할당 | | +------------------------------------------------------------+ | | | - 일반 NPC/몬스터 이동 | | | | - 다른 플레이어 스킬 이펙트 | | | | - 채팅 메시지 | | | +------------------------------------------------------------+ | | | | Priority 3 (Low) - 버짓의 20% 할당, 드롭 가능 | | +------------------------------------------------------------+ | | | - 배경 NPC | | | | - 환경 이펙트 | | | | - 멀리 있는 플레이어 | | | +------------------------------------------------------------+ | | | +------------------------------------------------------------------+
// 우선순위 기반 네트워크 버짓 시스템 class NetworkBudgetManager { private: struct QueuedPacket { int priority; // 0 = 최고, 3 = 최저 int64_t timestamp; // 큐잉 시간 (오래된 것 우선) std::vector data; bool canDrop; // 드롭 가능 여부 // 우선순위 큐 정렬용 bool operator<(const QueuedPacket& other) const { if (priority != other.priority) return priority > other.priority; // 낮은 값이 높은 우선순위 return timestamp > other.timestamp; // 오래된 것 먼저 } }; std::priority_queue m_sendQueue; int m_budgetPerTick; // 바이트 단위 int m_remainingBudget; public: void SetPlayerBudget(int bytesPerTick) { m_budgetPerTick = bytesPerTick; } void QueuePacket(const void* data, int size, int priority, bool canDrop = true) { // Critical은 무조건 즉시 전송 if (priority == 0) { SendImmediate(data, size); return; } QueuedPacket pkt; pkt.priority = priority; pkt.timestamp = GetCurrentTimeMs(); pkt.data.assign((uint8_t*)data, (uint8_t*)data + size); pkt.canDrop = canDrop; m_sendQueue.push(pkt); } void FlushQueue() { m_remainingBudget = m_budgetPerTick; while (!m_sendQueue.empty() && m_remainingBudget > 0) { auto pkt = m_sendQueue.top(); m_sendQueue.pop(); // 버짓 체크 if (pkt.data.size() > m_remainingBudget) { if (pkt.canDrop) { // 드롭 가능하면 버림 continue; } else { // 드롭 불가면 다음 틱으로 미룸 m_sendQueue.push(pkt); break; } } // 전송 SendPacket(pkt.data.data(), pkt.data.size()); m_remainingBudget -= pkt.data.size(); } // 오래된 패킷 정리 (500ms 이상) CleanupStalePackets(500); } };

Part 3. 동적 LOD (Level of Detail)

멀리 있는 플레이어는 덜 자세하게 보내도 되지 않아?

네트워크 LOD로 거리에 따라 업데이트 빈도와 정밀도를 조절합니다:

네트워크 LOD 시스템: +------------------------------------------------------------------+ | | | [ME] 기준 거리별 동기화 품질: | | | | 0-10m (LOD 0 - Full Detail): | | +------------------------------------------------------------+ | | | 업데이트: 매 틱 (20Hz) | | | | 내용: 위치, 회전, HP, 버프, 스킬, 애니메이션, 장비 | | | | 정밀도: float (4 bytes) | | | | 예상 크기: ~80 bytes/player | | | +------------------------------------------------------------+ | | | | 10-30m (LOD 1 - Reduced): | | +------------------------------------------------------------+ | | | 업데이트: 5 틱마다 (4Hz) | | | | 내용: 위치, 회전, HP, 주요 스킬 | | | | 정밀도: half (2 bytes) | | | | 예상 크기: ~40 bytes/player | | | +------------------------------------------------------------+ | | | | 30-50m (LOD 2 - Minimal): | | +------------------------------------------------------------+ | | | 업데이트: 10 틱마다 (2Hz) | | | | 내용: 위치만 | | | | 정밀도: int16 (2 bytes) | | | | 예상 크기: ~12 bytes/player | | | +------------------------------------------------------------+ | | | | 50m+ (LOD 3 - Icon Only): | | +------------------------------------------------------------+ | | | 업데이트: 20 틱마다 (1Hz) | | | | 내용: 존재 여부 + 대략적 위치 | | | | 정밀도: 셀 ID (2 bytes) | | | | 예상 크기: ~4 bytes/player | | | +------------------------------------------------------------+ | | | | 대규모 전쟁 100명 기준: | | - LOD 0 (10명): 80 x 10 = 800 bytes | | - LOD 1 (30명): 40 x 30 / 5 = 240 bytes (평균) | | - LOD 2 (40명): 12 x 40 / 10 = 48 bytes (평균) | | - LOD 3 (20명): 4 x 20 / 20 = 4 bytes (평균) | | - 총: ~1,092 bytes/tick (vs 풀 동기화 8,000 bytes) | | | +------------------------------------------------------------------+
// 동적 LOD 시스템 class NetworkLODSystem { private: struct LODConfig { float maxDistance; int updateInterval; // 틱 단위 int dataFlags; // 어떤 데이터를 보낼지 int positionPrecision; // 비트 수 }; std::vector m_lodLevels = { { 10.0f, 1, LOD_ALL, 32 }, // 풀 데이터 { 30.0f, 5, LOD_ESSENTIAL, 16 }, // 필수만 { 50.0f, 10, LOD_POSITION_ONLY, 12 }, // 위치만 { FLT_MAX, 20, LOD_ICON, 8 } // 아이콘 }; enum LODFlags { LOD_POSITION = 1 << 0, LOD_ROTATION = 1 << 1, LOD_HP = 1 << 2, LOD_BUFFS = 1 << 3, LOD_SKILLS = 1 << 4, LOD_ANIMATION = 1 << 5, LOD_EQUIPMENT = 1 << 6, LOD_ICON = 0, LOD_POSITION_ONLY = LOD_POSITION, LOD_ESSENTIAL = LOD_POSITION | LOD_ROTATION | LOD_HP | LOD_SKILLS, LOD_ALL = 0xFF }; public: void BroadcastPlayerState(Player* source) { auto& observers = GetPlayersInRange(source, 100.0f); for (Player* observer : observers) { float distance = CalculateDistance(source, observer); const LODConfig& lod = GetLODForDistance(distance); // 업데이트 간격 체크 if (!ShouldUpdate(source, observer, lod.updateInterval)) { continue; } // LOD에 맞는 패킷 생성 auto packet = CreateStatePacket(source, lod.dataFlags, lod.positionPrecision); // 버짓 시스템을 통해 큐잉 int priority = (distance < 30.0f) ? 1 : 2; observer->GetBudgetManager()->QueuePacket( packet.data(), packet.size(), priority, true ); } } PacketBuffer CreateStatePacket(Player* source, int flags, int precision) { PacketBuffer buffer; buffer.WriteInt(source->GetId()); if (flags & LOD_POSITION) { // 정밀도에 따라 다르게 인코딩 if (precision == 32) { buffer.WriteFloat(source->x); buffer.WriteFloat(source->y); buffer.WriteFloat(source->z); } else if (precision == 16) { buffer.WriteHalf(source->x); buffer.WriteHalf(source->y); buffer.WriteHalf(source->z); } else { // 양자화 buffer.WriteQuantized(source->x, precision); buffer.WriteQuantized(source->y, precision); } } // ... 다른 플래그들 처리 return buffer; } };

Part 4. 이벤트 병합과 샘플링

100명이 동시에 공격하면 100개 패킷을 다 보내?

병합과 샘플링으로 패킷 수를 줄입니다:

이벤트 병합 전략: +------------------------------------------------------------------+ | | | 상황: 100명이 보스를 동시에 공격 | | | | 나이브 방식: | | 100개 공격 이벤트 x 100명 전송 = 10,000 패킷 | | | | 병합 방식: | | +------------------------------------------------------------+ | | | 1개 배치 패킷에 100개 공격 정보 담기 | | | | [배치 헤더: 100개] [공격1] [공격2] ... [공격100] | | | | 100명에게 전송 = 100 패킷 | | | +------------------------------------------------------------+ | | | | 샘플링 방식 (멀리 있는 관찰자): | | +------------------------------------------------------------+ | | | 100개 중 랜덤 20개만 선택 | | | | [배치 헤더: 20개] [공격1] ... [공격20] | | | | 클라이언트: 나머지 80개는 로컬에서 생성 | | | +------------------------------------------------------------+ | | | | 데미지 숫자 병합: | | +------------------------------------------------------------+ | | | 100개 개별 데미지 -> 1초 동안 합산 -> 1개 DPS 패킷 | | | | "보스가 1초간 50,000 데미지 받음" | | | | 클라이언트: 랜덤 위치에 데미지 숫자 뿌리기 | | | +------------------------------------------------------------+ | | | +------------------------------------------------------------------+
// 이벤트 병합 시스템 class EventAggregator { private: struct AggregatedDamage { int targetId; int totalDamage; int hitCount; std::vector attackerIds; // 샘플링용 }; std::map m_damageAccumulator; int64_t m_lastFlushTime = 0; const int FLUSH_INTERVAL_MS = 100; // 100ms마다 플러시 public: void RecordDamage(int attackerId, int targetId, int damage) { auto& agg = m_damageAccumulator[targetId]; agg.targetId = targetId; agg.totalDamage += damage; agg.hitCount++; // 공격자 샘플 (최대 10명만 기록) if (agg.attackerIds.size() < 10) { agg.attackerIds.push_back(attackerId); } else if (rand() % agg.hitCount == 0) { // 저수지 샘플링으로 대체 agg.attackerIds[rand() % 10] = attackerId; } } void Flush() { for (auto& [targetId, agg] : m_damageAccumulator) { // 배치 패킷 생성 PacketDamageBatch pkt; pkt.targetId = agg.targetId; pkt.totalDamage = agg.totalDamage; pkt.hitCount = agg.hitCount; pkt.sampleAttackers = agg.attackerIds; // LOD에 따라 전송 auto& observers = GetObservers(targetId); for (auto* observer : observers) { float distance = GetDistance(observer, targetId); if (distance < 20.0f) { // 가까우면 풀 정보 observer->Send(pkt); } else { // 멀면 요약만 PacketDamageSummary summary; summary.targetId = agg.targetId; summary.totalDamage = agg.totalDamage; observer->Send(summary); } } } m_damageAccumulator.clear(); m_lastFlushTime = GetCurrentTimeMs(); } };

Part 5. 적응형 품질 시스템

네트워크가 나빠지면 자동으로 조절해?

RTT와 패킷 로스를 모니터링하여 실시간으로 품질을 조절합니다:

적응형 품질 조절: +------------------------------------------------------------------+ | | | 네트워크 상태 모니터링: | | | | RTT (Round Trip Time): | | - 좋음: < 50ms | | - 보통: 50-100ms | | - 나쁨: 100-200ms | | - 심각: > 200ms | | | | 패킷 로스: | | - 좋음: < 1% | | - 보통: 1-3% | | - 나쁨: 3-10% | | - 심각: > 10% | | | | 품질 레벨 자동 조절: | | +------------------------------------------------------------+ | | | Level 4 (최상): 버짓 50KB, LOD 풀, 20Hz | | | | Level 3 (상): 버짓 30KB, LOD 풀, 20Hz | | | | Level 2 (중): 버짓 20KB, LOD 줄임, 10Hz | | | | Level 1 (하): 버짓 10KB, LOD 최소, 5Hz | | | | Level 0 (생존): 버짓 5KB, 내 캐릭터만, 2Hz | | | +------------------------------------------------------------+ | | | +------------------------------------------------------------------+
// 적응형 네트워크 품질 시스템 class AdaptiveNetworkQuality { private: enum class QualityLevel { Survival = 0, // 최소 생존 Low = 1, Medium = 2, High = 3, Ultra = 4 }; struct QualityConfig { int budgetPerTick; // bytes int maxLOD; // 0-3 int tickRate; // Hz bool enableEffects; bool enableOtherPlayers; }; std::map m_qualityConfigs = { { QualityLevel::Survival, { 5000, 3, 2, false, false } }, { QualityLevel::Low, { 10000, 2, 5, false, true } }, { QualityLevel::Medium, { 20000, 1, 10, true, true } }, { QualityLevel::High, { 30000, 0, 20, true, true } }, { QualityLevel::Ultra, { 50000, 0, 20, true, true } } }; QualityLevel m_currentQuality = QualityLevel::High; MovingAverage m_rttAverage{20}; // 최근 20개 샘플 MovingAverage m_lossAverage{20}; public: void UpdateNetworkStats(int rttMs, float packetLoss) { m_rttAverage.Add(rttMs); m_lossAverage.Add(packetLoss); // 평균 계산 float avgRtt = m_rttAverage.GetAverage(); float avgLoss = m_lossAverage.GetAverage(); // 품질 레벨 결정 QualityLevel newQuality = DetermineQuality(avgRtt, avgLoss); // 급격한 변화 방지 (히스테리시스) if (newQuality != m_currentQuality) { if (newQuality < m_currentQuality) { // 품질 하락은 즉시 SetQuality(newQuality); } else { // 품질 상승은 천천히 (5초 유지 후) if (m_stableTime > 5000) { SetQuality(newQuality); } } } } QualityLevel DetermineQuality(float rtt, float loss) { // 둘 중 나쁜 쪽 기준 if (rtt > 200 || loss > 10.0f) return QualityLevel::Survival; if (rtt > 150 || loss > 5.0f) return QualityLevel::Low; if (rtt > 100 || loss > 3.0f) return QualityLevel::Medium; if (rtt > 50 || loss > 1.0f) return QualityLevel::High; return QualityLevel::Ultra; } void SetQuality(QualityLevel level) { m_currentQuality = level; auto& config = m_qualityConfigs[level]; m_budgetManager->SetBudget(config.budgetPerTick); m_lodSystem->SetMaxLOD(config.maxLOD); m_tickScheduler->SetTickRate(config.tickRate); // 클라이언트에 알림 NotifyQualityChange(level); } };

Part 6. 실제 대규모 PvP 사례

유명 게임들은 대규모 전투를 어떻게 처리해?
실제 게임 사례: +------------------------------------------------------------------+ | | | WoW (40vs40 전장): | | +------------------------------------------------------------+ | | | - 별도 전장 인스턴스 | | | | - 틱레이트 감소 (20Hz -> 10Hz) | | | | - 아군/적군 LOD 차등 (적은 더 상세히) | | | | - 이펙트 간소화 (옵션으로 "다른 플레이어 이펙트 숨김") | | | +------------------------------------------------------------+ | | | | EVE Online (수천 명 전투): | | +------------------------------------------------------------+ | | | - Time Dilation (게임 속도 자체를 느리게) | | | | - 1000명 이상: 게임 속도 10% | | | | - 우선순위: 내 함선 > 락온 대상 > 아군 > 적군 > 잔해 | | | | - 그리드 LOD: 화면 밖은 아이콘만 | | | +------------------------------------------------------------+ | | | | GW2 (WvW 대규모 공성전): | | +------------------------------------------------------------+ | | | - 플레이어 컬링: 일정 수 이상 렌더링 안 함 | | | | - 네임플레이트 숨김 (많으면) | | | | - 이펙트 자동 간소화 | | | | - 서버 측 우선순위: 성벽 상태 > 공성무기 > 플레이어 | | | +------------------------------------------------------------+ | | | | Lost Ark (레이드/GvG): | | +------------------------------------------------------------+ | | | - 8인 레이드: 풀 동기화 (관리 가능한 인원) | | | | - GvG: AOI + LOD 조합 | | | | - 이펙트 최적화: 중요 스킬만 동기화, 나머지 로컬 생성 | | | +------------------------------------------------------------+ | | | | New World (50vs50 전쟁): | | +------------------------------------------------------------+ | | | - 전쟁 인스턴스 분리 | | | | - 서버 틱레이트 동적 조절 | | | | - 버짓 기반 우선순위 큐 | | | | - "중요 이벤트" 우선 전송 (킬, 거점 점령) | | | +------------------------------------------------------------+ | | | +------------------------------------------------------------------+ 공통 패턴: +------------------------------------------------------------------+ | | | 1. 인스턴스 분리: 대규모 컨텐츠는 별도 서버/인스턴스 | | 2. 동적 품질: 인원/부하에 따라 틱레이트, LOD 자동 조절 | | 3. 우선순위: 내 캐릭터 > 타겟 > 파티 > 적 > 배경 | | 4. 이펙트 간소화: 다른 플레이어 이펙트 숨김 옵션 | | 5. 클라이언트 보조: 서버가 힌트만 주고 클라가 생성 | | | +------------------------------------------------------------------+

핵심 정리

  • 네트워크 버짓 = 틱당 전송 가능한 데이터 상한 (플레이어별 다름)
  • 우선순위 큐로 Critical -> High -> Normal -> Low 순서 전송
  • 네트워크 LOD: 거리에 따라 업데이트 빈도와 정밀도 차등
  • 이벤트 병합/샘플링으로 100개 이벤트 -> 1개 배치 패킷
  • 적응형 품질: RTT/패킷로스 모니터링으로 실시간 조절
  • 대규모 전투는 인스턴스 분리 + Time Dilation + 이펙트 간소화
