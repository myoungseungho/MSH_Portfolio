100명이 동시에 싸우는데 왜 안 터져요?

네트워크 버짓: 대규모 전투의 비밀

Part 1: 문제 상황 - 대규모 전투의 현실

MMO에서 대규모 전투할 때 렉 걸려본 적 있어?

100명 vs 100명 공성전. 게임은 슬라이드쇼가 되고, 스킬 누르면 3초 후에 나가고...

근데 신기한 게 있어. 똑같은 100명인데 어떤 게임은 매끄럽고, 어떤 게임은 터져.

왜 그럴까?

일단 100명이면 데이터가 얼마나 되는데?

계산해보자:

100명 전투에서 보내야 할 데이터 (1틱당): [플레이어 상태] - 위치 (x, y, z): 12 bytes - 회전: 4 bytes - HP/MP: 4 bytes - 버프 상태: 8 bytes - 현재 애니메이션: 4 bytes - 장비 상태: 8 bytes ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ = 40 bytes/플레이어 100명이면: 40 × 100 = 4,000 bytes [이벤트들] - 공격 이벤트: 30 bytes × 50개 = 1,500 bytes - 스킬 이펙트: 20 bytes × 30개 = 600 bytes - 데미지 숫자: 10 bytes × 100개 = 1,000 bytes ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ = 3,100 bytes 총: 4,000 + 3,100 = ~7 KB/틱 20틱 서버면: 7 × 20 = 140 KB/초 = 1.1 Mbps

1.1 Mbps... 요즘 인터넷이면 여유있어 보이지?

그럼 뭐가 문제야?

모든 플레이어가 좋은 인터넷 쓰는 게 아니야.

현실의 플레이어들: ┌─────────────────────────────────────────────────────┐ │ 플레이어 A (PC방 기가인터넷) │ │ 다운: 1,000 Mbps → 여유 충분 │ ├─────────────────────────────────────────────────────┤ │ 플레이어 B (가정용 WiFi) │ │ 다운: 100 Mbps → 근데 가족이 넷플릭스 보는 중... │ │ 실제 가용: 20 Mbps → 아직 괜찮음 │ ├─────────────────────────────────────────────────────┤ │ 플레이어 C (모바일 LTE) │ │ 다운: 20 Mbps → 근데 지하철 이동 중... │ │ 실제 가용: 3 Mbps → 1.1 Mbps 쓰면 터짐! │ ├─────────────────────────────────────────────────────┤ │ 플레이어 D (해외 접속) │ │ 핑: 200ms + 패킷 로스 5% │ │ → 데이터 재전송 필요 → 실제 필요량 2배 │ └─────────────────────────────────────────────────────┘ 문제: 가장 약한 플레이어에 맞춰야 모두가 플레이 가능

Part 2: 해결책의 핵심 - 네트워크 버짓

그래서 어떻게 해결해?

여기서 나온 개념이 네트워크 버짓(Network Budget)이야.

💰 비유: 월급처럼 생각해봐

네가 월급 300만원을 받는다고 해봐.
- 월세: 80만원 (필수)
- 식비: 50만원 (필수)
- 교통비: 20만원 (필수)
- 남은 돈: 150만원 → 여기서 쇼핑, 취미 등

월급 이상 쓰면? → 카드값 밀림 → 신용불량 → 터짐

네트워크도 똑같아!
- 플레이어마다 "이 정도 데이터는 받을 수 있어" = 버짓
- 버짓 이상 보내면? → 패킷 밀림 → 렉 → 끊김
플레이어마다 버짓이 다르다고?

응. 연결 상태 보고 서버가 개인별 버짓을 정해:

플레이어별 네트워크 버짓: ┌──────────────┬────────────┬─────────────────────────┐ │ 연결 상태 │ 버짓/틱 │ 설명 │ ├──────────────┼────────────┼─────────────────────────┤ │ PC 유선 │ 50 KB │ 풀 퀄리티 가능 │ │ PC WiFi │ 30 KB │ 약간 여유 │ │ 콘솔 │ 40 KB │ 대부분 유선 │ │ 모바일 WiFi │ 20 KB │ 불안정 고려 │ │ 모바일 LTE │ 10 KB │ 최소한만 │ │ 약한 연결 │ 5 KB │ 생존 모드 │ └──────────────┴────────────┴─────────────────────────┘ 측정 방법: 1. 연결 시 RTT(왕복 지연) 측정 2. 패킷 로스율 체크 3. 점진적으로 버짓 늘리다가 문제 생기면 줄임
근데 100명 전투에 7KB 필요한데, 버짓 5KB인 사람은?

핵심 질문이야! 여기서 진짜 기술이 나와.

"7KB를 어떻게 5KB 안에 넣을까?" → 우선순위를 정해야 해.

Part 3: 우선순위 - 뭘 먼저 보낼까?

월급 적으면 뭐부터 줄여?

당연히 덜 중요한 것부터지. 월세 안 내면 쫓겨나지만, 커피는 안 마셔도 돼.

네트워크도 똑같아:

패킷 우선순위 시스템: ┌─────────────────────────────────────────────────────┐ │ Priority 0: CRITICAL (무조건 전송, 버짓 무시) │ │ ───────────────────────────────────────────────── │ │ • 내 캐릭터 상태 │ │ • 내가 받은 데미지 (죽었는지 알아야지!) │ │ • 게임 결과 (승패, 보상) │ │ • 연결 끊김 알림 │ │ │ │ → 이거 안 보내면 게임 자체가 안 돼 │ └─────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────┐ │ Priority 1: HIGH (버짓의 50% 할당) │ │ ───────────────────────────────────────────────── │ │ • 적 위치 (PvP에서 안 보이면 어떻게 싸워?) │ │ • 파티원 상태 (힐러는 파티원 HP 봐야지) │ │ • 보스 패턴 (레이드에서 핵심) │ │ • 중요 게임 이벤트 │ └─────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────┐ │ Priority 2: NORMAL (버짓의 30% 할당) │ │ ───────────────────────────────────────────────── │ │ • 일반 NPC/몬스터 이동 │ │ • 다른 플레이어 스킬 이펙트 │ │ • 채팅 메시지 │ └─────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────┐ │ Priority 3: LOW (버짓의 20%, 버리기 가능) │ │ ───────────────────────────────────────────────── │ │ • 배경 NPC │ │ • 환경 이펙트 (나뭇잎 흔들림 같은 거) │ │ • 멀리 있는 플레이어 │ │ │ │ → 버짓 부족하면 과감히 버림 │ └─────────────────────────────────────────────────────┘
그래서 실제로 어떻게 동작해?

예를 들어 버짓 10KB인 플레이어:

버짓 10KB 플레이어의 1틱: [대기열] - Critical: 내 캐릭터 (300 bytes) → 무조건 전송 - High: 적 20명 (800 bytes) - High: 파티원 4명 (200 bytes) - Normal: NPC 30마리 (900 bytes) - Normal: 이펙트 50개 (1,000 bytes) - Low: 먼 플레이어 50명 (500 bytes) [전송 과정] 1. Critical 전송: 300 bytes → 남은 버짓: 9,700 2. High 전송 (버짓 50% = 5,000까지): - 적 20명: 800 bytes ✓ - 파티원: 200 bytes ✓ - 합계: 1,000 bytes → 남은 High 버짓: 4,000 3. Normal 전송 (버짓 30% = 3,000까지): - NPC: 900 bytes ✓ - 이펙트: 1,000 bytes ✓ - 합계: 1,900 bytes ✓ 4. Low 전송 (버짓 20% = 2,000까지): - 먼 플레이어: 500 bytes ✓ [결과] 총 전송: 300 + 1,000 + 1,900 + 500 = 3,700 bytes 버짓 10KB 안에 들어옴! ✓ 근데 만약 적이 50명이면? - High 필요량: 2,000 bytes > 할당량 (버짓 내) - 일부 적은 다음 틱으로 미룸 - 아주 먼 적은 버릴 수도

Part 4: 거리별 차등 - 멀면 대충 보내도 돼

100m 떨어진 플레이어를 1m 옆 플레이어만큼 상세하게 볼 필요 있어?

없지! 어차피 화면에 점으로 보이는데.

이게 네트워크 LOD (Level of Detail)야:

거리별 동기화 품질: 나(●)를 중심으로: 50m+: 아이콘만 ┌────────────────────────────────────────────────┐ │ 30-50m: 위치만 │ │ ┌────────────────────────────────────────┐ │ │ │ 10-30m: 위치+HP+스킬 │ │ │ │ ┌────────────────────────────────┐ │ │ │ │ │ 0-10m: 풀 정보 │ │ │ │ │ │ ● 나 │ │ │ │ │ │ 80 bytes/플레이어 │ │ │ │ │ └────────────────────────────────┘ │ │ │ │ 40 bytes, 4Hz │ │ │ └────────────────────────────────────────┘ │ │ 12 bytes, 2Hz │ └────────────────────────────────────────────────┘ 4 bytes, 1Hz [데이터 절약 효과 - 100명 전투] 풀 동기화: 80 bytes × 100명 = 8,000 bytes/틱 LOD 적용: - 0-10m (10명): 80 × 10 = 800 bytes (매 틱) - 10-30m (30명): 40 × 30 / 5 = 240 bytes (평균) - 30-50m (40명): 12 × 40 / 10 = 48 bytes (평균) - 50m+ (20명): 4 × 20 / 20 = 4 bytes (평균) ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 총: ~1,092 bytes 절약: 8,000 → 1,092 = 87% 절약!
와 그렇게 많이 줄어들어?

응! 그리고 플레이어는 거의 못 느껴.

왜냐면:

  • 멀리 있는 플레이어는 어차피 작게 보임
  • 0.5초에 한 번 업데이트해도 "걔 저기 있구나" 정도만 알면 됨
  • 가까이 오면 자동으로 풀 퀄리티로 전환

Part 5: 이벤트 병합 - 100개를 1개로

100명이 동시에 보스를 때리면 100개 패킷 보내?

그러면 터져. 병합해야 해:

이벤트 병합 전략: [상황] 100명이 보스 동시 공격 ❌ 나이브 방식: 100개 공격 이벤트 × 100명 전송 = 10,000 패킷 ✓ 병합 방식: ┌─────────────────────────────────────────────────┐ │ 1개 배치 패킷에 100개 공격 정보 담기 │ │ │ │ [헤더: 공격 100개] │ │ [공격1: 플레이어ID, 데미지, 스킬ID] │ │ [공격2: ...] │ │ ... │ │ [공격100: ...] │ │ │ │ → 100명에게 전송 = 100 패킷 │ └─────────────────────────────────────────────────┘ ✓ 샘플링 방식 (멀리 있는 사람에게): ┌─────────────────────────────────────────────────┐ │ 100개 중 랜덤 20개만 선택 │ │ │ │ [헤더: 공격 20개 (샘플)] │ │ [공격1] [공격7] [공격15] ... [공격98] │ │ │ │ 클라이언트: "100명이 때리는 중이구나" │ │ → 나머지 80개는 로컬에서 가짜로 생성 │ │ → 어차피 이펙트만 보이면 됨 │ └─────────────────────────────────────────────────┘ ✓ 데미지 숫자 병합: ┌─────────────────────────────────────────────────┐ │ 1초 동안 데미지 합산 → 1개 패킷 │ │ │ │ "보스가 1초간 50,000 데미지 받음" │ │ │ │ 클라이언트: 랜덤 위치에 데미지 숫자 뿌리기 │ │ → 실제와 똑같아 보임! │ └─────────────────────────────────────────────────┘

Part 6: 실제 게임들은 어떻게?

유명한 게임들은 대규모 전투 어떻게 처리해?
실제 게임 사례: ┌─────────────────────────────────────────────────────┐ │ EVE Online (수천 명 전투) │ │ ───────────────────────────────────────────────── │ │ • Time Dilation: 게임 속도 자체를 느리게! │ │ - 1000명 이상 → 게임 속도 10% │ │ - "느려도 공정하게" │ │ • 우선순위: 내 함선 > 락온 대상 > 아군 > 적군 │ │ • 화면 밖은 아이콘만 │ └─────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────┐ │ WoW (40 vs 40 전장) │ │ ───────────────────────────────────────────────── │ │ • 전장은 별도 인스턴스로 분리 │ │ • 틱레이트 낮춤: 20Hz → 10Hz │ │ • 옵션: "다른 플레이어 이펙트 숨김" │ │ • 적은 아군보다 상세하게 (적 위치가 더 중요) │ └─────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────┐ │ Guild Wars 2 (WvW 대규모 공성전) │ │ ───────────────────────────────────────────────── │ │ • 플레이어 컬링: 일정 수 이상은 안 그림 │ │ → 유저 불만 많았음... "적이 안 보여요!" │ │ • 네임플레이트 자동 숨김 │ │ • 이펙트 자동 간소화 │ └─────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────┐ │ Lost Ark (레이드/GvG) │ │ ───────────────────────────────────────────────── │ │ • 8인 레이드: 풀 동기화 (관리 가능한 인원) │ │ • GvG: AOI + LOD 조합 │ │ • 중요 스킬만 동기화, 나머지는 로컬 생성 │ └─────────────────────────────────────────────────────┘ 공통 패턴: ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 1. 인원 제한: 대규모 컨텐츠는 인원 상한 있음 2. 인스턴스 분리: 별도 서버에서 처리 3. 동적 품질: 인원 많으면 자동으로 퀄리티 낮춤 4. 우선순위: 내 캐릭터 > 타겟 > 파티 > 적 > 배경 5. 클라이언트 보조: 서버는 힌트만, 클라가 채움
그럼 완벽한 해결책은 없어?

없어. 항상 트레이드오프가 있어:

  • 정확성 vs 성능: 모든 걸 정확히 보여주면 터짐
  • 공정성 vs 부드러움: Time Dilation은 공정하지만 답답함
  • 비용 vs 퀄리티: 서버 더 좋으면 비용 증가

좋은 게임은 플레이어가 못 느끼는 선에서 최대한 속이는 것.

📌 핵심 정리

  • 네트워크 버짓 = 틱당 보낼 수 있는 데이터 상한 (월급처럼 정해진 한도)
  • 플레이어마다 버짓 다름 = 연결 상태에 따라 5KB ~ 50KB
  • 우선순위 시스템 = Critical(무조건) → High → Normal → Low(버릴 수 있음)
  • 네트워크 LOD = 멀리 있으면 대충 보내기 (87% 절약)
  • 이벤트 병합 = 100개 공격 → 1개 배치 패킷
  • 실제 게임 = 인원 제한 + 인스턴스 분리 + 동적 품질 조절
