0xC0000005가 떠요

Access Violation — 가장 흔한 크래시, 가장 중요한 디버깅 스킬

이런 에러를 본 적 있다면

Unhandled exception at 0x00007FF6A1B23456 in GameServer.exe:
0xC0000005: Access violation reading location 0x0000000000000010.

또는

Exception thrown: read access violation.
pPlayer was nullptr.

Part 1. Access Violation이 뭐야?

0xC0000005가 뭔데?

접근 위반(Access Violation)의 Windows 에러 코드다. CPU가 접근 권한이 없는 메모리를 읽거나 쓰려고 할 때 발생한다.

쉽게 말해: "네가 가면 안 되는 곳에 갔다"

왜 발생해?

주요 원인 3가지:

원인 예시 주소 패턴
1. nullptr 역참조 pPlayer->GetHP() (pPlayer가 null) 0x00000000 ~ 0x0000FFFF
2. 해제된 메모리 접근 delete pItem; pItem->Use() 0xDDDDDDDD, 0xFEEEFEEE
3. 버퍼 오버런 arr[1000] (크기가 100인 배열) 예측 불가

Part 2. 에러 메시지 해석하기

0xC0000005: Access violation reading location 0x0000000000000010 ^^^^^^^^ ^^^^^^^^^^^^^^^^^^ 읽기 시도 접근한 주소
reading vs writing?

reading: 메모리를 읽으려다 실패 (예: 값 가져오기)

writing: 메모리에 쓰려다 실패 (예: 값 저장하기)

주소가 0x10이면 무슨 뜻이야?

낮은 주소(0x0 ~ 0xFFFF)는 거의 100% nullptr + 오프셋이다.

예: pPlayer->m_nHP에서 pPlayer가 null이고, m_nHP가 구조체에서 0x10 위치에 있으면 → 0x10 접근 시도

// 구조체 예시 struct Player { int m_nID; // offset 0x00 int m_nLevel; // offset 0x04 int m_nHP; // offset 0x08 int m_nMP; // offset 0x0C char* m_pName; // offset 0x10 ← 여기! }; Player* pPlayer = nullptr; pPlayer->m_pName; // nullptr + 0x10 = 0x10 접근 시도 → 크래시!

Part 3. 크래시 분석 5단계

1 콜스택 확인

Debug → Windows → Call Stack (Ctrl+Alt+C)

→ 어떤 함수에서, 어떤 경로로 여기까지 왔는지 확인

2 크래시 라인 확인

콜스택 최상단의 함수를 더블클릭 → 정확히 어느 줄에서 터졌는지 확인

→ 노란 화살표가 가리키는 곳이 문제의 코드

3 변수 값 확인

Locals/Watch 창에서 관련 변수 값 확인

→ 어떤 포인터가 nullptr인지, 어떤 값이 이상한지 찾기

4 원인 역추적

콜스택을 따라 올라가며 "이 포인터가 왜 null이 됐지?" 추적

→ 값이 설정되는 곳, 해제되는 곳 찾기

5 재현 및 수정

원인을 찾았으면 재현 조건 파악 → 방어 코드 또는 로직 수정

Part 4. 실전 예시 — nullptr 크래시

void CGameManager::UpdatePlayer(int nPlayerID) { CPlayer* pPlayer = FindPlayer(nPlayerID); // 여기서 크래시! int nHP = pPlayer->GetHP(); // pPlayer가 nullptr // ... } // 콜스택: // → CGameManager::UpdatePlayer() ← 여기서 터짐 // → CGameManager::OnTick() // → main()
어떻게 고쳐?

방법 1: 방어 코드

void CGameManager::UpdatePlayer(int nPlayerID) { CPlayer* pPlayer = FindPlayer(nPlayerID); // nullptr 체크 추가 if (pPlayer == nullptr) { // 로그 남기고 리턴 LOG_ERROR("Player not found: %d", nPlayerID); return; } int nHP = pPlayer->GetHP(); // 안전 }

Part 5. 자주 보는 주소 패턴

주소 의미 원인
0x00000000 순수 nullptr 포인터가 초기화 안 됨 or 명시적 nullptr
0x00000001 ~ 0x0000FFFF nullptr + 작은 오프셋 nullptr 객체의 멤버 접근
0xCCCCCCCC 초기화 안 된 스택 변수 지역 변수 초기화 누락
0xCDCDCDCD 초기화 안 된 힙 메모리 new 후 초기화 안 함
0xDDDDDDDD 해제된 힙 메모리 delete 후 사용 (use-after-free)
0xFEEEFEEE 해제된 힙 (HeapFree) 해제 후 접근
0xABABABAB 힙 가드 바이트 버퍼 오버런 (경계 침범)

Part 6. 예외 설정으로 미리 잡기

크래시 나기 전에 미리 잡을 수 없어?

Debug → Windows → Exception Settings (Ctrl+Alt+E)

"Win32 Exceptions" → "0xC0000005 Access Violation" 체크

→ 예외 발생 즉시 멈춤 (catch 전에 잡힘)

// 예외 설정 후 동작 변화 // 설정 전: try-catch가 예외를 먹어버려서 어디서 터졌는지 모름 try { pPlayer->DoSomething(); // 여기서 터지지만... } catch (...) { // 여기로 와서 원인 파악 어려움 } // 설정 후: 예외 발생 즉시 정확한 위치에서 멈춤 pPlayer->DoSomething(); // ← 여기서 바로 멈춤!

핵심 정리

  • 0xC0000005 = Access Violation, 잘못된 메모리 접근
  • 낮은 주소 (0x0~0xFFFF) = 거의 100% nullptr 역참조
  • 분석 순서: 콜스택 → 크래시 라인 → 변수 값 → 원인 역추적
  • 메모리 패턴: 0xCC(스택 미초기화), 0xDD(해제됨), 0xFE(HeapFree)
  • Exception Settings: 예외 발생 즉시 잡기 설정 (Ctrl+Alt+E)
