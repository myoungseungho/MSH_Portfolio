자물쇠 하나에 다 몰리면? — 락을 쪼개는 샤딩(스트라이핑)

락 경합을 없애는 법 — 큰 자물쇠 하나를 여러 개로 쪼개 경합을 1/N로. '쪼개서 분산'이 DB·공간까지 관통하는 이유

30초 요약

락 경합 = 여러 스레드가 자물쇠 '하나'에 줄 서서, 코어를 늘려도 안 빨라지는 병목.

샤딩(락 스트라이핑) = 큰 자물쇠 하나를 여러 개로 쪼개고, 키(예: id)로 어느 자물쇠 담당인지 정함.

서로 다른 그룹은 다른 자물쇠라 안 부딪힘 → 경합이 1/N로 흩어져 처리량 ↑.

단, 균등 분배가 전제(핫샤드 주의) + 여러 샤드 걸친 작업은 복잡. 이 '쪼개서 분산'은 DB·공간까지 관통하는 만능 패턴.

Part 1. 문제 복습 — 자물쇠 하나에 다 몰린다

락 경합이 왜 문제였지?

여러 스레드가 공유 자료(예: 유저 테이블)를 안전하게 건드리려면 자물쇠(락)가 필요해. 근데 자물쇠가 하나뿐이면, 아무리 관계없는 유저를 건드려도 전부 그 하나에 줄 서야 해.

비유하면 공용 화장실이 딱 하나인 거야 — 100명이 와도 한 명씩. 코어(일꾼)를 늘려도 화장실이 하나라 줄만 길어지고 안 빨라져. 이게 락 경합이야.

자물쇠 범위를 좁히는 걸론 부족해?

도움은 되는데 한계가 있어. 결국 '하나의 자물쇠'가 남아있는 한 거기로 다 몰려. 그래서 발상을 바꿔 — 자물쇠 자체를 여러 개로 쪼개면? 그게 샤딩이야.

Part 2. 아이디어 — 자물쇠를 여러 개로 쪼갠다(샤딩)

어떻게 쪼개? 아무렇게나 나누면 안 되잖아.

규칙이 필요해. 키(예: 유저 id)로 '어느 자물쇠 담당인지' 정해. 흔한 방법이 id % N(나머지 연산):

• 자물쇠 4개면, id를 4로 나눈 나머지로 담당 결정.

• id 3, 7, 11 → 나머지 3 → 3번 자물쇠

• id 4, 8, 12 → 나머지 0 → 0번 자물쇠

핵심: 같은 유저는 항상 같은 자물쇠, 다른 유저는 흩어져. 그래서 서로 다른 그룹을 건드리는 스레드는 다른 자물쇠라 안 부딪혀 — 화장실을 여러 개 지어 '끝자리별로' 배정한 거지.

이게 왜 빨라져?

경합이 1/N로 흩어지니까. 자물쇠 4개면 한 자물쇠에 몰리는 양이 대략 1/4로 줄어 — 줄이 4갈래로 갈라지는 거야. 그럼 4개 코어가 각자 다른 자물쇠에서 동시에 일할 수 있어(경합이 겹치지 않는 한). 아래에서 직접 비교해봐 ↓

Part 3. 트레이드오프 — 공짜는 아니다

그럼 자물쇠를 무한정 늘리면 되나?

아니, 세 가지 함정이 있어:

1. 균등해야 이득: 한 키(예: 인기 아이템, 보스 몹)에 요청이 몰리면 그 자물쇠 하나만 과부하 = 핫샤드. 쪼개도 소용없어. (아래 위젯)

2. 여러 샤드에 걸친 작업: '전체 순회'나 '두 유저를 동시에 잠금'(거래) 하려면 여러 자물쇠를 잡아야 해 → 복잡해지고 락 순서 안 지키면 데드락.

3. 자물쇠도 메모리·관리 비용: 너무 많으면 오히려 낭비. 보통 코어 수의 몇 배 정도.

⚖️ 균등해야 이득 — 핫샤드 함정

샤딩은 '골고루 나뉜다'가 전제야. 한 키(예: 인기 아이템)에 요청이 몰리면 그 샤드만 과부하돼(핫샤드). 균등 vs 핫스팟을 바꿔봐.

해시로 키를 4개 샤드에 나눠. 골고루면 각 샤드가 1/4씩 — 이상적이야.

Part 4. 같은 아이디어의 사촌들 — '쪼개서 분산'

이 '쪼개기'가 다른 데서도 나와?

샤딩은 스케일만 다를 뿐 어디서나 나오는 만능 패턴이야. '하나에 몰리는 경합/부하를, 쪼개서 분산한다'는 같은 아이디어:

• 락 샤딩(이 글): 자물쇠 1개 → N개 (스레드 경합 분산)

• DB 샤딩: DB 서버 1대 → N대, 유저 id로 분산 (서버 부하 분산 — 우리 관문 21개가 이거)

• 파티셔닝: 큰 테이블 → 조각 (한 서버 안에서)

• AOI(관심영역): 온 맵 → 구역별로 (공간 부하 분산)

전부 '하나의 뜨거운 지점을 여러 개로 갈라 분산'이야. 락에서 이걸 이해하면 나머지가 다 같은 원리로 보여.

우리 서버는?

우리 게임 로직은 싱글스레드라 락 경합 자체가 없어(자물쇠를 안 쓰니 쪼갤 것도 없음 — 액터 모델의 이점). 락 샤딩은 멀티스레드 로직을 쓰는 서버의 이야기야.

대신 우리도 DB 샤딩(관문 21개)과 서버 분산으로 '쪼개서 분산'을 크게 쓰고 있어 — 같은 원리, 다른 스케일.

핵심 정리

  • 락 경합 = 자물쇠 하나에 다 줄 서는 병목(코어 늘려도 안 빨라짐).
  • 락 샤딩(스트라이핑) = 큰 자물쇠 1개를 N개로 쪼개고 키(id%N)로 담당 배정.
  • 같은 키는 같은 자물쇠, 다른 키는 흩어짐 → 경합이 1/N로 분산 → 처리량 ↑.
  • 트레이드오프: 핫샤드(불균등)/여러 샤드 걸친 작업 복잡·데드락/자물쇠 관리비.
  • '쪼개서 분산'은 락→DB→공간(AOI)까지 관통하는 만능 패턴.
  • 우리 서버는 싱글스레드라 락 경합 무관, 대신 DB 샤딩(관문 21개)으로 같은 원리 사용.
