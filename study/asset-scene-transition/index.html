씬 전환 시 메모리 정리

메모리 누수 없는 깔끔한 씬 전환 전략

Part 1. 개념 - 씬 전환의 메모리 문제

씬 전환할 때 왜 메모리 정리가 필요해?

Unity의 SceneManager.LoadScene()은 이전 씬 오브젝트를 파괴하지만, 에셋은 자동 해제되지 않습니다.

┌─────────────────────────────────────────────────────────────────┐
│                    씬 전환 시 메모리 상태                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Scene A 로드 상태                                              │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  GameObject들          에셋 (메모리)                     │   │
│  │  ├─ Player ─────────→ PlayerTexture (10MB)              │   │
│  │  ├─ Enemy ──────────→ EnemyTexture (8MB)                │   │
│  │  └─ Environment ────→ EnvTexture (20MB)                 │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  LoadScene("SceneB") 호출 후                                    │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  GameObject들 (파괴됨)  에셋 (메모리) ← 여전히 남아있음! │   │
│  │  ├─ Player ❌           PlayerTexture (10MB) ✓          │   │
│  │  ├─ Enemy ❌            EnemyTexture (8MB) ✓            │   │
│  │  └─ Environment ❌      EnvTexture (20MB) ✓             │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  Scene B 로드 후 (정리 안 함)                                   │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  총 메모리 사용량:                                       │   │
│  │  Scene A 에셋: 38MB (미사용, 누수!)                      │   │
│  │  Scene B 에셋: 45MB (현재 사용)                          │   │

└─────────────────────────────────────────────────────────────────┘

씬을 여러 번 전환하면 메모리가 계속 누적되어 결국 크래시합니다.

왜 에셋이 자동으로 안 지워져?

Unity의 에셋 캐싱 시스템 때문입니다. 성능을 위해 의도적으로 유지합니다.

// Unity 내부 동작 (개념적 설명) // Resources.Load나 AssetBundle.Load 시 // Unity는 내부적으로 에셋을 캐싱합니다 internal class AssetCache { // 한 번 로드된 에셋은 여기 캐시됨 static Dictionary<string, Object> loadedAssets; public static T Load<T>(string path) { if (loadedAssets.ContainsKey(path)) return loadedAssets[path]; // 캐시에서 반환 var asset = LoadFromDisk(path); loadedAssets[path] = asset; // 캐시에 저장 return asset; } } // 이 캐시는 명시적으로 비우지 않으면 유지됩니다 // Resources.UnloadUnusedAssets()가 그 역할을 합니다
💡 캐싱의 장점
같은 에셋을 다시 로드할 때 디스크 I/O 없이 즉시 반환됩니다. 씬을 왔다 갔다 하는 게임에서는 오히려 성능에 유리합니다.

Part 2. 기본 정리 방법

Resources.UnloadUnusedAssets()가 뭐야?

현재 참조되지 않는 에셋을 메모리에서 해제하는 Unity 내장 함수입니다.

using UnityEngine; using UnityEngine.SceneManagement; using System.Collections; public class BasicSceneTransition : MonoBehaviour { public void LoadSceneWithCleanup(string sceneName) { StartCoroutine(LoadSceneCoroutine(sceneName)); } private IEnumerator LoadSceneCoroutine(string sceneName) { // 1. 새 씬 로드 (이전 씬의 GameObject들이 파괴됨) yield return SceneManager.LoadSceneAsync(sceneName); // 2. 미사용 에셋 해제 yield return Resources.UnloadUnusedAssets(); // 3. GC 실행 (관리되는 메모리 정리) System.GC.Collect(); } }
UnloadUnusedAssets은 언제 호출해야 해?

씬 로드 직후가 가장 효과적입니다. 이전 씬의 참조가 모두 끊어진 상태이기 때문입니다.

┌─────────────────────────────────────────────────────────────────┐
│               UnloadUnusedAssets 타이밍                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ❌ 잘못된 타이밍: 씬 로드 전                                    │
│  ─────────────────────────────                                  │
│  Resources.UnloadUnusedAssets();  ← 이전 씬 오브젝트가 아직     │
│  SceneManager.LoadScene("B");        참조 중이라 해제 안 됨     │
│                                                                 │
│  ─────────────────────────────────────────────────────────────  │
│                                                                 │
│  ✅ 올바른 타이밍: 씬 로드 후                                    │
│  ────────────────────────────                                   │
│  SceneManager.LoadScene("B");     ← 이전 씬 오브젝트 파괴       │
│  Resources.UnloadUnusedAssets();  ← 참조 끊어진 에셋 해제       │
│                                                                 │
│  ─────────────────────────────────────────────────────────────  │
│                                                                 │
│  ✅✅ 가장 좋은 타이밍: 로딩 화면 중                              │
│  ────────────────────────────────                               │
│  SceneManager.LoadScene("Loading");  ← 경량 로딩 씬             │
│  Resources.UnloadUnusedAssets();     ← 여기서 정리 (히칭 숨김)  │
│  SceneManager.LoadScene("B");        ← 실제 씬 로드             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
GC.Collect()도 꼭 호출해야 해?

권장하지만 필수는 아닙니다. UnloadUnusedAssets가 내부적으로 GC를 트리거하기도 합니다.

// UnloadUnusedAssets vs GC.Collect 차이 // Resources.UnloadUnusedAssets() // - Unity 네이티브 에셋 (Texture, Mesh, AudioClip 등) 해제 // - 내부적으로 GC를 호출할 수 있음 (보장되지 않음) // - 비동기 (AsyncOperation 반환) // System.GC.Collect() // - C# 관리 메모리 (클래스 인스턴스, 배열 등) 해제 // - 동기 (즉시 실행, 프레임 히칭 유발 가능) // 둘 다 호출하는 것이 가장 확실함 private IEnumerator FullCleanup() { // 1. 네이티브 에셋 정리 yield return Resources.UnloadUnusedAssets(); // 2. 관리 메모리 정리 System.GC.Collect(); // 3. Finalizer 대기 (완전한 정리) System.GC.WaitForPendingFinalizers(); // 4. 한 번 더 GC (Finalizer가 해제한 객체 정리) System.GC.Collect(); }
⚠️ GC.Collect() 주의사항
게임플레이 중에 GC.Collect()를 호출하면 프레임 히칭이 발생합니다. 반드시 로딩 화면이나 일시정지 상태에서만 호출하세요.

Part 3. 로딩 씬 패턴

로딩 씬 매니저 어떻게 만들어?

싱글톤 패턴으로 전역 씬 전환 관리자를 만듭니다.

using UnityEngine; using UnityEngine.SceneManagement; using UnityEngine.UI; using System; using System.Collections; public class SceneTransitionManager : MonoBehaviour { public static SceneTransitionManager Instance { get; private set; } [SerializeField] private string loadingSceneName = "LoadingScene"; [SerializeField] private float minimumLoadingTime = 1f; private string _targetSceneName; private Action _onLoadComplete; private void Awake() { if (Instance != null) { Destroy(gameObject); return; } Instance = this; DontDestroyOnLoad(gameObject); } public void LoadScene(string sceneName, Action onComplete = null) { _targetSceneName = sceneName; _onLoadComplete = onComplete; StartCoroutine(TransitionCoroutine()); } private IEnumerator TransitionCoroutine() { float startTime = Time.realtimeSinceStartup; // 1. 로딩 씬으로 이동 yield return SceneManager.LoadSceneAsync(loadingSceneName); // 2. 이전 씬 에셋 정리 (핵심!) yield return CleanupMemory(); // 3. 타겟 씬 로드 var loadOp = SceneManager.LoadSceneAsync(_targetSceneName); loadOp.allowSceneActivation = false; // 4. 로딩 진행률 업데이트 while (loadOp.progress < 0.9f) { UpdateLoadingUI(loadOp.progress / 0.9f); yield return null; } // 5. 최소 로딩 시간 보장 (UX) float elapsed = Time.realtimeSinceStartup - startTime; if (elapsed < minimumLoadingTime) { yield return new WaitForSecondsRealtime( minimumLoadingTime - elapsed); } // 6. 씬 활성화 loadOp.allowSceneActivation = true; yield return loadOp; _onLoadComplete?.Invoke(); } private IEnumerator CleanupMemory() { // 프레임 대기 (오브젝트 파괴 완료 보장) yield return null; yield return null; // 미사용 에셋 해제 yield return Resources.UnloadUnusedAssets(); // GC 실행 System.GC.Collect(); System.GC.WaitForPendingFinalizers(); System.GC.Collect(); // 정리 완료 대기 yield return null; } private void UpdateLoadingUI(float progress) { // 로딩 UI 업데이트 (LoadingScene에 있는 UI 찾아서 업데이트) var slider = FindObjectOfType<Slider>(); if (slider != null) slider.value = progress; } }
로딩 씬은 어떻게 만들어?

최소한의 UI만 포함하여 메모리 사용량을 극도로 낮춥니다.

// LoadingScene 구성 // - Canvas (로딩 UI) // - Background (단색 또는 그라데이션) // - Loading Slider // - Loading Text // - Optional: 로딩 팁 텍스트 public class LoadingSceneUI : MonoBehaviour { [SerializeField] private Slider progressSlider; [SerializeField] private Text progressText; [SerializeField] private Text tipText; [SerializeField] private string[] tips; private void Start() { // 랜덤 팁 표시 if (tips.Length > 0 && tipText != null) { tipText.text = tips[Random.Range(0, tips.Length)]; } } public void SetProgress(float progress) { progressSlider.value = progress; progressText.text = $"{(int)(progress * 100)}%"; } } // 💡 로딩 씬 최적화 팁: // - 텍스처는 압축률 높게 (ETC2, ASTC) // - 폰트는 시스템 폰트 또는 경량 폰트 // - 애니메이션 최소화 // - 목표: 2-5MB 이하

Part 4. Addressables와 씬 전환

Addressables 쓸 때는 어떻게 해?

Addressables는 참조 카운팅 기반이라 더 세밀한 제어가 가능합니다.

using UnityEngine; using UnityEngine.AddressableAssets; using UnityEngine.ResourceManagement.AsyncOperations; using UnityEngine.ResourceManagement.ResourceProviders; using System.Collections; using System.Collections.Generic; public class AddressableSceneManager : MonoBehaviour { private AsyncOperationHandle<SceneInstance> _currentSceneHandle; private List<AsyncOperationHandle> _sceneAssetHandles = new(); public IEnumerator LoadSceneAsync(string sceneAddress) { // 1. 로딩 씬으로 이동 (Resources 기반 경량 씬) yield return SceneManager.LoadSceneAsync("LoadingScene"); // 2. 이전 씬의 Addressable 핸들 해제 yield return ReleaseCurrentScene(); // 3. 메모리 정리 yield return Resources.UnloadUnusedAssets(); System.GC.Collect(); // 4. 새 씬 로드 _currentSceneHandle = Addressables.LoadSceneAsync( sceneAddress, LoadSceneMode.Single ); while (!_currentSceneHandle.IsDone) { UpdateProgress(_currentSceneHandle.PercentComplete); yield return null; } } private IEnumerator ReleaseCurrentScene() { // 씬에서 로드한 에셋 핸들 해제 foreach (var handle in _sceneAssetHandles) { if (handle.IsValid()) { Addressables.Release(handle); } } _sceneAssetHandles.Clear(); // 이전 씬 핸들 해제 if (_currentSceneHandle.IsValid()) { yield return Addressables.UnloadSceneAsync( _currentSceneHandle ); } } // 씬 내에서 에셋 로드 시 핸들 등록 public void RegisterAssetHandle(AsyncOperationHandle handle) { _sceneAssetHandles.Add(handle); } }
씬별 에셋 그룹은 어떻게 관리해?

씬 단위로 Addressable Group을 분리하면 자동 해제가 쉬워집니다.

public class SceneAssetGroup { public string SceneName; public List<string> AssetLabels = new(); public List<AsyncOperationHandle> LoadedHandles = new(); public IEnumerator PreloadAssets() { foreach (var label in AssetLabels) { var handle = Addressables.LoadAssetsAsync<Object>( label, null // 개별 콜백 불필요 ); LoadedHandles.Add(handle); yield return handle; } } public void ReleaseAllAssets() { foreach (var handle in LoadedHandles) { if (handle.IsValid()) { Addressables.Release(handle); } } LoadedHandles.Clear(); } }

Part 5. DontDestroyOnLoad 처리

DontDestroyOnLoad 오브젝트는 어떻게 해?

씬 전환에도 살아남는 오브젝트는 참조하는 에셋도 해제되지 않습니다.

public class PersistentObjectManager : MonoBehaviour { public static PersistentObjectManager Instance { get; private set; } // 씬별로 교체 가능한 에셋 참조 private AudioClip _currentBGM; private Sprite _currentPlayerIcon; private void Awake() { if (Instance != null) { Destroy(gameObject); return; } Instance = this; DontDestroyOnLoad(gameObject); // 씬 로드 이벤트 구독 SceneManager.sceneUnloaded += OnSceneUnloaded; } private void OnSceneUnloaded(Scene scene) { // 씬별 에셋 참조 해제 ClearSceneSpecificAssets(); } public void ClearSceneSpecificAssets() { // 씬 전환 시 교체될 에셋 참조 해제 _currentBGM = null; _currentPlayerIcon = null; // 이렇게 해야 UnloadUnusedAssets에서 해제됨 } // 새 씬에서 에셋 설정 public void SetBGM(AudioClip clip) { _currentBGM = clip; // AudioSource 재생... } }
오브젝트 풀도 문제야?

맞습니다. 오브젝트 풀이 DontDestroyOnLoad라면 풀링된 오브젝트의 에셋도 계속 유지됩니다.

public class SceneAwareObjectPool : MonoBehaviour { [SerializeField] private GameObject prefab; private Queue<GameObject> _pool = new(); private string _originalScene; private void Awake() { _originalScene = SceneManager.GetActiveScene().name; SceneManager.sceneLoaded += OnSceneLoaded; } private void OnSceneLoaded(Scene scene, LoadSceneMode mode) { // 원래 씬이 아니면 풀 클리어 if (scene.name != _originalScene) { ClearPool(); } } public void ClearPool() { while (_pool.Count > 0) { var obj = _pool.Dequeue(); if (obj != null) { Destroy(obj); } } // 프리팹 참조도 해제 (필요 시) // prefab = null; } private void OnDestroy() { SceneManager.sceneLoaded -= OnSceneLoaded; } }
💡 풀 관리 전략
1. 씬별 풀: 씬과 함께 생성/파괴
2. 전역 풀: 공용 프리팹만 (UI, 파티클 등)
3. 하이브리드: 전역 풀이지만 씬 전환 시 비활성 오브젝트 파괴

Part 6. 고급 패턴

Additive 씬 로딩에서는 어떻게 해?

Additive로 로드한 씬은 명시적으로 Unload해야 합니다.

using UnityEngine; using UnityEngine.SceneManagement; using System.Collections; using System.Collections.Generic; public class AdditiveSceneManager : MonoBehaviour { private List<string> _loadedAdditiveScenes = new(); private string _mainSceneName; // 메인 씬 + 서브 씬들 로드 public IEnumerator LoadMainWithSubScenes( string mainScene, string[] subScenes) { // 1. 기존 Additive 씬들 언로드 yield return UnloadAllAdditiveScenes(); // 2. 메모리 정리 yield return Resources.UnloadUnusedAssets(); System.GC.Collect(); // 3. 메인 씬 로드 yield return SceneManager.LoadSceneAsync(mainScene); _mainSceneName = mainScene; // 4. 서브 씬들 Additive 로드 foreach (var subScene in subScenes) { yield return SceneManager.LoadSceneAsync( subScene, LoadSceneMode.Additive ); _loadedAdditiveScenes.Add(subScene); } } // 특정 서브 씬만 언로드 public IEnumerator UnloadSubScene(string sceneName) { if (!_loadedAdditiveScenes.Contains(sceneName)) yield break; yield return SceneManager.UnloadSceneAsync(sceneName); _loadedAdditiveScenes.Remove(sceneName); // 언로드 후 정리 yield return Resources.UnloadUnusedAssets(); } // 모든 Additive 씬 언로드 public IEnumerator UnloadAllAdditiveScenes() { var scenesToUnload = new List<string>(_loadedAdditiveScenes); foreach (var sceneName in scenesToUnload) { var scene = SceneManager.GetSceneByName(sceneName); if (scene.isLoaded) { yield return SceneManager.UnloadSceneAsync(scene); } } _loadedAdditiveScenes.Clear(); } }
씬 전환 중 프레임 드랍을 어떻게 줄여?

작업을 여러 프레임에 분산하여 히칭을 줄입니다.

public class SmoothSceneTransition : MonoBehaviour { // 점진적 메모리 정리 private IEnumerator GradualCleanup() { // 1단계: 비활성 오브젝트 파괴 (여러 프레임) var inactiveObjects = FindObjectsOfType<GameObject>(true) .Where(go => !go.activeInHierarchy) .ToList(); int destroyedPerFrame = 10; for (int i = 0; i < inactiveObjects.Count; i += destroyedPerFrame) { for (int j = i; j < Mathf.Min(i + destroyedPerFrame, inactiveObjects.Count); j++) { Destroy(inactiveObjects[j]); } yield return null; // 프레임 양보 } // 2단계: Resources.UnloadUnusedAssets (자체가 비동기) var unloadOp = Resources.UnloadUnusedAssets(); // 진행률 모니터링 while (!unloadOp.isDone) { // UI 업데이트 가능 yield return null; } // 3단계: 점진적 GC (Generation별) System.GC.Collect(0); // Gen 0만 yield return null; System.GC.Collect(1); // Gen 0, 1 yield return null; System.GC.Collect(2); // 전체 yield return null; } // 타임슬라이스 로딩 private IEnumerator TimeSlicedLoading(string sceneName) { var loadOp = SceneManager.LoadSceneAsync(sceneName); loadOp.allowSceneActivation = false; // 프레임당 로딩 시간 제한 (16ms = 60fps) float maxLoadTimePerFrame = 0.016f; while (loadOp.progress < 0.9f) { float frameStart = Time.realtimeSinceStartup; // 이 프레임에서 얼마나 더 로딩할 수 있나? while (Time.realtimeSinceStartup - frameStart < maxLoadTimePerFrame && loadOp.progress < 0.9f) { // Unity 내부 로딩 진행 } yield return null; // 프레임 양보 } loadOp.allowSceneActivation = true; yield return loadOp; } }

Part 7. 플랫폼별 고려사항

모바일에서 주의할 점은?

모바일은 메모리가 제한적이므로 더 적극적인 정리가 필요합니다.

public class MobileSceneTransition : MonoBehaviour { private IEnumerator MobileOptimizedTransition(string sceneName) { // 1. 로딩 전 가능한 모든 것 정리 PreCleanup(); // 2. 로딩 씬으로 이동 yield return SceneManager.LoadSceneAsync("LoadingScene"); // 3. 적극적 메모리 정리 yield return AggressiveCleanup(); // 4. 메모리 여유 확인 if (!HasEnoughMemory()) { // 추가 정리 또는 품질 낮추기 LowerQualitySettings(); yield return AggressiveCleanup(); } // 5. 새 씬 로드 yield return SceneManager.LoadSceneAsync(sceneName); } private void PreCleanup() { // 오브젝트 풀 클리어 ObjectPoolManager.Instance?.ClearAllPools(); // 캐시된 데이터 클리어 DataCache.Instance?.Clear(); // 이벤트 리스너 정리 (메모리 누수 방지) EventManager.Instance?.ClearAllListeners(); } private IEnumerator AggressiveCleanup() { // 프레임 대기 yield return null; yield return null; // 미사용 에셋 해제 yield return Resources.UnloadUnusedAssets(); // 풀 GC 실행 System.GC.Collect(); System.GC.WaitForPendingFinalizers(); System.GC.Collect(); // iOS: 메모리 압박 상황에서 추가 정리 #if UNITY_IOS UnityEngine.iOS.Device.SetNoBackupFlag( Application.temporaryCachePath); #endif // Android: Low Memory 콜백 대응 #if UNITY_ANDROID // Addressables 메모리 프로파일러 확인 #endif yield return null; } private bool HasEnoughMemory() { long available = Profiler.GetTotalReservedMemoryLong() - Profiler.GetTotalAllocatedMemoryLong(); // 최소 50MB 여유 확보 return available > 50 * 1024 * 1024; } private void LowerQualitySettings() { QualitySettings.SetQualityLevel( QualitySettings.GetQualityLevel() - 1, true); } }

핵심 정리

  • Resources.UnloadUnusedAssets(): 씬 로드 후 호출하여 미사용 에셋 해제
  • 로딩 씬 패턴: 메모리 피크를 낮추고 정리 히칭을 숨김
  • Addressables: 참조 카운팅 기반, 핸들 명시적 해제 필요
  • DontDestroyOnLoad: 씬 전환 시 참조 해제 필요
  • Additive 씬: UnloadSceneAsync로 명시적 언로드
  • 점진적 정리: 여러 프레임에 분산하여 히칭 최소화
  • 모바일: 적극적 정리 + 메모리 워닝 대응
