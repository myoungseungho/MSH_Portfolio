01 / PROJECT OVERVIEW

“서버가 느려요”를
추측으로 끝내지 않기.

서버 렉이라는 같은 증상 뒤에는 CPU, 메모리, 디스크, 네트워크, DB처럼 서로 다른 원인이 있습니다. 수치가 원인 후보와 다음 조사 지점으로 이어질 때 운영 판단이 빨라집니다.

01

Challenge

수치만 나열된 화면에서는 장애 순간에 “그래서 뭘 봐야 하지?”가 남습니다. 단일 숫자로 결론 내리지 않고, 같이 변한 지표를 따라 원인을 좁혀야 합니다.

02

Role

Windows 성능 카운터와 네트워크·MSSQL 요약을 한 표본으로 모아, 각 값의 의미와 다음 확인 항목을 바로 읽을 수 있게 설계했습니다.

03

Decision

DB 정보는 SQL Server가 감지된 머신에서만 읽기 전용 시스템 뷰·DMV로 조회합니다. 게임 데이터나 테이블 설정을 수정하지 않습니다.

THE MENTAL MODEL

컴퓨터를 작은 식당으로
생각하면 빠릅니다.

CPU요리하는 주방→ 주방 앞에 줄이 긴가?

Network손님과 연결된 도로→ 전달한 봉투가 사라지는가?

MSSQL주문·재고 장부 담당→ 앞사람이 장부를 잡고 있는가?

WHAT THIS PROJECT TEACHES

좋은 운영 지표는
“그래서?”에 답한다.
