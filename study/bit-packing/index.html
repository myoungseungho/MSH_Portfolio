2.75바이트 패킷을 보내는 법

Bit Stream - 바이트 경계를 무시하고 정확히 필요한 비트만 보내기

📦 네트워크 ⏱️ 15분 📅 2025.01.20

🤔 왜 필요해?

패킷을 보낼 때 왜 4바이트, 8바이트 단위로만 보내야 해?

보내야 하는 게 아니에요. 우리가 그렇게 생각하고 있을 뿐이에요.

일반적인 패킷 전송

struct Packet { uint8_t direction; // 1 바이트 (실제 필요: 3비트) uint16_t velocity; // 2 바이트 (실제 필요: 10비트) uint16_t rotation; // 2 바이트 (실제 필요: 9비트) } __attribute__((packed)); // 총 5바이트 = 40비트 // 실제 필요: 3 + 10 + 9 = 22비트

우리는 18비트(45%)를 낭비하고 있어요!

그럼 22비트만 보낼 수 있어?

가능해요! 비트 스트림(Bit Stream)을 사용하면 돼요.

일반 방식 vs 비트 스트림

일반 방식 (바이트 경계 유지): ┌─────────┬─────────────────┬─────────────────┐ │direction│ velocity │ rotation │ │ 8 bits │ 16 bits │ 16 bits │ └─────────┴─────────────────┴─────────────────┘ 1 byte 2 bytes 2 bytes = 5 바이트 (40비트) 비트 스트림 (바이트 경계 무시): ┌───┬──────────┬─────────┐ │dir│ velocity │rotation │ │3bit│ 10bit │ 9bit │ └───┴──────────┴─────────┘ = 22비트 = 2.75바이트!

5바이트 → 2.75바이트, 45% 절약!

💡 비트 스트림이 뭐예요?

구체적으로 어떻게 동작해?

비트 단위로 데이터를 차곡차곡 쌓는 버퍼예요.

🧱 비유: 벽돌 쌓기

일반 방식 (바이트 경계):
작은 물건도 벽돌 1개 단위로 포장
→ 큰 상자에 작은 물건 (공간 낭비)

비트 스트림:
물건 크기에 딱 맞게 자르고 붙임
→ 남는 공간 없이 빽빽하게 포장

3개의 물건 (3비트 + 10비트 + 9비트)
→ 정확히 22비트만 사용
실제로 어떻게 쓰이나요?

Step 1: 쓰기 (Write)

BitStream stream; // 1. direction: 3비트 stream.WriteBits(5, 3); // 값 5를 3비트로 (0~7) // 2. velocity: 10비트 stream.WriteBits(512, 10); // 값 512를 10비트로 (0~1023) // 3. rotation: 9비트 stream.WriteBits(256, 9); // 값 256을 9비트로 (0~511) // 총 22비트 = 2.75바이트만 사용!

Step 2: 전송

// 버퍼에서 실제 바이트 추출 uint8_t* buffer = stream.GetBuffer(); // [바이트0][바이트1][바이트2] size_t size = stream.GetByteSize(); // 3 bytes (22비트 → 올림) send(socket, buffer, size, 0); // 3바이트만 전송

Step 3: 읽기 (Read)

// 수신측에서 비트 단위로 읽기 uint32_t direction = stream.ReadBits(3); // 5 uint32_t velocity = stream.ReadBits(10); // 512 uint32_t rotation = stream.ReadBits(9); // 256 // 순서대로 정확히 복원!

🔧 비트 스트림 구현

코드로 보여주세요.

기본 구조

class BitStream { private: std::vector buffer; // 실제 데이터 버퍼 size_t bitPosition; // 현재 쓰기/읽기 위치 (비트) public: BitStream() : bitPosition(0) {} void WriteBits(uint32_t value, int numBits); uint32_t ReadBits(int numBits); uint8_t* GetBuffer() { return buffer.data(); } size_t GetByteSize() { return (bitPosition + 7) / 8; } // 올림 };

WriteBits 구현

void BitStream::WriteBits(uint32_t value, int numBits) { for (int i = 0; i < numBits; i++) { // 현재 바이트 인덱스 size_t byteIndex = bitPosition / 8; size_t bitIndex = bitPosition % 8; // 버퍼 확장 필요 시 if (byteIndex >= buffer.size()) buffer.push_back(0); // 비트 추출 (MSB부터) uint32_t bit = (value >> (numBits - 1 - i)) & 1; // 버퍼에 비트 쓰기 if (bit) buffer[byteIndex] |= (1 << (7 - bitIndex)); bitPosition++; } } // 예시: WriteBits(5, 3) // value = 5 = 0b101 // 3비트 쓰기: 1, 0, 1

ReadBits 구현

uint32_t BitStream::ReadBits(int numBits) { uint32_t result = 0; for (int i = 0; i < numBits; i++) { size_t byteIndex = bitPosition / 8; size_t bitIndex = bitPosition % 8; // 버퍼에서 비트 읽기 uint8_t bit = (buffer[byteIndex] >> (7 - bitIndex)) & 1; // 결과에 비트 추가 result = (result << 1) | bit; bitPosition++; } return result; } // 예시: ReadBits(3) // 버퍼에서 3비트 읽기: 1, 0, 1 // result = 0b101 = 5

🎯 실전 예시

실제 게임 패킷으로 보여주세요.

예시 1: 플레이어 이동 패킷

// 일반 방식 (바이트 경계) struct MovePacket { uint8_t playerId; // 1 byte (0~255) uint8_t direction; // 1 byte (0~7, 실제 3비트) uint16_t x; // 2 bytes (양자화된 위치) uint16_t y; // 2 bytes uint16_t rotation; // 2 bytes (0~360 → 9비트) }; // 총: 8 바이트 // 비트 스트림 방식 BitStream stream; stream.WriteBits(playerId, 8); // 8 bits stream.WriteBits(direction, 3); // 3 bits stream.WriteBits(x, 16); // 16 bits stream.WriteBits(y, 16); // 16 bits stream.WriteBits(rotation, 9); // 9 bits // 총: 52 bits = 6.5 바이트 (vs 8 바이트) // 절약: 18.75%

예시 2: 상태 플래그 + 체력

// 일반 방식 struct StatePacket { uint8_t flags; // 1 byte (독/무적/스턴/은신 = 4비트) uint8_t health; // 1 byte (0~100, 7비트) uint8_t mana; // 1 byte (0~100, 7비트) }; // 총: 3 바이트 = 24비트 // 비트 스트림 방식 BitStream stream; stream.WriteBits(flags, 4); // 4 bits stream.WriteBits(health, 7); // 7 bits stream.WriteBits(mana, 7); // 7 bits // 총: 18 bits = 2.25 바이트 (vs 3 바이트) // 절약: 25%

예시 3: 멀티플레이 동기화 (100명)

// 플레이어 1명당 패킷 // 일반 방식: 8 바이트 // 비트 스트림: 6.5 바이트 // 100명 동기화 (초당 20회) 일반: 8 * 100 * 20 = 16,000 bytes/s = 15.6 KB/s 비트 스트림: 6.5 * 100 * 20 = 13,000 bytes/s = 12.7 KB/s // 1시간 기준 일반: 56 MB/hour 비트 스트림: 45.7 MB/hour // 절약: 10.3 MB/hour (18.75%)

⚡ 고급 기법

더 최적화할 방법은?

1. 가변 길이 비트 (Variable Bit Length)

// 값에 따라 비트 수 조절 void WriteSmartInt(uint32_t value) { if (value < 16) // 4비트로 충분 { WriteBits(0, 1); // 플래그: 작은 값 WriteBits(value, 4); } else // 16비트 필요 { WriteBits(1, 1); // 플래그: 큰 값 WriteBits(value, 16); } } // playerId = 7 → 5비트 (플래그 1 + 값 4) // playerId = 1000 → 17비트 (플래그 1 + 값 16) // 대부분 작은 값 → 평균 절약!

2. 양자화 + 비트 패킹

// 회전을 양자화 후 비트 패킹 float rotation = 127.5f; // 0~360 // Step 1: 양자화 (360 → 512 레벨) uint16_t quantized = (uint16_t)((rotation / 360.0f) * 511.0f); // quantized = 181 // Step 2: 비트 스트림 (9비트만 사용) stream.WriteBits(quantized, 9); // 4바이트 → 1.125바이트 (71% 절약!)

3. 델타 + 비트 패킹

// 위치 변화량 (작은 값) int16_t deltaX = currentX - previousX; // -10 ~ +10 범위 // 5비트면 충분 (-16 ~ +15) stream.WriteBits(deltaX + 16, 5); // 부호 없는 값으로 변환 // 2바이트 → 0.625바이트 (69% 절약!)

4. 조건부 전송

// 플래그로 어떤 데이터가 있는지 표시 uint8_t flags = 0; if (positionChanged) flags |= 0x01; if (rotationChanged) flags |= 0x02; if (healthChanged) flags |= 0x04; stream.WriteBits(flags, 3); // 3비트 플래그 if (positionChanged) stream.WriteBits(x, 16); // 변경된 것만 전송 // 모든 데이터를 항상 보내지 않음!

📊 일반 패킹 vs 비트 스트림

일반 비트 패킹이랑 뭐가 달라?

일반 비트 패킹 (uint32_t 사용)

// 32비트 안에서 쪼개기 uint32_t packed = 0; packed |= (direction & 0x7) << 0; // 3비트 packed |= (velocity & 0x3FF) << 3; // 10비트 packed |= (rotation & 0x1FF) << 13; // 9비트 // 총 22비트 사용, 10비트 낭비 // 크기: 4바이트 (고정)

비트 스트림

BitStream stream; stream.WriteBits(direction, 3); // 3비트 stream.WriteBits(velocity, 10); // 10비트 stream.WriteBits(rotation, 9); // 9비트 // 총 22비트 사용, 낭비 없음 // 크기: 2.75바이트 (정확!)
항목 일반 비트 패킹 비트 스트림
크기 4바이트 (고정) 2.75바이트 (정확)

복잡도 쉬움 (비트 연산) 중간 (버퍼 관리)
유연성 낮음 (32비트 제한) 높음 (무제한)

  • 변화 있는 필드: 플래그 1비트 + 데이터
  • 평균 70% 압축률
  • 64명 서버에서 대역폭 1/3 절약

💼 실무 구현 가이드

Step 1: 비트 수 분석

// 각 필드가 실제로 필요한 비트 계산 struct PlayerState { uint8_t playerId; // 0~255 → 8비트 필요 uint8_t direction; // 0~7 → 3비트 필요 uint16_t x; // 0~65535 → 16비트 필요 uint16_t y; // 0~65535 → 16비트 필요 uint16_t rotation; // 0~511 → 9비트 필요 uint8_t health; // 0~127 → 7비트 필요 }; // 일반: 8 + 8 + 16 + 16 + 16 + 8 = 72비트 = 9바이트 // 최적: 8 + 3 + 16 + 16 + 9 + 7 = 59비트 = 7.375바이트 // 절약: 18%

Step 2: BitStream 클래스 작성

// 프로젝트에 맞는 BitStream 구현 class BitStream { private: std::vector buffer; size_t bitPosition = 0; public: // 기본 쓰기 void WriteBits(uint32_t value, int numBits); void WriteFloat(float value, float min, float max, int bits); void WriteVector3(const Vector3& v, int bitsPerAxis); // 기본 읽기 uint32_t ReadBits(int numBits); float ReadFloat(float min, float max, int bits); Vector3 ReadVector3(int bitsPerAxis); // 유틸리티 void Reset() { buffer.clear(); bitPosition = 0; } uint8_t* GetBuffer() { return buffer.data(); } size_t GetByteSize() { return (bitPosition + 7) / 8; } };

Step 3: 패킷 직렬화

// 보내기 void SerializePlayerState(BitStream& stream, const PlayerState& state) { stream.WriteBits(state.playerId, 8); stream.WriteBits(state.direction, 3); stream.WriteBits(state.x, 16); stream.WriteBits(state.y, 16); stream.WriteBits(state.rotation, 9); stream.WriteBits(state.health, 7); } // 받기 PlayerState DeserializePlayerState(BitStream& stream) { PlayerState state; state.playerId = stream.ReadBits(8); state.direction = stream.ReadBits(3); state.x = stream.ReadBits(16); state.y = stream.ReadBits(16); state.rotation = stream.ReadBits(9); state.health = stream.ReadBits(7); return state; }

Step 4: 테스트

// 단위 테스트 void TestBitStream() { BitStream stream; // 쓰기 stream.WriteBits(5, 3); // 101 stream.WriteBits(512, 10); // 1000000000 stream.WriteBits(256, 9); // 100000000 // 읽기 (순서 중요!) uint32_t v1 = stream.ReadBits(3); // 5 uint32_t v2 = stream.ReadBits(10); // 512 uint32_t v3 = stream.ReadBits(9); // 256 assert(v1 == 5); assert(v2 == 512); assert(v3 == 256); // 크기 확인 assert(stream.GetByteSize() == 3); // 22비트 → 3바이트 }

⚠️ 주의사항

조심할 점은?

1. 순서 일치 필수

// 보내는 순서 stream.WriteBits(x, 16); stream.WriteBits(y, 16); // 받는 순서 (반드시 같아야 함!) x = stream.ReadBits(16); y = stream.ReadBits(16); // ❌ 잘못된 순서 y = stream.ReadBits(16); // y에 x 값이 들어감! x = stream.ReadBits(16); // x에 y 값이 들어감!

2. 비트 수 불일치

// 서버: 9비트로 전송 stream.WriteBits(rotation, 9); // 클라이언트: 8비트로 읽기 rotation = stream.ReadBits(8); // ❌ 잘못된 값! // 해결: 상수로 관리 const int ROTATION_BITS = 9;

3. 범위 초과

// 9비트 = 0~511 표현 가능 stream.WriteBits(600, 9); // ❌ Overflow! // 해결: 범위 체크 uint32_t SafeWrite(uint32_t value, int bits) { uint32_t max = (1 << bits) - 1; return std::min(value, max); }

4. 버퍼 오버플로우

// 읽기 전에 크기 체크 if (stream.GetBitPosition() + 16 > stream.GetBitSize()) { // 읽을 데이터가 부족! return false; }

🔥 실전 최적화 조합

델타 압축, 양자화랑 함께 쓰면?

궁극의 조합: 델타 + 양자화 + 비트 스트림

// 플레이어 위치 (float 3개) // 원본: 4 * 3 = 12 바이트 // Step 1: 델타 계산 float dx = currentX - previousX; // -10.5 float dy = currentY - previousY; // +3.2 float dz = currentZ - previousZ; // -1.8 // Step 2: 양자화 (-100~100 → 16비트) int16_t qdx = Quantize(dx, -100, 100, 16); // -10.5 → short int16_t qdy = Quantize(dy, -100, 100, 16); int16_t qdz = Quantize(dz, -100, 100, 16); // Step 3: 비트 스트림 (작은 델타는 적은 비트) BitStream stream; if (abs(dx) < 1.0f) stream.WriteBits(qdx + 128, 8); // 8비트 (±1.28) else stream.WriteBits(qdx + 32768, 16); // 16비트 // 총 크기: 평균 24비트 = 3바이트 // vs 원본 12바이트 → 75% 절약!
💡 압축 단계:
1. 델타: 12바이트 → 6바이트 (변화량)
2. 양자화: 6바이트 → 6바이트 (정밀도 유지)
3. 비트 스트림: 6바이트 → 3바이트 (비트 절약)

총 절약률: 75%

📌 핵심 정리: Bit Packing & Bit Stream

  • 비트 스트림 - 바이트 경계를 무시하고 정확히 필요한 비트만 사용

  • 사용 사례 - Overwatch, Rocket League, Unreal Engine
