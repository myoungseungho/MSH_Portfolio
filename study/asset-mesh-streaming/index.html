메시 스트리밍 - LOD 연계

100만 폴리곤 캐릭터를 어떻게 부드럽게 보여줄까?

Part 1. LOD란 무엇인가?

LOD가 뭐야?

LOD (Level of Detail) = 거리에 따라 다른 품질의 메시 사용

멀리 있는 건 어차피 작게 보이니까, 폴리곤 수를 줄여도 모름

캐릭터 메시 LOD 예시: LOD 0 (가까움) LOD 1 (중간) LOD 2 (멀리) LOD 3 (아주 멀리) ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ │ ◉ │ │ ● │ │ • │ │ . │ │ /|\ │ │ /| │ │ / │ │ │ │ / \ │ │ /\ │ │ △ │ │ △ │ └─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘ 100,000 폴리곤 25,000 폴리곤 5,000 폴리곤 500 폴리곤 (5m 이내) (5~20m) (20~50m) (50m+) GPU 부하 비교: LOD 0: ████████████████████ 100% LOD 1: █████ 25% LOD 2: █ 5% LOD 3: ▏ 0.5%

Part 2. 전통적인 LOD의 문제

LOD만 있으면 되는거 아냐?

문제 1: 모든 LOD를 메모리에 들고 있어야 함

문제 2: LOD 전환 시 "팝핑" 현상

문제 1 - 메모리: 캐릭터 1개의 메시 메모리: ├─ LOD 0: 10MB ├─ LOD 1: 3MB ├─ LOD 2: 1MB └─ LOD 3: 0.2MB ──────────────── 총 14.2MB (한 캐릭터에!) 화면에 캐릭터 100명이면? → 1,420MB = 1.4GB! 문제 2 - 팝핑 현상: 프레임 N: 고품질 메시 ████████ 프레임 N+1: 저품질 메시 ▓▓▓▓ └── 갑자기 바뀌어서 눈에 띔! (팝핑)

Part 3. 메시 스트리밍이란?

그래서 메시 스트리밍이 뭔데?

핵심 아이디어: 필요한 LOD만 그때그때 로드

모든 LOD를 메모리에 들고 있지 않고, 현재 필요한 것만 로드

전통 방식 vs 메시 스트리밍: 전통 방식 (모두 로드): ┌─────────────────────────────────────┐ │ LOD0 LOD1 LOD2 LOD3 │ ← 전부 메모리에 │ 10MB 3MB 1MB 0.2MB │ └─────────────────────────────────────┘ 메모리: 14.2MB 메시 스트리밍 (필요한 것만): ┌───────────────┐ │ LOD 1 │ ← 현재 거리에서 필요한 것만! │ 3MB │ └───────────────┘ 메모리: 3MB (78% 절약!) 거리 변경 시: Player 접근 → LOD 0 스트리밍 요청 → 로드 완료 → LOD 전환 (비동기로 미리 로드)

Part 4. 스트리밍 풀과 우선순위

어떤 메시를 먼저 로드해?

우선순위 시스템으로 결정:

우선순위 계산 공식: Priority = (화면 크기) × (중요도) / (이미 로드된 LOD 품질) 화면 크기: 해당 오브젝트가 화면에서 차지하는 픽셀 수 중요도: 플레이어 캐릭터 > NPC > 배경 오브젝트 이미 로드된 LOD: 현재 로드된 것과 필요한 것의 차이 예시: ┌────────────────────────────────────────────────────┐ │ 오브젝트 │ 화면크기 │ 중요도 │ 우선순위 │ ├────────────────────────────────────────────────────┤ │ 플레이어 캐릭터 │ 10000px │ 1.0 │ HIGH │ │ 카메라 앞 NPC │ 5000px │ 0.8 │ HIGH │ │ 멀리 있는 건물 │ 500px │ 0.3 │ LOW │ │ 배경 나무들 │ 100px │ 0.1 │ LOWEST │ └────────────────────────────────────────────────────┘ 스트리밍 순서: 플레이어 → NPC → 건물 → 나무

Part 5. 부드러운 LOD 전환

팝핑 현상은 어떻게 해결해?

크로스 페이드 (Dithering) 또는 모핑 사용

1. 디더링 크로스 페이드: LOD 0: ████████████████████ (100% 불투명) LOD 1: ░░░░░░░░░░░░░░░░░░░░ (0% 불투명) ↓ 전환 중... LOD 0: ██████████░░░░░░░░░░ (50%) LOD 1: ░░░░░░░░░░██████████ (50%) ↓ 전환 완료 LOD 0: ░░░░░░░░░░░░░░░░░░░░ (0%) LOD 1: ████████████████████ (100%) → 두 메시를 동시에 그리면서 알파 블렌딩 → 부드럽지만 일시적으로 Draw Call 2배 2. 버텍스 모핑 (Unreal의 방식): LOD 0의 버텍스 위치 → LOD 1의 버텍스 위치로 보간 → 하나의 메시만 그리면서 부드럽게 변형 → 더 효율적이지만 구현 복잡

Part 6. Unreal Engine 구현

실제로 어떻게 설정해?

Unreal Engine의 Static Mesh LOD 설정:

// Static Mesh LOD 설정 (에디터) LOD Settings: ├─ Auto Compute LOD Distances: ✓ │ → 화면 크기 기반 자동 계산 │ ├─ LOD 0 Screen Size: 1.0 (거의 화면 전체) ├─ LOD 1 Screen Size: 0.5 (화면의 절반) ├─ LOD 2 Screen Size: 0.25 (화면의 1/4) ├─ LOD 3 Screen Size: 0.1 (화면의 1/10) │ └─ Streaming: ├─ Never Stream: ✗ (스트리밍 활성화) ├─ Streaming Distance Multiplier: 1.0 └─ LOD for Collision: 0 (콜리전은 항상 LOD0)
// 블루프린트에서 LOD 강제 설정 // 특정 오브젝트의 LOD 강제 지정 StaticMeshComponent->SetForcedLodModel(2); // LOD 전환 거리 커스텀 StaticMeshComponent->SetLODScreenSizeForLODLevel(1, 0.3f); // 스트리밍 우선순위 높이기 StaticMeshComponent->SetStreamingDistanceMultiplier(2.0f);

Part 7. HLOD (Hierarchical LOD)

건물들이 아주 많으면 어떻게 해?

HLOD: 여러 오브젝트를 하나로 합쳐서 LOD 처리

일반 LOD (개별 처리): ┌───┐ ┌───┐ ┌───┐ ┌───┐ │나무│ │나무│ │나무│ │나무│ ← 멀리서도 4개 각각 처리 └───┘ └───┘ └───┘ └───┘ → Draw Call 4개 HLOD (묶어서 처리): 가까이: ┌───┐ ┌───┐ ┌───┐ ┌───┐ ← 개별 나무 렌더링 └───┘ └───┘ └───┘ └───┘ Draw Call 4개 멀리: ┌─────────────────────┐ ← 하나로 합친 HLOD 메시 │ 숲 전체 │ Draw Call 1개! └─────────────────────┘ HLOD 빌드 과정: 1. 가까운 오브젝트들을 그룹으로 묶음 2. 각 그룹의 저품질 메시를 하나로 병합 3. 멀리서는 병합된 메시만 렌더링 4. 가까워지면 개별 메시로 전환

핵심 정리

  • LOD: 거리에 따라 다른 품질의 메시 사용
  • 메시 스트리밍: 필요한 LOD만 그때그때 로드
  • 우선순위: 화면 크기 × 중요도로 로드 순서 결정
  • 크로스 페이드/모핑: 팝핑 없이 부드러운 전환
  • HLOD: 여러 오브젝트를 하나로 합쳐 최적화
