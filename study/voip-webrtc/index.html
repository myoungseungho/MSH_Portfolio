Discord는 어떻게 실시간으로 목소리를 보내요?

VoIP와 WebRTC - 인터넷으로 목소리 보내는 법

Part 1. 전화랑 뭐가 달라?

친구랑 게임하면서 디스코드로 통화해본 적 있어?

당연히 있지! 롤 하면서 "여기로 와!" 하고 소리 지르잖아.

근데 신기하지 않아? 전화번호도 없이 어떻게 목소리가 실시간으로 가는 거지?

음... 인터넷으로 가니까?

그래. 근데 어떻게? 카카오톡 문자도 인터넷으로 가는데, 왜 음성은 실시간이 가능해?

한번 생각해 보자.

카카오톡 메시지는:

나 → 카카오 서버 → 친구 "뭐해?" 라는 3글자를 보내면 서버가 받아서 → 저장하고 → 친구에게 전달 몇 초 걸려도 상관없어 어차피 텍스트잖아

근데 음성 통화는?

나: "안녕~" → ??? → 친구 귀 0.1초 안에 도착해야 해 늦으면 대화가 이상해짐 "안녕~" (0.5초 후) "어... 뭐라고?" 이러면 대화가 안 돼!
아... 그럼 서버 거치면 느려지겠네?

정확해! 그래서 두 가지 선택지가 있어:

방법 장점 단점
서버 경유 연결 쉬움 느림, 서버 비용
직접 연결 (P2P) 빠름! 연결 어려움

음성 통화에서 가장 중요한 게 뭐야?

빠른 거... 실시간이어야 하니까?

맞아! 그래서 음성 통화는 P2P (Peer-to-Peer) 직접 연결을 선호해.

서버 경유: 나 ----→ 서버 ----→ 친구 50ms 50ms 총 100ms 지연 P2P 직접 연결: 나 ←=========→ 친구 40ms 총 40ms 지연!

근데 여기서 문제가 생겨...

Part 2. 직접 연결이 왜 어려워?

직접 연결하면 되지, 뭐가 어려워?

집에 컴퓨터가 있잖아. 친구 컴퓨터랑 직접 연결하려면 뭐가 필요해?

IP 주소?

맞아. 근데 너 집 컴퓨터 IP 주소가 뭐야?

네 컴퓨터 IP: 192.168.0.10 ...잠깐, 이거 친구도 똑같은 IP일 수 있는데?
어? 왜 같아?

이게 바로 NAT (공유기) 문제야!

🏠 비유: 아파트 주소

인터넷은 아파트 단지 같아.

공인 IP = 아파트 단지 주소 (예: 서울시 강남구 ...)
사설 IP = 동/호수 (예: 101동 1502호)

외부에서 "101동 1502호로 와!" 해봐야...
어느 아파트 단지인데? 알 수가 없어!
현실: 너네 집 친구네 집 ┌─────────────────┐ ┌─────────────────┐ │ 너: 192.168.0.10│ │친구: 192.168.0.5│ │ │ │ │ │ │ │ [공유기] │ │ [공유기] │ │ 공인IP: 1.2.3.4 │ 공인IP: 5.6.7.8 └────────┼────────┘ └────────┼────────┘ │ │ └──────── 인터넷 ────────────────┘ 너: "192.168.0.5로 연결!" 친구: "그게 어딘데? 우리 집에도 192.168.0.5 있는데?"
그럼 공인 IP를 알면 되는 거 아냐?

맞아! 근데 내가 내 공인 IP를 모른다는 게 문제야.

공유기 뒤에 숨어있으니까 내 컴퓨터는 "나는 192.168.0.10이야" 라고만 알아.

그래서 누군가가 "네 진짜 IP는 이거야" 라고 알려줘야 해.

누가 알려줘?

STUN 서버가 알려줘!

STUN = "네 공인 IP 알려주는 서버" 나 ----→ STUN 서버: "내 IP가 뭐야?" STUN ----→ 나: "너 공인 IP는 1.2.3.4:12345야" 이제 나는 이 정보를 친구에게 알려줄 수 있어!

구글이 무료 STUN 서버를 운영해: stun:stun.l.google.com:19302

오 그럼 해결된 거네?

아직 아니야. 어떤 공유기는 너무 까다로워서 STUN으로도 안 돼.

이럴 때는 어쩔 수 없이 TURN 서버가 중계해줘야 해.

TURN = "어쩔 수 없을 때 중계해주는 서버" 나 ----→ TURN ----→ 친구 P2P는 아니지만, 최소한 연결은 됨! 연결 성공률: - STUN만: ~85% - STUN + TURN: ~99%

Part 3. 연결은 됐는데, 목소리를 어떻게 보내?

연결됐으면 목소리 보내면 되는 거 아냐?

목소리가 뭔지부터 생각해보자.

마이크에 "안녕~" 하고 말하면 뭐가 나올까?

음... 소리?

컴퓨터가 이해하는 건 숫자야.

"안녕~" 하고 말하면: 마이크가 1초에 48,000번 소리를 측정해 (48kHz) ↓ 숫자로 변환 [1234, -567, 890, -1234, 567, ...] ↓ 1초 데이터 크기 2바이트 x 48,000개 = 96,000 바이트 = 768 kbps
768 kbps면... 많은 거야?

꽤 많아. 4명이 동시에 말하면 3 Mbps야.

인터넷 느린 친구는 끊길 수 있어.

그래서 압축이 필요해!

어떻게 압축해?

Opus라는 코덱을 써.

Opus 압축: 원본: 768 kbps (엄청 큼!) ↓ 압축 후: 24 kbps (32배 줄어듦!) 근데 품질은? - 6-12 kbps: 알아는 들음 - 16-24 kbps: 디스코드 수준 (충분!) - 64 kbps 이상: 음악 스트리밍 품질

디스코드는 보통 24 kbps 정도야. 768을 24로 줄이면서도 목소리는 선명해!

와 32배나 줄어들어? 어떻게 가능해?

사람 목소리의 특성을 이용해:

1. 사람은 모든 주파수를 듣지 않아 - 20Hz~20kHz가 가청 범위 - 목소리는 주로 85Hz~3kHz - 나머지는 버려도 됨! 2. 연속된 소리는 비슷해 - "아~~~" 하면 비슷한 패턴 반복 - 변화량만 저장해도 됨! 3. 조용한 구간은 거의 안 보내 - 말 안 할 때는 데이터 X

Part 4. 이걸 합치면? WebRTC!

STUN, TURN, Opus... 이걸 다 직접 구현해야 해?

아니! 이걸 전부 묶어서 쓰기 쉽게 만든 게 WebRTC야.

WebRTC = Web Real-Time Communication ┌────────────────────────────────────────┐ │ WebRTC │ │ ┌──────────┬──────────┬──────────┐ │ │ │ STUN │ TURN │ Opus │ │ │ │ (IP확인) │ (중계) │ (압축) │ │ │ └──────────┴──────────┴──────────┘ │ │ │ │ + 암호화 (보안) │ │ + 에코 제거 │ │ + 노이즈 제거 │ └────────────────────────────────────────┘ 브라우저에 이미 내장되어 있어!
브라우저에 내장? 그럼 설치 안 해도 돼?

맞아! 그래서 디스코드 웹 버전이 가능한 거야.

설치 없이 브라우저에서 바로 음성 통화!

그럼 Discord도 WebRTC 써?

Discord, Zoom, Google Meet... 다 WebRTC 기반이야.

실제 서비스들: Discord: WebRTC + 자체 서버 (SFU) Zoom: WebRTC + 자체 서버 Meet: 순수 WebRTC 게임: WebRTC 또는 미들웨어 (Vivox, Photon) "SFU"가 뭐냐면...

Part 5. 게임에서는 어떻게 써?

게임 음성 채팅도 P2P야?

경우에 따라 다른데, 대부분 게임은 서버 중계 (SFU) 방식을 써.

어? P2P가 빠르다면서 왜?

좋은 질문이야! 4명이 음성 채팅한다고 생각해봐.

P2P 풀 메시 (모두가 모두와 연결): A ←───→ B ↑ ╲ ╱ ↑ │ ╳ │ ↓ ╱ ╲ ↓ C ←───→ D 연결 수 = 4명 × 3 ÷ 2 = 6개 연결! 10명이면? 45개 연결! 업로드도 3배로 해야 함 (A→B, A→C, A→D)

연결이 너무 많아져!

그래서 서버를 거치는 거구나?

맞아! SFU (Selective Forwarding Unit) 방식:

SFU 서버 방식: ┌──────────┐ ┌───┤ Voice ├───┐ │ │ Server │ │ │ └────┬─────┘ │ │ │ │ A B C - 각자 서버로 1번만 업로드 - 서버가 다른 사람들에게 전달 - 연결 수 = 인원수 × 1 장점: - 녹음 가능 (신고 시스템!) - 관리 쉬움 - 욕설 차단 가능

Valorant, League of Legends, Fortnite 다 이 방식이야.

근접 음성 채팅은 어떻게 해? Fortnite에서 가까이 가면 들리잖아

3D 공간 오디오야!

근접 음성 (Proximity Voice): 거리에 따라 볼륨 조절: 5m 이내: 100% 볼륨 5~30m: 거리에 비례해서 감소 30m 이상: 0% (안 들림) 방향도 반영: 왼쪽에 있으면 → 왼쪽 스피커에서 크게 오른쪽에 있으면 → 오른쪽 스피커에서 크게

VRChat 같은 메타버스 게임에서는 필수 기능이야!

Part 6. 지연은 얼마나 생겨?

말하고 상대방이 듣기까지 얼마나 걸려?
음성 채팅 지연 분해: 1. 마이크 캡처 10~20ms 2. Opus 압축 5~20ms 3. 네트워크 전송 20~100ms (지역/서버 위치) 4. 버퍼링 20~60ms 5. 디코딩 5ms 6. 스피커 재생 10~20ms ───────────────────────────── 총합: 70~225ms 좋은 환경: 70~100ms (자연스러운 대화) 나쁜 환경: 200ms+ (대화 어색함)
전화는 얼마나 걸려?

일반 전화: 150~300ms

VoLTE: 100~150ms

잘 만든 VoIP가 전화보다 빠를 수 있어!

📌 핵심 정리: VoIP와 WebRTC

  • P2P - 서버 없이 직접 연결하면 빠르다
  • STUN - "네 공인 IP 알려줄게" (공유기 문제 해결)
  • TURN - 직접 연결 안 되면 중계해줌
  • Opus - 768kbps → 24kbps로 32배 압축
  • WebRTC - 위 기술 전부 묶은 패키지 (브라우저 내장)
  • SFU - 게임은 서버 중계 방식 선호 (관리 용이)
  • 지연 - 70~100ms면 자연스러운 대화 가능
