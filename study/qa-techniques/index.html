QA 기법 카탈로그 — 다른 분야는 어떻게 검증하나

제일 어려운 건 "돌리기"가 아니라 "정답을 아는 것" — 그리고 그걸 다루는 무기들

★ 제일 중요한 본질 — 오라클 문제 (the oracle problem)

테스트에서 가장 어려운 건 코드를 돌리는 것이 아니라, 나온 결과가 맞는지 아는 것이다.

계산기에 7×8을 넣어 56이 나왔다. 근데 56이 맞다는 걸 어떻게 아나? 내가 정답을 미리 알아야(=오라클) 채점이 된다.

답을 안 정해두면 테스트는 "뭔가 나왔네"에서 끝난다. 좋은 QA = 돌리기 전에 "정답을 어디서 가져올지" 먼저 정하는 것. (사람·옛버전·물리법칙·불변식)

Part 1. 다른 분야는 어떻게 검증하나

소프트웨어 말고 자동차·의료 같은 데선 QA를 어떻게 해?

이름과 도구만 다르지 "비교 기준을 먼저 두고 어긋남을 잡는다"는 본질은 똑같습니다.

분야방법핵심 아이디어
자동차/항공충돌시험 + FMEA(고장모드 영향분석)"이 부품이 망가지면 뭐가 터지나"를 표로 전수
의료/제약임상시험 (대조군 + 위약 + 통계)약 준 그룹 vs 안 준 그룹을 비교해 차이가 진짜인지
반도체/하드웨어번인 / 스트레스 테스트일부러 뜨겁게·오래 돌려 약한 놈을 미리 골라냄
금융/회계대사(reconciliation) + 감사양쪽 장부 합이 같아야 한다(불변식)

FMEA = 장난감 부품마다 "이게 빠지면 어떻게 되지?"를 하나하나 적어보는 것.

임상시험 = 한 반엔 새 간식, 다른 반엔 원래 간식을 주고 차이가 진짜인지 비교하는 것.

회계 대사 = 내 용돈기입장 합 = 실제 지갑 돈. 안 맞으면 어딘가 샌 거다.

Part 2. 테스트 기법 카탈로그 — 이름붙은 무기들

소프트웨어에서 실제로 쓰는 "기법"들엔 뭐가 있어?

크게 똑똑하게 줄이기, 컴퓨터로 넓히기, 기준 두고 어긋남 잡기 세 묶음입니다.

1. 경계값 분석 줄이기

버그는 경계에 산다. 0, 1, 최대, 최대+1을 노린다.
놀이기구 키 제한 120cm → 100·150 말고 119·120·121로. (< 인지 <= 인지가 거기서 갈린다)

2. 동치 분할 줄이기

같은 무리로 처리되는 값은 하나만 대표로 테스트.
1~10이 다 똑같이 처리되면 10개 다 말고 5 하나만. (단, 그 무리가 진짜 같은지 먼저 확인)

3. 블랙박스 vs 화이트박스 관점

속을 모르고 입출력만 보나(블랙), 코드 분기를 다 까보고 모든 갈림길을 한 번씩 타나(화이트).
블랙 = "동전 넣으니 콜라 나오네". 화이트 = if(이미 보유) 가지를 직접 열어 확인 — 우리가 둔갑 버그를 잡은 방식.

4. 속성 기반 테스트 (Property-based) 넓히기

케이스를 하나하나 적는 대신 "항상 성립해야 할 규칙"을 적고 컴퓨터가 수천 개를 자동 생성해 던진다.
"리스트를 정렬하면 항상 오름차순이고 개수는 그대로다" → 별별 리스트 1만 개로 자동 공격. (우리 8축의 상위 개념)

5. 퍼징 (Fuzzing) 넓히기

이상한 입력을 마구 던져 깨지나 본다.
글자수 칸에 이모지·100만 글자·빈값·음수를 넣어 크래시 나나. (예상 못한 입력이 사고 원흉)

6. 메타모픽 테스트 (Metamorphic) 정답 몰라도

정답은 몰라도 관계는 알 때, 그 관계로 채점.
"사진을 좌우로 뒤집어도 고양이는 고양이여야 한다." 결과값 말고 입력↔출력 관계로 검증.

7. 차등 테스트 (Differential) 기준 두기

두 개를 같은 입력에 돌려 결과를 비교.
옛 버전 vs 새 버전(또는 A구현 vs B구현)에 똑같은 입력 → 결과가 다르면 둘 중 하나가 버그. 리뉴얼 회귀를 잡는 핵심.

8. 불변식 (Invariant) 기준 두기

어떤 경우에도 깨지면 안 되는 규칙.
"거래 전후 두 사람 돈 총합은 불변." 깨지면 무조건 사고(복제/증발). 상황 100개 안 적어도 이 규칙 하나가 다 잡는다.

9. 회귀 테스트 (Regression) 기준 두기

고친 게 옛것을 안 깼는지 매번 재확인. 한 번 통과한 케이스를 모아 자동으로 반복.

Part 3. '상황'과 '가설'을 잘 세우는 법

기법은 알겠는데, 애초에 "어떤 상황을 테스트할지"는 어떻게 잘 떠올려?

좋은 테스트는 좋은 가설에서 나옵니다. 가설 = "이 상황에선 X가 망가질 것이다"라는 적대적 추측입니다. 세 질문으로 뽑습니다:

① "이게 어떻게 깨질 수 있지?" — 통과시키려 하지 말고 부수려고 본다.

② "정답을 어디서 가져오지?" — 오라클을 먼저 정한다(사람·옛버전·불변식·물리법칙).

③ "내가 안 해본 상황은?" — 경계·중복·동시·이상입력. (체크리스트의 축이 이걸 강제로 떠올리게 한다)

좋은 QA는 자물쇠 장수가 아니라 도둑처럼 생각한다. "어떻게 잠그지"가 아니라 "어떻게 따지"를 먼저 묻는다. 부수는 사람의 마음으로 봐야 부서질 곳이 보인다.

한 줄 정리

  • 제일 어려운 건 돌리기가 아니라 정답을 아는 것(오라클 문제).
  • 다른 분야(자동차·의료·반도체·금융)도 본질은 "기준 두고 어긋남 잡기"로 같다.
  • 무기는 세 묶음: 줄이기(경계값·동치분할), 넓히기(속성기반·퍼징·메타모픽), 기준 두기(차등·불변식·회귀).
  • 가설은 "부수려는" 마음에서 나온다 — 도둑처럼 생각하라.
