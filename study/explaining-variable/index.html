Part 1. 설명하는 변수가 뭐야?

복잡한 조건문이 뭔 말인지 모르겠어.

그 조건식의 의도를 담은 변수로 빼.

이름만 봐도 뭘 하려는지 알게 만드는 거야.

예를 들면?

if (player.hp > 0 && !player.isStunned && player.mp >= skill.cost)

이거 뭔 조건인지 바로 알아?

bool canUseSkill = ...로 빼면 if (canUseSkill)만 봐도 이해돼.

수학 공식 비유

x = (-b ± √(b²-4ac)) / 2a 를 계산할 때,
discriminant = b² - 4ac 로 먼저 빼두잖아.

복잡한 계산에 의미 있는 이름을 붙이는 것. 같은 거야.

Part 3. 언제 쓰면 좋아?

모든 조건문에 변수 빼야 해?

아니, 과하면 역효과야.

Explaining Variable 적용 기준

적용해야 할 때:
- 조건문이 3개 이상 조합
- 계산이 여러 단계
- 한 눈에 의도 파악 불가

불필요할 때:
- 단순한 null 체크
- 이미 명확한 비교
변수 이름은 어떻게 지어?

의도를 담아. "무엇을 하려는가"로.

isValidTarget, hasEnoughResource, canProceed 같은 식으로.

Part 4. 주의할 점

변수 많아지면 오히려 복잡해지지 않아?

그래서 균형이 필요해:

주의사항

1. 변수 과다 - 설명 변수가 10개면 차라리 메서드 분리
2. 이름 중복 - isValid, isOk, canDo가 다 있으면 혼란
3. 범위 주의 - 그 블록에서만 의미 있는 이름인지 확인
Extract Method랑 같이 쓰기도 해?

자주 같이 써.

복잡한 조건을 설명 변수로 빼고,

그 검증 로직 자체를 메서드로 추출하기도 해.

핵심 정리: Explaining Variable

  • 정의: 복잡한 표현식에 의미 있는 이름 부여
  • 목적: 가독성 향상, 의도 명확화
  • 이름: "무엇을 하려는가"로 짓기
  • 주의: 너무 많으면 메서드 추출 고려
  • 조합: Extract Method와 함께 쓰면 효과적
