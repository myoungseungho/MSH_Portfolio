메시 압축과 Quantization

버텍스 데이터를 압축하여 메모리와 대역폭 절약

Part 1. 개념: 메시 압축이란?

메시 압축이 뭐야?

3D 메시의 버텍스 데이터를 더 작은 용량으로 저장하는 기술입니다.

일반적인 메시는 버텍스당 위치(12B), 노말(12B), UV(8B), 탄젠트(16B) 등 40~60바이트를 사용합니다. 압축을 통해 이를 절반 이하로 줄일 수 있습니다.

Quantization은 뭐야?

연속적인 값(float)을 이산적인 값(정수)으로 변환하는 것입니다.

┌─────────────────────────────────────────────────────────────────┐
│                     Quantization 개념                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  [원본 데이터 - Float32]                                        │
│                                                                 │
│    Position: (1.234567f, -0.987654f, 2.345678f)  = 12바이트     │
│    Normal:   (0.577350f, 0.577350f, 0.577350f)   = 12바이트     │
│                                                                 │
│  [Quantization 후 - Int16]                                      │
│                                                                 │
│    Position: (40210, -32178, 76395) → 역변환 가능  = 6바이트    │
│    Normal:   (18918, 18918, 18918)  → 역변환 가능  = 6바이트    │
│                                                                 │
│  변환 공식:                                                     │
│    quantized = round((value - min) / (max - min) * 65535)       │
│    restored  = quantized / 65535 * (max - min) + min            │
│                                                                 │
│  결과: 24바이트 → 12바이트 (50% 절약)                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

정밀도가 약간 손실되지만, 시각적으로 구분하기 어려운 수준입니다.

┌─────────────────────────────────────────────────────────────────┐
│                  일반적인 버텍스 구조 (풀 정밀도)                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  struct Vertex {                                                │
│      Vector3 position;    // 12 bytes (float × 3)               │
│      Vector3 normal;      // 12 bytes (float × 3)               │
│      Vector4 tangent;     // 16 bytes (float × 4)               │
│      Vector2 uv0;         //  8 bytes (float × 2)               │
│      Vector2 uv1;         //  8 bytes (float × 2) - 라이트맵    │
│      Color32 color;       //  4 bytes (byte × 4)                │
│      // ─────────────────────────────────                       │
│      // Total: 60 bytes per vertex                              │
│  };                                                             │
│                                                                 │
│  스키닝 메시 추가:                                              │
│      BoneWeight weights;  // 16 bytes (4 weight + 4 index)      │
│      // ─────────────────────────────────                       │
│      // Total: 76 bytes per vertex                              │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│  예시: 10,000 버텍스 캐릭터                                     │
│    압축 전: 10,000 × 76 = 760KB                                 │

Part 2. 왜 필요해?

메시 압축 없으면 어떤 문제가 생겨?

📦 메모리 부담

  • 캐릭터 1개 메시: 500KB ~ 2MB
  • 화면에 50개 캐릭터 → 최대 100MB
  • 배경 메시, UI 메시 추가 → 메모리 초과

🔄 대역폭 병목

  • CPU → GPU 데이터 전송 병목
  • 버텍스 버퍼가 크면 Draw Call 비용 증가
  • 모바일 GPU는 메모리 대역폭이 제한적

⏱️ 로딩 시간

  • 디스크에서 읽는 시간 증가
  • 압축 해제 후 GPU 업로드 지연
  • 스트리밍 로딩 시 버퍼링 문제
어떤 상황에서 특히 중요해?

1. 모바일 게임

  • 메모리 제한이 엄격함 (1~2GB 전체)
  • 발열/배터리 → 대역폭 줄여야 함

2. 오픈월드 게임

  • 동시 로드 메시가 수천 개
  • 스트리밍 시스템 효율 필수

3. VR/AR

  • 90Hz+ 유지해야 함 → 대역폭 여유 필요
  • 양안 렌더링으로 Draw Call 2배

4. 군중 시뮬레이션

  • 수백~수천 캐릭터 동시 렌더
  • 인스턴싱과 함께 압축 필수

스크립트로 버텍스 포맷 제어하려면?
using UnityEngine; using UnityEngine.Rendering; public class OptimizedMeshCreator { public static Mesh CreateCompressedMesh(Mesh sourceMesh) { var optimizedMesh = new Mesh(); optimizedMesh.name = sourceMesh.name + "_Compressed"; // 버텍스 어트리뷰트 정의 (압축 포맷 지정) var attributes = new[] { // Position: Float32 → Float16 (정밀도 필요 시 유지) new VertexAttributeDescriptor( VertexAttribute.Position, VertexAttributeFormat.Float16, 3 // dimension ), // Normal: Float32 → SNorm8 (8비트 정규화) new VertexAttributeDescriptor( VertexAttribute.Normal, VertexAttributeFormat.SNorm8, 4 // 4바이트 정렬 ), // UV0: Float32 → Float16 new VertexAttributeDescriptor( VertexAttribute.TexCoord0, VertexAttributeFormat.Float16, 2 ), // Tangent: Float32 → SNorm8 new VertexAttributeDescriptor( VertexAttribute.Tangent, VertexAttributeFormat.SNorm8, 4 ) }; // 버텍스 버퍼 설정 optimizedMesh.SetVertexBufferParams(sourceMesh.vertexCount, attributes); // 데이터 복사 (자동 변환) optimizedMesh.vertices = sourceMesh.vertices; optimizedMesh.normals = sourceMesh.normals; optimizedMesh.uv = sourceMesh.uv; optimizedMesh.tangents = sourceMesh.tangents; optimizedMesh.triangles = sourceMesh.triangles; // 바운드 계산 optimizedMesh.RecalculateBounds(); return optimizedMesh; } }
인덱스 버퍼도 최적화할 수 있어?

네. 16비트 vs 32비트 인덱스를 선택할 수 있습니다:

public static void OptimizeIndexBuffer(Mesh mesh) { // 버텍스 수가 65535 이하면 16비트 인덱스 사용 가능 if (mesh.vertexCount <= 65535) { // 32비트 → 16비트로 변환 (메모리 50% 절약) mesh.indexFormat = IndexFormat.UInt16; } else { // 65535 초과 시 32비트 필수 mesh.indexFormat = IndexFormat.UInt32; } Debug.Log($"Index format: {mesh.indexFormat}, Triangles: {mesh.triangles.Length / 3}"); } /* 예시: 10,000 삼각형 메시 (30,000 인덱스) 32비트: 30,000 × 4 = 120KB 16비트: 30,000 × 2 = 60KB (50% 절약) */

⚠️ 16비트 인덱스 주의

  • 버텍스 수가 65,535개 초과 시 사용 불가
  • 서브메시(재질별 분할) 시에도 합산하여 체크
  • LOD0 메시는 초과하기 쉬우니 확인 필요

│  z                        └───┴───┘                            │

Octahedron Normal 구현은?
// 인코딩: 3D 노말 → 2D 옥타헤드론 Vector2 EncodeOctahedronNormal(Vector3 n) { // 옥타헤드론으로 투영 n /= (Mathf.Abs(n.x) + Mathf.Abs(n.y) + Mathf.Abs(n.z)); // 하반구 처리 (z < 0) if (n.z < 0) { float tx = n.x; n.x = (1 - Mathf.Abs(n.y)) * (tx >= 0 ? 1 : -1); n.y = (1 - Mathf.Abs(tx)) * (n.y >= 0 ? 1 : -1); } // [-1, 1] → [0, 1] 정규화 return new Vector2(n.x * 0.5f + 0.5f, n.y * 0.5f + 0.5f); } // 디코딩: 2D 옥타헤드론 → 3D 노말 (셰이더에서) /* half3 DecodeOctahedronNormal(half2 f) { f = f * 2.0 - 1.0; half3 n = half3(f.x, f.y, 1.0 - abs(f.x) - abs(f.y)); half t = saturate(-n.z); n.xy += n.xy >= 0.0 ? -t : t; return normalize(n); } */
탄젠트 공간 압축은?

탄젠트 재계산으로 저장 자체를 없앨 수 있습니다:

// 버텍스 셰이더에서 탄젠트 재계산 // 저장: 노말만 (탄젠트 저장 안 함) // 재계산: 노말 + UV 기울기로 탄젠트 유도 /* HLSL 셰이더 코드: // 월드 공간에서 탄젠트 재계산 float3 CalculateTangent(float3 worldNormal, float2 uv, float3 worldPos) { // 스크린 공간 편미분 사용 float3 dp1 = ddx(worldPos); float3 dp2 = ddy(worldPos); float2 duv1 = ddx(uv); float2 duv2 = ddy(uv); float3 tangent = dp1 * duv2.y - dp2 * duv1.y; tangent = normalize(tangent - worldNormal * dot(worldNormal, tangent)); return tangent; } */ // Unity에서 런타임 탄젠트 재계산 public static void RecalculateTangentsAtRuntime(Mesh mesh) { // 탄젠트 데이터 제거하여 메모리 절약 mesh.tangents = null; // 셰이더에서 ddx/ddy로 재계산하도록 설정 // → 버텍스당 16바이트 절약 }

⚠️ 탄젠트 재계산 주의

  • ddx/ddy는 삼각형 단위로 동일 → 노말맵 seam에서 아티팩트
  • UV가 미러링된 메시에서 문제 발생 가능
  • 고품질 캐릭터에는 사전 계산된 탄젠트 사용 권장

Part 5. Draco 압축

Draco 압축이 뭐야?

Google에서 개발한 3D 메시 압축 라이브러리입니다. 매우 높은 압축률을 제공합니다.

LOD 생성과 압축 자동화는?
#if UNITY_EDITOR using UnityEditor; public class LODMeshOptimizer { [MenuItem("Assets/Optimize LOD Meshes")] public static void OptimizeSelectedLODs() { foreach (var obj in Selection.gameObjects) { var lodGroup = obj.GetComponent<LODGroup>(); if (lodGroup == null) continue; var lods = lodGroup.GetLODs(); for (int i = 0; i < lods.Length; i++) { OptimizeLODLevel(lods[i], i, lods.Length); } } AssetDatabase.SaveAssets(); } private static void OptimizeLODLevel(LOD lod, int level, int totalLevels) { foreach (var renderer in lod.renderers) { var meshFilter = renderer.GetComponent<MeshFilter>(); if (meshFilter == null || meshFilter.sharedMesh == null) continue; var mesh = meshFilter.sharedMesh; var assetPath = AssetDatabase.GetAssetPath(mesh); // ModelImporter 설정 변경 var importer = AssetImporter.GetAtPath(assetPath) as ModelImporter; if (importer == null) continue; // LOD 레벨에 따른 압축 설정 float lodRatio = (float)level / (totalLevels - 1); if (lodRatio < 0.3f) // LOD 0 { importer.meshCompression = ModelImporterMeshCompression.Low; } else if (lodRatio < 0.7f) // 중간 LOD { importer.meshCompression = ModelImporterMeshCompression.Medium; importer.importTangents = ModelImporterTangents.None; } else // 먼 LOD { importer.meshCompression = ModelImporterMeshCompression.High; importer.importTangents = ModelImporterTangents.None; importer.importNormals = ModelImporterNormals.Calculate; } importer.SaveAndReimport(); Debug.Log($"Optimized LOD {level}: {mesh.name}"); } } } #endif

메시 압축 적용 시 체크리스트는?

⚠️ 압축 전 확인

  • [ ] 원본 메시 백업 (FBX/원본 유지)
  • [ ] 타겟 플랫폼별 테스트 환경 준비
  • [ ] 비주얼 품질 비교 기준 설정
  • [ ] 스키닝/애니메이션 호환성 확인

📋 적용 체크리스트

  • [ ] 인덱스 포맷: 65535 이하면 16비트
  • [ ] Position: Float16 (작은 오브젝트) 또는 Float32 (큰 환경)
  • [ ] Normal: SNorm8 또는 Octahedron
  • [ ] Tangent: 필요 시만 저장, 아니면 셰이더 계산
  • [ ] UV: Float16 (대부분 충분)
  • [ ] Color: 이미 압축됨, 필요 없으면 제거
  • [ ] LOD별: 멀수록 더 강한 압축

핵심 정리

  • Quantization = Float32 → 더 작은 정수형으로 변환 (정밀도 손실 감수)
  • Unity Mesh Compression은 디스크 크기만 줄임 (런타임 X)
  • Vertex Compression으로 런타임 메모리 절약
  • 인덱스 버퍼: 버텍스 65535 이하면 16비트 사용
  • 노말 압축: SNorm8 또는 Octahedron 인코딩
  • 탄젠트: 필요 없으면 제거, 셰이더에서 재계산
  • Draco: 80~95% 압축률, 디코딩 비용 있음
  • LOD별 전략: 먼 거리일수록 더 강한 압축
