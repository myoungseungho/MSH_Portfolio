어떤 스레드가 뭘 하는지 모르겠어요

Threads 창 — 멀티스레드 디버깅의 시작점

핵심 단축키

Threads 창 열기 Ctrl + Alt + H
Parallel Stacks 창 Ctrl + Shift + D, S
Parallel Watch 창 Ctrl + Shift + D, 1

Part 1. 왜 멀티스레드 디버깅이 어려운가

스레드가 여러 개인데 어디서 뭘 하는지 모르겠어

멀티스레드 디버깅이 어려운 이유:

1. 중단점에서 멈추면 모든 스레드가 멈춤 - 어떤 스레드가 뭘 하고 있었는지?

2. 콜스택은 현재 스레드만 - 다른 스레드 상태는?

3. 실행 순서가 매번 다름 - 재현이 어려움

그래서 뭘 써야 해?

Threads 창이 답이다. Debug → Windows → Threads (Ctrl+Alt+H)

모든 스레드의 상태를 한눈에 볼 수 있다.

Part 2. Threads 창 읽는 법

Threads 창 예시: ID Name Location Priority ───────────────────────────────────────────────────────────────────── ▶ 1234 MainThread CGameManager::OnTick() Normal 5678 WorkerThread#1 CPacketHandler::Process() Normal 9012 WorkerThread#2 WaitForSingleObject Normal 3456 DBThread CSQLConnection::Execute() AboveNormal 7890 LogThread CLogger::Flush() BelowNormal ▶ = 현재 보고 있는 스레드 (노란 화살표)
컬럼 의미
ID 스레드 ID (GetCurrentThreadId()와 동일)
Name 스레드 이름 (SetThreadDescription으로 설정)
Location 현재 실행 중인 함수 (가장 중요!)
Priority 스레드 우선순위

Part 3. 스레드 전환하기

다른 스레드의 콜스택을 보고 싶어

Threads 창에서 원하는 스레드를 더블클릭하면 그 스레드로 전환된다.

→ Call Stack 창이 해당 스레드의 콜스택으로 바뀜

→ Locals/Watch 창도 해당 스레드 컨텍스트로 바뀜

// 시나리오: WorkerThread에서 크래시 발생 // 1. 크래시 발생 → 디버거에서 멈춤 // 2. Threads 창 열기 (Ctrl+Alt+H) // 3. Location 컬럼 확인 → 어떤 스레드가 문제 함수에 있는지 // 4. 해당 스레드 더블클릭 // 5. Call Stack 창에서 전체 호출 경로 확인 // 6. 변수 값 분석

Part 4. 스레드 플래그 설정

특정 스레드만 집중해서 보고 싶어

Threads 창에서 스레드 우클릭 → Flag

플래그 설정된 스레드만 필터링해서 볼 수 있다.

기능 방법 용도
플래그 설정 우클릭 → Flag 관심 스레드 표시
플래그만 표시 툴바의 "Show Flagged Only" 많은 스레드 중 관심 있는 것만
이름 지정 우클릭 → Rename 스레드 식별 용이

Part 5. 스레드별 중단점

특정 스레드에서만 중단점이 동작하게 하고 싶어

중단점 우클릭 → Conditions → 필터 또는 조건에 스레드 ID 입력

// 방법 1: 조건으로 필터링 중단점 조건: GetCurrentThreadId() == 5678 // 방법 2: 필터 탭 사용 중단점 → Conditions → Filter ThreadId = 5678 // 방법 3: 스레드 이름으로 (SetThreadDescription 사용 시) ThreadName = "WorkerThread#1"
코드에서 스레드 이름을 지정하려면?
// Windows 10 1607+ / VS2017+ #include <processthreadsapi.h> HRESULT hr = SetThreadDescription( GetCurrentThread(), L"WorkerThread#1" ); // 또는 예전 방식 (VS 전용) #pragma pack(push, 8) struct THREADNAME_INFO { DWORD dwType; // 0x1000 LPCSTR szName; // 스레드 이름 DWORD dwThreadID; // 스레드 ID (-1 = 현재) DWORD dwFlags; // 0 }; #pragma pack(pop) void SetThreadName(DWORD dwThreadID, const char* szName) { THREADNAME_INFO info = { 0x1000, szName, dwThreadID, 0 }; __try { RaiseException(0x406D1388, 0, sizeof(info)/sizeof(ULONG_PTR), (ULONG_PTR*)&info); } __except(EXCEPTION_EXECUTE_HANDLER) {} }

Part 6. 실전: 스레드 상태로 문제 파악

스레드 Location을 보면 뭘 알 수 있어?

Location 컬럼을 보면 각 스레드가 지금 뭘 하고 있는지 바로 알 수 있다:

Location 패턴 의미 상태
WaitForSingleObject 무언가를 기다리는 중 대기 (정상)
Sleep 일정 시간 대기 중 대기 (정상)
recv / WSARecv 네트워크 수신 대기 I/O 대기 (정상)
EnterCriticalSection 락 획득 대기 블로킹 (확인 필요)
NtWaitForWorkViaWorkerFactory 스레드풀 대기 대기 (정상)
실제 비즈니스 함수 실제 작업 중 실행 중
// Deadlock 의심 상황 ID Location ────────────────────────────────────── 1234 EnterCriticalSection (g_csPlayer) ← 락 A 대기 중 5678 EnterCriticalSection (g_csWorld) ← 락 B 대기 중 // 만약 1234가 락 B를 들고 있고, 5678이 락 A를 들고 있다면? // → 서로 기다리면서 영원히 멈춤 = Deadlock!

핵심 정리

  • Threads 창: Ctrl+Alt+H로 열기, 모든 스레드 상태 확인
  • 스레드 전환: 더블클릭으로 해당 스레드 컨텍스트로 이동
  • Location 컬럼: 각 스레드가 지금 뭘 하는지 한눈에
  • 플래그: 관심 스레드만 필터링해서 보기
  • 스레드별 중단점: 조건에 ThreadId 지정
