왜 어떤 게임은 밝은 빛이 진짜 눈부셔 보일까?

Bloom과 HDR 렌더링 - 모니터의 한계를 뛰어넘는 법

Part 1. 실제로 눈이 부셔본 적 있어?

밖에 나가서 태양을 쳐다보면 어때?

당연히 눈이 부셔! 잠깐 보면 눈이 찡그려지고, 잔상도 남아.

그럼 게임에서 태양을 쳐다보면?

음... 그냥 흰색 동그라미?

눈이 부시지는 않아.

근데 어떤 게임은 진짜 눈부셔 보이지 않아? 빛이 막 퍼지고?

아 맞아! 사이버펑크나 엘든 링 같은 게임에서 태양 보면 빛이 퍼져보여.

네온사인도 빛나고.

그 차이가 뭘까?

일단 생각해보자. 모니터가 진짜 밝게 빛날 수 있어?

Part 2. 모니터의 한계

모니터... 밝기 올리면 밝아지긴 하잖아?

그래, 하지만 한계가 있어.

실제 세상의 밝기: 밤하늘 별빛 0.001 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 방 안 조명 100 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 맑은 날 야외 10,000 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 태양 직시 1,000,000,000 (10억!) → 가장 어두운 것과 가장 밝은 것의 차이: 1조 배!
모니터는?
일반 모니터의 밝기: 검정 (꺼진 상태) 0 ━━━━━━━━━━━━━━━━━━━━━━━━━ 흰색 (최대 밝기) 500 정도 → 차이: 약 500배 ... 1조 배 vs 500배? 모니터로 태양 밝기를 표현하는 건 불가능!

모니터 최대 밝기가 500이면, 태양(10억)을 어떻게 표현해?

흰색으로 표현하면 안 돼?

그게 바로 문제야!

현재 방식: 조명 (밝기 100) → 흰색으로 표현 태양 (밝기 10억) → ... 흰색으로 표현 둘 다 똑같이 흰색! 그래서 게임에서 태양이 "그냥 흰 동그라미"로 보이는 거야.

Part 3. 그럼 어떻게 해?

모니터 밝기를 더 높일 수는 없잖아. 방법이 있어?

두 가지를 해야 해:

1. 컴퓨터 안에서는 진짜 밝기를 저장한다

2. 모니터에 보여줄 때 눈속임을 쓴다

진짜 밝기를 저장한다고?

일반적으로 색상은 0~255 사이 숫자로 저장해.

255가 최대 밝기야. 그 이상은 없어.

일반 색상 저장 (8비트): 0 = 검정 128 = 회색 255 = 흰색 (최대!) 태양 밝기 10억? 저장 불가능. 그냥 255로 잘림.
그럼 어떻게 저장해?

숫자 범위를 늘리면 돼! 이게 HDR (High Dynamic Range)야.

HDR 색상 저장 (16비트 float): 0 = 검정 1 = 일반 흰색 100 = 밝은 조명 10,000 = 태양! 제한 없이 밝기 저장 가능!
📊 비유: 시험 점수

일반 (8비트) = 100점 만점 시험
천재가 와도 100점이 최대야.

HDR (16비트) = 점수 제한 없는 시험
천재는 10,000점, 일반인은 50점.
진짜 실력 차이가 드러나!

Part 4. 근데 모니터는 여전히 한계가 있잖아?

컴퓨터 안에서 10,000 밝기로 저장해도, 모니터는 255가 최대잖아?

좋은 질문이야! 그래서 "압축"을 해야 해.

이걸 톤 매핑 (Tone Mapping)이라고 해.

압축이라면... 밝은 것도 어둡게 만든다는 거야?

아니, 더 똑똑하게 해.

톤 매핑 방식: 원래 밝기: 0 1 10 100 1000 10000 │ │ │ │ │ │ ▼ ▼ ▼ ▼ ▼ ▼ 모니터 밝기: 0 0.3 0.5 0.7 0.9 0.99 → 어두운 건 적당히, 밝은 건 많이 압축! → 차이는 유지하면서 범위 안에 들어감

사진 찍을 때 "노출 조절"하는 것과 비슷해.

그러면 태양이 0.99고 조명이 0.7이면... 둘 다 밝은 흰색 아냐?

맞아! 그래서 눈속임이 필요해.

바로 Bloom이야!

Part 5. Bloom - 눈부심을 "연기"하는 법

Bloom이 뭔데?

실제로 눈이 부시면 어떻게 보여?

음... 빛이 퍼져 보여. 주변이 뿌옇게 되고.

바로 그거야!

밝은 물체 주변으로 빛이 "번지는" 효과.

Bloom 효과: Bloom 없음: Bloom 있음: ● ◉ 태양 빛이 퍼짐! (그냥 흰 동그라미) (눈부셔 보임!) 실제 이유: - 눈의 수정체에서 빛이 산란됨 - 카메라 렌즈에서도 마찬가지 - 뇌가 "아 이건 엄청 밝구나" 인식
그럼 Bloom은 어떻게 만들어?

생각보다 간단해!

Bloom 만드는 4단계: 1. 밝은 부분만 찾기 ┌─────────────────┐ │ ○ │ 밝기 1 이상인 픽셀만 추출 │ (태양만 남음) │ └─────────────────┘ 2. 흐리게 만들기 (블러) ┌─────────────────┐ │ ◉ │ 가우시안 블러 적용 │ (빛이 퍼짐) │ 여러 번 반복하면 더 퍼짐 └─────────────────┘ 3. 원본이랑 합치기 ┌─────────────────┐ │ 🏔️ + ◉ │ 원래 장면 + 블러된 밝은 부분 │ (완성!) │ └─────────────────┘
진짜 간단하네?

개념은 간단해. 근데 잘 만들려면 신경 쓸 게 있어.

문제 해결책
블러가 너무 비쌈 해상도 줄여서 블러 (1/2, 1/4 크기)
빛이 너무 퍼짐 여러 단계 블러 합성
어색한 경계 부드러운 임계값 사용

Part 6. 자동 노출 - 동굴에서 나오면 눈부신 이유

게임에서 어두운 동굴에서 밝은 밖으로 나가면 잠깐 눈부시던데?

그것도 HDR 기능이야! 자동 노출 (Auto Exposure).

그건 왜 그래?

실제 눈도 그래. 어두운 곳에 있다가 밝은 곳 가면:

눈의 적응 (명순응/암순응): 동굴 안 (어두움): - 눈 동공: 커짐 (빛 많이 받으려고) - 감도: 높음 동굴 밖 (밝음): - 갑자기 빛이 많이 들어옴! - 눈: "으악 눈부셔!" - 동공이 줄어들 때까지 2~3초 걸림 게임에서도 이걸 시뮬레이션: - 화면 평균 밝기 계산 - 밝으면 노출 낮춤 (어둡게) - 어두우면 노출 높임 (밝게) - 천천히 변화 → 적응하는 느낌!

Part 7. 실제 게임에서는?

실제 게임에서 이걸 다 써?

요즘 웬만한 게임은 다 써!

게임별 HDR/Bloom 활용: 야외 장면: - 태양에 강한 Bloom - 자동 노출로 실내/실외 전환 네온 거리 (사이버펑크): - 네온사인에 Bloom - 배경은 어둡게, 네온만 밝게 폭발 이펙트: - 폭발 중심 = 아주 밝은 값 (100+) - 자연스럽게 Bloom 발생 용암/마법: - 발광 재질에 HDR 값 사용 - Bloom으로 빛나는 느낌
성능은 괜찮아?

Bloom은 생각보다 가벼워!

성능 비용 (1080p 기준): HDR 렌더타겟: 메모리 2배 (16비트) 밝은 부분 추출: 0.1ms 블러 (4단계): 0.3~0.5ms 합성: 0.1ms 자동 노출: 0.1ms ─────────────────────── 총합: 약 0.5~1ms 60fps = 16.6ms이니까 전체의 3~6% 정도!

📌 핵심 정리: Bloom과 HDR

  • 문제 - 모니터는 밝기 표현에 한계가 있음 (255가 최대)
  • HDR - 컴퓨터 안에서 진짜 밝기를 저장 (태양=10,000)
  • 톤 매핑 - HDR을 모니터 범위로 압축 (차이는 유지)
  • Bloom - 밝은 부분 추출 → 블러 → 합성 (눈부심 연출)
  • 자동 노출 - 화면 밝기에 따라 노출 조절 (눈 적응 시뮬레이션)
  • 비용 - 전체 프레임의 3~6% 정도 (저렴함)
