ChatGPT로 살아있는 NPC 만드는 법

LLM이 뭐야?

LLM (Large Language Model) = 대규모 언어 모델

대표적 예: ChatGPT, Claude, Gemini

텍스트를 이해하고 생성하는 인공지능

수능 국어 만점 받을 정도로 똑똑해졌어!

그래서 이걸 게임에 어떻게 써?

핵심 아이디어:

LLM을 TRPG 마스터로 만들자!

1️⃣ TRPG가 뭐야?

TRPG (Table-top Role Playing Game)?

TRPG = 테이블 위에서 하는 롤플레잉 게임

필요한 것:

  • 시스템 룰 (규칙)
  • 대화
  • 주사위

컴퓨터 없이 상상력과 대화로 진행하는 RPG!

🎲 비유: TRPG는 이런 거야

마스터: "당신은 어두운 던전 입구에 서 있습니다."
플레이어: "문을 열어볼게요."
마스터: "주사위를 굴리세요. 10 이상이면 성공입니다."
플레이어: *주사위 굴림* "15 나왔어요!"
마스터: "문이 열리며 안에서 보물상자가 보입니다."

마스터가 스토리를 만들고, 플레이어의 행동에 반응하는 거야!
LLM이 이걸 할 수 있어?

LLM의 장점:

1. 창작 능력 - 새로운 스토리 생성

2. 적응력 - 플레이어 행동에 맞춰 반응

3. 자유도 - 뭘 해도 대응 가능

이거면 매번 새로운 게임 경험을 제공할 수 있어!

2️⃣ 기존 방식들의 문제점

방식 장점 단점
1. 전체 게임을 LLM에게
(AI Dungeon)		 - 가장 직관적
- 무한한 자유도
- 어떤 스토리든 생성 가능 		- 게임 난이도 없음
- 플레이어가 모든 걸 조작 가능
- "갑자기 용을 이겼습니다" 가능
2. NPC 대화만 LLM
(언커버더 스모킹건)		 - 채팅에 최적화됨
- 자연스러운 대화
- 롤 부여 쉬움 		- 몰입감 해칠 수 있음
- 세상 만사에 능통함
- 거짓말도 믿어버림
3. NPC를 AI 에이전트로
(스탠포드 제너레이티브 에이전트)		 - 자연스러운 행동
- 인지 → 계획 → 실행
- 진짜 살아있는 느낌 		- 연산량 많음
- 처리 시간 길어짐
- 비용 비쌈

3️⃣ 우리의 핵심 아이디어

어떻게 해결했어?

두 가지 핵심 기능

└─────────────────────────────────────────────┘

   ↓
"앞에 있는 사람 주먹으로 때리겠습니다"
   ↓
┌──────────────────┐
│  LLM 분석        │
│ • 카테고리: 공격 │
│ • 대상: 앞 사람  │
│ • 난이도: 중간   │
└────────┬─────────┘
         ↓
   ✅ 게임 이벤트로 변환!

┌─────────────────────────────────────────────┐
│ 2️⃣ 반응 행동 결정 기능                       │
└─────────────────────────────────────────────┘

NPC 상태: 맞았다!
   ↓
┌──────────────────────┐
│  LLM 사고 과정       │
│ • 나는 평화주의자    │
│ • 폭력은 싫어        │
│ • 대화로 풀자        │
└────────┬─────────────┘
         ↓
   ✅ "왜 그러십니까? 대화로 풀어봅시다!"
게임 룰은 누가 정해?

LLM에게 룰까지 맡기면 안 돼!

이유:

LLM은 평화를 사랑해서...

LLM에게 룰까지 맡기면:

플레이어: "주먹질!"
LLM: "주먹은 잘 통하지 않았어요.
      대화로 풀어봅시다!"

→ 공격이 항상 실패!
게임 시스템이 룰 담당:

플레이어: "주먹질!"
→ 시스템: 난이도 체크 → 주사위 굴림 → 성공!
→ 시스템: "턱에 맞았다!" (확정)
→ LLM: 이 결과를 바탕으로 스토리 생성
   "당신의 주먹이 정확히 턱에 꽂혔습니다.
    상대가 비틀거립니다!"

→ 공격 성공!

게임 플로우:

[노란색 = 플레이어]
플레이어가 행동 입력
↓

[초록색 = LLM]
LLM이 행동 분석
- 이동? 공격? 대화?
- 난이도는?
↓

[파란색 = 시스템]
시스템이 성공/실패 판정
- 주사위 굴림
- 확률 계산
↓

[초록색 = LLM]
LLM이 결과 해석
- "팔목을 접질렀다!"
↓

대화 행동이면:
  [초록색 = LLM]
  NPC가 어떻게 받아들이는지 분석
  - 수긍할 확률 30%
  ↓
  [파란색 = 시스템]
  확률로 판정
  ↓
  [초록색 = LLM]
  결과 생성
↓

히스토리에 기록
↓

[초록색 = LLM]
각 NPC가 반응 행동 결정
- 내가 관측한 것: ...
- 내 생각: ...
- 내 행동: ...
↓

NPC 행동도 동일한 과정 반복

        
5️⃣ 프롬프트 엔지니어링


        

            
프롬프트가 뭐야?

            

                
프롬프트 (Prompt) = LLM에게 주는 명령어

                
좋은 프롬프트 = 좋은 결과

                
나쁜 프롬프트 = 엉뚱한 결과

            

        


        
1게임 월드 시스템 프롬프트


        

            
LLM에게 게임 상태를 어떻게 알려줘?

            

                
시스템 프롬프트 = 현재 게임 상태를 알려주는 프롬프트

                
모든 프롬프트 앞에 붙음!

            

        



시스템 프롬프트 내용:

[전체 정보]
- 플레이어 캐릭터 정보 (간략)
- NPC 정보 (간략)
- 게임 맵 정보

[주체 캐릭터 상세]
- 이름: 김형사
- 나이: 45세
- 직업: 강력계 형사
- 배경: 20년 경력의 베테랑...
- 소지품: 권총, 배지, 수첩

[관측한 이벤트]
- 도서관에 도착했다
- 사서를 발견했다
- 도움을 요청했다

        

            
중요한 팁 있어?

            

                
미니멀 접근!

                
→ 그 캐릭터가 알 수 있는 정보만 제공

                
이유:

                
모든 정보를 다 주면 → NPC가 몰라야 할 것까지 알아버림

                
예: A와 B는 모르는 사이인데 이름을 알고 있음

            

        



인덱스 활용:

설정에 인덱스 붙이기:

[F1] 형사는 권총을 소지하고 있다.
[K1] 사서는 도서관장의 친구다.

LLM이 사유할 때:
"F1에 따르면 권총이 있으므로..."

장점:
- 문장 전체를 안 옮겨 적어도 됨
- 토큰 수 절약!

        
2행동 분석 프롬프트



분석 내용:

1. 행동이 실행 가능한가?
2. 대상이 필요하면 존재하는가?
3. 행동 카테고리는?
   - 1: 대화
   - 2: 이동
   - 3: 아이템 사용
   - 4: 조사
   - 5: 물리적 공격
4. 난이도는? (쉬움/중간/어려움)
5. 상태 변화는?
   - HP 감소
   - 아이템 획득
   - 위치 이동


프롬프트 예시:

캐릭터 A는 다음 행동을 시도합니다:
"권총으로 사서를 쏜다"

다음을 YAML 형식으로 분석하세요:

실행_가능:
  설명: |
    (이 행동이 왜 가능한지 단계별로 생각)
  결론: (예/아니오)

카테고리:
  설명: |
    (어떤 카테고리인지 단계별로 생각)
  결론: (번호)

난이도:
  설명: |
    (캐릭터 설정 고려해서 단계별로 생각)
  결론: (쉬움/중간/어려움)

상태_변화:
  - 대상: 사서
    변화: HP -50

        

            
프롬프트 작성 팁 있어?

            

                
1 YAML 형식 추천

                
→ JSON보다 토큰 수 적음

                
→ 읽기 편함

                
→ LLM도 잘 이해함

                
2 Chain-of-Thought (생각의 사슬)

                
→ 즉시 답하지 말고 단계별로 생각하게!

                
3 설명을 결론 앞에!

                
→ 결론 먼저 쓰면 변명하는 식으로 답함

                
→ 말하기 전에 생각하게 만들어!

            

        


        
3행동 결과 해석 프롬프트


        

            
성공/실패만 있으면 안 돼?

            

                
NO! 구체적인 장면이 없어!

            

        



단순 결과:

"점프 실패"

→ 그래서 어떻게 됐는데?


LLM 해석:

"있는 힘껏 점프했지만 반대편 난간을 헛디뎌서
 발목을 접질렀다"

→ 구체적!
→ 재밌는 상황!
→ 다양한 결과!

        

            
어떻게 잘 해석하게 만들어?

            

                
Few-Shot Learning!

                
→ 예시를 몇 개 보여주기

                
→ LLM이 패턴을 학습

                
→ 비슷하게 생성

            

        



Few-Shot 예시:

[예시 1]
행동: 브레이크 댄스로 도서관 중앙 이동
결과 (실패): "발목을 접지르고 목소리가 흐트러지며
              시끄러운 소동을 일으켰다"

[예시 2]
행동: 풍차돌기로 도서 열람실 이동하며 한탄
결과 (성공): "독특한 행동으로 주변 시선을 사로잡았다"

[실제 행동]
행동: 공중제비 3바퀴 돌며 입구로 이동
결과: ???

→ LLM이 비슷한 스타일로 생성!

        
4대화 반응 분석 프롬프트


        

            
대화는 어떻게 처리해?

            

                
대화는 말 듣는 사람이 결정해야 해!

            

        



대화 처리:

플레이어 A: "경찰입니다. 협조 부탁드립니다."

NPC B 입장에서 생각:
1. 나는 말을 들을 수 있는 상태인가? (예)
2. A와 친분이 있나? (모르는 사람)
3. 배지가 진짜인가? (잘 모르겠음)
4. 경찰이면 협조해야 하나? (그래야 할 것 같음)
5. 수긍할 확률: 70%

시스템이 확률로 판정 (랜덤)
→ 성공!

LLM이 대사 생성:
"네, 무엇을 도와드릴까요?"

        
5반응 행동 생성 프롬프트


        

            
NPC는 어떻게 행동을 결정해?

            

                
NPC 입장에서 생각하게 만들어!

            

        



NPC 사고 과정:

[나는 반응할 수 있는 상태인가?]
- 기절했나? (아니오)
- 멀리 있나? (가까이 있음)
→ 반응 가능!

[내가 관측한 것]
- 플레이어가 도서관에 들어왔다
- 나에게 말을 걸었다
- 형사라고 밝혔다

[내가 아는 배경 설정]
- 나는 도서관 사서다
- 최근 살인 사건이 있었다
- 도서관장이 무언가 알고 있다

[내 생각]
- 형사가 사건 조사를 온 것 같다
- 도움을 줘야 할까?
- 배지가 진짜면 협조해야지

[행동 필요성]
- 행동 필요? (예)
- 무슨 행동? "도움을 드리겠다고 답변"

7️⃣ 문제점과 향후 방향


        

            
문제점은 없어?

            

                
비용과 시간!

            

        



비용 문제:

게임 설정:
- NPC 3명
- 8 라운드 진행
- GPT-4.5 사용

비용: 약 5달러 ($5)

→ 엄청 비싼 게임!


시간 문제:

2023년: GPT-4 → 한 라운드 2분
2025년: GPT-4.5 → 한 라운드 40초

개선됐지만 여전히 느림

        
향후 개선 방향



1 성능 최적화

- 프롬프트 최적화 (토큰 수 줄이기)
- 배치 처리 (한 번에 여러 API 호출)
- 경량 모델 사용 (중요도 낮은 부분)

2 기억력 개선

문제:
- NPC가 알아야 할 걸 잊음
- NPC가 몰라야 할 걸 알아버림
- 이벤트가 많아지면 프롬프트 길어짐

해결 방향:
- 중요도 기반 이벤트 요약
- 캐릭터별 메모리 관리
- 장기/단기 기억 분리

3 행동 제어

문제:
- NPC가 오지랖 부림
- 갑자기 도움 주려고 함
- AI 어시스턴트처럼 행동

해결 방향:
- 롤플레이 강화 프롬프트
- 행동 억제 조건 명시
- 성격 설정 강화

4 멀티모달 확장

가능성:
- 이미지 생성 (상황 묘사)
- 음성 합성 (나레이션)
- 배경 음악 생성
- 비디오 생성

5 모델 최적화

- 게임 전용 파인튜닝
- 경량화 모델 디바이스 실행
- 엣지 컴퓨팅 활용

  • TRPG (Table-top RPG) - 대화와 주사위로 하는 롤플레잉 게임
    • 
                
  • NPC (Non-Player Character) - 플레이어가 조종하지 않는 캐릭터
    • 
                
  • AI 에이전트 - 스스로 인지, 계획, 실행하는 인공지능
    • 
                
  • 프롬프트 (Prompt) - LLM에게 주는 명령어/질문
    • 
                
  • 프롬프트 엔지니어링 - 좋은 결과를 위한 프롬프트 작성 기술
    • 
                
  • Chain-of-Thought - 단계별로 생각하게 만드는 기법
    • 
                
  • Few-Shot Learning - 예시를 주고 패턴을 학습시키는 기법
    • 
                
  • YAML - 사람이 읽기 쉬운 데이터 형식 (JSON보다 간결)
    • 
                
  • 토큰 (Token) - LLM이 처리하는 단위 (토큰 많을수록 비용 증가)
    • 
                
  • 시스템 프롬프트 - LLM에게 역할과 상황을 알려주는 프롬프트
    • 
                
  • 파인튜닝 (Fine-tuning) - 특정 목적에 맞게 모델 재학습
    • 
                
  • 핵심 메시지 - LLM을 TRPG 마스터로 만들어서, 플레이어가 무엇을 하든 자연스럽게 반응하는 살아있는 NPC를 만들 수 있다. 단, 게임 룰은 시스템이 담당하고, LLM은 분석과 스토리 생성만!
