A 함수 거친 후에만 B에서 멈추기

종속 중단점 — 특정 경로로 왔을 때만

Part 1. 문제 상황

이 함수가 여러 곳에서 호출되는데, 특정 경로일 때만 보고 싶어

TakeDamage()가 100번 호출되는데,
MonsterAttack()에서 호출된 경우만 보고 싶다면?

Part 2. 종속 중단점 설정 (VS 2022+)

어떻게 설정해?

1. 먼저 A 함수(MonsterAttack)에 중단점 설정

2. B 함수(TakeDamage)에 중단점 설정

3. B 중단점 우클릭 → Conditions → "Only enable when..."

// 설정 순서 1. MonsterAttack() 첫 줄에 중단점 (BP-A) 2. TakeDamage() 첫 줄에 중단점 (BP-B) 3. BP-B 우클릭 → Conditions 4. "Only enable when the following breakpoint is hit" 선택 5. 드롭다운에서 BP-A 선택 // 결과: // BP-A를 거쳤을 때만 BP-B가 활성화됨

Part 3. 수동으로 하는 방법

이전 VS 버전에서는?

전역 플래그 변수와 조건부 중단점 조합:

// 1. Watch 창에서 전역 플래그 추적용 변수 선언 // (Immediate 창에서) int g_bFromMonster = 0; // 2. A 함수 중단점에 Action 추가 // 메시지: {g_bFromMonster = 1} // Continue execution 체크 // 3. B 함수 중단점에 Condition 추가 // g_bFromMonster == 1 // 4. B 함수 통과 후 플래그 리셋 // 메시지: {g_bFromMonster = 0}

Part 4. 활용 예시

언제 쓰면 좋아?

1. 특정 UI에서 호출된 경우만 디버깅

2. 특정 패킷 처리 후 동작만 추적

3. 특정 상태에서의 함수 동작 분석

// 예: 몬스터 공격으로 인한 데미지만 보고 싶다 // 경로 1: 몬스터 → TakeDamage (이거만 보고 싶음) // 경로 2: 독 데미지 → TakeDamage // 경로 3: 낙하 데미지 → TakeDamage // 경로 4: PvP → TakeDamage // 종속 중단점으로 경로 1만 필터링!

핵심 정리

  • VS 2022+: "Only enable when..." 옵션
  • 이전 버전: 플래그 변수 + 조건부 중단점
  • 특정 호출 경로만 디버깅할 때 유용
  • 불필요한 중단 횟수 대폭 감소
