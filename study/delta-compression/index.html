100명 방에서 트래픽을 8배 줄이는 법

델타 압축(Delta Compression)으로 네트워크 패킷 최적화하기

Q. 멀티플레이 게임 만들었는데 서버비가 너무 많이 나와요.

서버비의 큰 부분이 네트워크 트래픽 비용이에요.

특히 실시간 게임은 캐릭터 위치를 계속 주고받아야 하니까 트래픽이 엄청나죠.

Q. 위치 데이터가 그렇게 큰가요?

계산해볼게요.

일반적인 위치 패킷: { playerId: 12345, // 4 bytes (int) x: 123.456789, // 4 bytes (float) y: 456.789012, // 4 bytes (float) z: 789.012345, // 4 bytes (float) rotationY: 45.123 // 4 bytes (float) } 총 크기: 20 bytes

별로 안 큰 것 같죠?

근데 이걸 초당 20번씩 보낸다고 생각해보세요.

Q. 얼마나 나오는데요?

실제 계산해봤어요.

조건 값
플레이어 수 100명
패킷 크기 20 bytes
전송 주기 초당 20회
초당 트래픽 100명 × 20 bytes × 20회 = 40KB/s
시간당 트래픽 144MB/hour
하루 트래픽 3.5GB/day

방 하나에서 하루에 3.5GB예요.

방이 10개면? 35GB.

방이 100개면? 350GB/day.

💡 첫 번째 의문

Q. 매번 전체 위치를 보내야 해요?

처음엔 저도 그렇게 했어요.

// 매 프레임마다 SendPosition(playerId, x, y, z, rotation);

근데 생각해보니까 이상한 거예요.

Q. 뭐가 이상한데요?

캐릭터가 천천히 걸어가고 있다고 해봐요.

0.00초: x = 100.0, y = 50.0, z = 200.0 0.05초: x = 100.1, y = 50.0, z = 200.0 0.10초: x = 100.2, y = 50.0, z = 200.0 0.15초: x = 100.3, y = 50.0, z = 200.0

y랑 z는 안 바뀌잖아요?

x도 0.1씩만 바뀌고요.

근데 매번 전부 다 보내고 있어요.

🏪 비유: 재고 보고

일반적인 방식 (전체 전송):
- 월요일: "사과 100개, 바나나 50개, 오렌지 30개"
- 화요일: "사과 99개, 바나나 50개, 오렌지 30개"
- 수요일: "사과 98개, 바나나 50개, 오렌지 30개"
→ 매일 전부 다 보고

델타 방식 (변화량만):
- 월요일: "사과 100개, 바나나 50개, 오렌지 30개" (초기)
- 화요일: "사과 -1개"
- 수요일: "사과 -1개"
→ 바뀐 것만 보고

🎯 델타 압축 (Delta Compression)

Q. 그럼 변화량만 보내면 되는 거 아냐?

정확해요!

그게 델타 압축(Delta Compression)이에요.

// 이전 위치 저장 previousPosition = currentPosition; // 다음 프레임 delta = currentPosition - previousPosition; // 변화가 있으면 델타만 전송 if (delta != 0) { SendDelta(playerId, delta); }
Q. 실제 패킷은 어떻게 생겼어요?

비교해볼게요.

일반 패킷 (Full State)

{ type: "POSITION", // 1 byte playerId: 12345, // 4 bytes x: 123.456, // 4 bytes y: 456.789, // 4 bytes z: 789.012, // 4 bytes rotation: 45.123 // 4 bytes } → 총 21 bytes

델타 패킷 (Delta)

{ type: "DELTA", // 1 byte playerId: 12345, // 4 bytes dx: 0.1, // 2 bytes (short, -32K ~ 32K) dy: 0.0, // 2 bytes dz: 0.0, // 2 bytes dRotation: 0.0 // 2 bytes } → 총 13 bytes

21 bytes → 13 bytes

약 38% 절약이에요.

Q. 어? 생각보다 별로 안 줄었는데요?

맞아요. 아직 더 할 게 있어요.

변화가 없으면 아예 안 보내면 되잖아요?

// 변화 없으면 전송 안 함 if (abs(delta.x) > 0.01 || abs(delta.y) > 0.01 || abs(delta.z) > 0.01) { SendDelta(playerId, delta); }

서 있는 캐릭터는 패킷을 안 보내요.

이게 진짜 큰 차이예요.

📊 실측 데이터

Q. 실제로 얼마나 줄어들어요?

100명 방에서 테스트해봤어요.

방식 패킷 크기 초당 전송 횟수 초당 트래픽
Full State
(모든 플레이어, 매번)		 21 bytes 100명 × 20회 = 2,000회 42 KB/s
Delta (움직일 때만)
(약 30%만 움직임)		 13 bytes 30명 × 20회 = 600회 7.8 KB/s
Delta + 임계값
(유의미한 변화만)		 13 bytes 20명 × 15회 = 300회 3.9 KB/s

42 KB/s → 3.9 KB/s

약 10.8배 절약!

Q. 하루 트래픽으로 계산하면?
방식 초당 시간당 하루
Full State 42 KB/s 151 MB/h 3.6 GB/day
Delta 압축 3.9 KB/s 14 MB/h 0.34 GB/day

방 100개면:

  • Full State: 360 GB/day
  • Delta 압축: 34 GB/day

326 GB 절약이에요!

⚠️ 문제점

Q. 델타만 보내면 문제 없어요?

문제가 있어요.

패킷이 유실되면 큰일나요.

Q. 왜요?

예를 들어볼게요.

초기 위치: x = 100 [서버 → 클라이언트] 패킷 1: dx = +10 → 클라이언트: x = 110 ✓ 패킷 2: dx = +10 → 유실! 패킷 3: dx = +10 → 클라이언트: x = 120 ✗ (실제론 130이어야 함) 10의 오차 발생!

델타는 누적이기 때문에

한 번 틀어지면 계속 틀어진 채로 가요.

Q. 그럼 어떻게 해요?

주기적으로 전체 위치를 보내요.

frameCount = 0; void Update() { frameCount++; // 델타 전송 if (HasMoved()) { SendDelta(delta); } // 5초마다 전체 위치 전송 (보정) if (frameCount % 100 == 0) { // 20fps 기준 5초 SendFullState(position); } }

이렇게 하면:

  • 평소: 델타 (작음, 빠름)
  • 5초마다: 전체 위치 (동기화 보정)

오차가 5초 이상 누적되지 않아요.

📦 패킷 구조 이해하기

Q. 똑같은 구조체로 패킷을 보낸다고 해도 델타형 구조체랑 일반 풀스테이트 구조체가 두 개가 나눠져 있겠네요?

정확해요!

실제로는 두 개의 다른 패킷 타입이 있어요.

패킷 타입 정의

// 패킷 타입 enum enum class PacketType : uint8_t { FULL_STATE = 0x01, // 전체 위치 DELTA = 0x02 // 변화량만 };

1. Full State 패킷 (21 bytes)

struct FullStatePacket { uint8_t type; // 1 byte: 0x01 int32_t playerId; // 4 bytes float x; // 4 bytes float y; // 4 bytes float z; // 4 bytes float rotation; // 4 bytes } __attribute__((packed)); // 패딩 제거 // 총 21 bytes

2. Delta 패킷 (13 bytes)

struct DeltaPacket { uint8_t type; // 1 byte: 0x02 int32_t playerId; // 4 bytes int16_t dx; // 2 bytes (-327.68 ~ 327.67) int16_t dy; // 2 bytes int16_t dz; // 2 bytes int16_t dRotation; // 2 bytes } __attribute__((packed)); // 총 13 bytes

크기도 다르고, 내용도 달라요.

수신측에서는 첫 바이트(type)를 보고 어느 구조체로 파싱할지 결정해요.

🔧 실제 구현

Q. 코드로 보여주세요.

서버 측 (C++)

class PositionSync { private: Vector3 previousPosition; float previousRotation; int frameCount = 0; static constexpr float DELTA_THRESHOLD = 0.01f; // 1cm static constexpr int FULL_SYNC_INTERVAL = 100; // 5초 (20fps 기준) public: void Update(Player& player) { frameCount++; Vector3 currentPos = player.GetPosition(); float currentRot = player.GetRotation(); // 델타 계산 Vector3 delta = currentPos - previousPosition; float deltaRot = currentRot - previousRotation; // 유의미한 변화가 있거나, 5초 주기 bool shouldSend = delta.Magnitude() > DELTA_THRESHOLD || std::abs(deltaRot) > 0.1f || frameCount % FULL_SYNC_INTERVAL == 0; if (shouldSend) { if (frameCount % FULL_SYNC_INTERVAL == 0) { // 전체 동기화 SendFullState(player.GetId(), currentPos, currentRot); } else { // 델타 전송 SendDelta(player.GetId(), delta, deltaRot); } previousPosition = currentPos; previousRotation = currentRot; } } private: void SendDelta(int playerId, const Vector3& delta, float deltaRot) { DeltaPacket packet; packet.type = static_cast(PacketType::DELTA); packet.playerId = playerId; packet.dx = FloatToShort(delta.x); packet.dy = FloatToShort(delta.y); packet.dz = FloatToShort(delta.z); packet.dRotation = FloatToShort(deltaRot); // 패킷 전송 BroadcastToRoom(&packet, sizeof(DeltaPacket)); // 13 bytes } void SendFullState(int playerId, const Vector3& pos, float rot) { FullStatePacket packet; packet.type = static_cast(PacketType::FULL_STATE); packet.playerId = playerId; packet.x = pos.x; packet.y = pos.y; packet.z = pos.z; packet.rotation = rot; // 패킷 전송 BroadcastToRoom(&packet, sizeof(FullStatePacket)); // 21 bytes } // float를 short로 압축 (정밀도 0.01) int16_t FloatToShort(float value) { return static_cast(value * 100.0f); // -327.68 ~ 327.67 } };

클라이언트 측 (C++)

class ClientPositionSync { private: std::unordered_map playerPositions; public: void OnReceivePacket(const uint8_t* data, size_t size) { // 첫 바이트로 패킷 타입 확인 PacketType type = static_cast(data[0]); switch (type) { case PacketType::FULL_STATE: HandleFullState(data, size); break; case PacketType::DELTA: HandleDelta(data, size); break; default: std::cerr << "Unknown packet type: " << static_cast(data[0]) << std::endl; break; } } private: void HandleFullState(const uint8_t* data, size_t size) { if (size < sizeof(FullStatePacket)) return; // 구조체로 캐스팅 const FullStatePacket* packet = reinterpret_cast(data); Vector3 position(packet->x, packet->y, packet->z); // 위치 직접 설정 (동기화 보정) playerPositions[packet->playerId] = position; UpdatePlayerPosition(packet->playerId, position, packet->rotation); } void HandleDelta(const uint8_t* data, size_t size) { if (size < sizeof(DeltaPacket)) return; const DeltaPacket* packet = reinterpret_cast(data); // short → float 변환 Vector3 delta( ShortToFloat(packet->dx), ShortToFloat(packet->dy), ShortToFloat(packet->dz) ); float deltaRot = ShortToFloat(packet->dRotation); // 이전 위치에 델타 적용 auto it = playerPositions.find(packet->playerId); if (it != playerPositions.end()) { Vector3 newPos = it->second + delta; playerPositions[packet->playerId] = newPos; UpdatePlayerPosition(packet->playerId, newPos, deltaRot); } } float ShortToFloat(int16_t value) { return value / 100.0f; } };
💡 핵심 포인트:
- 첫 바이트(type)로 패킷 타입 구분
- Full State: 21 bytes, 전체 위치 전송
- Delta: 13 bytes, 변화량만 전송
- 클라이언트는 switch로 분기 처리

🎛️ 최적화 팁

Q. 더 줄일 방법은 없어요?

몇 가지 더 있어요.

1. 비트 패킹 (Bit Packing)

// dx, dy, dz가 -3.27 ~ 3.27 범위라면 // short (2 bytes) 대신 10 bits만 사용 가능 // 3개 delta = 30 bits = 4 bytes (vs 6 bytes)

2. 가변 길이 인코딩

// 작은 값은 1 byte, 큰 값은 2 bytes if (abs(delta) < 127) { SendByte(delta); // 1 byte } else { SendShort(delta); // 2 bytes }

3. 예측 + 보정

// 클라이언트가 움직임 예측 // 예측이 맞으면 패킷 안 보냄 // 예측이 틀리면 보정 패킷만 보냄

이런 기법들을 조합하면

20배 이상도 가능해요.

Q. 그럼 무조건 델타 방식이 좋은 거예요?

아니에요. Trade-off가 있어요.

항목 Full State Delta Compression
패킷 크기 큼 (21 bytes) 작음 (13 bytes)
CPU 사용량 낮음 약간 높음 (델타 계산)
패킷 유실 문제 없음 오차 누적 가능
신규 접속자 바로 동기화 초기 상태 필요
구현 복잡도 쉬움 복잡함

적절한 혼용이 답이에요.

💼 실무 적용: 게임 시나리오별 패킷 선택

Q. 실제 게임에서 어떤 상황에 어떤 패킷을 보내나요?

게임 상황에 따라 전략적으로 선택해요.

📍 시나리오 1: 일반 이동

// 플레이어가 걸어다니는 경우 if (player.IsWalking()) { // Delta 사용 (13 bytes) // 이유: 부드러운 움직임, 예측 가능 SendDelta(playerId, deltaPos, deltaRot); } ✅ Delta 선택 이유: - 연속적인 움직임 - 패킷 유실되어도 다음 패킷으로 보정 - 트래픽 절약 효과 큼

⚡ 시나리오 2: 순간이동/텔레포트

// 텔레포트 스킬 사용 if (player.UsedTeleport()) { // Full State 사용 (21 bytes) // 이유: 불연속적 이동, 정확성 필요 SendFullState(playerId, newPos, newRot); } ✅ Full State 선택 이유: - 이전 위치와 관계 없음 - Delta로 표현 불가능한 큰 변화 - 패킷 하나로 정확한 위치 보장

🎯 시나리오 3: 스킬 시전

// 공격 스킬 사용 if (player.CastSkill()) { // Full State + 스킬 정보 (25 bytes) SendFullStateWithSkill(playerId, pos, rot, skillId); } ✅ Full State 선택 이유: - 중요한 이벤트 (실패 불가) - 다른 데이터(skillId)와 함께 전송 - 클라이언트 동기화 보장

🚪 시나리오 4: 신규 접속자

// 새 플레이어가 방에 입장 void OnPlayerJoinRoom(Player* newPlayer) { // 기존 플레이어들의 Full State 전송 for (auto& player : roomPlayers) { SendFullState(player.id, player.pos, player.rot); } } ✅ Full State 선택 이유: - 이전 상태가 없음 - 초기 동기화 필요 - Delta 계산 기준점 설정

🔄 시나리오 5: 주기적 보정

// 5초마다 전체 동기화 if (frameCount % 100 == 0) // 20fps 기준 { // Full State로 강제 동기화 SendFullState(playerId, pos, rot); } else { // 평소에는 Delta if (HasSignificantChange()) SendDelta(playerId, deltaPos, deltaRot); } ✅ Full State 선택 이유: - 누적 오차 제거 - 패킷 유실 복구 - 동기화 품질 유지

🏃 시나리오 6: 빠른 움직임 (대시, 점프)

// 대시 스킬 사용 if (player.IsDashing()) { // 빠른 움직임 → 높은 빈도 + Full State SendFullState(playerId, pos, rot); // 초당 60회 } else { // 일반 이동 → Delta SendDelta(playerId, deltaPos, deltaRot); // 초당 20회 }
💡 실무 가이드라인:

Full State를 쓰는 경우:
• 텔레포트, 순간이동
• 중요 이벤트 (스킬 시전, 피격)
• 신규 접속자 초기화
• 주기적 보정 (5초마다)
• 빠른 움직임 (대시, 점프)

Delta를 쓰는 경우:
• 일반 걷기/달리기
• 연속적인 회전
• 예측 가능한 움직임
• 변화가 작은 경우 (<1m)

아예 안 보내는 경우:
• 변화 없음 (정지)
• 변화가 임계값 미만 (<1cm)
• 시야 밖 플레이어

🎮 실제 게임 사례

Q. 실제 게임은 어떻게 쓰나요?

Overwatch

델타 압축 + 예측 + 보정

  • 평소: 델타만 전송
  • 빠른 움직임: Full State
  • 클라이언트 예측으로 부드러움 유지

League of Legends

하이브리드 방식

  • 중요 이벤트: Full State (스킬 시전)
  • 일반 이동: Delta
  • 시야 밖 유닛: 전송 안 함

PUBG

거리 기반 차등 전송

  • 가까운 플레이어: 높은 빈도 + Full State
  • 먼 플레이어: 낮은 빈도 + Delta
  • 시야 밖: 전송 안 함

📌 핵심 정리: 델타 압축

  • 델타 압축 - 변화량만 전송해서 패킷 크기 줄이기
  • 실측 결과 - 42 KB/s → 3.9 KB/s, 약 10.8배 절약
  • 핵심 원리 - 변화 없으면 아예 안 보냄
  • 주의사항 - 패킷 유실 시 오차 누적, 주기적 전체 동기화 필요
  • 구현 팁 - 5초마다 Full State로 보정
  • 추가 최적화 - 비트 패킹, 가변 길이 인코딩, 예측
  • 실전 적용 - Full State와 Delta 혼용이 최선
💡 Tip: 델타 압축은 트래픽 절약의 시작점이에요. 여기에 더해 "중요도 기반 전송", "시야 범위 필터링", "예측 알고리즘"을 조합하면 더 극적인 최적화가 가능합니다.
