Root Motion

걷다가 멈출 때 미끄러지지 않게 하는 법

Part 1. 발 미끄러짐 문제

게임에서 캐릭터가 걸을 때 발이 미끄러지는 거 본 적 있어?

발 미끄러짐(Foot Sliding)은 흔한 문제야:

발 미끄러짐 문제: 코드로 이동 + 걷기 애니메이션: 프레임 1: 프레임 2: 프레임 3: ┌───────────┐ ┌───────────┐ ┌───────────┐ │ 🚶 │ │ 🚶 │ │ 🚶 │ │ ↙ ↘ │ │ ↙ ↘ │ │ ↙ ↘│ │ └ ┘ │ │ └ ┘ │ │ └ ┘│ │▔▔▔│▔▔▔▔▔▔│ │▔▔▔▔▔│▔▔▔▔│ │▔▔▔▔▔▔▔│▔▔│ │ └──────────────┼──────────────┼─────→ │ │ 발 위치 │ 발 위치 │ 발 위치 │ └───────────┘ └───────────┘ └───────────┘ 문제: 발이 땅에 닿은 채로 "미끄러짐" 애니메이션의 발 움직임 ≠ 캐릭터 이동 속도
왜 발이 미끄러져?

애니메이션과 이동이 따로 놀기 때문이야:

문제의 원인: ┌─────────────────────────────────────────────┐ │ 방식 1: 코드 기반 이동 │ ├─────────────────────────────────────────────┤ │ │ │ 코드: position += velocity * deltaTime; │ │ 애니메이션: 그냥 제자리에서 걷기 재생 │ │ │ │ 이동 속도: 5m/s (코드로 정함) │ │ 애니메이션 속도: 3m/s (모션 캡처 시 속도) │ │ │ │ 불일치! → 발이 미끄러짐 │ │ │ └─────────────────────────────────────────────┘

Part 2. Root Motion이란?

Root Motion이 뭔데?

Root Motion은 애니메이션 자체에서 이동값을 추출하는 거야:

Root Motion 원리: 스켈레톤 구조: ┌─────────────────────────────────────────┐ │ [Hips] ← 보통 여기가 Root │ │ │ │ │ ┌─────────┼─────────┐ │ │ │ │ │ │ │ [L.Leg] [Spine] [R.Leg] │ │ │ │ │ │ │ ▼ ▼ ▼ │ │ │ │ Root(Hips)가 애니메이션에서 움직이면 │ │ 그 움직임을 캐릭터 이동에 적용! │ └─────────────────────────────────────────┘ 걷기 애니메이션의 Root 위치 변화: 시간: 0.0s 0.5s 1.0s Root Z: 0.0m 1.5m 3.0m ← 이 값으로 캐릭터 이동!
// Root Motion 기본 원리 class RootMotionController { void Update(float deltaTime) { // 1. 이전 프레임의 Root 위치 Vector3 prevRootPos = animation->GetRootPosition(prevTime); // 2. 현재 프레임의 Root 위치 Vector3 currRootPos = animation->GetRootPosition(currentTime); // 3. 이동량 계산 (애니메이션에서 추출) Vector3 rootMotionDelta = currRootPos - prevRootPos; // 4. 캐릭터 이동에 적용 // 애니메이션의 로컬 이동 → 월드 이동으로 변환 Vector3 worldDelta = character->rotation * rootMotionDelta; character->position += worldDelta; // 발이 움직인 만큼만 캐릭터가 이동 → 미끄러짐 없음! } };
그럼 발이 안 미끄러지는 거야?

정확히! 애니메이션의 발 움직임과 캐릭터 이동이 완벽히 일치해:

Root Motion 적용 결과: 프레임 1: 프레임 2: 프레임 3: ┌───────────┐ ┌───────────┐ ┌───────────┐ │ 🚶 │ │ 🚶 │ │ 🚶 │ │ ↙ ↘ │ │ ↙ ↘ │ │ ↙ ↘│ │ └ ┘ │ │ └ ┘ │ │ └ ┘│ │▔▔▔│▔▔▔▔▔▔│ │▔▔▔▔▔│▔▔▔▔│ │▔▔▔▔▔▔▔│▔▔│ │ ● │ │ ● │ │ ● │ │ 발이 땅에 │ 발이 땅에 │ 발이 땅에 │ │ 고정됨 │ 고정됨 │ 고정됨 │ └───────────┘ └───────────┘ └───────────┘ 발이 땅에 닿은 동안 미끄러지지 않음!

Part 3. 애니메이션 기반 vs 코드 기반

두 방식의 차이가 뭐야?
두 가지 이동 방식 비교: ┌─────────────────────────────────────────────────────┐ │ 코드 기반 이동 (In-Place Animation) │ ├─────────────────────────────────────────────────────┤ │ │ │ 코드: │ │ void Update() { │ │ velocity = input.GetAxis() * speed; │ │ position += velocity * dt; │ │ animator.Play("Walk"); // 제자리 걷기 │ │ } │ │ │ │ 장점: 정밀한 이동 제어 가능 │ │ 단점: 발 미끄러짐, 애니메이션 속도 조절 필요 │ │ │ └─────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────┐ │ Root Motion 기반 이동 │ ├─────────────────────────────────────────────────────┤ │ │ │ 코드: │ │ void Update() { │ │ animator.Play("Walk"); // Root가 움직이는 걷기│ │ // 이동은 OnAnimatorMove()에서 자동 처리 │ │ } │ │ │ │ void OnAnimatorMove() { │ │ position += animator.deltaPosition; │ │ } │ │ │ │ 장점: 발 미끄러짐 없음, 자연스러운 움직임 │ │ 단점: 이동 제어가 애니메이션에 종속 │ │ │ └─────────────────────────────────────────────────────┘
어떤 게 더 좋아?

Part 4. 하이브리드 방식

둘 다 쓰면 어떻게 해?

상황에 따라 전환하는 거야:

// 하이브리드 이동 시스템 class HybridMovement { bool useRootMotion = false; void Update() { // 상황 판단 if (isAttacking || isRolling || isClimbing) { // 정밀한 동작 → Root Motion useRootMotion = true; } else if (isRunning || isSprinting) { // 빠른 이동 → 코드 기반 useRootMotion = false; } } void OnAnimatorMove() { if (useRootMotion) { // 애니메이션에서 이동값 추출 controller.Move(animator.deltaPosition); transform.rotation *= animator.deltaRotation; } else { // 코드로 이동 Vector3 velocity = inputDir * speed; controller.Move(velocity * Time.deltaTime); } } }; // 다크소울 스타일 예시 void ProcessAction() { if (Input.GetButton("Attack")) { // 공격 중에는 Root Motion (정확한 이동) animator.applyRootMotion = true; animator.Play("SwordSlash"); } if (Input.GetButton("Roll")) { // 구르기도 Root Motion (정확한 이동 거리) animator.applyRootMotion = true; animator.Play("Roll"); } // 일반 이동은 코드 기반 (빠른 반응) if (!isAttacking && !isRolling) { animator.applyRootMotion = false; MoveByInput(); } }

Part 5. Root Motion 애니메이션 제작

애니메이션을 어떻게 만들어야 해?

모션 캡처 시 이동을 포함해서 녹화하거나, 수동으로 Root 커브를 만들어:

Root Motion 애니메이션 제작: 방법 1: 모션 캡처 (실제 이동 포함) ┌─────────────────────────────────────────────┐ │ 배우가 실제로 걸으면서 캡처 │ │ │ │ 스튜디오 ────────→ 캡처 결과 │ │ 🏃‍♂️──────────────→ Root가 Z축으로 이동 │ │ (실제로 3m 걸음) (3m 이동 데이터 포함) │ └─────────────────────────────────────────────┘ 방법 2: 제자리 애니메이션 + Root 커브 추가 ┌─────────────────────────────────────────────┐ │ 원본: 제자리 걷기 │ │ │ │ Root Position Z 커브 추가: │ │ ┌──────────────────────┐ │ │ │ ↗ │ │ │ │ ↗ │ ← 선형 이동 │ │ │ ↗ │ │ │ │ ↗ │ │ │ └──────────────────────┘ │ │ 0s 1s │ │ 0m 3m │ └─────────────────────────────────────────────┘
// Unity에서 Root Motion 커브 추출/적용 // Animator의 Root Motion 데이터 접근 void OnAnimatorMove() { // 애니메이션에서 추출된 이동량 Vector3 deltaPosition = animator.deltaPosition; // 이번 프레임 이동 Quaternion deltaRotation = animator.deltaRotation; // 이번 프레임 회전 // 캐릭터 컨트롤러에 적용 characterController.Move(deltaPosition); transform.rotation *= deltaRotation; } // 커스텀 Root Motion 처리 void CustomRootMotion() { AnimatorClipInfo[] clips = animator.GetCurrentAnimatorClipInfo(0); AnimationClip clip = clips[0].clip; // 커브에서 직접 읽기 float time = animator.GetCurrentAnimatorStateInfo(0).normalizedTime; float rootZ = clip.EvaluateCurve(time, "RootT.z"); // Root Position Z // 적용 transform.position.z = rootZ; }

Part 6. Root Motion의 문제점과 해결

Root Motion에도 문제가 있어?

몇 가지 주의점이 있어:

Root Motion 문제점: 문제 1: 애니메이션 속도 ≠ 원하는 속도 ┌─────────────────────────────────────────────┐ │ 걷기 애니메이션: 3m/s │ │ 원하는 속도: 5m/s │ │ │ │ 해결: 애니메이션 재생 속도 조절 │ │ animator.speed = 5.0f / 3.0f = 1.67 │ │ │ │ 주의: 너무 빠르면 부자연스러움 │ │ → 달리기 애니메이션으로 전환 필요 │ └─────────────────────────────────────────────┘ 문제 2: 회전 시 이동 방향 불일치 ┌─────────────────────────────────────────────┐ │ 캐릭터가 오른쪽을 보는데 │ │ Root Motion은 앞으로만 이동 │ │ │ │ 해결: Root Motion을 캐릭터 방향으로 회전 │ │ worldDelta = characterRotation * localDelta│ └─────────────────────────────────────────────┘ 문제 3: 경사면/계단 ┌─────────────────────────────────────────────┐ │ 애니메이션은 평지 기준 │ │ 경사면에서 뜨거나 뚫림 │ │ │ │ 해결: Root Motion Y축은 무시하고 │ │ CharacterController가 처리 │ └─────────────────────────────────────────────┘
// Root Motion 문제 해결 class RootMotionFixer { void OnAnimatorMove() { Vector3 delta = animator.deltaPosition; // 문제 1: 속도 조절 float desiredSpeed = inputMagnitude * maxSpeed; float animSpeed = GetAnimationSpeed(); animator.speed = desiredSpeed / animSpeed; // 문제 2: 방향 맞추기 // 로컬 Root Motion → 월드 좌표로 Vector3 worldDelta = transform.rotation * delta; // 문제 3: Y축 무시 (중력은 별도 처리) worldDelta.y = 0; // 지면 따라가기 if (Physics.Raycast(transform.position, Vector3.down, out hit)) { // 경사면 노멀에 맞춰 이동 방향 조정 worldDelta = Vector3.ProjectOnPlane(worldDelta, hit.normal); } characterController.Move(worldDelta); // 중력 별도 적용 ApplyGravity(); } float GetAnimationSpeed() { // 애니메이션 클립의 원래 이동 속도 AnimationClip clip = GetCurrentClip(); float distance = clip.GetRootMotionDistance(); return distance / clip.length; } }

핵심 정리

  • 발 미끄러짐은 코드 이동과 애니메이션 속도가 불일치할 때 발생
  • Root Motion은 애니메이션의 Root 뼈대 이동을 캐릭터 이동에 적용
  • Root Motion → 정밀한 동작 (격투, 등반, 구르기)
  • 코드 기반 → 빠른 반응 (FPS, 일반 이동)
  • 실제 게임은 대부분 하이브리드 (상황별 전환)
  • 속도 조절, 방향 변환, 경사면 처리 등 보정 필요
  • 모션 캡처 시 실제 이동 포함하거나 Root 커브 수동 추가
