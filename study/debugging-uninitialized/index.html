쓰레기 값이 들어있어요

미초기화 변수 — Debug와 Release가 다른 이유

Part 1. 증상

변수에 이상한 값이 들어있어요

변수를 선언만 하고 초기화하지 않으면 쓰레기 값이 들어있다.

C++는 자동 초기화를 해주지 않는다.

void DoSomething() { int nCount; // 미초기화 → 쓰레기 값 int* pPlayer; // 미초기화 → 쓰레기 주소 if (nCount > 0) // 정의되지 않은 동작! { // ... } }

Part 2. Debug vs Release

Debug에서는 됐는데 Release에서 안 돼요

Debug 빌드는 미초기화 메모리를 특정 패턴으로 채운다.

Release는 이전에 있던 쓰레기 값 그대로.

int bFlag; // 미초기화 // Debug 빌드 // bFlag = 0xCCCCCCCC (≠ 0, 항상 true) // Release 빌드 // bFlag = 이전 스택 내용 // 0일 수도 있고, 1일 수도 있고, 뭐든 될 수 있음 if (bFlag) // Debug: 항상 true { // Release: 불확정! DoSomething(); }

Part 3. 컴파일러 경고

미리 알 수 있는 방법?

컴파일러가 경고를 준다!

경고 레벨을 높이고, 경고를 에러로 처리하자.

// 컴파일 경고 예시 warning C4700: uninitialized local variable 'nCount' used // 프로젝트 설정 // C/C++ → General → Warning Level: Level4 (/W4) // C/C++ → General → Treat Warnings As Errors: Yes (/WX) // 또는 특정 경고만 에러로 #pragma warning(error: 4700)

Part 4. 예방

어떻게 방지해?

1. 선언과 동시에 초기화

2. 멤버 변수는 생성자 초기화 리스트 또는 기본값

3. 컴파일러 경고 무시하지 않기

// 지역 변수 - 선언과 동시에 초기화 int nCount = 0; int* pPlayer = nullptr; // 멤버 변수 - C++11 기본값 class CPlayer { int m_nHP = 100; // 기본값 int m_nMP = 50; bool m_bDead = false; }; // 또는 생성자 초기화 리스트 CPlayer::CPlayer() : m_nHP(100) , m_nMP(50) , m_bDead(false) { }

핵심 정리

  • C++는 자동 초기화 안 함
  • Debug: 0xCC, Release: 쓰레기
  • /W4 /WX 옵션으로 경고를 에러로
  • 선언과 동시에 초기화 습관화
