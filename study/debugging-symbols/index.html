.pdb 파일이 뭐야?

심볼과 소스 매칭 — 디버깅의 핵심 파일

Part 1. PDB란?

PDB 파일이 뭐야?

Program Database의 약자.

컴파일된 바이너리(.exe, .dll)와 소스 코드를 연결해주는 정보가 들어있다.

// PDB에 들어있는 정보 1. 함수 이름 ↔ 메모리 주소 매핑 CPlayer::TakeDamage() → 0x00401234 2. 변수 이름 ↔ 스택/레지스터 위치 m_nHP → [rbp-0x10] 3. 소스 파일 경로 ↔ 기계어 주소 Player.cpp:234 → 0x00401234 4. 타입 정보 (구조체, 클래스 레이아웃)

Part 2. PDB 없으면 어떻게 돼?

PDB 없이 디버깅하면?

Call Stack에 함수 이름 대신 주소만 나온다.

변수를 볼 수 없고, 소스 코드와 매칭이 안 된다.

// PDB 있을 때 → CPlayer::TakeDamage() Line 234 CMonster::Attack() Line 567 main() Line 45 // PDB 없을 때 → 0x00401234 0x00405678 0x00401000 [External Code]

Part 3. PDB 버전 불일치

"소스가 다릅니다" 메시지가 떠요

PDB와 exe가 다른 빌드라서 그렇다.

exe를 빌드한 후 소스를 수정했거나, PDB가 예전 버전이다.

해결: 다시 빌드하거나, 맞는 PDB 파일을 찾아서 로드.

Part 4. 심볼 경로 설정

심볼 경로는 어디서 설정해?

Debug → Options → Debugging → Symbols

Microsoft Symbol Servers를 추가하면 Windows DLL 심볼도 자동 다운로드된다.

// 심볼 서버 URL https://msdl.microsoft.com/download/symbols // 로컬 캐시 경로 (권장) C:\Symbols

핵심 정리

  • PDB = 바이너리 ↔ 소스 연결 정보
  • PDB 없으면 주소만 보임, 디버깅 불가
  • 버전 불일치 = 다시 빌드
  • Release에도 PDB 생성하면 크래시 분석 가능
