float 4바이트를 1바이트로 줄이는 법

Quantization - 정밀도를 희생해서 대역폭 50~70% 절약하기

📦 네트워크 ⏱️ 15분 📅 2025.01.20

🤔 왜 필요해?

float는 4바이트인데, 게임에서 정말 4바이트가 다 필요해?

아니에요. 대부분 낭비예요.

예시: 플레이어 체력

// C++에서 float 체력 float health = 85.3472819f; // 4바이트 (32비트) // 하지만 게임에서는... UI에 표시: "체력 85%" 실제 필요: 0~100 사이 정수 4바이트 중 실제로 의미 있는 데이터는 7비트 (0~127)만!

3.125바이트를 낭비하고 있어요.

다른 예시도 있어?

회전 각도

float rotation = 127.3891234f; // 4바이트 실제 필요: 0~360도 정밀도: 0.7도 (360/512)면 충분 필요한 비트: 9비트 (0~511) 낭비: 23비트!

위치 좌표

float x = 123.456789f; // 4바이트 실제 필요: -200 ~ 200 범위 정밀도: 0.01 (1cm)면 충분 필요한 비트: 16비트 (short) 낭비: 16비트!

매번 패킷을 보낼 때마다 의미 없는 비트를 전송하고 있어요.

💡 해결책: 양자화 (Quantization)

양자화가 뭐예요?

연속적인 값을 이산적인 값으로 바꾸는 것이에요.

🌡️ 비유: 온도계

디지털 온도계 (양자화 전):
23.8472819도 (32비트 float)

아날로그 온도계 (양자화 후):
24도 (8비트 정수)

당신은 소수점 7자리까지 필요한가요?
아니죠. 정수만으로 충분합니다.
구체적으로 어떻게 동작해?

3단계로 진행돼요.

Step 1: 범위 결정

// 체력은 0~100 사이 float minHealth = 0.0f; float maxHealth = 100.0f;

Step 2: 비트 수 결정

// 7비트 사용 = 0~127 표현 가능 int bits = 7; int maxValue = (1 << bits) - 1; // 127

Step 3: 변환 (Quantize)

// float (4바이트) → uint8_t (1바이트) float health = 85.3f; // 0~100을 0~127로 매핑 uint8_t quantized = (uint8_t)((health / 100.0f) * 127.0f); // quantized = 108 // 1바이트로 전송! (vs 4바이트)

Step 4: 복원 (Dequantize)

// 수신측에서 다시 float로 복원 float restored = (quantized / 127.0f) * 100.0f; // restored = 85.0394... (원본 85.3과 유사)

4바이트 → 1바이트, 75% 절약!

📊 실전 예시

실제 코드로 보여주세요.

예시 1: 체력 양자화 (0~100 → 7비트)

// 양자화 함수 uint8_t QuantizeHealth(float health) { // 0~100을 0~127로 매핑 float normalized = health / 100.0f; // 0.0 ~ 1.0 return (uint8_t)(normalized * 127.0f); } // 역양자화 함수 float DequantizeHealth(uint8_t quantized) { float normalized = quantized / 127.0f; return normalized * 100.0f; } // 사용 예시 float originalHealth = 85.3f; uint8_t compressed = QuantizeHealth(originalHealth); // 108 float restored = DequantizeHealth(compressed); // 85.04 // 오차: 0.26 (0.3%) // 크기: 4바이트 → 1바이트 (75% 절약)

예시 2: 회전 양자화 (0~360도 → 9비트)

// 0~360도를 0~511로 매핑 uint16_t QuantizeRotation(float degrees) { float normalized = degrees / 360.0f; return (uint16_t)(normalized * 511.0f); } float DequantizeRotation(uint16_t quantized) { float normalized = quantized / 511.0f; return normalized * 360.0f; } // 사용 예시 float originalRotation = 127.5f; uint16_t compressed = QuantizeRotation(originalRotation); // 181 float restored = DequantizeRotation(compressed); // 127.4 // 정밀도: 360/512 = 0.7도 // 크기: 4바이트 → 2바이트 (50% 절약) // 비트 패킹 시: 9비트만 사용 가능 (1.125바이트)

예시 3: 위치 양자화 (-100~100 → 16비트)

// -100 ~ 100을 -32768 ~ 32767로 매핑 int16_t QuantizePosition(float position) { // 범위 정규화: -100~100 → 0~1 float normalized = (position + 100.0f) / 200.0f; // 0~1 → 0~65535 uint16_t unsigned_value = (uint16_t)(normalized * 65535.0f); // 부호 있는 int16_t로 변환 return (int16_t)(unsigned_value - 32768); } float DequantizePosition(int16_t quantized) { // int16_t → 0~65535 uint16_t unsigned_value = (uint16_t)(quantized + 32768); // 0~65535 → 0~1 float normalized = unsigned_value / 65535.0f; // 0~1 → -100~100 return normalized * 200.0f - 100.0f; } // 사용 예시 float originalX = 42.758f; int16_t compressed = QuantizePosition(originalX); // 23450 float restored = DequantizePosition(compressed); // 42.76 // 정밀도: 200/65536 = 0.003 (3mm) // 크기: 4바이트 → 2바이트 (50% 절약)

⚖️ 정밀도 vs 크기 트레이드오프

비트를 줄이면 오차가 커지겠네요?

정확해요! 비트 수에 따라 정밀도가 달라져요.

체력 (0~100) 양자화 비교

비트 수 표현 범위 정밀도 크기 오차
32비트 (float) 0~100 0.0000001 4바이트 0%
16비트 (short) 0~65535 0.0015 2바이트 0.002%
8비트 (byte) 0~255 0.39 1바이트 0.4%
7비트 0~127 0.79 1바이트* 0.8%
4비트 0~15 6.67 0.5바이트* 6.7%

* 비트 패킹 사용 시

💡 선택 기준:
• 시각적 데이터 (체력바, 이펙트): 7~8비트면 충분
• 물리 시뮬레이션 (충돌, 탄도): 16비트 이상
• 회전 각도: 8~10비트
• 위치 좌표: 16비트 (맵 크기에 따라)

🎯 실무 적용: 어떤 데이터를 양자화할까?

모든 float를 양자화해야 하나요?

아니에요. 선택적으로 해야 해요.

✅ 양자화하면 좋은 데이터

  • 체력/마나 - 0~100%, 7~8비트
  • 회전 각도 - 0~360도, 8~10비트
  • 위치 (제한된 맵) - 고정 범위, 16비트
  • 속도 - 최대 속도 제한, 10~12비트
  • 애니메이션 시간 - 0~1, 8~10비트
  • 스킬 쿨다운 - 0~100초, 10비트
  • 버프 지속시간 - 0~60초, 10비트

❌ 양자화하면 안 되는 데이터

  • 총알 궤적 계산 - 정밀도 중요
  • 물리 시뮬레이션 - 오차 누적 위험
  • 카메라 위치 - 떨림 발생 가능
  • 돈/재화 - 정확성 필수
  • 타임스탬프 - 정밀도 필수

🔧 고급 기법

더 효율적으로 하는 방법은?

1. 적응형 양자화 (Adaptive Quantization)

// 상황에 따라 비트 수 조절 if (player.IsInCombat()) { // 전투 중: 높은 정밀도 quantized = QuantizeHealth(health, 10); // 10비트 } else { // 평소: 낮은 정밀도 quantized = QuantizeHealth(health, 7); // 7비트 }

2. 비선형 양자화 (Non-linear Quantization)

// 체력이 낮을 때 더 정밀하게 float QuantizeNonLinear(float health) { if (health < 20.0f) return QuantizeHealth(health, 8); // 20% 이하: 높은 정밀도 else return QuantizeHealth(health, 6); // 20% 이상: 낮은 정밀도 } // 이유: 체력이 낮을 때 정확한 표시가 중요 (생존 여부)

3. 델타 + 양자화 조합

// 변화량을 양자화 float healthChange = currentHealth - previousHealth; // 변화량은 작으니까 8비트로 충분 int8_t deltaQuantized = (int8_t)(healthChange); // 4바이트 → 1바이트 // 정밀도도 유지

  • 결과: 4바이트 * 3 = 12바이트 → 4.5바이트

거리 기반 양자화

  • 가까운 플레이어: 16비트 (정밀)
  • 먼 플레이어: 12비트 (덜 정밀)
  • 매우 먼 플레이어: 8비트 (대략적)
  • 이유: 멀리 있으면 어차피 덜 보임

물리 + 양자화

  • 차량 위치: 16비트 (정밀)
  • 차량 회전: 쿼터니언 압축 (48비트 → 32비트)
  • 속도: 12비트 양자화
  • 결과: 60fps에서도 부드러운 동기화

Counter-Strike

최소 비트 전략

  • 체력: 7비트 (0~100)
  • 탄약: 8비트 (0~255)
  • 각도: 16비트 fixed-point
  • 철학: 필요한 최소한만 보냄

💼 실무 가이드라인

Step 1: 데이터 분석

// 실제 게임에서 측정 float minObserved = 999999.0f; float maxObserved = -999999.0f; // 10분간 플레이 for (int frame = 0; frame < 36000; frame++) { float value = GetPlayerHealth(); minObserved = min(minObserved, value); maxObserved = max(maxObserved, value); } // 결과: 0.0 ~ 100.0 // → 7~8비트면 충분하다고 판단

Step 2: 비트 수 계산

// 필요한 정밀도 결정 float range = maxObserved - minObserved; // 100 float precision = 1.0f; // 1 단위면 충분 // 필요한 단계 수 int steps = (int)(range / precision); // 100 // 필요한 비트 수 int bits = ceil(log2(steps)); // 7비트 // 7비트 = 0~127 표현 가능 (충분!)

Step 3: 프로파일링

// Before Packet size: 21 bytes - playerId: 4 bytes - x: 4 bytes (float) - y: 4 bytes (float) - z: 4 bytes (float) - rotation: 4 bytes (float) - health: 1 byte (이미 최적화됨) // After (양자화 적용) Packet size: 13 bytes - playerId: 4 bytes - x: 2 bytes (int16_t) - y: 2 bytes (int16_t) - z: 2 bytes (int16_t) - rotation: 2 bytes (int16_t) - health: 1 byte // 절약: 38% (21 → 13 bytes)

⚠️ 주의사항

양자화할 때 조심할 점은?

1. 오차 누적

// 나쁜 예: 양자화된 값으로 계속 계산 float health = 100.0f; health = Dequantize(Quantize(health - 10)); // 89.98 health = Dequantize(Quantize(health - 10)); // 79.92 health = Dequantize(Quantize(health - 10)); // 69.84 // 3번 반복 → 오차 0.16 누적! // 좋은 예: 원본 값으로 계산, 전송 시만 양자화 float health = 100.0f; // 서버에서 유지 health -= 10; // 90.0 health -= 10; // 80.0 health -= 10; // 70.0 SendToClient(Quantize(health)); // 전송 시에만 양자화

2. 범위 초과

// 체력 7비트 (0~127)로 양자화했는데... float health = 150.0f; // 버프로 최대 체력 증가! // Overflow 발생 uint8_t quantized = QuantizeHealth(health); // 127 (잘림!) // 해결: 범위 체크 uint8_t QuantizeHealthSafe(float health) { health = clamp(health, 0.0f, 100.0f); // 범위 제한 return (uint8_t)((health / 100.0f) * 127.0f); }

3. 정밀도 불일치

// 서버와 클라이언트가 다른 정밀도 사용 // Server: 8비트 양자화 // Client: 7비트 양자화 // → 동기화 깨짐! // 해결: 상수로 관리 const int HEALTH_QUANTIZE_BITS = 7; // 공통 헤더에 정의

📌 핵심 정리: Quantization

  • 양자화 - float (4바이트)를 int (1~2바이트)로 압축
  • 핵심 원리 - 범위와 정밀도를 제한해서 비트 절약
  • 실측 결과 - 대역폭 50~70% 절약
  • 적용 대상 - 체력, 회전, 위치, 속도 등 (물리 계산 제외)
  • 비트 선택 - 7~8비트 (UI 표시용), 16비트 (정밀 위치)
  • 주의사항 - 오차 누적 방지, 범위 초과 체크
  • 실전 조합 - 델타 압축 + 양자화 + 비트 패킹
