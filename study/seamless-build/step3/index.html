STEP 3 — 고스팅: 이웃이 보인다 ★첫 마법

서버들이 서로 통신해, 경계 부근 액터를 이웃에 '고스트(읽기전용 복사본)'로 흘린다. 옆 칸이 보이고, 세계가 하나로 붙는다.

STEP 3의 목적

STEP 2의 결핍("옆 칸이 안 보임 = 데이터 문제")을 푼다. 경계 폭 N 안의 액터를 이웃 서버에 읽기전용 복사본(고스트)으로 스트리밍하고, 이웃은 그걸 자기 클라에게 함께 방송한다.

🎥 실제 작동 — 3D 뷰어 (STEP 3)

STEP 2와 똑같이 게이트 연결 1개지만, 이번엔 경계 근처에 서면 옆 칸(다른 색) 몬스터가 반투명 큐브로 나타난다. 내 칸 몬스터는 빨간 불투명, 옆 칸 고스트는 반투명 + 외곽선이 주인 존 색. 옆 칸에서 멀어지면 고스트가 스르륽 사라진다 — 9개 서버가 하나의 세계로 붙은 첫 순간.

✅ 지금 되는 것

· 서버가 서버에게 붙는다 — 각 존은 클라용 포트 + 피어용 포트를 둘 다 열고 이웃에 connect

· 경계 폭 N 안의 액터만 이웃에 읽기전용 고스트로 push (전부 보내면 분산의 의미가 없다)

· 이웃은 받은 고스트를 자기 클라에게 SM_GHOST로 함께 방송 → 뷰어가 옆 칸을 반투명으로 그린다

· 고스트는 TTL이 있어, 갱신이 끊기면 자동으로 사라진다(옆 칸에서 멀어질 때)

❌ 아직 안 되는 것 (다음 단계에서)

· 고스트는 보이기만 함 — 아직 경계를 넘어가 살 수는 없다(권한 이전 없음) → STEP 4 심리스 이주

· 옆 칸 몬스터를 공격할 수는 없다(읽기전용) → STEP 5 위치 투명 라우팅

Part 1. 서버가 서버에게 — listen과 connect 둘 다

지금까진 클라만 서버에 붙었다. 옆 칸을 보이게 하려면?

서버끼리 대화해야 한다. 각 서버가 클라용 포트 + 피어용 포트 둘 다 열고, 이웃의 피어 포트에 connect해 내 경계 액터를 보낸다. 예전에 정리한 "서버는 listen도 connect도 한다"가 실제로 쓰이는 지점.

존0 ─(피어: 내 경계 액터 push)─▶ 존1 ─(push)─▶ 존2 존0 ◀─(push)─ 존1 ◀─(push)─ 존2 각 서버: client:9001+z, peer:9101+z

Part 2. 경계 폭 N 안의 것만 보낸다 (AOI)

내 칸 액터를 전부 이웃에 보내나?

아니다. 경계 폭 N(=3) 안에 있는, 옆 칸에서 실제로 보일 만한 것만 보낸다. 이게 관심 영역(AOI)의 기본. 멀리 있는 건 안 보내 트래픽을 아낀다.

// 이웃 nb와의 경계 폭 N 안인가?
bool NearBoundary(float x, float y, int nb) { if (nb == zoneIdx + 1) return x >= zx0 + CellSize - N; // 오른쪽 이웃 if (nb == zoneIdx - 1) return x < zx0 + N; // 왼쪽 ... (위/아래도) } // 매 틱: 경계 안 액터를 이웃에게 push foreach (var nb in neighbors) foreach (var (id, mo) in monsters) if (NearBoundary(mo.X, mo.Y, nb)) await Send(peerOut[nb], SM_MOVE(id, mo.X, mo.Y, myZone));

Part 3. 받은 고스트를 클라에 함께 방송 (+ TTL)

받은 고스트는 어떻게 처리하지? 계속 쌓이나?

내 클라에게 SM_GHOST로 함께 방송한다(내 액터 + 이웃 고스트). 그리고 TTL(수명)을 둬서 2틱 넘게 갱신 안 오면 지운다 — 이웃이 매 틱 갱신하니, 멀어지면 자동 소멸. 게임 상태는 여전히 틱 스레드 혼자 만진다(단일 스레드 유지).

[C] → 위치 (11,5) [지금 zone 1] [C] 🐺 M101 = (17,5) [내 칸 zone 1] ← 내 칸 몬스터(진짜) [C] 👻 (고스트) M100 = (7,5) [옆 칸 zone 0] ← 옆 칸 몬스터가 보인다! (세계가 붙음)

❌ 남은 결핍: ① 고스트는 읽기전용 — 때려도 무반응(주인이 이웃 서버라 판정 불가) → STEP 5. ② 경계 통과가 여전히 어색(넘는 순간 아바타가 원 서버에 잠깐 남는 등) → STEP 4 이주.

★ 이야기로 (A→Z)

네트워크를 몰라도 읽히게.

STEP 2에서 저는 게이트로 재접속을 숨겼지만, 여전히 옆 칸이 텅 비어 보이는 문제가 남아 있었습니다. 게이트는 지금 붙은 한 서버의 데이터만 전달할 뿐이니까요. 이건 연결이 아니라 데이터 문제였습니다.

옆 칸을 보이게 하려면, 옆 칸 서버가 가진 정보를 내 서버가 알아야 합니다. 그러려면 서버끼리 대화해야 합니다. 지금까진 클라만 서버에 붙었는데, 이제 서버가 다른 서버에게도 연결을 겁니다.

서버가 listen도 connect도 한다 — 각 서버는 클라를 받는 문(포트) 말고, 이웃 서버와 주고받는 문을 하나 더 엽니다. 이웃의 문으로 걸어 들어가(connect) 내 경계 근처 액터를 보냅니다.

그런데 내 칸의 모든 액터를 옆에 보낼 필요는 없습니다. 옆 칸에서 실제로 보이는 건 경계 근처에 있는 것뿐이니까요. 그래서 경계 폭 N 안에 든 것만 보냈습니다.

관심 영역(AOI) — "누가 무엇을 알아야 하는가"를 정하는 규칙입니다. 경계에서 먼 액터는 옆 칸에 안 보내, 필요한 것만 주고받아 낭비를 줄입니다.

옆에서 받은 복사본은 고스트라고 부릅니다. 진짜가 아니라 '보여주기용 읽기전용 복사본'입니다. 내 서버는 이 고스트를 내 클라들에게 자기 액터와 함께 방송합니다. 그리고 고스트에 수명을 둬서, 이웃이 더는 보내주지 않으면(그 액터가 경계에서 멀어졌으면) 조용히 지웁니다.

실제로 돌려보니, 클라가 존1 경계에 서 있을 때 자기 칸 몬스터(🐺 M101)와 함께 옆 칸 존0의 몬스터가 고스트(👻 M100)로 보였습니다. 처음으로 경계 너머가 보인 겁니다. 세계가 하나로 붙기 시작한 순간이죠. 이게 이 시리즈의 첫 마법입니다.

하지만 두 가지가 남았습니다. 이 고스트는 읽기전용이라, 때려도 아무 반응이 없습니다 — 그 액터의 진짜 주인은 이웃 서버라, 데미지 판정을 내 서버가 내릴 수 없으니까요. 그리고 경계를 통과하는 순간이 아직 어색합니다(넘을 때 내 아바타가 원래 서버에 잠깐 남았다 사라지는 게 보였습니다). 여기서 배운 것은 이 시리즈의 헌법입니다: "보인다 ≠ 소유한다." 고스트는 보이지만 내 것이 아닙니다. 다음 단계는 이 둘을 푸는 겁니다 — 소유권을 매끄럽게 넘기는 심리스 이주(STEP 4)와, 경계 너머를 때리는 위치 투명 라우팅(STEP 5).

핵심 정리

  • 서버가 피어 포트로 서로 연결(listen+connect) → 경계 폭 N 안의 액터를 이웃에 고스트로 push.
  • 받은 고스트를 내 클라에게 SM_GHOST로 함께 방송 → 옆 칸이 보인다(세계가 붙음).
  • AOI(경계 폭)로 필요한 것만, TTL로 멀어지면 자동 소멸. 게임 상태는 여전히 단일 스레드.
  • 고스트는 읽기전용('보인다 ≠ 소유한다') → 때려도 무반응(STEP 5), 경계 통과 어색(STEP 4).
