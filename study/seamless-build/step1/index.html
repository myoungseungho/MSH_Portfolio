STEP 1 — 3×3으로 찢기, 경계라는 새 문제

한 대짜리 월드를 9칸으로 나눠 서버 9대에 맡긴다. 부하는 1/9로 줄지만, '경계=벽'과 '옆 칸 안 보임'이라는 새 결핍이 생긴다.

STEP 1의 목적

STEP 0의 결핍("서버 1대뿐 → 스케일 아웃 불가")을 푼다. 월드를 3×3 = 9칸으로 나누고, 같은 서버 exe를 zone 인자만 바꿔 9번 띄운다. 클라는 자기 칸 서버에 접속한다.

🎥 실제 작동 — 3D 뷰어 (STEP 1)

바닥 9칸의 색과 번호가 각각 다른 서버(존). 걷다가 흰 경계선을 넘으면 ⛔ 경계! 재접속 배너가 뜨고(끊고 재접속=프리즈), 이전 칸 몬스터가 사라지며 새 칸 것만 보인다(옆 칸은 텅 빔). 머리 위 점 = 지금 담당 서버 색.

✅ 지금 되는 것

· 월드를 9칸으로 나눠 서버 9대가 한 칸씩 담당 (바닥 색·번호로 확인, 부하 1/9)

· 경계를 넘으면 끊고 재접속 = 경계 = 벽 (프리즈 배너)

· 각 서버가 자기 칸만 방송 → 옆 칸은 텅 빔 (넘는 순간 몬스터 교체)

❌ 아직 안 되는 것 (다음 단계에서)

· 경계 재접속이 그대로 노출(프리즈·순간이동 느낌) → STEP 2 게이트가 숨김

· 옆 칸이 안 보임(데이터 문제) → STEP 3 고스팅

· 경계 너머 상호작용/전투 없음 → STEP 4·5

Part 1. 어떻게 9대로 나누나?

서버 9대면 프로젝트도 9개 만들어야 하나?

아니다. exe는 하나, zone 인자(0~8)만 바꿔 9번 실행한다. 각 실행이 자기 칸(col, row)·포트(9001+zone)·담당 구역을 계산해 그 칸만 맡는다. 존별 차이는 전부 '실행 인자'일 뿐 — 코드 중복 0.

// 서버: 실행 인자로 '내가 몇 번 칸인지'를 받는다
int zoneIdx = args.Length > 0 ? int.Parse(args[0]) : 0; int col = zoneIdx % 3, row = zoneIdx / 3; int Port = 9001 + zoneIdx; // 칸마다 포트 하나 float zx0 = col * 10, zy0 = row * 10; // 이 칸의 담당 구역 [zx0,zx0+10) x [zy0,zy0+10) // 나머지(틱·방송·몬스터)는 STEP 0과 동일하되 '자기 칸'으로 스코프
월드 30×30을 3×3으로: 존6 존7 존8 각 칸 10×10. 존3 존4 존5 존 번호 = row*3 + col. 존0 존1 존2 포트 = 9001 + 존번호.

Part 2. 클라는 어느 서버에 붙나?

클라는 9대 중 어디로 접속할지 어떻게 정하지?

자기 위치로 칸을 계산한다. 위치 → 칸 번호 → 포트. 위치만 알면 어느 서버인지 바로 나온다.

int ZoneOf(float x, float y) => ((int)y / 10) * 3 + ((int)x / 10); int PortOf(int z) => 9001 + z; // (5,5) → 칸0 → :9001 , (15,5) → 칸1 → :9002 , (25,5) → 칸2 → :9003

Part 3. 경계 = 벽 (넘으면 끊고 재접속)

칸을 걸어서 넘어가면 무슨 일이 일어나지?

클라가 걷다가 ZoneOf가 바뀌는 순간(다른 칸 진입), 지금 연결을 끊고 새 칸 서버에 재접속한다. 그 잠깐이 프리즈다. 이게 경계가 벽처럼 느껴지는 이유 — 그리고 STEP 4에서 없앨 바로 그것.

while (ZoneOf(x, y) == curZone && x <= 25) { // 이 칸 안에서 걷는 동안 await Send(CM_MOVE(x, y)); x += 2; // 이동을 이 칸 서버에 보냄 } // 칸이 바뀌었다 → 벽! client.Dispose(); // 지금 서버와 연결 끊고 curZone = ZoneOf(x, y); Console.WriteLine($"⛔ 경계! → zone {curZone} 재접속 (프리즈)"); // 루프 위로 돌아가 새 칸 서버에 다시 connect

Part 4. 옆 칸 안 보임 + 부하 1/9

왜 옆 칸이 안 보이지? 그리고 부하가 나뉜 건 어떻게 확인해?

옆 칸 안 보임: 각 서버는 자기 칸의 사람·몬스터만 알고 방송한다. 존1 서버는 존0을 아예 모른다. 그래서 존1에 있으면 존0 몬스터(M100)가 안 보이고 존1 것(M101)만 보인다.

부하 1/9: 클라가 존0,1,2만 지나가면 나머지 존은 0명인 채로 자기 몬스터만 돌린다. 각 서버가 자기 칸만 감당한다는 증거.

[C] ===== zone 0 접속 (:9001) ===== [C] 🐺 M100 = (9,5) [zone 0] ← 존0 몬스터만 보임 [C] ⛔ 경계! zone 0 → 1 : 연결 끊고 재접속 (프리즈) [C] ===== zone 1 접속 (:9002) ===== [C] 🐺 M101 = (18,5) [zone 1] ← 존1 것만. 존0의 M100은 안 보임(옆 칸 안 보임) ... [Z4] tick #9 | 0명 | M104(14,15) ← 안 방문한 존은 0명 (부하 분산 증명)

❌ 남은 결핍: ① 경계마다 재접속이 클라에 그대로 노출(프리즈) → STEP 2 게이트로 숨긴다. ② 옆 칸이 여전히 안 보임 → STEP 3 고스팅.

★ 이야기로 (A→Z)

네트워크를 몰라도 읽히게.

STEP 0에서 저는 서버 1대짜리 게임을 완성했습니다. 근데 이 한 대가 모든 접속자를 다 감당해야 했습니다. 사람이 많아지면 결국 터집니다. 그래서 월드를 9칸으로 나누고, 칸마다 서버 한 대씩 두기로 했습니다. 그러면 한 대는 자기 칸만 맡으니 부하가 1/9로 줄어듭니다.

공간 분할 — 월드를 격자(3×3)로 잘라 각 조각을 다른 서버가 맡는 방식입니다. 손님을 '사람 수'가 아니라 '땅'으로 나누는 거죠.

서버 9개를 위해 프로젝트를 9개 만들진 않았습니다. 같은 프로그램을 '너는 몇 번 칸이야'라는 인자만 바꿔 9번 실행했습니다. 각 실행이 자기 칸의 위치 범위와 포트를 스스로 계산합니다. 클라는 자기 위치가 몇 번 칸인지 계산해서 그 칸의 서버로 접속했습니다.

여기서 첫 문제가 드러났습니다. 클라가 칸을 걸어서 넘어가면, 이제 다른 서버가 담당입니다. 그런데 지금 구조에선 기존 서버와 연결을 끊고 새 서버에 다시 붙는 수밖에 없었습니다. 그 재접속하는 잠깐 동안 화면이 멈춥니다.

경계 = 벽 — 칸과 칸 사이를 넘을 때마다 끊고 재접속하니, 유저 입장에선 보이지 않는 벽에 부딪혀 잠깐 멈추는 느낌입니다. '하나의 월드'가 아니라 '9개의 방'처럼 느껴집니다.

둘째 문제. 각 서버는 자기 칸만 압니다. 존1 서버는 존0에 누가 있는지, 무슨 몬스터가 있는지 전혀 모릅니다. 그래서 칸 경계 너머는 텅 비어 보입니다. 실제로 클라가 존0에 있을 땐 M100이 보이다가, 존1로 넘어가면 M100은 사라지고 M101만 보였습니다.

정리하면, 9칸으로 나눠 부하는 성공적으로 나눴지만, 그 대가로 경계가 벽이 되고, 옆 칸이 안 보이는 두 결핍이 생겼습니다. 이 둘이 다음 단계들을 부릅니다 — 재접속을 숨기는 게이트(STEP 2), 옆 칸을 보이게 하는 고스팅(STEP 3), 그리고 벽을 없애는 심리스 이주(STEP 4). 여기서 배운 기준은 하나 더 늘었습니다: "나누면 반드시 경계가 생기고, 경계는 새 일감이다."

핵심 정리

  • 월드를 3×3=9칸으로 공간 분할, 같은 exe를 zone 인자만 바꿔 9번 실행 → 부하 1/9.
  • 클라는 자기 위치로 칸을 계산해 그 칸 서버에 접속.
  • 경계를 넘으면 끊고 재접속 = '경계는 벽'(프리즈). → STEP 2 게이트가 숨긴다.
  • 각 서버는 자기 칸만 앎 = 옆 칸 안 보임. → STEP 3 고스팅이 보이게 한다.
  • 교훈: 나누면 반드시 '경계'가 생기고, 경계는 새 일감이다.
