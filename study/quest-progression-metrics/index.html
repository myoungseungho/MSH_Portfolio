성장 곡선 병목을 찾는 기준

이 주제는 왜 자꾸 추상적으로 느껴질까?

퀘스트 재미는 감성으로 설계하고, 진행 문제는 퍼널 데이터로 잡아야 해.

핵심: 추상 판단을 기준어와 지표로 쪼개면 초보자도 바로 실행할 수 있어.

등산 코스 비유

풍경이 좋아도 경사가 급하면 중간에 포기하듯 성장 곡선도 완만해야 해.

시각화: 문제를 구조화하는 시작점

모호한 목표를 구조화하면 에이전트가 같은 방향으로 움직인다.

지금까지 한 줄 요약: 오해를 먼저 분해해야 학습 속도가 붙는다.

퀘스트 성장 용어 카드

처음 보는 용어가 많으면 어디서부터 읽어야 해?

아래 표에서 각 용어를 정의 → 왜 필요한지 → 없으면 생기는 문제 순서로 읽으면 된다.

이 순서가 정리되면 직무가 달라도 같은 문장으로 대화할 수 있다.

용어10초 정의왜 필요한가없으면 생기는 문제
완료 퍼널 (Completion Funnel)단계별 진입/완료 비율 흐름어디서 유저가 떨어지는지 찾으려고문제 구간을 감으로 추측하게 됨
난이도 곡선 (Difficulty Curve)레벨 구간별 체감 난이도 변화성장 리듬을 안정화하려고갑작스러운 벽 구간 생성
진행 병목 (Progression Bottleneck)다음 단계로 못 넘어가는 구간정체 구간을 빠르게 제거하려고반복 정체로 이탈 증가

시각화: 용어 정렬 이후

용어 오해가 줄어들면 수정 요청의 왕복이 줄어든다.

지금까지 한 줄 요약: 용어 정의를 합의해야 지표가 제대로 작동한다.

퀘스트 진행 지표

지표는 어떻게 정해야 초보자도 바로 쓸 수 있어?

처음엔 5개 내외가 좋아. 너무 많으면 운영이 무거워져.

측정 가능 + 행동 연결 가능 조건을 충족하는 지표만 남겨야 실제로 굴러간다.

지표정의목표미달 시 액션
단계 완료율각 단계 시작 대비 완료 비율목표 범위이탈 높은 단계 우선 수정
평균 완료 시간퀘스트 1개 완료 시간기획 범위동선/조건 단순화
재도전 횟수실패 단계 평균 재시도3회 이하난이도/보상 보정
병목률다음 단계 진입 실패 비율10% 이하병목 단계 분해
구간 이탈률해당 구간 세션 종료 비율목표 이하튜토리얼/힌트 보강
[검증 게이트 예시] 1) PR 생성 시 자동 측정 2) 야간 배치 종료 시 재측정 3) 기준 미달 항목 자동 반려 4) 동일 시나리오 재검증 통과 후 병합

시각화: 지표 기반 판정 루프

지표는 보고용 숫자가 아니라 다음 행동을 정하는 기준이다.

병목 개선 실행 루프

그래서 지금 당장 어떤 순서로 실행하면 돼?

아래 순서를 그대로 작업 티켓으로 나눠 실행하면 된다.

각 단계 완료 시 지표를 다시 측정해서 통과 여부를 확인한다.

  1. 메인 퀘스트 퍼널로 분해
  2. 구간별 완료/이탈 자동 집계
  3. 병목 단계 자동 탐지
  4. 보상/난이도 A/B 조정안 생성
  5. 통과안 본 서버 반영

시각화: 실행 루프가 고정된 상태

순서가 고정되면 에이전트가 밤에도 같은 리듬으로 협업한다.

지금까지 한 줄 요약: 실행 순서와 통과 기준을 함께 고정해야 자동 협업이 유지된다.

📌 핵심 정리

  • 퀘스트 개선은 퍼널 데이터로 병목을 찾는 것이 핵심
  • 완료율/이탈률/재도전 횟수를 함께 봐야 원인이 보임
  • A/B 기반 조정이 시행착오를 줄임
  • 병목률을 줄이면 성장 체감과 잔존이 함께 개선됨
