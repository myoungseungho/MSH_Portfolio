Procedural Assets

알고리즘으로 에셋을 생성하는 기술

Part 1: 프로시저럴 생성이란

Q1: "프로시저럴 에셋"이 뭔가요? 그냥 만들어둔 에셋이랑 뭐가 다른 거죠?

미리 만들어둔 파일이 아니라, 알고리즘으로 실시간 생성하는 에셋입니다.

[전통 에셋 vs 프로시저럴 에셋]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
          전통 에셋                 프로시저럴 에셋
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
생성      아티스트가 제작          알고리즘이 생성
저장      파일로 저장 (MB~GB)      시드값만 저장 (bytes)
다양성    제작된 만큼만            무한 변형 가능
로딩      디스크에서 읽기          CPU/GPU 연산
품질      일관된 고품질            품질 변동 있음
수정      재작업 필요              파라미터 조정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[프로시저럴 에셋의 동작]

입력:  Seed = 12345
           │
           ↓
    ┌─────────────────┐
    │  프로시저럴      │
    │  생성 알고리즘   │
    │  (노이즈, 규칙)  │
    └─────────────────┘
           │
           ↓
출력:  텍스처, 메시, 지형, 던전 등

→ 같은 시드 = 항상 같은 결과 (결정적)
→ 시드만 공유하면 모든 클라이언트가 동일한 월드 생성

프로시저럴 생성의 대표 사례:

Minecraft
├─ 지형: Perlin Noise 기반
├─ 동굴: 3D Noise Carving
├─ 바이옴: 온도/습도 기반 선택
└─ 시드 하나로 무한 월드 생성

No Man's Sky
├─ 행성: 18경(quintillion)개 행성
├─ 생물: 조합형 프로시저럴 생물
├─ 식물: L-System 변형
└─ 저장 용량: ~10GB (무한 우주)

Hades
├─ 던전 구조: Wave Function Collapse
├─ 방 배치: 규칙 기반 생성
└─ 적 배치: 난이도 기반 생성
Q2: 프로시저럴 생성의 장단점은 뭔가요?

저장 공간 절약과 무한 다양성이 최대 장점, 품질 제어가 최대 단점입니다.

[장점]

1. 저장 공간 절약
   전통: 100개 나무 모델 = 500MB
   프로시저럴: 나무 생성 알고리즘 + 파라미터 = 1MB
   → 99.8% 절약

2. 무한한 다양성
   전통: 10종류 지형 → 반복 느껴짐
   프로시저럴: 시드별 고유 지형 → 항상 새로움

3. 런타임 커스터마이징
   전통: 빌드 후 변경 불가
   프로시저럴: 파라미터로 실시간 조절 가능

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[단점]

1. 품질 제어 어려움
   - 모든 결과물이 "좋아 보일" 보장 없음
   - 극단적 파라미터 → 이상한 결과
   - 예: "이상하게 생긴 지형" 발생

2. 연산 비용
   - 로딩 대신 생성 = CPU/GPU 시간 소모
   - 복잡한 알고리즘 → 프레임 드롭

3. 디버깅 어려움
   - 특정 시드에서만 발생하는 버그
   - 재현하려면 시드 필요

4. 아티스트 제어력 감소
   - "정확히 이렇게" 만들기 어려움
   - 의도한 비주얼 보장 안 됨

Part 2: 노이즈 함수

Q3: 프로시저럴 생성에서 "노이즈"가 왜 중요한가요?

노이즈는 "자연스러운 무작위"를 만드는 핵심 도구입니다.

[순수 랜덤 vs 노이즈]

순수 랜덤 (rand()):
██░░██░░░░██████░░██░░░░████░░██
→ 각 픽셀이 독립적 → 지글지글 (white noise)
→ 지형으로 쓰면: 뾰족뾰족 산 (비현실적)

Perlin Noise:
░░░▒▒▓▓██████▓▓▒▒░░░░▒▒▓▓██▓▓▒▒░░
→ 이웃 픽셀과 부드럽게 연결
→ 지형으로 쓰면: 완만한 언덕 (자연스러움)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[노이즈의 특성]

1. 결정적 (Deterministic)
   - 같은 좌표 → 항상 같은 값
   - noise(5.2, 3.1) = 0.742... (항상)

2. 연속적 (Continuous)
   - noise(5.2) ≈ noise(5.3) (비슷한 값)
   - 부드러운 변화

3. 범위 제한
   - 보통 -1 ~ 1 또는 0 ~ 1
   - 예측 가능한 출력 범위

Perlin Noise 기본 구현:

// 간소화된 Perlin Noise 2D
class PerlinNoise {
public:
    PerlinNoise(unsigned int seed = 0) {
        // 순열 테이블 초기화
        for (int i = 0; i < 256; i++) {
            p[i] = i;
        }
        // 시드 기반 셔플
        std::mt19937 rng(seed);
        std::shuffle(p, p + 256, rng);
        // 중복해서 256~511 채우기 (래핑용)
        for (int i = 0; i < 256; i++) {
            p[256 + i] = p[i];
        }
    }

    float Sample(float x, float y) {
        // 정수 좌표 (격자 위치)
        int xi = (int)floor(x) & 255;
        int yi = (int)floor(y) & 255;

        // 소수 좌표 (셀 내 위치)
        float xf = x - floor(x);
        float yf = y - floor(y);

        // 페이드 함수 (부드러운 보간)
        float u = Fade(xf);
        float v = Fade(yf);

        // 해시 (순열 테이블 참조)
        int aa = p[p[xi] + yi];
        int ab = p[p[xi] + yi + 1];
        int ba = p[p[xi + 1] + yi];
        int bb = p[p[xi + 1] + yi + 1];

        // 그래디언트 계산 및 보간
        float x1 = Lerp(Grad(aa, xf, yf), Grad(ba, xf - 1, yf), u);
        float x2 = Lerp(Grad(ab, xf, yf - 1), Grad(bb, xf - 1, yf - 1), u);

        return Lerp(x1, x2, v);  // -1 ~ 1 범위
    }

private:
    int p[512];

    float Fade(float t) {
        // 6t^5 - 15t^4 + 10t^3 (개선된 페이드 함수)
        return t * t * t * (t * (t * 6 - 15) + 10);
    }

    float Grad(int hash, float x, float y) {
        // 의사-랜덤 그래디언트 벡터와 내적
        int h = hash & 3;
        float u = h < 2 ? x : y;
        float v = h < 2 ? y : x;
        return ((h & 1) ? -u : u) + ((h & 2) ? -v : v);
    }
};
Q4: fBm (Fractal Brownian Motion)이 뭔가요?

여러 주파수의 노이즈를 합쳐서 복잡한 패턴을 만드는 기법입니다.

[fBm = 여러 옥타브의 합]

옥타브 1 (낮은 주파수):
  ▁▂▃▅▆█▆▅▃▂▁▂▃▄▅▆▇█▇▆▅▄▃▂▁
  → 큰 산, 큰 언덕

옥타브 2 (중간 주파수):
  ▂▄▆▇▆▄▂▃▅▇▆▄▂▃▅▆▅▃▂▄▆█▆▄▂
  → 중간 언덕

옥타브 3 (높은 주파수):
  ▃▅▄▆▅▇▆█▇▅▆▄▅▆▇▆▅▄▆▇█▆▅▄▃
  → 작은 돌, 표면 디테일

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
합성:  옥타브1 + 옥타브2×0.5 + 옥타브3×0.25

결과:  ▂▄▅▇██▇▅▄▃▃▄▅▆▇██▇▆▅▄▃▂▃▄▅▆▇
       → 자연스러운 지형 (큰 구조 + 세부 디테일)

float FBM(float x, float y, int octaves, float lacunarity, float persistence) {
    float total = 0.0f;
    float amplitude = 1.0f;
    float frequency = 1.0f;
    float maxValue = 0.0f;  // 정규화용

    for (int i = 0; i < octaves; i++) {
        total += m_Noise.Sample(x * frequency, y * frequency) * amplitude;

        maxValue += amplitude;

        amplitude *= persistence;   // 진폭 감소 (보통 0.5)
        frequency *= lacunarity;    // 주파수 증가 (보통 2.0)
    }

    return total / maxValue;  // -1 ~ 1 정규화
}

// 사용 예: 지형 높이맵 생성
float height = FBM(worldX * 0.01f, worldZ * 0.01f, 6, 2.0f, 0.5f);

// 파라미터 의미:
// octaves = 6      → 디테일 수준
// lacunarity = 2.0 → 각 레벨의 주파수 배율
// persistence = 0.5 → 각 레벨의 진폭 비율

[노이즈 종류별 특성]

Perlin Noise
├─ 가장 유명한 노이즈
├─ 격자 기반 그래디언트 보간
├─ 약간의 축 정렬 아티팩트
└─ 용도: 지형, 구름, 대리석

Simplex Noise
├─ Perlin의 개선판 (Ken Perlin)
├─ 삼각형 격자 → 더 자연스러움
├─ 계산 효율 좋음 (고차원에서)
└─ 용도: 3D 지형, 볼륨 노이즈

Worley (Cellular) Noise
├─ 점들 사이의 거리 기반
├─ 세포, 돌, 금속 패턴
├─ 가장 가까운 점까지 거리 = 밝기
└─ 용도: 돌바닥, 균열, 유기체 표면

Value Noise
├─ 격자점에 랜덤값 → 보간
├─ Perlin보다 단순하지만 덜 자연스러움
├─ 축 정렬 아티팩트 심함
└─ 용도: 단순한 랜덤 필요 시

Part 3: 프로시저럴 텍스처

Q5: 텍스처를 프로시저럴하게 만들면 어떤 장점이 있나요?

해상도 무제한, 메모리 절약, 실시간 변형이 가능합니다.

[프로시저럴 텍스처 vs 이미지 텍스처]

이미지 텍스처:
├─ 4K 텍스처 = 64MB VRAM
├─ 가까이 가면 픽셀 보임
├─ 타일링하면 반복 눈에 띔
└─ 변형하려면 새 이미지 필요

프로시저럴 텍스처:
├─ 알고리즘 = 수KB
├─ 무한 해상도 (런타임 계산)
├─ 반복 없음 (좌표 기반 생성)
└─ 파라미터로 실시간 변형

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[프로시저럴 텍스처 활용]

1. 셰이더에서 직접 생성
   - 픽셀 셰이더가 UV에서 노이즈 계산
   - 메모리: 0 (텍스처 없음!)
   - 단점: GPU 연산 비용

2. 미리 베이크 후 사용
   - 빌드 시 프로시저럴 → 이미지 변환
   - 런타임 비용 없음
   - 무한 해상도 혜택은 없음

3. 런타임 캐시
   - 필요할 때 생성 → 텍스처 캐시
   - 최선의 절충안

셰이더에서 프로시저럴 텍스처:

// 프로시저럴 대리석 텍스처 셰이더
float4 ProceduralMarble(float2 uv) {
    // 기본 노이즈
    float noise = fbm(uv * 4.0, 6);

    // 줄무늬 패턴 (사인파 + 노이즈 왜곡)
    float vein = sin(uv.x * 20.0 + noise * 10.0);
    vein = smoothstep(0.0, 0.1, abs(vein));

    // 색상
    float3 baseColor = float3(0.95, 0.93, 0.88);  // 밝은 크림색
    float3 veinColor = float3(0.3, 0.3, 0.35);    // 어두운 회색

    float3 color = lerp(veinColor, baseColor, vein);

    return float4(color, 1.0);
}

// 프로시저럴 나무 텍스처
float4 ProceduralWood(float2 uv) {
    // 나이테 패턴 (거리 기반)
    float2 center = uv - 0.5;
    float dist = length(center) * 10.0;

    // 노이즈로 나이테 왜곡
    float noise = fbm(uv * 2.0, 4) * 0.5;
    float rings = sin(dist + noise * 5.0);
    rings = (rings + 1.0) * 0.5;  // 0~1 정규화

    // 색상 (밝은 나무 ~ 어두운 나무)
    float3 lightWood = float3(0.85, 0.65, 0.4);
    float3 darkWood = float3(0.5, 0.3, 0.15);

    float3 color = lerp(darkWood, lightWood, rings);

    return float4(color, 1.0);
}
Q6: 노말맵도 프로시저럴하게 만들 수 있나요?

네, 높이맵에서 그래디언트를 계산하여 노말을 생성합니다.

float3 GenerateNormalFromHeight(float2 uv, float heightScale) {
    // 주변 높이 샘플링
    float2 texelSize = 1.0 / _TextureSize;

    float hL = GetProceduralHeight(uv - float2(texelSize.x, 0));
    float hR = GetProceduralHeight(uv + float2(texelSize.x, 0));
    float hD = GetProceduralHeight(uv - float2(0, texelSize.y));
    float hU = GetProceduralHeight(uv + float2(0, texelSize.y));

    // 기울기 계산 (Sobel-like)
    float dX = (hR - hL) * heightScale;
    float dY = (hU - hD) * heightScale;

    // 노말 벡터 구성
    float3 normal = normalize(float3(-dX, -dY, 1.0));

    // 탄젠트 공간 노말맵 인코딩 (0~1)
    return normal * 0.5 + 0.5;
}

// 프로시저럴 벽돌 노말
float3 ProceduralBrickNormal(float2 uv) {
    // 벽돌 그리드
    float2 brickUV = uv * float2(4, 8);  // 4x8 그리드
    float2 brickId = floor(brickUV);

    // 홀수 행 오프셋 (벽돌 쌓기 패턴)
    if (fmod(brickId.y, 2) == 1) {
        brickUV.x += 0.5;
    }

    float2 localUV = frac(brickUV);

    // 벽돌 내부의 높이
    float height = 0.0;

    // 그라우트(줄눈) 영역
    float grout = 0.05;
    if (localUV.x < grout || localUV.x > 1-grout ||
        localUV.y < grout || localUV.y > 1-grout) {
        height = -0.1;  // 줄눈은 낮음
    } else {
        // 벽돌 표면 노이즈
        height = fbm(uv * 20.0, 3) * 0.02;
    }

    return GenerateNormalFromHeight(uv, height);
}

Part 4: 프로시저럴 메시

Q7: 메시(3D 모델)도 프로시저럴하게 만들 수 있나요?

네, 지형부터 건물, 식물까지 다양한 메시를 알고리즘으로 생성합니다.

[프로시저럴 메시 생성 방법]

1. 높이맵 → 지형 메시
   ┌───────────────┐
   │ 높이맵 (2D)   │
   │ ░░▒▒▓▓██▓▓▒▒░░│
   └───────────────┘
           │
           ↓ 버텍스 Z = 높이값
   ┌───────────────┐
   │     /\  /\    │
   │   /\  /\  /\  │   ← 메시 (3D)
   │  ────────────  │
   └───────────────┘

Mesh GenerateTerrainMesh(int width, int height, float scale) {
    std::vector<Vertex> vertices;
    std::vector<uint32_t> indices;

    // 버텍스 생성
    for (int z = 0; z <= height; z++) {
        for (int x = 0; x <= width; x++) {
            Vertex v;

            // 위치 (노이즈로 높이 결정)
            float noiseX = x * scale;
            float noiseZ = z * scale;
            float heightValue = FBM(noiseX * 0.02f, noiseZ * 0.02f, 6, 2.0f, 0.5f);
            heightValue = (heightValue + 1.0f) * 0.5f;  // 0~1 정규화
            heightValue = pow(heightValue, 2.0f);       // 산을 더 날카롭게

            v.position = Vector3(x * scale, heightValue * 50.0f, z * scale);

            // UV
            v.uv = Vector2((float)x / width, (float)z / height);

            // 노말 (나중에 계산)
            v.normal = Vector3(0, 1, 0);

            vertices.push_back(v);
        }
    }

    // 인덱스 생성 (삼각형)
    for (int z = 0; z < height; z++) {
        for (int x = 0; x < width; x++) {
            int topLeft = z * (width + 1) + x;
            int topRight = topLeft + 1;
            int bottomLeft = topLeft + (width + 1);
            int bottomRight = bottomLeft + 1;

            // 첫 번째 삼각형
            indices.push_back(topLeft);
            indices.push_back(bottomLeft);
            indices.push_back(topRight);

            // 두 번째 삼각형
            indices.push_back(topRight);
            indices.push_back(bottomLeft);
            indices.push_back(bottomRight);
        }
    }

    // 노말 계산
    CalculateNormals(vertices, indices);

    return Mesh(vertices, indices);
}
Q8: Marching Cubes가 뭔가요?

3D 스칼라 필드에서 등치면(isosurface)을 추출하는 알고리즘입니다.

[Marching Cubes 원리]

1. 3D 공간을 그리드로 분할
   ┌───┬───┬───┐
   │   │   │   │
   ├───┼───┼───┤   ← 각 셀이 큐브
   │   │   │   │
   └───┴───┴───┘

2. 각 꼭짓점에서 밀도값 샘플링
   ●─────────○
   │         │    ● = 표면 안 (밀도 > threshold)
   │         │    ○ = 표면 밖 (밀도 < threshold)
   ○─────────●

3. 256가지 케이스 중 하나 선택
   안/밖 조합에 따라 삼각형 생성 패턴 결정

4. 삼각형 생성
   ●─────────○
   │\   ╱    │
   │ ╲╱     │    ← 표면을 근사하는 삼각형
   ○────●────●

용도:
- 3D Noise → 동굴, 행성 지형
- CT 스캔 → 의료 영상 시각화
- 메타볼(Metaball) → 용암, 물방울

// Marching Cubes 간소화 (핵심 개념)
void MarchingCubes(float*** densityField, int size, float threshold,
                   std::vector<Triangle>& triangles) {
    for (int z = 0; z < size - 1; z++) {
        for (int y = 0; y < size - 1; y++) {
            for (int x = 0; x < size - 1; x++) {
                // 8개 꼭짓점의 밀도 수집
                float corners[8];
                corners[0] = densityField[x][y][z];
                corners[1] = densityField[x+1][y][z];
                corners[2] = densityField[x+1][y+1][z];
                corners[3] = densityField[x][y+1][z];
                corners[4] = densityField[x][y][z+1];
                corners[5] = densityField[x+1][y][z+1];
                corners[6] = densityField[x+1][y+1][z+1];
                corners[7] = densityField[x][y+1][z+1];

                // 케이스 인덱스 계산 (0~255)
                int cubeIndex = 0;
                for (int i = 0; i < 8; i++) {
                    if (corners[i] > threshold) {
                        cubeIndex |= (1 << i);
                    }
                }

                // 룩업 테이블에서 삼각형 생성
                GenerateTriangles(cubeIndex, corners, threshold, triangles);
            }
        }
    }
}

Part 5: L-System과 식물 생성

Q9: L-System이 뭔가요? 왜 식물 생성에 좋은가요?

문자열 치환 규칙으로 자기 유사(self-similar) 구조를 만드는 시스템입니다.

[L-System 기본 원리]

공리 (시작): A
규칙: A → AB
      B → A

세대별 진화:
  n=0:  A
  n=1:  AB           (A→AB)
  n=2:  ABA          (A→AB, B→A)
  n=3:  ABAAB        (A→AB, B→A, A→AB)
  n=4:  ABAABABA     ...

→ 피보나치 수열과 같은 성장 패턴!

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[나무 생성용 L-System]

공리: F
규칙: F → F[+F]F[-F]F

해석:
  F  = 앞으로 이동하며 선 그리기
  +  = 왼쪽으로 25° 회전
  -  = 오른쪽으로 25° 회전
  [  = 현재 상태 저장 (스택 push)
  ]  = 상태 복원 (스택 pop)

n=1:  F[+F]F[-F]F
      │
      ↓
        ╱
      ─┼─      ← 간단한 가지
        ╲

n=3 이상:
          ╱╲
        ╱    ╲
      ─┼─  ─┼─
    ╱   ╲╱   ╲  ← 복잡한 나무
   ─┼─────────┼─
        │

L-System 구현:

class LSystem {
public:
    struct Rule {
        char symbol;
        std::string replacement;
        float probability;  // 확률적 L-System용
    };

    std::string axiom;
    std::vector<Rule> rules;
    float angle = 25.0f;
    float length = 1.0f;
    float lengthDecay = 0.9f;  // 세대마다 길이 감소

    std::string Generate(int iterations) {
        std::string current = axiom;

        for (int i = 0; i < iterations; i++) {
            std::string next;
            for (char c : current) {
                bool replaced = false;
                for (const auto& rule : rules) {
                    if (c == rule.symbol) {
                        // 확률적 규칙 (다양성 추가)
                        if (rule.probability >= 1.0f ||
                            Random01() < rule.probability) {
                            next += rule.replacement;
                            replaced = true;
                            break;
                        }
                    }
                }
                if (!replaced) {
                    next += c;
                }
            }
            current = next;
        }

        return current;
    }

    Mesh InterpretAsMesh(const std::string& lstring) {
        std::vector<Vertex> vertices;
        std::vector<uint32_t> indices;
        std::stack<TurtleState> stateStack;

        TurtleState turtle;
        turtle.position = Vector3::Zero;
        turtle.direction = Vector3::Up;
        turtle.currentLength = length;

        for (char c : lstring) {
            switch (c) {
                case 'F':  // 앞으로 이동 + 선분 생성
                    {
                        Vector3 end = turtle.position +
                                      turtle.direction * turtle.currentLength;
                        AddBranch(vertices, indices,
                                  turtle.position, end, turtle.thickness);
                        turtle.position = end;
                        turtle.currentLength *= lengthDecay;
                    }
                    break;

                case '+':  // Z축 기준 왼쪽 회전
                    turtle.direction = RotateY(turtle.direction, angle);
                    break;

                case '-':  // Z축 기준 오른쪽 회전
                    turtle.direction = RotateY(turtle.direction, -angle);
                    break;

                case '&':  // X축 기준 아래로
                    turtle.direction = RotateX(turtle.direction, angle);
                    break;

                case '^':  // X축 기준 위로
                    turtle.direction = RotateX(turtle.direction, -angle);
                    break;

                case '[':  // 상태 저장
                    stateStack.push(turtle);
                    turtle.thickness *= 0.7f;  // 가지 두께 감소
                    break;

                case ']':  // 상태 복원
                    turtle = stateStack.top();
                    stateStack.pop();
                    break;
            }
        }

        return Mesh(vertices, indices);
    }
};

Part 6: Wave Function Collapse

Q10: Wave Function Collapse가 뭔가요? 던전 생성에 어떻게 쓰나요?

이웃 제약 조건을 만족하면서 타일을 배치하는 알고리즘입니다.

[Wave Function Collapse 원리]

1. 시작: 모든 셀이 "미결정" 상태
   ┌───┬───┬───┬───┐
   │ ? │ ? │ ? │ ? │   ? = 모든 타일이 가능
   ├───┼───┼───┼───┤
   │ ? │ ? │ ? │ ? │
   └───┴───┴───┴───┘

2. 가장 낮은 엔트로피 셀 선택
   (가능한 타일 수가 가장 적은 셀)

3. 랜덤하게 타일 하나 결정
   ┌───┬───┬───┬───┐
   │ ? │ ? │ ? │ ? │
   ├───┼───┼───┼───┤
   │ ? │ ═ │ ? │ ? │   ═ = 복도 타일로 결정!
   └───┴───┴───┴───┘

4. 제약 조건 전파 (Propagation)
   ┌───┬───┬───┬───┐
   │ ? │ ? │ ? │ ? │
   ├───┼───┼───┼───┤
   │═/╬│ ═ │═/╬│ ? │   이웃에 연결 가능한 타일만 남김
   └───┴───┴───┴───┘

5. 2~4 반복 → 완성
   ┌───┬───┬───┬───┐
   │ ╔ │ ═ │ ═ │ ╗ │
   ├───┼───┼───┼───┤
   │ ║ │ ╬ │ ═ │ ║ │   완성된 던전!
   └───┴───┴───┴───┘

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[타일 연결 규칙 예시]

타일:  ═ (가로 복도)
├─ 왼쪽: ═, ╬, ╠, ╔, ╚ 가능
├─ 오른쪽: ═, ╬, ╣, ╗, ╝ 가능
├─ 위: 벽, ╦, 없음
└─ 아래: 벽, ╩, 없음

타일:  ╬ (교차로)
├─ 왼쪽: ═, ╬, ╠, ╔, ╚ 가능
├─ 오른쪽: ═, ╬, ╣, ╗, ╝ 가능
├─ 위: ║, ╬, ╦, ╠, ╣ 가능
└─ 아래: ║, ╬, ╩, ╠, ╣ 가능

WFC 구현:

class WaveFunctionCollapse {
public:
    struct Cell {
        std::set<int> possibleTiles;  // 가능한 타일 ID들
        bool collapsed = false;
        int finalTile = -1;
    };

    void Initialize(int width, int height) {
        m_Grid.resize(width * height);
        for (auto& cell : m_Grid) {
            // 모든 타일이 가능한 상태로 시작
            for (int i = 0; i < m_TileCount; i++) {
                cell.possibleTiles.insert(i);
            }
        }
    }

    bool Collapse() {
        while (true) {
            // 1. 가장 낮은 엔트로피(가능성이 적은) 셀 찾기
            int minEntropy = INT_MAX;
            int targetCell = -1;

            for (int i = 0; i < m_Grid.size(); i++) {
                if (!m_Grid[i].collapsed) {
                    int entropy = m_Grid[i].possibleTiles.size();
                    if (entropy < minEntropy) {
                        minEntropy = entropy;
                        targetCell = i;
                    }
                }
            }

            // 모두 collapse됨 = 완료
            if (targetCell == -1) return true;

            // 가능한 타일이 없음 = 모순 (실패)
            if (minEntropy == 0) return false;

            // 2. 랜덤하게 타일 선택
            Cell& cell = m_Grid[targetCell];
            std::vector<int> options(cell.possibleTiles.begin(),
                                      cell.possibleTiles.end());
            cell.finalTile = options[rand() % options.size()];
            cell.collapsed = true;
            cell.possibleTiles.clear();
            cell.possibleTiles.insert(cell.finalTile);

            // 3. 제약 조건 전파
            Propagate(targetCell);
        }
    }

private:
    void Propagate(int startCell) {
        std::queue<int> toProcess;
        toProcess.push(startCell);

        while (!toProcess.empty()) {
            int current = toProcess.front();
            toProcess.pop();

            // 4방향 이웃 확인
            for (int dir = 0; dir < 4; dir++) {
                int neighbor = GetNeighbor(current, dir);
                if (neighbor < 0 || m_Grid[neighbor].collapsed)
                    continue;

                // 현재 셀과 호환되지 않는 타일 제거
                bool changed = false;
                auto& possible = m_Grid[neighbor].possibleTiles;

                for (auto it = possible.begin(); it != possible.end(); ) {
                    if (!IsCompatible(current, neighbor, *it, dir)) {
                        it = possible.erase(it);
                        changed = true;
                    } else {
                        ++it;
                    }
                }

                if (changed) {
                    toProcess.push(neighbor);
                }
            }
        }
    }
};

class ProceduralAssetManager {
public:
    // 1. 시드 관리 - 재현성 보장
    void SetWorldSeed(uint64_t seed) {
        m_WorldSeed = seed;
    }

    uint64_t GetChunkSeed(int chunkX, int chunkZ) {
        // 청크별 고유 시드 (월드 시드에서 파생)
        return Hash(m_WorldSeed, chunkX, chunkZ);
    }

    // 2. 품질 검증 - 나쁜 결과 필터링
    bool ValidateGeneratedContent(const GeneratedLevel& level) {
        // 플레이 가능성 검증
        if (!HasPathFromStartToEnd(level)) {
            return false;  // 막힌 레벨 거부
        }

        // 밸런스 검증
        if (CountEnemies(level) > MAX_ENEMIES_PER_ROOM) {
            return false;  // 너무 어려움
        }

        // 미적 검증
        if (GetEmptySpaceRatio(level) > 0.7f) {
            return false;  // 너무 텅 빔
        }

        return true;
    }

    // 검증 실패 시 다른 시드로 재생성
    GeneratedLevel GenerateValidLevel() {
        const int MAX_ATTEMPTS = 100;

        for (int i = 0; i < MAX_ATTEMPTS; i++) {
            GeneratedLevel level = GenerateLevel(m_CurrentSeed + i);

            if (ValidateGeneratedContent(level)) {
                return level;
            }
        }

        // 폴백: 수작업 레벨 사용
        return LoadHandcraftedLevel("fallback_level");
    }

    // 3. 성능 최적화 - LOD와 캐싱
    Mesh GetProceduralMesh(const std::string& id, int lodLevel) {
        std::string cacheKey = id + "_lod" + std::to_string(lodLevel);

        // 캐시 확인
        if (m_MeshCache.Contains(cacheKey)) {
            return m_MeshCache.Get(cacheKey);
        }

        // 생성 (비동기로 처리 권장)
        Mesh mesh = GenerateMesh(id, lodLevel);
        m_MeshCache.Put(cacheKey, mesh);

        return mesh;
    }
};
