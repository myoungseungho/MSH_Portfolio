C# / Unity NDC 2019
Boxing Enum Generic GC Unity

1. 박싱(Boxing)이란?

박싱이 뭔가요?

C#에서 값 타입(int, struct 등)을 참조 타입(object)으로 변환할 때 발생하는 과정입니다.

값 타입: 스택(Stack)에 저장 참조 타입: 힙(Heap)에 저장 박싱 과정: 1. 힙에 "박스" 공간 할당 2. 스택의 값을 박스에 복사 3. 박스의 참조를 반환
void PrintValue(object obj) {
    Debug.Log(obj);
}

int num = 42;
PrintValue(num);  // 여기서 박싱 발생!
                  // int(값 타입) → object(참조 타입)
왜 박싱이 문제인가요?

박싱 = 힙 할당 = GC 대상

박싱이 발생하면 힙에 메모리가 할당되고, 이 메모리는 나중에 GC(Garbage Collection)가 정리해야 합니다.

박싱 1회 → 힙 할당 (12~24 바이트) 박싱 100회 → 쓰레기 100개 생성 쓰레기 누적 → GC 발생 GC 발생 → 프레임 드랍!

게임에서 GC = 스파이크

GC가 돌면 게임이 순간 멈추고, 플레이어는 "끊김"을 느낍니다. 특히 모바일 게임에서는 치명적입니다.

박싱된 객체의 크기는 얼마인가요?
타입 32-bit 64-bit
값 타입 (int 등) 4 바이트 4 바이트
박싱된 객체 12 바이트 24 바이트

참조 타입은 Virtual Table 포인터와 Type 정보를 헤더로 가지기 때문에 8바이트(64-bit 기준 16바이트)가 추가됩니다.

예시 계산

한 프레임에 Equals 비교 125회 발생
→ 비교당 박싱 2회 × 24바이트 = 48바이트
→ 125 × 48 = 6KB/프레임
→ 60fps면 360KB/초 쓰레기 발생

2. Enum + Generic = 박싱 지옥

왜 Enum과 Generic이 만나면 박싱이 발생하나요?

제네릭 메서드에서 Equals()를 호출하면, 내부적으로 object.Equals(object)가 호출됩니다. 

void Compare<T>(T a, T b) {
    if (a.Equals(b)) {  // 여기서 박싱!
        // ...
    }
}

enum CardRank { Ace, King, Queen }
Compare(CardRank.Ace, CardRank.King);  // 박싱 2회 발생

왜 그럴까?

Equals() 메서드 시그니처: public virtual bool Equals(object obj) ^^^^^^ object 타입! Enum은 값 타입 → object로 변환 → 박싱! 추가로: - a.Equals(b) 호출 시 b가 박싱됨 (인자) - a도 object의 Equals를 호출하려면 박싱됨 (수신자) = 비교 1회에 박싱 2회!
Dictionary에서도 이 문제가 발생하나요?

네! Dictionary<TKey, TValue>에서 Enum을 키로 사용하면 검색할 때마다 박싱이 발생합니다. 

Dictionary<CardRank, int> cardValues = new();

cardValues[CardRank.Ace] = 1;   // 박싱 발생!
var value = cardValues[CardRank.Ace];  // 또 박싱!

List도 마찬가지

List<T>.Contains(), IndexOf(), Remove() 등 내부에서 Equals를 호출하는 모든 메서드에서 Enum 사용 시 박싱 발생!

Enum.HasFlag()도 문제인가요?

비트 마스킹을 위해 자주 쓰는 HasFlag()도 박싱이 발생합니다. 

[Flags]
enum Permissions { Read = 1, Write = 2, Execute = 4 }

Permissions perm = Permissions.Read | Permissions.Write;
bool canWrite = perm.HasFlag(Permissions.Write);  // 박싱!

HasFlag 내부 구현

public bool HasFlag(Enum flag)  // Enum = 참조 타입!
{
    // 내부에서 object로 다루므로 박싱 발생
}

성능을 위해 비트 마스킹을 쓴 건데, 실제로는 박싱으로 인해 오히려 쓰레기가 더 많이 발생하는 역설!

3. 정석적 해법과 그 한계

C#에서 제공하는 공식 해결책은 뭔가요?

IEqualityComparer 커스텀 구현

Dictionary나 List 생성자에 커스텀 Comparer를 넘기면 내부에서 그 Comparer를 사용합니다. 

public class CardRankComparer : IEqualityComparer<CardRank>
{
    public bool Equals(CardRank x, CardRank y)
    {
        return x == y;  // 구체 타입이라 박싱 없음!
    }

    public int GetHashCode(CardRank obj)
    {
        return (int)obj;  // int로 캐스팅, 박싱 없음
    }
}

// 사용
var dict = new Dictionary<CardRank, int>(new CardRankComparer());
정석적 해법의 문제점은 뭔가요?

"이게 해법이라고?"

  • Enum 타입마다 Comparer 클래스를 만들어야 함
  • Dictionary 생성할 때마다 Comparer를 넘겨야 함
  • 까먹으면 다시 박싱 발생
  • 프로그래머한테 일을 시키는 거지!
"언어를 이렇게 쓰라고 하는 거지?" Enum 10개 만들면 → Comparer 10개 작성 Dictionary 100개 만들면 → 생성자 100개 수정 영화 <극한직업> 대사가 떠오름: "이게 해법이라고 내놓는 거지?"
C# 7.3의 Enum 제약은 해결책이 되나요?

C# 7.3부터 제네릭에 where T : Enum 제약을 걸 수 있게 되었습니다. 

void Process<T>(T value) where T : Enum
{
    // T가 Enum임을 컴파일러가 알게 됨
}

// Enum.GetValues 같은 것도 안전하게 사용 가능

하지만...

컴파일러가 T가 Enum인 걸 알아도, Equals 호출 시 여전히 박싱이 발생합니다. 

// IL 코드를 보면...
box !!T          // 여전히 박싱!
callvirt Equals

결론

C# 7.3의 Enum 제약은 타입 안전성만 제공할 뿐, 박싱 문제는 해결하지 못합니다.

4. 실용적 해결책: Enum ↔ int 변환

핵심 아이디어가 뭔가요?

Enum은 내부적으로 int

Enum은 결국 숫자입니다. int로 바꿔서 처리하면 박싱이 발생하지 않습니다!

CardRank.Ace = 0 (내부적으로 int 0) CardRank.King = 1 (내부적으로 int 1) int끼리 비교 → 박싱 없음! int를 Dictionary 키로 → 박싱 없음!

문제

일반 Enum은 (int)enumValue로 쉽게 변환 가능. 하지만 제네릭 T는 타입을 모르니까 캐스팅 불가! 

void Process<T>(T value) where T : Enum
{
    int num = (int)value;  // 컴파일 에러!
                          // T가 뭔지 모르니까 캐스팅 불가
}
해결책 1: 동적 코드 생성 (Expression)

런타임에 T 타입을 알게 되면, 그때 변환 코드를 동적으로 생성합니다. 

public static class EnumConverter<TFrom, TTo>
{
    public static readonly Func<TFrom, TTo> Convert;

    static EnumConverter()
    {
        var param = Expression.Parameter(typeof(TFrom));
        var convert = Expression.Convert(param, typeof(TTo));
        Convert = Expression.Lambda<Func<TFrom, TTo>>(convert, param)
                            .Compile();
    }
}

// 사용
int num = EnumConverter<CardRank, int>.Convert(CardRank.Ace);

한계: iOS (AOT 플랫폼)

iOS는 보안상 런타임 코드 생성을 금지합니다. Expression.Compile()을 사용할 수 없어요!

해결책 2: C++ 스타일 Union (FieldOffset)

C#에서도 [StructLayout]과 [FieldOffset]을 사용해 C++의 union처럼 같은 메모리를 공유할 수 있습니다. 

[StructLayout(LayoutKind.Explicit)]
struct EnumUnion<TEnum> where TEnum : struct
{
    [FieldOffset(0)]
    public TEnum EnumValue;

    [FieldOffset(0)]
    public int IntValue;
}

// 사용
var union = new EnumUnion<CardRank>();
union.EnumValue = CardRank.Ace;
int num = union.IntValue;  // 같은 메모리, 타입만 다르게 해석

장점

함수 호출 없이 메모리 직접 접근 → 최고 성능!

한계: Unity 버전

구버전 Unity(.NET 3.5)에서는 동작하지만, 최신 Unity(.NET 4.x)에서는 제네릭 + FieldOffset 조합 시 런타임 에러가 발생할 수 있습니다.

해결책 3: Unsafe 포인터 (권장)

C#에서 unsafe 블록 내에서 포인터를 사용하면 메모리를 직접 조작할 수 있습니다. 

public static class EnumToInt<TEnum> where TEnum : struct
{
    public static unsafe int Convert(TEnum value)
    {
        int* ptr = (int*)&value;
        return *ptr;
    }
}

public static class IntToEnum<TEnum> where TEnum : struct
{
    public static unsafe TEnum Convert(int value)
    {
        TEnum* ptr = (TEnum*)&value;
        return *ptr;
    }
}

// 사용
int num = EnumToInt<CardRank>.Convert(CardRank.Ace);
CardRank rank = IntToEnum<CardRank>.Convert(0);

이게 최종 해법!

  • 모든 플랫폼에서 동작 (iOS 포함)
  • 최고 성능 (포인터 직접 접근)
  • 박싱 완전 제거

Unity에서 unsafe 활성화

Player Settings > Other Settings > Allow 'unsafe' Code 체크

5. 박싱 없는 EnumDictionary

어떻게 구현하나요?

Enum을 키로 받되, 내부적으로는 int로 변환해서 저장합니다. 

public class EnumDictionary<TKey, TValue>
    where TKey : struct  // Enum 제약
{
    private Dictionary<int, TValue> _inner = new();

    public TValue this[TKey key]
    {
        get => _inner[EnumToInt<TKey>.Convert(key)];
        set => _inner[EnumToInt<TKey>.Convert(key)] = value;
    }

    public bool ContainsKey(TKey key)
    {
        return _inner.ContainsKey(EnumToInt<TKey>.Convert(key));
    }

    // ... 나머지 Dictionary 인터페이스 구현
}

사용

var values = new EnumDictionary<CardRank, int>();
values[CardRank.Ace] = 1;     // 박싱 없음!
var v = values[CardRank.Ace];  // 박싱 없음!
오픈소스가 있나요?

GitHub: libgni/EnumExtension

발표자가 공개한 라이브러리입니다.

  • BitConverter - Enum ↔ int 변환
  • EnumDictionary - 박싱 없는 Dictionary
  • EnumHashSet - 박싱 없는 HashSet

6. 정리

문제 원인 해결책
Enum.Equals() 박싱 object.Equals(object) 호출 int로 변환 후 비교
Dictionary<Enum, T> 박싱 GetHashCode, Equals 호출 EnumDictionary 사용
HasFlag() 박싱 Enum 타입 인자 비트 연산자 직접 사용
제네릭 T 캐스팅 불가 컴파일러가 타입 모름 unsafe 포인터

핵심 교훈

  • Enum + Generic = 박싱 이 조합을 항상 의심하라
  • 편의 기능(HasFlag 등)도 내부를 확인하라
  • 게임에서 GC = 프레임 드랍 최대한 피하라
  • 언어의 공식 해법이 항상 최선은 아니다

한계

이 기법은 32비트 Enum(기본 int)만 지원합니다. byte, short, long 기반 Enum은 별도 처리가 필요합니다. (실무에서 대부분 기본 int를 사용하므로 큰 문제는 아님)
