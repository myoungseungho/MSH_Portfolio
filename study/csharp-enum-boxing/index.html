왜 Enum만 쓰면 GC가 터질까? 박싱 문제

C# Enum의 숨겨진 성능 함정 - NDC 2019 정리

Boxing Enum Generic GC Unity

Part 1. 박싱(Boxing)이 뭐야?

int를 object에 넣으면 뭐가 달라지는 거야?

값을 "박스"에 담는 거야.

int는 스택에 살고, object는 힙에 사는데, 타입이 다르니까 변환이 필요해.

void PrintValue(object obj) { Debug.Log(obj); } int num = 42; PrintValue(num); // 여기서 박싱 발생! // int(값 타입) -> object(참조 타입)
박싱이 왜 문제야? 그냥 타입 변환 아냐?

힙에 메모리가 할당돼!

힙 할당 = GC가 나중에 정리해야 함 = 게임 끊김의 원인!

택배 비유

int = 내 손에 들고 있는 물건 (스택)
object = 택배 박스에 담아서 창고에 보관 (힙)

물건을 박스에 넣고 창고에 보내려면 박스 비용 + 배송 비용이 들지?
박싱도 마찬가지야. 힙 할당 비용 + 나중에 GC 비용!
박싱된 객체는 얼마나 커?

원래 값 + 헤더 오버헤드가 붙어.

타입 32-bit 64-bit
int (값 타입) 4 바이트 4 바이트
박싱된 int 12 바이트 24 바이트
계산 예시

한 프레임에 Equals 비교 125회 발생
-> 비교당 박싱 2회 x 24바이트 = 48바이트
-> 125 x 48 = 6KB/프레임
-> 60fps면 360KB/초 쓰레기 발생!

Part 2. Enum + Generic = 박싱 지옥

Enum이랑 Generic이 만나면 왜 박싱이 발생해?

Equals() 메서드 때문이야.

제네릭에서 Equals를 호출하면 object.Equals(object)가 불려.

void Compare(T a, T b) { if (a.Equals(b)) { // 여기서 박싱! // ... } } enum CardRank { Ace, King, Queen } Compare(CardRank.Ace, CardRank.King); // 박싱 2회 발생!
왜 박싱이 2회나 발생해?

Equals 메서드 시그니처를 봐봐.

public virtual bool Equals(object obj) ^^^^^^ object 타입! a.Equals(b) 호출 시: 1. b가 object로 변환 -> 박싱 1회 (인자) 2. a도 virtual Equals 호출하려면 -> 박싱 1회 (수신자) = 비교 1회에 박싱 2회!
Dictionary에서 Enum을 키로 쓰면?

검색할 때마다 박싱!

Dictionary cardValues = new(); cardValues[CardRank.Ace] = 1; // 박싱 발생! var value = cardValues[CardRank.Ace]; // 또 박싱!
HasFlag()도 마찬가지야?

응, 더 황당해.

성능을 위해 비트 마스킹을 쓴 건데, 실제로는 박싱으로 더 느려!

[Flags] enum Permissions { Read = 1, Write = 2, Execute = 4 } Permissions perm = Permissions.Read | Permissions.Write; bool canWrite = perm.HasFlag(Permissions.Write); // 박싱! // HasFlag 내부: public bool HasFlag(Enum flag) // Enum = 참조 타입! { // 내부에서 object로 다루므로 박싱 발생 }
역설적 상황

"비트 연산으로 성능 최적화하자!" -> HasFlag 사용
-> 내부에서 박싱 발생
-> 오히려 더 느려짐!

좋은 의도가 나쁜 결과를 낳는 케이스.

Part 3. 정석적 해법? "이게 해법이라고?"

C#에서 공식으로 제공하는 해결책은 뭐야?

IEqualityComparer 커스텀 구현이야.

Dictionary 생성자에 커스텀 Comparer를 넘기면 돼.

public class CardRankComparer : IEqualityComparer { public bool Equals(CardRank x, CardRank y) { return x == y; // 구체 타입이라 박싱 없음! } public int GetHashCode(CardRank obj) { return (int)obj; // int로 캐스팅, 박싱 없음 } } // 사용 var dict = new Dictionary(new CardRankComparer());
이게 왜 문제야?

프로그래머한테 일을 시키는 거지!

영화 <극한직업> 대사가 떠오름: "이게 해법이라고 내놓는 거지?" Enum 10개 만들면 -> Comparer 10개 작성 Dictionary 100개 만들면 -> 생성자 100개 수정 까먹으면? -> 다시 박싱 발생!
C# 7.3에서 where T : Enum 제약이 생겼다던데?

타입 안전성만 제공할 뿐, 박싱 문제는 해결 못 해.

void Process(T value) where T : Enum { // T가 Enum임을 컴파일러가 알게 됨 // 하지만... } // IL 코드를 보면... box !!T // 여전히 박싱! callvirt Equals
결론

C# 7.3의 Enum 제약은 타입 안전성만 제공.
박싱 문제는 여전히 존재한다!

Part 4. 진짜 해결책: Enum -> int 변환

핵심 아이디어가 뭐야?

Enum은 내부적으로 int야!

int로 바꿔서 처리하면 박싱이 발생하지 않아.

CardRank.Ace = 0 (내부적으로 int 0) CardRank.King = 1 (내부적으로 int 1) int끼리 비교 -> 박싱 없음! int를 Dictionary 키로 -> 박싱 없음!
근데 제네릭 T는 캐스팅이 안 되잖아?

맞아. 컴파일러가 T가 뭔지 모르니까.

void Process(T value) where T : Enum { int num = (int)value; // 컴파일 에러! // T가 뭔지 모르니까 캐스팅 불가 }
그럼 어떻게 해?

방법이 3가지 있어. 하나씩 보자.

방법 원리 한계
Expression (동적 생성) 런타임에 변환 코드 생성 iOS 불가 (AOT)
FieldOffset (Union) 메모리 공유 최신 Unity 호환성
Unsafe 포인터 메모리 직접 접근 모든 플랫폼 OK!

Part 5. 최종 해법: Unsafe 포인터

Unsafe 포인터가 뭐야?

C#에서 C++ 스타일로 메모리를 직접 조작하는 거야.

public static class EnumToInt where TEnum : struct { public static unsafe int Convert(TEnum value) { int* ptr = (int*)&value; return *ptr; } } public static class IntToEnum where TEnum : struct { public static unsafe TEnum Convert(int value) { TEnum* ptr = (TEnum*)&value; return *ptr; } } // 사용 int num = EnumToInt.Convert(CardRank.Ace); CardRank rank = IntToEnum.Convert(0);
이게 최종 해법!

- 모든 플랫폼에서 동작 (iOS 포함)
- 최고 성능 (포인터 직접 접근)
- 박싱 완전 제거
Unity에서 unsafe 어떻게 활성화해?

Player Settings > Other Settings > Allow 'unsafe' Code 체크!

이걸 이용해서 EnumDictionary도 만들 수 있어?

당연하지! Enum을 키로 받되, 내부에선 int로 저장해.

public class EnumDictionary where TKey : struct // Enum 제약 { private Dictionary _inner = new(); public TValue this[TKey key] { get => _inner[EnumToInt.Convert(key)]; set => _inner[EnumToInt.Convert(key)] = value; } public bool ContainsKey(TKey key) { return _inner.ContainsKey(EnumToInt.Convert(key)); } // ... 나머지 구현 } // 사용 var values = new EnumDictionary(); values[CardRank.Ace] = 1; // 박싱 없음! var v = values[CardRank.Ace]; // 박싱 없음!
GitHub: libgni/EnumExtension
  • BitConverter - Enum <-> int 변환
  • EnumDictionary - 박싱 없는 Dictionary
  • EnumHashSet - 박싱 없는 HashSet

Part 6. HasFlag 대안

HasFlag 대신 뭘 써야 해?

비트 연산자를 직접 써!

// 나쁜 예: HasFlag 사용 (박싱 발생!) bool canWrite = perm.HasFlag(Permissions.Write); // 좋은 예: 비트 연산 직접 사용 (박싱 없음!) bool canWrite = (perm & Permissions.Write) == Permissions.Write; // 또는 0이 아닌지 확인 bool canWrite = (perm & Permissions.Write) != 0;
방식 코드 박싱
HasFlag perm.HasFlag(Permission.Write) 발생!
비트 연산 (perm & Permission.Write) != 0 없음!

Part 7. 실무 가이드라인

Enum 박싱 예방 수칙
  • Dictionary, List에 Enum 키 사용 시 - EnumDictionary 또는 커스텀 Comparer 사용
  • 제네릭에서 Enum 비교 시 - int로 변환 후 비교
  • HasFlag 사용 금지 - 비트 연산자 직접 사용
  • 핫 패스(자주 호출되는 코드) - 프로파일러로 박싱 체크
문제 원인 해결책
Enum.Equals() 박싱 object.Equals(object) 호출 int로 변환 후 비교
Dictionary 박싱 GetHashCode, Equals 호출 EnumDictionary 사용
HasFlag() 박싱 Enum 타입 인자 비트 연산자 직접 사용
제네릭 T 캐스팅 불가 컴파일러가 타입 모름 unsafe 포인터
한 줄 요약

"Enum + Generic = 박싱을 의심하라"
한계

이 기법은 32비트 Enum(기본 int)만 지원.
byte, short, long 기반 Enum은 별도 처리 필요.
(실무에서 대부분 기본 int를 사용하므로 큰 문제는 아님)

핵심 정리: C# Enum 박싱 문제

  • 박싱 - 값 타입 -> 참조 타입 변환, 힙 할당 + GC 대상
  • Enum + Generic - Equals 호출 시 박싱 2회 발생
  • HasFlag - 편의 함수지만 박싱 발생, 비트 연산으로 대체
  • 공식 해법 - IEqualityComparer, 하지만 번거로움
  • 실용적 해법 - Enum -> int 변환 (unsafe 포인터)
  • 게임에서 GC = 프레임 드랍 - 박싱 최대한 피하라
