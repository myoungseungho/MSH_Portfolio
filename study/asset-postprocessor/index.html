에셋 프로세서

Unity AssetPostprocessor를 통한 자동 Import 처리

Part 1. 개념

AssetPostprocessor가 뭐야?

AssetPostprocessor는 Unity에서 에셋이 Import될 때 자동으로 호출되는 콜백 시스템입니다. 에셋이 프로젝트에 추가되거나 변경될 때 Import 설정을 자동으로 조정할 수 있습니다.

┌─────────────────────────────────────────────────────────────────────────────┐
│                        AssetPostprocessor 처리 흐름                          │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   [원본 파일]                                                                │
│   texture.png, model.fbx, audio.wav                                         │
│         │                                                                   │
│         ▼                                                                   │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │                     Unity Import Pipeline                            │   │
│   │                                                                     │   │
│   │   Phase 1: OnPreprocess*                                            │   │
│   │   ┌───────────────────────────────────────────────────────────┐     │   │
│   │   │  • OnPreprocessTexture()                                  │     │   │
│   │   │  • OnPreprocessModel()                                    │     │   │
│   │   │  • OnPreprocessAudio()                                    │     │   │
│   │   │  • OnPreprocessAsset() (모든 에셋)                         │     │   │
│   │   │                                                           │     │   │
│   │   │  → Import 설정 변경 가능                                   │     │   │
│   │   │  → assetImporter 접근하여 설정 조작                        │     │   │
│   │   └───────────────────────────────────────────────────────────┘     │   │
│   │         │                                                           │   │
│   │         ▼                                                           │   │
│   │   [ Unity 내부 Import 처리 ]                                        │   │
│   │   원본 → 압축/변환 → 플랫폼별 최적화                                 │   │
│   │         │                                                           │   │
│   │         ▼                                                           │   │
│   │   Phase 2: OnPostprocess*                                           │   │
│   │   ┌───────────────────────────────────────────────────────────┐     │   │
│   │   │  • OnPostprocessTexture(Texture2D texture)                │     │   │
│   │   │  • OnPostprocessModel(GameObject root)                    │     │   │
│   │   │  • OnPostprocessAudio(AudioClip clip)                     │     │   │
│   │   │  • OnPostprocessAllAssets(imported[], deleted[], moved[]) │     │   │
│   │   │                                                           │     │   │
│   │   │  → Import된 결과물에 접근                                  │     │   │
│   │   │  → 추가 처리 (컴포넌트 추가, 데이터 추출 등)               │     │   │
│   │   └───────────────────────────────────────────────────────────┘     │   │
│   │                                                                     │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│         │                                                                   │
│         ▼                                                                   │
│   [Import 완료]                                                             │
│   .asset, Library/에 캐시                                                   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

핵심은 OnPreprocess*는 Import 전에, OnPostprocess*는 Import 후에 호출된다는 점입니다. 설정 변경은 Pre에서, 결과 가공은 Post에서 합니다.

Part 2. 왜 필요해?

수동으로 Import 설정하면 안 돼?

소규모 프로젝트에서는 가능하지만, 규모가 커지면 일관성과 효율성 문제가 발생합니다.

┌─────────────────────────────────────────────────────────────────────────────┐
│                    수동 설정 vs AssetPostprocessor                           │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ❌ 수동 설정의 문제점                                                       │
│  ├─ 😓 반복 작업: 같은 설정을 매번 수동으로                                  │
│  ├─ 🔀 불일치: 팀원마다 다른 설정 적용                                       │
│  ├─ 🐛 실수: 설정 누락, 잘못된 값 입력                                       │
│  └─ ⏰ 시간 낭비: 에셋 개수에 비례하여 증가                                  │
│                                                                             │
│  ✅ AssetPostprocessor 장점                                                  │
│  ├─ 🤖 자동화: Import 시 규칙에 따라 자동 설정                               │
│  ├─ ✓ 일관성: 모든 에셋에 동일한 규칙 적용                                  │
│  ├─ 🛡️ 안정성: 코드로 규칙 검증, 실수 방지                                  │
│  └─ 📈 확장성: 에셋 수 증가해도 비용 동일                                    │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│  실제 사례 비교 (1000개 텍스처 기준)                                         │
│                                                                             │
│  수동 설정:                                                                  │
│  • 텍스처당 평균 30초 × 1000개 = 500분 (8시간+)                             │
│  • 설정 변경 시 전체 재작업 필요                                             │
│                                                                             │
│  AssetPostprocessor:                                                        │
│  • 초기 스크립트 작성: 30분                                                  │
│  • Import 자동 처리: 에셋당 0.1초 미만                                       │
│  • 규칙 변경 시 코드 수정 후 Reimport                                       │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

Part 3. 기본 구현

기본 AssetPostprocessor 구현 방법은?

AssetPostprocessor 클래스를 상속하고 원하는 콜백 메서드를 오버라이드합니다. Editor 폴더에 위치해야 합니다.

// Editor/TexturePostprocessor.cs using UnityEditor; using UnityEngine; public class TexturePostprocessor : AssetPostprocessor { // Import 전 호출 - 설정 변경 void OnPreprocessTexture() { // assetPath: 현재 Import 중인 에셋 경로 // assetImporter: 현재 에셋의 Importer TextureImporter importer = (TextureImporter)assetImporter; // 경로에 따라 다른 설정 적용 if (assetPath.Contains("Assets/Art/UI/")) { ApplyUITextureSettings(importer); } else if (assetPath.Contains("Assets/Art/Characters/")) { ApplyCharacterTextureSettings(importer); } else if (assetPath.Contains("Assets/Art/Environment/")) { ApplyEnvironmentTextureSettings(importer); } } private void ApplyUITextureSettings(TextureImporter importer) { // UI 텍스처: Sprite, 작은 크기, 압축 importer.textureType = TextureImporterType.Sprite; importer.spriteImportMode = SpriteImportMode.Single; importer.maxTextureSize = 512; importer.mipmapEnabled = false; // UI는 밉맵 불필요 importer.isReadable = false; // 플랫폼별 설정 TextureImporterPlatformSettings androidSettings = new TextureImporterPlatformSettings { name = "Android", overridden = true, maxTextureSize = 512, format = TextureImporterFormat.ASTC_6x6 }; importer.SetPlatformTextureSettings(androidSettings); TextureImporterPlatformSettings iosSettings = new TextureImporterPlatformSettings { name = "iPhone", overridden = true, maxTextureSize = 512, format = TextureImporterFormat.ASTC_6x6 }; importer.SetPlatformTextureSettings(iosSettings); } private void ApplyCharacterTextureSettings(TextureImporter importer) { // 캐릭터 텍스처: 높은 품질 importer.textureType = TextureImporterType.Default; importer.maxTextureSize = 2048; importer.mipmapEnabled = true; importer.isReadable = false; importer.textureCompression = TextureImporterCompression.CompressedHQ; // 노멀맵 감지 (파일명 기반) if (assetPath.Contains("_N.") || assetPath.Contains("_Normal")) { importer.textureType = TextureImporterType.NormalMap; } } private void ApplyEnvironmentTextureSettings(TextureImporter importer) { // 환경 텍스처: 큰 크기 허용 importer.textureType = TextureImporterType.Default; importer.maxTextureSize = 4096; importer.mipmapEnabled = true; importer.streamingMipmaps = true; // 스트리밍 밉맵 importer.isReadable = false; } // Import 후 호출 - 결과물 가공 void OnPostprocessTexture(Texture2D texture) { // Import된 텍스처에 접근 가능 Debug.Log($"Texture imported: {assetPath}, " + $"Size: {texture.width}x{texture.height}"); // 예: 텍스처 정보를 데이터베이스에 기록 // AssetDatabase.AddObjectToAsset() 등 사용 가능 } }
모델(FBX) 처리는 어떻게 해?

모델 Import는 메시, 리그, 애니메이션, 머티리얼 등 복잡한 설정이 필요합니다.

// Editor/ModelPostprocessor.cs using UnityEditor; using UnityEngine; using System.Linq; public class ModelPostprocessor : AssetPostprocessor { void OnPreprocessModel() { ModelImporter importer = (ModelImporter)assetImporter; // 공통 설정 importer.importVisibility = false; importer.importCameras = false; importer.importLights = false; importer.isReadable = false; // 메모리 절약 importer.meshCompression = ModelImporterMeshCompression.Medium; // 캐릭터 모델 (SK_ 접두사) if (assetPath.Contains("/SK_")) { ApplySkeletalMeshSettings(importer); } // 정적 메시 (SM_ 접두사) else if (assetPath.Contains("/SM_")) { ApplyStaticMeshSettings(importer); } } private void ApplySkeletalMeshSettings(ModelImporter importer) { // 리그 설정 importer.animationType = ModelImporterAnimationType.Generic; // 본 개수 최적화 (모바일용) importer.optimizeBones = true; importer.sortHierarchyByName = true; // 애니메이션 Import 설정 importer.importAnimation = true; importer.animationCompression = ModelImporterAnimationCompression.Optimal; importer.resampleCurves = true; // 스킨 가중치 정밀도 importer.skinWeights = ModelImporterSkinWeights.Standard; // 4 bones/vertex } private void ApplyStaticMeshSettings(ModelImporter importer) { // 정적 메시는 리그/애니메이션 불필요 importer.animationType = ModelImporterAnimationType.None; importer.importAnimation = false; // 메시 최적화 importer.meshOptimizationFlags = MeshOptimizationFlags.PolygonOrder | MeshOptimizationFlags.VertexOrder; // Generate Lightmap UVs (환경 오브젝트용) if (assetPath.Contains("/Environment/")) { importer.generateSecondaryUV = true; } } // 모델 Import 후 - GameObject에 접근 void OnPostprocessModel(GameObject root) { // Import된 모델의 루트 GameObject // 1. 폴리곤 수 검증 int totalTris = 0; foreach (var mf in root.GetComponentsInChildren<MeshFilter>()) { if (mf.sharedMesh != null) totalTris += mf.sharedMesh.triangles.Length / 3; } foreach (var smr in root.GetComponentsInChildren<SkinnedMeshRenderer>()) { if (smr.sharedMesh != null) totalTris += smr.sharedMesh.triangles.Length / 3; } if (totalTris > 30000) { Debug.LogWarning($"[Model] High poly count: {assetPath} has {totalTris} triangles"); } // 2. 자동 컴포넌트 추가 (Props 폴더) if (assetPath.Contains("/Props/")) { // MeshCollider 자동 추가 foreach (var mf in root.GetComponentsInChildren<MeshFilter>()) { if (mf.GetComponent<Collider>() == null) { MeshCollider col = mf.gameObject.AddComponent<MeshCollider>(); col.convex = true; } } } // 3. LOD 그룹 자동 설정 SetupLODGroup(root); } private void SetupLODGroup(GameObject root) { // LOD0, LOD1, LOD2 명명 규칙에 따라 자동 설정 Transform[] children = root.GetComponentsInChildren<Transform>(); var lod0 = children.FirstOrDefault(t => t.name.Contains("LOD0")); var lod1 = children.FirstOrDefault(t => t.name.Contains("LOD1")); var lod2 = children.FirstOrDefault(t => t.name.Contains("LOD2")); if (lod0 == null) return; LODGroup lodGroup = root.GetComponent<LODGroup>(); if (lodGroup == null) lodGroup = root.AddComponent<LODGroup>(); LOD[] lods = new LOD[3]; lods[0] = new LOD(0.6f, lod0.GetComponents<Renderer>()); if (lod1 != null) lods[1] = new LOD(0.3f, lod1.GetComponents<Renderer>()); if (lod2 != null) lods[2] = new LOD(0.1f, lod2.GetComponents<Renderer>()); lodGroup.SetLODs(lods.Where(l => l.renderers != null).ToArray()); lodGroup.RecalculateBounds(); } // 머티리얼 할당 커스터마이즈 Material OnAssignMaterialModel(Material material, Renderer renderer) { // FBX에서 가져온 머티리얼 대신 프로젝트 머티리얼 사용 string materialPath = $"Assets/Art/Materials/{material.name}.mat"; Material existingMaterial = AssetDatabase.LoadAssetAtPath<Material>(materialPath); if (existingMaterial != null) { return existingMaterial; } // 없으면 기본 처리 return null; } }
오디오 처리는?

오디오는 용도에 따라 로드 방식과 압축 설정이 크게 달라집니다.

// Editor/AudioPostprocessor.cs using UnityEditor; using UnityEngine; public class AudioPostprocessor : AssetPostprocessor { void OnPreprocessAudio() { AudioImporter importer = (AudioImporter)assetImporter; // SFX (효과음) if (assetPath.Contains("/SFX/") || assetPath.StartsWith("SFX_")) { ApplySFXSettings(importer); } // BGM (배경음악) else if (assetPath.Contains("/BGM/") || assetPath.StartsWith("BGM_")) { ApplyBGMSettings(importer); } // Voice (음성) else if (assetPath.Contains("/Voice/") || assetPath.StartsWith("VO_")) { ApplyVoiceSettings(importer); } // Ambient (환경음) else if (assetPath.Contains("/Ambient/")) { ApplyAmbientSettings(importer); } } private void ApplySFXSettings(AudioImporter importer) { // 효과음: 짧고 자주 재생 → 메모리에 로드 importer.forceToMono = true; // 모노로 변환 (공간음향 제외) importer.loadInBackground = false; // 즉시 로드 importer.preloadAudioData = true; AudioImporterSampleSettings settings = new AudioImporterSampleSettings { loadType = AudioClipLoadType.DecompressOnLoad, // 빠른 재생 compressionFormat = AudioCompressionFormat.ADPCM, // 낮은 CPU quality = 0.7f, sampleRateSetting = AudioSampleRateSetting.OptimizeSampleRate }; importer.defaultSampleSettings = settings; // 모바일용 설정 AudioImporterSampleSettings mobileSettings = settings; mobileSettings.quality = 0.5f; importer.SetOverrideSampleSettings("Android", mobileSettings); importer.SetOverrideSampleSettings("iPhone", mobileSettings); } private void ApplyBGMSettings(AudioImporter importer) { // 배경음악: 길고 1개씩 재생 → 스트리밍 importer.forceToMono = false; // 스테레오 유지 importer.loadInBackground = true; // 백그라운드 로드 importer.preloadAudioData = false; AudioImporterSampleSettings settings = new AudioImporterSampleSettings { loadType = AudioClipLoadType.Streaming, // 스트리밍 compressionFormat = AudioCompressionFormat.Vorbis, // 높은 압축률 quality = 0.5f, // 품질 vs 크기 균형 sampleRateSetting = AudioSampleRateSetting.PreserveSampleRate }; importer.defaultSampleSettings = settings; } private void ApplyVoiceSettings(AudioImporter importer) { // 음성: 중간 길이, 순차 재생 importer.forceToMono = true; // 음성은 모노로 충분 importer.loadInBackground = true; importer.preloadAudioData = false; AudioImporterSampleSettings settings = new AudioImporterSampleSettings { loadType = AudioClipLoadType.CompressedInMemory, compressionFormat = AudioCompressionFormat.Vorbis, quality = 0.6f, sampleRateSetting = AudioSampleRateSetting.OptimizeSampleRate }; importer.defaultSampleSettings = settings; } private void ApplyAmbientSettings(AudioImporter importer) { // 환경음: 루프 재생, 메모리 효율 중요 importer.forceToMono = true; importer.loadInBackground = true; importer.preloadAudioData = false; AudioImporterSampleSettings settings = new AudioImporterSampleSettings { loadType = AudioClipLoadType.Streaming, // 루프니까 스트리밍 compressionFormat = AudioCompressionFormat.Vorbis, quality = 0.4f, // 환경음은 품질 낮아도 OK sampleRateSetting = AudioSampleRateSetting.OptimizeSampleRate }; importer.defaultSampleSettings = settings; } void OnPostprocessAudio(AudioClip clip) { // Import된 오디오 클립 정보 로깅 Debug.Log($"[Audio] {assetPath}: " + $"Length={clip.length:F2}s, " + $"Channels={clip.channels}, " + $"Frequency={clip.frequency}Hz"); // 너무 긴 SFX 경고 if (assetPath.Contains("/SFX/") && clip.length > 5.0f) { Debug.LogWarning($"[Audio] SFX too long: {assetPath} is {clip.length}s. " + "Consider moving to BGM or Ambient."); } } }

Part 4. 고급 기능

여러 Postprocessor의 실행 순서를 제어할 수 있어?

GetPostprocessOrder 속성을 오버라이드하여 실행 순서를 제어합니다. 낮은 값이 먼저 실행됩니다.

public class FirstProcessor : AssetPostprocessor { // 낮은 값 = 먼저 실행 public override int GetPostprocessOrder() => -100; void OnPreprocessTexture() { Debug.Log("First: 기본 설정 적용"); // 기본 설정 } } public class SecondProcessor : AssetPostprocessor { // 기본값 = 0 public override int GetPostprocessOrder() => 0; void OnPreprocessTexture() { Debug.Log("Second: 경로별 오버라이드"); // 경로 기반 설정 } } public class LastProcessor : AssetPostprocessor { // 높은 값 = 나중에 실행 public override int GetPostprocessOrder() => 100; void OnPreprocessTexture() { Debug.Log("Last: 최종 검증"); // 검증 및 로깅 } } // 실행 순서: FirstProcessor → SecondProcessor → LastProcessor

OnPostprocessAllAssets는 언제 사용해?

OnPostprocessAllAssets는 배치 처리에 적합합니다. 모든 에셋 변경 사항을 한 번에 받아 처리할 수 있습니다.

using UnityEditor; using UnityEngine; using System.Collections.Generic; using System.IO; public class AssetChangeTracker : AssetPostprocessor { // 모든 에셋 변경 후 한 번 호출됨 (static 메서드) static void OnPostprocessAllAssets( string[] importedAssets, // 새로 Import된 에셋 string[] deletedAssets, // 삭제된 에셋 string[] movedAssets, // 이동된 에셋 (목적지) string[] movedFromAssetPaths) // 이동된 에셋 (출발지) { // 1. 변경 로그 기록 if (importedAssets.Length > 0) { Debug.Log($"[AssetTracker] Imported {importedAssets.Length} assets"); foreach (string path in importedAssets) { // 변경 이력 기록 LogAssetChange("Import", path); } } if (deletedAssets.Length > 0) { Debug.Log($"[AssetTracker] Deleted {deletedAssets.Length} assets"); foreach (string path in deletedAssets) { LogAssetChange("Delete", path); // 참조 무결성 검사 CheckOrphanedReferences(path); } } for (int i = 0; i < movedAssets.Length; i++) { LogAssetChange("Move", $"{movedFromAssetPaths[i]} → {movedAssets[i]}"); } // 2. Addressables 자동 등록 ProcessAddressables(importedAssets); // 3. 에셋 데이터베이스 업데이트 UpdateAssetDatabase(importedAssets, deletedAssets); } private static void LogAssetChange(string action, string path) { string logPath = "Assets/Editor/AssetChanges.log"; string entry = $"[{System.DateTime.Now:yyyy-MM-dd HH:mm:ss}] {action}: {path}\n"; File.AppendAllText(logPath, entry); } private static void CheckOrphanedReferences(string deletedPath) { // 삭제된 에셋을 참조하는 다른 에셋 찾기 string guid = AssetDatabase.AssetPathToGUID(deletedPath); string[] allAssets = AssetDatabase.GetAllAssetPaths(); foreach (string assetPath in allAssets) { string[] dependencies = AssetDatabase.GetDependencies(assetPath, false); foreach (string dep in dependencies) { if (dep == deletedPath) { Debug.LogWarning($"[Orphan] {assetPath} references deleted asset: {deletedPath}"); } } } } private static void ProcessAddressables(string[] importedAssets) { // Addressables 폴더에 추가된 에셋 자동 등록 foreach (string path in importedAssets) { if (path.StartsWith("Assets/Addressables/")) { // Addressables API로 자동 등록 // AddressableAssetSettingsDefaultObject.Settings.CreateOrMoveEntry(...); Debug.Log($"[Addressables] Auto-register: {path}"); } } } private static void UpdateAssetDatabase(string[] imported, string[] deleted) { // ScriptableObject 기반 에셋 목록 업데이트 AssetManifest manifest = AssetDatabase.LoadAssetAtPath<AssetManifest>( "Assets/Data/AssetManifest.asset"); if (manifest != null) { bool changed = false; foreach (string path in imported) { if (!manifest.assets.Contains(path)) { manifest.assets.Add(path); changed = true; } } foreach (string path in deleted) { if (manifest.assets.Remove(path)) { changed = true; } } if (changed) { EditorUtility.SetDirty(manifest); AssetDatabase.SaveAssets(); } } } } // 간단한 AssetManifest 예시 public class AssetManifest : ScriptableObject { public List<string> assets = new List<string>(); }

public class FBXUserPropertiesProcessor : AssetPostprocessor { // FBX의 User Properties를 읽는 콜백 void OnPostprocessGameObjectWithUserProperties( GameObject go, string[] propNames, object[] values) { // 예: Maya에서 "ColliderType=Box" 속성 설정 for (int i = 0; i < propNames.Length; i++) { string propName = propNames[i]; object value = values[i]; Debug.Log($"[FBX Property] {go.name}: {propName} = {value}"); switch (propName) { case "ColliderType": AddCollider(go, value.ToString()); break; case "IsInteractable": if ((bool)value) { go.AddComponent<InteractableObject>(); } break; case "LODLevel": // LOD 레벨 메타데이터 저장 int lodLevel = System.Convert.ToInt32(value); go.name = $"{go.name}_LOD{lodLevel}"; break; case "AudioTrigger": // 오디오 트리거 자동 설정 AudioSource audio = go.AddComponent<AudioSource>(); audio.spatialBlend = 1.0f; break; } } } private void AddCollider(GameObject go, string type) { switch (type.ToLower()) { case "box": go.AddComponent<BoxCollider>(); break; case "sphere": go.AddComponent<SphereCollider>(); break; case "capsule": go.AddComponent<CapsuleCollider>(); break; case "mesh": MeshCollider mc = go.AddComponent<MeshCollider>(); mc.convex = true; break; } } } // InteractableObject 예시 public class InteractableObject : MonoBehaviour { public string interactionPrompt = "Press E to interact"; }

AssetPostprocessor 사용 시 주의할 점은?

AssetPostprocessor는 강력하지만 잘못 사용하면 문제가 생깁니다.

// 무한 루프 방지 예시 public class SafePostprocessor : AssetPostprocessor { // 처리 중인 에셋 추적 private static HashSet<string> _processing = new HashSet<string>(); static void OnPostprocessAllAssets( string[] imported, string[] deleted, string[] moved, string[] movedFrom) { List<string> toProcess = new List<string>(); foreach (string path in imported) { // 이미 처리 중이면 스킵 if (_processing.Contains(path)) continue; // 처리 대상 조건 if (ShouldProcess(path)) { toProcess.Add(path); } } if (toProcess.Count == 0) return; // 처리 중 플래그 설정 foreach (string path in toProcess) { _processing.Add(path); } try { // 실제 처리 foreach (string path in toProcess) { ProcessAsset(path); } } finally { // 플래그 해제 (지연 실행) EditorApplication.delayCall += () => { foreach (string path in toProcess) { _processing.Remove(path); } }; } } private static bool ShouldProcess(string path) { return path.StartsWith("Assets/Art/") && (path.EndsWith(".png") || path.EndsWith(".fbx")); } private static void ProcessAsset(string path) { // 안전한 처리 로직 Debug.Log($"Processing: {path}"); } }
