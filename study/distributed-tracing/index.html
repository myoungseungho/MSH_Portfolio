Distributed Tracing

장애 원인을 빠르게 찾는 법

1. 로그만 보면 안 돼?

서버 로그 보면 원인 알 수 있잖아?

분산 시스템에서는 어려워!

단일 서버 (쉬움): [Game Server] - 14:00:01 로그인 요청 - 14:00:02 DB 조회 - 14:00:03 에러 발생! <- 바로 찾음 분산 시스템 (어려움): [Gate] -> [Game] -> [GameDB] -> [Redis] | | | | 로그인 캐릭터 DB조회 세션 요청 로딩 저장 "14:00:03 에러 발생" -> 어느 서버에서? -> 어떤 요청 때문에? -> 다른 서버에서 뭘 했길래?
로그를 다 모아보면?
분산 로그의 문제: [Gate Server 로그] 14:00:01.123 Request from user_123 14:00:01.124 Request from user_456 14:00:01.125 Forward to Game Server [Game Server 로그] 14:00:01.130 Received request 14:00:01.135 Query to DB 14:00:01.500 Timeout error! 질문: 어떤 유저 요청이 타임아웃 났어? 답: 모름! 로그가 연결이 안 됨!

요청 단위로 추적이 필요해!

2. 분산 추적이 뭐야?

Trace ID? Span?
분산 추적 구조: [하나의 요청 = 1개의 Trace] Trace ID: abc-123 ├── Span 1: Gate Server (50ms) │ └── Span 2: Game Server (400ms) │ ├── Span 3: DB Query (350ms) <- 병목! │ └── Span 4: Redis (5ms) 용어: - Trace: 요청의 전체 여정 - Span: 각 서비스에서의 작업 단위 - Trace ID: 요청을 식별하는 고유 ID - Parent Span: 호출한 쪽 - Child Span: 호출된 쪽
어떻게 연결돼?
비유: 택배 송장

송장 번호 = Trace ID
물류 센터마다 찍는 스캔 = Span

송장 번호로 "어디서 지연됐는지" 추적 가능!
-> "대전 센터에서 24시간 멈춤" 바로 확인

3. 어떻게 구현해?

코드에서 Trace ID를 전달해?

HTTP 헤더로 전파:

// Gate Server (요청 시작) void OnRequest(Request& req) { // Trace ID 생성 (또는 클라이언트에서 받음) std::string traceId = GenerateTraceId(); std::string spanId = GenerateSpanId(); // 현재 Span 시작 Span span = tracer.StartSpan("gate.login", traceId, spanId); // Game Server로 요청할 때 Trace 정보 전달 HttpRequest gameReq; gameReq.SetHeader("X-Trace-Id", traceId); gameReq.SetHeader("X-Parent-Span-Id", spanId); gameReq.SetHeader("X-Span-Id", GenerateSpanId()); auto response = gameClient.Request(gameReq); // Span 종료 span.End(); } // Game Server (요청 받음) void OnRequest(Request& req) { // Trace 정보 추출 std::string traceId = req.GetHeader("X-Trace-Id"); std::string parentSpanId = req.GetHeader("X-Parent-Span-Id"); std::string spanId = req.GetHeader("X-Span-Id"); // 자식 Span 시작 Span span = tracer.StartSpan("game.login", traceId, spanId, parentSpanId); // DB 호출 (새 Span) Span dbSpan = tracer.StartSpan("db.query", traceId); auto result = db.Query("SELECT * FROM users"); dbSpan.End(); span.End(); }
게임 서버 TCP는?

패킷에 Trace 정보 포함:

// 패킷 구조에 Trace 정보 추가 struct PacketHeader { uint16_t packetId; uint16_t size; // 분산 추적용 char traceId[32]; char spanId[16]; char parentSpanId[16]; }; // 패킷 전송 시 void SendPacket(Connection* conn, Packet& packet) { // 현재 컨텍스트에서 Trace 정보 가져오기 auto ctx = TraceContext::Current(); packet.header.traceId = ctx.GetTraceId(); packet.header.spanId = GenerateSpanId(); packet.header.parentSpanId = ctx.GetSpanId(); conn->Send(packet); } // 패킷 수신 시 void OnPacket(Connection* conn, Packet& packet) { // Trace 컨텍스트 복원 TraceContext ctx( packet.header.traceId, packet.header.spanId, packet.header.parentSpanId ); // 이 컨텍스트에서 Span 시작 Span span = tracer.StartSpan("game.process_packet", ctx); // 패킷 처리... span.End(); }

4. Jaeger로 시각화

Jaeger가 뭐야?
Jaeger 아키텍처: [Game Server] --> [Jaeger Agent] --> [Jaeger Collector] [Gate Server] --> [Jaeger Agent] --> | [DB Server] --> [Jaeger Agent] --> v [Elasticsearch] | v [Jaeger UI] (대시보드)

Jaeger UI에서 Trace 검색, 시각화 가능!

설정은 어떻게 해?

// OpenTelemetry SDK (C++) #include #include void InitTracing() { // Jaeger Exporter 설정 auto exporter = std::make_unique( JaegerExporterOptions{ .endpoint = "http://jaeger:14268/api/traces", .service_name = "game-server" } ); // Tracer Provider 설정 auto provider = std::make_shared( std::move(exporter) ); // 글로벌 등록 trace::Provider::SetTracerProvider(provider); }

5. 장애 분석 실제 사례

"로그인이 느려요" 신고가 왔어
분산 추적 없이: 1. Gate 로그 확인 -> 정상 2. Game 로그 확인 -> 정상 3. DB 로그 확인 -> 정상? 4. Redis 로그 확인 -> 정상? 5. 재현 안 됨... 뭐지? 소요 시간: 2시간
분산 추적으로: 1. Jaeger에서 "느린 로그인" Trace 검색 2. Trace 확인: - Gate: 10ms - Game: 20ms - DB Query: 2,500ms! <- 발견! 3. DB Span 상세 보기: - Query: "SELECT * FROM user_items WHERE user_id = ?" - user_items 테이블 인덱스 없음! 소요 시간: 5분

6. 게임 서버 분산 추적 팁

패킷마다 Trace하면 너무 많지 않아?

샘플링이 필수:

// 샘플링 전략 class TracingSampler { public: bool ShouldSample(const std::string& traceId) { // 1. 에러 요청은 100% 수집 if (HasError()) return true; // 2. 느린 요청은 100% 수집 if (GetLatency() > 100) return true; // 3. 일반 요청은 1% 샘플링 return hash(traceId) % 100 == 0; } };

핵심 정리: Distributed Tracing

  • 목적 - 분산 시스템에서 요청 흐름 추적
  • 구성 - Trace ID + Span으로 요청 연결
  • 전파 - HTTP 헤더 또는 패킷에 Trace 정보 포함
  • 도구 - Jaeger, Zipkin, DataDog
  • 샘플링 - 전체 수집은 비용 폭탄, 1% 샘플링
  • 효과 - 장애 원인 파악 2시간 -> 5분
