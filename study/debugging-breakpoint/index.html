F9만 누르지 마세요

중단점(Breakpoint)의 숨겨진 기능들 — 조건부 중단점, 히트 카운트, 액션

핵심 단축키

중단점 설정/해제 F9
중단점 활성화/비활성화 Ctrl + F9
모든 중단점 삭제 Ctrl + Shift + F9
중단점 창 열기 Ctrl + Alt + B

Part 1. 기본 중단점의 한계

F9로 중단점 찍고 디버깅하면 되는 거 아니야?

간단한 버그는 그래도 된다. 하지만 이런 상황을 보자:

1만 번 반복되는 루프에서 9,999번째에만 버그가 난다면? F5를 9,999번 눌러야 할까?

멀티스레드 환경에서 특정 스레드만 잡고 싶다면?

멈추지 않고 로그만 찍고 싶다면?

이런 경우에 고급 중단점 기능이 필요하다.

Part 2. 조건부 중단점 (Conditional Breakpoint)

특정 조건일 때만 멈추게 할 수 있어?

조건부 중단점을 쓰면 된다. 중단점 우클릭 → 조건(Conditions)을 선택한다.

// 예: 10000번 루프에서 i == 9999일 때만 멈추고 싶다 for (int i = 0; i < 10000; i++) { ProcessItem(i); // ← 여기에 중단점 설정 } // 중단점 우클릭 → 조건 → "i == 9999" 입력 // → 9999번째에서만 멈춤!
조건에 뭘 넣을 수 있어?

C++ 표현식이면 뭐든 가능하다:

조건 예시 의미
i == 9999 i가 9999일 때
pPlayer == nullptr 포인터가 null일 때
pPlayer->m_nLevel > 50 레벨이 50 초과일 때
strcmp(name, "admin") == 0 이름이 "admin"일 때
GetCurrentThreadId() == 1234 특정 스레드에서만

주의: 조건 평가에 부작용이 있는 함수(예: i++)를 넣으면 디버깅하면서 값이 바뀌어 버린다!

Part 3. 히트 카운트 (Hit Count)

100번째 호출에서만 멈추고 싶어

히트 카운트를 설정한다. 중단점 우클릭 → 조건 → 히트 카운트 탭.

옵션 의미 예시
= (같음) 정확히 N번째에만 100번째 호출에서만 멈춤
>= (이상) N번째부터 매번 100번째부터 계속 멈춤
배수 N의 배수마다 10번마다 멈춤 (10, 20, 30...)
// 실전 예: 1000번째 패킷 처리할 때 상태 확인 void ProcessPacket(Packet* pPacket) { // 중단점 설정 + 히트 카운트 = 1000 HandlePacket(pPacket); } // 1~999번은 그냥 지나가고, 1000번째에만 멈춤 // → 반복 눌러야 하는 고통에서 해방!

Part 4. 액션 (Tracepoint) — 멈추지 않는 중단점

멈추지 않고 로그만 찍고 싶어

Tracepoint(추적점)을 쓴다. 중단점 우클릭 → 작업 탭 → "출력 창에 메시지 기록" 체크.

그리고 "계속 실행" 체크하면 멈추지 않고 로그만 찍는다.

// 메시지 형식 예시: "ProcessItem 호출: i = {i}, item = {pItem->name}" // 출력 창에 이렇게 나온다: // ProcessItem 호출: i = 0, item = Sword // ProcessItem 호출: i = 1, item = Shield // ProcessItem 호출: i = 2, item = Potion // ... // 특수 키워드: $FUNCTION → 현재 함수명 $CALLER → 호출자 함수명 $CALLSTACK → 전체 콜스택 $TID → 스레드 ID $PID → 프로세스 ID $TICK → 타임스탬프
이게 printf 디버깅이랑 뭐가 달라?

코드 수정 없이 로그를 추가/삭제할 수 있다!

빌드 안 해도 되고, 커밋할 필요도 없고, 디버깅 끝나면 중단점만 삭제하면 된다.

특히 릴리즈 빌드 디버깅할 때 printf를 넣으면 동작이 바뀔 수 있는데, Tracepoint는 영향이 적다.

Part 5. 필터 — 특정 스레드/프로세스만

멀티스레드에서 특정 스레드만 잡고 싶어

조건에 GetCurrentThreadId() == 스레드ID를 넣거나, 필터 탭을 사용한다.

// 방법 1: 조건으로 필터링 조건: GetCurrentThreadId() == 12345 // 방법 2: 필터 탭 사용 ThreadId = 12345 ThreadName = "WorkerThread" ProcessName = "GameServer.exe" // 방법 3: Threads 창에서 스레드 ID 확인 Debug → Windows → Threads (Ctrl+Alt+H) → 원하는 스레드의 ID 복사 → 조건에 입력

Part 6. 실전 조합 예시

여러 기능을 조합하면?

강력한 디버깅 시나리오가 가능해진다:

시나리오 설정
100번째 호출이면서 값이 음수일 때만 히트 카운트=100 + 조건: value < 0
특정 스레드에서 10번마다 로그 조건: ThreadId + 히트 배수=10 + Tracepoint
null 들어올 때 콜스택 로그 조건: ptr==nullptr + 액션: $CALLSTACK + 계속 실행
첫 10번은 지나치고 그 다음부터 히트 카운트 >= 11

핵심 정리

  • 조건부 중단점: 특정 조건일 때만 멈춤 (i == 9999)
  • 히트 카운트: N번째 호출에서만 멈춤 (100번째만)
  • Tracepoint: 멈추지 않고 로그만 출력 (printf 대체)
  • 필터: 특정 스레드/프로세스에서만 동작
  • 조합: 여러 기능을 함께 써서 정밀 디버깅
