오디오 스트리밍

3분짜리 BGM을 어떻게 끊김없이 재생할까?

Part 1. 문제 상황 - BGM 파일의 크기

BGM 파일이 얼마나 크길래 스트리밍이 필요해?

3분짜리 BGM을 비압축 PCM으로 저장하면:

샘플링 레이트: 44,100 Hz (1초에 44,100번 샘플링)
비트 뎁스: 16bit (샘플당 2바이트)
채널: 스테레오 (2채널)

1초 = 44,100 × 2바이트 × 2채널 = 176,400 바이트 ≈ 172KB

3분 = 180초 × 172KB = 30.96MB

게임에 BGM 10곡이면? → 약 310MB가 메모리에!

효과음(0.5초)은 86KB라 메모리에 올려도 됨

하지만 BGM은 너무 커서 전부 로딩하면 메모리 폭발

Part 2. 해결책 - 조금씩 읽기

그럼 어떻게 해야 해?

핵심 아이디어: 전체를 읽지 말고, 재생할 부분만 조금씩 읽자

전체 로딩 (❌ 나쁜 방법):
┌──────────────────────────────────────────┐
│          30MB 전체를 메모리에            │
└──────────────────────────────────────────┘
→ 메모리 30MB 사용

스트리밍 (✅ 좋은 방법):
┌────┐
│256K│ ← 현재 재생 중인 부분만
└────┘
→ 메모리 256KB만 사용!

메모리 절약: 30MB → 256KB = 99% 절약

Part 3. 링 버퍼 (Ring Buffer)

조금씩 읽으면 끊기지 않아?

링 버퍼(원형 버퍼)를 사용하면 끊김 없이 재생 가능!

읽기와 재생을 동시에 진행하는 구조

링 버퍼 구조 (4개 블록 예시):

     ┌─────────────────────────────────┐
     │                                 │
     ▼                                 │
┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐
│ 블록 A │ → │ 블록 B │ → │ 블록 C │ → │ 블록 D │
│재생완료│   │재생 중 │   │읽기완료│   │ 읽는중 │
└────────┘   └────────┘   └────────┘   └────────┘
    ↑             ↑
  Write        Read
  Position     Position

시간 흐름:
T=0: A 재생, B 읽기
T=1: B 재생, C 읽기, A에 새 데이터 쓰기
T=2: C 재생, D 읽기, B에 새 데이터 쓰기
... (무한 반복)

핵심: 재생 위치가 읽기 위치를 절대 추월하지 않도록!

버퍼 크기가 클수록 안전하지만, 메모리를 더 사용

Part 4. 더블 버퍼링

더 간단한 방법은 없어?

더블 버퍼링: 버퍼 2개로 번갈아 사용

더블 버퍼링 동작:

상태 1: 버퍼 A 재생 중
┌────────────────┐   ┌────────────────┐
│   버퍼 A       │   │   버퍼 B       │
│   🔊 재생중    │   │   📥 로딩중    │
└────────────────┘   └────────────────┘

상태 2: 버퍼 A 끝나면 스왑!
┌────────────────┐   ┌────────────────┐
│   버퍼 A       │   │   버퍼 B       │
│   📥 로딩중    │   │   🔊 재생중    │
└────────────────┘   └────────────────┘

→ A 재생하는 동안 B 로딩
→ B 재생하는 동안 A 로딩
→ 무한 반복!

Part 5. 압축 포맷과 디코딩

압축하면 더 좋지 않아?

맞아! 실제 게임에서는 압축된 오디오를 스트리밍해

포맷별 비교:

포맷      │ 압축률  │ CPU 부하 │ 음질   │ 용도
──────────┼─────────┼──────────┼────────┼─────────────
PCM/WAV   │ 없음    │ 없음     │ 원본   │ 효과음
OGG Vorbis│ 10:1    │ 중간     │ 좋음   │ BGM (PC)
MP3       │ 10:1    │ 중간     │ 보통   │ BGM (호환용)
AAC       │ 12:1    │ 중간     │ 좋음   │ 모바일
ADPCM     │ 4:1     │ 낮음     │ 보통   │ 효과음
Opus      │ 15:1    │ 중간     │ 매우좋음│ 최신 게임

30MB WAV → 3MB OGG (10배 압축!)
→ 디스크 I/O도 줄고, 스트리밍 버퍼도 작아짐

주의: 압축 포맷은 실시간 디코딩이 필요

디스크 → 압축 데이터 로드 → CPU 디코딩 → PCM → 재생

Part 6. Unity 구현 예시

실제로 어떻게 설정해?

Unity에서는 AudioClip Import Settings에서 설정:

// AudioClip Import Settings Load Type 옵션: 1. Decompress On Load → 로딩 시 압축 해제, 메모리에 PCM 저장 → 효과음에 적합 (빠른 재생, 메모리 많이 사용) 2. Compressed In Memory → 압축 상태로 메모리에, 재생 시 디코딩 → 중간 크기 오디오 (메모리 절약, CPU 사용) 3. Streaming ★ BGM용! → 디스크에서 실시간 스트리밍 → BGM에 적합 (메모리 최소, 디스크 I/O)
// 코드에서 스트리밍 BGM 재생 public class BGMManager : MonoBehaviour { AudioSource audioSource; void PlayBGM(string bgmPath) { // 스트리밍으로 로드 (메모리에 전체 로드 안함) AudioClip clip = Resources.Load<AudioClip>(bgmPath); // 이미 Import Settings에서 Streaming 설정됨 audioSource.clip = clip; audioSource.loop = true; audioSource.Play(); } }

Part 7. 스트리밍 vs 프리로드 판단 기준

언제 스트리밍하고 언제 전체 로드해?

간단한 판단 기준:

판단 플로우:

오디오 길이가 얼마?
    │
    ├─ 1초 미만 ──────→ Decompress On Load (효과음)
    │                   예: 발소리, 총소리, UI 사운드
    │
    ├─ 1~10초 ────────→ Compressed In Memory
    │                   예: 대사, 짧은 환경음
    │
    └─ 10초 이상 ─────→ Streaming ★
                        예: BGM, 긴 환경음, 내레이션

메모리 vs 반응속도 트레이드오프:
┌─────────────────────────────────────────────┐
│ 프리로드   ◄─────────────────► 스트리밍    │
│ 즉시 재생                      메모리 절약  │
│ 메모리 많이                    약간 지연    │
└─────────────────────────────────────────────┘

핵심 정리

  • 3분 BGM = 30MB → 스트리밍으로 256KB만 사용
  • 링 버퍼/더블 버퍼로 끊김 없는 재생
  • OGG/AAC 압축으로 디스크 I/O 감소
  • 효과음은 프리로드, BGM은 스트리밍
  • Unity: Load Type을 "Streaming"으로 설정
