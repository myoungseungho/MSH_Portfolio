웹 게임의 스트리밍

브라우저 환경에서 에셋을 효율적으로 전달하는 전략

Part 1. 웹 게임의 특수한 환경

웹 게임은 일반 게임과 뭐가 달라? 그냥 똑같이 에셋 로딩하면 안 돼?

웹 게임은 완전히 다른 제약 조건에서 동작합니다.

네이티브 게임 vs 웹 게임 비교
═══════════════════════════════════════════════════════════

                   네이티브 게임              웹 게임
───────────────────────────────────────────────────────────
설치              다운로드 후 설치           설치 없음 (URL 접속)
첫 실행           설치 완료 후 즉시          에셋 다운로드 필요
저장소 접근       로컬 디스크 무제한         브라우저 캐시/IndexedDB
파일 시스템       직접 접근                  보안상 불가
메모리            OS가 관리                  브라우저 탭당 제한
실행 환경         Native/DirectX/OpenGL      JavaScript/WebAssembly
그래픽 API        DirectX 12, Vulkan         WebGL 2.0, WebGPU
네트워크          선택적                     항상 의존

가장 큰 차이는 설치 과정이 없다는 것입니다. 유저가 URL을 클릭하면 바로 플레이 가능해야 합니다.

설치가 없으면 좋은 거 아니야? 왜 문제가 돼?

설치가 없다는 건 모든 에셋을 매번 네트워크로 받아야 한다는 의미입니다.

웹 게임의 주요 제약

  • 첫 로딩 시간: 3초 이상 걸리면 53%의 유저가 이탈 (Google 연구)
  • 메모리 제한: 브라우저 탭당 ~2-4GB (모바일은 더 적음)
  • 캐시 한계: IndexedDB는 기기 용량의 50% 또는 최대 수 GB
  • 네트워크 의존: 오프라인이면 플레이 불가 (Service Worker 없이)
  • 파일 접근 불가: 로컬 파일 시스템 직접 접근 금지

100MB 게임도 매번 다운로드해야 한다면, 유저는 기다리다 떠나버립니다.

그럼 웹 게임은 크기를 작게 만들어야 하는 거야?

전체 크기보다 초기 로딩 크기가 중요합니다. 핵심은 점진적 로딩(Progressive Loading)입니다.

점진적 로딩 전략
═══════════════════════════════════════════════════════════

전통적 로딩 (❌)
┌─────────────────────────────────────────────────────────┐
│ [==================== 100% ===================] 플레이  │
│              10초 대기 (유저 이탈)                       │
└─────────────────────────────────────────────────────────┘

점진적 로딩 (✅)
┌─────────────────────────────────────────────────────────┐
│ [== 15% ==] 플레이 시작!   ← 2초 만에 게임 시작         │
│                                                         │
│ 플레이 중 백그라운드 로딩:                              │
│   └─ [====== 45% ======] 다음 레벨 프리로드            │
│   └─ [=========== 70% ===========] 고품질 텍스처       │
│   └─ [================= 100% ==================] 완료  │
└─────────────────────────────────────────────────────────┘

처음에는 최소한의 에셋만 로드하고, 나머지는 플레이하면서 백그라운드로 받습니다.

Part 2. 에셋 분류와 로딩 우선순위

어떤 에셋을 먼저 로드해야 해?

에셋을 우선순위 계층(Priority Tier)으로 분류합니다.

// 에셋 우선순위 분류 enum AssetPriority { // Tier 0: 즉시 필요 (초기 로딩에 포함) CRITICAL = 0, // 로딩 화면, 기본 셰이더, 코어 UI // Tier 1: 게임 시작에 필요 ESSENTIAL = 1, // 플레이어 모델, 첫 스테이지 지형 // Tier 2: 게임플레이에 필요 (점진적 로드) GAMEPLAY = 2, // 적 모델, 아이템, 이펙트 // Tier 3: 품질 향상 (여유 있을 때) ENHANCEMENT = 3, // 고해상도 텍스처, 디테일 메시 // Tier 4: 선택적 (캐시용) OPTIONAL = 4 // 다음 레벨, 미사용 스킨 }; // 에셋 매니페스트 const assetManifest = { "tier0": { "totalSize": 500 * KB, // 500KB - 2초 내 로드 "assets": [ "loading-screen.png", "core-shader.glsl", "ui-atlas-min.png", "audio-manager.wasm" ] }, "tier1": { "totalSize": 3 * MB, // 3MB - 게임 시작 전 "assets": [ "player-model.glb", "level1-terrain.bin", "basic-sfx.ogg" ] }, // ... 나머지 티어 };
500KB로 로딩 화면을 만들 수 있어?

가능합니다. 핵심은 최소한의 것만 넣는 것입니다.

Tier 0 (500KB) 구성 예시

  • 로딩 UI: CSS 애니메이션 기반 스피너 (JS 불필요)
  • 로고: SVG 또는 초압축 PNG (~20KB)
  • 배경: CSS 그라데이션 또는 패턴
  • 진행 바: 순수 HTML/CSS
  • 에셋 로더 코드: ~50KB (minified)
<!-- 순수 CSS 로딩 화면 --> <style> .loading-container { display: flex; flex-direction: column; align-items: center; justify-content: center; height: 100vh; background: linear-gradient(135deg, #1a1a2e, #16213e); } .spinner { width: 50px; height: 50px; border: 4px solid rgba(255,255,255,0.3); border-top-color: #00d9ff; border-radius: 50%; animation: spin 1s linear infinite; } @keyframes spin { to { transform: rotate(360deg); } } .progress-bar { width: 200px; height: 4px; background: rgba(255,255,255,0.2); border-radius: 2px; margin-top: 20px; overflow: hidden; } .progress-fill { height: 100%; background: #00d9ff; transition: width 0.3s ease; } </style> <!-- HTML 구조 (인라인) --> <div class="loading-container"> <div class="spinner"></div> <div class="progress-bar"> <div class="progress-fill" id="progress"></div> </div> <p id="status">Loading assets...</p> </div>
로딩 진행 상황은 어떻게 표시해?

에셋 로더에서 진행률 콜백을 제공합니다.

class WebAssetLoader { constructor() { this.loadedBytes = 0; this.totalBytes = 0; this.onProgress = null; } async loadTier(tierAssets) { // 총 크기 계산 this.totalBytes = tierAssets.reduce((sum, a) => sum + a.size, 0); this.loadedBytes = 0; const results = []; for (const asset of tierAssets) { const data = await this.loadAsset(asset); results.push(data); this.loadedBytes += asset.size; this.reportProgress(asset.name); } return results; } async loadAsset(asset) { const response = await fetch(asset.url); if (!response.ok) { throw new Error(`Failed to load: ${asset.name}`); } // 스트리밍 읽기로 진행률 세분화 const reader = response.body.getReader(); const chunks = []; let receivedBytes = 0; while (true) { const { done, value } = await reader.read(); if (done) break; chunks.push(value); receivedBytes += value.length; // 청크 단위로 진행률 업데이트 this.reportProgress(asset.name, receivedBytes / asset.size); } return this.processAsset(asset.type, chunks); } reportProgress(currentAsset, assetProgress = 1) { const overallProgress = this.loadedBytes / this.totalBytes; if (this.onProgress) { this.onProgress({ overall: overallProgress, currentAsset: currentAsset, assetProgress: assetProgress }); } } } // 사용 예 const loader = new WebAssetLoader(); loader.onProgress = (info) => { document.getElementById('progress').style.width = `${info.overall * 100}%`; document.getElementById('status').textContent = `Loading: ${info.currentAsset}`; };

Service Worker가 뭐야? 왜 웹 게임에 중요해?

Service Worker는 브라우저와 네트워크 사이의 프록시입니다. 모든 네트워크 요청을 가로채서 캐시 응답을 줄 수 있습니다.

// service-worker.js const CACHE_NAME = 'game-assets-v1'; // 핵심 에셋 미리 캐싱 (install 이벤트) self.addEventListener('install', (event) => { event.waitUntil( caches.open(CACHE_NAME).then((cache) => { // Tier 0 에셋은 Service Worker 설치 시 캐싱 return cache.addAll([ '/', '/index.html', '/assets/core-shader.glsl', '/assets/ui-atlas-min.png', '/assets/engine.wasm' ]); }) ); }); // 요청 가로채기 (fetch 이벤트) self.addEventListener('fetch', (event) => { event.respondWith( caches.match(event.request).then((cachedResponse) => { // 캐시에 있으면 즉시 반환 if (cachedResponse) { return cachedResponse; } // 없으면 네트워크 요청 후 캐싱 return fetch(event.request).then((networkResponse) => { // 에셋 URL인 경우에만 캐싱 if (event.request.url.includes('/assets/')) { const responseToCache = networkResponse.clone(); caches.open(CACHE_NAME).then((cache) => { cache.put(event.request, responseToCache); }); } return networkResponse; }); }) ); }); // 이전 버전 캐시 정리 (activate 이벤트) self.addEventListener('activate', (event) => { event.waitUntil( caches.keys().then((cacheNames) => { return Promise.all( cacheNames .filter((name) => name !== CACHE_NAME) .map((name) => caches.delete(name)) ); }) ); });
IndexedDB는 언제 써?

IndexedDB는 구조화된 데이터와 대용량 바이너리에 적합합니다.

class AssetDatabase { constructor(dbName = 'GameAssets') { this.dbName = dbName; this.db = null; } async init() { return new Promise((resolve, reject) => { const request = indexedDB.open(this.dbName, 1); request.onerror = () => reject(request.error); request.onsuccess = () => { this.db = request.result; resolve(); }; request.onupgradeneeded = (event) => { const db = event.target.result; // 에셋 저장소 if (!db.objectStoreNames.contains('assets')) { const store = db.createObjectStore('assets', { keyPath: 'id' }); store.createIndex('type', 'type', { unique: false }); store.createIndex('version', 'version', { unique: false }); } // 게임 세이브 저장소 if (!db.objectStoreNames.contains('saves')) { db.createObjectStore('saves', { keyPath: 'slot' }); } }; }); } async getAsset(id) { return new Promise((resolve, reject) => { const tx = this.db.transaction('assets', 'readonly'); const store = tx.objectStore('assets'); const request = store.get(id); request.onerror = () => reject(request.error); request.onsuccess = () => resolve(request.result); }); } async storeAsset(id, data, metadata) { return new Promise((resolve, reject) => { const tx = this.db.transaction('assets', 'readwrite'); const store = tx.objectStore('assets'); const record = { id: id, data: data, // ArrayBuffer 또는 Blob type: metadata.type, version: metadata.version, timestamp: Date.now() }; const request = store.put(record); request.onerror = () => reject(request.error); request.onsuccess = () => resolve(); }); } async checkVersion(id, serverVersion) { const cached = await this.getAsset(id); if (!cached) return false; return cached.version === serverVersion; } }

Part 4. WebGL 텍스처 최적화

웹에서는 어떤 텍스처 포맷을 써야 해?

브라우저마다 지원하는 압축 포맷이 다릅니다. Basis Universal이 해결책입니다.

WebGL 텍스처 포맷 지원 현황
═══════════════════════════════════════════════════════════

                     Chrome    Firefox    Safari    Edge
───────────────────────────────────────────────────────────
PNG/JPG (비압축)       ✅        ✅        ✅       ✅
DXT (S3TC)             ✅        ✅        ❌       ✅
PVRTC                  ❌        ❌        ✅       ❌
ETC1                   ✅        ✅        ❌       ✅
ETC2                   ✅        ✅        ❌       ✅
ASTC                   ✅        ✅        ✅       ✅
───────────────────────────────────────────────────────────

Basis Universal (KTX2)
├─ 하나의 파일로 모든 브라우저 지원
├─ 런타임에 기기에 맞는 포맷으로 트랜스코딩
└─ 원본 대비 75-90% 크기 감소
Basis Universal이 뭐야?

Basis는 중간 포맷입니다. 저장은 하나의 포맷으로 하고, 로드 시 기기가 지원하는 포맷으로 변환합니다.

// Basis Universal 텍스처 로더 class BasisTextureLoader { constructor(gl) { this.gl = gl; this.transcoder = null; this.targetFormat = this.detectBestFormat(); } detectBestFormat() { const gl = this.gl; // ASTC가 가장 좋음 (품질 + 크기) if (gl.getExtension('WEBGL_compressed_texture_astc')) { return 'ASTC_4x4'; } // DXT (Windows/Linux 데스크톱) if (gl.getExtension('WEBGL_compressed_texture_s3tc')) { return 'BC7'; // 또는 'BC1' (알파 없으면) } // ETC2 (Android) if (gl.getExtension('WEBGL_compressed_texture_etc')) { return 'ETC2'; } // PVRTC (iOS Safari - WebGL 1.0) if (gl.getExtension('WEBGL_compressed_texture_pvrtc')) { return 'PVRTC1_4'; } // 최후의 수단: 비압축 return 'RGBA32'; } async initTranscoder() { // Basis 트랜스코더 WASM 로드 const { BasisFile, initializeBasis } = await import('./basis_transcoder.js'); await initializeBasis(); this.BasisFile = BasisFile; } async loadTexture(url) { const response = await fetch(url); const arrayBuffer = await response.arrayBuffer(); // Basis 파일 파싱 const basisFile = new this.BasisFile(new Uint8Array(arrayBuffer)); if (!basisFile.startTranscoding()) { throw new Error('Transcoding failed'); } // 타겟 포맷으로 트랜스코딩 const width = basisFile.getImageWidth(0, 0); const height = basisFile.getImageHeight(0, 0); const levels = basisFile.getNumLevels(0); const texture = this.gl.createTexture(); this.gl.bindTexture(this.gl.TEXTURE_2D, texture); for (let level = 0; level < levels; level++) { const dstSize = basisFile.getImageTranscodedSizeInBytes( 0, level, this.getFormatEnum()); const dst = new Uint8Array(dstSize); basisFile.transcodeImage(dst, 0, level, this.getFormatEnum(), 0, 0); this.uploadCompressedTexture(level, dst, width >> level, height >> level); } basisFile.close(); basisFile.delete(); return texture; } }
텍스처 스트리밍도 웹에서 가능해?

네, 밉맵 레벨별 스트리밍을 구현할 수 있습니다.

class WebTextureStreaming { constructor(gl) { this.gl = gl; this.textures = new Map(); } async loadTextureProgressive(textureId, baseUrl) { const gl = this.gl; const texture = gl.createTexture(); gl.bindTexture(gl.TEXTURE_2D, texture); // 1. 최저 해상도 즉시 로드 (예: 32x32) const thumbUrl = `${baseUrl}_thumb.basis`; const thumbData = await this.fetchAndTranscode(thumbUrl); gl.texImage2D(gl.TEXTURE_2D, 6, gl.RGB, 32, 32, 0, gl.RGB, gl.UNSIGNED_BYTE, thumbData); gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MAX_LEVEL, 6); this.textures.set(textureId, { glTexture: texture, currentLevel: 6, targetLevel: 0, baseUrl: baseUrl }); // 2. 백그라운드에서 고해상도 로드 this.scheduleHighResLoad(textureId); return texture; } async scheduleHighResLoad(textureId) { const info = this.textures.get(textureId); // 카메라에서 가까우면 우선순위 높임 const priority = this.calculatePriority(textureId); // 단계별 업그레이드: 256 -> 512 -> 1024 -> 2048 const mipLevels = [4, 3, 2, 1, 0]; // 밉 레벨 for (const level of mipLevels) { if (level >= info.currentLevel) continue; // 네트워크 상태에 따라 대기 await this.waitForBandwidth(); const url = `${info.baseUrl}_mip${level}.basis`; const mipData = await this.fetchAndTranscode(url); // GPU에 업로드 const gl = this.gl; const size = Math.pow(2, 11 - level); // 2048 / 2^level gl.bindTexture(gl.TEXTURE_2D, info.glTexture); gl.texImage2D(gl.TEXTURE_2D, level, gl.RGB, size, size, 0, gl.RGB, gl.UNSIGNED_BYTE, mipData); gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MAX_LEVEL, level); info.currentLevel = level; } } async waitForBandwidth() { // Network Information API 활용 if (navigator.connection) { const conn = navigator.connection; // 데이터 절약 모드면 고해상도 스킵 if (conn.saveData) { throw new Error('Data saver mode'); } // 연결이 느리면 대기 if (conn.effectiveType === '2g' || conn.effectiveType === 'slow-2g') { await new Promise(r => setTimeout(r, 5000)); } } } }

Part 5. WASM과 멀티스레딩

WebAssembly를 쓰면 웹 게임이 더 빨라져?

네, WASM은 JavaScript보다 훨씬 빠릅니다. 특히 CPU 집약적인 작업에서요.

JavaScript vs WebAssembly 성능 비교
═══════════════════════════════════════════════════════════

작업                     JavaScript    WASM      속도 향상
───────────────────────────────────────────────────────────
물리 시뮬레이션            100ms       15ms       6.7x
경로 탐색 (A*)             50ms        8ms       6.3x
텍스처 디코딩              80ms       12ms       6.7x
JSON 파싱                  10ms        3ms       3.3x
이미지 처리               120ms       20ms       6.0x
───────────────────────────────────────────────────────────

WASM 장점:
├─ 네이티브에 가까운 실행 속도
├─ 컴파일 타임 최적화
├─ 예측 가능한 성능
└─ C/C++/Rust 코드 재사용

WASM 단점:
├─ 초기 컴파일 오버헤드
├─ 파일 크기 증가
├─ DOM 접근 불가 (JS 통해야 함)
└─ 디버깅 복잡
에셋 로딩에 WASM을 어떻게 활용해?

텍스처 디코딩, 압축 해제, 데이터 파싱 등에 WASM을 사용합니다.

웹에서도 멀티스레딩이 돼?

Web Worker를 사용하면 메인 스레드를 블로킹하지 않고 에셋을 처리할 수 있습니다.

// asset-worker.js (Web Worker) self.importScripts('wasm-processor.js'); let processor = null; self.onmessage = async (event) => { const { type, data, id } = event.data; switch (type) { case 'init': processor = new WasmAssetProcessor(); await processor.init(); self.postMessage({ type: 'ready' }); break; case 'decode-texture': const decoded = processor.decodeBasisTexture(data); // Transferable로 전송 (복사 없이) self.postMessage( { type: 'texture-decoded', id, data: decoded }, [decoded.buffer] // ownership 이전 ); break; case 'decompress': const decompressed = processor.decompressLZ4(data); self.postMessage( { type: 'decompressed', id, data: decompressed }, [decompressed.buffer] ); break; } }; // 메인 스레드 class AssetWorkerPool { constructor(workerCount = navigator.hardwareConcurrency || 4) { this.workers = []; this.nextWorker = 0; this.pending = new Map(); this.idCounter = 0; for (let i = 0; i < workerCount; i++) { const worker = new Worker('asset-worker.js'); worker.onmessage = (e) => this.handleMessage(e, i); this.workers.push(worker); } } async init() { await Promise.all( this.workers.map(w => new Promise(resolve => { w.postMessage({ type: 'init' }); w.addEventListener('message', function handler(e) { if (e.data.type === 'ready') { w.removeEventListener('message', handler); resolve(); } }); }) ) ); } decodeTexture(basisData) { return this.sendTask('decode-texture', basisData); } sendTask(type, data) { const id = ++this.idCounter; const worker = this.workers[this.nextWorker]; this.nextWorker = (this.nextWorker + 1) % this.workers.length; return new Promise((resolve) => { this.pending.set(id, resolve); worker.postMessage({ type, data, id }, [data.buffer]); }); } handleMessage(event, workerIndex) { const { id, data } = event.data; const resolve = this.pending.get(id); if (resolve) { this.pending.delete(id); resolve(data); } } }

Part 6. 네트워크 최적화

네트워크가 느리면 어떻게 대응해?

적응형 품질(Adaptive Quality) 시스템을 구현합니다.

class AdaptiveAssetLoader { constructor() { this.qualityLevel = 'high'; // high, medium, low this.bandwidthHistory = []; this.monitorConnection(); } monitorConnection() { // Network Information API if (navigator.connection) { navigator.connection.addEventListener('change', () => { this.updateQualityLevel(); }); } // 실제 다운로드 속도 측정 setInterval(() => this.measureBandwidth(), 5000); } async measureBandwidth() { const testUrl = '/bandwidth-test.bin'; // 100KB 테스트 파일 const start = performance.now(); try { const response = await fetch(testUrl + '?t=' + Date.now()); const blob = await response.blob(); const elapsed = (performance.now() - start) / 1000; const bandwidth = (blob.size * 8) / elapsed; // bits per second this.bandwidthHistory.push(bandwidth); if (this.bandwidthHistory.length > 5) { this.bandwidthHistory.shift(); } this.updateQualityLevel(); } catch (e) { console.warn('Bandwidth test failed'); } } updateQualityLevel() { const avgBandwidth = this.getAverageBandwidth(); // Mbps 단위로 변환 const mbps = avgBandwidth / 1000000; if (mbps >= 10) { this.qualityLevel = 'high'; } else if (mbps >= 3) { this.qualityLevel = 'medium'; } else { this.qualityLevel = 'low'; } console.log(`Quality level: ${this.qualityLevel} (${mbps.toFixed(1)} Mbps)`); } getAssetUrl(assetId) { // 품질 레벨에 따라 다른 에셋 반환 const qualitySuffix = { 'high': '', // 원본 'medium': '_med', // 50% 크기 'low': '_low' // 25% 크기 }; return `/assets/${assetId}${qualitySuffix[this.qualityLevel]}.bin`; } }
오프라인에서도 플레이할 수 있게 할 수 있어?

Service Worker + IndexedDB를 조합하면 완전한 오프라인 지원이 가능합니다.

// 오프라인 지원 매니저 class OfflineManager { constructor() { this.isOnline = navigator.onLine; this.setupListeners(); } setupListeners() { window.addEventListener('online', () => { this.isOnline = true; console.log('Back online'); this.syncPendingData(); }); window.addEventListener('offline', () => { this.isOnline = false; console.log('Gone offline'); this.showOfflineIndicator(); }); } async cacheForOffline(assetList) { const cache = await caches.open('offline-assets'); const db = await this.openDB(); for (const asset of assetList) { // 이미 캐시되어 있는지 확인 const cached = await cache.match(asset.url); if (cached) continue; // 다운로드 및 캐싱 const response = await fetch(asset.url); await cache.put(asset.url, response.clone()); // IndexedDB에 메타데이터 저장 await this.storeMetadata(db, asset); } console.log(`Cached ${assetList.length} assets for offline play`); } async getCacheStatus() { const cache = await caches.open('offline-assets'); const keys = await cache.keys(); let totalSize = 0; for (const request of keys) { const response = await cache.match(request); const blob = await response.blob(); totalSize += blob.size; } return { fileCount: keys.length, totalSize: totalSize, canPlayOffline: keys.length >= MINIMUM_OFFLINE_ASSETS }; } } // UI에서 오프라인 다운로드 버튼 document.getElementById('download-offline').addEventListener('click', async () => { const offlineMgr = new OfflineManager(); const essentialAssets = await fetch('/manifest/offline.json').then(r => r.json()); await offlineMgr.cacheForOffline(essentialAssets); alert('게임을 오프라인에서도 플레이할 수 있습니다!'); });

핵심 정리

  • 점진적 로딩: 최소 에셋으로 게임 시작, 나머지는 백그라운드 로드
  • 우선순위 계층: Tier 0 (500KB) → Tier 1 (3MB) → ... 단계별 분류
  • 캐싱 전략: Service Worker + IndexedDB + HTTP Cache 조합
  • 텍스처 포맷: Basis Universal/KTX2로 모든 브라우저 지원
  • WASM + Worker: CPU 집약 작업은 WASM, 메인 스레드 블로킹 방지
  • 적응형 품질: 네트워크 상태에 따라 자동 품질 조절
  • 오프라인 지원: Service Worker로 완전한 오프라인 플레이 가능
