스택 오버플로우

재귀 호출과 큰 지역 변수 — 스택 공간 소진

Part 1. 증상

Stack overflow 예외가 발생했습니다

스택 메모리가 바닥났다는 뜻.

기본 스택 크기는 1MB (Windows).

Part 2. 원인 1: 무한 재귀

Call Stack에 같은 함수가 수천 개

재귀 종료 조건이 없거나 도달하지 못한다.

// 무한 재귀 void ProcessNode(Node* pNode) { DoSomething(pNode); ProcessNode(pNode->next); // 종료 조건 없음! } // 올바른 재귀 void ProcessNode(Node* pNode) { if (pNode == nullptr) return; // 종료 조건! DoSomething(pNode); ProcessNode(pNode->next); }

Part 3. 원인 2: 큰 지역 변수

재귀 없는데도 스택 오버플로우?

함수 안에 큰 배열을 선언하면 스택이 금방 찬다.

// 스택에 1MB 배열 선언 → 즉시 오버플로우 void BadFunction() { char buffer[1024 * 1024]; // 1MB 지역 변수 ← 위험! } // 해결: 힙에 할당 void GoodFunction() { char* buffer = new char[1024 * 1024]; // 힙에 할당 // ... 사용 ... delete[] buffer; } // 더 좋은 해결: vector 사용 void BetterFunction() { std::vector buffer(1024 * 1024); }

Part 4. 디버깅 방법

어떻게 찾아?

1. Call Stack에서 반복되는 함수 확인

2. 해당 함수의 지역 변수 크기 확인

3. 재귀 깊이 제한 또는 반복문으로 변환

// Call Stack 예시 (재귀 오버플로우) → ProcessNode() Line 45 ProcessNode() Line 45 ProcessNode() Line 45 ... (수천 번 반복) ProcessNode() Line 45 main() Line 10

Part 5. 스택 크기 늘리기

스택 크기 조절할 수 있어?

프로젝트 속성 → Linker → System → Stack Reserve Size

하지만 이건 임시방편. 근본 원인을 해결하자.

핵심 정리

  • 무한 재귀 = 종료 조건 확인
  • 큰 지역 변수 = 힙 할당으로 변경
  • Call Stack에서 반복 패턴 확인
  • 스택 크기 늘리기는 임시방편
