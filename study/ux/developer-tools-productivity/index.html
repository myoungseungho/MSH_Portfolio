개발자 도구 생산성

게임 개발자 도구가 생산성을 10배 올리는 법

Part 1. 인게임 콘솔과 치트

개발 중에 레벨 99 캐릭터로 테스트하려면 어떻게 해?

인게임 콘솔(Console)과 치트 명령어를 사용합니다:

인게임 개발자 콘솔: +----------------------------------------------------------+ | | | [~] 키로 콘솔 열기 | | +----------------------------------------------------+ | | | > setlevel 99 | | | | [OK] 레벨이 99로 변경되었습니다. | | | | | | | | > additem sword_legendary 1 | | | | [OK] 전설의 검 x1 추가됨 | | | | | | | | > teleport dungeon_boss | | | | [OK] 던전_보스 위치로 이동합니다. | | | | | | | | > god | | | | [OK] 무적 모드 활성화 | | | +----------------------------------------------------+ | | | +----------------------------------------------------------+ 필수 개발자 치트 명령어: +----------------------------------------------------------+ | 명령어 기능 | | ------- ---- | | god 무적 모드 | | noclip 벽 통과 | | fly 비행 모드 | | setlevel [n] 레벨 설정 | | additem [id] [n] 아이템 추가 | | addgold [n] 골드 추가 | | teleport [zone] 지역 이동 | | spawn [mob] 몬스터 소환 | | killall 주변 몬스터 제거 | | timescale [n] 게임 속도 조절 | | clearquest 퀘스트 초기화 | +----------------------------------------------------------+
// 개발자 콘솔 시스템 class DevConsole { std::map<std::string, CommandFunc> m_commands; bool m_isOpen = false; std::vector<std::string> m_history; public: void Init() { // 치트 명령어 등록 RegisterCommand("god", [](const Args& args) { Player::Get()->SetInvincible(!Player::Get()->IsInvincible()); return Player::Get()->IsInvincible() ? "무적 모드 ON" : "무적 모드 OFF"; }); RegisterCommand("setlevel", [](const Args& args) { if (args.size() < 1) return "Usage: setlevel [level]"; int level = std::stoi(args[0]); Player::Get()->SetLevel(level); return Format("레벨이 %d로 변경됨", level); }); RegisterCommand("additem", [](const Args& args) { if (args.size() < 1) return "Usage: additem [id] [count=1]"; std::string itemId = args[0]; int count = args.size() > 1 ? std::stoi(args[1]) : 1; auto* item = ItemDB::Find(itemId); if (!item) return Format("아이템 '%s' 없음", itemId); Player::Get()->GetInventory()->Add(item, count); return Format("%s x%d 추가됨", item->name, count); }); RegisterCommand("teleport", [](const Args& args) { if (args.size() < 1) return "Usage: teleport [zone]"; std::string zone = args[0]; auto* spawn = ZoneDB::GetSpawnPoint(zone); if (!spawn) return Format("존 '%s' 없음", zone); Player::Get()->TeleportTo(spawn->position); return Format("%s로 이동", zone); }); RegisterCommand("spawn", [](const Args& args) { if (args.size() < 1) return "Usage: spawn [mobId] [count=1]"; std::string mobId = args[0]; int count = args.size() > 1 ? std::stoi(args[1]) : 1; auto* mobData = MobDB::Find(mobId); if (!mobData) return Format("몬스터 '%s' 없음", mobId); Vector3 pos = Player::Get()->GetPosition() + Vector3(5, 0, 0); for (int i = 0; i < count; i++) { SpawnManager::Spawn(mobData, pos + Vector3(i * 2, 0, 0)); } return Format("%s x%d 소환됨", mobData->name, count); }); // 자동완성용 아이템 목록 RegisterAutoComplete("additem", []() { return ItemDB::GetAllIds(); }); } void Execute(const std::string& input) { m_history.push_back(input); auto tokens = Tokenize(input); if (tokens.empty()) return; auto& cmd = tokens[0]; auto args = std::vector<std::string>(tokens.begin() + 1, tokens.end()); auto it = m_commands.find(cmd); if (it != m_commands.end()) { std::string result = it->second(args); Log(result); } else { Log(Format("알 수 없는 명령어: %s", cmd)); } } };
릴리즈 빌드에서는 치트 어떻게 막아?

조건부 컴파일과 권한 체크를 사용합니다:

치트 보안: +----------------------------------------------------------+ | | | 1. 조건부 컴파일 (완전 제거) | | +----------------------------------------------------+ | | | #ifdef DEV_BUILD | | | | // 개발 빌드에서만 치트 활성화 | | | | RegisterCheatCommands(); | | | | #endif | | | +----------------------------------------------------+ | | | | 2. 권한 체크 (서버 검증) | | +----------------------------------------------------+ | | | if (Player::HasPermission(PERM_CHEAT)) { | | | | // GM 계정만 치트 가능 | | | | ExecuteCheat(cmd); | | | | } | | | +----------------------------------------------------+ | | | | 3. 서버 사이드 검증 | | +----------------------------------------------------+ | | | 치트 실행 -> 서버에 요청 -> 권한 확인 -> 실행 | | | | (클라이언트만으로 치트 불가) | | | +----------------------------------------------------+ | | | +----------------------------------------------------------+

Part 3. 프로파일링 도구

게임이 왜 느린지 어떻게 찾아?

프로파일러로 성능 병목을 시각적으로 확인합니다:

프로파일링 결과 예시: +----------------------------------------------------------+ | Frame: 16.7ms (60 FPS 목표) | | +------------------------------------------------------+| | | CPU || | | +--------------------------------------------------+ || | | |[Update]------|[Physics]-|[AI]------|[Render] | || | | | 4.2ms | 3.1ms | 5.8ms | 2.1ms | || | | +--------------------------------------------------+ || | | || | | GPU || | | +--------------------------------------------------+ || | | |[Shadow]---|[G-Buffer]-----|[Lighting]|[Post] | || | | | 2.3ms | 4.5ms | 3.2ms | 1.8ms | || | | +--------------------------------------------------+ || | +------------------------------------------------------+| | | | 병목 발견: AI 처리 5.8ms (35%) | | +----------------------------------------------------+ | | | AI::PathFind() 3.2ms 55% <- 핫스팟 | | | | AI::TargetSelect() 1.5ms 26% | | | | AI::StateUpdate() 0.8ms 14% | | | | 기타 0.3ms 5% | | | +----------------------------------------------------+ | | | +----------------------------------------------------------+
// 간단한 프로파일링 시스템 class Profiler { struct ProfileBlock { std::string name; double startTime; double elapsed; int depth; }; std::vector<ProfileBlock> m_blocks; std::stack<int> m_activeBlocks; int m_currentDepth = 0; public: void BeginBlock(const std::string& name) { ProfileBlock block; block.name = name; block.startTime = GetHighResTimer(); block.depth = m_currentDepth++; m_activeBlocks.push(m_blocks.size()); m_blocks.push_back(block); } void EndBlock() { int idx = m_activeBlocks.top(); m_activeBlocks.pop(); m_blocks[idx].elapsed = GetHighResTimer() - m_blocks[idx].startTime; m_currentDepth--; } void RenderOverlay() { // 화면에 프로파일 결과 표시 float y = 10; for (const auto& block : m_blocks) { std::string indent(block.depth * 2, ' '); std::string text = Format("%s%s: %.2fms", indent, block.name, block.elapsed * 1000); // 느린 블록 강조 Color color = block.elapsed > 0.002 ? COLOR_RED : COLOR_WHITE; DrawText(10, y, text, color); y += 16; } } }; // 사용법 #define PROFILE_BLOCK(name) ProfileScope _prof##__LINE__(name) class ProfileScope { ProfileScope(const std::string& name) { Profiler::Get()->BeginBlock(name); } ~ProfileScope() { Profiler::Get()->EndBlock(); } }; // 실제 사용 void Update() { PROFILE_BLOCK("Update"); { PROFILE_BLOCK("Physics"); PhysicsWorld::Step(); } { PROFILE_BLOCK("AI"); AIManager::Update(); // <- 여기가 느리다고 표시됨 } { PROFILE_BLOCK("Render"); Renderer::Draw(); } }

Part 4. 자동화 스크립트

반복 작업을 어떻게 자동화해?

빌드 자동화, 테스트 자동화, 배포 자동화:

자동화가 필요한 작업: +----------------------------------------------------------+ | | | 1. 빌드 자동화 | | +----------------------------------------------------+ | | | 수동: 빌드 설정 -> 빌드 -> 결과 확인 -> 복사 (30분) | | | | 자동: ./build.sh 한 줄로 끝 (15분, 병렬 처리) | | | +----------------------------------------------------+ | | | | 2. 데이터 변환 | | +----------------------------------------------------+ | | | Excel -> CSV -> Binary 변환 | | | | 수동: 파일 하나씩 변환 (100개면 2시간) | | | | 자동: 스크립트로 전체 변환 (5분) | | | +----------------------------------------------------+ | | | | 3. 테스트 자동화 | | +----------------------------------------------------+ | | | 수동: 기능 하나씩 직접 테스트 | | | | 자동: 100개 테스트 케이스 자동 실행 + 리포트 | | | +----------------------------------------------------+ | | | | 4. 배포 자동화 | | +----------------------------------------------------+ | | | 수동: 서버마다 파일 복사 (10대면 1시간) | | | | 자동: 한 번에 모든 서버 배포 (10분) | | | +----------------------------------------------------+ | | | +----------------------------------------------------------+
# 빌드 자동화 스크립트 (Python) import subprocess import os import shutil from datetime import datetime def build_game(): print("=== 게임 빌드 시작 ===") # 1. 버전 업데이트 version = update_version() print(f"버전: {version}") # 2. 데이터 변환 print("데이터 변환 중...") convert_all_data() # 3. 클라이언트 빌드 print("클라이언트 빌드 중...") result = subprocess.run([ "msbuild", "GameClient.sln", "/p:Configuration=Release", "/p:Platform=x64", "/m" # 병렬 빌드 ], capture_output=True) if result.returncode != 0: print("빌드 실패!") send_slack_notification("빌드 실패", result.stderr) return False # 4. 서버 빌드 print("서버 빌드 중...") build_server() # 5. 패키징 print("패키징 중...") output_path = package_build(version) # 6. 알림 send_slack_notification( "빌드 성공", f"버전 {version}\n경로: {output_path}" ) print(f"=== 빌드 완료: {output_path} ===") return True def convert_all_data(): """Excel -> Binary 데이터 변환""" data_path = "Data/Excel" output_path = "Data/Binary" for excel_file in os.listdir(data_path): if excel_file.endswith(".xlsx"): # Excel -> CSV -> Binary csv = convert_excel_to_csv(f"{data_path}/{excel_file}") binary = convert_csv_to_binary(csv) shutil.copy(binary, output_path) def run_tests(): """자동화 테스트 실행""" print("=== 테스트 실행 ===") test_results = [] # 단위 테스트 result = subprocess.run(["./UnitTests.exe"], capture_output=True) test_results.append(("단위 테스트", result.returncode == 0)) # 통합 테스트 result = subprocess.run(["./IntegrationTests.exe"], capture_output=True) test_results.append(("통합 테스트", result.returncode == 0)) # 결과 출력 for name, passed in test_results: status = "PASS" if passed else "FAIL" print(f" {name}: {status}") return all(passed for _, passed in test_results) if __name__ == "__main__": if build_game() and run_tests(): print("모든 작업 완료!") else: print("작업 실패!") exit(1)
CI/CD 파이프라인은 뭐야?

Continuous Integration/Deployment - 코드 푸시하면 자동으로 빌드/테스트/배포:

CI/CD 파이프라인: +----------------------------------------------------------+ | | | 개발자 코드 푸시 | | ↓ | | +----------------------------------------------------+ | | | 1. Trigger: Git Push 감지 | | | +----------------------------------------------------+ | | ↓ | | +----------------------------------------------------+ | | | 2. Build: 자동 빌드 (클라이언트 + 서버) | | | +----------------------------------------------------+ | | ↓ | | +----------------------------------------------------+ | | | 3. Test: 자동화 테스트 실행 | | | +----------------------------------------------------+ | | ↓ (테스트 통과 시) | | +----------------------------------------------------+ | | | 4. Deploy: 테스트 서버 자동 배포 | | | +----------------------------------------------------+ | | ↓ (QA 승인 시) | | +----------------------------------------------------+ | | | 5. Release: 라이브 서버 배포 | | | +----------------------------------------------------+ | | | +----------------------------------------------------------+ 효과: - 버그 조기 발견 (푸시할 때마다 테스트) - 배포 시간 단축 (수동 2시간 -> 자동 15분) - 휴먼 에러 감소 (항상 같은 과정)

Part 5. 디버깅 도구

런타임에 게임 상태를 어떻게 확인해?

디버그 오버레이와 인스펙터를 사용합니다:

디버그 오버레이 (F1 토글): +----------------------------------------------------------+ | [게임 화면] | | +------------------------------------------------------+| | | FPS: 60.2 || | | Frame: 16.7ms || | | Draw Calls: 234 || | | Triangles: 1.2M || | | || | | [캐릭터] Players: 45 || | | HP: 1500/1500 Monsters: 128 || | | MP: 800/800 NPCs: 32 || | | Pos: (123.4, 0, 567.8) || | | State: IDLE || | | Target: none || | | || | | [NavMesh 표시] [Collider 표시] [AI State 표시] || | +------------------------------------------------------+| | | +----------------------------------------------------------+ 오브젝트 인스펙터 (마우스 오른쪽 클릭): +----------------------------------------------------------+ | Monster_Wolf_001 | | +----------------------------------------------------+ | | | Transform | | | | Position: [123.4] [0.0] [567.8] | | | | Rotation: [0] [45] [0] | | | | Scale: [1] [1] [1] | | | +----------------------------------------------------+ | | | Stats | | | | HP: [250] / 500 | | | | ATK: 50 DEF: 20 SPD: 5 | | | +----------------------------------------------------+ | | | AI | | | | State: CHASE | | | | Target: Player_001 | | | | Path: [Show] | | | +----------------------------------------------------+ | | | [Kill] [Heal] [Teleport Here] | | | +----------------------------------------------------+ | | | +----------------------------------------------------------+
// 디버그 오버레이 시스템 class DebugOverlay { bool m_bShowStats = true; bool m_bShowNavMesh = false; bool m_bShowColliders = false; bool m_bShowAI = false; public: void Toggle() { m_bShowStats = !m_bShowStats; } void Render() { if (!m_bShowStats) return; // 기본 성능 정보 float y = 10; DrawText(10, y, Format("FPS: %.1f", GetFPS())); y += 16; DrawText(10, y, Format("Frame: %.1fms", GetFrameTime() * 1000)); y += 16; DrawText(10, y, Format("Draw Calls: %d", GetDrawCallCount())); y += 16; // 플레이어 정보 if (auto* player = Player::Get()) { y += 20; DrawText(10, y, "=== Player ==="); y += 16; DrawText(10, y, Format("HP: %d/%d", player->GetHP(), player->GetMaxHP())); y += 16; DrawText(10, y, Format("Pos: (%.1f, %.1f, %.1f)", player->GetPosition().x, player->GetPosition().y, player->GetPosition().z)); y += 16; DrawText(10, y, Format("State: %s", GetStateName(player->GetState()))); y += 16; } // 선택적 시각화 if (m_bShowNavMesh) NavMesh::DebugRender(); if (m_bShowColliders) Physics::DebugRenderColliders(); if (m_bShowAI) AIManager::DebugRenderPaths(); } }; // 오브젝트 인스펙터 class DebugInspector { GameObject* m_pSelected = nullptr; public: void OnRightClick(Vector2 screenPos) { // 레이캐스트로 오브젝트 선택 Ray ray = Camera::ScreenToRay(screenPos); if (Physics::Raycast(ray, &hit)) { m_pSelected = hit.gameObject; } } void RenderWindow() { if (!m_pSelected) return; ImGui::Begin("Inspector"); // Transform if (ImGui::CollapsingHeader("Transform")) { auto pos = m_pSelected->GetPosition(); if (ImGui::DragFloat3("Position", &pos.x)) { m_pSelected->SetPosition(pos); } } // Stats (Monster인 경우) if (auto* monster = dynamic_cast<Monster*>(m_pSelected)) { if (ImGui::CollapsingHeader("Stats")) { int hp = monster->GetHP(); if (ImGui::SliderInt("HP", &hp, 0, monster->GetMaxHP())) { monster->SetHP(hp); } } // 퀵 액션 if (ImGui::Button("Kill")) monster->Kill(); ImGui::SameLine(); if (ImGui::Button("Heal")) monster->FullHeal(); } ImGui::End(); } };

핵심 정리

  • 인게임 콘솔: 치트 명령어로 빠른 테스트 (레벨, 아이템, 텔레포트)
  • 레벨 에디터: 시각적 맵 제작으로 10배 빠른 작업
  • 프로파일러: CPU/GPU/메모리 병목 시각적 확인
  • 자동화 스크립트: 빌드, 데이터 변환, 테스트, 배포 자동화
  • CI/CD: 푸시 -> 빌드 -> 테스트 -> 배포 자동 파이프라인
  • 디버그 오버레이: 런타임 상태 확인 + 오브젝트 인스펙터
