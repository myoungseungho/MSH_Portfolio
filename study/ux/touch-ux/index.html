터치 UX

왜 모바일 게임 버튼은 저 위치에 있을까?

Part 1. 엄지 도달 범위 (Thumb Zone)

모바일 게임 UI가 왜 다 아래쪽에 몰려 있어?

엄지 도달 범위 때문입니다. 한 손으로 스마트폰을 잡으면 엄지가 닿는 영역이 제한됩니다:

엄지 도달 범위 (Thumb Zone) - 오른손 기준: +------------------------------------------+ | | | +------------------------------------+ | | | Hard Zone Hard Zone | | <- 상단: 손을 뻗어야 닿음 | | (닿기 어려움) (닿기 어려움) | | | | | | | | +------------------+ | | | | | | | | | | Ow! | Natural Zone | OK | | <- 중앙: 편하게 닿음 | | Zone | (가장 편함) | Zone | | | | | | | | | | +------------------+ | | | | | | | | OK Zone | | <- 하단: 쉽게 닿음 | | (쉽게 닿음) | | | +------------------------------------+ | | | | [___] <- 홈 버튼 | | | | (O) <- 엄지 위치 | | | +------------------------------------------+ 중요 버튼은 Natural Zone (하단 중앙-오른쪽)에 배치!
화면 크기에 따라 달라지지 않아?

네, 화면이 커질수록 도달 범위가 줄어듭니다:

화면 크기별 편한 영역: +------------------------------------------+ | | | 4.7인치 (iPhone SE) 6.7인치 (Plus) | | +-----------------+ +-----------+ | | | | | XXX | | | | 넓은 영역 | | XXX | | | | 편하게 | | XXX | | | | 닿음 | | | | | | | | 좁은 | | | | | | 영역 | | | +-----------------+ +-----------+ | | | +------------------------------------------+ 큰 화면 대응 전략: 1. Reachability 기능 (화면 반으로 내리기) 2. 중요 버튼을 더 아래에 배치 3. 양손 모드 제공 4. 스와이프 제스처로 상단 기능 접근
// 화면 크기에 따른 UI 배치 조정 class AdaptiveUILayout { void LayoutForDevice(float screenHeight) { float thumbReachRatio; if (screenHeight < 600) { // 작은 화면 thumbReachRatio = 0.75f; // 화면 75%까지 편하게 닿음 } else if (screenHeight < 750) { // 중간 화면 thumbReachRatio = 0.65f; // 화면 65%까지 } else { // 큰 화면 thumbReachRatio = 0.55f; // 화면 55%까지만 } // 중요 버튼은 도달 가능 영역 내에 배치 float safeZoneTop = screenHeight * (1.0f - thumbReachRatio); PositionCriticalButtons(safeZoneTop, screenHeight); } void PositionCriticalButtons(float top, float bottom) { // 공격 버튼: 오른쪽 하단 (가장 자주 누름) m_attackBtn.SetPosition(SCREEN_RIGHT - 80, bottom - 100); // 스킬 버튼들: 공격 버튼 주변 호 형태 m_skill1.SetPosition(SCREEN_RIGHT - 160, bottom - 80); m_skill2.SetPosition(SCREEN_RIGHT - 120, bottom - 160); // 이동 조이스틱: 왼쪽 하단 m_joystick.SetPosition(80, bottom - 100); } };

Part 2. 터치 타겟 크기

버튼이 얼마나 커야 해?

최소 44pt (약 7mm)가 업계 표준입니다:

터치 타겟 크기 가이드라인: +----------------------------------------------------------+ | | | Apple Human Interface Guidelines: | | - 최소 44 x 44 pt (포인트) | | - 물리적으로 약 7mm x 7mm | | | | Google Material Design: | | - 최소 48 x 48 dp (density-independent pixels) | | - 터치 영역 간 최소 8dp 간격 | | | | 게임 업계 권장: | | - 자주 누르는 버튼: 64-80 pt | | - 일반 버튼: 48-64 pt | | - 설정/메뉴: 44 pt (최소) | | | +----------------------------------------------------------+ 버튼 크기별 오터치율 (연구 결과): +----------------------------------------------------------+ | | | 크기 오터치율 설명 | | ----- -------- ---- | | 32 pt 5.6% 너무 작음, 스트레스 유발 | | 44 pt 2.1% 최소 허용 크기 | | 56 pt 0.8% 일반적인 크기 | | 72 pt 0.2% 게임 액션 버튼 권장 | | | +----------------------------------------------------------+
// 터치 영역 확장 (시각적 크기보다 터치 영역 크게) class TouchableButton { Rect m_visualRect; // 눈에 보이는 크기 Rect m_touchRect; // 실제 터치 인식 크기 public: void SetSize(float visualWidth, float visualHeight) { m_visualRect.SetSize(visualWidth, visualHeight); // 터치 영역은 최소 44pt 보장 float touchWidth = std::max(visualWidth, 44.0f); float touchHeight = std::max(visualHeight, 44.0f); // 시각 영역 중심으로 터치 영역 확장 m_touchRect.SetSize(touchWidth, touchHeight); m_touchRect.CenterOn(m_visualRect.Center()); } bool HitTest(float x, float y) { // 터치 판정은 확장된 영역으로 return m_touchRect.Contains(x, y); } void Render() { // 렌더링은 시각 영역으로 DrawButton(m_visualRect); } };
버튼이 너무 붙어 있으면 어떻게 돼?

오터치(Fat Finger Problem)가 발생합니다:

버튼 간격 문제: +----------------------------------------------------------+ | | | 나쁜 예시 - 버튼이 붙어 있음: | | +-----+-----+-----+ | | | Btn | Btn | Btn | <- 어떤 버튼 누르려는지 구분 어려움 | | +-----+-----+-----+ | | | | 좋은 예시 - 충분한 간격: | | +-----+ +-----+ +-----+ | | | Btn | | Btn | | Btn | | | +-----+ +-----+ +-----+ | | ^ ^ | | | | | | +-- 최소 8dp 간격 --+ | | | +----------------------------------------------------------+ 실수 방지 기법: +----------------------------------------------------------+ | | | 1. 위험한 버튼 분리 | | [확인] [취소] <- 멀리 떨어뜨림 | | | | 2. 중요 버튼 크게 | | [ 확인 ] [취소] <- 주요 액션 강조 | | | | 3. 확인 단계 추가 | | [삭제] -> "정말 삭제?" -> [삭제] <- 2단계 확인 | | | | 4. 되돌리기 제공 | | "삭제됨. [되돌리기]" <- 실수 복구 가능 | | | +----------------------------------------------------------+

Part 3. 손가락 가림 문제 (Occlusion)

손가락이 화면을 가려서 안 보이면?

터치하는 순간 손가락 아래가 안 보입니다. 이것이 Occlusion 문제입니다:

손가락 가림 문제: +----------------------------------------------------------+ | | | 터치 전: 터치 중: | | +-------------+ +-------------+ | | | | | (O) | <- 손가락 | | | [드래그해서 | | [ ????? | <- 가려서 안 보임| | | 조준하세요]| | ????? ] | | | | + | | | | | +-------------+ +-------------+ | | | +----------------------------------------------------------+ 해결 방법: +----------------------------------------------------------+ | | | 1. 오프셋 표시 (Offset Cursor) | | +-----------------------------+ | | | [*] | <- 터치점 위에 커서 | | | | | | | | (O) | <- 손가락 | | +-----------------------------+ | | | | 2. 콜아웃 (Callout) | | +-----------------------------+ | | | +--------+ | | | | | 색상 | | <- 터치 위에 정보 | | | | 선택중 | | | | | +--------+ | | | | \ | | | | (O) | <- 손가락 | | +-----------------------------+ | | | | 3. 루페 (Loupe/Magnifier) | | +-----------------------------+ | | | +------+ | | | | |[확대]| | <- 터치점 확대 표시 | | | | 화면 | | | | | +------+ | | | | (O) | | | +-----------------------------+ | | | +----------------------------------------------------------+
// 조준 시스템에서 오프셋 커서 구현 class AimingSystem { Vector2 m_touchPos; Vector2 m_aimPos; const float OFFSET_Y = -80.0f; // 손가락 위 80pt public: void OnTouchMove(float x, float y) { m_touchPos = {x, y}; // 조준점은 터치점 위에 표시 m_aimPos = {x, y + OFFSET_Y}; } void Render() { // 터치점에서 조준점으로 선 그리기 DrawLine(m_touchPos, m_aimPos, COLOR_WHITE_TRANSLUCENT); // 조준점 표시 DrawCrosshair(m_aimPos); // 터치 영역 피드백 (반투명) DrawCircle(m_touchPos, 30, COLOR_WHITE_25); } }; // 텍스트 선택 루페 구현 class TextSelectionLoupe { void OnLongPress(float x, float y) { // 손가락 위치 위에 확대경 표시 float loupeY = y - 100; // 손가락 위 // 터치 위치 주변 화면 캡처 + 확대 Texture capture = CaptureRect(x - 50, y - 50, 100, 100); DrawScaled(capture, x, loupeY, 2.0f); // 2배 확대 } };

Part 4. 모바일 게임 UI 레이아웃

모바일 게임 UI 어떻게 배치해?

일반적인 모바일 ARPG UI 배치입니다:

모바일 ARPG 기본 레이아웃: +----------------------------------------------------------+ | | | [Menu] [HP Bar----][MP Bar----] [Mini] [Quest] | | [Map] [List] | | | | | | 게임 화면 | | (터치 영역) | | | | | | | | +---+ [Skill2] | | | | <- 가상 조이스틱 [Skill1] [ATK] | | | J | [Skill3] [Dodge] | | +---+ | | | +----------------------------------------------------------+ 영역별 역할: - 왼쪽 하단: 이동 (조이스틱) - 오른쪽 하단: 액션 (공격, 스킬, 회피) - 상단 왼쪽: 캐릭터 상태 (HP, MP) - 상단 오른쪽: 정보 (미니맵, 퀘스트)
// 모바일 게임 UI 레이아웃 시스템 class MobileGameUILayout { // 화면 영역 정의 enum Zone { TOP_LEFT, // 캐릭터 상태 TOP_CENTER, // 알림, 버프 TOP_RIGHT, // 미니맵, 퀘스트 MIDDLE, // 게임 화면 (터치 인터랙션) BOTTOM_LEFT, // 이동 조이스틱 BOTTOM_CENTER, // 자동 사냥, 채팅 등 BOTTOM_RIGHT // 액션 버튼 }; struct UIElement { Zone zone; int priority; // 같은 영역 내 우선순위 Rect bounds; }; void LayoutForScreen(float width, float height) { float safeTop = GetSafeAreaTop(); // 노치 대응 float safeBottom = GetSafeAreaBottom(); // 홈 인디케이터 // 상단 영역 (화면 높이의 15%) float topHeight = height * 0.15f; // 하단 영역 (화면 높이의 25%) float bottomHeight = height * 0.25f; // HP/MP 바: 왼쪽 상단 m_hpBar.SetPosition(20, safeTop + 10); m_mpBar.SetPosition(20, safeTop + 50); // 미니맵: 오른쪽 상단 m_minimap.SetPosition(width - 120, safeTop + 10); // 조이스틱: 왼쪽 하단 m_joystick.SetCenter(120, height - safeBottom - 120); // 공격 버튼: 오른쪽 하단 (가장 큰 버튼) m_attackBtn.SetCenter(width - 80, height - safeBottom - 80); m_attackBtn.SetSize(100, 100); // 큰 터치 영역 // 스킬 버튼: 공격 버튼 주변 호 형태 LayoutSkillButtons(width - 80, height - safeBottom - 80); } void LayoutSkillButtons(float centerX, float centerY) { // 공격 버튼 중심으로 120도 간격 호 형태 배치 float radius = 100.0f; float startAngle = 120.0f; // 왼쪽 위부터 for (int i = 0; i < 4; i++) { float angle = startAngle + i * 30.0f; float rad = angle * DEG_TO_RAD; float x = centerX + cos(rad) * radius; float y = centerY - sin(rad) * radius; m_skillBtns[i].SetCenter(x, y); m_skillBtns[i].SetSize(60, 60); } } };
가로 모드랑 세로 모드 둘 다 지원해야 해?

장르에 따라 다릅니다:

장르별 화면 방향: +----------------------------------------------------------+ | | | 가로 모드 (Landscape) 권장: | | - MMORPG, ARPG: 넓은 시야 필요 | | - FPS, TPS: 조준 영역 확보 | | - 레이싱: 시야각 중요 | | - MOBA: 맵 전체 조망 필요 | | | | 세로 모드 (Portrait) 권장: | | - 캐주얼 게임: 한 손 조작 | | - 퍼즐 게임: 세로로 긴 보드 | | - 카드 게임: 카드 배치 | | - Idle/방치형: 한 손 조작 | | | | 둘 다 지원: | | - 턴제 RPG: 전투는 가로, 메뉴는 세로 | | - 수집형 RPG: 탐색 가로, 가챠 세로 | | | +----------------------------------------------------------+ 가로 모드 장단점: +----------------------------------------------------------+ | 장점: | | - 넓은 게임 화면 | | - 양손 조작에 적합 | | - PC 게임 이식 쉬움 | | | | 단점: | | - 한 손 조작 불가 | | - 지하철에서 불편 | | - 휴대폰 꺼내자마자 바로 플레이 어려움 | +----------------------------------------------------------+

Part 5. 터치 제스처

탭 말고 다른 터치 방식은?

다양한 터치 제스처를 게임에 활용할 수 있습니다:

게임에서 자주 쓰는 제스처: +----------------------------------------------------------+ | | | 1. 탭 (Tap) | | (O) -> (O) | | 터치 후 바로 떼기 | | 용도: 선택, 공격, 확인 | | | | 2. 더블 탭 (Double Tap) | | (O)(O) 빠르게 두 번 | | 용도: 줌 인/아웃, 대시, 상호작용 | | | | 3. 롱 프레스 (Long Press) | | (O)~~~ 꾹 누르기 (500ms+) | | 용도: 컨텍스트 메뉴, 차징, 아이템 정보 | | | | 4. 스와이프 (Swipe) | | (O) ---> 방향으로 쓸기 | | 용도: 이동, 회피, 페이지 넘기기 | | | | 5. 드래그 (Drag) | | (O)-----(O) 누른 채로 이동 | | 용도: 조이스틱, 아이템 이동, 조준 | | | | 6. 핀치 (Pinch) | | (O) (O) -> (O)(O) 또는 반대 | | 두 손가락으로 벌리기/오므리기 | | 용도: 줌, 맵 확대/축소 | | | +----------------------------------------------------------+
// 제스처 인식 시스템 class GestureRecognizer { Vector2 m_touchStart; float m_touchStartTime; bool m_isTouching = false; const float TAP_MAX_DISTANCE = 20.0f; const float TAP_MAX_DURATION = 0.3f; const float LONG_PRESS_DURATION = 0.5f; const float SWIPE_MIN_DISTANCE = 50.0f; const float SWIPE_MAX_DURATION = 0.3f; public: void OnTouchStart(float x, float y) { m_touchStart = {x, y}; m_touchStartTime = Time::Now(); m_isTouching = true; } void OnTouchEnd(float x, float y) { if (!m_isTouching) return; m_isTouching = false; float duration = Time::Now() - m_touchStartTime; float distance = Distance(m_touchStart, {x, y}); // 탭 판정 if (distance < TAP_MAX_DISTANCE && duration < TAP_MAX_DURATION) { OnTap(x, y); return; } // 스와이프 판정 if (distance > SWIPE_MIN_DISTANCE && duration < SWIPE_MAX_DURATION) { Vector2 direction = Normalize({x - m_touchStart.x, y - m_touchStart.y}); OnSwipe(direction); return; } } void Update() { if (!m_isTouching) return; float duration = Time::Now() - m_touchStartTime; // 롱 프레스 판정 if (duration > LONG_PRESS_DURATION) { OnLongPress(m_touchStart.x, m_touchStart.y); m_isTouching = false; // 한 번만 발생 } } };

Part 6. 햅틱 피드백

진동 피드백은 왜 중요해?

촉각 피드백이 터치의 불확실성을 해소합니다:

햅틱 피드백 유형: +----------------------------------------------------------+ | | | iOS Haptic Feedback: | | +----------------------------------------------------+ | | | Impact: 짧은 충격 (Light, Medium, Heavy) | | | | Selection: 선택 피드백 (가벼운 틱) | | | | Notification: 알림 (Success, Warning, Error) | | | +----------------------------------------------------+ | | | | 게임 적용 예시: | | +----------------------------------------------------+ | | | 버튼 클릭 -> Impact Light | | | | 공격 적중 -> Impact Medium | | | | 크리티컬 히트 -> Impact Heavy + 추가 진동 | | | | 피격 -> Notification Warning | | | | 레벨업 -> Notification Success | | | | 아이템 획득 -> Selection | | | | 스킬 쿨다운 -> 연속적인 짧은 진동 | | | +----------------------------------------------------+ | | | +----------------------------------------------------------+ 좋은 햅틱 = 액션과 일치 + 과하지 않음
// 햅틱 피드백 시스템 class HapticFeedback { public: // 버튼 터치 static void OnButtonTap() { #ifdef IOS UIImpactFeedbackGenerator(UIImpactFeedbackStyleLight).impactOccurred(); #else // Android Vibrator.vibrate(VibrationEffect.createOneShot(10, 50)); #endif } // 공격 적중 static void OnHit(float damage) { if (damage > 1000) { // 크리티컬: 강한 진동 + 추가 펄스 TriggerImpact(Heavy); Delay(50, []{ TriggerImpact(Medium); }); } else if (damage > 100) { TriggerImpact(Medium); } else { TriggerImpact(Light); } } // 피격 static void OnDamaged() { #ifdef IOS UINotificationFeedbackGenerator().notificationOccurred(.warning); #else // 패턴: 짧은-긴-짧은 long[] pattern = {0, 30, 50, 100, 50, 30}; Vibrator.vibrate(pattern, -1); #endif } // 스킬 차징 (연속 피드백) static void OnCharging(float progress) { // progress에 따라 진동 강도 증가 int intensity = (int)(progress * 255); int interval = (int)(100 - progress * 80); // 빨라지는 간격 TriggerContinuous(intensity, interval); } };

핵심 정리

  • 엄지 도달 범위: 중요 버튼은 화면 하단 중앙~오른쪽에 배치
  • 터치 타겟: 최소 44pt, 자주 쓰는 버튼은 64pt 이상
  • 버튼 간격: 최소 8dp, 위험한 버튼은 멀리 분리
  • 손가락 가림: 오프셋 커서, 콜아웃, 루페로 해결
  • 레이아웃: 왼쪽 하단=이동, 오른쪽 하단=액션, 상단=정보
  • 제스처: 탭, 롱프레스, 스와이프, 드래그, 핀치 활용
  • 햅틱: 액션과 일치하는 촉각 피드백으로 확신 제공
