핫 리로드

핫 리로드가 개발 속도를 얼마나 바꿀까?

Part 1. 핫 리로드의 원리

핫 리로드가 뭐야?

게임을 재시작하지 않고 코드/에셋을 즉시 반영하는 기능입니다:

핫 리로드 없이: +----------------------------------------------------------+ | | | 코드 수정 -> 빌드 -> 게임 종료 -> 게임 시작 -> 테스트 | | 상황 재현 -> 확인 | | | | 1회 반복: 2-5분 | | 하루 100회 반복: 3-8시간 낭비 | | | +----------------------------------------------------------+ 핫 리로드 있으면: +----------------------------------------------------------+ | | | 코드 수정 -> [Ctrl+R] -> 즉시 반영 -> 확인 | | | | 1회 반복: 2-5초 | | 하루 100회 반복: 3-8분 | | | | 생산성 60배 향상! | | | +----------------------------------------------------------+
어떻게 가능해?

런타임에 모듈을 교체하는 방식입니다:

핫 리로드 메커니즘: +----------------------------------------------------------+ | | | 방법 1: DLL 언로드/리로드 | | +----------------------------------------------------+ | | | 1. 게임 로직을 별도 DLL로 분리 | | | | 2. 코드 수정 후 DLL 재컴파일 | | | | 3. 기존 DLL 언로드 | | | | 4. 새 DLL 로드 | | | | 5. 함수 포인터 재연결 | | | +----------------------------------------------------+ | | | | 방법 2: 스크립트 언어 사용 | | +----------------------------------------------------+ | | | 1. 게임 로직을 Lua/Python 등으로 작성 | | | | 2. 스크립트 파일 수정 | | | | 3. 스크립트 엔진이 파일 변경 감지 | | | | 4. 해당 스크립트만 다시 로드 | | | +----------------------------------------------------+ | | | | 방법 3: 바이트코드 패치 | | +----------------------------------------------------+ | | | 1. 함수 시작 부분에 점프 코드 삽입 | | | | 2. 새 함수 코드를 메모리에 로드 | | | | 3. 점프 대상을 새 함수로 변경 | | | +----------------------------------------------------+ | | | +----------------------------------------------------------+

Part 2. 스크립트 리로드 vs 에셋 리로드

스크립트 핫 리로드는 어떻게 달라?

스크립트는 더 쉽게 핫 리로드할 수 있습니다:

스크립트 핫 리로드 (Lua 예시): +----------------------------------------------------------+ | | | 초기 로드: | | +----------------------------------------------------+ | | | scripts/player.lua 로드 | | | | -> Lua VM에 바이트코드로 컴파일 | | | | -> 전역 테이블에 함수 등록 | | | +----------------------------------------------------+ | | | | 핫 리로드: | | +----------------------------------------------------+ | | | 1. 파일 변경 감지 (파일 시스템 워치) | | | | 2. 기존 함수 참조 저장 | | | | 3. dofile("scripts/player.lua") | | | | 4. 전역 테이블의 함수가 새 코드로 덮어씌워짐 | | | | 5. 기존 객체들은 새 함수를 자동으로 호출 | | | +----------------------------------------------------+ | | | | 장점: 빌드 불필요, 1초 미만 리로드 | | | +----------------------------------------------------------+
에셋 핫 리로드는?

텍스처, 메시, 사운드 등도 핫 리로드 가능합니다:

에셋 핫 리로드: +----------------------------------------------------------+ | | | 텍스처 핫 리로드: | | +----------------------------------------------------+ | | | 1. 아티스트가 PSD/PNG 파일 저장 | | | | 2. 파일 워처가 변경 감지 | | | | 3. 새 텍스처 로드 (백그라운드) | | | | 4. 준비되면 GPU 텍스처 교체 | | | | 5. 게임 화면에 즉시 반영 | | | +----------------------------------------------------+ | | | | CSV/데이터 핫 리로드: | | +----------------------------------------------------+ | | | 1. 밸런스 CSV 수정 (몬스터 HP, 스킬 데미지 등) | | | | 2. CSV 재로드 | | | | 3. 데이터 테이블 갱신 | | | | 4. 게임 내 모든 몬스터에 즉시 적용 | | | +----------------------------------------------------+ | | | +----------------------------------------------------------+

Part 3. 상태 유지 문제

핫 리로드하면 게임 상태가 날아가지 않아?

이것이 핫 리로드의 가장 어려운 문제입니다:

상태 유지 문제: +----------------------------------------------------------+ | | | 리로드 전: | | +----------------------------------------------------+ | | | class Player { int hp = 100; int mp = 50; } | | | +----------------------------------------------------+ | | | | 코드 수정 (새 필드 추가): | | +----------------------------------------------------+ | | | class Player { int hp; int mp; int shield = 0; } | | | +----------------------------------------------------+ | | | | 문제: | | - 기존 Player 객체의 메모리 레이아웃이 변경됨 | | - hp, mp 값은 유지하고 싶지만 클래스 구조가 달라짐 | | - 단순히 DLL 교체하면 크래시 또는 데이터 손상 | | | +----------------------------------------------------------+
어떻게 해결해?

여러 가지 상태 보존 전략이 있습니다:

상태 보존 전략: +----------------------------------------------------------+ | | | 1. 직렬화/역직렬화 | | +----------------------------------------------------+ | | | 리로드 전: 모든 객체 -> JSON/Binary 저장 | | | | 리로드 후: JSON/Binary -> 새 객체 생성 | | | | 장점: 구조 변경에 유연 | | | | 단점: 느림, 복잡한 참조 처리 어려움 | | | +----------------------------------------------------+ | | | | 2. 코드/데이터 분리 | | +----------------------------------------------------+ | | | 코드: 함수만 포함 (핫 리로드 대상) | | | | 데이터: 별도 구조체 (유지됨) | | | | PlayerData (유지) + PlayerLogic (리로드) | | | +----------------------------------------------------+ | | | | 3. 포인터 대신 핸들 사용 | | +----------------------------------------------------+ | | | Player* pPlayer; // 리로드 후 무효 | | | | Handle hPlayer; // 리로드 후 유효 | | | | Handle -> 테이블 조회 -> 실제 객체 | | | +----------------------------------------------------+ | | | +----------------------------------------------------------+

Part 4. 엔진별 구현

Unity에서는 어떻게 해?

Unity는 Enter Play Mode Settings을 제공합니다:

Unity 핫 리로드 최적화: +----------------------------------------------------------+ | | | 기본 동작: | | +----------------------------------------------------+ | | | 코드 수정 -> 컴파일 (5-30초) -> 도메인 리로드 | | | | -> 씬 재로드 -> 플레이 모드 진입 | | | | 문제: 도메인 리로드가 느림 | | | +----------------------------------------------------+ | | | | 최적화 설정 (2019.3+): | | +----------------------------------------------------+ | | | Edit > Project Settings > Editor | | | | [x] Enter Play Mode Settings | | | | [ ] Reload Domain (끄면 빠름, 주의 필요) | | | | [ ] Reload Scene | | | +----------------------------------------------------+ | | | | 주의사항: | | +----------------------------------------------------+ | | | 도메인 리로드 끄면: | | | | - static 변수가 초기화 안 됨 | | | | - [RuntimeInitializeOnLoadMethod] 필요 | | | | - 이벤트 구독 해제 필수 | | | +----------------------------------------------------+ | | | +----------------------------------------------------------+
Unreal은?

Unreal은 Live Coding을 제공합니다:

Unreal Live Coding: +----------------------------------------------------------+ | | | Ctrl+Alt+F11 -> 핫 리로드 트리거 | | | | 동작 방식: | | +----------------------------------------------------+ | | | 1. 변경된 CPP 파일 컴파일 | | | | 2. 패치 DLL 생성 | | | | 3. 함수 단위로 코드 패치 | | | | 4. 에디터/게임 계속 실행 | | | +----------------------------------------------------+ | | | | 제한사항: | | +----------------------------------------------------+ | | | - 헤더 파일 변경은 불가 (풀 리컴파일 필요) | | | | - 생성자/소멸자 변경 주의 | | | | - UPROPERTY/UFUNCTION 추가 불가 | | | | - 기존 객체는 새 코드 사용하지만 재생성 안 됨 | | | +----------------------------------------------------+ | | | | 장점: C++ 네이티브 코드 핫 리로드! | | | +----------------------------------------------------------+
// Unreal: Live Coding 친화적 코드 작성 // 헤더 (수정 시 풀 리컴파일 필요) UCLASS() class AMyActor : public AActor { GENERATED_BODY() // 함수 선언만 (구현은 CPP에) void UpdateLogic(); // 데이터는 UPROPERTY로 UPROPERTY() int32 Health; }; // CPP (Live Coding으로 수정 가능) void AMyActor::UpdateLogic() { // 이 코드를 수정하면 Live Coding 가능 Health -= 10; if (Health <= 0) { Die(); } }

Part 5. 핫 리로드 워크플로우

실제로 어떻게 활용해?

효과적인 핫 리로드 워크플로우:

핫 리로드 워크플로우: +----------------------------------------------------------+ | | | 1. 게임플레이 디자이너 | | +----------------------------------------------------+ | | | 게임 실행 중 -> CSV 수정 -> 저장 -> 즉시 반영 | | | | 몬스터 HP, 스킬 데미지 등 밸런스 조정 | | | | 결과 확인 -> 다시 수정 -> 반복 (수백 번) | | | +----------------------------------------------------+ | | | | 2. 프로그래머 | | +----------------------------------------------------+ | | | 버그 발생 위치까지 게임 진행 | | | | 코드 수정 -> Ctrl+R -> 즉시 반영 | | | | 버그 수정 확인 (다시 처음부터 할 필요 없음!) | | | +----------------------------------------------------+ | | | | 3. 아티스트 | | +----------------------------------------------------+ | | | 게임 실행 중 -> PSD 수정 -> 저장 -> 화면 즉시 갱신 | | | | 조명, 색감 조정 결과를 실시간으로 확인 | | | +----------------------------------------------------+ | | | | 4. UI 디자이너 | | +----------------------------------------------------+ | | | UI 레이아웃 JSON 수정 -> 저장 -> 즉시 반영 | | | | 버튼 위치, 크기 조정 반복 | | | +----------------------------------------------------+ | | | +----------------------------------------------------------+

핵심 정리

  • 핫 리로드: 재시작 없이 코드/에셋 즉시 반영 (생산성 60배)
  • 구현 방법: DLL 리로드, 스크립트 엔진, 바이트코드 패치
  • 스크립트: Lua 등은 매우 쉽게 핫 리로드 가능
  • 에셋: 텍스처, CSV, JSON 등도 핫 리로드 지원
  • 상태 유지: 직렬화, 코드/데이터 분리, 핸들 시스템으로 해결
  • Unity: Enter Play Mode Settings로 도메인 리로드 스킵
  • Unreal: Live Coding으로 C++ 함수 핫 패치
