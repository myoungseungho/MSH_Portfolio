클라가 '나 순간이동했어'라고 우기면? — 서버 권위와 스피드핵 방어

클라가 보낸 값을 믿지 않는다. 서버가 모든 판단의 최종 권위

30초 요약

클라이언트는 조작될 수 있어 — 보낸 좌표·속도·수량을 그대로 믿으면 핵에 뚫려.

서버 권위 = 서버가 '가능한 범위'를 직접 계산해 검증하고, 벗어나면 거부·되돌림(스냅백).

예측(화면 표시)은 클라가 해도 되지만, 판정·재화·이동 결과는 무조건 서버가 결정.

Part 1. 클라를 믿으면 안 되는 이유

이동은 클라가 계산해서 위치만 보내면 편하잖아?

편하지만 위험해. 클라 메모리·패킷은 조작 가능하거든. '나 지금 여기 있어'를 마음대로 보내면 순간이동·스피드핵이 돼.

클라가 보낸 값을 서버가 그대로 적는 순간, 게임은 클라에게 점령당해.

그럼 어떻게 검증해?

서버가 '직전 위치 + 최대 이동 속도 × 경과 시간'으로 갈 수 있는 최대 범위를 계산해. 클라가 그보다 멀리 갔다고 주장하면 → 불가능 → 거부하고 합법 위치로 되돌려.

속도뿐 아니라 좌표(맵 경계), 수량(>0), 소유권(진짜 가진 아이템인가), 상태(죽었는데 공격?), 빈도(비정상적으로 빠른 반복)도 같은 식으로 검증해.

Part 2. 핵을 켜봐

신뢰 vs 권위를 직접 비교해봐.

탭으로 ① 클라 신뢰 ② 서버 권위 를 고르고 '스피드핵 켜기'를 눌러봐.

클라 신뢰는 3배 속도가 그대로 통과(뚫림), 서버 권위는 최대 속도 초과를 거부하고 합법 위치로 스냅백해(차단).

Part 3. 예측과 어떻게 공존해

근데 클라 예측은 클라가 먼저 움직이는 거잖아? 모순 아냐?

아니. 예측은 '내 화면 표시'만 미리 하는 거고, 진짜 위치는 서버가 확정해. 예측이 틀리면 서버가 보정(스냅백)하지.

즉 '보여주기'는 클라가, '결정'은 서버가 — 이 둘을 분리하면 빠른 반응과 보안을 동시에 잡아.

에러 코드는 자세히 주면 안 돼?

검증 실패 시 '왜 막혔는지'를 너무 자세히 알려주면 핵 제작자에게 힌트가 돼. 그래서 조용히 무시하거나 연결을 끊는 게 보통이야.

우리 CLAUDE.md의 서버 안정성 원칙 9번(서버 권위)도 같은 얘기 — 범위·소유권·상태·빈도를 검증하고, 실패 시 상세 에러 대신 무시/끊기.

Part 4. 무엇을 검증하나

검증 축예시
범위좌표가 맵 안인가, 배열 인덱스 0≤i<MAX, 수량>0
소유권이 아이템/스킬을 실제로 보유하나 (클라 주장 불신)
상태/권한죽었는데 공격? 레벨 미달? 이벤트 기간 외?
속도/빈도최대 이동 속도 초과? 같은 패킷 비정상 반복?
한 줄로?

서버는 클라가 보낸 모든 값을 '용의자'로 보고 직접 검증해. 클라는 '요청'만 하고, '결정'은 항상 서버. 이게 모든 온라인 게임 보안의 출발점이야 (UE의 Server RPC WithValidation도 정확히 이걸 위한 장치).

핵심 정리

  • 클라는 조작 가능 — 보낸 값을 그대로 믿으면 핵에 뚫림
  • 서버 권위 = 가능한 범위를 서버가 계산해 검증, 벗어나면 거부·스냅백
  • 예측(표시)은 클라, 결정(판정)은 서버 — 분리하면 반응성+보안 동시에
  • 검증 축: 범위·소유권·상태/권한·속도/빈도
  • 실패 시 상세 에러 X(핵 힌트) → 조용히 무시/끊기. UE Server RPC WithValidation과 동일
