Weak Reference

GC와 협력하는 스마트한 참조 관리

Part 1. 개념 - Strong vs Weak Reference

Strong Reference가 뭐야?

객체를 살려두는 참조입니다. 우리가 평소 쓰는 모든 변수가 Strong Reference예요.

Strong Reference가 하나라도 있으면 GC는 그 객체를 절대 수거하지 않습니다.

// Strong Reference - 일반적인 참조 class Player { // 이 참조가 살아있는 한 Texture는 GC 대상이 아님 private Texture2D portrait; // Strong Reference public void SetPortrait(Texture2D tex) { portrait = tex; // Strong Reference 생성 } } // Player 인스턴스가 살아있으면 → portrait도 살아있음 // portrait이 살아있으면 → Texture2D도 살아있음 // 이 체인이 끊어져야 GC 수거 가능
그럼 Weak Reference는?

객체를 살려두지 않는 참조입니다. "있으면 쓰고, 없으면 말고"의 철학이죠.

GC 입장에서 Weak Reference만 있는 객체는 "참조 없음"과 동일합니다.

using System; // Weak Reference - GC가 수거할 수 있는 참조 class AssetCache { // WeakReference<T>로 감싸면 GC가 수거 가능 private WeakReference<Texture2D> cachedTexture; public void Cache(Texture2D tex) { cachedTexture = new WeakReference<Texture2D>(tex); } public Texture2D TryGetCached() { // TryGetTarget: 아직 살아있으면 true + 객체 반환 // GC가 수거했으면 false if (cachedTexture != null && cachedTexture.TryGetTarget(out Texture2D tex)) { return tex; // 캐시 히트! } return null; // 캐시 미스 (GC가 수거함) } }
왜 굳이 Weak Reference를 써?

핵심은 메모리 압박 시 자동 해제입니다.

┌─────────────────────────────────────────────────────────────────┐
│                    Strong vs Weak 비교                          │

│                                                                 │

│  │ ├─ "hero" → Tex1 ────┼──→ Texture1 (10MB)  │                │

│  Weak Reference (스마트 캐시)                                   │
│  ┌──────────────────────┐                                       │
│  │ Cache Dictionary     │                                       │
│  │ ├─ "hero" → Weak ────┼─ ─ → Texture1 (10MB)  │              │
│  │ ├─ "enemy" → Weak ───┼─ ─ → (GC 수거됨)      │  메모리 부족  │

메모리가 부족하면 GC가 알아서 정리해주므로 OOM을 예방할 수 있습니다.

Part 2. C# WeakReference 구현

WeakReference<T> 어떻게 써?

.NET 4.5+에서 제공하는 제네릭 WeakReference<T>를 사용합니다.

using System; using System.Collections.Generic; public class WeakReferenceCache<TKey, TValue> where TValue : class { private Dictionary<TKey, WeakReference<TValue>> _cache = new Dictionary<TKey, WeakReference<TValue>>(); // 캐시에 저장 (Weak 참조로) public void Add(TKey key, TValue value) { _cache[key] = new WeakReference<TValue>(value); } // 캐시에서 조회 (없으면 null) public TValue TryGet(TKey key) { if (_cache.TryGetValue(key, out var weakRef)) { if (weakRef.TryGetTarget(out TValue value)) { return value; // 아직 살아있음! } // GC가 수거함 → 딕셔너리에서도 제거 _cache.Remove(key); } return null; } // 캐시 정리 (죽은 참조 제거) public void Cleanup() { var deadKeys = new List<TKey>(); foreach (var kvp in _cache) { if (!kvp.Value.TryGetTarget(out _)) { deadKeys.Add(kvp.Key); } } foreach (var key in deadKeys) { _cache.Remove(key); } } }
SetTarget은 뭐야?

WeakReference의 대상 객체를 변경하는 메서드입니다.

var weakRef = new WeakReference<Texture2D>(textureA); // 나중에 다른 텍스처로 변경 weakRef.SetTarget(textureB); // 참조 해제 (null로 설정) weakRef.SetTarget(null);

주의: SetTarget(null)을 해도 WeakReference 객체 자체는 남아있습니다. 딕셔너리에서 완전히 제거하려면 Remove를 호출해야 합니다.

trackResurrection이 뭐야?

WeakReference 생성자의 두 번째 파라미터로, Finalizer 실행 후에도 추적할지 결정합니다.

// trackResurrection = false (기본값, Short Weak Reference) var shortWeak = new WeakReference<MyClass>(obj, false); // trackResurrection = true (Long Weak Reference) var longWeak = new WeakReference<MyClass>(obj, true);
┌─────────────────────────────────────────────────────────────────┐
│              Short vs Long Weak Reference                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │

│                                                                 │

│  참조 유효: ├─────────────────────────────────┤                 │
│            ① 마킹 ────────────────────────── ④ 해제 직전까지    │
│                                                                 │

Part 3. Unity 에셋 시스템과 Weak Reference

Unity에서 Weak Reference를 어떻게 활용해?

Unity의 UnityEngine.Object는 특수한 객체이므로 null 체크 방식이 다릅니다.

using UnityEngine; using System; using System.Collections.Generic; public class UnityAssetCache<T> where T : UnityEngine.Object { private Dictionary<string, WeakReference<T>> _cache = new Dictionary<string, WeakReference<T>>(); public T TryGet(string key) { if (_cache.TryGetValue(key, out var weakRef)) { if (weakRef.TryGetTarget(out T asset)) { // ⚠️ Unity 객체는 추가 체크 필요! // C# 참조는 살아있지만 Unity 네이티브 객체가 // Destroy 되었을 수 있음 if (asset != null) // Unity의 == null 연산자 { return asset; } } _cache.Remove(key); } return null; } public void Add(string key, T asset) { if (asset == null) return; _cache[key] = new WeakReference<T>(asset); } }
⚠️ Unity 객체의 특수성
Unity 객체는 C# 래퍼 + 네이티브 객체 구조입니다. Destroy() 호출 시 네이티브는 즉시 해제되지만 C# 래퍼는 GC까지 남아있습니다. 따라서 WeakReference.TryGetTarget이 true여도 Unity의 == null이 true일 수 있습니다.
Addressables에서는 어떻게 해?

Addressables는 AsyncOperationHandle로 참조 카운팅을 합니다. Weak Reference와 함께 쓰면 더 유연해집니다.

using UnityEngine; using UnityEngine.AddressableAssets; using UnityEngine.ResourceManagement.AsyncOperations; using System; using System.Collections.Generic; public class AddressableWeakCache { private class CacheEntry { public WeakReference<Object> WeakAsset; public AsyncOperationHandle Handle; public DateTime LastAccess; } private Dictionary<string, CacheEntry> _cache = new Dictionary<string, CacheEntry>(); public async Task<T> LoadAsync<T>(string address) where T : Object { // 1. 캐시 확인 if (_cache.TryGetValue(address, out var entry)) { if (entry.WeakAsset.TryGetTarget(out var cached) && cached != null) { entry.LastAccess = DateTime.Now; return (T)cached; // 캐시 히트! } // Weak 참조가 죽었으면 Handle도 해제 if (entry.Handle.IsValid()) { Addressables.Release(entry.Handle); } _cache.Remove(address); } // 2. 새로 로드 var handle = Addressables.LoadAssetAsync<T>(address); await handle.Task; if (handle.Status == AsyncOperationStatus.Succeeded) { var asset = handle.Result; _cache[address] = new CacheEntry { WeakAsset = new WeakReference<Object>(asset), Handle = handle, LastAccess = DateTime.Now }; return asset; } return null; } // 오래된 약한 참조 정리 public void CleanupStale(TimeSpan maxAge) { var now = DateTime.Now; var toRemove = new List<string>(); foreach (var kvp in _cache) { var entry = kvp.Value; // 죽은 참조 또는 오래된 참조 제거 bool isDead = !entry.WeakAsset.TryGetTarget(out var asset) || asset == null; bool isStale = (now - entry.LastAccess) > maxAge; if (isDead || isStale) { if (entry.Handle.IsValid()) { Addressables.Release(entry.Handle); } toRemove.Add(kvp.Key); } } foreach (var key in toRemove) { _cache.Remove(key); } } }
Resources.Load와 다른 점은?

Resources.Load는 명시적 Unload 필요, Addressables + WeakRef는 자동 해제 가능합니다.

Part 4. Soft Reference vs Weak Reference

Soft Reference가 뭐야?

메모리가 부족할 때만 수거되는 참조입니다. Java에는 있지만 C#에는 없습니다.

┌─────────────────────────────────────────────────────────────────┐
│              참조 강도 스펙트럼 (Java 기준)                      │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  강함                                              약함         │
│  ←────────────────────────────────────────────────────→        │
│                                                                 │
│  Strong      Soft        Weak        Phantom                   │
│  ──────      ────        ────        ───────                   │
│  절대 GC    메모리       GC 때마다   Finalize                   │
│  안 됨      부족 시만    수거 대상   이후에만                   │
│                                                                 │
│  ─────────────────────────────────────────────────────────────  │
│                                                                 │
│  C#에서의 구현:                                                 │
│                                                                 │
│  Strong ───────→ 일반 참조 (T reference)                       │
│  Weak ─────────→ WeakReference<T>                              │
│  Soft ─────────→ ❌ 직접 구현 필요 (아래 참조)                  │
│  Phantom ──────→ 불필요 (Finalizer로 대체)                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
C#에서 Soft Reference를 어떻게 구현해?

메모리 사용량을 모니터링하며 조건부로 Strong/Weak를 전환하는 방식으로 구현합니다.

using System; using UnityEngine; using UnityEngine.Profiling; public class SoftReference<T> where T : class { private T _strongRef; // Strong 보관 private WeakReference<T> _weakRef; // Weak 보관 private readonly long _memoryThreshold; // 압박 기준 public SoftReference(T target, long memoryThresholdMB = 100) { _strongRef = target; _weakRef = new WeakReference<T>(target); _memoryThreshold = memoryThresholdMB * 1024 * 1024; } public T Target { get { UpdateReferenceMode(); // Strong이 있으면 그것 반환 if (_strongRef != null) return _strongRef; // Weak에서 시도 if (_weakRef.TryGetTarget(out T target)) return target; return null; // GC됨 } } public bool IsAlive { get { if (_strongRef != null) return true; return _weakRef.TryGetTarget(out _); } } private void UpdateReferenceMode() { long usedMemory = Profiler.GetTotalAllocatedMemoryLong(); long reservedMemory = Profiler.GetTotalReservedMemoryLong(); long freeMemory = reservedMemory - usedMemory; if (freeMemory < _memoryThreshold) { // 메모리 압박 → Strong 해제, Weak만 유지 if (_strongRef != null) { Debug.Log($"[SoftRef] 메모리 압박으로 Strong 해제"); _strongRef = null; } } else { // 메모리 여유 → Weak가 살아있으면 Strong 복원 if (_strongRef == null && _weakRef.TryGetTarget(out T target)) { _strongRef = target; } } } // 명시적 해제 public void Clear() { _strongRef = null; _weakRef.SetTarget(null); } }
게임에서 Soft 캐시 어떻게 써?

자주 쓰는 에셋은 Strong, 가끔 쓰는 에셋은 Weak로 관리하는 하이브리드 방식입니다.

using System.Collections.Generic; using UnityEngine; public class HybridAssetCache { private class CacheEntry { public SoftReference<Object> Reference; public int HitCount; public float LastAccessTime; } private Dictionary<string, CacheEntry> _cache = new(); private const int HOT_THRESHOLD = 5; // 5번 이상 = Hot public T Get<T>(string key) where T : Object { if (_cache.TryGetValue(key, out var entry)) { entry.HitCount++; entry.LastAccessTime = Time.realtimeSinceStartup; var asset = entry.Reference.Target as T; if (asset != null) { return asset; // 캐시 히트 } // 캐시 미스 (GC됨) - 재로드 필요 _cache.Remove(key); } return null; } public void Add(string key, Object asset) { // 첫 로드 시 기본 100MB 임계값으로 Soft Reference 생성 _cache[key] = new CacheEntry { Reference = new SoftReference<Object>(asset, 100), HitCount = 1, LastAccessTime = Time.realtimeSinceStartup }; } // Hot 에셋(자주 사용)을 Strong으로 고정 public void PromoteHotAssets() { foreach (var entry in _cache.Values) { if (entry.HitCount >= HOT_THRESHOLD) { // Hot 에셋은 임계값을 0으로 → 항상 Strong 유지 var target = entry.Reference.Target; if (target != null) { entry.Reference = new SoftReference<Object>( target, 0 // 항상 Strong 유지 ); } } } } }

Part 5. 실전 패턴: 조건부 로딩

조건부 로딩이 뭐야?

있으면 즉시 사용, 없으면 로드 패턴입니다. WeakReference의 핵심 활용법이죠.

using System; using System.Threading.Tasks; using UnityEngine; using UnityEngine.AddressableAssets; public class ConditionalAssetLoader<T> where T : Object { private WeakReference<T> _weakRef; private readonly string _address; private Task<T> _loadingTask; public ConditionalAssetLoader(string address) { _address = address; } // 동기적 접근: 있으면 반환, 없으면 null public T GetIfLoaded() { if (_weakRef != null && _weakRef.TryGetTarget(out T asset) && asset != null) { return asset; } return null; } // 비동기 접근: 없으면 로드해서 반환 public async Task<T> GetOrLoadAsync() { // 1. 이미 있으면 즉시 반환 var existing = GetIfLoaded(); if (existing != null) return existing; // 2. 이미 로딩 중이면 그 Task 대기 if (_loadingTask != null && !_loadingTask.IsCompleted) return await _loadingTask; // 3. 새로 로드 _loadingTask = LoadInternalAsync(); return await _loadingTask; } private async Task<T> LoadInternalAsync() { try { var handle = Addressables.LoadAssetAsync<T>(_address); var asset = await handle.Task; if (asset != null) { _weakRef = new WeakReference<T>(asset); } return asset; } finally { _loadingTask = null; } } }
이걸 UI에 어떻게 적용해?

아이콘 같은 UI 이미지에 지연 로딩 + 캐시 패턴을 적용합니다.

using System.Collections.Generic; using UnityEngine; using UnityEngine.UI; public class WeakIconManager : MonoBehaviour { private static Dictionary<string, ConditionalAssetLoader<Sprite>> _loaders = new(); [SerializeField] private Sprite _placeholder; public async void SetIcon(Image image, string iconAddress) { // 로더 가져오거나 생성 if (!_loaders.TryGetValue(iconAddress, out var loader)) { loader = new ConditionalAssetLoader<Sprite>(iconAddress); _loaders[iconAddress] = loader; } // 즉시 사용 가능하면 바로 적용 var immediate = loader.GetIfLoaded(); if (immediate != null) { image.sprite = immediate; return; } // 플레이스홀더 표시 후 비동기 로드 image.sprite = _placeholder; var sprite = await loader.GetOrLoadAsync(); // 로드 완료 - Image가 아직 유효한지 확인 if (image != null && sprite != null) { image.sprite = sprite; } } // 메모리 정리 public static void ClearUnusedLoaders() { var toRemove = new List<string>(); foreach (var kvp in _loaders) { if (kvp.Value.GetIfLoaded() == null) { toRemove.Add(kvp.Key); } } foreach (var key in toRemove) { _loaders.Remove(key); } } }

Part 6. 주의사항과 안티패턴

WeakReference 쓸 때 주의할 점은?

몇 가지 흔한 실수가 있습니다.

// ❌ 안티패턴 1: TryGetTarget 결과를 변수에 안 받음 if (weakRef.TryGetTarget(out var asset)) { // ... 다른 코드 ... } // 여기서 asset 다시 접근하면 GC될 수 있음! UseAsset(asset); // 위험! asset이 null일 수 있음 // ✅ 올바른 패턴: 지역 변수로 Strong 참조 유지 if (weakRef.TryGetTarget(out var asset) && asset != null) { // 이 블록 안에서는 asset이 Strong 참조로 유지됨 UseAsset(asset); // 안전! } // ❌ 안티패턴 2: Dictionary 키를 정리 안 함 Dictionary<string, WeakReference<Object>> cache; // 객체가 GC되어도 Dictionary에 키는 계속 남아있음 // → 메모리 누수 (키 문자열 + WeakReference 객체) // ✅ 올바른 패턴: 주기적 정리 private void CleanupDeadReferences() { var deadKeys = cache .Where(kvp => !kvp.Value.TryGetTarget(out _)) .Select(kvp => kvp.Key) .ToList(); foreach (var key in deadKeys) cache.Remove(key); } // ❌ 안티패턴 3: Unity 객체 null 체크 누락 if (weakRef.TryGetTarget(out GameObject go)) { go.SetActive(true); // Destroy된 객체면 크래시! } // ✅ 올바른 패턴: Unity null 체크 추가 if (weakRef.TryGetTarget(out GameObject go) && go != null) { go.SetActive(true); // 안전! }
ConditionalWeakTable은 뭐야?

키도 Weak로 관리하는 특수 컬렉션입니다. 키가 GC되면 엔트리도 자동 제거됩니다.

using System.Runtime.CompilerServices; using UnityEngine; public class GameObjectMetadata { // ConditionalWeakTable: 키(GameObject)가 GC되면 자동 정리 private static ConditionalWeakTable<GameObject, Metadata> _metadata = new(); public class Metadata { public string OriginalName; public float SpawnTime; public int CustomId; } // GameObject에 메타데이터 연결 public static void SetMetadata(GameObject go, Metadata data) { _metadata.Add(go, data); // go가 Destroy/GC되면 data도 자동 정리됨! } // 메타데이터 조회 public static Metadata GetMetadata(GameObject go) { _metadata.TryGetValue(go, out var data); return data; } }
💡 ConditionalWeakTable 활용
기존 클래스를 수정하지 않고 추가 데이터를 연결할 때 유용합니다. Dictionary와 달리 키 객체가 GC되면 자동으로 엔트리가 제거되어 메모리 누수가 없습니다.
GC.KeepAlive는 뭐야?

JIT 최적화로 인한 조기 GC를 방지하는 메서드입니다.

public void ProcessWithWeakRef() { var data = new LargeData(); var weakRef = new WeakReference<LargeData>(data); // JIT가 "data는 더 이상 안 쓰네?" 판단하면 // 이 시점에서 GC 대상이 될 수 있음! DoSomethingLong(); // 시간 오래 걸리는 작업 // weakRef.TryGetTarget이 실패할 수 있음 if (weakRef.TryGetTarget(out var result)) { // 여기 못 들어올 수 있음 } // 해결책: KeepAlive로 참조 유지 강제 GC.KeepAlive(data); // 이 줄까지 data가 살아있도록 보장 }
⚠️ KeepAlive 위치 중요
GC.KeepAlive()는 반드시 객체를 마지막으로 사용하는 코드 이후에 호출해야 합니다. 메서드 끝에 두는 것이 일반적입니다.

Part 7. 성능과 메모리 영향

WeakReference 자체의 오버헤드는?

매우 작습니다. WeakReference<T> 객체 하나당 약 16-24바이트입니다.

GC 성능에 영향은?

WeakReference가 많으면 GC가 추가 작업을 해야 합니다.

// GC 동작 시 WeakReference 처리 단계 // 1. 일반 GC 단계 // - 루트에서 시작해 Strong 참조 추적 // - 도달 가능한 객체 마킹 // 2. WeakReference 처리 단계 (추가 비용) // - 모든 WeakReference 순회 // - 대상 객체가 마킹되지 않았으면 → 참조 무효화 // - 대상 객체가 마킹되었으면 → 그대로 유지 // 3. 수거 단계 // - 마킹 안 된 객체 해제 // WeakReference 수에 따른 GC 영향 (대략적) // - 100개 이하: 무시할 수준 // - 1,000개: 0.1ms 미만 추가 // - 10,000개: 0.5~1ms 추가 가능 // - 100,000개: 5~10ms 추가 가능 (문제 수준)
💡 최적화 팁
WeakReference 개수는 수천 개 이하로 유지하세요. 에셋 캐시 용도라면 충분합니다. 수만 개 이상 필요하다면 다른 전략(LRU 캐시 + 명시적 해제)을 고려하세요.
프로파일링은 어떻게 해?

Unity Profiler와 커스텀 통계를 함께 활용합니다.

using System.Collections.Generic; using UnityEngine; public class WeakRefProfiler : MonoBehaviour { private Dictionary<string, WeakReference<Object>> _cache = new(); // 통계 private int _hitCount; private int _missCount; private int _gcCollectedCount; public T Get<T>(string key) where T : Object { if (_cache.TryGetValue(key, out var weakRef)) { if (weakRef.TryGetTarget(out var obj) && obj != null) { _hitCount++; return (T)obj; } // GC에 의해 수거됨 _gcCollectedCount++; _cache.Remove(key); } _missCount++; return null; } public void PrintStats() { int aliveCount = 0; int deadCount = 0; foreach (var kvp in _cache) { if (kvp.Value.TryGetTarget(out var obj) && obj != null) aliveCount++; else deadCount++; } float hitRate = _hitCount + _missCount > 0 ? (float)_hitCount / (_hitCount + _missCount) * 100 : 0; Debug.Log($@" ═══════════════════════════════════════ WeakReference Cache Statistics ═══════════════════════════════════════ Total Entries: {_cache.Count} Alive: {aliveCount} Dead (pending cleanup): {deadCount} ─────────────────────────────────────── Cache Hits: {_hitCount} Cache Misses: {_missCount} Hit Rate: {hitRate:F1}% ─────────────────────────────────────── GC Collected: {_gcCollectedCount} ═══════════════════════════════════════"); } #if UNITY_EDITOR private void OnGUI() { if (!Debug.isDebugBuild) return; GUILayout.BeginArea(new Rect(10, 10, 200, 100)); GUILayout.Label($"WeakRef Cache: {_cache.Count}"); GUILayout.Label($"Hit Rate: {(_hitCount * 100f / Mathf.Max(_hitCount + _missCount, 1)):F1}%"); GUILayout.Label($"GC Collected: {_gcCollectedCount}"); GUILayout.EndArea(); } #endif }

핵심 정리

  • WeakReference = GC가 수거할 수 있는 참조 (메모리 압박 시 자동 해제)
  • TryGetTarget 패턴으로 안전하게 접근 (+ Unity null 체크 필수)
  • Soft Reference는 C#에 없음 → 메모리 임계값 기반 하이브리드 구현
  • 조건부 로딩: GetIfLoaded() → 없으면 GetOrLoadAsync()
  • Dictionary 키 정리 필수 (죽은 WeakReference 엔트리 제거)
  • ConditionalWeakTable: 키도 Weak로 관리하는 특수 컬렉션
  • 오버헤드: 객체당 ~24바이트, 수천 개까지는 무시할 수준
